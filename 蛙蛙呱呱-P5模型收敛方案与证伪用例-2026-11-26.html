P5 模型收敛方案与证伪用例

把 claim / cells / prose / card 四组组件收敛为可解释的单一模型：先证伪，再动代码。

2026-11-26 · 分支 refactor/wiring-truth · 前置：P4 七包归位 + 81 shim 退场（99a58ae）

0. 结论先行

审计 13 个模块（合计 5,438 行）后，结论和原来的假设不同：

  • 四组不是四份重复实现，而是四条链：claim 是文本机理、cells 是读数、prose 是正文、card 是任务信封。它们的“重复”主要在入口与契约声明，不在算数。
  • 真正需要收敛的只有 4 个点（下表）。其中 P5-5（cells 统一读数）已经在跑，且默认开启。
  • 其余三片都会改变产物（claims.json 的 contract 版本、sections 结构、卡的字段集）。按“不改业务行为”的既有约束，这三片必须逐片放行，不能一把梭。

1. 目标模型

Card（任务信封）        owner / deps / inputs / outputs / non_goals
  └─ brief             must_answer / standards / evidence_rules / acceptance_checks
  └─ Cell[]            (qid, dim, entity, measure, grain) → 可寻址
        └─ Claim       value + unit + period + source_ref + quote + grade
              └─ Section   判断 → 事实 → 机理 → 反例 → 判别 → 所以 → 边界
                    └─ Prose 11 字段（spec 9 + facts 2），文笔门禁只量正文

四条链共用同一套标识：qid / dim / entity / measure / grain / period。 收敛的本质是把这六个键变成唯一寻址方式，而不是把四个模块塞进一个文件。

判断标准：任何一条结论都能从 Section 反查到 Claim → Cell → 数据观测。
反查断链，就是模型没收敛；文件多少不是指标。

2. 分片计划

P5-1 claim 契约集中（不改产物）

  • 新增 core/claims/contract.py：只放常量与纯函数（必填字段、契约版本、iter_numbers()）。
  • claims_v4、cells_claims、claim_consistency 改为从这里取字段名；输出的 JSON 保持逐字节不变。
  • 删除条件：三处不再各写字段名，且 claims_v4 的 sections 结构被 report_assembly 完全吸收。

P5-2 prose 阈值单一出处（不改产物）

  • 把 prose_style.DEFAULTS 与 configs/report_prose.yaml 的重合键收敛为“配置为准、代码只留兜底”，兜底值由 report_contract 统一导出。
  • 删除条件：prose_style 不再自带一份完整默认值。

P5-3 card 单一编排入口（字段不动）

  • 新增 core/cards/pipeline.py：issue() / verify() / collect() 三个函数，内部只做转发。
  • 调用方（report_cli、report_flow）改走 pipeline；四个实现模块保留。
  • 删除条件：四个模块里不再有“第二套发卡/收卡顺序”。

P5-4 模型收敛（唯一会改产物的一片）

  • 新 ClaimCard 落盘 schema；claims_v4 的映射层并入 claims；cells_claims 的 v2 / v3 双契约合并为一版。
  • 这一片会改变 claims.json 的 contract 字段与 sections 形状，必须单独放行、单独回归真实项目。

3. 证伪用例（先写测试，再改代码）

每条都是“如果收敛做错了，这条会红”。已写成可执行断言的形式，分片时直接落进 tests/。

4. 与现有门禁的关系

  • 不改 check_report_flow F1–F12、ci_report_checks、check_move_cards；它们是产物级门禁，收敛不得绕过。
  • 新增的只有两类：契约常量一致性测试（F2/F4）、反查链测试（F6）。都进 tests/test_gates.py 或 tests/regression。
  • P5-1/P5-2/P5-3 的验收口径统一为：pytest 630+/630、ci_report_checks ALL PASS、同一项目产物 SHA 不变。
