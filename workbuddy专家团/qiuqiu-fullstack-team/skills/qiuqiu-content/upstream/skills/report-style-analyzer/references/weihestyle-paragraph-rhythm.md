# 渭河文风段落节奏

## 总体节奏

渭河文风的段落像现场分析，不像摘要报告。它通常让读者跟着作者走一遍判断过程：

```text
提出问题
-> 讲常见误解
-> 解释为什么不够
-> 换业务视角
-> 拆指标
-> 得出阶段判断
-> 继续下钻或落到动作
```

## 段落长度

### 短段

长度：1-2 句。

用途：

- 强调一个判断。
- 引出下一层问题。
- 放置公式。
- 做阶段性停顿。

示例功能：

```text
到这里，我们只能得到一个阶段性结论。
```

### 中段

长度：3-5 句。

用途：

- 解释一个指标的业务含义。
- 反驳一个常见误区。
- 说明一个小推理链。

段内常见结构：

```text
现象 -> 判断 -> 解释 -> 小结
```

### 长段

长度：5 句以上，或一个较长自然段。

用途：

- 承载复杂业务机制。
- 把多个变量串成一个场景。
- 展示作者“边想边拆”的过程。

长段不能只是堆句子，必须有内部推进：

```text
背景 -> 误解 -> 转折 -> 业务解释 -> 判断 -> 下一步
```

## 段落功能分布

一篇渭河文风文章通常包含：

- `问题段`: 说明为什么这个问题真实存在。
- `误区段`: 说明常规答案为什么不够。
- `拆解段`: 把指标拆到下一层。
- `场景段`: 把指标翻译成业务对象。
- `判断段`: 给出作者阶段性结论。
- `动作段`: 指向看板、专项、复盘、策略或资源配置。
- `边界段`: 说明还不能判断什么。

## 段内推进

常见段内结构有四种：

### 1. 误区反驳型

```text
很多人会认为 X。
但这个理解的问题在于 Y。
如果放到真实业务里，应该看 Z。
所以这里不能直接得出 A，只能先判断 B。
```

### 2. 指标翻译型

```text
表面上看是 X 指标变化。
但这个指标对应的业务场景是 Y。
在 Y 场景里，真正能被干预的是 Z。
所以报告里要跟踪的不是 X 本身，而是 Z。
```

### 3. 阶段结论型

```text
拆到这里，已经能说明 X。
但还不能说明 Y。
下一步需要看 Z。
如果 Z 也成立，才能进入具体策略。
```

### 4. 行动落地型

```text
这个判断如果成立，就不能停留在报告里。
它要变成一个看板/专项/复盘机制。
业务侧需要看到 A，分析侧需要跟踪 B。
否则这个结论只是解释了问题，没有推动问题被解决。
```

## 节奏禁忌

- 不要把每段都压成一句短结论。
- 不要连续堆多个短段，会失去推理过程。
- 不要用纯清单替代论述。
- 不要每段都以“首先、其次、最后”推进。
- 不要只保留结论，删掉误区、转折和边界。
