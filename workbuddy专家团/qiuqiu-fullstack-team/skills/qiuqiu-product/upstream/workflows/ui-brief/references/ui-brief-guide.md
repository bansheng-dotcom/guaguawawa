# UI Brief 质量指南

## 1. 好 UI brief 的定义

好 UI brief 不是视觉说明，而是把页面要完成的用户任务讲清楚。

| 模块 | 必须回答 |
| --- | --- |
| 页面目标 | 用户来这里完成什么 |
| 信息架构 | 第一眼看什么，下一步做什么 |
| 用户动作 | 用户能点、选、输入、确认什么 |
| 状态 | 空态、加载、成功、失败、权限 |
| 审查重点 | UI/前端需要重点判断什么 |

## 2. 常见反模式

- 先说风格，不说任务。
- 只写模块，不写用户动作。
- 缺空态、错误态和权限态。
- 用 PM brief 替代高保真设计。
