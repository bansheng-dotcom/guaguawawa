# 术语翻译表

> 用途：把项目里的技术语言翻译成用户能判断的语言。

| 术语 | 人话解释 | 为什么重要 |
| --- | --- | --- |
| PRD | 产品需求文档，说明要做什么、为什么做、做到什么算完成 | 防止开发和设计各理解各的 |
| 验收标准 | 判断一个功能是否完成的检查条件 | 防止“差不多完成” |
| 信息架构 | 页面内容怎么分组、怎么摆放、怎么让人找到 | 决定用户能不能看懂页面 |
| 状态 | 页面或数据当前处于什么情况，例如加载中、成功、失败、无权限 | 决定异常时用户会不会迷路 |
| HashRouter | 站内页面地址用 `#` 区分 | 静态部署方便，但地址不如普通路由自然 |
| API Gateway | 后端接口总入口 | 统一鉴权、限流、日志和错误处理 |
| AI Gateway | 模型调用总入口 | 避免前端暴露密钥，统一控制模型成本和权限 |
| Worker | 后台任务执行器 | 处理慢任务，避免页面卡住 |
| Queue | 排队系统 | 控制任务顺序和并发，避免服务被挤爆 |
| RLS | 数据权限隔离 | 保证用户只能看到自己有权限的数据 |
| trace_id | 一次操作的追踪编号 | 出问题时能查到完整链路 |
| Tool Registry | Agent 工具清单 | 规定 Agent 能调用哪些工具 |
| Orchestrator | Agent 调度器 | 决定任务怎么拆、谁来做、怎么合并结果 |
| Memory | Agent 的项目记忆 | 减少重复解释，但不能替代真实文件 |
| 幂等 | 同一个操作重复执行，不会产生重复或错误结果 | 重试、补跑、失败恢复时很重要 |
| 审计日志 | 记录谁在什么时候做了什么 | 出错、追责、排查权限问题时需要 |
