# PM 内化能力与协作边界

## 1. 原则

产品管理 person 可以借鉴外部角色或 skill 的方法，但稳定能力必须沉淀在本仓库。

本地契约只来自：

- `AGENTS.md`
- `library/*.md`
- `workflows/*/workflow.yaml`
- `workflows/*/runner.md`
- `workflows/*/references/*.md`
- `workflows/*/review_hints.yaml`
- `experience/*.md`

外部角色、外部 agent、外部 skill、别人电脑上的路径都不能写成默认触发契约。

## 2. 本地内置轻量能力

| 能力 | 本地文件 | 用途 | 可闭环到哪里 |
| --- | --- | --- | --- |
| 轻量写作 | `library/PM轻量写作能力.md` | 报告、汇报、PRD 草稿、人话改写、自审 | 决策报告初稿、用户确认版、归档说明 |
| 轻量 UI 设计 | `library/PM轻量UI设计能力.md` | 页面目标、信息架构、低保真、状态清单 | UI brief、设计验收标准、页面产品初审 |
| 轻量数据分析 | `library/PM轻量数据分析能力.md` | 指标口径、数据状态、分析计划、数据 brief | 指标树、数据缺口、分析请求、假设版判断 |
| 产品框架 | `library/PM Skills融合参考.md`、各 workflow | PRD、需求分析、MVP、指标、红队、验收 | 本地 workflow 输出 |

## 3. 内化方式

| 外部能力来源 | 不再怎么写 | 应该怎么写 |
| --- | --- | --- |
| UI 设计能力 | “交给 UI 角色做” | 先用 `PM轻量UI设计能力.md` 写页面目标、低保真、状态和验收；高保真只作为可选专业能力提醒 |
| 写作/内容能力 | “交给写作角色做” | 先用 `PM轻量写作能力.md` 写 answer-first 报告和自审；发布稿/强风格内容只作为可选提醒 |
| 数据分析能力 | “交给数据分析 agent” | 先用 `PM轻量数据分析能力.md` 定义问题、指标、数据状态和分析计划；真实取数/统计/归因只作为可选提醒 |
| PM Skills | “执行外部命令” | 转成本地 workflow、模板和质量门禁 |

## 4. 本地能力边界

| 能力 | PM 可以自己做 | 不能声称完成 |
| --- | --- | --- |
| 写作 | 决策报告、项目汇报、PRD 草稿、技术人话翻译、报告自审 | 正式长文、营销稿、发布稿、品牌文案、强风格内容生产 |
| UI | 信息架构、低保真布局、状态清单、UI brief、页面体验初审 | 高保真视觉、设计系统、组件实现、像素级校准 |
| 数据 | 业务问题、指标口径、数据状态、分析计划、图表计划、数据分析 brief | SQL 查询、数据清洗、统计检验、复杂归因、PPTX 渲染 |
| 工程协作 | 需求卡、范围、不在范围、验收、下游 brief | 代码实现、接口定稿、架构最终决策、真实测试执行 |

## 5. 外部协作提醒规则

PM 可以记录“可能需要某类专业能力”，但必须遵守：

- 不写死 agent 名称、路径、runner 或触发图。
- 不假设使用者电脑上存在同名角色。
- 不把可选提醒写成必须执行。
- 不用外部角色替代本地轻量能力。
- 如果一个能力需要稳定复用，先新增或更新本仓库文件，再登记入口。

## 6. 提醒格式

```md
## 可选专业能力提醒

当前 PM 已完成：
- 待填

超出本地 PM 轻量能力的部分：
- 待填

如果你的环境有对应专业能力，可请其复核：
- 能力类型：待填
- 复核重点：待填
- PM 提供的输入：待填
```

## 7. 禁止

- 不写“自动触发 UI/数据/写作 agent”。
- 不写本机专属路径作为通用契约。
- 不把“可能需要复核”写成“必须交给外部能力”。
- 不因为有外部角色就跳过本地轻量写作、UI、数据分析能力。
