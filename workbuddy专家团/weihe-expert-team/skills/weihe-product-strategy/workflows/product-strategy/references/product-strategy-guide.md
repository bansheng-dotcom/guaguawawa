# 产品战略与机会树质量指南

## 1. 好战略判断的定义

好战略判断不是“多做功能”，而是明确当前阶段保护什么、鼓励什么、放弃什么。

| 模块 | 必须回答 |
| --- | --- |
| 阶段目标 | 当前最重要的一件事 |
| 用户分群 | 谁的什么任务优先 |
| 机会 | 哪些问题值得解决 |
| 方案 | 哪些方案对应机会 |
| 实验 | 先验证什么 |
| 取舍 | 做什么、不做什么 |
| 壁垒 | 是否增强长期能力 |

## 2. 机会树写法

目标 -> 机会 -> 方案 -> 实验。

不要从目标直接跳到功能。

## 3. 来自 pm-skills 的战略框架怎么用

框架只服务当前决策，不按清单全跑。

| 框架 | 适用问题 | 输出 |
| --- | --- | --- |
| Product Strategy Canvas | 阶段方向不清、取舍不清 | 愿景、分群、取舍、指标、增长、能力、壁垒 |
| Value Proposition | 用户为什么会行动不清 | Who / Why / Before / How / After / Alternatives |
| Opportunity Solution Tree | 团队直接跳功能 | 目标、机会、方案、实验 |
| SWOT / PESTLE / Five Forces | 外部环境和竞争压力影响决策 | 外部约束、机会、威胁和应对 |
| Ansoff Matrix | 增长路径选择 | 市场渗透、市场开发、产品开发、多元化取舍 |
| Business / Lean / Startup Canvas | 商业模式或早期产品方向不清 | 用户、问题、方案、渠道、成本、收入、关键指标 |
| Pricing / Monetization | 收费或商业化是关键决策 | 价格假设、付费对象、风险、验证实验 |

## 4. 常见反模式

- 战略报告写成需求清单。
- 只写做什么，不写不做什么。
- 用户分群只有身份标签，没有任务场景。
- 没有阶段目标，却谈壁垒。
- 把框架堆满，但没有回答当前要拍板的问题。
