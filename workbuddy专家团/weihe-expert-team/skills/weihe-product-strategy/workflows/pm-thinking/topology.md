# PM 质问与思考拓扑

## 1. 目标

用最少问题把需求方向想清楚，而不是让用户陷入一问一答。

## 2. 拓扑图

```mermaid
flowchart TD
  A["用户想法"] --> B["抽取已知事实"]
  B --> C["RAG Gate: pre-question L1"]
  C --> D["补充发问约束/纠错摘要"]
  D --> E["写默认假设"]
  E --> F["推演关键缺口"]
  F --> G{"缺口会改变方向?"}
  G -- "是" --> H["合并成 1 个关键追问"]
  G -- "否" --> I["按默认假设推进"]
  H --> J["更新事实/假设"]
  I --> K["选择后续 workflow"]
  J --> K
```

## 3. 输出包

| 产物 | 用途 | 生命周期 |
| --- | --- | --- |
| 已确认事实 | 避免误解用户 | 当前需求 |
| 发问依据 | 说明问题来自真实场景和 L1 Gate | 本轮追问前 |
| 默认假设 | 支撑继续推进 | 确认前为临时 |
| 风险缺口 | 告诉用户哪里会影响方向 | 当前需求 |
| 推荐 workflow | 接到需求分析、PRD、MVP 等 | 下一步 |
