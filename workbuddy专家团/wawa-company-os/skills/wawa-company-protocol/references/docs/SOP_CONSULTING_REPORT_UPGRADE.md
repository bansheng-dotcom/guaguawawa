# 一人公司 · 咨询级深度商业分析报告出具标准 SOP (McKinsey-Grade)

> **文档编号**：DSH-SOP-REP-002（正式升级版，全面替代旧版 DSH-SOP-REP-001）  
> **适用范围**：一人公司全量智能体（R01 ~ R20）  
> **核心使命**：彻底消除“技术代码感、机器状态码、排版花哨廉价、缺乏商业机理”的问题。要求所有角色出具的报告必须达到**“商业叙事先行、因素分析分解、情景动态推演、出版级栅格排版、证据抽屉隐藏”**的咨询级水准。

---

## 一、 报告专业度四大核心铁律

1. **❌ 严禁出现任何 Emoji 与花哨色块**：
   * 严禁出现 🏛️、📌、🔍、📊、🚨、⚠️、🚀 等符号；
   * 采用克制的纯 CSS 几何线标（Line Glyph）与微米级线条排版。
2. **❌ 严禁外露代码与调试日志**：
   * 严禁出现 `[skill.quality] PASS`、`[skill.trend] PASS`、`SHA256`、`runner命令` 等字段；
   * 技术检查统一翻译为“**数据置信度审计**：六维质量得分 10.0，排查断流假象，确认反映真实经营损益”；
   * 复算命令与技术凭证一律**收起至底部的“审计追溯抽屉 (Audit Trace Ledger)”**，供机器和审计者按需展开，不污染决策者视线。
3. **✅ 必须包含“损益因式分解 (DuPont)”与“商业机理解释”**：
   * 拒绝报账式陈述（“利润降了 10%”）；
   * 必须穿透因果机理：将利润拆解为 `收入 − 成本`，剖析是由于“收入塌陷”还是“固定成本刚性锁定（负杠杆）”造成。
4. **✅ 必须附带“动态情景推演 (Simulation)”**：
   * 必须回答：“**如果放任该问题持续 3~6 个月，会累计蒸发多少资金？拖累全年总盘多少百分比？**”；
   * 为创始人和管理层决策提供量化的紧迫性与止血依据。

## 二、 咨询级报告结构与标准版式

所有交付报告（HTML 沉浸版与 Markdown 快读版）必须严格遵循以下章节结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ [公文小标] BUSINESS DECISION MEMO · 12-Column Grid Layout  │
│ [主标题] 核心命题与责任下钻（一句话讲透现象与主因）          │
│ [导语条] 包含分析周期、样本基准、置信等级（Level 3 生产复算级） │
├─────────────────────────────────────────────────────────────┤
│ 1. 核心结论先行与决策建议 (Executive Summary)                │
│    • 【决策指令】：明确动作（收紧/纠偏/排查/冻结）            │
│    • 【核心定性】：主因收敛至哪个单点（如 C区贡献 97.7% 跌幅）│
│    • 【指标指示带 (Metric Strip)】：等宽数字 + 核心状态线    │
├─────────────────────────────────────────────────────────────┤
│ 2. 三级归因穿透分析 (Root Cause Drilldown)                   │
│    • L1 数据置信度：六维质检无断流，排除假异动              │
│    • L2 经营责任分解：因素变动与责任分解列表                │
│    • L3 商业外部对齐：内因与外因边界，宏观对齐锚点          │
├─────────────────────────────────────────────────────────────┤
│ 3. 杜邦损益因素变动：收入与成本的拉锯                        │
│    • 收入变动与成本变动的剪刀差分析                         │
│    • 损益表项杜邦对比表 (DuPont Table)                      │
├─────────────────────────────────────────────────────────────┤
│ 4. 动态仿真：若不纠偏的长期损益影响                          │
│    • 未来 6 个月预期失血预测与全年拖累比例                  │
├─────────────────────────────────────────────────────────────┤
│ 5. 量化图谱支撑 (Chart Verification)                         │
│    • 内嵌 48 型 SVG 矢量图谱（走势折线/贡献瀑布/集中度帕累托） │
├─────────────────────────────────────────────────────────────┤
│ 6. 护栏熔断红线指标 (Guardrails & Kill-Switch)               │
│    • 表格形式：监控维度、指标名称、当前基线、触发即刻回滚红线 │
├─────────────────────────────────────────────────────────────┤
│ 7. 分阶段推进与阶梯灰度路线图 (Rollout Roadmap)              │
│    • 严格按 T0(5%) → T1(20%) → T2(50%) → T3(100%) 时间轴     │
├─────────────────────────────────────────────────────────────┤
│ 8. 后续行动项责任清单 (Next Actions)                         │
│    • 责任到部门与负责人的可落地战役清单                      │
├─────────────────────────────────────────────────────────────┤
│ 9. 审计追溯与复现凭证 (Audit Trace & Ledger) [可收起抽屉]    │
│    • 折叠收起：原始数据指纹、复算命令、技能执行耗时          │
└─────────────────────────────────────────────────────────────┘
```

## 五、 视觉/媒体资产的确定性装配 (Deterministic Visual Assembly)

对于涉及视觉生成的角色（如 R10 视觉设计官），研报必须体现设计资产的“确定性”与“可审计性”：

### 5.1 视觉产出的四大审计准则
1. **Prompt 审计凭证**：所有生图任务必须以 JSON 契约形式输出 Prompt 原始记录，严禁 AI 编造生成的提示词；
2. **Design Tokens 强制校验**：生成的任何视觉物料，其色彩、字体、圆角大小必须强制校验 `token.json` 中的设计令牌，违者门禁 FAIL；
3. **确定性 SVG 渲染优先**：对于宣传物料版式，必须使用 `render poster` 接口输出 SVG 矢量稿，杜绝位图生图带来的不可测性；
4. **媒体资产清单 (Manifest)**：视觉资产需在“证据抽屉”中以 Manifest 表格呈现（包含：文件名、尺寸、MIME 类型、指纹哈希）。

### 5.2 视觉 narrative 组件注入
*   **视觉一致性 (Brand Consistency)**：自动计算视觉内容与 `brand.vi` 的偏离度，若对比度低于 WCAG 3.0 或色彩偏移超标，系统将自动触发报告熔断。
*   **规格门禁**：对 UI 产出必须执行“五态覆盖测试”（正常/hover/active/disabled/loading），缺一项即视为深度不足，报告不予交付。

## 六、 角色叙事属性兼容性设计（Dynamic Narrative Assembly）

不同角色拥有不同的能力领域，必须根据其“业务属性”动态注入叙事组件，严禁一刀切。

### 6.1 业务属性域分类 (Domain-Specific Narrative)
每一份报告应根据角色 `ROLE_PROFILE` 自动加载对应叙事包：

| 领域属性 | 叙事重点 | 标准加载叙事组件 |
| :--- | :--- | :--- |
| **经营类 (R06/R12/R14)** | 利润/增长因果分解、杜邦负杠杆穿透 | 杜邦损益分解 + 动态情景仿真 + 帕累托集中度 |
| **财务风控类 (R01/R03/R04/R15)** | 现金跑道危机、三表勾稽平衡、税务合规 | 三表勾稽分析 + 现金流波动图 + 资产质量审计表 |
| **产品工程类 (R07/R08/R09/R17/R19)** | 需求价值流、P99延时容量、模型漂移 | 留存漏斗分解 + 服务吞吐容量图 + 故障率看板 |
| **视觉设计类 (R10)** | 视觉资产合规、Token 一致性、五态覆盖 | 视觉一致性分数 + 五态覆盖审计 + 媒体 Manifest |
| **组织协同类 (R02/R05/R11/R13)** | 全链路流速、项目群阻塞、VOC 挽回 | 关键路径拓扑图 + 任务阻塞漏斗 + 体验满意度矩阵 |
| **人才组织效能类 (R16)** | 人均产值增速差、岗位单点断层风险 | 人才能力模型画像 + 人效剪刀差分析表 |
| **数据资产类 (R18)** | 数仓管道健康度、跨表对账差异率、血缘追踪 | 跨表对账差异表 + 管道延迟监控看板 |
| **技术底座可靠性类 (R20)** | 全站可用性 SLA、容灾演练 RTO/RPO、无指责复盘 | 分布式探活心跳图 + 容灾调用拓扑 + 故障自愈审计 |

### 6.2 兼容性实现机制：报告反应堆 (Reporting Reactor)
为实现动态注入，所有角色报告生成逻辑必须通过 `role_runtime.py` 提供的 **适配器模式**：
1. **意图路由**：通过 `intent` 解析，将任务派发至领域适配器 (`NarrativeAdapter`)；
2. **叙事挂载**：适配器根据角色属性（如 R10 -> `DesignNarrator`），自动加载对应的“叙事组件包”；
3. **核心框架**：统一调用底层 `report_generator` 进行渲染，确保所有报告的排版版式（12 栅格、指示带、附录）在公司内完全一致。

这种模式允许新增领域只需开发“叙事包”，无需修改任何底层渲染代码。

## 七、 验收与防退化门禁

任何智能体提交报告逻辑，必须通过以下硬性测试验证（参考 `tests/test_deep_report.py`）：
1. **排版门禁**：HTML 产物内嵌 `<svg>` 矢量图表 **≥ 3 张**，体积 **≥ 30KB**；
2. **文字门禁**：Markdown 文本字数充实（**≥ 6KB**），杜绝“三段式”敷衍报告；
3. **纯净度门禁**：正文严禁出现 `[skill.`、`SHA256`、`cmd` 等字符串，必须通过无代码噪点审计。
