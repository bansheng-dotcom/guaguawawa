# 一人公司 · 组织章程（ORG.md）

> 本文档是 20 个角色 Agent 的**组织架构与汇报关系的唯一权威说明**。
> 它回答四个问题：谁负责什么、向谁汇报、与谁交接、出了事找谁。
> 机器可读的注册表在 `core/registry.py`，本文是它的组织语义层。

---

## 一、组织总图

```

                              │      创始人（你）        │

        ▼          ▼          ▼            ▼            ▼          ▼          ▼

   │        │ │ R19 智模│ │ R10 设计│  │        │  │人事     │ │        │ │        │
   └────────┘ └────────┘ └────────┘  └────────┘  └────────┘ └────────┘ └────┬───┘
```

**两条汇报线**：

1. **执行线**：执行角色 → R01（汇总）→ 创始人。
2. **独立评审线**：R04 蛙挑刺 **旁路直通创始人**，评审结论不经过 R01，
   保证「生成与校验分离」——R04 的 `pass/fail` 不被执行线拦截。

| 层 | 角色 | 这层回答的问题 | 汇报对象 | 验收方 |

## 四、权力与红线（谁可以决定什么）

| 事项 | 决定权 | 门槛 |
|---|---|---|
| 任务拆解与角色组合 | R01 | 单一主责、有验收、有终止条件 |
| 可逆决策（双向门） | R01 + 执行角色 | 快速决策 |
| 部分可逆决策 | R01 | 中度尽调 + 反方质询 |
| **不可逆决策**（裁员/关停/锁定产品） | **仅创始人** | R01 `escalate` 判定 + 人工签发 |
| 大额资金 / 受监管市场 / 条款书 | **仅创始人** | R03 复核 + 人工批准 |
| 质量结论（pass/fail） | **仅 R04** | 独立语境、身份红线 |
| 代码不可逆线上操作（drop/truncate/force push） | **需授权** | R09 无 handoff/owner 即拦 |

**铁律（继承自 R01 模块 B/C）**：
1. 一个文件/一个职能只有 **一个 owner**；「共同负责」＝没人负责。
2. 编排器必须瘦：只加载上下文 → 派发正确角色 → 回收结果 → 更新状态，不写产出、不替执行者判断。
3. 生成与校验分离：谁生成谁负责，R04 独立评审，自评不算数（`reviewer == producer` 即 FAIL）。
4. 一切带终止条件：成功标准全命中→收口；杀死标准触发→强制终止转复盘。

## 五、角色如何加入/退出编制

- **加入**：在 `core/registry.py` 追加 `ROLES` 记录（id/dir/capabilities/inputs/outputs/integrated_from），
  按《角色Agent生成SOP》五步法落地 `agent.py`，`run_tests.py` 全绿后 `status: implemented`，
  R01 编排器的 `ROUTING` 矩阵同步更新（**两处必须同步**，R01 模块 B5 已踩过坑）。
- **退出/降级**：`status` 改 `pending`，从 ROUTING 移除；历史任务卡与产物保留在 workspace 不删除。

## 六、与其余协议文档的关系

|---|---|
| `ORG.md`（本文） | 谁负责什么、向谁汇报、与谁交接 |

| `core/protocol.py` | 端口/任务卡/事件的字段契约 |
