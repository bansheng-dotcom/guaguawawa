# 取舍/优先级规则 · pipeline-recovery

1. **结构 → 状态 → 授权**：判定严格按此顺序。DAG 结构性错误（环/悬空边）优先级
   最高，其次运行状态（failed/upstream_failed 阻断），最后才是回填授权。前一层
   不过，后一层不讨论。

2. **失败上游是硬阻断，不是可选项**。任何 `failed`/`upstream_failed` 出现即阻断
   所有下游动作。不存在"先回填再修"的合法路径——顺序倒置是流程事故。

3. **回填 = 不可逆动作 = 必须人工授权**。R18 永远不执行回填，只产出方案 +
   handoff 声明。授权三要件（authorized=true + approver 非空 + 区间有序）缺一不可。

4. **"覆盖修复"是真命题里的伪命题**。回填能重写数据，但改不了任务逻辑。用回填
   掩盖 failed 任务，等于把 bug 埋进历史数据。

5. **越界即移交**：回填后数据的业务解释归 R06；生产库直接运维（drop/truncate）
   归 R20 + 人工。R18 的边界止于"数据稳定到达 + 方案合规"。
