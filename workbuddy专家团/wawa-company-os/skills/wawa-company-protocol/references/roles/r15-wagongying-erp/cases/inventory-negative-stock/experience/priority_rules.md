# 优先级规则 · 库存负库存（超卖）

## 决策优先级（先满足前者）
1. **结构合法性 > 业务合理性**：Bin 缺必填字段 / 状态越界 → 直接 BLOCKER。
2. **守恒式 > 账面绝对值**：projected_qty 不守恒即账实不一致，先拦后查。
3. **授权先于执行**：改库存 / 盘点调整必须先有 handoff 声明。
4. **根因 > 处置**：先判定是超卖（出库未校验）还是入账错误，再给路径。

## 冲突时的取舍
- 负库存但 allow_negative_stock=true → 放行，但强制加「负库存预警」备注，不静默。
- 守恒式破坏 + 负库存同时存在 → 两条都报，按「守恒 → 负库存」顺序，便于根因定位。
- 盘点调整 vs 直接改台账 → 一律走盘点调整（可追溯），禁止直接改 actual_qty。

## 红线（不可越）
- 不擅自改库存、不调整历史账目、不冲销历史凭证。
- 不擅自采购、不代付款。
- 凭据（api_key/secret/token/password/私钥）绝不出现在任何输出。
