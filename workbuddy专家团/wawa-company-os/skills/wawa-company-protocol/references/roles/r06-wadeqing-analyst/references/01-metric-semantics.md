# 模块A · 核心分析方法论与标准流程

本模块整合了数据分析过程中的四个核心支柱：指标语义与模型构建、数据质量与异常校验、可视化与高管交付、根因下钻与业务解释。核心主张：**无标准则无分析，无业务视角则无价值**。

---

## A1. 指标语义与口径建模

一个指标只有当下面核心问题都能被精确解答，并可被计算引擎直接执行时，才算「定义完成」，否则视为「口径未定，禁止上线/汇报」。

### 指标定义「7 问法」
1. **这是什么** —— 一句白话，业务人员一听就懂。
2. **怎么算** —— SQL / 公式 / 明确的分步逻辑，精确到字段和函数。
3. **粒度** —— 聚合的底层单位，一行代表什么（如「每账户每月」，而非模糊的「每事件」）。
4. **纳入/排除** —— 默认看不出的过滤条件（如测试单、内部账号、退款、未支付、特定渠道）。
5. **边界 Case** —— 升级如何计费、跨币种如何换算、试用期转化为付费怎么算、30天内退款怎么追溯。
6. **谁用，用于什么决策** —— 消费方是谁，决定了口径的严格程度和时效要求。
7. **多少算好** —— 业务目标值 / 告警阈值（低于多少需要介入）。

### 指标四类型
| 类型 | 定义 | 示例 |
|---|---|---|
| **Simple 简单** | 单一度量的直接聚合 | 总订单量、总活跃用户数 |
| **Ratio 比率** | 分子 ÷ 分母（二者皆聚合） | 转化率 = 支付用户数 / 访问用户数 |
| **Cumulative 累计** | 自起始时间的滚动求和 | 累计收入、历史累计下载量 |
| **Derived 派生** | 已定义指标的四则运算组合 | NRR = (期初MRR + 扩张 - 流失) / 期初MRR |

### 常见经营指标标准口径与防坑指南
- **GMV**：支付订单金额之和，**不含退款/取消**，绝不等同于净收入。区间汇总按「区间结束日」入账；退款按固定时点（退款时间 or 下单时间）归因，必须明确且全局统一。
- **净收入**：GMV − 退款（退款时点口径必须提前锁定）。
- **ARPU / ARPPU**：ARPU = 收入 / 活跃用户数；ARPPU = 收入 / 付费用户数。**核心约束**：分母与分子的时间窗口必须严格一致。
- **留存率 (D1/D7/D30)**：第 N 期仍活跃的 cohort / 期初 cohort。必须明确声明是 **bounded**（恰在第 N 期活跃，标准定义）还是 **unbounded/rolling**（第 N 期起任一时刻活跃）。行业参考：App留存粗标 D1>40% / D7>20% / D30>10%；SaaS W1>70% / W4>50%。
- **LTV (生命周期价值)**：简单版 = ARPU × 毛利率 / 月流失率。无毛利率时 = ARPU × (1 / 月流失率)。**LTV:CAC** 比例评估：<1 毁灭，1–3 边缘，3–5 健康，>5 极好或说明获客投入不足。
- **快照类 vs 求和类**：总量、库存、粉丝数取「筛选期末」最新值（禁止求和）；新增、流失、净增按时段**求和**。

### 口径对账 (Reconciliation) 容差标准
两数不一致时六大根因（按频率）：过滤条件不同 > JOIN 类型不同（导致膨胀或丢失） > 粒度不同 > 时区（UTC vs 本地） > 定义漂移 > 刷新滞后。
**容差阈值铁律**：
- 财务总账：**0%**
- 财务经营分析：**< 0.1%**
- 营销指标：**< 1%**
- 产品互动指标：**< 2%**
- 机器学习特征/标签：**< 0.5%**

## A2. 数据质量与完整性校验

任何分析结论的前提是数据可靠。所有进入分析环节的数据必须经过以下质量审计，并附带质量评分卡。

### 核心校验维度
1. **空值与完整率 (Completeness)**
   - 必须扫描核心维度和度量列。超出业务容忍度即阻断（如 `user_id` 缺失率 > 0% 为严重异常）。
2. **离群点与极值 (Outliers)**
   - 规则：IQR 1.5倍法则（`[Q1 - 1.5 * IQR, Q3 + 1.5 * IQR]`）标记异常。
   - 业务阈值：订单金额不能为负，用户年龄应在 `[0, 120]` 区间，超过即视为脏数据。
3. **重复数据 (Uniqueness)**
   - 全行级重复（Pipeline Fan-out）必须为 0%。
   - 业务主键级重复（如 `order_id`）必须为 0%，除非业务明确说明包含了版本历史记录。
4. **参照完整性 (Referential Integrity)**
   - 子表外键在父表中必须存在，计算**孤儿率 (Orphan Rate)**。如：订单表中的 `user_id` 必须在用户表中存在，孤儿率 > 0.1% 需告警。
5. **新鲜度 (Freshness)**
   - 比较数据最后更新时间戳与当前时间的 Lag。超出既定 SLA（如 T+1 任务滞后超过 24h）为不合格。

## A3. 根因下钻与异动分析 (Root Cause Investigation)

当核心指标发生显著异动（暴跌或飙升）时，采用结构化、可证伪的框架进行下钻，拒绝“我觉得”式的猜测。

### 五步下钻法
1. **验证异动真伪 (Validate)**
   - 计算最近数据点相对于滚动均值的 Z-Score。如果变化在 **±1.5个标准差**以内，归为正常波动，记录并结案。
2. **锁定时间线 (Establish Timeline)**
   - 是突变（Step Change - 提示事件驱动）还是渐变（Gradual Drift - 提示结构性变化）？
3. **指标公式拆解 (Decompose)**
   - 将指标拆解为其数学因子。例：`收入 = 流量 × 转化率 × 客单价`。先找出是哪个因子的绝对贡献度最大，再往下钻。
4. **维度下钻与贡献度 (Drill-down)**
   - 在最大影响因子下，按维度（渠道、国家、版本、用户分层）计算**绝对贡献度**。使用帕累托原则锁定 Top 影响维度。
5. **假设检验 (Test Hypotheses)**
   - 针对 Top 维度提出假设（如：iOS 新版崩溃导致某渠道转化率跌）。使用数据证伪或证实，交叉验证日志。

## A4. 可视化报告与高管交付物

交付物不应是数据的堆砌，而必须是支撑决策的逻辑闭环。向高管或业务线的交付需遵循极简主义和金字塔原理。

### SCQA 与金字塔原理
- **Situation (情景)**：一句话说明背景（我们为什么看这个数）。
- **Complication (冲突)**：业务痛点、异动或当前未决的挑战。
- **Resolution (结论/方案)**：**直接把结论写在第一行**。先亮底牌，再摆论据。
- 每个洞察必须附带量化影响（如：ARR 影响规模、受波及用户数）。

### 图表设计「无术语」原则
- **标题即结论**：图表标题不能是“各渠道转化率趋势”，而必须是“小红书渠道转化率本周大跌30%，拉低整体大盘”。
- **去噪**：去掉多余的网格线、不必要的图例和非核心数据标签。
- **凸显**：只用强调色高亮你要说的核心数据点（如异动柱子标红，其他标灰）。

### HTML 记分卡与摘要结构指南
一份标准的高管交付物（HTML 报告或摘要）必须包含：
1. **Top Insights (核心洞察)**：3-5 条影响决策的硬核结论，必须带量化指标。
2. **Business Impact (商业影响)**：明确风险、成本节省或收入机会。
3. **Evidence (数据论据)**：经过筛选的、支持核心洞察的关键图表或下钻结果。
4. **Call to Action (行动建议)**：具体到谁、在什么时间、需要做什么（如：建议产品线 A 立即回滚版本），决不能是“建议优化”。
