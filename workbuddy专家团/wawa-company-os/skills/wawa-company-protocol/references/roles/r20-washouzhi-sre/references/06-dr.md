# 06 · 灾难恢复与回滚口径（dr）
> 蒸馏自: 补充技能/01-当前能力域/anthropics__knowledge-work-plugins/operations/skills/runbook/SKILL.md
>


> 技能：`dr` ｜ 动作：`rpo_rto`（RPO/RTO 与恢复手册）、`rollback`（回滚计划）
> 来源：业务连续性/灾难恢复（DR）语义 + R20 回滚纪律

## 第一层：方法论

灾难恢复层定义**多快恢复、丢多少、谁先谁后、能否回滚**。把这段做成确定性
校验的价值，不在于"恢复得更快"，而在于**让环依赖的恢复手册和没有回滚计划的
预案进不了生产**——一个 RPO=48h 的恢复手册等于"丢了 48 小时数据也能接受"；
一个依赖图成环的恢复顺序等于"谁先谁后都动不了"。

三条方法论：

1. **灾难恢复是「预案」，不是「已发生的切换」**。本角色只校验 RPO/RTO 与
   恢复手册结构是否成立，不擅自执行灾难切换（红线 2：不擅自灾难切换）。
2. **依赖顺序必须无环**。恢复谁先谁后必须可排（Kahn 拓扑），环 = 恢复时
   死锁。没有回滚计划的恢复手册不可信。
3. **RPO/RTO 是上限不是目标**。RPO ≤ `dr.rpo_max_hours`、RTO ≤
   `dr.rto_max_hours` 是硬约束。超过上限的恢复手册等于宣布"丢了这么多
   也没关系"，这在 R20 眼里不可接受。

**本角色只校验恢复手册与回滚计划，不执行切换**。

## 第二层：可执行口径

| 判据 | 口径 | 取值来源 |
|---|---|---|
| rpo_hours | > 0 且 ≤ `dr.rpo_max_hours`（默认 4） | 恢复点目标 |
| rto_hours | > 0 且 ≤ `dr.rto_max_hours`（默认 24） | 恢复时间目标 |
| recovery_type | ∈ `dr.recovery_types`（hot/warm/cold） | 恢复类型枚举 |
| dependency_edges | 有边时 Kahn 拓扑无环 | 依赖顺序 |
| rollback_plan | 非空 | 回滚计划（硬要求） |
| rollback.steps | ≥ 1 步 | 回滚步骤 |
| 人工决策点 | human_decision_point/approver/handoff 任一非空 | 红线 2：不擅自切换 |
| 步骤顺序 | 有 after 边时无环 | 回滚顺序 |

**阈值单一真源**：`dr.recovery_types` / `dr.rto_max_hours` /
`dr.rpo_max_hours` 以 `experience/thresholds.json` 的 `dr` 段为准。

## 第三层：已验证的算例

**算例 A（干净恢复手册）**：`examples/rpo_rto.json`
```
rpo=1 / rto=4 / warm / dependencies=[db,app,cdn] /
edges=[[db,app],[app,cdn]] / rollback_plan=切回主站
```
RPO/RTO 在限内、依赖图线性无环、回滚计划非空 → `ok=true`，`verdict=PASS`。

**算例 B（脏恢复手册）**：`examples/rpo_rto_dirty.json`
```
rpo=48 / rto=100 / warm / rollback_plan=切回主站
```
BLOCKER ×2：`dr.rpo_max`（48 > 4）+ `dr.rto_max`（100 > 24）拦。

**算例 C（回滚计划）**：`examples/rollback.json` vs `rollback_dirty.json`
```
steps=[{s1,停新站},{s2,切回主站,after=s1}] + human_decision_point=true → PASS
rollback_plan="" + steps=[{s1}] + human_decision_point=false            → FAIL
```
回滚计划非空、步骤 ≥1、人工决策点是硬要求。

## 第四层：实战踩坑

1. **Kahn 实现要防"假节点"**。`_has_cycle()` 只在边两端都在 nodes 里时才建边，
   悬空边不参与拓扑——否则不存在的节点会被算进 indeg，误判成环。悬空边由
   数据完整性单独处理，两条判据分工（R18 pipeline 同款实现平移）。

2. **dependencies 为空但 edges 非空**：`_has_cycle` 里 nodes 为空时 indeg 空，
   循环不执行，`seen(0) < len(nodes)(0)` 为 False，返回无环——但这是"空图"
   不是"无环"。判据只在 `len(edges)>0` 时才追加 acyclic 检查，避免空图误报。

3. **rollback 的步骤环判据只在有 after 边时触发**。`after=""` 表示第一步，
   不参与建边。判据 `if any(e[0] for e in sedges)` 保证只有显式 after 边才
   检查环。s1.after="" 不建边，s2.after=s1 建边，线性无环。

4. **rollback_plan 在 rpo_rto 里回写为布尔，在 rollback 里回写为字符串**。
   两个动作的 `rollback_plan` 字段类型不同（rpo_rto 只记录"有没有"，rollback
   记录"内容"）。`concrete_keys` 含 `rollback_plan`，两种类型都过评审的
   concrete_artifact——因为评审只看"键是否存在"，不看类型。

5. **human_decision_point 三选一与 restore 的授权声明同构**。`bool(...) or
   bool(...) or bool(...)` 的或运算。灾难切换/回滚是不可逆动作，必须显式
   声明人工决策点。这是红线 2 在 dr 动作的具体落点。
