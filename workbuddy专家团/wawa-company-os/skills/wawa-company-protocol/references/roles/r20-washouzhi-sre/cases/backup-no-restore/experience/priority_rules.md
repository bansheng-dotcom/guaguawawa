# 取舍/优先级规则 · backup-no-restore

1. **结构 → 清单 → 演练证据**：判定严格按此顺序。备份仓结构性错误（repo 空 /
   未加密 / 排除规则非法）优先级最高，其次快照清单（≥1、id 唯一、保留策略
   白名单），最后才是恢复演练证据。前一层不过，后一层不讨论。

2. **「有快照」≠「能恢复」是硬边界，不是修辞**。快照数量再多也不能替代一次
   真实恢复演练。恢复能力只有两个硬证据：`restored_count>0` 与
   `checksum_match=true`，缺一不可。

3. **加密是备份的硬要求**。`encrypted != true` 直接 BLOCKER，不进入后续讨论。
   未声明加密的备份仓在 R20 眼里不可信。

4. **恢复与删除都是不可逆高风险动作，必须人工授权**。R20 永远不执行
   restore/forget，只产出方案 + 授权/演练/审批声明（红线 2）。

5. **越界即移交**：恢复后数据的业务含义归 R06；删除快照归 R01 审批 + 人工；
   凭据管理走密钥管理（红线 1：凭据绝不进工件）。
