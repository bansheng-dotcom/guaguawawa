## 2. 一个入口

```bash
python guagua.py report build \
  --intent "内蒙古三城水果市场调研" \
  --dir "内蒙古水果三城调研_2026-11-16_pipeline" \
  --out workspace/report_upgrade/p4_build_pipeline3 \
  --lens market --quote-mode warn
```

行为：

1. 从 `question_library` + `report_framework.match` 选问题；
2. 先算一次 coverage（输入问题）；
3. 走 v9 `analysis` 框架（`report_compose.build`）；
4. 从 `analysis_trace.json` 的 findings **反推“报告实际回答了哪些问题”**，重算 coverage；
5. 写 `coverage.json` + `manifest.json`；
6. `manifest.ok = 渲染 ok 且 coverage=COMPLETE`；
7. 门禁强制：`report_compose` 内已含 depth quality、R04、quote gate。

`--lens` 只做方法权重（market/ops/chain/fix），不改章节结构、不改门禁。

## 5. 本轮修掉的问题

1. **Q5 套壳指标**：`uniform_item_share` 原来只算不判，现在参与 `Q5_no_shell`；同一条数覆盖 ≥0.80 判 FAIL。
2. **F5 边界误判**：v9 把边界写成“结论前提”，F5 只认“边界/本节边界”；现在也认 `结论前提`。
3. **lens 漏 price 方法**：第一版 market lens 只有 3 节；补 `momentum/trajectory/economics/transmission/arbitrage/risk` 后 11 节。
4. **coverage 从 findings 反推**：不再“先拍 3 个问题再硬套”，而是用报告实际回答的 9–10 个问题算覆盖。

## 8. 建议

**先做 P4.1，再做 P5。** 理由：

1. 现在单 lens 90%，还差 1 个 finding；直接删旧结构，会丢掉“另一 lens 才有的判断”；
2. 12 条 quote gap 和 3 条反爬源没清，strict 模式下 build 仍会被拦；
3. `<31` / assumptions / 任意 `a/b` 还在，门禁仍可被“形式满足”；
4. P5 是删除，不可逆；P4.1 是收紧，可回滚。

**P4.1 建议顺序：**

1. `derived → source` 映射（让 quote gate 按断言校验）；
2. 清 `<31` / assumptions / 任意 `a/b`（先灰度，再默认）；
3. 补 12 条 quote gap（换源/降级）；
4. `target_level` 接 coverage，不再硬编码 L4；
5. 再进 P5 删 22 纲领 / 2 帧 / 3 入口。
