## 2. 三条硬规矩（写进代码，不靠提示词）

1. **意图相关度 < 0.30 → 该专家不许出场**
   相关度 = 域命中(2.0) + 域词(IDF×1.2) + 动作标签(1.5) + 技能触发词(IDF) + 能力条目(1.2)，归一到 0–1。
   泛词（分析/怎么样/变化/对比…）在生成专家卡时就被剔除，避免「一句话 20 个角色全命中」。
2. **数据齐备度 < 0.50 → 只能交 BLOCKED，并写明缺什么**
   齐备度 = 该专家的方法里有几个被 `methods.plan()` 挂上 ÷ 总数；缺的能力从 `skipped[].missing` 读。
3. **意图命中的专家全部 BLOCKED → 整份报告失败（`INTENT_UNBOUND`）**
   **不许退回「用数据能算的东西出报告」**——这是修「问招聘答水果」的关键一条。

另：专家在卡里声明 `refuses`（如 R16 不答「价格行情」）→ 即使触发词命中也被提前否决。

## 4. 没做到什么（必须写明）

1. **水果经营诊断的正文变了（哈希从 `A0357882` → `0EE0A56B`），这是 P2 的有意变更，不是回归。**
   原因：第 5 问从 `breakeven` 换成 `risk`——`breakeven` 现在归 R15（供应链），R06 不再抢答它。
   代价：单价数据的「保本提价」判断在纯经营诊断里不再自动出现，需要意图里带「提价/保本/直采」才会由 R15 出场。
   这是「谁该答」与「数据能算什么」分离后的必然结果；如果你觉得诊断也该看保本，应把 `breakeven` 加进 R06 的方法归属，而不是回退编排器。
2. **域词仍是人工维护的**（`scripts/gen_experts.py` 的 `DOMAIN_TRIGGERS`）。
   目前 20 角色共约 200 个域词，覆盖了价格/供应/人事/增长/稳定性等主要域，但**不是自动学出来的**；
   新业务域要加词，且必须重跑 `gen_experts.py`（CI 会拦漂移）。
3. **四种输入仍只打通了 data 一种**：document / research / instruction 在 `report_line` 里仍是显式报错，P3 才实现。
4. **`report_model --audit` 仍为 1**：P2 没动图型配置与维度注册表，那是 P4 的活。
