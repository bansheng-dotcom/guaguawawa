### 2.1 blocked 能力（9 个）

| 能力 | 提供者 | 原因 |
|---|---|---|
| `mvp.slice` / `mvp.prototype` / `mvp.learning` | r08 | MVP 只做执行，不进报告 |
| `mvp.launch` | r08 + r09 | 两个都不进报告 |
| `tech.spec` / `tech.test` | r09 | 工程 0/8 可进报告技能 |
| `brand.tokens` | r10 | 设计 `enters=false` |
| `integration.contract` | r17 + r09 | 自动化与工程都不进报告 |
| `integration.webhook` | r17 | 自动化 `enters=false` |

### 2.2 simulated 能力（4 个）

| 能力 | 提供者 | 原因 |
|---|---|---|
| `brand.consistency` / `brand.production` | r11 | 内容角色可做定性判断，不能当品牌硬证据 |
| `content.structure` / `content.voice` | r11 | 结构与语调是定性 claim，不带数字 |

### 2.3 关键结论

**“20 角色覆盖任何业务”在组织层成立，在报告层只对一半业务域成立：**

- 能出决策级报告：市场/需求、经营/成本、链路、风险/合规、数据/模型、可靠性；
- 部分能：客户/增长（real）、内容/品牌（simulated）；
- 不能：工程/技术、MVP/上线、系统集成（blocked）。

**这不是产线问题，是证据契约问题。** 把 22 纲领合并成 1 个，不会让 r09 的工程证据、r10 的品牌证据自动出现。

### 3.2 “任何业务” readiness（15 问）

| 指标 | 值 |
|---|---|
| coverage | **0.833** |
| verdict | **INCOMPLETE** |
| real | 12 |
| simulated | 1（`brand.consistency`） |
| blocked | 2（`tech.spec`、`integration.contract`） |
| gaps | **Q10 技术规格 / Q12 系统集成** |

**分域：**

| 域 | 状态 |
|---|---|
| 市场 / 经营 / 链路 / 风险 / 合规 | real |
| 可靠性 / 数据 / 模型 | real |
| 品牌 / 内容 | simulated |
| 技术 / 集成 | **blocked** |

**结论：** 15 问里 12 问能出硬结论，2 问必须写 gap，1 问只能写“建议/观察”。这就是“任何业务”的真实现状。

## 7. 建议

**建议进入 P3。** 理由：

1. P3 要补的 C01/C02/C08 是**证据缺口**（等级/规格、同期、单位、来源一致性），正好对应 15 问里已经 real 的域；
2. tech/integration 的 blocked 是**能力缺口**，属于 P4 扩维度/补证据契约，不是 P3 数据问题；
3. 先把 P3 做完，报告才有“可核验的证据”；否则 P4 统一的仍是“有结构、没证据”的稿子。

**P3 的第一批任务：**

1. `research_intake.verify()` 接进 `report build` 前置；
2. `sources.json` 强制 `quote` + `grade`；
3. 回填水果 13 个来源，跑 quote 校验；
4. `manifest` 增加 `quotes: {total, verified, unverified}`；
5. 规则：任一头条断言引用 `unverified` 来源时，拒绝出报告。
