# 拆卡升级 SOP（维度 × 深度 × 证据 × 语义层）

> 版本 **v1.1** · 2026-11-21（v1.0 同日）
> 适用：所有业务线（个护/酒水/奶食品/水果/调味料/预制菜…），**不绑定行业**。
> v1.1 变更：加语义层 v2（两层 + 度量代数 + 证据指纹）；加"图必须画全量基础数据"；
> 加"验证回流"；加"分支日志"与"候选拆解评分"。

## 0. 一句话

**每一问下发时必须带"6 维 × 5 层"格子表 + 案例语义层；角色交格子，不交段落；
验收看格子填没填、深度到没到、口径对不对、图能不能画出全量数据。**

v1.0 只解决了"格子填没填"；v1.1 补上"**填的东西能不能用**"——
比率被求和、粒度过期、口径混算，这些错 v1.0 抓不到。

## 1. 四个定义

### 1.1 六维网格（覆盖"广"）—— 同 v1.0

对每一问逐一判断下列维度是否适用；适用必须给格子，不适用必须写"不适用 + 原因"。

| 维度 | 追问 | 例子（Q3 内蒙品牌） |
|---|---|---|
| 对象 | 谁：品牌/企业/渠道/人群 | TOP10 + 长尾、经销商、门店 |
| 空间 | 在哪：全国/省/盟市/旗县/商圈 | 全区、呼包鄂赤、旗县 |
| 时间 | 哪期：年/季/月/周；同比环比 | 2023–2025、大促周 |
| 结构 | 怎么分：品类/渠道/价格带/人群 | 品类×渠道、价格带×渠道 |
| 机制 | 为什么：驱动与约束 | 铺货×动销×复购×导购 |
| 边界 | 什么条件下不成立；反例 | 平台口径≠线下 |

规则：六维中"不适用"最多 2 个；每适用维 ≥2 格；单问上限 24 格（超了拆问）。

### 1.2 深度阶梯（覆盖"深"）—— 同 v1.0

| 层 | 交付要求 | 门槛 |
|---|---|---|
| L1 事实 | 数 + 单位 + 期次 + 来源 | 有值 |
| L2 结构 | 拆子项或 ≥3 可比点 | 可横向比 |
| L3 机理 | 驱动/约束/传导链 | **must 题最低** |
| L4 反例 | 什么情况下不成立 | 探索题 |
| L5 前瞻 | 最小验证（谁/多久/看什么） | 行动类题 |

### 1.3 证据栏 —— 同 v1.0

`source_file` / `grade(A-D)` / `period` / `unit` / `scope` / `calc`。

### 1.4 语义层 v2（新增）—— 解决"填的数能不能用"

**先回答一个设计问题**：数据模型到底放哪？

| 方案 | 优点 | 致命问题 |
|---|---|---|
| 固定 5 张 cube（我的 v0） | 一劳永逸 | **锁死行业**，换业务线就得重做一套 |
| 纯案例 `semantic_layer.yaml`（对标的做法） | 灵活、不锁行业 | 换案例就重写，**跨案例无法复用**，度量口径各写各的 |
| **两层 v2（本版）** | 通用规则复用 + 案例只做实例化 | 需要一次性的通用层设计 |

**两层结构**：

```
交付/generic_semantics_v1.yaml          ← 跨业务线通用（度量代数、粒度、口径五要素）
        ▲ inherits
<项目>/semantic_layer.yaml            ← 案例层：实体清单、度量清单、别名、边界
```

案例层**只能实例化，不能改写**通用规则。

**核心升级：度量代数**（这是"专业"与"外行"的分水岭）

| 类型 | 可加总 | 可平均 | 典型错误 |
|---|---|---|---|
| `flow` 流量（零售额、销量） | ✅ | ⚠️仅同粒度 | 跨月相加当月 |
| `stock` 存量（库存、门店数） | ❌跨期 | ❌ | 把 12 个月库存加总 |
| `ratio` 比率（同比、份额、均价） | ❌ | ❌ | **把各品牌份额加起来当总份额** |
| `index` 指数（价格指数） | ❌ | ❌ | 直接平均 |

**口径五要素**：分母 / 范围 / 期次 / 币种 / 名义或实际。缺一项，这个数就不能跨源比较。

**证据指纹**：`(measure_id, region, category, channel, period)` 相同 = 同一条事实，
可跨报告复用；口径/期次变了才失效。这就是"续接"的正确形态——**复用事实，不复用结论**。

模板见 `交付/semantic_layer.template.yaml`。

## 2. 角色与职责

| 角色 | 职责 | 不做 |
|---|---|---|
| **R01 拆卡** | 六维网格；定深度目标；**维护案例语义层**；生成 2–3 种拆法并评分选一 | 不替角色填格 |
| **执行角色** | 按格采数；填不了写 `unavailable`；机制格给传导链 | 不跳格、不把推断当实测 |
| **R04 验收** | 只验格子 + 语义规则（G1–G12） | 不改稿、不补格 |

## 3. 流程（S1–S8）

### S1 澄清（不变）
```bash
report clarify --intent "…" --out <项目>
report clarify --dir <项目> --answer C1=… C3=…
```
新增：clarify 输出 `must_not_start_when`（例如"品牌级区域数据缺失时，不得承诺品牌排名结论"）。

### S2 问题分层（不变）
`asks[].tier`：must / support / explore → 决定深度门槛。

### S3 候选拆解 + 评分（新增，抄 article-director 的候选机制）

对每个 must 问，R01 至少给 **2 种拆法**，按五项打分选一：

| 维度 | 权重 | 判据 |
|---|---:|---|
| 决策相关性 | 25 | 这格数据会不会改变结论 |
| 覆盖广度 | 20 | 六维覆盖数 |
| 可获取性 | 20 | 公开/平台/一手/推断 |
| 机制可证 | 20 | L3 是否有证据链 |
| 成本 | 15 | 需要几个来源、多久 |

落选的拆法写进 `decomposition_log.yaml`（为什么不选）。**只有一种拆法 = 没拆。**

### S4 生成网格（v1.0 的 S3）
`grid.json`：六维 × 格子 + 深度目标 + 每格引用的 `measure_id` / 实体 id / `period`。

### S5 出映射表并确认
```bash
report brief --dir <项目> --plan          # 带：格子数 / 深度目标 / 候选拆法数
report brief --dir <项目> --plan --confirm
```
人审先看三列：**格子数 < 8、深度目标 < L3、候选拆法 = 1** 的 must 问，退回重拆。

### S6 发卡（工单带网格 + 语义层引用）

```
## 你负责 Q3（must，L3）
语义层：本卡只能使用 semantic_layer.yaml 里已声明的度量与实体
| 维度 | 格子 | measure | 深度 |
|---|---|---|---|
| 对象 | TOP10 品牌 | share | L1 |
| 空间 | 呼包鄂赤 | share | L2 |
| 时间 | 2023/2024/2025 | share | L2 |
| 结构 | 品类×渠道 | share | L2 |
| 机制 | 铺货×动销×复购 | retail_sales | L3 |
| 边界 | 平台 vs 线下 | — | L4 |
```

### S7 收卡 + 验证回流（新增，这是 v1.1 的关键）

**不再"缺格就整卡拒收"**，而是：

```
collect → 产出 backfill_request.json
   ├── missing_cells: 缺哪几格（哪维、要什么 measure、什么期次）
   ├── conflicts:     同口径两个值，需裁决
   ├── stale:         期次超出 freshness
   └── ratio_errors:  比率被求和/平均
→ R01 定向补数（只补缺的格）
→ 只重跑受影响节（不是全篇重做）
→ 二次收卡仍缺 → 进未答清单
```

### S8 出报告（不变）
报告结构、图、口径页不动。变化只在：图下面的数据从"一个数"变成"一格矩阵"。

## 4. 门禁（G1–G12）

| 门禁 | 判据 | 不通过 |
|---|---|---|
| G1 覆盖率 | 已填格 / 应有格 ≥ 70% | 进 backfill |
| G2 深度 | must 题 ≥1 格 L3；explore ≥1 格 L4 | 退卡 |
| G3 证据 | 每格有 period/unit/source/grade；A+B ≥50% | 退卡 |
| G4 口径唯一 | 同 scope+period+measure 只能一个值 | 进 conflicts |
| G5 诚实 | unavailable 带 tried[]+why；推断不得冒充实测 | 退卡 |
| G6 结构 | 每个适用维度至少 1 格 | 退卡 |
| **G7 度量代数** | ratio 不得求和/平均；同图不得混 grain/scope | 退卡 |
| **G8 图全量** | 图的数据点数 ≥ 该 measure 声明的 grain 覆盖（多期画多期、多城画多城） | 图不合格 |
| **G9 新鲜度** | period 不早于 freshness；超期标 stale，不得唯一支撑结论 | 降级 |
| **G10 回流闭环** | backfill_request 每条都有处理结果（补/降级/删） | 不许发 |
| **G11 分支日志** | 每 must 问 ≥3 条 stop 记录（试过什么、为什么停） | 视为没深入 |
| **G12 候选拆解** | ≥2 种拆法 + 五项评分 + 落选理由 | 退回重拆 |

> G7/G8 是 v1.1 新增里最值钱的两条：
> 前者抓"把份额加起来"这类外行错，后者治"图只画一个数"。

## 5. 图合同（新增，抄 data-analysis-report-agent 的 chart_spec_pack）

每张图必须声明：

```yaml
chart:
  chart_id: c1
  claim_to_prove: "口腔 CR5 仅 33.3%，是新品牌唯一入口"
  why_visual_not_text: "七个份额的分布，文字列不出形状"
  decision_role: dominant | supporting | optional
  focus_target: "其他 66.7%"
  required_metrics: [share]
  required_annotations: ["前五累计 37.4%", "其他=长尾"]
  failure_conditions: ["口径混用平台与统计公报", "份额求和"]
  data_points: 6        # 必须等于语义层声明的粒度覆盖
```

**门禁**：`data_points` 少于应有粒度 → 图不合格（G8）。

## 6. 失败与降级

| 情况 | 处理 |
|---|---|
| 某维确实无公开数据 | 格子标 unavailable，进未答清单，不静默删 |
| 只有 C/D 级来源 | 可填，但不得作为 must 结论唯一证据 |
| 格子数 > 24 | 拆成两问 |
| L3 无证据 | 降级为 hypotheses，不得写成结论 |
| 期次过期 | 标 stale，报告注明"截至 X 期" |
| 回流一次仍缺 | 进未答清单，报告首页/口径页可见 |

## 7. 与产线的接口

```
clarify.json (Q + tier + must_not_start_when)
    │  S3 候选拆解评分 → decomposition_log.yaml
    │  S4 语义层 + grid.json
    ▼
plan.json (含 格子数 / 深度目标 / 候选数)
    │
TASK.md (网格 + measure 引用)
    │
claims.json (cells[] + chart.chart_id)
    │
collect → backfill_request.json → 定向补数 → 二次收卡
    │  G1–G12
    ▼
report（不变：叙事 + 图 + 口径页）
```

## 9. 版本

| 版本 | 日期 | 变更 |
|---|---|---|
| v1.0 | 2026-11-21 | 六维网格 + L1–L5 + 证据栏 + G1–G6 |
| v1.1 | 2026-11-21 | 语义层 v2（两层/度量代数/指纹）；G7–G12；验证回流；图合同；候选拆解 |

**变更规则**：维度与度量类型可按业务线扩展，但以下四条不许动：
1. 先定维度再采数；
2. 缺格必须显性；
3. 比率不可求和、不同粒度不可同图；
4. 图必须画出全量基础数据。
