## 0. 先读：这份 SOP 的规矩

1. **一次只推一个阶段。** 阶段没过门禁，不进下一阶段。
2. **每阶段先打 tag。** `git tag pre-Pn-YYYYMMDD`，失败可整段回滚。
3. **删除必须留痕。** 所有删除写进 `_attic/DELETED.md`（文件 / 行数 / 删除前 commit / 恢复命令）。
4. **不改口径只改结构时，产物必须逐字节可复现。** P1 的核心验收就是「删了 3000 行，报告不变」。
5. **任何门禁都不许用「人工确认」替代。** 人工点击是签字，不是判据。


### 1.2 四种输入，一条后端

| 输入 | 判定 | 专家行为 |
|---|---|---|

| `--research` | 采集型 | 抓来源 + quote 回抓校验，未命中不得引用 |
| `--input` 文件 | 评审型 | 先审后写，不改原文事实 |

### 1.3 产物

```

```

### P2.2 编排器

**做什么**：新增 `core/orchestrator.py`：

```python
def plan(intent, project_dir=None, input_path=None, research=False) -> dict:
    """返回 {domain, roster[], blocked[], reason}"""
```

规则（写死在代码里，不靠提示词）：

1. **域判定**：意图切词 → 域候选（用 `experts.yaml` 的 `triggers`），得分 < 阈值的域不选；
2. **数据齐备**：用 `methods.plan()` 的 `mounted/skipped` 对每个候选专家的 `needs.required` 求交；
3. **排序**：`score = 域相关度 × 0.6 + 数据齐备度 × 0.4`，取前 1–5 位；
4. **硬规矩**：
   - 意图相关度 < 0.3 的专家**不许出场**（防止「问招聘调数据」）；
   - `required` 缺一项 → 该专家 `BLOCKED`，写 `missing`；
   - 全员 BLOCKED → 直接返回错误，**不出报告**；
   - 出场名单与 BLOCKED 名单一并写 `decisions.json`。

**产物**：`core/orchestrator.py`、`<out>/decisions.json`。

**通过判据（这是 P2 的核心验收）**

```bash
# 期望：exit != 0；stdout 含 "INTENT_UNBOUND" 与 "缺 table.headcount"（或该专家 refuses 命中）
```

## 5. P3 · 深度叙事引擎

> **目标**：每一节都走完「观察 → 对照 → 机理 → 落点 → 证伪」，不是只有第一节。
> **工期**：2–3 天。
> **风险**：中（改写生成逻辑，但不动数据层）。

### P3.1 机理库补齐

**做什么**：`core/claims.py` 的机理函数按 finding 类型补全（当前只有 size/trend 等少数几个）。
每个机理必须返回 `(mechanism, implication, falsifier, confidence)`，且：

- `mechanism` 必须含**判别方法**（「看下一期 X 与 Y 是否反向」这类可观测动作）；
- `falsifier` 必须是**阈值或数据项**，不许「视情况而定」；
- 没有 tags 就返回空串，由门禁判「本节深度不足」，**不许编机理**。

**通过判据**

```bash
python -c "
from core import claims
import inspect
fns=[n for n in dir(claims) if n.startswith('_mech_')]
print(len(fns), fns)"     # 期望覆盖到所有 finding 类型
python -m pytest tests/test_claims.py -q   # 若有
```

### P3.2 五段链接到每一节

**做什么**：`report_compose._section_of()` / `claims.to_section()` 输出固定五段；
`decision_report` 不再只给第一节留 boundary，改为：

- 每节 `reading` 至少 3 条：观察 / 对照或机理 / 落点；
- 每节必有 `falsifier`；
- 每节 `boundary` 只在该节假设最重时出现（其余集中到末节）。

**通过判据**

```bash
# ① 结构判据：每节必须有机理与证伪
python -c "
import json
d=json.load(open('_attic/p3_ok/draft_sections.json',encoding='utf-8'))
for s in d['sections']:
    if s.get('appendix'): continue
    print(s['title'][:24], 'falsifier=', bool(s.get('falsifier')))
"

# ② 反例判据：故意删掉一节的机理，门禁必须拦
# 复制 p3_ok 的 draft，删掉第 2 节 reading 里的机理句，重跑 report_flow，必须 FAIL
```

**失败怎么办**：机理是「写出来的」不是「配出来的」——如果某个 finding 类型确实没有可写的机理，
允许该节降级为「描述节」，但必须**在标题里写清「本节只陈述事实」**，且不计入「有机理」覆盖率。

### P3.3 反模板门禁加严

**做什么**：`core/report_quality.py` 的 `research` 档：

- `Q1`（标题即判断）从 0.85 提到 0.95；
- `Q2`（有对照）从 0.50 提到 0.80；
- `Q4`（有机理）从 0.40 提到 0.70；
- 新增 `Q8`：每节证伪条件覆盖率 ≥ 0.9。

**通过判据**

```bash
python -m core.report_quality _attic/p3_ok/report.html
# 必须 PASS，且 Q2/Q4 的实测值 ≥ 新阈值
python -m core.report_quality _attic/baseline_report/report.html
# 基线报告应当 FAIL（证明新门槛真的更严）
```

**P3 杀死标准**

- 提高阈值后，**你自己认为合格的报告也过不了** → 说明阈值拍脑袋，回退到「先测 3 份真实报告再定档」；
- 机理句开始出现「因为市场变化」这类空话 → 立即停，机理必须带判别方法。

## 6. P4 · 排版 + 按数据关系选图 + PDF

> **目标**：HTML 与 PDF 同一份源；图按数据关系选型；版式有硬规则。
> **工期**：2 天。
> **风险**：低（只动呈现层，不动内容）。

### P4.1 版式令牌

**做什么**：`core/report_renderer.py` 里抽出 `styles/report.css`（或内联常量 + 注释）：

|---|---|---|
| 页面 | A4 纵向，页边距 18mm | 打印预览 |

## 7. P5 · 三层质检 + 收口

## 8. 回滚与止血

| 场景 | 动作 |
|---|---|
| 单阶段失败 | `git reset --hard pre-Pn-YYYYMMDD`（该阶段开头打的 tag） |
| 只想退某个删除 | `git show <sha>:<path> > <path>`（命令在 `_attic/DELETED.md` 里） |
| 新入口跑不出报告 | 旧入口名在 P5 前一直保留，切回即可 |
| 报告内容倒退 | 用 `_attic/baseline_report/report.md` 的哈希做回归，任何阶段都不许无故改变 |

## 9. 每阶段交付给你的东西（不是口头汇报）

每个阶段结束，交一份 `交付/SOP-Pn-验收-YYYY-MM-DD.md`，必须含：

## 10. 一页速查

```
P1 立一条线 + 删 3000 行死件      → 报告 md 哈希不变
P2 专家注册表 + 编排器            → 问招聘必须 FAIL，换意图必须换内容
P3 每节五段论证链                 → 机理/证伪逐节齐全，基线报告应被判红
P4 版式令牌 + 按关系选图 + PDF    → HTML/PDF 同源，图四件套齐
P5 三层质检 + 收一个入口名        → 三条反例必须全拦
```

**唯一不可妥协的一条**：任何阶段都不许用「放宽门禁」来换「通过」。
门禁变红只有两种合法处理——修内容，或证明该判据本身错了并写进交付说明。
