# 报告产线升级 SOP

> 版本：v1.0 · 2026-11-17
> 目标：从「22 纲领 / 3 走法 / 2 分支 / 多套口径」升级为「1 条产线 / 1 个入口 / 覆盖度驱动 / 决策级断言」
> 周期：Phase 0–5 约 12 周；Phase 6 持续
> Owner：R01 蛙全局　｜　独立验收：R04 蛙挑刺　｜　工程执行：R09 / R18　｜　数据：R06 / R05　｜　决策：创始人

---

## 0. 一句话

**先定义“决策级”，再建“能力图”，再统一“产线”。顺序反了，统一出来的只是一个更整齐的空框架。**

---

## 1. 成功标准

### 1.1 North Star（升级完成的标志）

| 指标 | 现状 | 目标 |
|---|---|---|
| 报告入口 | 4 个（run / pack / produce / research） | **1 个**（build） |
| 分支 | A/B 两分支 | **0 分支**，只有 coverage |
| 报告类型 | 22 纲领 + 3 帧 | **1 个框架 + 17+ 维度 + 可选 lens** |
| 头条断言可行动比例 | 未统计 | **≥70%** |
| 每份报告的 coverage | 未记录 | **必填**，含 gaps |
| 新业务边际成本 | 未统计 | **≤2 人日/份**（有数据前提下） |
| 结论半年命中率 | 无台账 | **开始记录**，第 2 季度出首份校准 |

### 1.2 护栏（任何阶段都不能破）

1. 不可比比较不进标题；
2. 每个头条断言必须有 `falsifier`；
3. 每个数字必须有 ref，且没有 `<31` / assumptions 绕过；
4. 每份报告必须有 `coverage` 和 `gaps`；
5. `manifest` 必须记录每道门禁是否真的执行过；
6. 旧 CLI 至少保留一个版本的兼容别名，不做 big-bang。

### 1.3 反指标（不要拿这些当成功）

- “只剩一条产线”——产线数量是手段，不是目标；
- “报告页数更多”——页数不等于深度；
- “深度分 100”——当前分数测的是形式合规，不是决策质量；
- “20 个角色都出现在报告里”——出现不等于有贡献。

## 2. 五条原则

1. **问题优先于报告类型**：先有问题树，再有章节；类型是选中的维度长出来的。
2. **覆盖度优先于分支**：不问“走 A 还是 B”，只问“问题被覆盖了多少”。
3. **断言优先于章节**：报告是 claim 的视图，不是章节的容器。
4. **数据等级优先于数字密度**：A/B/C/D 等级决定一句话能不能进标题，密度只决定可读性。
5. **结果闭环优先于文档完美**：报告发出去之后要对结果负责，否则系统不会学习。

## 3. 路线图

| Phase | 周期 | 主题 | 关键产出 | Gate（不过不进下一阶段） |
|---|---|---|---|---|
| **P0** | D1–D2 | 冻结与基线 | baseline.json、git tag | 基线可复跑 |
| **P1** | W1–W2 | 决策级定义 + ClaimCard | claim schema、10 条水果断言审计 | 10 条全部有 refs；≥3 条 `actionable=false` 有理由 |
| **P2** | W3–W6 | 能力图 + 覆盖度 | capability_graph.json、coverage.json | 每个问题映射到能力或显式缺口 |
| **P3** | W7–W9 | 数据 intake | quote 校验、来源分级、缺口清单 | 每个来源有 quote + grade |
| **P4** | W10–W12 | v9 统一 + 一个入口 | `report build`、parity 报告 | 4 份水果报告 parity ≥90% |
| **P5** | W13–W14 | 下线旧结构 | 22 纲领/2 帧/3 入口删除 | CI 全绿、文档同步 |
| **P6** | W15+ | 结果台账 | outcomes/、月度校准 | 首份命中率报告 |

> **不要跳阶段。** 尤其是不要从 P0 直接跳到 P4：P4 统一的是框架，P1–P3 填的是内容；先统一会得到一个漂亮但空的框架。

## 4. 角色与职责（RACI）

| 角色 | 职责 | 备注 |

## 6. Phase 1 — 决策级定义 + ClaimCard（W1–W2）

### 产出

- `core/claim_card.py`；
- `workspace/report_upgrade/claims_fruit.json`；
- `claims_audit.json`；
- `docs/REPORT-DECISION-GRADE.md`。

### 验收

- 10 条断言全部有 refs；

## 7. Phase 2 — 能力图 + 覆盖度（W3–W6）

### 目标

把“20 角色覆盖维度”的口号，变成一张可查询的表：**谁能回答什么问题、以什么证据、到什么状态**。

### 任务

  - 输入：`core/report_roles.classify()` + `docs/ROLE_CAPABILITY_MATRIX.md` + `configs/r*.yaml` + `prompt_profile.json`；
  - 输出：`role × question × status(real/simulated/blocked) × evidence × skills`；
  - CLI：`python guagua.py report capabilities --graph`。

  - 每个问题映射到 `report_framework.MECE_GROUPS` 与 `DIMENSIONS`；
  - 标注 `primary`（主证据）、`optional`。
- [ ] 新建 `core/coverage.py`：
  - `coverage(questions, graph)` → `{questions, capabilities, roles, gaps, coverage, verdict}`；
  - 阈值默认 0.8，可配。
- [ ] 用水果项目的 5 个问题跑 coverage，产出 `coverage_fruit.json`；
- [ ] 明确 4 个“不进报告”角色的处理：补能力，或从“报告承诺”里移除。

### 产出

- `core/capability_graph.py`；
- `core/question_library.py`；
- `core/coverage.py`；
- `workspace/report_upgrade/capability_graph.json`；

### 验收

## 8. Phase 3 — 数据 intake（W7–W9）

### 目标

把“证据可追溯”升级为“证据可核验”：没有 quote 的来源不能支撑头条断言。

### 任务

- [ ] 把 `core/research_intake.verify()` 接进主路径（`report build` 的前置步骤）；
- [ ] `sources.json` 强制 `quote` 字段；没有 quote 的来源标 `unverified` 并降级；
- [ ] `evidence_pack` 传播 `grade` A/B/C/D 与 `quote_status`；
- [ ] `manifest` 增加 `quotes: {total, verified, unverified}`；
- [ ] 回填水果项目的 13 个来源：能补 quote 的补，补不了的降级并在报告里写缺口；
- [ ] 头条断言只能引用 `verified` 且 `grade ≤ B` 的来源；C 级只能做量级判断。

- 数据 intake gate；
- 更新后的 `sources.json`；
- `workspace/report_upgrade/quote_check_fruit.json`。

### 验收

## 附录 A：ClaimCard schema

```json
{
  "id": "C07",
  "statement": "呼市富士苹果批发价是赤峰的 1.98 倍",
  "headline": true,
  "refs": ["S01#富士苹果", "S03#富士苹果"],
  "values": {"a": 14.00, "b": 6.00, "unit": "元/公斤"},
  "comparability": {
    "same_product": "unknown",
    "same_period": "yes",
    "same_unit": "yes",
    "same_channel": "yes"
  },
  "rivals": [
    {"name": "等级/规格差异", "status": "unruled", "evidence": ""},
    {"name": "市场势力/摊位结构", "status": "unruled", "evidence": ""},
    {"name": "时点/到货结构", "status": "partially_ruled", "evidence": "同日，但到货结构未知"}
  ],
  "falsifier": "同等级同规格报价差 < 20%",
  "confidence": "low",
  "grade": "C",
  "actionable": false,
  "decision": "是否按 2 倍价差做跨城套利",
  "owner": "r01",
  "expiry": "2026-12-31"
}
```

**规则：**

- `headline=true` ⇒ `actionable=true`；
- `actionable=true` ⇒ `comparability` 无 `unknown`、`rivals` 全部 `ruled/partially_ruled` 且有 evidence、`falsifier` 非空；
- `grade` ∈ {A,B,C,D}；`confidence` ∈ {low,medium,high}；
- 预测类 `expiry` 必填；
- `refs` 必须能在 evidence pack 里找到。
