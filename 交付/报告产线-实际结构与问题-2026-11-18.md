## 一、一句话

**今天真正在跑的只有一条路：`report decide` = `core/decision_report.py`。**
它先用「方法库从数据里找能算的东西」起草 3–5 个问题，再逐问作答，再把答案交给唯一渲染器出 HTML。
报告线真正触达的角色只有 **3 个**（R06 / R19 / R05，共 5 次技能调用）；R04 是第 4 个，
但它那一脚（`artifact inventory`）在闲置的 `report_compose.build()` 里，**线上不执行**。
R01 同时是作者与逐节校验者（后者以子进程 `r01/skills/s09_interpret.py` 执行）。
文档里的 A/B 分支、22 纲领、A 层/B 层、六条协作流水线，全部是它之外的第二套系统。

## 二、报告的 12 个环节（每个环节的真实环境）

```
① 入口          guagua.py report decide|build
② 数据台        analysis_desk.scan        → 项目目录变成可算观测 + 证据索引
③ 画像/挂载     methods.plan              → 57 个方法里挂上 26 个，跳过 31 个
④ 决策契约      decision.draft/validate   → 3–5 个问题（auto 时由数据能力反推）
⑤ 跑方法        methods.run               → 26 个方法产出 finding（带数字的判断）
⑥ 选图          decision.choose_chart     → 对照类型 → 17 个候选图型里选 1 个
⑦ 装配章节      report_compose._section_of → finding → 节（标题/解读/refs/表/图/边界/证伪）
⑧ 产出 draft    decision_report.build     → draft_sections.json + evidence_pack.json
⑨ 逐节过账      R01 s09_interpret sections（子进程）→ 每个数字必须能被 refs 解释
⑩ 渲染          report_flow.run → report_bridge → report_renderer（唯一 HTML 出口）
⑪ 门禁          binding / chart / quality（quality 只告警）
⑫ 落盘          report.html + report.md + manifest/binding/chart_audit/decision_trace
```

### ① 入口：三个名字，一条实现

| 名字 | 文件 | 真实行为 |
|---|---|---|
| `report decide` | `core/report_cli.py:90-104` | 真入口：`decision_report.build(min_binding=0.8)` |
| `report build` | `core/report_cli.py:68-87` | **同一个实现**，把 `min_binding` 写死 0.8，`--lens` 打 deprecation 后丢弃 |
| `report produce/research` | `core/report_cli.py:112-151` | 兼容别名，最终都转 `decision_report.build` |

`report run` 只在同时给 `--evidence` + `--draft` 时可用（`report_cli.py:154-168`）。
README 里那句 `report produce --intent … --dir … --out …`（`README.md:41`）**今天跑不出主线**：
`produce` 走的是 `cmd_produce_alias`（`report_cli.py:112`），不抛错但也不读 `--draft`，与文档不符。

### ② 数据台：项目目录 → 可算观测

`core/analysis_desk.py:439 scan()` 递归扫项目目录，跳过 `raw/out*/_archive/gates`，把 CSV/JSON 归一成
长表观测 `Obs(entity, sub, time, metric, value, unit, channel)`，同时建两样东西：

- `desk.pack`（证据包）：每个数字有 id / 单位 / 期次 / 来源文件（`analysis_desk.py:194`、`:217-226`）；
- `desk.derived`（派生量）：公式 + 实算值，供后面复算（`:228-234`）。

单位统一走 `_unit_scale()`：元/公斤 ÷2、元/500克原值（`analysis_desk.py:96-102`）。
**这是整条线最扎实的一层**：价格类口径只在这里归一，后面所有方法都吃同一份视图。

### ③ 画像与挂载：57 个方法，挂上 26 个

`methods.plan()` 按 `register_need()` 谓词判断「数据有没有到这个方法的最低要求」：

```
mounted: 26    skipped: 31
skip funnel     missing=['table.orders']
skip retention  missing=['table.retention']
skip rfm        missing=['table.retention']
skip reviews    missing=['table.reviews']
skip sla        missing=['table.sla']
skip payment_mix missing=['table.payments']
skip roi        missing=['table.spend']
...
```

（实测输出，见 `workspace/_audit_run/_probe.py`）

**环境真相**：57 个方法里 26 个是「价格/成本」族（`core/analysis_methods.py` + `core/methods/`），
另外 31 个是订单/评价/投放/工单/SLA 等「通用表」族。**一份价格数据永远只挂上价格族**，
所以不管意图写「招聘」还是「组织设计」，出来的都是同一批价格判断（第五节有复现）。

### ④ 决策契约：问题由数据能力反推，不是由意图决定

```python
# core/decision_report.py:57-67
src = decision_path or os.path.join(project_dir, "data", "decision.json")
auto = not os.path.exists(src)
if auto:
    ctr = decision.draft(intent, mounted, audience=audience)
```

`decision.draft()` 的签名是 `draft(intent, available, decision="")`（`core/decision.py:153`），
但**函数体里 `intent` 只被原样存进返回值的 `"intent"` 字段**（`:190-199`），
真正决定问题的是 `available`（挂载了哪些方法）和 `QBANK` 的 `priority`（`:53-144`）。

契约校验 `decision.validate()`（`:205-239`）只查结构性约束：
schema、问题数 3–5、`finding` 不重复、对照类型在 `CHART_POLICY` 里、图型在 48 型注册表里。
**它没有一条检查「这些问题和 intent 有关系」**。

### ⑤ 跑方法：finding = 一句带数字的判断

`core/analysis_methods.py` 每个方法返回一个 `Finding`（`:210-231`）：

```python
key / title / question / reading[] / refs[] / assumptions[] / chart / table
boundary / falsifier / so_what / actions[] / weight / meta
```

`methods.run()` 额外补两件事：证据台账（`m_ledger`）和逐方法专属 `falsifier`（`core/methods/__init__.py:102-112`）。

**环境真相**：方法是**领域写死**的。`core/analysis_methods.py` 里 `CAT_RULES` 硬编码了
白条鸡/鸡蛋/对虾/带鱼/苹果/梨… 的损耗率与冷链成本（`:44-76`），
`_score_market()` 认死了「东瓦窑」「呼和浩特」（`:321-330`），
`_ORIGIN_BAN` 认死了「活牛/育肥/羔羊」（`:88-89`）。
全仓 `core/` 里「奶酪」出现 94 处、「内蒙古」81 处、「家居百货」22 处、「呼和浩特」21 处。

### ⑥ 选图：8 种对照 → 17 个候选图型

`decision.CHART_POLICY`（`core/decision.py:40-49`）把对照类型映射到允许图型：

| 对照 | 允许图型 |
|---|---|
| compare_categories / compare_to_zero | hbar / vbar / dot / lollipop |
| compare_two_points | grouped_bar / dumbbell / slope |
| change_over_time | line / area |
| composition | stacked_bar / pct_stacked |
| distribution | dot / box / histogram |
| relationship | scatter / bubble |
| vs_threshold | bullet / target_band / vbar |

`choose_chart()`（`:295-341`）的策略是：**按 policy 顺序试第一个能适配的**。
后果是 48 型里实际只会出现 17 型，而这份水果报告只出了 3 型（hbar/line/grouped_bar），
第 5 节 breakeven「方法未产出图」——因为方法没给 `chart`（`decision_report.py:119-120` 记成缺口，不从表格凑数，这一点是对的）。

### ⑦ 装配：finding → 节

`report_compose._section_of()`（`core/report_compose.py:99-105`）优先走论证层 `claims.to_section()`，
没有 Claim 的老方法走 `_section_from()`（`:80-96`）。
每节固定带：`title`（判断，必须带数字）、`question`（决策问题）、`reading[]`（每条带 refs）、
`falsifier`（可证伪条件）、`boundary`（边界，只第一节留一处）。

`decision_report` 还会给每节补三样（`:90-123`）：
`sec["title"] = f.title`、`sec["so_what"]` 以「所以：…」收口的第 3 条解读、
`sec["question"]/sec["decision"]/sec["falsifier"]`。

### ⑧ draft：章节稿 + 证据包

`core/decision_report.py:158-178` 组装 `draft`，落 `draft_sections.json` 与 `evidence_pack.json`。
这一步的 `standfirst` 是程序拼的：

```python
standfirst = (f"{answered}/{declared} 个决策问题有证据：{first}" ...)
```

**这就是报告第一句话的来源**——不是「结论」，是「答了几问 + 第一节标题」。

### ⑨ 逐节过账：R01 自己校验自己

`report_flow.run()`（`core/report_flow.py:423-466`）是唯一能走到渲染的路径，
强制要求 `evidence + draft.sections`（`:417-420`），然后：

```python
chk = check_sections(draft, pack, out_dir)   # :433  → 子进程调 R01 interpret sections
contract = build_sections_contract(draft, pack, theme)
lay = layout_errors(contract, require_appendix=True)
ok = bool(chk.get("ok")) and not lay
if ok: files = render(contract, out_dir, ...)   # 门禁不过不落盘
```

`check_sections` → `_call_r01(["interpret","sections",...])`（`:281-300`）→ `r01/skills/s09_interpret.py::_check_sections`（`:499-667`）。
它检查 7 项：派生量公式可算、证据包有数、导语带数、≥3 节、每节标题带数+有 refs+数字可解释+图带来源、禁用词、至少一处边界。

**这是全系统最强的门禁，但它的作者是 R01，裁判也是 R01。**

### ⑩ 渲染：唯一 HTML 出口

`report_flow.render()`（`:258-278`）→ `report_bridge.render_html()` → `core/report_renderer.py`（1876 行）。
图表走 `render_chart()`（`report_renderer.py:1439-1465`）：`engine="v2"` 时用 matplotlib 出 SVG，
失败回退 v1，并用 `_CHART_STATS` 记 total/v2/v1/fallback/error（`:1426-1436`）。本次实测 4/4 走 v2。

### ⑪ 门禁：实际生效的只有三条

`decision_report.py:184-231`：

| 门 | 判据 | 失败后果 |
|---|---|---|
| `render` | `report_flow` 是否落盘 | **block** |
| `binding` | 已答/已问 ≥ `min_binding`（默认 0.8） | **block** |
| `chart` | 有图的节 ≥ 0.8 | **block** |
| `quality` | `report_quality.audit(html)` | **warn**（注释明说不能当唯一放行依据，`:184-185`） |

`report_quality.py` 两档（`PROFILES`，`:61-72`）：`research` 要 6 节/4000 字/100 数/4 图，`baseline` 要 4 节/800 字/30 数/1 图。
本次实测 **score 87.5 / 密度 83.5 / 6 节 / 4241 字 / 354 数**，过。

### ⑫ 落盘：11 个文件

```

evidence_pack.json     证据包（本次 726 条可寻址数字）
draft_sections.json    章节稿（5 节）
section_check.json     R01 逐节过账结果
binding.json           declared/answered/rows/unanswered
chart_audit.json       每节图型 + 是否过 chart_spec
quality.json           深度门禁
contract.json          渲染契约（sections）
manifest.json          总账（producer=r01，ok，gates）
report.html / report.md
```

## 四、20 个角色是怎么协作的

### 4.1 文档写的（`ORG.md`、`PROTOCOL.md`）

```
创始人
  └─ R01 蛙全局（CEO/编排）
       ├─ 执行线：R02/R03/R05/R06/... → R01 → 创始人
       └─ 独立评审线：R04 蛙挑刺 → 直接创始人（旁路 R01）
```

三条协议：
- **模式 A** 单角色五步（澄清→自查→展开→自评→汇报，`PROTOCOL.md:20-63`）
- **模式 B** 失败/越界移交（6 类触发 + handoff 字段，`PROTOCOL.md:65-98`）
- **模式 C** 多角色编排（GSD 五相环 + 任务卡六段 + 波次，`PROTOCOL.md:102-145`）

### 4.2 代码实际做的

**A. 编排侧（`guagua.py plan / dispatch`）**

```
intent → r01 plan → route(intent) → N 张 Task（六段：title/owner/intent/acceptance/
         owned_files/deps）→ 写入 workspace
     → dispatch --all → 按 deps 拓扑取 ready → runner.invoke(role, ["run","--task",id])
     → 每张卡 stdout 里的 __AGENT_RESULT__ 追写 workspace/artifacts/r01/dispatch_results.jsonl
```

`role_runtime.emit()`（`shared/role_runtime.py:75-139`）是每个角色的统一出口：落 `result.json` + `evidence.json`，
并明确「不再生成 HTML/MD 报告」。

**B. 这条编排卡在哪：结果没人读**

`dispatch_results.jsonl` 的写入在 `r01/agent.py:275-293`，注释写着「供报告内核消费」。
全仓 grep `dispatch_results` **只有这 2 处（定义 + 写入）**，没有消费者。
`report_flow.run()` 的 `results` 形参（`report_flow.py:405`）在 v10 已不读——
不给 `evidence+draft` 直接抛 `FlowError`（`:417-420`）。

**C. 报告侧：只有 3 个角色真的参与（R04 是第 4 个，但没执行）**

本次实跑 `decision_trace.json` 的 `skills` 字段：

| 调用 | 次数 | 在哪 |
|---|---|---|
| `r06 explore time_series` | 1 | `analysis_methods.py:743`（trajectory 方法） |
| `r06 describe` | 1 | `analysis_methods.py:1262` |
| `r19 eval-ci` | 1 | `analysis_methods.py:1291`（sample 方法） |
| `r06 power` | 1 | `analysis_methods.py:1299` |
| `r05 research ledger` | 1 | `analysis_methods.py:1364` |

R04 只在 `report_compose.build()` 里被调一次 `artifact inventory`（`report_compose.py:640`），

### P0 · binding 是自证的：declared 由 auto 起草，answered 由同一批 finding 决定

