# SOP：核心系统重构的容量与测试覆盖门禁（R09 蛙稳码）

## 1. 逻辑导图

```text
[异常/诉求输入] → [L1 数据与证据真实性] → [L2 维度下钻：API P99 延时]
                → [L3 外部锚点对齐] → [决策指令] → [护栏熔断] → [阶梯灰度]
```

## 2. 核心指标口径

| 指标 | 公式 | 单位 | 目标 | 告警 |
| :--- | :--- | :---: | :---: | :--- |
| API P99 延时 | `P99 响应时间（压测）` | ms | ≤ 200 | > 500 熔断降级 |
| 单元测试覆盖率 | `已覆盖行 / 总行` | % | ≥ 80 | < 60 禁止合并 |
| 跳过用例数 | `skip/xfail 计数` | 条 | 0 | ≥ 1 判假通过 |

## 3. 分步诊断动作

1. 先跑测试：确认无 skip、无假通过。
2. 看覆盖率：关键分支是否覆盖，缺口列清单。
3. 压性能：定位 P99 热点，给出优化或回滚方案。
4. 备回滚：迁移脚本必须可逆，且有验证步骤。
5. 出报告：变更点 + 风险 + 回滚路径 + 观察指标。

## 4. 门禁（不满足即阻断）

| 编号 | 触发条件 | 判定 | 处置 |
| :---: | :--- | :---: | :--- |
| G1 | 存在 skip/xfail 掩盖失败 | BLOCKER | 判假通过，拒绝合并 |
| G2 | P99 > 500ms | BLOCKER | 熔断降级，回滚变更 |
| G3 | 无回滚脚本 | BLOCKER | 禁止发布 |

## 5. 归因路径

- **L1 数据层**：先排除脏数据、断流、重复计数，确认是真实异动。
- **L2 经营层**：按维度下钻，锁定贡献度 ≥70% 的因子（本角色主维度见 KPI 表）。
- **L3 商业层**：对齐外部锚点，区分内因外因；未接入外部数据时只声明口径，不虚构大盘数字。

## 6. 禁用词与反例

- ❌「大幅提升」「表现良好」「值得期待」等无数据锚定的形容词。
- ❌ 只给建议不给阈值；只给阈值不给回滚动作。
- ❌ 把历史个案当通用结论，不做样本量说明。
