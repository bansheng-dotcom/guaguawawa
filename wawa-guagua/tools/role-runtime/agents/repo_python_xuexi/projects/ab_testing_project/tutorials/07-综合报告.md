## 一、这个模块的作用

前面6个模块已经把所有的分析做完了。07把这些串起来,**生成一份别人看得懂的报告**。

这也是你简历里能引用的东西——在GitHub上放这个项目,面试官可以点开 `data/final_report.md` 直接看到你的分析能力。

## 二、报告写给谁看

| 读者 | 他们关心什么 | 报告的哪个部分 |
|------|------------|--------------|
| **老板/VP** | 上还是不上?风险多大? | 第7章 结论与建议 |
| **产品经理** | 效果好不好?有没有副作用? | 第3章 核心指标 + 第5章 护栏 |
| **运营团队** | 对我们的影响是什么?(低线城市) | 第4章 细分分析 |
| **技术/算法** | 方法对不对?要不要复盘? | 第2章 实验设计 + 第8章 方法论 |
| **面试官** | 你脑子里有没有完整流程? | 整份报告 |

报告的核心原则:**先给结论,再给细节;数字要带解释;不确定的要明说。**

### 自动决策逻辑 (第310-330行)

```python
if gmv_r['significant'] and gmv_r['ci_lower'] > 0:
    if simpson_warning:
        recommendation = "有条件上线 -- 分城市分阶段"
    else:
        recommendation = "推荐全量上线"
elif gmv_r['significant']:
    recommendation = "延长实验周期"
else:
    recommendation = "暂不上线"
```

这个决策树虽然简化,但包含了A/B实验决策的核心逻辑:
1. 北极星显著 + CI不含0 → 可上线
2. 但如果有辛普森悖论 → 必须分策略
3. 如果北极星不显著 → 不勉强

## 六、面试完整话术

当面试官问"你做过A/B实验吗",完整回答:

> "做过。在美团优选的时候,我们想把首页「今日爆品」的选品逻辑从城市运营手动选品切换成算法个性化推荐。我负责了整个实验的设计和分析。
>
> **实验设计**:根据历史GMV数据(均值25元,标准差14元)和业务需求(MDE=2%),算出来每组至少需要17,000+用户。考虑到社区团购的T+1配送延迟和周末囤货效应,建议实验周期14天,覆盖两个完整周。指标体系分三层:北极星(GMV+件数)、护栏(履约成本率/生鲜损耗率/退货率)、探索指标。
>
> **实验前提**:AA验证阶段,对连续指标用t检验+KS检验、分类指标用卡方检验、用户画像用分布一致性检验,9项全部通过后进入正式实验。
>
> **实验结果**:GMV提升约2%,p<0.001,95%CI排除0。但护栏指标中履约成本率上升了约3%——算法推了远距离供应商的商品。
>
> **细分分析**:分城市看,一线城市GMV+7%,履约成本率反而下降;三五线城市GMV-2%,履约成本+6%。交互效应检验确认了城市等级的调节效应显著——这是典型的辛普森悖论。
>
> **根因分析**:三五线存在三个问题:团长代下单普遍→用户画像不完整、网格仓库存数据未与推荐模型打通→供给匹配断裂、团长密度低→履约半径长。这些导致算法在低线城市失效。
>
> **最终建议**:一线先全量,三五线做供给感知优化(引入本地库存约束到模型、降冷启动用户算法权重)后再测。这个分析后来沉淀成了团队的A/B实验标准流程。"
