# 01 实验设计

---

## 一、白话理解

### 你遇到的问题

产品经理:"我们做个A/B测试吧,一半用户看运营选的品,一半看算法推荐的品!"

你说好。然后产品经理问:**"要测多少用户?测多久?"**

你不能回答"随便"——但也不能拍脑袋。这就是实验设计。

### 一个例子讲清楚

假设你在美团优选的仓库,有一箱苹果。你想知道这批苹果平均重量是不是250g。

- 称1个,230g → 说明不了什么
- 称10个 → 有点参考价值,但可能碰巧拿了偏大或偏小的
- 称100个 → 基本有谱了

**称多少个 = 样本量**。样本太少,结论不可靠;样本太多,浪费时间。

但社区团购跟称苹果还不一样——每个用户的GMV波动很大(有人买10块钱,有人买100块)。**用户之间的差异越大,需要的样本越多**,这样才能"平均掉"个体差异。

### 社区团购的特殊性

你的GMV均值约25元,但标准差约14元——**标准差超过均值的一半**。对比纯电商(GMV均值45元,标准差30元),社区团购的"信噪比"更差,所以同等MDE下需要的样本量更大。

此外,社区团购有**周末囤货效应**——用户周六日下单量是工作日的1.5-2倍。如果你只测一周(周一到周五),实验结果不能代表真实情况。所以实验周期必须覆盖至少两个完整周。

## 二、核心概念

### 2.1 α 和 β — 两种错误的权衡

```
                真实情况
              有差异    无差异
             ┌────────┬────────┐
    说有差异 │   ✅   │ 假阳性  │ ← Type I Error,概率=α
    说无差异 │ 假阴性  │   ✅   │ ← Type II Error,概率=β
             └────────┴────────┘
```

**α (显著性水平) = 我愿意接受多大的"冤枉好人"风险。**

在社区团购里:
- 如果把α设得很小(比如0.01) → 你几乎不会错误地说"算法更好"(假阳性少)
  → 但代价是即使算法真的好,你也可能检不出(Type II Error变大)
- 行业惯例: α=0.05

**β = 漏掉真实效果的概率。1-β = Power(统计功效)。**

Power=0.80的意思是:如果算法真的比运营好,你有80%的概率能检测出来(20%的概率漏掉)。

### 2.2 MDE:最小可检测效应

MDE回答了:**"你至少想检出多大的效果?"**

```
MDE=2% → 如果算法真实效果是2%的GMV提升,你的实验能检测出来(Power=80%)
       → 但如果真实效果只有0.5%,你的实验检测不出——太小了,淹没在噪音里
```

MDE设多少取决于业务:
- 社区团购毛利薄(~15-20%),2%的GMV提升已经是值得做的
- 如果是品牌广告投放(ROI极低),可能MDE要设到10%才值得做

**MDE越小,需要的样本量越大**——因为你想要更精确地分辨微小的差异。

代码里的敏感性分析表清楚地展示了这个关系:
```
MDE 1.0% → 每组70,000人
MDE 2.0% → 每组17,000人
MDE 5.0% → 每组2,800人
```

### 2.3 指标体系:不是指标越多越好

社区团购A/B实验的指标设计,核心思路是:

```
北极星指标: 衡量"我们到底要什么"  → 人均GMV + 人均件数
护栏指标:   确保"我们不要牺牲什么" → 履约成本率 / 生鲜损耗率 / 退货率
探索指标:   收集信息,为下次迭代   → 爆品GMV占比 / 首单转化率
```

**为什么社区团购的护栏指标跟电商不一样?**

电商最担心的是"推荐了但转化率掉"、"客单价被拉低"。
社区团购更担心的是**履约成本**和**损耗率**。

因为社区团购是"次日达+自提"模式,每个订单要走网格仓→团长→用户三级履约。如果算法为了推GMV而推荐了远距离供应商的商品,履约成本会把利润全部吃掉。同样,如果它推了高损耗的生鲜品但当天没卖完,第二天就只能扔掉——这就是你简历里"生鲜损耗率降15%"对应的真实业务场景。

## 三、代码导读

打开 [01_experiment_design.py](../01_experiment_design.py),重点看:

### 样本量计算 (第40-65行)

```python
power_analysis = TTestIndPower()
sample_size_per_group = power_analysis.solve_power(
    effect_size=cohens_d,  # MDE/标准差
    alpha=0.05,            # 显著性水平
    power=0.80,            # 统计功效
    ratio=1.0,             # 1:1分流
    alternative='two-sided'
)
```

`cohens_d = MDE_绝对值 / 标准差 = (25×0.02) / 14 = 0.0357`

这个d值很小,意味着"信号微弱,噪音很大"——所以样本量需求大。

### MDE敏感性分析 (第70-80行)

跑7个不同的MDE值,看样本量怎么变化。这个表格是给产品经理看的——"如果你想检出1%的提升,需要14万人,我们日活不够,建议MDE设到2%。"

### 实验周期 (第95-110行)

社区团购的关键考量:
- T+1配送延迟 → 用户今天下单,明天才能拿到货 → 行为窗口2天
- 周末囤货效应 → 必须覆盖完整周 → 至少2个完整周

### 指标体系 (第115-140行)

代码里print出来的那棵树,就是社区团购指标体系的完整结构。背下来——面试必问。

## 五、面试怎么讲

**面试官:"如果让你设计一个A/B实验,你怎么确定样本量?"**

> "我主要关注四个参数:α(显著性,通常0.05)、Power(功效,通常0.80)、基准均值和标准差(从历史数据取)、以及MDE(最小可检测效应)。
>
> MDE是结合业务来定的。比如我在社区团购做爆品推荐实验时,GMV均值约25元,标准差约14元。社区团购毛利薄,2%的GMV提升就有业务价值——于是我设MDE=2%,算出来每组至少需要17,000+用户。
>
> 除了算样本量,还要考虑业务节奏——社区团购有周末囤货效应,所以实验周期必须≥2个完整周+配送延迟窗口,一般是14-16天。
>
> 另外我会在实验设计阶段就定义好指标体系:北极星(GMV+件数)、护栏(履约成本+损耗率)、探索——避免实验结束后'挑着看指标'的p-hacking问题。"

**面试官:"指标体系怎么设计的?"**

> "我参考OSM框架:先明确业务目标(Objective)——'在利润不恶化的前提下提GMV';再拆解策略(Strategy)——算法推荐影响哪些环节;最后映射到指标(Measurement)。
>
> 北极星指标是人均GMV和件数,护栏指标是履约成本率、生鲜损耗率、退货率——社区团购的特殊性在于履约链路长,推荐策略可能影响后端的成本结构。这三层指标(北极星/护栏/探索)确保我既知道'效果好不好',也知道'有没有副作用'。"
