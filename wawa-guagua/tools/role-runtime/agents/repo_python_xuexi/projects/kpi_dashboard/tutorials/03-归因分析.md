# 03 归因分析决策树

---

## 一、白话理解

### 异动监控告诉你"出问题了"。归因分析告诉你"问题在哪"。

7月GMV环比下降17.8%。这是"发生了什么"。但你需要知道"为什么"：

- 是用户不买了，还是每单买得少了？
- 是所有品类都跌，还是只有生鲜跌？
- 是所有团长都跌，还是只有头部跌？
- 是需求侧问题（天气热不想买菜），还是供给侧问题（履约成本涨了）？

**归因分析就是一层层"拆"——从整体异动拆到根因。**

### 归因的四个层次

```
GMV下降17.8%
  │
  ├── 第一层：量价拆解
  │   订单量下降? 还是客单价下降?
  │   → 订单量下降是主因(用户少了)
  │
  ├── 第二层：品类归因
  │   哪个品类拖了后腿?
  │   → 蔬菜水果下滑最严重(夏季淡季)
  │
  ├── 第三层：团长层级归因
  │   头部/中部/尾部哪个层级下滑?
  │   → 头部团长稳住了,中部和尾部团长掉量
  │
  └── 第四层：履约端归因
       履约成本率和损耗率异常吗?
       → 暴雨导致配送成本暴涨+生鲜损耗加剧
```

**最终根因：季节性(夏季高温淡季) + 供给冲击(7月暴雨)**

---

## 二、核心方法

### 2.1 量价拆解

GMV = 订单量 × 客单价。这是第一层拆解——马上能知道"量"出了问题还是"价"出了问题。

```
订单量变化: -16.2%
客单价变化: -1.9%
→ 主要是量的下降
```

**如果订单量降得多：** 用户流失/流量下滑 → 排查用户侧(拉新渠道/竞对/团长活跃度)
**如果客单价降得多：** 每单买得少了/单价低了 → 排查供给侧(品类结构/促销力度/爆品价格)

### 2.2 品类归因

不是所有品类同步涨跌——有些品类是"领头羊"，有些是"拖后腿的"。

```python
for 每个品类:
   计算该品类GMV的环比变化
   if 变化 < -10% and 该品类权重 > 15%:
      标记为"主要拖累品类"
```

### 2.3 团长层级归因

头部20%团长贡献45%的GMV。如果头部团长"掉量"，影响远大于尾部团长流失。

所以归因的分辨率是：**先看头部有没有问题，再看整体。** 因为头部出问题是紧急事件（需要人工跟进），尾部出问题是系统性趋势（需要机制调整）。

## 三、代码导读

打开 [03_root_cause.py](../03_root_cause.py)：

### 量价拆解（第55-65行）


## 四、面试怎么讲

**面试官："如果GMV突然下降15%，你怎么分析？"**

> "我不直接猜原因——我会走归因决策树：
>
> 第一层量价拆解：GMV=订单量×客单价。看哪个在降。如果订单量降得多→用户侧问题；客单价降得多→供给侧问题。
>
> 第二层品类归因：看哪个品类拖了后腿。如果是生鲜类→可能是季节性因素或质量问题；如果是标品类→可能是价格或供给问题。
>
> 第三层团长层级：重点看头部20%团长有没有掉量。头部掉量是紧急事件需要人工跟进，尾部掉量是趋势性问题。
>
> 第四层履约端：看履约成本率和损耗率有没有异常。如果履约成本飙涨→可能天气/配送问题影响了用户体验，间接导致GMV下降。
>
> 在美团优选我做过7月淡季的GMV归因——订单量降了16%，根因是季节性(高温导致生鲜需求下降)叠加供给冲击(7月中旬暴雨导致履约成本暴涨)。这个归因框架后来沉淀成了团队的标准操作指南。"
