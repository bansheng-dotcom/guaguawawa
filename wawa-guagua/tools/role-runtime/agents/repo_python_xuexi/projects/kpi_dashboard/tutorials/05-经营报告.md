# 05 月度经营分析报告

---

## 一、这个模块干什么

把前面所有的分析结果写成一份**结构化月报**。

这份报告的读者是城市总经理——他不是数据分析师，他只需要知道：
1. 上个月做得好不好(KPI达成)
2. 哪里好哪里不好(分品类/分团长)
3. 有没有风险(异动提示)
4. 下个月该做什么(建议)

---

## 二、报告结构(6段式)

```
1. 核心KPI概览
   → 一页表: 7个指标 × (实际 vs 11月 vs 环比 vs 目标 vs 达成)
   → 老板只需要扫一眼这一页

2. 品类分析
   → 7个品类的GMV+占比+损耗率
   → 运营经理看"哪个品类要加投入,哪个要减"

3. 团长分层分析
   → 头部20%/中部60%/尾部20%的GMV+活跃数+人均产出
   → BD团队看"头部团长稳不稳,要不要干预"

4. 城市等级分析
   → 一线 vs 三五线的GMV+履约成本+损耗率
   → 策略讨论: 供给约束/团长密度/用户画像差异

5. 异动与风险提示
   → 3-5条本月关键异动+等级+归因
   → 确认已知风险, 预警未知风险

6. 下月建议
   → 3-4条可执行动作
   → 不是"继续优化"这种废话 —— 每条都带具体指向
```

## 五、面试怎么讲

**面试官："你怎么做月度汇报？"**

> "我有标准的月报模板，六个部分：KPI概览(一页表)、品类分析(GMV+损耗)、团长分层(头部/中部/尾部)、城市维度(一线vs三五线)、异动和风险提示、下月建议。
>
> 每部分的结论前面写——老板可能只看第一部分。异动提示我会直接附上归因结论和影响评估，不是只丢出'履约成本率上升了'。下月建议是具体可执行的——'春节前提前2周备货,重点补速冻食品和肉禽'而不是'继续优化供给'。
>
> 这份模板我在美团优选每月都用，城市总评价'终于不用看一堆SQL结果表了'。"
