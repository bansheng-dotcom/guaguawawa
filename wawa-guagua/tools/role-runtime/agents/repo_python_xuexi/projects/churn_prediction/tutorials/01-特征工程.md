# 01 特征工程 — 从原始行为构造预测信号

---

## 一、白话理解

### 模型的好坏，80%由特征决定

给你两个用户的数据：
- 用户A：最近3天买过、30天买了9次、每次花28元、下单趋势在上升、团长很活跃
- 用户B：28天没买了、30天只买了1次、花了15元就再没来过、团长也快歇业了

**不需要机器学习，你也能判断B更可能流失。**

特征工程就是把"你看一眼就能判断"的信息，转化成模型能理解的数字。

### 四类特征解决什么问题

| 特征类别 | 解决的问题 | 示例 |
|---------|----------|------|
| RFM衍生 | 用户价值+活跃度 | recency(多久没买)/frequency(买了几次)/monetary(花了多少) |
| 行为比率 | 用户决策质量 | 点击→下单转化率、加购放弃率 |
| 时间衰减 | 趋势在变好还是变坏 | 最近一周vs前一周下单量变化、指数衰减权重 |
| 团长关联 | 外部环境 | 常去的团长是不是也在走下坡路？ |

## 二、几个关键特征的构造逻辑

### 2.1 RFM综合评分

```python
rfm_score = (R分 + F分 + M分) / 3
```
把三个维度归一化到0-100再平均。15分 = 又久又穷又低频 → 高危。

### 2.2 时间衰减：越近的行为越重要

```python
recency_score = exp(-recency_days / 7)  # 7天半衰期
```
- 1天前买过 → score=0.87
- 7天前买过 → score=0.37
- 14天前买过 → score=0.14

```python
engagement_score = recency_score × frequency_score
```
综合"最近有多活跃"和"有多频繁"。

### 2.3 高危组合：三个坏信号同时出现

```python
high_risk_combo = (recency>20天) & (趋势下降) & (团长也不稳)
```
一个坏信号可以忽略，**三个坏信号同时出现** → 极高概率流失。这种交互特征ML模型自己可能学不到（需要很深很深的树），手动构造能直接帮模型。

### 2.4 为什么需要标准化？

recency_days的范围是1-30，monetary_30d的范围是0-750。如果不标准化，逻辑回归会给monetary更大的权重（因为数字大）。**标准化让所有特征在同一个尺度上竞争。**

```python
scaler = StandardScaler()  # (x - mean) / std
X_train_scaled = scaler.fit_transform(X_train)
```
