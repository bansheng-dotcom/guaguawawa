# 03 模型评估 — AUC/PR/阈值/Lift

---

## 一、AUC：排序能力

AUC = "随机抽一个流失用户和一个非流失用户，模型给流失用户更高概率的概率。"

AUC=0.5 = 随机猜测 | AUC=0.7 = 还行 | AUC=0.8 = 不错 | AUC=0.9+ = 很好

**AUC不依赖阈值——它只衡量"排序"好不好。**

---

## 二、混淆矩阵：阈值=0.5时到底对了多少

```
              Predicted:不流失  Predicted:流失
Actual:不流失      TN               FP
Actual:流失        FN               TP
```

- Precision = TP / (TP + FP) — 标记为"高风险"的用户里，真正流失的比例
- Recall = TP / (TP + FN) — 所有真实流失的用户里，被你找到了多少

**Precision和Recall是矛盾的** — 阈值设高→Precision高但Recall低（只抓最确定的，漏掉很多）；阈值设低→Recall高但Precision低（宁可错杀一千）。

---

## 三、阈值调优

代码在0.2-0.8之间扫描阈值，找F1最大的：

```python
阈=0.5: P=0.75 R=0.53 F1=0.62  ← 只抓到53%的流失
阈=0.4: P=0.60 R=0.72 F1=0.66  ← 抓到72%,但Precision降到60%
```

**选择哪个阈值取决于业务：**
- 预算有限(只能发100张优惠券) → 选高阈值，Precision优先
- 预算充裕(可以发1000张) → 选低阈值，Recall优先

---

## 四、Lift曲线：比随机强多少

```
Top 20%用户捕获了约50%的真实流失 → Lift = 50%/20% = 2.5倍
```

翻译：用模型挑前20%用户发优惠券，比随机发多抓到2.5倍的流失。Lift>2才算有实用价值。

---

## 五、PR曲线：不均衡分类的必看指标

ROC-AUC在不均衡数据下可能"虚高"。PR曲线(Precision vs Recall)没有这个问题——因为它直接看"你预测为流失的人里有多少真的流失了"。

**如果PR曲线下面积(AP)远低于AUC，说明模型在低Recall场景下Precision很差。**
