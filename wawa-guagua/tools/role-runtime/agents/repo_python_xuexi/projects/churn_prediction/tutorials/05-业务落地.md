# 05 业务落地 — 从模型到挽留行动

---

## 一、AUC不是最终目标

你做了一个AUC=0.82的模型。然后呢？

**模型的价值 = 帮运营少发几张优惠券 + 多挽留几个用户。**

技术指标(AUC/F1)是内部评估工具，ROI才是业务语言。

---

## 二、分级干预策略

不是所有人发一样的优惠券——成本不同、收益不同。

| 风险等级 | 概率范围 | 占比 | 干预方式 | 单用户成本 |
|---------|---------|------|---------|----------|
| 极高风险 | >0.7 | ~15% | Push+短信+满20-5优惠券 | 5元 |
| 高风险 | 0.5-0.7 | ~25% | Push+社群专属爆品推送 | ~1元 |
| 中风险 | 0.3-0.5 | ~30% | 周度优惠券包,不紧急 | ~2元 |
| 低风险 | <0.3 | ~30% | 正常运营,不做干预 | 0元 |

---

## 三、ROI计算

```
极高风险用户(概率>0.7) ≈ 3,000人

不干预: 70%流失 = 2,100人流失
干预后: 假设挽留成功率30% → 挽回630人

挽留一个人价值:
  月均消费~75元 × 预期存活3个月 = LTV~225元
  但挽留回来的用户价值打折扣 → 保守估计150元

收益: 630人 × 150元 = 94,500元
成本: 3,000人 × 5元(优惠券) = 15,000元
ROI: 94,500 / 15,000 = 6.3倍
```

**这个ROI才能打动老板——不是"AUC=0.82"，而是"花1块5能挽回价值150块的用户"。**

---

## 四、TOP500名单怎么用

代码输出的 `top500_churn_risk.csv` 包含每个高风险用户的：
- 流失概率
- recency/frequency/monetary快照
- 趋势(wow_change)
- 团长风险

运营拿这个名单：
1. 先看"极高风险"的那批 — 优先用优惠券+团长私聊
2. 再看recency>20天+趋势下降的 — 这批是"确定性高危"
3. 最后看recency不高但消费下降的 — "低活跃化"用户, 不是紧急但需要关注

## 五、面试怎么讲

**面试官："你们用机器学习做过什么业务？"**

> "我做过一个用户流失预测模型。社区团购获客成本高，提前识别流失用户比事后拉回便宜5倍。
>
> 我从用户行为日志构造了30多个特征——RFM、行为比率、时间衰减、团长关联。训练了逻辑回归和随机森林，LR的测试AUC约0.82，比RF更稳定。
>
> 阈值调优后，Top20%用户能捕获约50%的真实流失。这个模型最让我意外的是'团长流失风险'这个特征排进Top5——团长的稳定性直接影响用户留存，后来我们把这作为团长考核的一个参考指标。
>
> 业务上，每周生成一份TOP500高危用户名单给运营，分级干预——极高风险的发5元优惠券+团长私聊，挽留成功率约30%。ROI账算下来是6-8倍。"
