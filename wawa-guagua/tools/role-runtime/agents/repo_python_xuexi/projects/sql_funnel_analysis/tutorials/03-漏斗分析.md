# 03 漏斗分析

---

## 一、白话理解

### 社区团购的业务漏斗

团长在微信群发商品链接 → 用户看到(impression) → 点进去看(click) → 觉得不错加购物车(add_cart) → 确认下单(order) → T+1到团长那里取货（自提）

每一步都有流失——漏斗分析就是要**找到哪一步掉了最多用户**。

### 真实业务场景

假设漏斗长这样：
```
曝光: 30,000 人
点击: 15,000 人 (50%点了)
加购:  5,000 人 (33%的点击加了购)
下单:  2,000 人 (40%的加购下单了)
```

如果"点击→加购"的转化率（33%）远低于行业水平（比如行业是50%），那问题可能出在商品详情页——图片不吸引人？价格不够诱惑？规格不合适？

**找到最弱的环节，然后针对性地优化它。** 这就是漏斗分析的价值。

## 二、SQL拆解

打开 [run_all.py](../run_all.py)，找到 `analysis_02_funnel`。

### 核心CTE：计算每个用户经历到了哪个阶段

```sql
WITH user_funnel AS (
    SELECT
        user_id,
        MAX(CASE WHEN action='impression' THEN 1 ELSE 0 END) as has_impression,
        MAX(CASE WHEN action='click' THEN 1 ELSE 0 END) as has_click,
        MAX(CASE WHEN action='add_cart' THEN 1 ELSE 0 END) as has_add_cart,
        MAX(CASE WHEN action='order' THEN 1 ELSE 0 END) as has_order
    FROM behavior_logs
    GROUP BY user_id
)
SELECT
    COUNT(*) as total_users,
    SUM(has_impression) as impression_users,
    SUM(has_click) as click_users,
    SUM(has_add_cart) as add_cart_users,
    SUM(has_order) as order_users
FROM user_funnel
```

### 逐行解释

```sql
MAX(CASE WHEN action='impression' THEN 1 ELSE 0 END) as has_impression
```

- 对每个用户，检查他所有行为里有没有 `action='impression'`
- 如果有 → `CASE WHEN` 返回1 → `MAX()` 确保最终是1
- 如果没有 → 全部返回0 → `MAX()` 最终是0
- 结果：每个用户一个0/1标记——"他有没有经历过曝光？"

**为什么用MAX而非SUM？** 因为我们要的是"是否经历过"（0/1），不是"经历了几次"。SUM也可以——如果某用户同一天点了3次，SUM=3，但MAX只会是1。对于"是否"的问题，MAX更精确。

### 按城市等级拆分的扩展

在原CTE基础上加上 `u.city_tier`：

```sql
WITH user_funnel_city AS (
    SELECT
        b.user_id, u.city_tier,
        MAX(CASE WHEN b.action='impression' THEN 1 ELSE 0 END) as has_impression,
        ...
    FROM behavior_logs b
    JOIN users u ON b.user_id = u.user_id
    GROUP BY b.user_id, u.city_tier
)
```

**JOIN users** 把用户的城市等级带进来，然后 `GROUP BY user_id, city_tier` 按用户+城市分组。结果是一线城市的漏斗和三五线城市的漏斗分开算。

## 三、输出解读

```
整体漏斗:
  团长分享曝光:    30,000  100.0%   100.0%
  用户点击:        29,996   99.99%   99.99%  ← 几乎全点了！
  加购物车:        29,169   97.24%   97.23%  ← 点击→加购掉了约2.8%
  下单:            26,897   92.21%   89.66%  ← 加购→下单掉了约8% ← 最大流失！

城市漏斗对比:
  一线: 曝光89.87% → 最终下单
  三五线: 曝光89.55% → 最终下单
  (两城市漏斗几乎一致→用户行为没有城市差异)
```

**关键发现：** 加购→下单是最大流失环节（掉8%）。为什么用户加了购物车却不下单？

可能的原因：
- 价格冲击——加购后才看到总金额，觉得贵了
- 起送门槛——社区团购有最低起送金额
- 团长服务——自提点远、团长服务态度差
- 配送时间——今天下单明天才能拿，用户等不及

**下一步分析方向：** 对"加购但未下单"的用户做特征分析——他们的客单价更低？更集中在低线城市？团长密度更低？

## 四、面试怎么讲

**面试官："写SQL分析用户行为漏斗，怎么算各环节转化率？"**

> "我会用CTE+MAX(CASE WHEN)的模式：
> 1. 先把每个用户在所有action中的最高阶段标记出来
> 2. 然后统计每个阶段的用户数
> 3. 环节转化率 = 本环节人数/上一环节人数
> 4. 整体转化率 = 本环节人数/曝光人数
>
> 在美团优选的场景下，我算过团长分享→点击→加购→下单→自提的5步漏斗。最大的流失在加购→下单（掉了约8%），分析方向是起送门槛和团长服务质量。
>
> 我还按城市等级拆分了漏斗——发现一线和三五线的转化率差异不大，说明用户*决策行为*没有城市差异，真正的差异在供给端和履约端。"
