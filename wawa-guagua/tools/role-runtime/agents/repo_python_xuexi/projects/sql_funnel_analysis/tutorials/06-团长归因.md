# 06 团长归因分析

---

## 一、白话理解

### 社区团购最核心的角色——团长

在没有算法的低线城市，**团长就是推荐引擎。** 团长在群里推荐什么，用户就买什么。所以搞清楚"哪个团长的获客能力最强"、"哪个团长在流失用户"——直接关系到GMV。

### 两种归因逻辑

| 归因方式 | 问题 | SQL逻辑 |
|----------|------|---------|
| **首次触点** | 用户第一次下单是通过哪个团长？→ 这个团长"获客" | MIN(order_date)找到首次订单的leader_id |
| **末次触点** | 用户最近一次下单是通过哪个团长？→ 这个团长"激活留存" | MAX(order_date)找到最近订单的leader_id |

**举例：** 用户通过团长A第一次下单（被A"拉新"），但后来常去团长B那里取货（因为B更近）。A的"首次触点贡献"大，B的"末次触点贡献"大。两个指标衡量了不同维度的团长价值。

## 二、SQL拆解

打开 [run_all.py](../run_all.py)，找到 `analysis_05_attribution`。

### 首次触点归因

```sql
WITH first_order AS (
    -- 每个用户的首次下单日期
    SELECT user_id, MIN(order_date) as first_date
    FROM orders GROUP BY user_id
),
first_touch AS (
    -- JOIN回orders,把首次订单的leader_id拉出来
    SELECT o.leader_id,
           COUNT(DISTINCT o.user_id) as acquired_users,  -- 获客数
           ROUND(SUM(o.total_amount),2) as attributed_gmv  -- 归因GMV
    FROM orders o
    JOIN first_order f ON o.user_id = f.user_id AND o.order_date = f.first_date
    GROUP BY o.leader_id
)
SELECT ft.*, gl.leader_name, gl.city_tier, gl.leader_density
FROM first_touch ft
JOIN group_leaders gl ON ft.leader_id = gl.leader_id
ORDER BY ft.attributed_gmv DESC
```

**关键JOIN条件：** `o.order_date = f.first_date`——只取"恰好等于首次日期"的订单。如果用户第一次在同一天下了两单（上午一单下午一单），两个leader都会计入首次触点。

### 末次触点归因

SQL完全对称，只是把MIN改成MAX、first_date改成last_date：

```sql
MAX(order_date) as last_date
...
ON o.user_id = l.user_id AND o.order_date = l.last_date
```

### 团长GMV贡献综合排名（含履约成本）

```sql
SELECT
    o.leader_id, gl.leader_name, gl.city_tier,
    COUNT(DISTINCT o.order_id) as order_count,
    COUNT(DISTINCT o.user_id) as unique_users,
    ROUND(SUM(o.total_amount),2) as total_gmv,
    ROUND(SUM(o.total_amount)*1.0/COUNT(DISTINCT o.order_id),2) as avg_order_value,
    ROUND(AVG(f.fulfillment_cost),2) as avg_fulfill_cost,
    ROUND(SUM(f.loss_amount),2) as total_loss
FROM orders o
JOIN group_leaders gl ON o.leader_id = gl.leader_id
LEFT JOIN fulfillment f ON o.order_id = f.order_id
GROUP BY o.leader_id
ORDER BY total_gmv DESC
```

**注意：** `SUM(total_amount)*1.0 / COUNT(DISTINCT order_id)` — 乘以1.0强制转浮点数。SQLite中整数除法会截断小数（`5/2=2` 而非 `2.5`）。

```

  leader_120: 获客474人, GMV 10,195 (一线, 密度low)
  leader_188: 获客415人, GMV  8,712 (一线, 密度low)

末次触点 TOP3:
  leader_54:  留存532人, GMV 12,191  ← 同时是获客+留存双料冠军
  leader_188: 留存433人, GMV  8,862
  leader_92:  留存364人, GMV  8,622

团长GMV综合 TOP3:
  leader_54:  订单1,209, 用户1,176, GMV 26,963, 客单22.3, 履约成本5.15, 损耗50.56
  leader_120: 订单1,069, 用户1,044, GMV 23,116, 客单21.6, 履约成本8.41, 损耗44.15
  leader_188: 订单1,016, 用户1,001, GMV 21,339, 客单21.0, 履约成本8.15, 损耗29.11
```

**解读：** leader_54是全能型——获客最多、留存最多、GMV最高。但注意leader_120是个一线城市团长，履约成本8.41（比leader_54的5.15高出63%）——因为一线城市团长密度低、配送距离远。

**团长的城市等级和密度分布（需要对比看）：**
- 三五线团长GMV排名更高——因为他们服务的用户更多（一线城市团购竞争更激烈）
- 低密度区域（low）也有高GMV团长——团长个人能力比位置更重要

## 四、面试怎么讲

**面试官："怎么衡量不同渠道/团长的贡献？"**

> "我做过首次触点和末次触点两种归因。首次触点衡量'获客能力'——用户第一次下单是通过谁；末次触点衡量'留存能力'——用户最近一次是通过谁。
>
> 两者结合能发现不同的团长价值：有些团长擅长拉新（首次触点GMV高但末次低，说明用户第一次来了但后来跑了），有些团长擅长维护老客（末次高但首次低）。理想的团长是两种都高——比如我分析中发现leader_54同时是获客和留存的冠军。
>
> 归因之外我还会看团长的履约成本和损耗率——GMV高但每单都亏损的团长不是好团长。"
