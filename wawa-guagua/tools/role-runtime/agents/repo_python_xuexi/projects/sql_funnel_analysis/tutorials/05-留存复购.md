# 05 留存复购分析

---

## 一、白话理解

### 增长 vs 复购——哪个更重要？

社区团购发展到今天，新客增长已经放缓（该下APP的都下了）。**复购率才是业务健康度的核心指标。**

- 次日复购率：用户今天买了，明天还会再买吗？
- 7日复购率：这周买了，下周还会来吗？
- 30日复购率：这个月买了，下个月还会来吗？

社区团购的复购跟普通电商不一样：**生鲜蔬菜是高频消费，理想的次日复购率应该是50-70%**（用户基本每天买菜）。如果这个数低于30%，说明用户不在你这儿买菜了——可能有更便宜的渠道（菜市场、超市），或者服务体验差了。

### 你的拼多多买菜经验能直接回答：

"为什么生鲜损耗率降15%对复购率有影响？" —— 用户买到过烂菜一次，就可能再也不来了。损耗和复购是因果关系。

## 二、SQL拆解

打开 [run_all.py](../run_all.py)，找到 `analysis_04_retention`。

### 次日复购率SQL

```sql
WITH first_orders AS (
    -- Step 1: 找到每个用户的首次下单日期
    SELECT user_id, MIN(order_date) as first_order_date
    FROM orders GROUP BY user_id
),
repurchase AS (
    -- Step 2: 在首次下单后，用户还有没有在第N天再次下单？
    SELECT f.user_id, f.first_order_date,
           COUNT(DISTINCT o.order_id) as day1_orders,
           julianday(o.order_date) - julianday(f.first_order_date) as day_diff
    FROM first_orders f
    LEFT JOIN orders o ON f.user_id = o.user_id
        AND o.order_date > f.first_order_date   -- 必须是在首次之后
    GROUP BY f.user_id
)
-- Step 3: 统计
SELECT
    COUNT(*) as total_first_time_users,
    SUM(CASE WHEN day1_orders >= 1 THEN 1 ELSE 0 END) as day1_repurchase,
    ROUND(SUM(...)*100.0/COUNT(*),2) as day1_repurchase_rate
FROM repurchase
```

### 关键点

**1. LEFT JOIN + 日期过滤**
```sql
LEFT JOIN orders o ON f.user_id = o.user_id
    AND o.order_date > f.first_order_date
```
LEFT JOIN保证即使没有复购的用户也会保留（day1_orders=0）。

**2. 首次订单用MIN(date)**
```sql
MIN(order_date) as first_order_date
```
注意：这个SQL假设数据表覆盖了30天——如果用户在数据周期之前就有订单，那"首次"其实是错的。真实工作中要先确认数据的时间范围。

### 按城市等级的7日复购率SQL

在原基础上加JOIN users获取city_tier：
```sql
WITH first_orders AS (
    SELECT o.user_id, MIN(o.order_date) as first_order_date, u.city_tier
    FROM orders o JOIN users u ON o.user_id = u.user_id
    GROUP BY o.user_id
),
repurchase AS (
    SELECT f.user_id, f.city_tier, f.first_order_date,
           COUNT(DISTINCT o2.order_id) as repurchase_count
    FROM first_orders f
    LEFT JOIN orders o2 ON f.user_id = o2.user_id
        AND o2.order_date > f.first_order_date
        AND julianday(o2.order_date) - julianday(f.first_order_date) <= 7
    GROUP BY f.user_id
)
```

注意多了一个条件 `<= 7`——只统计首次后7天内的复购。

## 四、面试怎么讲

**面试官："怎么计算复购率？"**

> "先找到每个用户的首次下单日期(MIN(order_date))，再去订单表查首次之后是否还有订单。关键点是LEFT JOIN——保证没有复购的用户也保留在结果中，避免分母缺失。
>
> 在社区团购场景，我算过次日/7日/30日复购率，并按城市等级和用户类型下钻。如果发现三五线用户7日复购率显著低于一线，就要排查是履约体验问题还是供给匹配问题——这跟我的履约成本分析和损耗率监控直接关联。"
