# 02 数据探索

---

## 一、白话理解

拿到数据第一件事——**先看一遍，别上来就分析。**

数据探索回答：
- 每张表有多少条记录？
- 每个品类有多少商品？均价多少？毛利率多少？
- 用户分布：一线城市 vs 三五线城市各多少？
- 行为漏斗：每天产生多少条impression/click/add_cart/order？

这些SQL虽然简单，但能帮你**快速发现数据质量问题**。比如：如果行为日志里"下单"比"加购"还多，那肯定数据有问题。

## 二、SQL拆解

打开 [run_all.py](../run_all.py)，找到 `analysis_01_exploration` 函数。

### 查询1：各表行数

```sql
SELECT 'group_leaders' as table_name, COUNT(*) as rows FROM group_leaders
UNION ALL SELECT 'users', COUNT(*) FROM users
UNION ALL SELECT 'products', COUNT(*) FROM products
UNION ALL SELECT 'orders', COUNT(*) FROM orders
UNION ALL SELECT 'order_items', COUNT(*) FROM order_items
UNION ALL SELECT 'behavior_logs', COUNT(*) FROM behavior_logs
UNION ALL SELECT 'fulfillment', COUNT(*) FROM fulfillment
```

**UNION ALL** 把7个独立查询的结果摞成一张表。注意：UNION ALL不会去重（我们也不需要去重）。如果用了UNION（不加ALL），SQL引擎会尝试去重，浪费性能。

### 查询2：各品类商品数及毛利率

```sql
SELECT category_name,
       COUNT(*) as product_count,
       ROUND(AVG(unit_price),2) as avg_price,
       ROUND(AVG(cost_price),2) as avg_cost,
       ROUND((AVG(unit_price)-AVG(cost_price))/AVG(unit_price)*100,1) as margin_pct
FROM products
GROUP BY category_name
ORDER BY product_count DESC
```

**GROUP BY + 聚合函数 = 数据分析师的日常。** 这里计算毛利率=(均价-成本)/均价。所有品类毛利率都在31-33%——社区团购毛利薄且均匀。

### 查询3：城市等级用户分布

```sql
SELECT city_tier,
       CASE WHEN city_tier='tier_1_new' THEN '一线/新一线' ELSE '三五线' END as city_label,
       COUNT(*) as user_count,
       ROUND(COUNT(*)*100.0/SUM(COUNT(*)) OVER(),1) as pct
FROM users GROUP BY city_tier
```

**关键SQL技巧：SUM(COUNT(*)) OVER()**
- `COUNT(*)` 是按组计数
- `OVER()` 窗口函数在"全表"范围计算总和
- 结果：每组的数量除以总数 = 占比

不用窗口函数的笨办法：子查询 `SELECT COUNT(*) FROM users` 然后手动除。窗口函数一行搞定。

### 查询4：行为漏斗各环节总量

```sql
SELECT action,
       COUNT(*) as cnt,
       COUNT(DISTINCT user_id) as unique_users
FROM behavior_logs
GROUP BY action
ORDER BY
  CASE action WHEN 'impression' THEN 1 WHEN 'click' THEN 2
              WHEN 'add_cart' THEN 3 WHEN 'order' THEN 4 END
```

**CASE WHEN in ORDER BY** 是自定义排序——让结果按"曝光→点击→加购→下单"的自然顺序排列，而不是字母序。

## 三、输出解读

```
各表行数:
  group_leaders     200      ← 200个团长
  users           30,000      ← 3万用户
  products           800      ← 800款商品
  orders          65,277      ← 6.5万订单
  order_items     67,287      ← 6.7万条明细(≈每单1.03个品→用户买得偏少？等下验证)
  behavior_logs  957,604      ← 96万条行为日志
  fulfillment     65,277      ← 每单一条履约记录

城市等级:
  一线/新一线: 9,667 (32.2%)  ← 美团优选用户更多在低线
  三五线:     20,333 (67.8%)

行为漏斗:
  impression: 529,770   ← 团长分享后被看到53万次
  click:      254,319   ← 约48%的用户点击了
  add_cart:   106,228   ← 约42%的点击加了购
  order:       67,287   ← 约63%的加购最终下单
```

**order_items(67,287) ≈ orders(65,277)说明大部分用户每单只买1个品。** 跟社区团购的实际行为——"用户看到爆品→单独下单这个品"吻合。

## 四、面试怎么讲

**面试官："拿到一批新数据，你先做什么？"**

> "先做数据探索——不是直接跑模型。我一般查4件事：
> 1. 各表行数——有没有空表？数据量级合理吗？
> 2. 基础聚合——品类分布、城市分布、时间范围
> 3. 关键字段的空值率和异常值——比如行为日志里有没有action_time为null？
> 4. 业务逻辑一致性——比如order_items的总金额是否≈orders的total_amount？
> 这套流程帮我快速建立对数据的认知，也能提前发现数据质量问题。"
