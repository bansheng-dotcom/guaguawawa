## W1D1：Python数据模型与容器

### 能力簇
**Python数据模型** —— 理解Python如何表示数据，掌握四种核心容器的选择和使用

### 具体知识清单

**1. 变量与赋值**
- 变量名规则（字母/数字/下划线，不能数字开头，避开关键字如`class/if/for/import`）
- 动态类型（同一变量可以先后指向不同类型，`x=1; x="hello"`合法）
- `=`是"贴标签"不是"装盒子"（引用语义，不是复制）
- `id()`查看对象身份
- 多重赋值 `a, b = 1, 2`

**2. 核心数据类型**
- `int`任意精度（不像C/Java有溢出）、`float` IEEE 754双精度（`0.1+0.2!=0.3`问题）
- `str`不可变、`bool`（`True/False`，`bool(0)=False, bool([])=False`）
- `None`空值（不是0、不是空字符串、不是False）
- `type()`查看类型

**3. 类型转换**
- `int("123")`、`float("3.14")`、`str(456)`
- 转换失败→ValueError、隐式转换 `1+2.0=3.0`

**4. list — 一排格子，有顺序，可修改**
- 创建：`[1,2,3]`、`list("abc")`、`[]`
- 索引`lst[0]`/`lst[-1]`、切片`lst[1:3]`/`lst[::-1]`、修改`lst[0]=100`
- 方法：`.append()` `.insert(idx,val)` `.extend()` `.pop(idx)` `.remove(val)` `del lst[idx]`
- `x in lst`、`len(lst)`、`.index(val)`、`.count(val)`
- 底层：动态数组，append均摊O(1)，insert/delete O(n)
- **陷阱：`lst2=lst1`不拷贝！改一个另一个也变。正确用`.copy()`或`[:]`**

**5. tuple — 一排格子，有顺序，不可修改**
- 创建：`(1,2,3)`或`1,2,3`（逗号是本质）、单元素必须`(1,)`加逗号
- 为什么有list还要tuple：①不可变=可哈希→能做dict key ②性能略好 ③语义暗示
- **陷阱：`(1)`不是tuple是int！必须`(1,)`**

**6. dict — 标签贴纸，按名字找，O(1)**
- 创建：`{"key":val}`、`dict(a=1,b=2)`、取值`d["key"]`或`d.get("key",default)`
- 赋值`d["new"]=val`（新增或覆盖）、删除`del d["key"]`/`d.pop("key")`
- 遍历：`for k in d:`/`for k,v in d.items():`/`for v in d.values():`
- 底层哈希表：查找/插入/删除均O(1)
- **陷阱：key必须是不可变类型，list不能做key**

**7. set — 不重复的袋子，无顺序**
- 创建：`{1,2,3}`、`set([1,2,2,3])`→`{1,2,3}`、空集合必须`set()`（`{}`是空dict！）
- 操作：`&| - ^`交并差对称差、`.add()/.remove()/.discard()`（不报错版）
- 用途：去重、成员检查O(1) vs list O(n)

**8. 容器选择决策树（L3关键）**
```
需要按位置取第N个？ → list(可改)/tuple(不可改)
需要按标签/名字取？ → dict
需要去重或快速判断存在？ → set
一个东西多个属性？ → dict
一堆同类型东西？ → list
需做dict的key → tuple（不可变才可哈希！）
```

## W1D2：控制流全量

### 能力簇
**程序控制流** —— 让程序自己做判断、遍历数据、处理异常

### 具体知识清单

**1. if/elif/else**
- 语法：`if 条件:` / `elif 条件:` / `else:`（冒号+缩进）
- 比较运算符：`== != > < >= <=`
- 逻辑运算符：`and or not`（短路求值：`a and b`如果a是False就不看b）
- 成员运算符：`in / not in`
- 身份运算符：`is / is not`（`x is None`不是`x == None`）
- 真值测试：`0`/`""`/`[]`/`{}`/`None`→False
- **陷阱1：`if x = 5`报错（=是赋值，==是比较）**
- **陷阱2：elif条件顺序——从上到下第一个成立就停，必须"先窄后宽"**
- **陷阱3：`if a==3 or 4`→永远True（应该写`if a==3 or a==4`）**

**2. for循环**
- 遍历list：`for item in lst:`
- 遍历dict：`for k in d:` / `for k,v in d.items():` / `for v in d.values():`
- 带索引：`for i, item in enumerate(lst):`
- 并行遍历：`for a, b in zip(lst1, lst2):`
- `range(n)` / `range(start, stop, step)`
- 嵌套for：外层走一步，内层走一轮
- 三大基本模式：**累加**(`total+=x`)、**计数**(`count+=1`)、**找极值**(`if x>max_val: max_val=x`)
- **陷阱：遍历时修改list→跳过元素或索引错乱**

**3. while循环**
- 语法：`while 条件:`
- 必须保证最终退出（否则死循环）
- for vs while：已知次数→for，未知次数/条件驱动→while
- `break`（跳出整个循环）、`continue`（跳过本轮，进入下一轮）
- `while True: if 条件: break` 模式
- **陷阱：忘了更新循环变量→死循环**

**4. 异常处理**
- `try/except ValueError:` 捕获特定异常
- `except Exception as e:` 捕获通用异常并拿到出错信息
- `finally:` 无论是否报错都执行（关文件用）
- 为什么教：数据分析中读CSV常遇格式错误，不能让整个分析崩溃

**5. 三元表达式**：`x if 条件 else y`（适合简单赋值，不要嵌套）

| L4 | 给业务逻辑→正确组织条件分支+循环+处理边界情况 |

## W1D3：函数与函数式编程

### 能力簇
**函数封装** —— 把逻辑打包复用，理解抽象的力量

### 具体知识清单

**1. 函数定义与调用**
- `def func_name(params):` + 缩进体
- 定义时不执行（只是"记菜谱"），调用时才执行（"做菜"）
- `return`返回值（没有return→返回None）
- 多返回值：`return a, b`（实际返回tuple）
- 文档字符串：`"""一句话说清楚做什么"""`（紧接着def下面）

**2. 参数全系**
- 位置参数：`def f(a, b):` → `f(1, 2)`按顺序对应
- 默认参数：`def f(a, b=10):` → `f(1)`或`f(1, 20)`，默认值必须在后面
- 关键字参数：`f(a=1, b=2)`或`f(b=2, a=1)`可以换顺序
- `*args`（可变位置参数，打包成tuple）和 `**kwargs`（可变关键字，打包成dict）
- **陷阱：默认参数如果是可变对象（list/dict）→所有调用共享同一个对象！**
  - ❌ `def f(lst=[]): lst.append(1); return lst` → 第二次调用得到`[1,1]`
  - ✅ `def f(lst=None): if lst is None: lst = []; ...`

**3. 作用域 LEGB**
- Local → Enclosing → Global → Built-in（查找顺序）
- 函数内变量（局部）外面访问不到
- 函数内可读全局变量但不可直接修改（需`global`声明）
- **陷阱：在函数里`x = 10`创建的是局部变量，不是修改全局x**

**4. lambda表达式**
- 一句话函数：`lambda x: x**2`
- 常用场景：`sorted(lst, key=lambda x: x['age'])`、`map(lambda x: x*2, lst)`
- lambda vs def：简单逻辑(<1行)用lambda，有名字/多行/复杂→用def

**5. map / filter / sorted**
- `map(func, iterable)` → 每个元素套func
- `filter(func, iterable)` → 保留func返回True的
- `sorted(iterable, key=func)` → 按func返回值排序
- 返回的是迭代器（惰性求值），需`list()`转换为list

**6. 推导式**
- 列表推导：`[x**2 for x in range(10) if x%2==0]`
- 字典推导：`{k: v*2 for k,v in d.items()}`
- 集合推导：`{x for x in lst if x>0}`
- 推导式 vs map/filter：推导式更Pythonic、可读性更好
- **陷阱：Python 3.8以前推导式变量会泄漏到外部作用域**

### 深度要求
| 级别 | 检测标准 |
|------|---------|
| L2 | 定义/调用函数、使用默认参数和关键字参数、写lambda和推导式 |
| L3 | 讲"什么时候该用函数封装""参数传递机制(不可变对象像值传递，可变对象像引用传递)""为什么默认参数不要用可变对象""推导式相比for循环好在哪"|
| L4 | 给一段100行的重复代码→正确提取成3个函数（参数设计合理、无默认参数陷阱）|

|----|------|------|---------|------|
| 1 | 基础 | 速卖通(电商) | `def calc_total(orders):`→遍历order list→返回总金额 | L2 |
| 2 | 基础 | 速卖通(电商) | `def judge_order(amount, threshold=500):`→返回"大单"/"小单" | L2 |

## W1D4：文件IO + 字符串 + 正则

### 能力簇
**数据进出与文本处理** —— 从文件读数据、清洗文本、写回文件

### 具体知识清单

**1. 文件读写基础**
- `open(path, mode, encoding='utf-8')` + `with`语句（自动关闭，比手动f.close()安全）
- mode：`'r'`读、`'w'`写（覆盖！先清空再写）、`'a'`追加、`'r+'`读写
- `f.read()`全读为一个字符串、`f.readline()`逐行、`f.readlines()`→list of str
- `f.write(str)`、`f.writelines(list_of_str)`
- **陷阱1：`'w'`模式一打开就清空原文件内容！** 
- **陷阱2：忘写`encoding='utf-8'`→Windows下中文乱码**
- **陷阱3：写CSV最好加`newline=''`防止Windows多余空行**

**2. CSV处理**
- `csv.DictReader(f)` → 每行自动变dict（第一行=表头=key）
- `csv.DictWriter(f, fieldnames=[])` + `writeheader()` + `writerows(list_of_dict)`
- **陷阱：CSV读进来的数字是字符串！！必须`int(row['金额'])`转换**

**3. JSON处理**
- `json.load(f)`读JSON文件 → dict/list
- `json.dump(obj, f, ensure_ascii=False)`写JSON文件
- `json.loads(str)`解析JSON字符串、`json.dumps(obj)`序列化为JSON字符串

**4. 字符串方法全量**
- 去空格：`.strip() / .lstrip() / .rstrip()`
- 分割合并：`.split(sep) / .rsplit() / .splitlines() / .join(iterable)`
- 查找替换：`.find(sub) / .rfind() / .index(sub) / .replace(old, new) / .count(sub)`
- 判断类：`.startswith(pre) / .endswith(suf) / .isalpha() / .isdigit() / .isalnum() / .isspace()`
- 大小写：`.lower() / .upper() / .title() / .capitalize() / .swapcase()`
- f-string格式化：`f"{金额:.2f}"`(小数位)、`f"{名字:>10}"`(右对齐)、`f"{比例:.1%}"`(百分比)

**5. 正则表达式**
- `re.search(pattern, str)` → 第一个匹配的Match对象（或None）
- `re.findall(pattern, str)` → 所有匹配结果的list
- `re.sub(pattern, repl, str)` → 替换所有匹配
- `re.split(pattern, str)` → 按正则分割
- `re.compile(pattern)` → 预编译（频繁使用时提升性能）
- 元字符：`.`任意字符 `^`开头 `$`结尾 `*`0-n次 `+`1-n次 `?`0或1次 `{n,m}`n到m次 `[...]`字符集 `[^...]`排除集 `|`或 `(...)`分组 `\d`数字 `\w`字母数字 `\s`空白 `\b`单词边界
- 贪婪 vs 非贪婪：`.*`(贪) vs `.*?`(不贪)——高频考点
- 分组与捕获：`()`捕获组 `(?:...)`不捕获 `\1`反向引用
- 前瞻后顾：`(?=...)`正前瞻 `(?!...)`负前瞻 `(?<=...)`正后顾
- 标志：`re.DOTALL`(.匹配换行) `re.IGNORECASE`(忽略大小写) `re.MULTILINE`(^$匹配行首尾)
- **陷阱：`re.search`和`re.match`区别——match只从字符串开头匹配！**

## W1D5：代码组织 + 模块化 + 生产化思维

### 能力簇
**从Notebook到可复用代码** —— 理解项目结构、模块化、环境管理、`.py`与`.ipynb`的区别

### 具体知识清单

**1. import机制**
- `import module` → 用`module.func()`
- `from module import func` → 直接用`func()`
- `from module import *` → 不推荐（污染命名空间）
- `import pandas as pd` → 别名约定
- Python搜索路径：当前目录→PYTHONPATH→标准库→site-packages
- **陷阱：文件名和标准库/第三方库重名→import出错（如`csv.py`）**

**2. 模块与包**
- 一个`.py`文件 = 一个模块
- `__name__ == "__main__"`：判断当前是被直接运行（`python xx.py`）还是被import
- 包 = `__init__.py` + 模块的文件夹（Python 3.3+ `__init__.py`可不写，但建议保留）
- 推荐项目结构：
  ```
  project/
    data/           # 原始数据（只读）
    src/            # 源代码
      __init__.py
      io.py         # 读写数据
      clean.py      # 清洗
      analyze.py    # 分析
    output/         # 输出结果
    main.py         # 入口：python main.py 跑全流程
    requirements.txt
    README.md
  ```

**3. .py vs .ipynb —— 生产化思维（v5.0新增）**
- Notebook（.ipynb）：适合探索性分析、画图、写报告、教学
- .py脚本：适合可复用逻辑、定时任务、生产环境
- 最佳实践：Notebook里探索→把核心逻辑提取成.py→Notebook里import
- 操作演示：把一个Notebook里的分析代码逐步提取→保存为.py→验证导入可用
- **什么时候用.ipynb？** 探索/画图/给老板看。**什么时候用.py？** 重复执行/定时任务/团队共享

**3.1 🔥 Jupyter Notebook 核心操作——后面W4-W16每天都要用（v6.1补全）**

W1-W2你可能还在用.py文件。但从W3开始，大部分练习和项目都在Jupyter Notebook里进行。以下操作必须熟练：

**基本操作（每天用100次）**：
- `Shift+Enter`：运行当前cell并跳到下一个。**这是你用得最多的快捷键**
- `Ctrl+Enter`：运行当前cell但不跳走（调试时常用）
- `Esc` → 进入命令模式（蓝色边框）vs `Enter` → 进入编辑模式（绿色边框）
- `Esc + A`：在当前cell上方插入新cell。`Esc + B`：在下方插入
- `Esc + M`：切换为Markdown cell（写注释用）。`Esc + Y`：切换为Code cell

**执行顺序陷阱——Jupyter最大的坑**：
- Cell左边的`[ ]`里的数字=执行顺序。**不一定是代码行号的顺序！**
- 如果你来回跳着执行cell→`[5]`可能依赖`[3]`的变量但`[3]`还没执行→变量未定义
- **解决方案**：出问题时→Kernel → Restart & Run All（清空所有状态→从头跑一遍）
- 面试级问题："为什么Jupyter里代码跑通了但.py里报错？"→因为.py是线性执行的但Notebook你跳着跑了

**Magic Commands（Jupyter专属增强）**：
```python
%timeit df.groupby('city')['amount'].mean()    # 自动多次运行测速（W2D4核心工具）
%matplotlib inline                               # 图直接显示在notebook里（默认已启用）
%pwd                                             # 当前工作目录
%ls                                              # 列出当前目录文件
%history                                         # 查看运行过的命令
```

**变量检查器**：
- 在notebook最后加一个cell→只写变量名→运行→显示该变量的值（DataFrame会渲染成表格）
- `df.head()` 快速预览→Notebook会自动渲染成HTML表格→比print好看得多

**W2D4-W16你会怎么用Jupyter**：
- 探索数据：读CSV→`df.head()`→`df.info()`→`df.describe()`——每个操作一个cell→逐步看
- 分析数据：分组→画图→统计检验——中间结果都显示→不断调整参数直到满意
- 导出报告：最后把"关键发现"整理成Markdown cell→File→Download as→HTML/PDF

**Jupyter vs VS Code .py的选择**：
- 探索/画图/做统计 → Jupyter（即时反馈）
- 定时脚本/生产代码/团队协作 → VS Code .py（版本控制友好）
- W1-W2教的.py是基础→W3+引入Jupyter是因为DA的工作流=探索先行→生产化后行

**4. 虚拟环境**
- `python -m venv venv` 创建
- `venv\Scripts\activate` 激活（Windows）/ `source venv/bin/activate`（Mac/Linux）
- `pip install pandas` 安装包
- `pip freeze > requirements.txt` 导出依赖
- 为什么用虚拟环境：不同项目不同依赖版本互不冲突，不污染系统Python

**5. 代码风格PEP 8**
- 缩进：4个空格（不要用Tab！）
- 行宽：≤79字符（docstring/注释≤72）
- 命名：`snake_case`变量和函数、`CamelCase`类名、`UPPER_CASE`常量
- 函数之间空两行，类之间空两行
- docstring：每个函数至少一行"""做什么"""
