### AB 面试完整 Q&A

**Q: SRM 为什么放在第一步？**

> "SRM(Sample Ratio Mismatch) = 实际分流比例偏离预期——比如预期 50/50——实际 48/52。SRM 放在第一步——因为如果 SRM 失败——说明随机化出了问题——后续所有分析(包括 CUPED、t-test)都基于'随机化成功'的假设——假设不成立——分析结果无效。所以必须在分析前检查 SRM——SRM 失败->暂停实验->排查根因->不要继续分析。"

**Q: MDE 减半为什么 n 翻 4 倍？**

> "样本量公式——n 正比于 1/MDE^2。MDE 从 2% 降到 1%(减半)——MDE^2 从 4 变成 1(变为 1/4)——所以 n 需要翻 4 倍。这个平方关系是 AB 实验中最重要的量级直觉——'我想检测更小的效应'的代价是指数级的——不是线性的。所以 MDE 不是'越小越好'——是在'商业上可接受的精度'和'实验成本(时间+用户数)'之间做 trade-off。"

**Q: CUPED 方差缩减多少——能举个例子吗？**

> "方差缩减比例约等于 rho^2——实验前协变量 X 和实验后指标 Y 的相关系数的平方。如果 rho=0.7——方差缩减约 49%——相当于样本量减半(因为 n 正比于方差)。rho=0.5——缩减 25%。rho=0.3——缩减 9%——效果不明显。这就是为什么选协变量很重要——选和 Y 高度相关的实验前指标——不是随便选一个'实验前的数据'。"

**Q: 三段式决策——为什么要分三段——不能一次看完吗？**

> "因为每多偷看一次——假阳性率累积——alpha 膨胀。看 1 次——alpha=0.05。看 5 次——alpha 膨胀到约 0.14。看 10 次——alpha 膨胀到约 0.19。三段式决策——只在三个预设时间点做决策——(1)安全护栏(1-2 天——只看护栏指标——不看效果)——(2)中期检查(样本量 50%——看效果方向——不做最终决策)——(3)最终决策(样本量 100%——唯一一次 alpha=0.05 的正式检验)。三段式在'及时发现严重问题'和'控制假阳性率'之间找平衡。"

### SQL 面试模拟——完整评分卡

**第 1 轮: SQL 技术面——30 分钟——4 题**

**题 1——手写连续登录 SQL(5 分钟——10 分):**
WITH numbered AS (SELECT user_id, login_date, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) AS rn FROM logins),
grouped AS (SELECT user_id, login_date, login_date - rn * INTERVAL '1 day' AS grp FROM numbered)
SELECT user_id, COUNT(*) AS days FROM grouped GROUP BY user_id, grp HAVING COUNT(*) >= 3;

评分要点: CTE 分层清晰(2 分)——差值法正确(3 分)——知道同天多条记录的坑(2 分)——能解释为什么差值法有效(3 分)。

**题 2——窗口函数 SUM OVER PARTITION + ROWS(3 分钟——10 分):**
SELECT user_id, order_date, amount, SUM(amount) OVER (PARTITION BY user_id ORDER BY order_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS cumsum FROM orders;

评分要点: 显式写 ROWS(5 分)——不是默认 RANGE——能解释 ROWS vs RANGE 的区别(5 分)。

**题 3——说出 >= 5 个 SQL 坑(2 分钟——10 分):**
NOT IN+NULL——LEFT JOIN+WHERE——窗口无 ROWS——COUNT(column) vs COUNT(*)——隐式类型转换。每个 2 分——含错误+根因+解法。

**题 4——追问 NOT IN+NULL 为什么结果为空(1 分钟——10 分):**
NOT IN = <> ALL——任何值与 NULL 比较 = UNKNOWN——WHERE UNKNOWN 不返回任何行。解法——子查询加 IS NOT NULL——或改用 NOT EXISTS。

**Q1: 画出因果推断方法决策树(3 分钟)**

```
能随机化吗？

          ├── 有+无对照组 → Causal Impact / ITS

                              ├── 能 → PSM(核心:CIA/无未观测混淆)
                              └── 不能 → 有工具变量吗(F>10)?
                                        ├── 有 → IV(核心:外生性+相关性)
                                        └── 没有 → 相关性分析(非因果推断)
```

**Q2: DID——平行趋势怎么检验？不成立怎么办？(3 分钟)**

检验——三层次——(1)视觉——处理前趋势图——肉眼判断大致平行 (2)统计——事件研究法——处理前每个时间点生成虚拟处理变量——如果任何处理前交互项系数显著——平行趋势被拒绝——联合 F 检验——(3)稳健性——逐个去掉最早的时间点——确认 ATT 稳定。

不成立——四种应对——(1)检查特殊事件——在报告中解释——(2)加 group-specific time trend——(3)Synthetic Control——(4)CSDID。

**Q3: PSM——核心假设是什么？不成立怎么办？(2 分钟)**

核心假设——CIA——所有混淆变量都被观测到了——不存在未观测混淆。不可检验——三件事增强可信度——(1)SMD<0.1——(2)Rosenbaum 敏感性——(3)多方法验证。

**Q4: 辛普森悖论——怎么检测？(2 分钟)**

simpson_scan()——自动对比分组结论和合计结论是否方向相反。如果相反——在报告中同时展示分组和合计——解释为什么看起来矛盾——告诉 PM 哪个数字反映她关心的用户群。

### 弱项补强——常见的 5 个面试卡壳点——提前准备

**卡壳 1——被问"p 值是什么"——背出了定义——面试官追问"为什么 p<0.05 不等于 95% 概率"——卡住了。**

准备: P(地面湿|下过雨)不等于 P(下过雨|地面湿)——地面湿还可能是洒水车。同理——P(p<0.05|H0为真)不等于 P(H0为真|p<0.05)。提前准备这个比喻——面试时脱口而出。

**卡壳 2——被问"CUPED 的 theta 为什么在对照组算"——知道答案——但说不清楚。**

准备: "实验组的 Y 含有实验效应——如果用全量(control+treatment)估计 theta——theta 会吸收部分实验效应——导致 Y_adj 把实验效应减掉了一部分——ATT 被低估。极端情况——实验效应很大——全量 theta 可能比对照组 theta 大很多——ATT 可能被减到零。所以必须在对照组估计——因为对照组的 Y 不含实验效应。"

**卡壳 3——被问"你的项目有什么局限"——只说"数据量不够大"——太泛。**

准备: 选具体局限——"鲜果多 DID 的局限——DID 只控制了时间不变和单位不变的未观测因素——不控制时变的未观测因素。比如北京 9 月同时上线了另一个促销活动——这个活动的影响会被 DID 归因到 AI 推荐上。我在报告中标注了这个局限——并建议用 CSDID 或 Causal Forest 做异质性处理效应分析。"

**卡壳 4——被问"你和计算机专业的人有什么区别"——不知道怎么说。**

准备: "计算机专业的人擅长'造工具'——我擅长'用工具解决业务问题——并把解决方案工程化'。我的代码不如他们的高效——但我的代码有业务口径(分子/分母/时间窗口)、有数据溯源(从邮件能追溯到 SQL)、有分析报告(结论先行+三版本翻译)。他们造了一把好刀——我知道该切哪块肉。"

**卡壳 5——被问"你最大的弱点是什么"——说"我太追求完美"——太假。**

准备: "我的代码性能优化经验还不够——虽然 W23 做了 profiling——从 15 分钟优化到 2 分钟——但那是在百万级数据上——如果是亿级数据——我还没实际做过。不过我已经在 README 中标注了每个操作的数据量阈值和 Hive 迁移方案——当数据量超过阈值时——我知道该怎么做——只是还没在生产环境中做过。"
