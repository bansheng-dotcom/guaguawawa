### cron 的完整使用指南——从零到自动化

**cron 的三大坑 + Python 解法:**

**坑 1: 环境变量不同。** cron 的 PATH 是 /usr/bin:/bin——不含 Python venv 路径。解法——在 cron 命令中显式调用 venv 里的 python 解释器：

```bash
# crontab -e
0 8 * * * cd /path/to/project && /path/to/venv/bin/python main.py >> output/cron.log 2>&1
```

**坑 2: 工作目录不同。** cron 从 $HOME 目录执行——不是你的项目目录。你的代码里 `pd.read_csv('data/orders.csv')` 会找不到文件——因为当前目录不是项目根目录。解法——先 cd 到项目根目录——或者在 Python 代码里用绝对路径。

**坑 3: 失败了你不知道。** cron 不报错——除非你主动把输出重定向到日志文件。解法——`>> output/cron.log 2>&1`——stdout 和 stderr 都写入日志——每天早上检查日志文件。

**cron 表达式速查:**

```
分钟 小时 日 月 星期
0    8    *  *   *      # 每天早上 8:00
0    8    *  *  1-5    # 工作日早上 8:00
0    */4  *  *   *      # 每 4 小时
30   9    1  *   *      # 每月 1 号早上 9:30
0    8    1  *   1      # 每月 1 号且周一早上 8:00
```

**脚本封装——scripts/run_daily.sh——让 cron 调用的是一行脚本而不是复杂的命令:**

```bash
#!/bin/bash
# scripts/run_daily.sh——供 cron 调用
set -e  # 任何命令失败立即退出

cd /path/to/xianguoduo
source venv/bin/activate
python main.py --mode=daily
echo "[$(date)] Daily run completed" >> output/cron.log
```

### 告警策略的设计原则——不是"每个 warning 都告警"——是"按严重程度分级"

**告警的三级体系——从信息到紧急:**

| 级别 | 事件 | 通知方式 | 谁收到 | 期望响应时间 |
|------|------|---------|--------|-----------|
| INFO | 日报成功完成 | 不通知——只记录日志 | — | — |
| WARN | 数据量比昨天少 30% | 日志标注 WARNING | 分析师自己检查 | 当天 |
| ERROR | 管道执行失败 | 邮件告警 | 分析师 | 2 小时内 |
| CRITICAL | 连续 3 天管道失败 | 邮件+即时消息 | 分析师+leader | 立即 |

**不要犯的错误——"每个异常都发邮件——结果每天收到 50 封告警——习以为常后——真正的告警被埋没了。"** 告警的设计原则——信息密度 > 告警数量。一封邮件 = 一个需要人工介入的事件。如果不需要人工介入——不应该是告警——应该是日志。

```python
def alert_if_needed(issues: list, consecutive_failures: int):
    """按严重程度分级告警——不是一刀切的'有错就发邮件'。"""
    if not issues:
        return  # 一切正常——不告警

    if any(i['severity'] == 'critical' for i in issues):
        send_alert_email(subject='[CRITICAL] 日报管道严重异常', body=format_issues(issues))
    elif consecutive_failures >= 3:
        send_alert_email(subject='[WARN] 日报管道连续 3 天异常', body=format_issues(issues))
    elif any(i['severity'] == 'error' for i in issues):
        send_alert_email(subject='[ERROR] 日报管道异常', body=format_issues(issues))
    else:
        logger.warning('管道有 WARN 级别的问题——未触发邮件告警: %s', issues)
```

### 任务失败告警的完整实现

```python
import smtplib
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart
import logging
import traceback

logger = logging.getLogger(__name__)

def send_alert_email(subject: str, body: str, to_email: str = None):
    """管道失败时发送告警邮件。

    使用 QQ 邮箱 SMTP——需要先在 QQ 邮箱设置中开启 SMTP 并获取授权码。
    授权码不是 QQ 密码——是 QQ 邮箱生成的 16 位一次性密码。
    """
    smtp_server = 'smtp.qq.com'
    smtp_port = 587
    from_email = os.getenv('ALERT_EMAIL_FROM', 'your_email@qq.com')
    password = os.getenv('ALERT_EMAIL_PASSWORD', '')  # QQ 邮箱授权码——不是密码
    to_email = to_email or os.getenv('ALERT_EMAIL_TO', from_email)

    msg = MIMEMultipart()
    msg['From'] = from_email
    msg['To'] = to_email
    msg['Subject'] = f'[鲜果多告警] {subject}'
    msg.attach(MIMEText(body, 'plain', 'utf-8'))

    try:
        with smtplib.SMTP(smtp_server, smtp_port) as server:
            server.starttls()
            server.login(from_email, password)
            server.send_message(msg)
        logger.info(f'告警邮件已发送至 {to_email}')
    except Exception as e:
        logger.error(f'告警邮件发送失败: {e}')


def run_main_with_alert():
    """带告警的 main() 包装器——任何未处理异常触发邮件告警。"""
    try:
        main()
        logger.info('日报流程成功完成')
    except Exception as e:
        error_detail = traceback.format_exc()
        logger.exception('日报流程失败')

        # 发送告警邮件——含完整 traceback
        body = f'鲜果多日报执行失败\n\n错误: {str(e)}\n\n完整 Traceback:\n{error_detail}'
        send_alert_email(subject='日报执行失败', body=body)
        raise


if __name__ == '__main__':
    run_main_with_alert()
```

**告警的设计原则——不是"每个 warning 都发邮件"——是"只有需要人工介入的才告警":**

| 事件 | 是否告警 | 原因 |
|------|---------|------|
| 管道全部成功 | 否——只记录日志 | 正常——不需要打扰任何人 |
| 管道失败（数据加载） | 是——发邮件 | 需要人工检查——数据源可能有问题 |
| 管道失败（依赖缺失） | 是——发邮件 | 需要人工修复——pip install 某个包 |
| 数据量异常低（比昨天少 50%+） | 是——发邮件 | 可能是数据源问题——也可能是业务突变——需要判断 |
| 数据量正常波动（+-10%） | 否——只记录日志 | 正常波动——不需要告警 |

### DAG 设计模式——在 Python 中实现并行/条件分支/重试

```python
import time
import logging
from concurrent.futures import ThreadPoolExecutor

logger = logging.getLogger(__name__)

def run_with_retry(func, max_retries=3, wait_seconds=30, **kwargs):
    """带重试的函数执行——失败后等待 wait_seconds 再试——最多 max_retries 次。"""
    for attempt in range(1, max_retries + 1):
        try:
            return func(**kwargs)
        except Exception as e:
            if attempt == max_retries:
                logger.error(f"{func.__name__} 失败 {max_retries} 次——放弃")
                raise
            logger.warning(f"{func.__name__} 第 {attempt} 次失败——{wait_seconds}s 后重试: {e}")
            time.sleep(wait_seconds)


def run_daily_pipeline():
    """日报 DAG——含并行加载+条件分支+重试逻辑。

    DAG 结构:
    load_orders ──┐
                   ├──> clean_data ──> analyze ──> report
    load_users  ──┘
    """
    # 并行: load_orders 和 load_users 同时进行——互不依赖
    with ThreadPoolExecutor(max_workers=2) as executor:
        orders_future = executor.submit(run_with_retry, load_orders, max_retries=2)
        users_future = executor.submit(run_with_retry, load_users, max_retries=2)
        orders = orders_future.result()
        users = users_future.result()

    # 顺序: clean 依赖 load 的结果
    clean = run_with_retry(clean_data, orders=orders)

    # 条件分支: 数据量决定分析深度
    if len(clean) < 1000:
        logger.info("数据量 < 1000——走快速分析路径")
        metrics = quick_analysis(clean)
    else:
        logger.info("数据量 >= 1000——走完整分析路径")
        metrics = full_analysis(clean)

    # 生成报告 + 发邮件
    report_path = generate_report(metrics)
    email_daily_report(report_path)

    return metrics
```

### 日报自动化的完整 shell 脚本——从 cron 到邮件

```bash
#!/bin/bash
# scripts/run_daily.sh——供 cron 调用的日报全流程脚本
set -e
PROJECT_DIR="/path/to/xianguoduo"
cd "$PROJECT_DIR"

LOG_FILE="output/cron.log"
echo "========================================" >> "$LOG_FILE"
echo "[$(date '+%Y-%m-%d %H:%M:%S')] Daily pipeline started" >> "$LOG_FILE"

# Step 1: Activate venv and run pipeline
source venv/bin/activate
python main.py --mode=daily >> "$LOG_FILE" 2>&1
EXIT_CODE=$?

# Step 2: Check result
if [ $EXIT_CODE -eq 0 ]; then
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] Pipeline SUCCESS" >> "$LOG_FILE"

    # Step 3: Send email report
    python -c "
from src.report import email_daily_report
email_daily_report('output/daily_report.md')
" >> "$LOG_FILE" 2>&1

    echo "[$(date '+%Y-%m-%d %H:%M:%S')] Email sent" >> "$LOG_FILE"
else
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] Pipeline FAILED (exit code: $EXIT_CODE)" >> "$LOG_FILE"

    # Send alert
    python -c "
from src.alert import send_alert_email
send_alert_email('日报执行失败', 'Exit code: $EXIT_CODE. Check output/cron.log for details.')
" >> "$LOG_FILE" 2>&1

    echo "[$(date '+%Y-%m-%d %H:%M:%S')] Alert sent" >> "$LOG_FILE"
    exit $EXIT_CODE
fi

echo "[$(date '+%Y-%m-%d %H:%M:%S')] Daily pipeline completed" >> "$LOG_FILE"
```

**crontab 配置——每天早上 8:00 执行:**

```bash
# crontab -e
0 8 * * * /bin/bash /path/to/xianguoduo/scripts/run_daily.sh
```

**这个脚本的设计原则:** (1) 所有输出重定向到日志——可追溯 (2) 成功和失败分路径——成功发日报——失败发告警 (3) 时间戳标注——每天的执行记录不会混淆 (4) exit code 传递——cron 知道脚本是否成功。

### 报表自动化的完整验收——不只是"能发邮件"——是"邮件打开率 100%"

**日报邮件的设计原则——和 Dashboard 一样——结论先行:**

差的邮件标题: "鲜果多日报"——不知道是涨了还是跌了——可能被忽略。

好的邮件标题: "鲜果多日报 1/19——GMV +5.2%——订单量 +3.1%——北京市场领涨"——扫一眼标题就知道今天的核心信息——不需要打开邮件。

差的邮件正文: 只有附件——"日报见附件"——需要下载/打开 Excel——手机上无法快速浏览。

好的邮件正文: KPI 摘要 + 环比变化 + 一句话结论——在手机上 10 秒就能看完——不需要下载附件。附件留给"需要深入分析的人"。

```python
def generate_email_subject(kpi_df: pd.DataFrame) -> str:
    """生成日报邮件标题——含核心 KPI + 变化方向——结论先行。"""
    latest = kpi_df.iloc[-1]
    prev = kpi_df.iloc[-2]

    gmv_change = (latest['gmv'] - prev['gmv']) / prev['gmv'] * 100
    orders_change = (latest['orders'] - prev['orders']) / prev['orders'] * 100

    direction = '+' if gmv_change > 0 else ''
    return (
        f'鲜果多日报 {latest["date"]}——'
        f'GMV {direction}{gmv_change:.1f}%——'
        f'订单量 {direction}{orders_change:.1f}%'
    )
```

### 日报邮件自动化——从数据到邮件附件

```python
from email.mime.base import MIMEBase
from email import encoders
from pathlib import Path

def email_daily_report(report_path: str, to_email: str = None):
    """发送日报邮件——含 KPI 摘要正文 + 完整报告附件。

    邮件正文 = KPI 摘要——运营总监在手机上就能看——不需要下载附件。
    附件 = 完整报告 / Excel / 图表——在电脑上查看。
    """
    to_email = to_email or os.getenv('REPORT_EMAIL_TO', 'boss@xianguoduo.com')

    # 读 KPI 摘要——作为邮件正文
    kpi_df = pd.read_parquet('output/daily_kpi.parquet')
    latest = kpi_df.iloc[-1]
    body = f'''
    <h3>鲜果多日报——{latest["date"]}</h3>
    <ul>
      <li>GMV: {latest["gmv"]:,.0f} 万元</li>
      <li>订单数: {latest["orders"]:,} 单</li>
      <li>用户数: {latest["users"]:,} 人</li>
      <li>客单价: {latest["avg_order_value"]:,.2f} 元</li>
    </ul>
    <p>完整报告见附件。</p>
    '''

    msg = MIMEMultipart()
    msg['Subject'] = f'鲜果多日报——{latest["date"]}'
    msg.attach(MIMEText(body, 'html', 'utf-8'))

    # 附件——完整报告
    with open(report_path, 'rb') as f:
        attachment = MIMEBase('application', 'octet-stream')
        attachment.set_payload(f.read())
        encoders.encode_base64(attachment)
        attachment.add_header('Content-Disposition', f'attachment; filename={Path(report_path).name}')
        msg.attach(attachment)

    send_alert_email(subject=msg['Subject'], body=body, to_email=to_email)
```
