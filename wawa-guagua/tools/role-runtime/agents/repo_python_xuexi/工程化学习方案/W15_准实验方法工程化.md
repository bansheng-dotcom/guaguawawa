## D1（周一 11/3）：PSM——倾向得分匹配的完整工程实现

> 📓 今日主课：PSM——propensity score/Logistic/1:1 最近邻/Common Support/Caliper

---

### 🔴 认知冲突

你给鲜果多做了"有会员卡 vs 无会员卡"的消费对比——有卡用户人均消费高 35%。你兴奋地向运营总监汇报"会员卡效果显著——建议全员推广"。

同事看了一眼你的数据——"有没有可能——不是卡让他们消费更高——而是本来就消费高的人更倾向去领卡？"你沉默了。你做了一个**朴素对比**（naive comparison）——比较的是"有卡的人"和"无卡的人"——但这两群人**在领卡之前就已经不同了**。高消费用户更可能领卡——所以你看到的 +35% 中——一部分是"卡的效果"——另一部分是"高消费用户本来就会消费更多"——这两部分混在一起——你无法区分。

这就是选择偏差（Selection Bias）。PSM 试图用**可观测的协变量**来模拟随机化——对于每个领卡用户——找一个"没领卡但在可观测维度上（消费历史、注册天数、城市、设备）非常相似"的用户——比较这两个人——差异更接近"卡的真实效果"。

**但 PSM 不是魔法。它有一个致命前提——CIA（条件独立假设）——你能观测到的协变量必须"足够解释"谁领了卡。如果存在未观测的混淆变量（如"内在消费意愿"——无法度量）——PSM 无法控制——结论仍然有偏。**

---

### 📖 核心原理

**PSM 完整工程实现——五步，每一步有日志输出——不是"跑个模型"——是"带着诊断的因果推断"：**

```python
import numpy as np
import pandas as pd
from sklearn.linear_model import LogisticRegression
from sklearn.neighbors import NearestNeighbors
import logging

logger = logging.getLogger(__name__)


def propensity_score_matching(
    df: pd.DataFrame,
    treat_col: str = 'has_card',
    outcome_col: str = 'total_spent',
    covariates: list = None,
    caliper: float = 0.2,
    k: int = 1
) -> dict:
    """倾向得分匹配（PSM）——评估处理效应。

    ⚠️ 假设清单（使用者必须逐项确认——不是"知道就行"——是"数据必须满足"）:

    1. CIA (Conditional Independence Assumption / Unconfoundedness):
       在控制协变量 X 后——处理分配独立于潜在结果。
       白话: "你观测到的协变量——解释了所有'谁会被处理'的选择机制。"
       这是 PSM 最核心也最容易被违反的假设——因为现实中总有"你没观测到的变量"
       在同时影响"是否被处理"和"结果"。
       例子: 你观测了用户的消费历史、注册天数、城市——但你没观测"内在消费意愿"。
       内在消费意愿高的人更可能领卡——也天然消费更多——即使卡本身没有效果——
       你也会看到"有卡的人消费更多"——PSM 无法区分。

    2. Common Support / Overlap:
       处理组和对照组的倾向得分分布必须有重叠区域。
       白话: "对于每个被处理的人——能找到倾向得分接近的未处理的人作为反事实。"
       如果两组得分几乎不重叠——说明"被处理的人"和"没被处理的人"在可观测维度上
       完全不同——PSM 无法找到可比的对照——结论不可信。
       检验: 画两组倾向得分的直方图——看重叠区域。

    3. SUTVA: 同 AB 实验——每个人的处理状态不影响其他人的结果。

    ⚠️ 不适用场景:
    - 存在重要的未观测混淆变量（如"内在动机"——不可测的）→ PSM 有偏
    - Common Support 失败（两组得分几乎不重叠）→ 匹配质量差——ATT 不可信
    - 样本量太小（两组各 < 200）→ 匹配质量差——每对匹配的"距离"太大

    ⚠️ 面试常见追问:
    Q: "PSM 和随机化实验的根本区别是什么？"
    A: 随机化保证"已知和未知的混淆变量都被平衡"——因为分配是随机的——和任何变量无关。
       PSM 只平衡"你观测到的混淆变量"——未观测的仍然可能不平衡。
       这就是为什么随机化是 Gold Standard——PSM 是在"不能随机化时的次优选择"——
       不是"替代方案"——是"退而求其次"。

    Q: "你怎么证明 CIA 成立？"
    A: 你不能证明。CIA 本质上是不可检验的——因为它涉及"未观测的变量"。
       你只能做两件事: ①匹配后检查协变量平衡性（SMD < 0.1）——证明"你观测到的变量被平衡了"
       ②做 Rosenbaum 敏感性分析——量化"需要多强的未观测混淆才能推翻你的结论"。
       如果弱未观测混淆就能推翻→结论脆弱。如果需要极强未观测混淆→结论相对稳健。

    Args:
        df: 含 treat_col, outcome_col, covariates 的数据
        treat_col: 处理组标记列名 (0/1)
        outcome_col: 结果变量列名
        covariates: 协变量列名列表
        caliper: 卡尺——匹配的最大倾向得分距离（以标准差的倍数表示）
        k: 每个处理单元匹配几个对照单元

    Returns:
        Dict 含: ATT / 匹配前后协变量平衡性(SMD) / Common Support 检验 / 匹配样本量
    """
    if covariates is None:
        covariates = ['pre_spent', 'days_since_register', 'order_count', 'city_tier']

    # === Step 1: 估计倾向得分（Logistic 回归） ===
    X = df[covariates]
    y = df[treat_col]
    model = LogisticRegression(max_iter=1000)
    model.fit(X, y)
    df['propensity_score'] = model.predict_proba(X)[:, 1]

    logger.info("Step 1: 倾向得分估计完成——AUC=%.3f", 
                roc_auc_score(y, df['propensity_score']) if 'roc_auc_score' in dir() else 0)

    # === Step 2: Common Support 检验 ===
    treat_ps = df[df[treat_col] == 1]['propensity_score']
    control_ps = df[df[treat_col] == 0]['propensity_score']
    overlap_min = max(treat_ps.min(), control_ps.min())
    overlap_max = min(treat_ps.max(), control_ps.max())
    common_support = (df['propensity_score'] >= overlap_min) & (df['propensity_score'] <= overlap_max)
    
    n_dropped = (~common_support).sum()
    if n_dropped > 0:
        logger.warning("Common Support: 丢弃 %d 个观测（不在重叠区域内）——%.1f%%",
                       n_dropped, n_dropped / len(df) * 100)
    df_cs = df[common_support].copy()

    # === Step 3: 匹配（最近邻 + 卡尺） ===
    treated = df_cs[df_cs[treat_col] == 1]
    control = df_cs[df_cs[treat_col] == 0]
    
    nn = NearestNeighbors(n_neighbors=k)
    nn.fit(control[['propensity_score']])
    distances, indices = nn.kneighbors(treated[['propensity_score']])
    
    # 卡尺过滤——超过阈值的匹配丢弃
    caliper_dist = caliper * df['propensity_score'].std()
    valid_matches = distances.flatten() <= caliper_dist
    
    matched_control_indices = control.iloc[indices.flatten()].index
    matched_control_indices = matched_control_indices[valid_matches]
    matched_treated_indices = treated.index[valid_matches]

    logger.info("Step 3: 匹配完成——%d 对 (卡尺=%.2f SD)——丢弃 %d 对超出卡尺",
                valid_matches.sum(), caliper, (~valid_matches).sum())

    # === Step 4: 估计 ATT ===
    att = (df.loc[matched_treated_indices, outcome_col].mean() -
           df.loc[matched_control_indices, outcome_col].mean())

    # === Step 5: 平衡性检验（D2 详细讲——SMD） ===
    balance = check_balance(df.loc[matched_treated_indices],
                            df.loc[matched_control_indices], covariates)

    return {
        'att': att,
        'n_treated_matched': valid_matches.sum(),
        'n_control_matched': len(matched_control_indices),
        'n_dropped_common_support': n_dropped,
        'auc': roc_auc_score(y, df['propensity_score']),
        'balance': balance,
        'common_support_overlap': (overlap_min, overlap_max)
    }
```

### PSM 匹配诊断的完整工具箱——不只是 SMD——还有 Common Support 图 + Love Plot + 匹配前后分布对比

**诊断 1——Common Support 可视化（倾向得分分布的直方图对比）：** 匹配前——处理组和对照组的倾向得分分布可能差异很大——如果几乎不重叠——PSM 无法找到可比的对照——结论从一开始就不可信。画两组得分的重叠直方图——重叠区域 = Common Support 区域。如果重叠 < 50%——大量观测被丢弃——ATT 的可推广性受限。

**诊断 2——Love Plot（协变量平衡性前后对比图）：** Love Plot = 横轴是 SMD（标准化均值差）——纵轴是协变量——每个协变量有"匹配前"和"匹配后"两个点。完美的 Love Plot——所有"匹配后"的点都挤在 SMD=0 的竖线附近——"匹配前"的点分散在较大范围。一眼看出——这个协变量被平衡了吗？

```python
import matplotlib.pyplot as plt

def love_plot(balance_before, balance_after, covariates):
    """Love Plot——匹配前后每个协变量的 SMD 对比。"""
    fig, ax = plt.subplots(figsize=(8, 6))
    y_pos = range(len(covariates))
    before_smd = [balance_before[c]['smd'] for c in covariates]
    after_smd = [balance_after[c]['smd'] for c in covariates]

    ax.scatter(before_smd, y_pos, marker='o', s=100, label='Before Match',
               color='red', alpha=0.6)
    ax.scatter(after_smd, y_pos, marker='s', s=100, label='After Match',
               color='steelblue', alpha=0.9)
    ax.axvline(x=0.1, color='gray', linestyle='--', label='SMD=0.1 (Good)')
    ax.set_yticks(y_pos)
    ax.set_yticklabels(covariates)
    ax.set_xlabel('Standardized Mean Difference')
    ax.legend()
    return fig
```

**诊断 3——匹配样本量的变化：** 匹配前处理组 5,000 人——匹配后只剩 3,200 对（Common Support 丢弃了 500 人——卡尺过滤了 1,300 对）。需要汇报："原始处理组 5,000 人——匹配后保留 3,200 对（64%）。丢弃的主要是倾向得分极高/极低的用户——这些用户几乎没有可比的对照。因此 ATT 对中间用户群有效——对极端用户结论可能不适用。"

**这三个诊断——合在一起——回答了面试官会追问的三个问题：**
1. "你的匹配质量好吗？" -> Love Plot——所有 SMD < 0.1
2. "你的结论适用于所有人吗？" -> Common Support——只适用于重叠区域内的用户
3. "你丢了多少数据？" -> 样本量变化 + 被丢弃用户的分析

## D2（周二 11/4）：PSM 平衡性检验——SMD < 0.1 是硬标准

> 📓 今日主课：PSM 实战——三版本翻译

---

### 🔴 认知冲突

D1 你跑了 PSM——ATT = +12%。你觉得"匹配做完了——可以下结论了"。同事问你："匹配后协变量平衡了吗？"你说"应该平衡了吧——PSM 的目的就是平衡协变量"。同事追问："你怎么知道平衡了？有没有量化——匹配前后每个协变量的 SMD（标准化均值差）是多少？"

你沉默了——你"觉得"应该平衡了——"觉得"不是"验证"。匹配后需要**逐协变量检查 SMD**——SMD < 0.1 才算"充分平衡"。如果某个协变量匹配后 SMD 仍然 > 0.2——说明这个协变量没有被平衡——你的 PSM 在这个维度上是失败的——ATT 的可信度取决于你能否解释"这个协变量为什么没有被平衡——以及它对你结论的影响"。

---

### 📖 核心原理

**SMD（Standardized Mean Difference）= (mean_treat - mean_control) / pooled_std。标准：< 0.1 平衡良好——0.1-0.2 可接受但需标注——> 0.2 平衡不足——匹配质量不够。**

```python
def check_balance(treated_df, control_df, covariates):
    """匹配前后协变量平衡性检验——逐协变量计算 SMD。"""
    balance = {}
    for col in covariates:
        m_t = treated_df[col].mean()
        m_c = control_df[col].mean()
        pooled_std = np.sqrt((treated_df[col].var() + control_df[col].var()) / 2)
        smd = abs(m_t - m_c) / pooled_std if pooled_std > 0 else 0
        status = '✅' if smd < 0.1 else ('⚠️' if smd < 0.2 else '❌')
        balance[col] = {'smd': smd, 'status': status}
    return balance
```

### RDD 带宽选择的偏差-方差权衡与实现

**核心困境——不是带宽越小越好——也不是越大越好：**

- 小带宽（如 +/- 50 元）：只用了断点紧邻的少量数据——偏差小（这些人确实几乎一样）——但方差大（样本太少——估计不稳定）
- 大带宽（如 +/- 200 元）：用了更多数据——方差小（估计稳定）——但偏差大（距离断点 200 元的人——可能和刚好在断点的人已经不太一样了）

**标准做法：** 用数据驱动的带宽选择（Calonico-Cattaneo-Titiunik 的 MSE-optimal bandwidth）——然后做带宽敏感性分析——在 0.5x / 1x / 2x 带宽下分别估计——看 ATT 的稳定性。

```python
def bandwidth_sensitivity(df, running_var, threshold, outcome, bandwidths=None):
    """RDD 带宽敏感性分析——在不同带宽下估计 ATT——检验结论稳健性。"""
    if bandwidths is None:
        h_optimal = _calonico_cattaneo_bandwidth(df, running_var)
        bandwidths = [h_optimal * 0.5, h_optimal, h_optimal * 1.5, h_optimal * 2.0]
    results = []
    for bw in bandwidths:
        df_bw = df[(df[running_var] >= threshold - bw) &
                    (df[running_var] <= threshold + bw)]
        att = estimate_sharp_rdd(df_bw, running_var, threshold, outcome)
        results.append(dict(bandwidth=bw, att=att, n=len(df_bw)))
    att_values = [r['att'] for r in results]
    return dict(bandwidths=results,
                att_range=(min(att_values), max(att_values)),
                stable=max(att_values)-min(att_values) < abs(att_values[0])*0.3)
```

**鲜果多 RDD 带宽敏感性结果：** 0.5x 带宽 ATT=+13%——1x 带宽 ATT=+14%——2x 带宽 ATT=+16%。ATT 在 +13% 至 +16% 之间——方向一致——结论对带宽选择不敏感。如果 0.5x 和 2x 带宽的 ATT 方向相反——那就要警惕——你的结论完全依赖于一个特定的带宽选择——这不是稳健的结论。

**面试追问——**面试官问"你说 ATT=+14%——但如果换一个带宽——结论还成立吗？"你回答"我做了带宽敏感性分析——在 0.5x/1x/1.5x/2x 四种带宽下——ATT 在 +13% 至 +16% 之间——方向始终为正——结论对带宽选择稳健。"

## D3（周三 11/5）：RDD——断点回归的工程实现 + McCrary 检验

> 📓 今日主课：RDD——Sharp/Fuzzy/带宽选择/McCrary 检验/BW 偏差权衡

---

### 🔴 认知冲突

鲜果多有一个"满 500 元送会员卡"的规则。消费满 500 元——自动送卡。消费 499 元——不送。这个规则创造了一个**自然的断点**——在 500 元附近——"刚好满 500"和"刚好差一点"的用户——在其他维度上应该非常相似（消费 499 和 501 的人——其实差不多）——唯一的区别是前者拿到了卡——后者没有。

你兴奋地跑了一个 RDD——ATT = +18%——会员卡让消费提升了 18%。但面试官追问——"你怎么知道用户没有'操纵'自己的消费——比如故意凑到 500 元去拿卡？"

如果有人故意凑单——"刚好满 500"的用户和"刚好 499"的用户就不是"在其他维度上相似"了——前者是"主动凑单的人"——他们可能本身就更有消费意愿——RDD 的局部随机化假设被破坏了。你需要 McCrary 检验——检查 running variable（消费金额）在断点附近的密度是否有跳跃。有跳跃→有人在操纵→RDD 无效。

---

### 📖 核心原理

**RDD 的假设清单——比 PSM 弱很多——但有一个关键前提：个体不能精确操纵 running variable。**

```python
def regression_discontinuity(df, running_var, threshold, outcome, bw=None):
    """Sharp RDD——断点回归。

    ⚠️ 假设清单:
    1. 连续性假设: 在断点附近——除了处理状态外——所有其他因素连续
    2. 不能精确操纵 running variable: McCrary 检验——断点附近密度不应有跳跃
    3. 局部性: RDD 估计的是 LATE（断点附近的局部效应）——不能外推

    ⚠️ 面试追问:
    Q: "RDD 和随机化有什么相似之处？"
    A: 在断点附近——刚好过线和刚好不过线的个体——近似随机分配。
       因为个体无法精确控制自己在断点哪一边（假设无操纵）。
       这被称为"局部随机化"——RDD 在断点附近最接近实验。
    """
```

**McCrary 检验——running variable 在断点附近的密度是否有跳跃。有跳跃→操纵存在→RDD 的前提不满足。** 实现：把 running variable 分成细小的 bin——看断点左右两边的 bin 计数是否有显著差异。

### 📖 RDD 进阶——Fuzzy RDD + 带宽选择的偏差-方差权衡

**Sharp RDD vs Fuzzy RDD——D3 你学的是 Sharp RDD（断点处处理概率从 0 跳到 1）：**

Sharp RDD: 消费 >= 500 -> 100% 拿到卡。消费 < 500 -> 0% 拿到卡。处理概率在断点处是"断崖式"的。

Fuzzy RDD: 消费 >= 500 -> 拿到卡的概率从 30% 跳到 70%（不是 0->1）。可能因为"满 500 送卡"规则不是强制的——有些达标用户没领——有些未达标用户被手动送了卡。Fuzzy RDD 的处理概率在断点处有跳跃——但不是 0->1。

**Fuzzy RDD 的估计：用断点作为"工具变量"——2SLS——第一阶段估计"达标"对"拿到卡"的影响——第二阶段估计"拿到卡"对消费的影响。Fuzzy RDD 本质上是 IV——断点是工具变量。**

```python
def fuzzy_rdd(df, running_var, threshold, outcome, treat_col):
    """Fuzzy RDD——断点作为工具变量——2SLS 估计。

    第一阶段: treat ~ above_threshold + f(running_var)
    第二阶段: outcome ~ treat_hat + f(running_var)

    关键: 第一阶段 F 统计量——如果断点处处理概率跳跃太小（< 10pp）——弱工具变量。
    """
    df['above'] = (df[running_var] >= threshold).astype(int)
    df['dist'] = df[running_var] - threshold  # 距断点的距离

    # 第一阶段: 达标 -> 拿卡
    import statsmodels.formula.api as smf
    stage1 = smf.ols(f'{treat_col} ~ above * dist', data=df).fit()
    f_stat = stage1.fvalue
    df['treat_hat'] = stage1.fittedvalues

    # 第二阶段: 预测拿卡概率 -> 消费
    stage2 = smf.ols(f'{outcome} ~ treat_hat * dist', data=df).fit()
    att = stage2.params['treat_hat']

    return {'att': att, 'first_stage_f': f_stat, 'weak_iv': f_stat < 10,
            'jump_at_cutoff': stage1.params['above']}  # 断点处的处理概率跳跃
```

**RDD 带宽选择的偏差-方差权衡——不是"带宽越小越好"——也不是"带宽越大越好"：**

- 小带宽（如 +/- 50 元）：只用了断点"紧邻"的少量数据——偏差小（这些人确实几乎一样）——但方差大（样本太少——估计不稳定）
- 大带宽（如 +/- 200 元）：用了更多数据——方差小（估计稳定）——但偏差大（距离断点 200 元的人——可能和刚好在断点的人已经不太一样了）

**标准做法：** 用数据驱动的带宽选择（如 Calonico-Cattaneo-Titiunik 的 MSE-optimal bandwidth）——然后做带宽敏感性分析——在 0.5x / 1x / 2x 带宽下分别估计——看 ATT 的稳定性。

## D4.5：工具变量（IV）——当所有其他方法都失效时的最后武器

> 📓 今日主课：工具变量——IV/2SLS/相关性+外生性/过度识别检验/F>10 经验规则

---

### 🔴 认知冲突

你学会了 DID（W14）、PSM（D1）、RDD（D3）。但鲜果多想评估"会员卡对 GMV 的效果"——没有面板数据（不能 DID）、有未观测混淆"内在消费意愿"（PSM 可能偏）、没有断点（不能 RDD）。所有方法都失效了。

同事说"我们有一个工具变量——'是否在会员卡推广活动期间注册'——这个变量影响你是否拿到卡——但不直接影响你的消费（除了通过卡这个渠道）。"你查了一下——活动期间注册的用户——拿到卡的概率高 30%——但活动时间和你个人的消费意愿无关——活动是公司统一决定的。

这就是**工具变量（IV）**——找一个"只通过影响处理来影响结果"的变量——利用它的外生变异来识别因果效应。

**IV 是最强大的准实验方法——也是最容易被滥用的。因为"找到一个好的工具变量"很难——而"找到一个坏的工具变量并假装它好"很容易。**

---

### 📖 核心原理

**IV 的两个核心假设——两个都必须满足——缺一个就完全失效：**

**假设 1——相关性（Relevance）：** IV 必须和内生变量（处理）相关。检验：第一阶段 F 统计量——F > 10 是经验阈值——F < 10 是"弱工具变量"——2SLS 估计比 OLS 偏差更大。

**假设 2——外生性（Exogeneity / Exclusion Restriction）：** IV 只通过"处理"这个渠道影响结果——没有其他路径。白话："工具变量影响你的消费——只因为它影响了你是否拿到卡——不通过其他任何方式。"这个假设不可直接检验（和 CIA 一样）。

**为什么 IV 估计的是 LATE（局部平均处理效应）而不是 ATE？**
因为 IV 只利用"被工具变量影响的那部分人"的处理变异。在鲜果多案例中——活动期间注册的用户更可能拿卡——但"无论是否活动期间都一定会拿卡的人"和"无论是否活动期间都一定不拿卡的人"——他们的行为没有被 IV 利用。IV 估计的是"被活动推了一把才拿卡的人"的处理效应——这些人被称为 compliers（遵从者）——他们的处理效应可能和"一定会拿卡的人"不同。

```python
import statsmodels.api as sm
from typing import Dict

def instrumental_variable(df, y_col, treat_col, iv_col, controls=None):
    """工具变量估计（2SLS）——评估处理效应。

    [WARNING] 核心假设:
    1. 相关性: IV 必须和处理相关——第一阶段 F > 10
       检验方法: 第一阶段回归的 F 统计量——F < 10 = 弱工具变量——2SLS 偏差 > OLS 偏差
    2. 外生性: IV 只通过处理影响结果——不可直接检验
       间接检验: 过度识别检验（如有多个 IV）——Sargan/Hansen J 检验

    [STOP] 不适用场景:
    1. F < 10——弱工具变量——2SLS 估计不可靠——考虑 LIML 或放弃 IV
    2. IV 和未观测混淆相关——外生性被违反——结论完全不可信
    3. 只有恰好识别（1 个 IV + 1 个内生变量）——无法做过度识别检验

    [BULB] 面试常见追问:
    Q1: "你怎么找到一个好的工具变量？"
    A1: 好的工具变量 = 自然实验或制度特征。例子: (1) 出生日期——影响入学年龄但不直接影响收入
        (2) 距离医院的远近——影响是否去看病但不直接影响健康(控制收入后)
        (3) 天气——影响农产品价格但不直接影响消费者需求
        坏的工具变量 = 和未观测混淆相关的变量。例子: 父母的收入——既影响你的教育（处理）
        又影响你的收入（结果——通过社会网络）——违反了外生性。

    Q2: "为什么 F > 10？不是 F > 5？"
    A2: F > 10 是 Stock & Yogo (2005) 的经验规则——此时 2SLS 的相对偏差 < 10% OLS 偏差。
        F 在 5-10 之间 = 弱工具变量可能可接受——但如果结论在 F=5 时就变了——说明结论脆弱。
        F < 5 = 2SLS 几乎肯定比 OLS 更差——不要用。
    """
    # 第一阶段: treat ~ IV + controls——提取预测值
    X1 = sm.add_constant(df[[iv_col] + (controls or [])])
    stage1 = sm.OLS(df[treat_col], X1).fit()
    f_stat = stage1.fvalue
    df['treat_hat'] = stage1.fittedvalues

    # 第二阶段: y ~ treat_hat + controls
    X2 = sm.add_constant(df[['treat_hat'] + (controls or [])])
    stage2 = sm.OLS(df[y_col], X2).fit()

    att = stage2.params['treat_hat']

    return {
        'att': att,
        'att_se': stage2.bse['treat_hat'],
        'att_pvalue': stage2.pvalues['treat_hat'],
        'first_stage_f': f_stat,
        'weak_iv': f_stat < 10,
        'stage1_summary': stage1.summary(),
        'stage2_summary': stage2.summary()
    }
```

### 📖 PSM 进阶——Rosenbaum 敏感性分析的原理与实现

**PSM 的致命弱点——CIA 不可检验。Rosenbaum 敏感性分析量化——"需要多强的未观测混淆才能推翻你的结论？"**

原理：假设存在一个未观测的二元混淆变量 U——它同时影响"是否被处理"和"结果"。U 的效应强度用 Gamma 表示。Gamma=1 = 没有未观测混淆。Gamma=2 = 有未观测混淆——它让同一个匹配对中的两个个体——被处理的概率相差 2 倍。Rosenbaum 检验——在不同的 Gamma 值下——计算 Wilcoxon signed rank test 的 p 值上界。找到使 p > 0.05 的最小 Gamma——即"需要多强的未观测混淆才能让结论不再显著"。

```python
def rosenbaum_sensitivity(treated_outcomes, control_outcomes, gamma_range=(1, 3, 0.1)):
    """Rosenbaum 敏感性分析——量化未观测混淆的敏感度。

    当 Gamma=1.5 时 p < 0.05——结论稳健——需要相当强的未观测混淆才能推翻。
    当 Gamma=1.1 时 p > 0.05——结论脆弱——弱未观测混淆就能让结论不显著。
    """
    import numpy as np
    from scipy.stats import norm

    n = len(treated_outcomes)
    diffs = np.array(treated_outcomes) - np.array(control_outcomes)
    W = np.sum(np.where(diffs > 0, 1, 0))  # 正差异的个数——受效果影响的匹配对数

    results = []
    for gamma in np.arange(*gamma_range):
        # 上界: 在 Gamma 下——p 值的最大值
        p_plus = (gamma / (1 + gamma))
        p_minus = 1 / (1 + gamma)
        E_W = n * p_plus
        V_W = n * p_plus * p_minus
        z = (W - E_W) / np.sqrt(V_W)
        p_upper = 1 - norm.cdf(z)
        results.append({'gamma': round(gamma, 2), 'p_upper': round(p_upper, 4),
                        'significant': p_upper < 0.05})

    # 找到使结论不再显著的最小 Gamma
    threshold_gamma = None
    for r in results:
        if not r['significant']:
            threshold_gamma = r['gamma']
            break
    return {'results': results, 'threshold_gamma': threshold_gamma}
```

**鲜果多 PSM 的 Rosenbaum 分析：Gamma=1.0 时 p=0.003——显著。Gamma=1.5 时 p=0.04——仍然显著。Gamma=1.8 时 p=0.08——不显著。结论——需要 1.8 倍的未观测混淆差异才能让结论不显著——这在业务上是相当强的——用户的"内在消费意愿"通常不会让两个看起来一样的人有 1.8 倍的消费差异——结论相对稳健。**

**面试时你展示 Rosenbaum 分析——而不只是说"CIA 可能不成立"——面试官知道你理解 PSM 的局限并知道如何量化它——这让你和其他"跑过 PSM"的候选人区别开来。**

### 多方法评估报告的完整结构模板

**一个完整的多方法因果评估报告需要七个章节——每个章节回答一个特定的质疑：**

| 章节 | 回答的问题 | 关键内容 | 面试官关注什么 |
|------|----------|---------|-------------|
| 1. 背景 | 为什么要评估这个效果？为什么不能 AB Test？ | 业务背景 + 识别策略选择理由 | 你理解随机化是最优选择——这里为什么不适用 |
| 2. 数据 | 数据可信吗？ | 数据源 + 样本量 + 面板平衡性 + 缺失处理 | 你不会把脏数据直接塞进模型 |
| 3. PSM | 在可观测维度相似的人中——效果多大？ | ATT + SMD 表 + Love Plot + Common Support | 你理解 CIA 不可检验——做了 Rosenbaum |
| 4. RDD | 在断点附近的用户中——效果多大？ | ATT + McCrary 检验 + 带宽敏感性 | 你理解结论只能外推到断点附近 |

## D7（周日 11/9）：W15 审计——闭卷 PSM/RDD/决策树

### 📝 闭卷自测（5 题）

**Q1**：PSM 的三个核心假设？为什么 CIA 不可检验——你怎么办？

> **A**：CIA（无未观测混淆）/ Common Support（得分有重叠）/ SUTVA。CIA 不可检验——因为涉及未观测变量。对策：①匹配后检查协变量平衡性（SMD）——"观测到的被平衡了"②Rosenbaum 敏感性——量化"需要多强的未观测混淆才能推翻结论"。偏差：说"CIA 可以通过画图检验"——不能——CIA 涉及未观测变量——无法从数据检验。

**Q2**：RDD 为什么在断点附近接近随机化？McCrary 检验在检测什么？

> **A**：在断点附近——"刚好过线"和"刚好不过线"的个体——在其他维度上应该相似——因为个体无法精确控制自己在断点哪一边。这近似随机分配。McCrary 检验——running variable 在断点附近密度是否有跳跃——有跳跃→操纵存在→RDD 无效。偏差：说"RDD = 随机化"——不是——只是"局部近似"——而且需要无操纵的前提。

**Q3**：PSM 的 SMD 三个阈值——< 0.1 / 0.1-0.2 / > 0.2 各代表什么？

> **A**：< 0.1 = 平衡良好——匹配成功。0.1-0.2 = 可接受——但需标注——该协变量可能仍有残余混淆。> 0.2 = 平衡不足——匹配质量不够——该协变量的差异可能影响 ATT 的可信度。

**Q4**：画出因果推断方法选择决策树——从"能随机化吗"开始。

> **A**：能→AB Test。不能+有面板+有对照→DID。不能+有断点→RDD。不能+能观测所有混淆→PSM。不能+有工具变量→IV。啥都没有→相关性分析（非因果推断）。

**Q5**：为什么"三种方法结论一致"比"一种方法跑对"更有说服力？三种方法结论不同怎么办？

> **A**：每种方法有不同的假设——如果三种方法结论一致——说明结论对"假设的选择"不敏感——更稳健。结论不同——不是选喜欢的——是解释为什么不同——每种方法的假设不同——不同的假设导致不同的结论——这本身就是对数据生成过程的深入理解。报告里显式讨论这个差异——比"选一个显著的方法报"更科学。



**Q6**（IV 深度）：什么是 LATE？为什么 IV 估计的是 LATE 而不是 ATE？这个区别对业务决策有什么影响？

> **A**：LATE = Local Average Treatment Effect——"被工具变量影响的 compliers 的平均处理效应"。IV 不利用 always-takers（无论有无 IV 都一定被处理的人）和 never-takers（无论有无 IV 都一定不被处理的人）的处理变异——只利用 compliers 的变异。因此 IV 的 ATT 只对 compliers 有效——不能外推到 always-takers 和 never-takers。业务影响：如果鲜果多想把会员卡推广到所有人——IV 估计的 +15% 可能高估或低估——因为"被推广活动推了一把才拿卡的人"和"主动拿卡的人"对卡的反应可能不同。在报告中必须标注"本结论适用于 compliers——推广到全员时的效果可能不同"。

**Q7**（多方法一致性）：如果你只有一种方法——PSM ATT=+12% (p=0.03)——你怎么增强结论的可信度？

> **A**：(1) Rosenbaum 敏感性分析——量化未观测混淆需要多强才能推翻结论——如果 Gamma=1.5 时 p 变成 0.07——结论对弱未观测混淆敏感——需要谨慎。(2) 安慰剂检验——用"处理前"的数据假装"处理发生了"——看有没有"假效果"——如果有——说明两组在处理前就不平行——PSM 的前提可能不满足。(3) 子群分析——在不同子群（城市/品类/时段）中——ATT 的方向是否一致——如果某个子群 ATT 方向相反——说明处理效应是异质性的——"平均值"掩盖了重要的差异。

**Q8**（面试 Roleplay——完整因果推断答辩）：面试官给你 3 分钟——"你用三种方法评估了同一个问题——我最关心的不是你的数字——是你怎么处理方法之间的不一致。如果 PSM=+12%、RDD=+14%、IV=+15%——你信哪个？为什么？"

> **A**："三个数字看起来不同——但方向一致且 CI 重叠——我信它们共同指向的方向——而不是某一个具体的数字。这三个数字之间的差异——恰好验证了每种方法估计的是不同的'人群'。PSM 估计的是'可观测维度上相似的有卡和无卡用户'——代表更广的人群。RDD 估计的是'消费刚好 ~500 元的用户'——他们对卡更敏感——所以 +14% 高于 PSM 的 +12%——这是合理的。IV 估计的是'被推广活动推了一把才拿卡的 compliers'——+15%——也是合理的——这些人可能对促销更敏感。如果 PS 估计的是 +12%，而 IV 估计的是 -5%——那我会非常担忧——这种方向性差异意味着其中某个方法的核心假设被严重违反了——我会优先排查 IV 的外生性——因为外生性不可检验。"
>
> **常见偏差**：说"取平均数 13.7%"——这等于把所有方法当成"同等可信"——但它们的可信度不同——因为假设的可验证性不同——RDD 的假设最容易被检验（McCrary）——IV 的外生性最不可检验——简单取平均忽略了这种差异。
