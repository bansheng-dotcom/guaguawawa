| **L5** | 可维护 | W20-W32 | 第14-18章 | pre-commit + 配置外提 + dbt/Airflow + Docker + 代码审查通过 |

### 三个核心问题

**Q：为什么数据分析师需要工程化？SQL 和 pandas 够用了吧？**

面试官不会问你的分析结论（简历上写了），TA 会问：
- "你这个分析的代码怎么复现？"
- "如果数据更新了，你怎么保证结果一致？"
- "你做的 RFM 分群，换一批数据能自动跑吗？"

三个问题的答案决定了你是 15k 还是 30k。工程化就是这三个问题的答案。

**Q：224 天够吗？**

够。不是"学完"工程化——是把工程化变成肌肉记忆。第 1 天 `git init`，第 224 天你的 GitHub 上 10+ 个项目全部有 CI/CD 绿灯。面试官看一眼你的 GitHub 就知道你不是裸奔写代码的人。

**Q：主计划和工程化的关系是什么？**

主计划告诉你"今天学什么分析方法"（比如 W10D3 学 Hive 数据倾斜）。工程化告诉你"今天代码怎么写才规范"（比如 W10D3 的代码注释里记录数据倾斜的解决方案+push）。两条线并行：白天学分析，晚上练工程化。

### 1.2 每个文件的职责（铁律）

| 文件 | 放什么 | 不放什么 |
|------|--------|---------|
| `io.py` | `read_csv()` `read_sql()` `load_config()` `save_report()` | 清洗逻辑、分析逻辑、画图 |
| `clean.py` | `drop_missing()` `fix_types()` `remove_outliers()` | 读文件、聚合分析、画图 |
| `features.py` | `compute_rfm()` `add_date_features()` `encode_categoricals()` | 读写文件、统计分析 |
| `analyze.py` | `run_ab_test()` `compute_cohort()` `segment_users()` | 读写文件、画图 |
| `visualize.py` | `plot_funnel()` `plot_heatmap()` `plot_trend()` | 数据处理、分析逻辑 |

**犯一次"放错文件"没事。犯三次就不行——以后你找不到代码就是今天埋的坑。**

### 1.3 为什么不能用 `.ipynb` 做生产代码

`.ipynb` 的问题不在于"能跑不能跑"——在于：
1. **执行顺序不确定**：cell 可以跳着跑，你跑出来的结果同事跑不出来
2. **版本控制灾难**：`.ipynb` 的 JSON 里混着代码+输出+图片，git diff 完全不可读
3. **无法测试**：你不能 `import` 一个 notebook，所以不能给里面的函数写测试

**`.ipynb` 的正确用法**：放在 `notebooks/` 里做探索。探索清楚了 → 把逻辑提取到 `src/*.py` → notebook 只保留最后的调用。

### 2.4 常见自救场景

**"我 git push 了不该推的文件"**
```bash
# 1. 先把文件加入 .gitignore
echo "data/secret.csv" >> .gitignore
# 2. 从 git 跟踪中移除（不删本地文件）
git rm --cached data/secret.csv
# 3. 提交
git add .gitignore && git commit -m "remove sensitive file" && git push
```

**"我 commit 了但发现漏了一个文件"**
```bash
git add 漏掉的文件
git commit --amend -m "修正后的commit message"
git push --force-with-lease  # 注意：只有你自己的分支可以 force push
```

**"我改坏了想回到上一个版本"**
```bash
git log --oneline  # 找到想回去的那个 commit 的 hash
git checkout <hash> -- src/clean.py  # 只回滚这个文件
# 或者
git stash  # 暂存当前改动，回到干净状态
```

❌ 手写（你会漏包）

✅

```python
def compute_cohort_retention(
    df: pd.DataFrame,
    user_col: str = 'user_id',
    date_col: str = 'order_date',
    period: str = 'M'
) -> pd.DataFrame:
    """计算同期群留存矩阵。

    按用户首次购买日期分组，计算每组在后续各时间窗口的留存率。

    Args:
        df: 订单数据，需含 {user_col} 和 {date_col} 列
        user_col: 用户唯一标识列名
        date_col: 订单日期列名
        period: 时间窗口——'D'=天 'W'=周 'M'=月

        三角矩阵 DataFrame：
        - index = 同期群标签 (如 '2025-01')
        - columns = 第0期, 第1期, 第2期...

        ValueError: 如果 df 为空或缺少必需列

        >>> orders = pd.read_csv('orders.csv')
        >>> retention = compute_cohort_retention(orders, period='M')
        >>> retention.iloc[0]  # 第一个同期群的留存曲线
    """
```

### 5.2 什么时候用哪一级

```python
# DEBUG：排查问题时才开，平时不显示
logger.debug('正在处理第 %d 行，当前值: %s', i, value)

# INFO：正常的流程节点——"做到了哪一步"
logger.info('开始加载数据: %s', filepath)
logger.info('数据加载完成: %d 行, %d 列', len(df), len(df.columns))
logger.info('RFM 分群完成: %d 用户, 处理耗时 %.1f 秒', len(rfm), elapsed)

# WARNING：不太对但程序还能继续——"可能需要关注"
if missing_rate > 0.10:
    logger.warning('%s 缺失率 %.1f%%，超过10%%阈值，建议检查数据源', col, missing_rate * 100)
if len(df) < 100:
    logger.warning('数据量仅 %d 行，统计推断可能不可靠', len(df))

# ERROR：某个步骤失败了，但程序可能还能继续
try:
    df = pd.read_csv(filepath)
except FileNotFoundError:
    logger.error('数据文件不存在: %s，请检查路径', filepath)
    df = pd.DataFrame()  # 降级：用空 DataFrame 继续

# CRITICAL：程序完全不能继续了
if df.empty:
    logger.critical('数据为空，无法继续分析')
    sys.exit(1)
```

### 5.3 print 和 logging 的本质区别

```python
# print：输出到终端，没了。没法回溯，区分不了重要程度。
```

## 第6章 · 命名规范：看名字就知道是什么（L2→L3）

### 6.1 变量命名规则

```python
# ❌ 坏命名
d = pd.read_csv('x.csv')
d2 = d[d['a'] > 0]
d3 = d2.groupby('b')['c'].sum()

# ✅ 好命名
orders_df = pd.read_csv('orders.csv')
valid_orders = orders_df[orders_df['amount'] > 0]
revenue_by_city = valid_orders.groupby('city')['amount'].sum()
```

**规则**：
- DataFrame 变量：`_df` 后缀 → `orders_df` `cleaned_df` `result_df`
- 聚合结果：`_by_` 连接 → `revenue_by_city` `count_by_category`
- 布尔变量：`is_` `has_` 前缀 → `is_valid` `has_missing`
- 列表：复数 → `orders` `cities` `user_ids`
- 函数：动词开头 → `filter_` `compute_` `check_` `plot_` `load_` `save_`

### 6.2 模块 docstring

每个 `src/*.py` 文件开头必须写一行说明：

```python
# src/io.py
"""数据读写模块：负责所有 CSV/Excel/Parquet/SQL 的读取和写入。"""

# src/clean.py
"""数据清洗模块：缺失值处理、异常值剔除、类型修正、数据验证。"""

# src/analyze.py
"""分析模块：RFM 分群、同期群留存、AB 实验评估、漏斗分析。"""
```

### 6.3 禁止名单

搜索你的代码——如果出现以下变量名，**立刻改掉**：

| 禁止 | 原因 | 改为 |
|------|------|------|
| `x` `y` `z` | 不知道是什么 | `customer_id` `order_amount` |
| `d` `d1` `d2` | 不知道是什么 | `orders_df` `cleaned_df` |
| `tmp` `temp` | 临时变量应命名 | `intermediate_result` |
| `df1` `df2` | 分不清 | `before_merge` `after_merge` |
| `data` `dat` | 太泛 | `user_data` `sales_data` |
| `f` `proc` | 函数名应动词开头 | `filter_` `process_` `compute_` |

## 第8章 · 数据验证模式（L3 核心）

### 8.1 merge 后的行数验证

```python
# merge 前后必须验证行数——这是第一道防线
before = len(orders_df)
merged = orders_df.merge(customers_df, on='customer_id', how='left')
after = len(merged)

assert after >= before, f"行数异常: merge前{before}行, merge后{after}行"
# 如果 after > before（一对多膨胀），记录原因
if after > before:
    logger.warning('一对多膨胀: %d -> %d 行 (+%d)', before, after, after - before)
```

### 8.2 pipe 链式清洗

不用中间变量，用 `pipe` 串联：

```python
# ❌ 中间变量地狱
df1 = clean_dates(raw_df)
df2 = clean_amounts(df1)
df3 = remove_outliers(df2)
df4 = fill_missing(df3)

# ✅ pipe 链式
df = (pd.read_csv('data/dirty.csv')
      .pipe(clean_dates)
      .pipe(clean_amounts)
      .pipe(remove_outliers)
      .pipe(fill_missing))
```

### 8.3 聚合后的合理性检查

```python
# 任何聚合操作后至少检查这三项
revenue_share = df.groupby('city')['amount'].sum()
revenue_share['share'] = revenue_share / revenue_share.sum()

# 1. 占比和为1
assert abs(revenue_share['share'].sum() - 1.0) < 0.001

# 2. 每项在0-1之间
assert (revenue_share['share'] >= 0).all() and (revenue_share['share'] <= 1).all()

# 3. 没有重复分组
assert revenue_share.index.is_unique
```

### 8.4 输入数据的质量检查

```python
def validate_input(df: pd.DataFrame, required_cols: List[str]) -> None:
    """对输入数据做存在性+合理性检查。不通过直接抛异常。"""
    # 1. 非空
    if df.empty:
        raise ValueError('输入 DataFrame 为空')
    
    # 2. 必需列存在
    missing = set(required_cols) - set(df.columns)
    if missing:
        raise ValueError(f'缺少必需列: {missing}')
    
    # 3. 无全空列
    all_null_cols = df.columns[df.isna().all()].tolist()
    if all_null_cols:
        logger.warning('这些列全为空: %s', all_null_cols)
```

## 第15章 · dbt：SQL 的工程化（L5）

### 15.1 三层模型示例

`models/staging/stg_orders.sql`：
```sql
WITH source AS (
    SELECT * FROM {{ source('raw', 'orders') }}
),
cleaned AS (
    SELECT
        order_id,
        customer_id,
        CAST(order_date AS DATE) AS order_date,
        CAST(quantity AS INT) AS quantity,
        CAST(unit_price AS DECIMAL(10,2)) AS unit_price,
        quantity * unit_price AS total_amount,
        CASE WHEN status IN ('cancelled', 'refunded') THEN 0 ELSE 1 END AS is_valid
    FROM source
    WHERE quantity > 0 AND unit_price > 0
)
SELECT * FROM cleaned WHERE is_valid = 1
```

`models/intermediate/int_customer_orders.sql`：
```sql
WITH orders AS (
    SELECT * FROM {{ ref('stg_orders') }}
)
SELECT
    customer_id,
    COUNT(DISTINCT order_id) AS order_count,
    SUM(total_amount) AS total_spent,
    MIN(order_date) AS first_order_date,
    MAX(order_date) AS last_order_date
FROM orders
GROUP BY customer_id
```

`models/marts/customer_360.sql`：
```sql
WITH customers AS (
    SELECT * FROM {{ ref('int_customer_orders') }}
)
SELECT
    customer_id,
    order_count,
    total_spent,
    total_spent / NULLIF(order_count, 0) AS avg_order_value,
    first_order_date,
    last_order_date,
    CASE
        WHEN order_count >= 10 THEN 'VIP'
        WHEN order_count >= 5 THEN 'Regular'
        WHEN order_count >= 2 THEN 'Occasional'
        ELSE 'One-time'
    END AS customer_tier
FROM customers
```

## 第16章 · Airflow：任务调度（L5）

### 16.1 最小 DAG 示例

```python
from airflow import DAG
from airflow.operators.python import PythonOperator
from airflow.operators.bash import BashOperator
from airflow.operators.email import EmailOperator
from datetime import datetime, timedelta

default_args = {
    'owner': 'data-team',
    'retries': 1,
    'retry_delay': timedelta(minutes=5),
    'email_on_failure': True,
}

with DAG(
    dag_id='daily_report',
    default_args=default_args,
    description='每日自动化报表：SQL取数 → pandas处理 → 发送邮件',
    schedule_interval='0 8 * * *',  # 每天早上8点
    start_date=datetime(2025, 1, 1),
    catchup=False,
    tags=['report', 'daily'],
) as dag:

    extract = BashOperator(
        task_id='run_sql_query',
        bash_command='python /app/scripts/extract_data.py',
    )

    transform = PythonOperator(
        task_id='process_with_pandas',
        python_callable=lambda: __import__('scripts.transform').transform.main(),
    )

    send_email = EmailOperator(
        task_id='send_report_email',
        to='team@company.com',
        subject='每日数据报告 {{ ds }}',
        html_content='报告请见附件',
    )

    extract >> transform >> send_email  # 依赖关系：串行执行
```

### 16.2 核心概念

| 概念 | 一句话 |
|------|--------|
| DAG | 有向无环图——所有 Task 的编排蓝图 |
| Operator | 一个 Operator = 一个 Task (Python/Bash/Email/SQL) |
| Schedule | cron 表达式，定义多久跑一次 |
| `>>` | 定义依赖：A >> B 表示 A 完成后才跑 B |
| retries | 失败自动重试次数 |

## 第18章 · 常见错误 + 解决方案

| 错误 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: No module named 'src'` | `PYTHONPATH` 没设 | 在 `main.py` 最开头加 `import sys; sys.path.insert(0, '.')` |
| `FileNotFoundError: data/orders.csv` | 工作目录不对 | 用 `pathlib.Path(__file__).parent / 'data' / 'orders.csv'` |
| GitHub Actions 报错 `No such file` | 路径写死了 Windows 格式 | 全部改成 `pathlib.Path` |
| `pip install` 后 import 还是报错 | 装了全局 Python 没装在 venv 里 | 确认命令行前面有 `(venv)` |
| git push 被拒绝 | 有人在同一个分支 push 了 | `git pull --rebase` 再 `git push` |
| pytest 找不到测试 | 测试文件名不是 `test_*.py` | 重命名为 `tests/test_xxx.py` |
| merge 后行数暴涨 | 一对多 JOIN | 检查 join key 是否唯一；加 `assert` 验证 |
