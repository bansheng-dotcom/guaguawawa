# 指标与数据验证质量指南

## 1. 这类报告做什么

指标框架位于需求分析、PRD 和 MVP 验证之间。它把“我们觉得有价值”变成“我们用什么信号判断有效”。

| 输入 | 输出 |
| --- | --- |
| 需求分析报告 | 成功指标、数据缺口、Go/No-Go |
| PRD 草稿 | 指标树、指标字典、护栏指标 |
| MVP 假设 | 实验指标、通过标准、停止标准 |
| 数据缺失场景 | 证据更新计划和替代信号 |

## 2. 好指标的标准

| 标准 | 说明 |
| --- | --- |
| 连接决策 | 能决定做、停、改、上线或回滚 |
| 可定义 | 有口径、单位、粒度、时间窗、排除项 |
| 可获得 | 知道数据源，或明确待补数据 |
| 可行动 | 团队知道影响它的输入动作 |
| 有护栏 | 不让主指标伤害体验、质量、成本或信任 |

## 3. 指标分层

| 层级 | 问题 | 示例 |
| --- | --- | --- |
| 北极星指标 | 最终希望改变什么结果 | 激活率、留存、有效分析完成数 |
| 输入指标 | 哪些行为驱动结果 | 首次配置完成率、模板使用率 |
| 护栏指标 | 不能被伤害什么 | 错误率、投诉率、处理时长、成本 |
| 商业指标 | 是否支持业务目标 | 付费转化、续费、客单价 |

## 4. 数据缺口处理

| 数据状态 | 写法 |
| --- | --- |
| 有数据 | 写来源、口径、样本和时间窗 |
| 部分有 | 写能支持什么，不能支持什么 |
| 没有数据但低风险 | 写假设版指标和补证据计划 |
| 没有数据且高风险 | 不给确定结论，先补证据 |

## 5. 常见反模式

- 只写“提升用户满意度”，没有定义怎么测。
- 只有结果指标，没有输入指标。
- 只有增长指标，没有体验、质量、成本护栏。
- 没有基线却写精确目标值。
- 用平均值掩盖分群差异。
- 把数据分析执行任务混进 PM 指标定义流程。
