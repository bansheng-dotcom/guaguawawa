# 知识科普写作 Agent

为「AI数据分析社群」知识星球生产科普/知识类文章的主工作流。

设计原则：
- 先搭知识框架，再写正文
- 先补证据，再做润色
- 先代码检查，再交给 LLM 审查
- 细纲一旦确认，只补内容，不重写结构

---

## 入口判断

当任务是以下类型时，使用这套流程：
- 知识科普文章
- 工具解析、方法拆解、实验复盘
- 需要先研究、再写作、再审查的知识星球文章

不要用这套流程处理：
- 纯公告
- 纯营销软文
- 已有完整成稿、只需微调几句的文章

---

## 标准产物

选题 ID 统一记为 `{id}`。默认使用以下文件名：

- `tmp/{id}-outline.md`
- `tmp/{id}-detailed-outline.md`
- `tmp/{id}-draft.md`
- `state/reviews/{id}.json`

如果某次实验使用了 `01-选题+大纲.md`、`02-细纲.md`、`03-文章.md` 这类阶段编号文件，可以保留；但归档前要能映射回上面的标准文件名。

---

## 六阶段总览

```text
选题确认
  -> topic-knowledge-architecture
  -> 阶段1 大纲
  -> 阶段2 细纲
  -> 阶段3 研究填充
  -> 阶段4 名词解释注入
  -> 阶段5 成文组装
  -> scripts/check_article.py (原项目)
  -> 阶段6 回溯审查
  -> 人工终审
  -> 发布
```

## 阶段契约

### 阶段1：大纲

目标：定义文章各段要回答的问题，不提前写完整正文。

输入：
- 选题需求
- `D:\知识库\projects\知识星球自动更新-AI社群\skills\topic-knowledge-architecture\SKILL.md` 的知识体系输出

输出格式：

```md
# [文章标题]

## 一、[段落主题]
回答：[这段要回答读者的什么问题]

## 二、[段落主题]
回答：[这段要回答读者的什么问题]
```

完成标准：
- 每一段都对应一个明确问题
- 顺序合理，读者能从“为什么关心”走到“能做什么”

产物：`tmp/{id}-outline.md`

人工闸门：需要渭河确认后再进入阶段2。

### 阶段2：细纲

目标：把段落拆成可以独立研究的论点单元。

输入：
- 大纲
- 原始选题需求

输出格式：

```md
## 一、[段落主题]
回答：[继承自大纲]

1.1 [论点标题]
  论点: [一句话核心主张]
  需要解释: [需要白话解释的概念]
  需要引用: [需要找的论文/数据/官方口径]
  需要案例: [需要补的场景或案例]
  待研究: [尚未掌握、需要搜索的内容；没有则写 —]
```

必须有：
- 每个论点只说一件事
- 明确区分“已知结论”和“待研究事项”
- 文末保留 `## 名词预扫描`

产物：`tmp/{id}-detailed-outline.md`

人工闸门：需要渭河确认结构。确认后不再大改章节结构。

### 阶段3：研究填充

目标：只补证据，不写整篇文章。

角色：研究员，详细规范见 `agents/researcher.md`

输入：
- 当前处理的单条细纲项
- 限制在单条任务范围内的最小上下文

输出格式：

```md
研究发现：
[来源：作者/机构, "标题", 年份]
[关键数据或结论]
链接：[URL]

为什么发生：
[机制解释]

这意味着什么：
[与本文论点的关系]
```

完成标准：
- 至少有 2 个可追溯来源，优先原始来源
- 不能补写细纲里没有的全新主张
- 找不到就写 `待补充`，不编造

产物：直接追加到 `tmp/{id}-detailed-outline.md`

### 阶段4：名词解释注入

目标：把“读者可能卡住的术语”提前处理掉。

输入：
- 已填充的完整细纲

操作：
1. 扫描专有名词、产品名、技术术语
2. 只给真正影响理解的词加解释
3. 在首次出现位置附近插入解释标记

格式：

```md
[名词解释: Transformer = 一种让模型理解整段上下文关系的神经网络结构]
```

完成标准：
- 解释控制在 20-40 字左右
- 白话、准确、不过度展开
- 不为解释而解释

### 阶段5：成文组装

目标：把已经准备好的材料组装成文章；不新增论点，不补新研究。

输入：
- 完整细纲
- 阶段3 的研究填充
- 阶段4 的名词解释

写作规则：
1. 只使用施工图里的论点、数据、引用
2. 按细纲原顺序展开
3. 每个论点优先遵循“研究发现 -> 为什么发生 -> 这意味着什么”
4. 开头要有具体场景、问题或反直觉事实
5. 首次出现的名词自然嵌入解释
6. 结尾补 3-5 个延伸阅读或后续选题
7. 语言要像人解释问题，不像教科书，也不像客服

产物：`tmp/{id}-draft.md`

写完后立刻执行：
- `python D:\知识库\projects\知识星球自动更新-AI社群\scripts\check_article.py tmp/{id}-draft.md`

### 阶段6：逻辑回溯审查

目标：对照细纲检查成文是否漏写、跳步、编造或有 AI 味。

角色：审查员，详细规范见 `agents/reviewer.md`

输入：
- 草稿全文
- 细纲原文

产物：`state/reviews/{id}.json`

不通过处理：
- 只退回阶段5修改
- 除非发现细纲本身错了，否则不回退到阶段2

---

## 强制规则

- 发布前必须通过 `D:\知识库\projects\知识星球自动更新-AI社群\scripts\check_article.py`
- 发布只能人工触发，Agent 不得调用 `D:\知识库\projects\知识星球自动更新-AI社群\scripts\publish_article.mjs`
- 每阶段都要落盘，不能只在对话里完成
- 研究阶段优先补证据，不优先追求文风
- 成文阶段不能偷偷新增研究结论
- 审查阶段只报问题，不代写文章

---

## 失败回退

- 大纲不清楚：回到 `topic-knowledge-architecture`
- 细纲颗粒度太粗：重做阶段2
- 研究证据不足：只重做对应条目的阶段3
- 草稿 AI 味重或逻辑断裂：重做阶段5
- 代码检查未通过：先修草稿，再进阶段6
