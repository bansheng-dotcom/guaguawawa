# 渭河文风语言库

## 使用原则

这些不是固定口头禅，而是功能句。下游 agent 使用时要先判断段落功能，再选择表达。

## 1. 判断句

功能：给出作者判断，建立取舍。

- “真正的问题不是 X，而是 Y。”
- “这个指标本身不是结论，它对应的业务场景是……”
- “这件事的关键不在于有没有数据，而在于数据能不能推动动作。”
- “如果只从公式上看，这个结论是成立的，但在业务里还不够。”
- “这里不能简单理解为 X，因为 Y。”
- “这不是一个单纯的技术问题，而是一个业务判断问题。”
- “这个指标能解释现象，但不能直接成为策略。”

## 2. 转折句

功能：从表层理解切到深层逻辑。

- “但是在真实业务里，问题往往不是这样展开的。”
- “问题在于，这个拆法只能解释结果，不能指导动作。”
- “如果只按这个公式继续往下拆，就会漏掉真正的业务场景。”
- “这也是很多分析师容易误判的地方。”
- “看起来是在分析指标，实际上是在判断业务资源怎么分配。”
- “所以这里要先停一下，不能急着往下套模型。”

## 3. 解释句

功能：把抽象指标翻译成读者能理解的业务场景。

- “换句话说，这个指标背后对应的是……”
- “你可以把它理解成……”
- “落到业务里，其实就是……”
- “它不是一个孤立的数据变化，而是几个业务动作叠加后的结果。”
- “这个时候看指标，不是为了知道数字本身，而是为了知道谁能改变它。”
- “数据只是把问题暴露出来，真正要解释的是背后的业务机制。”

## 4. 推进句

功能：带读者从一层问题进入下一层。

- “到这里，我们只能得到一个阶段性结论。”
- “接下来要继续往下拆。”
- “再往下一层看，问题会变得更具体。”
- “这时候就不能只看总量了，要开始看结构。”
- “如果这个判断成立，下一步要验证的是……”
- “所以我们需要把这个指标重新拆一层。”

## 5. 边界句

功能：限制结论，避免万能化。

- “这并不意味着 X 一定成立。”
- “这个方法解决不了 Y。”
- “不能把这个结论直接外推到所有场景。”
- “这个判断只适用于当前这种业务条件。”
- “如果换成另一个城市/用户/阶段，结论可能要重新看。”
- “这里还缺一个验证，所以只能先作为阶段性判断。”

## 6. 收束句

功能：把分析落到动作或下一步。

- “所以报告里真正要跟踪的是……”
- “接下来不是继续堆指标，而是把这个问题变成一个专项。”
- “这类问题最后要落到看板、复盘和业务动作上。”
- “到这一步，分析师的价值不是给答案，而是帮助业务选择下一步。”
- “这也是为什么同样一个指标，不同人会拆出完全不同的结论。”

## 7. 禁用或慎用表达

这些表达容易产生 AI 味或模板味：

- “综上所述”
- “具有重要意义”
- “赋能业务”
- “提升用户体验”
- “优化运营策略”
- “加强精细化管理”
- “多维度分析”
- “持续关注”

不是绝对不能用，但必须补充具体对象、动作、指标和边界。
