# Strategy Profiles

策略层只负责内容协议，不负责工作流结构。

固定边界：

- 允许定义：目标、章节意图、概念解释策略、步骤边界规则、自动推断信号、提示后缀
- 禁止定义：节点、边、provider、model、并发图、回退图

机器可读配置位于：

- `references/strategies/knowledge-explainer.json`
- `references/strategies/teaching-playbook.json`

## knowledge-explainer

- 目标：帮助读者理解一个命题、概念、原理或方法边界
- 默认结构：问题、概念、原理、证据、边界
- 概念解释：只要不解释会阻塞理解，就先做最小解释
- 成功标准：读者真正理解了，不要求立刻照做复现

## teaching-playbook

- 目标：帮助读者先理解要得到什么结果、该走哪条路径，再按步骤做成一件事，并在失败时知道先查哪一层
- 默认结构：目标与结果、基础概念、执行路径、执行步骤、代码或提示词样例、验证、排错、边界、附录
- 概念解释：只解释会阻塞执行、影响路径选择、容易混淆、或影响排错判断的词
- 成功标准：读者知道为什么这样做、知道自己该走哪条路、能照着做，并知道哪里该停、哪里该查

## Step Boundary Rule

以下情况可以合并为同一步：

- 不需要切换页面
- 不需要更换软件
- 不需要新增权限或登录
- 不需要等待独立结果
- 不需要基于前一步结果做分支判断

以下情况必须拆成新步骤：

- 需要跳转到新页面
- 需要切换到另一个工具或软件
- 需要输入新的密钥、权限、配置
- 需要等待明确输出再决定后续动作
- 失败后会进入不同排查路径
- 验证目标已经变化

总规则：

- 同一执行场景、同一验证目标、同一失败域就合并；否则拆步

## Required Tutorial Step Fields

教学步骤策略下，重点步骤默认应能落到以下字段：

- 目标
- 前提
- 操作
- 预期结果
- 失败现象
- 排查
- 下一步
