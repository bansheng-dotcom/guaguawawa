## 模块 8：经营分析 — 四大模块框架

### 经营分析 vs 数据分析

| 经营分析 | 数据分析 |
|----------|----------|
| 定期体检（全面扫描） | 专项手术（针对具体问题） |
| 固定周期（周/月/季） | 无固定周期 |
| 好坏都说，全面拉通 | 聚焦命题，深入解决 |
| Excel 或在线文档 | Jupyter/Python/各种形式 |

### 报告四大模块

**模块一：目标达成情况**（干得怎么样）
- 核心 KPI × 完成率 × 时间进度差
- 红绿灯标注，谁好谁坏一目了然

**模块二：指标拆解**（为什么好/差）
- MECE 原则下钻
- 订单 = 车辆侧 × 用户侧 = (活跃车数×翻台率) × (用户数×人均订单)
- 拆到具体责任部门/人

**模块三：资源配置**（钱花得值不值）
- 投入产出 ROI 分析
- 成本花给了谁？效果如何？下一步怎么调？

**模块四：专题分析**（近期重点做什么）
- 新功能评估、大促复盘、新渠道研究

### 三条灵魂问题
1. 这笔成本（资源）花给了谁？
2. 效果如何？
3. 下一步应该怎么调整？

## 模块 9：指标体系设计

### OSM vs CMOP

| | OSM | CMOP |
|---|---|---|
| 逻辑 | 目标→策略→度量 | 全面→度量→组织→流程 |
| 适用 | 新业务冷启动 | 复杂的互联网平台 |
| 分析师角色 | 执行者（写SQL） | 建设者（设计+推动+迭代） |

### CMOP 四要素
- **C (Comprehensive)**：全面描述对业务有影响的所有指标
- **M (Measurement)**：剪枝——剔除对最终目标无影响的冗余指标
- **O (Organization)**：指标与具体部门权责挂钩
- **P (Process)**：建立监控/复盘/新增/退出流程

### 面试回答框架
1. 先用 OSM 展示结构化思维（目标-策略-度量）
2. 再补充 CMOP 的组织和流程视角（体现深度）
3. 举一个真实例子，说明如何通过指标体系定位到具体部门的问题

## 模块 10：因果推断方法

### 方法选择决策树

```
能开 AB 实验？
├── 是 → AB 实验（黄金标准）
└── 否 → 有面板数据+协变量？
    ├── 是 → PSM-DID（最稳健）
    ├── 仅有横截面+丰富协变量 → PSM
    ├── 仅有时间序列+对照组 → DID
    └── 只有一个处理单元 → 合成控制法(SCM)
```

### PSM（倾向得分匹配）
- **核心**：「找个长得像的」
- **步骤**：Logistic回归算倾向得分 → 最近邻匹配 → 平衡性检验
- **局限**：无法解决不可观测混杂因素

### DID（双重差分）
- **核心**：「减去时间趋势」
- **前提**：平行趋势检验（最关键！）
- **公式**：(处理后-处理前) - (对照后-对照前)

### PSM-DID（组合拳）
- **先 PSM** 匹配出干净对照组
- **再 DID** 消除不随时间变化的混杂
- **最后**：安慰剂检验 + 稳健性检验

## 补充模块 C1：用户增长分析

### 核心三维度
- **付费金额**：花了多少钱 → 客单价/ARPU
- **在线时长**：用了多久 → DAU×人均时长
- **访问频率**：来了几次 → 频次/留存

### AARRR 海盗模型
| 阶段 | 核心问题 | 指标 |
|------|----------|------|
| 获客 | 从哪来？渠道质量？ | CAC、渠道转化率 |
| 激活 | 首次体验是否顺畅？ | 激活率、首次关键行为 |
| 留存 | 会不会回来？ | 次留/7留/30留 |
| 变现 | 是否付费？ | 付费率、ARPU、LTV |
| 传播 | 是否推荐？ | K因子、邀请转化率 |

### 同期群分析（Cohort Analysis）
**定义**：固定一批用户，看某指标随时间变化
**价值**：避免「平均化」误导，精准评估策略效果

### 留存本质
**留存是结果，不是原因**。是供应/价格/体验共同作用的结果。别只盯着留存数字，要拆到留存下降的业务根因。

## 补充模块 C2：供需模型（双边市场分析）

### 四象限诊断矩阵

| 完单率 | 司机利用率 | 诊断 | 策略 |
|--------|-----------|------|------|
| 高 | 高 | 供需双优 | 维持，持续监控 |
| 低 | 高 | 供小于求 | 拉司机/加补贴 |
| 高 | 低 | 供大于求 | 拉乘客/发券 |
| 低 | 低 | 供需双差 | 深入分析匹配机制 |

### 核心指标
- **完单率(GCR)**：完成的订单/总发单 → 供给满足需求的程度
- **总计费时长占比**：有单时长/在线总时长 → 需求满足供给的程度

### PDS 模型（用户增长系统化）
日活 = 老用户留存 + 沉睡用户回流 + 新用户拉新 - 流失
- K因子 = 新用户数/日活用户数（拉新效果）
- 睡眠率 = 次日未登录/日活（粘性）
- 回流率 = 次日活跃的睡眠用户/睡眠用户数
- 流失率 = 次日流失的睡眠用户/睡眠用户数

## 补充模块 C3：数据产品与分析师价值

### 分析师在数据产品中的角色

| 角色 | 做什么 |
|------|--------|
| **需求翻译官** | 把模糊需求翻译成可执行的数据产品需求 |
| **指标体系设计者** | 为产品提供科学的指标框架 |
| **策略逻辑提供者** | 把分析逻辑固化到产品中 |
| **产品落地推动者** | 跨团队推动产品从0到1 |

### 分析师不沦为「取数机」的关键
1. **独立价值**：主动发现业务问题，而非被动接需求
2. **资源配置引导**：通过分析告诉老板钱该往哪投
3. **矛盾化解**：在多部门间用数据说话
4. **产品化思维**：把重复性工作沉淀成工具
