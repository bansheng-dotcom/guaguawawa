# 模块C · 探索性与产品分析
> 蒸馏自: 补充技能/01-当前能力域/nimrodfisher__data-analytics-skills/03-data-analysis-investigation/SKILL.md, 补充技能/01-当前能力域/nimrodfisher__data-analytics-skills/01-data-quality-validation/SKILL.md, 补充技能/01-当前能力域/nimrodfisher__data-analytics-skills/04-data-storytelling-visualization/SKILL.md

> 整合自 data-analytics-skills 技能库。核心主张：**在谈论任何业务指标前，必须先验证数据质量，明确分母与分段，并以驱动业务决策为最终目标**。

## C1. 数据质量与基线验证 (Data Quality & Baseline)

所有分析的第一步是建立数据信任度。未经质量验证的探索只会导致错误的业务决策。

- **核心原则**：不信任未经审计的数据源。在产出任何分析结论前，必须完成空值、重复、参照完整性与新鲜度检查。
- **验证维度**：
  - **空值与完整性**：核心维度字段（如 user_id, session_id）空值率须严控（如 < 0.1%）。
  - **唯一性与重复**：区分是业务正常的重复（如多次购买）还是底层数据管道的 fan-out 错误。
  - **新鲜度 (Freshness)**：对比当前查询数据时间与业务期望延迟 (SLA)。滞后数据不能用于实时决策。
  - **业务阈值域**：如年龄 `0-120`，订单金额 `>0`，异常极值需确认是脏数据还是核心业务现象（如超级大客）。

## C2. 漏斗分析与转化 (Funnel Analysis)

用于诊断多步流程（如注册、购买）的流失节点，寻找最大转化杠杆。

- **构建四要素**：
  1. **严格顺序**：用户必须按序到达，跨步或倒置视为不符合规则（或需另行定义路径分析）。
  2. **绝对互斥**：每人在每一步的计数唯一，去重聚合。
  3. **分母锚定**：第一步即定义了“全集”，切忌中途更换口径。
  4. **时间窗口**：根据业务属性定义合理窗口。高频如 24 小时，低频如 7-30 天。
- **两种转化率**：
  - **整体转化率**：最后一步 / 第一步。对外沟通、汇报核心指标。
  - **步骤转化率**：第 N 步 / 第 N-1 步。寻找“漏水”最严重的环节。
- **行动指南**：通过**绝对流失量 × 预期人均价值**估算流失的财务影响 (Opportunity Cost)。在流失最大的节点下钻维度（设备、渠道、新老客）。

## C3. 留存与同期群分析 (Cohort Analysis)

评估产品是否真正留住用户，衡量长期产品健康度。

- **定义基准**：
  - **同期群 (Cohort)**：按某一初始事件（如首单、注册月）对用户分组。
  - **回访事件 (Activity)**：什么行为才算“留存”？（登录不等于活跃，有核心价值操作才算）。
- **表格结构**：Rows = Cohort (如 2023-11)，Cols = Periods (如 Month 0, Month 1)。Period 0 必须是 100%。
- **核心规律**：
  - 关注“留存曲线”是否趋于平缓（**Smile Curve** 是好兆头）。
  - SaaS 留存标杆：NRR (净收入留存) ≥ 100% 优秀，< 90% 需警报；Logo Churn (客户数流失) ≤ 5% 优秀。
- **寿命与价值**：预估寿命（月） = 1 / 月流失率。LTV:CAC 比例指导获客，≥ 3:1 为健康。

## C4. 分段与聚类 (Segmentation & Clustering)

拒绝平均数掩盖真相，将用户划分为特征清晰、可行动的群体。

- **预定义 vs 数据驱动**：
  - **预定义 (Rule-based)**：如 RFM（最近一次消费、频率、金额）。易解释，可直接接入营销系统。
  - **数据驱动 (K-Means)**：寻找隐性模式。使用前须标准化 (Z-score)。特征 3-7 个，`k` 组数建议 3-7。
- **K-Means 有效性评估**：
  - 轮廓系数 (Silhouette Score) ≥ 0.3 视为聚类有一定结构。
  - 每组人数不能太少（通常预期每组 ≥ 100 人或占总量的 5% 以上）。
- **画像解释与策略映射**：
  - 计算各段在特征上的均值，并对比总体均值（`vs_overall_pct`）。挑选偏离最大的 2 个特征定义该段。
  - 必须映射到具体业务策略：如 **Retain & Expand** (高价值), **Monetise**, **Activate** (沉睡), **Win-Back** (流失挽回)。如果多个群体你采用相同的策略，则分群无效。

## C5. 根因下钻分析 (Root Cause Analysis - RCA)

当关键指标出现异动（>3% 的意外偏离或异常的 WoW 波动）时启动，拒绝拍脑袋猜测。

- **七步探底法**：
  1. **确认信号**：用 Z-score 或异常检测确认不是正常波动，排查数据管道问题。
  2. **界定时间轴**：是瞬时骤降 (Step change) 还是缓慢阴跌 (Drift)？
  3. **关联已知事件**：对比发版记录、节假日、营销活动日历。
  4. **维度拆解**：使用公式 `(值_b - 值_a) / 总变化` 计算各维度（渠道、国家、平台）的绝对贡献度。
  5. **生成假设**：列出可能原因，按（可能性 × 易测性）排序。
  6. **实证验证**：拒绝或接受假设，寻找交叉证据。
  7. **结案与对策**：不只有原因，还要有影响量化和短期/长期预防对策。
- **陷阱提示**：谨防 **辛普森悖论**（整体趋势与分组趋势相反，必须切分维度看问题）。

## C6. 趋势与时间序列 (Time Series Analysis)

分离噪音，识别真实业务方向。

- **四大成分**：趋势 (Trend) + 季节性 (Seasonality) + 循环 (Cyclic) + 残差/噪音 (Residual)。
- **季节性评估**：`Seasonality Strength = 1 - var(残差)/var(总量)`，≥0.6 视为强季节性。强季节指标优先看同比 (YoY) 以剔除季节影响。
- **异常检测**：使用抗离群算法，如基于中位数的 `|当前值 - 滚动中位数| > 3 * 1.4826 * 全局 MAD`，避免传统均值被极端异常值拉偏。
- **底线原则**：最少数据点 `min_points = 6`。没有足够的数据长度，拒绝进行虚假预测或趋势下定论。

## C7. 从数据到洞察交付 (Insight Synthesis & Storytelling)

停止交付“数据罗列”和“查数表”，转而交付“高管摘要 (Executive Summary)”和“决策主张”。

- **洞察提炼三步法 (So What -> Why -> Now What)**：
  - 现象：发生了什么。
  - 归因与影响：为什么重要？影响多少钱或多少用户？
  - 行动：业务部门接下来该做什么。
- **金字塔原理 (Pyramid Principle)**：
  - 结论先行。将洞察放在标题，证据在正文，详情在附录。
  - 避免“悬念式”报告。执行高管不需要侦探小说。
- **可视化准则**：
  - 明确图表类型：对比用条形图，趋势用折线，分布用直方。
  - 视觉层级：突出最核心的线或柱子，淡化网格和无用边框 (Data-ink ratio)。
  - 标题即结论。如：“移动端流失率是 PC 端的两倍”，而非“流失率按设备类型分布”。
- **仪表板规范 (Dashboard Spec)**：
  - 一个 Dashboard 只能回答一个核心问题。
  - 10-12 个指标上限。遵循：Hero指标 -> 趋势分析 -> 维度下钻。
