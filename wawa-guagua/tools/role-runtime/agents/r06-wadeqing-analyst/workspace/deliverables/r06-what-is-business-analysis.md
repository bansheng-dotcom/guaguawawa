# 商业分析怎么做：从业务问题到可复算的数字结论

> 角色：R06 蛙得清（数据分析师，战略、数据与智能层）
> 主题：商业分析本身怎么做——数据侧的方法与纪律
> 术语与阈值来源：`SKILL.md`、`references/00-capability-charter.md`、`references/01-metric-semantics.md` 及 `references/02`–`06`
> 适用对象：需要发起或采信分析结论的业务方、产品方，以及协作角色 R07（优先级与决策汇报）、R03（正式财务/统计意见）、R18（数据链路）、R19（模型工程）
> 结论：商业分析不是「给个分析」，是**给个别人能重新算一遍的分析**。

---

## 一、数据分析在商业分析里的角色

商业分析的产出物不是观点，是**数字结论**。而一个数字结论要在商业上站得住，必须同时满足三个条件，缺一不可。

| 条件 | 含义 | 不满足的后果 |
|---|---|---|
| **可复算** | 给出指标口径、时间窗口、过滤条件与粒度后，任何人用同一份数据能算出同一个数 | 结论无法被验证，只能靠信任传递，无法跨部门对齐 |
| **可验证** | 每个数字能回溯到具体的结果对象（result），而非口头转述 | 汇报链条上失真，无法追责也无法修正 |
| **有边界** | 明确声明结论在什么数据、什么口径、什么假设下成立 | 结论被外推到自己不成立的场景，造成错误决策 |

因此 R06 对商业分析的定义是：

> **把业务问题变成可复算、可验证的数字结论——不是「给个分析」，是「给个别人能重新算一遍的分析」。**

这条定义带来两个直接纪律：

1. **无标准则无分析**。口径不统一时，两张报表数字不同不是「小问题」，而是分析尚未开始。R06 的职责边界是**管数字说明什么（分析结论）**，而 R18 管数据怎么流（ELT/数仓）；两者不可互相代偿。
2. **无业务视角则无价值**。一个算得完全正确、但没人用它做决策的指标，是成本不是资产。因此每个指标必须回答「谁用、用于什么决策」。

在实际落地顺序上，商业分析通常沿「问题受理 → 口径定义 → 数据体检 → 探索诊断 → 根因分解 → 统计验证 → 结论交付」推进。**这个顺序只是叙述上的自然次序，不是本方法论的卖点**；真正的门禁是每一环都必须交出可复算的证据才允许往下走，任何一环 FAIL，分析就停在原地，不许「先出结论再补数据」。

## 二、指标口径 7 问：口径未定，禁止上线汇报

一个指标只有当下列 7 个问题都能被精确解答、且可被计算引擎直接执行时，才算「定义完成」；否则一律视为 **「口径未定，禁止上线/汇报」**。

### 2.1 7 问清单

| # | 问题 | 要答到什么程度 | 典型缺失后果 |
|---|---|---|---|
| 1 | **这是什么** | 一句白话，业务人员一听就懂 | 跨部门对同一名词各说各话 |
| 2 | **怎么算** | SQL / 公式 / 明确的分步逻辑，精确到字段和函数 | 无法复算，数字只能被相信不能被检验 |
| 3 | **粒度** | 聚合的底层单位，一行代表什么（如「每账户每月」，而非模糊的「每事件」） | JOIN 后记录倍增，口径被 DISTINCT 错误掩盖 |
| 4 | **纳入 / 排除** | 默认看不出的过滤条件（测试单、内部账号、退款、未支付、特定渠道） | 两套报表差异的第一大根因 |
| 5 | **边界 Case** | 升级如何计费、跨币种如何换算、试用期转化为付费怎么算、30 天内退款怎么追溯 | 长尾场景反复引发对账争议 |
| 6 | **谁用，用于什么决策** | 消费方是谁，决定口径的严格程度和时效要求 | 用宽松口径支撑高频决策，或用严格口径拖死时效 |
| 7 | **多少算好** | 业务目标值 / 告警阈值（低于多少需要介入） | 数字只有描述力，没有决策力 |

### 2.2 门禁规则

- **7 问未答完 → 口径未定 → 禁止上线、禁止汇报。** 这不是建议，是硬拦截。
- 口径必须以标准文档（YAML / Markdown）落盘，明确**分子、分母、过滤条件、时间维度（及所属时区）、业务粒度**，形成唯一真理来源。
- 口径定义完成后，还需通过**防幻觉联动**校验：逐个核验每个表达式引用的列在真实数据中确实存在，并对度量做一次实算。
- 拒绝把指标定义留在某个人脑子里或某张看板的工具配置里——那是「漂移」，不是「定义」。

## 三、指标四类型

任何指标都可以归入以下四类之一。**分类的意义在于：它决定了这个指标能不能直接求和、能不能跨期相除、以及在对账时该用什么方式复算。**

| 类型 | 定义 | 示例 | 关键纪律 |
|---|---|---|---|
| **Simple 简单** | 单一度量的直接聚合 | 总订单量、总活跃用户数 | 可直接按时间区间求和；跨维度可加 |
| **Ratio 比率** | 分子 ÷ 分母（二者皆聚合） | 转化率 = 支付用户数 / 访问用户数 | **不可对比率求平均**；必须先算分子分母再相除；分子与分母的时间窗口必须严格一致 |
| **Cumulative 累计** | 自起始时间的滚动求和 | 累计收入、历史累计下载量 | 只增不减；**不可跨期相加**（会把同一段历史重复计入） |
| **Derived 派生** | 已定义指标的四则运算组合 | NRR = (期初MRR + 扩张 − 流失) / 期初MRR | 依赖的下层指标必须全部已定义且口径一致；任一层口径漂移，派生指标同步失真 |

## 四、常见经营指标的标准口径与防坑

以下口径为 R06 的标准口径，业务方与协作角色在引用时必须逐条对齐，不得自行简化。

### 4.1 收入类

| 指标 | 标准口径 | 防坑要点 |
|---|---|---|
| **GMV** | 支付订单金额之和，**不含退款/取消** | **绝不等同于净收入**。区间汇总按「区间结束日」入账；退款按固定时点（退款时间 or 下单时间）归因，**必须明确且全局统一**。混用两种归因时点，是月度 GMV 对不上的典型原因 |
| **净收入** | GMV − 退款 | 退款时点口径必须提前锁定，不能在结算时才决定 |

### 4.2 用户价值类

| 指标 | 标准口径 | 防坑要点 |
|---|---|---|
| **ARPU** | 收入 / 活跃用户数 | **核心约束：分母与分子的时间窗口必须严格一致**。「本月收入 ÷ 上月活跃用户」这类错配是无效指标 |
| **ARPPU** | 收入 / 付费用户数 | 同上；且付费用户必须是同一窗口内的去重付费用户，不是订单数 |

### 4.3 留存类

| 指标 | 标准口径 | 防坑要点 |
|---|---|---|
| **留存率 D1 / D7 / D30** | 第 N 期仍活跃的 cohort / 期初 cohort | **必须明确声明是 bounded（恰在第 N 期活跃，标准定义）还是 unbounded / rolling（第 N 期起任一时刻活跃）**。二者不可混用，rolling 恒大于等于 bounded，混用会系统性高估留存 |

**行业参考值（用于「多少算好」的判断，不是目标承诺）：**

- App 留存粗标：**D1 > 40% / D7 > 20% / D30 > 10%**
- SaaS：**W1 > 70% / W4 > 50%**

### 4.4 生命周期价值类

| 指标 | 标准口径 | 防坑要点 |
|---|---|---|
| **LTV（简单版）** | ARPU × 毛利率 / 月流失率 | 分母必须是**月**流失率，与 ARPU 口径周期对齐 |
| **LTV（无毛利率时）** | ARPU × (1 / 月流失率) | 只能用于横比，不能当毛利口径金额对外报 |
| **预估寿命（月）** | 1 / 月流失率 | 流失率接近 0 时该估计发散，须标注不可用 |

**LTV:CAC 比例评估标准：**

| 区间 | 判定 |
|---|---|
| **< 1** | **毁灭**（每获客一元亏一元） |
| **1–3** | **边缘** |
| **3–5** | **健康** |
| **> 5** | **极好，或说明获客投入不足** |

> 注意最后一条的双向解读：LTV:CAC > 5 既可能是极优，也可能是**获客投入不足**——即有钱可赚却没敢投。必须结合增长目标判断，不可单看比值下结论。

### 4.5 快照类 vs 求和类

| 类别 | 典型指标 | 正确算法 |
|---|---|---|
| **快照类** | 总量、库存、粉丝数 | 取「筛选期末」最新值，**禁止求和** |
| **求和类** | 新增、流失、净增 | 按时段**求和** |

**快照类求和是最常见也最隐蔽的口径事故**：它不会报错，只会给出一个看起来合理但完全错误的大数。

## 五、口径对账：容差铁律与六大根因

当两个数不一致时，先查根因，再谈容差；根因未定位前，任何「差不多」都是掩盖问题。

### 5.1 六大不一致根因（按频率排序）

| 排序 | 根因 | 说明 |
|---|---|---|
| 1 | **过滤条件不同** | 最常见。测试单、内部账号、退款、未支付、特定渠道是否被排除 |
| 2 | **JOIN 类型不同** | 导致膨胀（多对多 Fan-out）或丢失，且常被 DISTINCT 错误掩盖 |
| 3 | **粒度不同** | 订单级 vs 用户级 vs 账户月级，聚合层级不对齐 |
| 4 | **时区** | UTC vs 本地时区，跨零点统计直接错位 |
| 5 | **定义漂移** | 口径在时间里被悄悄改动，无版本记录 |
| 6 | **刷新滞后** | 一方已刷新、另一方未刷新，属于时序差异而非口径差异 |

排查顺序也按此频率推进；同时重点审查 `LEFT JOIN vs INNER JOIN` 带来的数据发散或截断、`WHERE` 过滤的顺序与空值处理逻辑、以及底层聚合粒度是否对齐。

### 5.2 容差阈值铁律

| 指标域 | 容差 |
|---|---|
| **财务总账** | **0%** |
| **财务经营分析** | **< 0.1%** |
| **营销指标** | **< 1%** |
| **产品互动指标** | **< 2%** |
| **机器学习特征 / 标签** | **< 0.5%** |

**规则：超出对应容差即判定 `fail`，必须追踪计算路径，不得带差异上线。** 对账采用绝对差异和百分比差异**双轨验证**，避免相对值在大基数下失真。

## 六、数据质量六维审计与评分机制

任何分析结论的前提是数据可靠。**质检是门禁，不是事后补救。** 所有进入分析环节的数据必须经过质量审计，并附带质量评分卡。

### 6.1 六维模型与权重

| 维度 | 权重 | 核心关注点与评估算法 |
|---|---|---|
| **Completeness（完整性）** | 20% | 空值率概览；重点区分结构性空值 vs 随机空值，超阈值标记风险 |
| **Accuracy（准确性）** | 20% | 跨字段逻辑自洽（如 `shipped_date >= order_date`）、财务恒等式复算（如 `净利润 = 收入 − 退款 − 折扣`） |
| **Consistency（一致性）** | 20% | 引用完整性（标准 FK 关系，统计孤儿记录率）；跨系统对账差异计算 |
| **Timeliness（及时性）** | 15% | 验证流水线 SLA（最新记录时间戳距当前时间）；回填延迟与管道事件断崖式掉量 |
| **Uniqueness（唯一性）** | 15% | 键级唯一性（PK 和自然键重复率）；整行重复检查；辨别版本迭代还是 Fan-out 错误 |
| **Validity（有效性）** | 10% | 取值范围限制（年龄 0–120，百分比 0–1，枚举值一致性）；离群点与格式校验 |

### 6.2 评分机制

| 分值 | 含义 |
|---|---|
| **0** | 系统失败 |
| **5** | 半数通过 |
| **8** | 仅小问题可用 |
| **10** | 全数通过 |

严重度定级：**CRITICAL / HIGH / MEDIUM / LOW**。触发 CRITICAL 的典型情形：核心营收出现负数、外键孤立率激增、数据延迟超过 **2×SLA**。

### 6.3 硬性门禁阈值

| 项目 | 规则 |
|---|---|
| **空值容忍度** | 核心业务字段（交易金额、用户 ID）空值率 **> 5% 警告，> 30% 熔断（FAIL）**；非核心人口统计学特征（偏好标签）可放宽至 **50%** |
| **重复与扩散** | 整行重复率 **> 0% 触发预警排查，> 1% 熔断（FAIL）**；必须说明键级重复是业务设计（如版本控制 SCD2）还是错误多对多 JOIN |
| **离群点** | IQR 非参数法 `[Q1 − 1.5×IQR, Q3 + 1.5×IQR]`，或正态分布用 `\|z\| > 3`；须定性判断是真实业务信号、数据错误还是系统哨兵值（如 9999-12-31） |
| **关联共线性** | 特征探索阶段 `\|r\| >= 0.8` 提示共线性风险，`\|r\| >= 0.95` 判定为近乎同一度量，需降维或剔除 |
| **参照完整性** | 订单表 `user_id` 须在用户表中存在，**孤儿率 > 0.1% 需告警**；关键财务与订单域孤儿率必须为 0% |
| **新鲜度** | 超出既定 SLA（如 T+1 任务滞后超过 **24h**）为不合格 |

**底线：脏数据必须 FAIL。** 门禁产出的记分卡必须带 `rows_after`、各维度分与 `overall_score`，没有这些字段的质检等于没做。数据质量不过关时，不许进入高管决策层。

## 七、分析方法：从描述到驱动分解

严禁未经探索性分析直接运行复杂模型。分析必须从理解数据本身的「形状」开始。

### 7.1 探索性分析必报项

- **集中趋势与离散程度**：均值、中位数、标准差。
- **分布形态**：5 分位数（p5）、95 分位数（p95）揭示长尾；偏度识别分布非对称性。
- **数据异常监控**：连续变量超出均值 ± 3σ 须单独记录并结合业务语境判定是否剔除；分类变量单类别占比 > 90% 通常表示该特征缺乏信息熵，后续下探需谨慎使用。

### 7.2 漏斗分析

| 要素 | 要求 |
|---|---|
| **严格顺序** | 用户必须按序到达，跨步或倒置视为不符合规则（或另定义路径分析） |
| **绝对互斥** | 每人在每一步的计数唯一，去重聚合 |
| **分母锚定** | 第一步即定义「全集」，切忌中途更换口径 |
| **时间窗口** | 按业务属性定义，高频如 **24 小时**，低频如 **7–30 天** |

两种转化率必须区分：**整体转化率 = 最后一步 / 第一步**（对外沟通与汇报的核心指标）；**步骤转化率 = 第 N 步 / 第 N−1 步**（用于寻找「漏水」最严重的环节）。行动指南：以**绝对流失量 × 预期人均价值**估算流失的财务影响，在流失最大的节点下钻设备、渠道、新老客。

### 7.3 留存与同期群

- **同期群（Cohort）**：按某一初始事件（如首单、注册月）分组；**回访事件**必须定义清楚——登录不等于活跃，有核心价值操作才算。
- **表格结构**：行 = Cohort，列 = Periods；**Period 0 必须为 100%**。
- **核心规律**：关注留存曲线是否趋于平缓（**Smile Curve** 是好兆头）。
- **SaaS 留存标杆**：**NRR ≥ 100% 优秀，< 90% 需警报；Logo Churn ≤ 5% 优秀**。

### 7.4 RFM 与分群

**分群的目的不是为了分群，而是为了差异化行动。**

| 路径 | 说明 |
|---|---|
| **预定义（Rule-based）** | 如 RFM（最近一次消费、频率、金额），易解释，可直接接入营销系统 |
| **数据驱动（K-Means）** | 使用前须标准化（Z-score）；特征 **3–7 个**，`k` 组数建议 **3–7 个** |

有效性校验：

- **轮廓系数（Silhouette Score）≥ 0.3** 视为聚类有一定结构。
- 每组人数不能太少，通常**预期每组 ≥ 100 人或占总量的 5% 以上**。
- 画像解释：计算各段特征均值并对比总体均值，挑选偏离最大的 **2 个特征**定义该段。
- **必须映射到具体业务策略**：Retain & Expand（高价值）、Monetise、Activate（沉睡）、Win-Back（流失挽回）。**如果多个群体采用相同策略，则分群无效。**

### 7.5 根因与贡献分解

当核心指标异动时，采用结构化、可证伪的框架下钻，拒绝「我觉得」式猜测。

**异动触发门槛：**

| 指标类型 | 立案阈值 |
|---|---|
| **营收类** | 非预期偏离 **> 3%** |
| **活跃 / 互动类** | 无法用已知原因解释的周环比（WoW）偏离 **> 5%** |
| **异常 / 错误率** | 任何具有统计显著性的非预期突增（**Z-score > 1.5**） |
| **常规日周波动** | **±1.5 个标准差**以内归为正常波动，记录并结案 |

**已知原因**（大型节假日、计划内停机、大版本发布）不启动标准 RCA。启动前第一步永远是排除数据基建故障：ETL 延迟、调度失败、埋点丢失。

**绝对贡献度公式：**

```
分段贡献度 = (分段期末值 − 分段基线值) / 整体总变化量
```

- **正贡献度** = 拉动大盘往变动方向移动的核心力量。
- **负贡献度** = 逆势而动、拖累大盘的力量。
- **铁律：Δ 贡献各项之和必须等于总变化量。** 若不等，说明维度未穷尽（MECE 破了）或存在重复计算，必须回到拆解步骤修正，不得带着不闭合的分解出报告。
- **注意**：当总体变化量接近 0（各分段涨跌互抵）时，百分比分母失效。此时应直接排查**绝对变动量**，而非百分比。

**三层微观效应分解（Volume-Rate-Mix）**——一个群体的收入下跌，必须回答是「人少了」还是「人不肯花钱了」：

1. **体积效应（Volume）**：单纯由于用户规模涨跌带来的贡献（`Δ受众数量 × 历史人均值`）
2. **率效应（Rate）**：人均转化效率改变带来的贡献（`历史受众数量 × Δ人均效率`）
3. **结构效应（Mix）**：高/低价值用户结构漂移带来的影响（`(当期分段占比 − 基线期分段占比) × 整体基线期总量`）

**帕累托下钻**：按绝对变动量降序，累计解释了 **80%** 变化的前 N 个细分段即为调查标靶。**必须警惕辛普森悖论**——整体趋势与分组趋势可能相反，确认结论前总要下钻到最小颗粒度查看「率」的方向是否反转。

### 7.6 时间序列

- **四大成分**：趋势 + 季节性 + 循环 + 残差。
- **季节性强度** = `1 − var(残差) / var(总量)`，**≥ 0.6 视为强季节性**；强季节指标优先看同比（YoY）以剔除季节影响。**季节性强度 > 0.6 时，所有同比/环比分析必须做季节性调整。**
- **异常检测**：使用抗离群算法，如基于中位数的 `|当前值 − 滚动中位数| > 3 × 1.4826 × 全局 MAD`，避免均值被极端值拉偏。
- **底线原则**：最少数据点 `min_points = 6`。没有足够的数据长度，拒绝进行虚假预测或趋势下定论。

## 八、统计纪律：p 值不是结论

一切涉及对比的分析必须经过统计检验，杜绝凭直觉判断「数据差」。

### 8.1 方法选型清单

| 场景 | 方法 |
|---|---|
| 两组均值对比 | **Welch's t 检验**（默认不等方差） |
| 分类频次 / 比例对比 | **卡方检验** 或**两比例 z 检验** |
| 多组均值对比 | **方差分析（ANOVA）** |
| 前置检查 | 检验前务必通过直方图或正态性检验评估分布前提 |

### 8.2 强制联合报告

- **绝对禁止单独报告 p 值**：p 值不等于效应量。
- **强制联合报告**：`p 值` + `效应量` + `95% 置信区间`。
- **效应量必须按检验类型同报**：**Cohen's d**（均值差）/ **η²**（ANOVA）/ **R²**（回归）/ **Cramér's V**（卡方）/ **相对 Lift**（比例对比）。
- **文案红线**：
  - 相关性描述只能使用「数据提示」「一致于」「不能排除」等审慎词汇。
  - 「我们确信 / 证明」仅能用于通过严格受控实验（A/B）验证的结论。**相关不写成因果。**

### 8.3 防混杂三板斧

- **时间混杂**：对比同周天，避免节假日 / 周末效应。
- **同期群混杂**：按获客时期（Cohort）对齐生命周期。
- **选择混杂**：检查分母（基数人群）的构成是否发生漂移。

### 8.4 A/B 实验纪律

**设计阶段（强制预注册）**：上线前必须敲定 **1 个主指标**、**2–3 个护栏指标（Guardrail metrics）**、**MDE（最小可检测效应）**。实验时长至少覆盖一个完整的周循环（7 天 / 14 天等）。

**样本量计算**：

```
n = 2 · (z_(α/2) + z_β)² · p(1−p) / MDE²
```

常规阈值：**α = 0.05（z = 1.96）**；**功效 Power = 80%（z = 0.84）**。

**评估阶段——SRM 必检**：

- **SRM（Sample Ratio Mismatch）样本比例失配**：**第一步必检**。用卡方检验对比实际流量与预期流量（如 50/50）。
- **红线：若 SRM p < 0.01，立即停止后续指标解读**，实验分流机制存在严重 Bug，**结论无效**。
- **功效 < 0.8 时，不得下「无差异」结论。** 功效不足意味着检验没有能力发现真实存在的效应，此时「不显著」是信息不足，不是证据为无。

**决策矩阵**：

| 情形 | 决策 |
|---|---|
| 主指标显著为正 + 护栏未破 | **建议上线（Ship）** |
| 主指标不显著 | 不上线 |
| 护栏指标显著恶化 | **绝对不上线**（即使主指标极好） |

### 8.5 观察性数据的因果推断

无法做 A/B 时必须采用结构化因果推断框架，避免把「相关」误作「因果」。四步为：**建模**（把业务先验转为因果 DAG，定义干预变量、结果变量与全部可能混杂因子）→ **识别**（判断因果效应能否从观测数据计算，常用后门准则）→ **估计**（拟合，如倾向得分匹配 PSM / IPW）→ **反驳**（添加随机共同原因、安慰剂干预、数据子集替换；若原效应估计剧烈波动，则结论不可靠）。

**关键声明：因果关系无法被绝对证明，只能被反驳。结论只对已调整的观测混杂成立；未观测混杂（隐藏共同原因，如天气、竞对调价）不可消除，必须如实声明。** 复杂的 IV / 双机器学习等模型生产由 R19 承载，R06 的统计检验是**探索前哨**。

## 九、降级纪律：不制造确定性

**数据不足时不制造确定性**，这不是谨慎，是诚信要求。降级必须显式、可见、可追溯。

| 情况 | 行为 |
|---|---|
| **数据不足 / 样本不够** | 返回 `blocked` 或标注「待核实」，**不许用话术补足证据** |
| **重依赖缺失**（scipy / spaCy / dowhy / omicverse） | 后端门禁探测，**如实降级，不假装会算**；生信类无重后端即返回 `blocked`，只给管线脚手架，**不产出数值结论** |
| **因果要求但无实验条件、也无观测混杂清单** | 降级为相关性探索，并在结论中写入声明 |
| **要求正式财务 / 统计意见** | 移交 **R03**，不越权出正式意见 |
| **结论超出数据边界** | 对抗评审点名即 **FAIL**，按 react / writer / controller 回路由 |
| **口径未定** | 不进入计算，先退回口径定义 |

可用的替代表述：**「数据提示」「一致于」「不能排除」「待核实」「置信度：低/中/高」**。
不可用的表述：在证据不足时使用「证明」「必然」「显著提升」等确定性措辞。

## 十、结论如何交到决策

分析的最后一公里是汇报。**交付物不应是数据的堆砌，而必须是支撑决策的逻辑闭环。**

### 10.1 可审计报告的结构

采用**金字塔原理**：结论先行，证据在正文，详情在附录；论据遵循 **MECE（相互独立、完全穷尽）**，3–5 条。重大汇报用 **SCQA** 构建情绪曲线：S 情境 → C 冲突 → Q 疑问 → A 解答。

一份合格的交付物必须包含：

| 区块 | 要求 |
|---|---|
| **决策结论（Recommendation）** | 首段加粗，用明确祈使句指出建议 |
| **核心洞察（Top Insights）** | 3–5 条影响决策的硬核结论，**必须带量化指标** |
| **商业影响量化** | 挂钩具体金额（ARR 增量 / 降本）、效率或战略风险规避金额；**含糊其辞（如「显著提升」）不允许出现在摘要中** |
| **关键论据（Key Evidence）** | 经过筛选的、支持核心洞察的关键图表或下钻结果，**不超过 5 条** |
| **最大风险敞口（Key Risk/Caveat）** | 坦诚列出最有可能导致该结论翻车的一个业务前提假设 |
| **明确下一步（Requested Action）** | 动作 + Owner + Due Date。**没有 Action 闭环的报告只是数字堆砌** |

**图表纪律**：标题即结论（如「移动端结算页 40% 的流失率拖垮了整体转化」，而非「按设备类型的转化率」）；去噪（移除深色网格线、多余边框与坐标轴线）；凸显（只保留 1–2 种前置视觉属性，非核心对比数据退为灰色）。一个 Dashboard 只回答一个核心问题，指标上限 **10–12 个**，遵循 Hero 指标 → 趋势分析 → 维度下钻。

### 10.2 可追溯性要求

- **每个数字可回溯到 result**：报告由渲染器确定性生成，正文中的每个数字都能追到对应的计算结果对象，而非人工抄写。
- 报告必须附带 **QA 清单**（对应 48 图类规格校验）与**置信度声明**（高 / 中 / 低），为决策者提供风险预期。
- **根因类交付的契约不可妥协**：产出中若无清晰的「分段贡献度占比」及「被证伪的假设清单」，一律视为交付不合格——排除错误答案本身就是核心产出。

### 10.3 角色交接

| 交接对象 | 交接内容 | 边界 |
|---|---|---|
| **R07** | 统计验证阶段的**假设与效应量**，由 R07 做优先级排序与决策汇报 | R06 出结论与证据，不做跨部门优先级仲裁 |
| **R03** | **正式财务 / 统计意见** | R06 不越权出具正式财务意见 |
| **R18** | 数据链路问题（ETL 延迟、Schema 变更、埋点丢失） | R18 管数据怎么流，R06 管数字说明什么 |
| **R19** | IV / 双机器学习、生信重后端等模型工程 | R06 统计检验是探索前哨，不是模型生产 |
| **R01** | 结论超边界或口径无法收敛时的升级裁决 | 汇报对象 |

## 十一、边界与降级条件

### 11.1 能力边界

1. **本方法给出的是分析纪律与口径标准，不是业务结论本身。** 结论的成立范围严格受数据覆盖范围、口径定义与时间窗口约束。
2. **统计检验的因果结论只对已调整的观测混杂成立。** 未观测混杂不可消除，任何声称「证明了因果」的表述都超出本方法边界。
3. **不产出正式财务 / 统计意见。** 此类需求移交 R03。
4. **不承担模型生产。** IV、双机器学习（EconML 级）、生信重后端由 R19 承载。
5. **不承担数据链路建设。** ELT、数仓、埋点治理属 R18 职责范围。
6. **不承接口径未定的分析请求。** 7 问未答完即禁止上线汇报，这是入口拦截而非事后补救。

### 11.2 降级条件与对应动作

| 触发条件 | 降级动作 |
|---|---|
| 数据不足 / 样本量不达标 | 返回 `blocked` 或标「待核实」，不制造确定性 |
| 功效 **< 0.8** | **不得下「无差异」结论**，只能报「当前样本不足以判定」 |
| **SRM p < 0.01** | **立即停止后续指标解读**，实验结论整体无效，退回实验设计方排查分流 Bug |
| 对账超出容差 | 判定 `fail`，先定位六大根因，不带差异上线 |
| 数据质量触发熔断（空值 > 30%、整行重复 > 1%、核心营收负数、延迟 > 2×SLA） | **FAIL 并熔断下游管线**，标注受影响行数与业务波及面，脏数据不进决策层 |
| 重依赖缺失（scipy / spaCy / dowhy / omicverse） | 后端门禁探测后如实降级，不假装会算；生信类返回 `blocked`，只给 scaffold |
| 结论超出数据边界 | 对抗评审点名即 **FAIL**，按 react / writer / controller 回路由 |
| 因果要求但无实验条件、也无观测混杂清单 | 降级为相关性探索，结论中显式声明 |
| 维度分解不闭合（Δ 贡献之和不等于总变化） | 不得出报告，退回重新拆解 |

### 11.3 一句话总结

**商业分析的质量不取决于结论有多漂亮，取决于别人能不能用同一份数据把你的数字重新算一遍。** 口径是入口，质量是门禁，统计是纪律，边界是诚信——四者缺一，分析就只是观点。
