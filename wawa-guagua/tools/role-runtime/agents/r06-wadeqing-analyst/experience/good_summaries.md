# 好结论范例（跨 case 通用）

## 核心原则
四层分析框架（数据事实→运营逻辑→组织归因→行动建议）是内部推理工具，不得作为子标题输出。
输出是完整段落和分点列表，读者看到逻辑，不是框架标注。

## 数据边界
- 数据能说明"是什么"：写事实
- 数据能推断"为什么"：写推断，注明推断
- 数据无法回答"谁造成的"：写"需补充[X数据]后确认"
- 组织归因无数据支撑时跳过

## 禁用词替代表

| 禁用 | 替代 |
|------|------|
| 需要关注 | 建议[谁]在[时间]前完成[具体行动] |
| 可能存在问题 | 数据显示[X]，原因指向[Y]（待验） |
| 整体趋势良好 | [指标]从X升至Y，主要来自[A]贡献 |
| 后续需要跟进 | 建议[负责方]在[Q几]前完成[核查项] |
| 有待进一步分析 | 需补充[X数据]，当前无法判断 |
