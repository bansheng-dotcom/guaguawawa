00两条路线，先选一条

不要一上来就搬 125 个文件。

路线包含风险适用
A 最小修复 术语表 + 入口图 + 修门禁假绿 + 四个入口标 deprecated 接近零，不动 .py 结构 只想让新人能接手
B 完整收口 A + core 分包 + claim / prose / card 收敛 中到高，需要兼容期 准备长期维护、持续加功能
建议：先按 A 做一遍（第 2–4 节），把“会假绿的门禁”修掉；再按包推进 B。A 是 B 的安全带，跳过 A 直接搬，等于蒙眼改产线。

02先修“会假绿”的门禁 最高优先级

搬文件时，只有一类门禁会静默通过——那比报错更危险。

2.1 唯一会假绿的地方

文件问题后果
scripts/check_report_isolation.py:41 CORE.glob("report_*.py")，文件一进 core/report/ 就扫不到 永远 PASS，报告层读了知识库也没人知道
scripts/check_convergence.py 16 处 _read("core/xxx.py") 硬编码 文件缺失直接抛错（响，但会挡住搬迁）
scripts/ci_report_checks.py 5 处 python -m core.report_quality 等 路径失效后步骤红（响，可修）

2.3 必须补的证伪测试

门禁修完不等于有效。加一条单测：在 core/report/ 下写临时文件，内容含 import shared.knowledge，断言门禁返回 FAIL；删掉后断言 PASS。

验收动作（人工做一次）：故意违规必须红。做过这一步，后面搬文件才可信；不做，搬家就是在赌。

2.4 收敛门禁怎么改

# scripts/check_convergence.py
WATCHED = {
    "registry":     "core/platform/registry.py",
    "roster":       "core/platform/roster.py",
    "decision":     "core/report/decision_report.py",
    "methods":      "core/report/analysis_methods.py",
    "orchestrator": "core/report/orchestrator.py",
}

def _read(key: str) -> str:
    p = ROOT / WATCHED[key]
    if not p.exists():
        raise FileNotFoundError(f"收敛门禁监视的文件不存在：{p}")
    return p.read_text(encoding="utf-8", errors="replace")

05PR 2–6：core 分包

一个包一个 PR。先搬被依赖的，再搬依赖别人的。

5.1 顺序

platform → data / sources → charts → claims → cards → report → prose

理由：paths / workspace / project / registry / protocol 几乎被所有模块引用，先搬它们，后面的包才有稳定地基。

5.2 每个包的固定六步

  1. 只移动，不改名、不改逻辑 
    git mv core/registry.py core/platform/registry.py
git mv core/paths.py    core/platform/paths.py
  2. 旧路径写 shim，保留一个版本 
    # core/registry.py（兼容层）
from core.platform.registry import *  # noqa: F401,F403
  3. 修包内相对导入与 core.xxx 引用

    用 codemod 或 IDE 重构；不要手工改 117 处 import。

  4. 更新耦合清单 
    python scripts/scan_business_terms.py --write-whitelist
# 同步 configs/gates.yaml / check_convergence WATCHED / ci_report_checks 的 -m 路径
  5. 先跑子集，再跑全量 
    python -m pytest tests/test_orchestration.py tests/test_gates.py -q
python scripts/ci_report_checks.py
  6. 一个包一个 commit 
    git commit -m "refactor(core): move platform modules into core/platform (shims kept)"

5.3 四条硬规则

规则原因
移动与改名分开一个 PR 同时改路径和名字，diff 无法审，回滚也无法只回滚一半
CLI 模块的 shim 必须转发 main否则 python -m core.report_quality 会静默空跑
包的 __init__.py 保持空import 时加载重模块会引入循环依赖
shim 不删，最后一轮单独删删 shim 是破坏性变更，必须独立 PR + 全量回归

CLI 模块的 shim 模板

# core/report_quality.py（兼容层）
from core.report.quality import *        # noqa: F401,F403
from core.report.quality import main

if __name__ == "__main__":
    raise SystemExit(main())

06PR 7+：模型收敛

每个收敛独立 PR，带兼容层，不做“一次删干净”。

收敛做法删除条件
claim 四合一 ClaimCard 为唯一内存模型；cells_claims 只做“格子 → ClaimCard”编译器；claims.py / claims_v4.py 标 deprecated 旧报告逐份重编译通过 + golden corpus 通过
cells 三读数 cells_unified.observations() 唯一读数；v1/v2/v3 入口从 CLI 移除，保留只读适配器 runlog 统计三个月无调用
prose 五合一 prose_contract（spec + style）+ prose_render（candidates + gen）；critic 归 r04 F10 / F12 不回归
card 六合一 cards/pipeline.py = plan + issue + probe + bundle；task_frame 并入 card_plan 拆卡链路端到端通过
版本词汇 代码不写 v10–v14，只保留 schema 版本 dsh.*/vN “唯一入口”≤1 处
兼容期规则：旧 JSON 读器至少保留一版；新写盘只产新 schema；check_convergence 违规数只许下降。违反任意一条，不许删旧模块。

07验收总表

每个 PR 合并前逐项打勾，缺一项不合。

自动门禁

  • pytest tests ≥ 673，全绿
  • ci_report_checks ALL PASS
  • check_role_tests 20/20
  • check_gate_lock PASS 且变更可见
  • scan_business_terms --check 0/0/0
  • gen_agent_packs --check 无漂移
  • check_project_boundary PASS
  • check_doc_consistency PASS

人工证伪

  • 隔离门禁：故意违规必须 FAIL
  • 收敛门禁：删一个被监视文件必须报错
  • 新增 check_* 必须在 GATES.md 出现
  • shim 删除前跑过一次全量回归
  • 旧报告能重新编译（抽一份样本）
  • “唯一入口”声明数量未增加

08如果只做最小修复

三件事，不动任何 .py 结构，风险接近零。

#动作产出
1写术语表与入口说明docs/GLOSSARY.md + docs/ENTRYPOINTS.md
2修隔离门禁的 glob + 加证伪单测唯一会假绿的门禁被堵上

09风险与回滚

风险触发回滚 / 缓解
import 断裂分包移动文件旧路径保留 shim；按包分批提交，单包可单独 revert
门禁假绿glob 没覆盖新目录先做第 2 节；加证伪测试
白名单漂移core_files.json 忘记重生成--write-whitelist 后逐条 review diff
CLI 空跑shim 没转发 main()用 5.3 的模板；CI 保留 python -m 步骤
产物不兼容批次三换 schema旧读器保留一版；新写盘只产新 schema
文档再次漂移入口文档改版GLOSSARY 为术语唯一出处；check_doc_consistency 进 CI
