# 交卡规范（酒水赛道调研 · 2026-11-19）

> 你是蛙蛙呱呱专家团的一名角色。你只交 `cards/<角色>/claims.json`，报告由 R01 统一出具。
> 本文件是硬约束：不过规的卡会被 `report collect` 拒收，整份报告出不来。

## 0. 总任务与边界

- 总任务：中国酒水赛道全景研究（白酒为主，含啤酒、葡萄酒、低度酒），判断这个赛道现在值不值得进、从哪一段切入。
- 时点：2026 年 11 月。优先 2025 全年 / 2026 上半年数据；2024 及更早只用于趋势对照。
- 纯赛道研究，不预设主体（不假设某家公司、某个区域经销商）。
- 只用公开可核来源。**引文必须是从你实际打开的页面里逐字复制的**，不许改写、不许拼贴、不许凭记忆写 URL。
- 查不到就写进 `missing`，不要编。D 级来源（只有摘要、打不开全文）只能当线索，不能支撑结论。

## 1. 文件结构（严格照此 JSON）

```json
{
  "role": "r05",
  "meta": {"title": "…", "doc_type": "调研报告", "profile": "research", "intent": "…"},
  "numbers": [{"id": "N1", "name": "指标名（含口径）", "value": 354.9, "unit": "万千升", "period": "2025", "source_file": "S1"}],
  "derived": [{"id": "D1", "formula": "N1/N2*100", "value": 12.1, "unit": "%", "note": "…"}],
  "sources": [{"file": "S1", "title": "…", "org": "…", "url": "https://…", "grade": "A", "quote": "原文逐字"}],
  "conflicts": [{"name": "指标名", "reason": "两个口径差在哪"}],
  "sections": [{
    "title": "结论（必须含数字）",
    "question": "这一节回答谁的什么问题",
    "refs": ["N1","N2","D1"],
    "reading_style": "list",
    "reading": [
      {"strong": "观察　", "text": "…数字…", "refs": ["N1"]},
      {"strong": "机理　", "text": "…判别方法…", "refs": ["D1"]}
    ],
    "falsifier": "若…超过 X，本节作废",
    "boundary": "这条结论不能外推到…",
    "chart": { }
  }],
  "boundaries": ["本卡覆盖…，不覆盖…"],
  "missing": ["没查到…"]
}
```

- 每张卡 **2 节**（最多 3 节）；每节 `reading` 至少 2 条，建议 4—6 条，按「观察 / 对照 / 机理 / 落点」分工。
- `refs` 是本节全部引用 id 的并集；每条 `reading` 的 `refs` 只放该条用到的 id。
- `strong` 用这四个标签之一：`观察　` `对照　` `机理　` `落点　`（含全角空格）。
- 数字 id 用 `N1…`，派生量用 `D1…`，来源用 `S1…`，跨卡会由系统加角色前缀，不用自己加。

## 2. 数字规则（最容易卡住，逐条照做）

审核程序会逐个检查**正文里出现的每个数字**能不能由该条 `refs` 解释。允许的只有五种：

1. 等于某个被引用数字的值（含 ×1 / ×100 / ×1000 单位换算）；
2. 等于两个被引用数字的**和或差**；
3. 是 `derived` 里的派生量，且该条 `refs` 引用了这个 `D` id；
4. 是 1990—2100 的年份（如 2025）；
5. 是标题/图标题里的数字（只查「有没有数字」，不查可解释性）。

**推论（照做就不会错）**：
- 正文里每写一个百分比、单价、倍数、差额，都要么来自 `derived`（写公式），要么是来源原文直接给出的一个 `numbers` 条目。**不要心算百分比直接写**。
- 派生量必须能被公式精确算出：容差 `max(0.05, |声明值|×0.5%)`，`value` 写你实际算出的结果（保留 1—2 位小数）。
- 量纲换算写进公式，例如「亿元 → 万元」用 `N1*10000`。
- `name` 必须带口径，例如「白酒产量（规上企业）」「飞天茅台一批价（53度500ml）」。**同一指标全卡统一用同一个 name**，否则冲突检查抓不到。
- 同一个 `name` + 同一个 `period` 出现两个不同值 → 必须在 `conflicts` 里写 `{name, reason}` 说明口径差；不写就被拦。

## 3. 来源分级

| 级 | 什么算 |
|---|---|
| S | 法规/标准/部委文件原文（消费税、广告法、酒类流通管理办法等） |
| A | 国家统计局、海关总署、上市公司年报/公告、交易所披露、政府公报 |
| B | 中国酒业协会、券商研报、行业协会报告（未被媒体转述） |
| C | 媒体报道、行业媒体转述第三方数据 |
| D | 只有摘要/付费墙/打不开全文——只作线索，不作结论 |

每条 `quote` 30—200 字，必须是原文连续片段。同一来源被多条数字复用就只写一个 `S`。

## 4. 图表（可选，最多 1 张/卡）

有 3 个以上可比点才画；否则用 `table` 或干脆不画。图必须给全：

```json
"chart": {
  "type": "hbar",
  "title": "结论式标题（含数字）",
  "unit_meta": "亿元",
  "source": "S1/S2",
  "refs": ["N1","N2","N3"],
  "baseline": {"label": "2024 年", "value": 100},
  "annotate": [{"at": "贵州茅台", "text": "占 34.2%"}],
  "bars": [{"label": "贵州茅台", "value": 1709.0}]
}
```

- 图型白名单：`hbar` `vbar` `line` `waterfall` `pareto` `stacked_bar` `pct_stacked` `donut` `pie`。
- 数据点字段按图型：柱/条 `bars`，折线 `series:[{name,points:[{x,value}]}]`，瀑布 `steps`，帕累托 `items`。
- 点数限制：`hbar/vbar` 3—12，`line/area` 4—24，`waterfall` 3—10，`pareto` 3—15，`pie/donut` 3—6。
- 所有数据点的 `value` 也必须能被 `refs` 解释（同上规则）。
- 缺 `baseline`、缺 `annotate`、标题不带数字，都会被判「报告级图不合格」。

## 5. 标题与文风

- 标题即结论，必须含数字。反例：「白酒行业分析」；正例：「产量 354.9 万千升、九连降：缩量已成定局」。
- 禁用词（出现即整份报告不合格）：需要关注、有待进一步分析、值得注意、综合来看、可能存在问题、有待观察、进一步优化、一定程度上。
- 每节必须有 `falsifier`（带可观测阈值）和 `boundary`（不能外推到哪）。
- 每张卡 `boundaries` 至少 2 条，写清「本卡覆盖什么、没覆盖什么、影响哪条结论」。
