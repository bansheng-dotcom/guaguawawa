# 报告出具能力升级：去壳 · 叙事 · 减冗余

## Context（为什么做这件事）

用户诉求：20 个智能体的分析能力、48 型图表能力都已到位，但「出报告」时完全看不到能力体现，
产出「没办法看」。用户明确要求：**不是修某一份报告，而是升级智能体团队的「报告出具能力」本身**，
让团队能稳定产出高标准、能读的报告。

已定位瓶颈在**渲染/成稿层**（分析已深、图表已好）：

1. **Markdown 快读版最难看**：`core/report_bridge.py::write_markdown()` 把每个 `reading` 条目渲染成
   `- **判断　**…`、`- **机理　**…`，即每个句子前带可见的加粗标签（判断/口径差/机理/落点/证伪/本节边界），
   读起来像带标签的清单，不是报告。
2. **HTML 有可见脚手架框**：每节渲染「本节问题」「为什么做」「证据边界」「本章结论」四个框，把叙事切碎。
3. **冗余复述**：封面 standfirst + 「结论先行」summary + 每节「本章结论」+ 末节口径，同一结论多次出现。

用户已确认方案：**去壳 + 叙事拼接 + 减冗余**，且 **HTML 与 Markdown 一起改**。

## 目标

- 移除所有可见的段标、序号角标、重复前缀、脚手架框。
- 把「观察→对照→机理→落点→证伪」论证链渲染成**连贯叙事段落**。
- 底层校验（数字可复算、来源可回溯、证伪可观测、专业标准门禁）通过隐藏属性保留，不受影响。
- 三道门禁 + 深度门禁 + 全部回归测试保持绿色。

## 核心约束（不能破）

- `scripts/check_professional_standard.py` 的 `_sections()` 会从 `data-label="…"` 提取标签，
  `check_v10()` 的 V3/V8/V9 依赖「多个独立 label」。**因此 `data-label` 必须逐条保留**，只能改可见性，不能合并/删除。
- `core/report_quality.py::_sections()` 用 `<li>` 提取 items（fallback 是按句号切分）。改成 `<p>` 后需确认 fallback 够用。
- `scripts/check_report_flow.py` F5 依赖文本里的「边界」字样 → 保留 notes 里的「证据边界」即可。
- `scripts/check_report_flow.py` F3 依赖 `<section id="summary">` 且带数字 → 保留「结论先行」summary 段。

## 改造方案

### 1. Markdown（core/report_bridge.py::write_markdown）

- 去掉所有 `**strong**` 加粗前缀（intro / reading / notes）。
- `reading`：
  - `reading_style == "prose"`：把条目按句号拼接成一个正文段落（无 bullet、无标签）。
  - `reading_style == "list"`（默认枚举类）：渲染为 `- text`（保留 bullet，去掉加粗标签）。
- 去掉 `> {question}` 块引用（问题属脚手架，正文标题已是结论）。
- `notes`：去掉 `**label**`，条目作普通段落。

### 2. HTML（core/report_renderer.py::render + CSS）

- `reading` 渲染（现 1634–1643 行）：
  - 新增 `reading_style` 支持，默认 `"prose"`。
  - `prose`：`<div class="reading prose"><p>` 内用 `<span data-label="{strong}">{text}</span>` 逐条拼接成一段，
    中间以 `。` 连接；`data-label` 逐条保留（门禁靠它）。
  - `list`：`<div class="reading"><ul><li data-label="{strong}">{text}</li></ul>`（无可见编号/标签）。
- 去掉脚手架框：
  - 「本节问题」`<p class="q"><b>本节问题</b>…` → 去掉加粗标签与框，`question` 弱化为导语或直接不渲染。
  - 「为什么做」`<p class="why">` → 去掉。
  - 「本章结论」`<div class="chapter-conclusion">` → 去掉（节标题已是结论）。
  - 「证据边界」`<div class="boundary"><b>证据边界</b>…` → 弱化为小字备注（保留「边界」字样以满足 F5）。
- CSS 同步：删除/弱化 `.q`、`.why`、`.chapter-conclusion`、`.reading ol/li` 的可见标签样式，
  新增 `.reading.prose p`、`.reading li` 的正文字体行距。

### 3. 叙事拼接标记（reading_style 的「来源」）

- 业务章节（`claims.to_section` 及 `frames*.py` 产出的论证链章节）**默认走 prose**，无需改动。
- 明确标记为 `"reading_style": "list"` 的枚举类章节（这几处是真正需要独立成条目的）：
  - `core/report_flow.py::build_contract`：`结论与证据`、`动作与停止条件`、`口径与分数`。
  - `core/report_flow.py::build_sections_contract`：追加的 `口径与分数`（`记录层` 是表格，无 reading）。
  - `core/report_compose.py::_actions_section`、`_gap_section`。
- `build_sections_contract` 的白名单 `("charts", "intro", "blocks", "why", "refs")` 增加 `"reading_style"`，让标记透传。

### 4. 减冗余

- 去掉「本章结论」框（节标题已承载结论）。
- `build_sections_contract` 的「口径与分数」末尾不再把 `draft["boundaries"]` 逐条复述
  （这些边界已在 notes「证据边界」中呈现，见 464–465 行的 `{"strong": "边界", …}` 追加逻辑移除）。

## 文件改动清单

| 文件 | 改动 |
|---|---|
| `core/report_bridge.py` | `write_markdown()` 去标签 + 叙事拼接 + 去 question 块引用 |
| `core/report_renderer.py` | `render()` 的 reading/question/why/boundary/conclusion 渲染 + `CSS` 变量 |
| `core/report_flow.py` | `build_contract` / `build_sections_contract` 标 `reading_style="list"` + 白名单加 `reading_style` + 去 boundary 复述 |
| `core/report_compose.py` | `_actions_section` / `_gap_section` 标 `reading_style="list"` |
| `core/report_quality.py` | `_sections()` 兼容 `<p>`（fallback 已按句切分，必要时补 `<p>` 提取） |
| `tests/*` | 仅同步断言了 `<li>`/`data-label`/「本节问题」/「本章结论」/MD 加粗前缀的用例 |

不动的：`core/claims.py`（label 词汇是反模板多样性的来源，保留）、`frames*.py`（默认 prose）。

## 分阶段实施与验收

1. **先 Markdown**：改 `write_markdown`。
   - 验收：`python -m pytest tests/test_report_flow.py tests/test_report_sections.py tests/test_report_flow_opt.py -q`，并目检生成 `.md` 无 `**判断**` 前缀。
2. **再 HTML**：改 `render()` + CSS + reading_style 透传。
   - 验收：生成报告后依次跑
     `python scripts/check_report_flow.py --dir <out>`、
     `python -m core.report_quality <out>/report.html`、
     `python scripts/check_report_layout.py <out>/report.html`、
     `python scripts/check_professional_standard.py <out>/report.html`。
3. **全量回归**：
   - `python guagua.py check`
   - `python scripts/ci_report_checks.py`
   - `python -m pytest tests -q`

## 风险与回退

1. **最高风险**：误删/合并 `data-label`，导致 v10 门禁 V3/V8/V9 或 M3 `_chain` FAIL。
   → 铁律：`data-label` 逐条保留，只改可见性；改动后立即跑 `check_professional_standard.py`。
2. `report_quality._sections()` 的 `<li>` 提取在 prose 下变空，`item_counts`/`uniform` 上报值会变（不影响硬门禁），
   必要时补 `<p>` 提取保持口径。
3. F5 若连带 notes 的「证据边界」也删了会 FAIL → 保留 notes「证据边界」，只弱化样式。
4. F3 与 `summary` 强绑定 → 保留「结论先行」summary 段，只弱化样式，不删除。
5. 回退：本改动集中在渲染层与少量标记，`git` 可整段 revert；不改 `claims.py`/`frames*.py` 的分析逻辑，分析结果不受影响。
