07升级方案 v2

顺序修正：先建“接线真相”，再删幽灵，再谈分包与合并。

  1. P0 · 接线真相表（不改代码）

    自动生成：功能 → 生产入口 → 模块 → 非测试 import → 文档声明。规则：从 guagua.py、r*/agent.py、scripts/*.py 出发做可达性；python -m core.X 也算入口；只有测试引用标 UNWIRED；文档提及但文件不存在标 DOC_DEAD；环境变量只在死代码里被读标 ENV_DEAD。

  2. P1 · 修第二类假绿（半天）

    check_dead_code 改成“只有非文档、非测试的代码引用才算 LIVE/SCRIPT”；纯文档提及必须进显式 allowlist 并写理由。新增 check_doc_code_links：文档里的 core/X.py、python -m core.X 必须存在。保留上一版的 isolation glob 修复。

  3. P2 · 断舍离 A / B（约 1,300 行）

    先删零影响孤儿，再处理 coverage / analysis_lab / gate_chain 并同步文档。验收：UNWIRED ≤ 5（allowlist 内）、DOC_DEAD = 0。

  4. P3 · 世代台账 + 弃用协议

    每个关注点一行 CURRENT / LEGACY / REMOVAL_CONDITION；新增层 PR 必须写“替代谁、何时删、删前保留什么读路径”；UNWIRED、DOC_DEAD、唯一入口 三个计数只许下降（棘轮）。

  5. P4 · 再谈物理分包

    上一版的 PR 2–6 放到这里。否则只是把 1,800 行死代码搬进 8 个更整齐的包。注意：仓库已有一次“只做逻辑分组、不动文件”的失败尝试（8ce7af0），零 import 使用——分包必须落到 import 规范，不能只写文档。

  6. P5 · 最后才是模型收敛

    先决定 ClaimCard 是“接回”还是“归档”，再做 claim / cells / prose / card 四合一；否则会把孤儿合并进主模型，等于给死代码续命。
