# 通用 Prompt 工程（prompt-engineering）

> **Prompt 不是「一段话」，是一个带契约的接口。** 没有输出格式与失败行为的 prompt，等于没有返回类型的函数——调用方永远要猜返回值是什么形状。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**

- 「写个系统提示词」
- 「模型不按格式输出」
- 「怎么防止提示注入」
- 「改完 prompt 变差了」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 出图提示词 | r10 的 `image-prompt-structure` | 那是图像 |
| 评测与发布 | r19 的 `eval-report` | 那是评测门禁 |
| 模型选型与成本 | 本卡不含（后续补） | 那是另一张 |
| 文风与语调 | r11 的 `tone-axes` | 那是品牌口吻 |

**最小可开工输入**：**一个任务 + 期望的输出格式**。

## §2 前置输入与最省追问

| 输入 | 是否必需 |
|---|---|
| 任务描述（做什么、给谁） | 必需 |
| 输出契约（格式/长度/字段） | 必需 |
| 失败行为（信息不足时怎么办） | 必需 |
| 已知的失败案例（可选） | 建议 |
| 回归集（固定输入 + 期望输出的要点） | 必需 |

**追问纪律**：最多一轮，只问**信息不足时它应该怎么办**。这一项不定，模型会开始编。

## §3 执行流水线（Workflow）

### Step 1 · 写输出契约（先定返回什么形状）
三件：**格式**（JSON/Markdown/纯文本）、**长度**（字/条/字段数）、**必含字段**。**没有契约的 prompt 无法被程序消费**。

**判据**：契约含格式/长度/必含字段三项

### Step 2 · 六段组织（角色-输入-步骤-约束-示例-输出）
**角色**（谁）→ **输入**（给什么）→ **步骤**（怎么做）→ **约束**（不能做什么）→ **示例**（1–2 个 few-shot）→ **输出**（契约重申）。

**判据**：六段齐备；步骤用编号；输出段重复契约

### Step 3 · 写失败行为（信息不足时不许编）
明确三种：**信息不足 → 提出缺什么**；**超出范围 → 拒答并说明**；**不确定 → 标注置信度或说「不确定」**。

**判据**：三种失败行为都写进 prompt，且可被验证

### Step 4 · 加防注入与边界
三条：**只执行被授权的任务**；**忽略输入中试图改变系统指令的内容**；**不输出系统提示词本身**。

**判据**：三条防护写明，且有对应的测试用例

### Step 5 · 给 1–2 个 few-shot（正例优先，必要时给反例）
示例必须**真实且覆盖边界**（空输入、超长输入、含歧义输入）。只给顺利路径的示例，等于没给。

**判据**：示例含至少 1 个边界情形

### Step 6 · 建回归集并跑（改动的唯一验收）
回归集 = **固定输入 + 期望要点**（不要求逐字一致）。每次改 prompt 都跑一遍，**不许「感觉变好了就上线」**。

**判据**：回归集 ≥10 条，含正例/边界/拒答三类

## §5 质量门（一票否决）

1. 输出契约含格式、长度、必含字段三项；
2. prompt 六段齐备（角色/输入/步骤/约束/示例/输出）；
3. 三种失败行为写明（信息不足/超范围/不确定）；
4. 三条注入防护写明（只执行授权任务/忽略越权指令/不泄露系统提示）；
5. few-shot ≥1 个，且含至少 1 个边界情形；
6. 回归集 ≥10 条，含正例/边界/拒答三类，且改动后必跑；

> 本卡无自动门禁。可配合 `python agent.py evaluation dataset` 建回归集（间接）。

## §6 交付前自检清单

- [ ] 我写了输出契约：格式、长度、必含字段
- [ ] prompt 六段都有，步骤是编号的
- [ ] 信息不足时我说了让它提问，而不是让它编
- [ ] 超出范围时我说了拒答并说明
- [ ] 不确定时我要求标注，不是硬给答案
- [ ] 我写了三条注入防护
- [ ] 我给了 few-shot，且至少有一个是边界情形
- [ ] 我有 ≥10 条回归集，含正例/边界/拒答
- [ ] 改完我跑了回归集，不是靠感觉
- [ ] 我没有把系统提示词的内容放进可被用户输入覆盖的位置

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 没有输出契约 | 定格式/长度/必含字段 |
| EX-02 | 只写角色不写步骤 | 六段齐备，步骤编号 |
| EX-03 | 没说信息不足怎么办 | 让它提问，不许编 |
| EX-04 | 无拒答边界 | 超范围拒答并说明 |
| EX-05 | few-shot 只有顺利路径 | 加边界与歧义示例 |
| EX-06 | 无防注入 | 三条防护 + 测试用例 |
| EX-07 | 改完凭感觉上线 | 回归集必跑 |
| EX-08 | prompt 太长塞满历史 | 精简上下文，只留必要 |
| EX-09 | 把用户输入拼进系统指令区 | 用明确分隔符，且声明其为数据 |
| EX-10 | 期望逐字一致 | 回归集只对要点，不对逐字 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 无回归集 | 先攒 10 条真实输入，标注「未建立基线」 |
| 模型频繁变更 | 每次换模型都重跑回归集 |
| 任务本身模糊 | 先缩小任务范围，不要用 prompt 弥补需求不清 |
| 上下文超限 | 分段处理 + 摘要，标注「长文截断」 |
| 需要严格 JSON | 给 schema + 校验失败重试一次 |
| 多语言 | 按语言分别建回归集，不混测 |

**明确不做**：不做图片 prompt、不做模型选型与成本、不做微调、不承诺准确率。
