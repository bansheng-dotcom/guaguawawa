# 客服话术与 SLA（customer-support-sla）

> **客户不会因为问题生气，会因为「不知道接下来会怎样」生气。** 所以好的回复不是道歉更诚恳，是**明确说出：发生了什么、我们要做什么、什么时候有结果**。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**

- 「这个投诉怎么回」
- 「客服多久必须回」
- 「怎么分级」
- 「客户要求赔偿怎么办」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 退款与订单状态 | r14 的 `order-lifecycle` | 那是交易校验 |
| 健康分与续约 | r13 的 `qbr-health` / `renewal-expansion` | 那是经营 |
| 文案语调 | r11 的 `tone-axes` | 那是品牌口吻 |
| 故障复盘 | r20 的 `incident-response` | 那是内部 |

**最小可开工输入**：**一类具体问题 + 当前响应时长**。

## §2 前置输入与最省追问

| 输入 | 是否必需 |
|---|---|
| 问题类型清单（按频率） | 必需 |
| 影响面（单客户 / 多客户 / 全站） | 必需 |
| 当前响应与解决时长 | 必需 |
| 可给的补偿空间（谁批、上限） | 必需 |
| 升级路径与决策人 | 必需 |

**追问纪律**：最多一轮，只问**补偿空间谁批、上限多少**。没有授权上限的客服会乱承诺。

## §3 执行流水线（Workflow）

### Step 1 · 四级分级（按影响 × 紧急）
**P0 全站不可用**（≤15 分钟响应）／**P1 多客户受阻**（≤1 小时）／**P2 单客户受阻**（≤4 小时）／**P3 咨询**（≤1 个工作日）。

**判据**：四级各有响应与解决时限，且写明计时起点

### Step 2 · 写「承认-解释-动作-时间」四段话术
**承认**（说清发生了什么，不推诿）→ **解释**（为什么，一句）→ **动作**（我们在做什么）→ **时间**（什么时候有结果）。四段缺一即不合格。

**判据**：每类问题的话术四段齐备，且时间点具体

### Step 3 · 禁词与表达纪律
禁用：**「系统繁忙」「操作失败」**（零信息）、**「敬请谅解」**（空道歉）、**「应该」「大概」**（不确定要说不确定，不要含糊）。

**判据**：禁词零出现；不确定处明确说「不确定，X 前给结论」

### Step 4 · 补偿与承诺边界
补偿必须有**授权上限**与**审批人**；承诺必须是**当前能交付的**。**不许**为平息投诉承诺未上线功能或超权限金额。

**判据**：补偿有上限与审批人；承诺项均在当前能力内

### Step 5 · 升级与交接（什么时候往上抬）
三条升级触发：**P0/P1**、**客户明确要求上级**、**超过时限 50%**。升级时必须带：客户 id、问题摘要、已做动作、客户诉求。

**判据**：升级触发写死；交接信息四项齐备

### Step 6 · 度量与回看（时限履约率）
两个数：**首响达标率**、**解决达标率**；辅以**一次解决率**与**重开率**。按 P 级分别统计。

**判据**：四项指标按 P 级分别统计并回看

## §5 质量门（一票否决）

1. 四级分级明确，每级有响应与解决时限，且写明计时起点；
2. 每类问题话术含四段：承认 / 解释 / 动作 / 时间；
3. 禁词零出现（系统繁忙、操作失败、敬请谅解、应该、大概）；
4. 补偿有授权上限与审批人；承诺项不超出当前能力；
5. 三条升级触发写死，交接带四项信息（客户/摘要/已做/诉求）；
6. 按 P 级统计首响达标率与解决达标率；

> 本卡无自动门禁。可配合 `python harness.py edit --input <话术.json>` 做禁词扫描（间接）。

## §6 交付前自检清单

- [ ] 我分了四级，每级有时限，并写明从什么时候开始计时
- [ ] 每类问题我的话术都有承认/解释/动作/时间四段
- [ ] 我没有用「系统繁忙」「操作失败」「敬请谅解」
- [ ] 不确定的地方我明说了不确定，并给了给结论的时间
- [ ] 补偿我写了上限和谁批
- [ ] 我没有承诺未上线的功能
- [ ] 升级触发和时间节点我写死了
- [ ] 交接时我带了客户/摘要/已做/诉求四项
- [ ] 我按 P 级统计了首响与解决达标率

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 只写「尽快回复」 | 每级写具体时限与计时起点 |
| EX-02 | 话术只道歉不解释 | 四段：承认/解释/动作/时间 |
| EX-03 | 用「系统繁忙」 | 说清发生了什么 + 数据怎样 + 下一步 |
| EX-04 | 用「敬请谅解」 | 给具体补偿或明确说明不能给 |
| EX-05 | 不确定却说「应该」 | 明说不确定 + 给结论时间 |
| EX-06 | 客服自行承诺补偿 | 补偿有上限与审批人 |
| EX-07 | 承诺未上线功能 | 只承诺当前能力内 |
| EX-08 | 升级不带上下文 | 带客户/摘要/已做/诉求 |
| EX-09 | 不度量 | 按 P 级统计四项指标 |
| EX-10 | 所有问题同一时限 | 按影响分级 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 无 7×24 人力 | P0/P1 走值班，P2/P3 顺延并明确告知 |
| 无工单系统 | 用邮件标签 + 每日清单，标注「非系统化」 |
| 补偿无授权 | 只道歉与给方案，不承诺金额 |
| 多语言客户 | 按目标语言出话术，标注「未做本地化润色」 |
| 涉及法律纠纷 | 立即升级创始人 + r03，客服不表态 |
| 问题无法解决 | 明确说做不到 + 给替代方案 + 给退出路径 |

**明确不做**：不做退款与订单校验、不做健康分、不承诺超权限补偿、不处理法律纠纷。
