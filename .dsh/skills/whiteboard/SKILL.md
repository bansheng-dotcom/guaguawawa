## §3 执行流水线（Workflow）

### Step 1 · 定图类型
**架构图**（谁调谁）/ **流程图**（先做什么）/ **关系图**（谁连谁）——三选一，不混。

**判据**：混画是最常见的失败

### Step 2 · 定命名与类型
每个节点写清 **类型 + 名称**（如「服务：订单」「存储：订单库」），类型用固定词表。

**判据**：类型不明的图无法评审

### Step 3 · 标连线方向与协议
每条线标 **方向 + 协议/介质**（HTTP/gRPC/MQ/人工）。

**判据**：无方向的线等于没说

### Step 4 · 显式分层
分层（接入/服务/存储/外部）必须画出来；**不许一条线直接穿过三层而不经过中间节点**。

**判据**：穿层线通常意味着漏了节点

### Step 5 · 出可编辑格式
导出 `.svg` 或白板源文件，**不要交截图**。

**判据**：截图不可改＝不可接手

## §5 质量门（一票否决）

1. 图类型单一（架构/流程/关系）；
2. 每个节点有类型与名称；
3. 每条连线有方向与协议；
4. 分层显式且无穿层线；
5. 交付可编辑格式而非截图；

> 本卡无自动门禁。**任一项不过即不得交付**，且必须在交付物里写明「逐项人工核对」。
> 可用 `python agent.py designsys list` 做间接校验（若该命令存在）。

## §6 交付前自检清单

- [ ] 这张图只表达一件事（架构/流程/关系之一）
- [ ] 每个节点都写了类型
- [ ] 每条线都有方向，并标了协议
- [ ] 分层画出来了，没有一条线穿三层
- [ ] 交的是可编辑文件，不是截图
- [ ] 外部系统与团队边界标了
- [ ] 命名全图统一（不混中英、不混大小写风格）

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 架构与流程混一张图 | 拆成两张 |
| EX-02 | 节点只写名字不写类型 | 类型用固定词表 |
| EX-03 | 连线无方向 | 每条线标方向与协议 |
| EX-04 | 一条线穿三层 | 补中间节点或改画法 |
| EX-05 | 交截图 | 交可编辑 SVG/源文件 |
| EX-06 | 命名风格混乱 | 全图统一命名规范 |
| EX-07 | 外部系统不标 | 边界必须显式 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 没有白板工具 | 用文本 DSL 画（Mermaid），仍可编辑 |
| 系统细节不全 | 未知节点标「待确认」，不留空 |
| 读者是管理层 | 减少协议细节，突出边界与数据流 |
| 图过大（>40 节点） | 拆成总览图 + 分域图 |
| 需要打印 | 导出 PDF 并检查字号 |

**明确不做**：不做实现、不做性能评估、不用截图交付。
