# 客户健康与 QBR（QBR Health）

> 一句话定位：**这个技能存在的意义，是防止"客户已经在流失，但报表上全是绿的"**。
> 客户流失几乎不会突然发生，它是**健康分慢慢下滑、风险归因没人写、临期续约没人管**三件事累积的结果。
> 健康分最大的价值不是打分，而是**把"感觉这个客户有点冷"变成"42 分，红色，使用腰斩，30 天后到期"**。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这个客户还能续吗」「帮我排一下续约风险」
- 「算一下客户健康分」「哪些客户要重点关注」
- 「这个客户该不该升级处理」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 给客户报价 / 谈折扣 | `r14` 交易 + 创始人 | 本技能只判风险，不签合同不定价 |
| 处理退款与履约 | `r14` 交易 | 那不是客户成功问题 |
| 改产品解决客户诉求 | `r07` 产品 | 本技能产出 VOC，不负责实现 |
| 保证续约率 | 拒绝 | 只给**可验证的风险判定与行动建议**，不承诺结果 |

**最小可开工输入**：**客户名 + 四维打分（使用/支持/VOC/互动）+ 距续约天数**。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| `name` | 必需 | 无名字无法归属，`health.name` BLOCKER |
| `usage` / `support` / `voc` / `engagement`（0–100） | 必需 | 缺任一则该维度记 0 并标注"缺失按 0 计"，不得猜一个中间值 |
| `renewal_in_days` | 必需 | 缺则无法判断临期，必须问 |
| `risk_reason`（at_risk 时） | 必需 | 红色客户无归因即 BLOCKER |
| 环比数据（上期分） | 建议 | 缺则不做 delta 红标，标注"无上期对比" |

**追问纪律**：最多一轮，只问**四维打分与续约日期**。其余按上期数据或行业默认补全并标注。

## §3 执行流水线（Workflow）

### Step 1 · 四维打分（原始分，不带感情）
| 维度 | 权重 | 看什么 | 不要看什么 |
|---|---|---|---|
| `usage` | **30%** | 活跃用户数、核心功能使用频次、数据增量 | 登录次数（刷出来的活跃没意义） |
| `support` | **25%** | 工单量、解决时长、升级次数、CSAT | 单条好评 |
| `voc` | **25%** | NPS、访谈原话、需求兑现情况 | 销售转述 |
| `engagement` | **20%** | 会面频次、响应速度、决策人参与度 | 邮件数量 |

**计算**：`健康分 = usage×0.30 + support×0.25 + voc×0.25 + engagement×0.20`

> 打分必须有依据（截图/工单号/访谈记录）。**没有依据的分等于 0，不是 60。**

- **产出**：四维分 + 加权分
- **过关条件**：四维齐全且各有依据

### Step 2 · 落三色区间
| 区间 | 阈值 | 含义 | 动作 |
|---|---|---|---|
| 🟢 healthy | **≥ 75** | 健康 | 常规维护，找增购机会 |
| 🟡 watch | **50–74** | 观察 | 本月内主动触达一次 |
| 🔴 at_risk | **< 50** | 风险 | **必须写归因 + 定升级动作** |

- **产出**：`band`（healthy / watch / at_risk）
- **过关条件**：`band` 与分数一致（`risk.band_consistency` 会校验）

### Step 3 · 环比与临期标记（真正的预警信号）
两件事必须单独看，不能只看绝对分：

| 信号 | 判据 | 为什么重要 |
|---|---|---|
| **delta 下滑** | 环比降 ≥ 10 分 | 高分下滑比低分稳定更危险 |
| **临期续约** | `renewal_in_days ≤ 90` | 低于 90 天才处理，已经来不及 |
| 临期 + 低分 | ≤90 天 且 分 < 70 | **最高优先级**，本季必须处理 |

> 一个 82 分但环比掉 15 分、30 天后到期的客户，比一个稳定 60 分的客户更危险。

- **产出**：delta 标记 + 临期标记 + 优先级
- **过关条件**：临期客户全部被标出

### Step 4 · 风险归因（红线客户必写）
`at_risk` 客户必须写 `risk_reason`，且要**指到具体事实**：

| 反例 | 正例 |
|---|---|
| 「客户不太满意」 | 「使用腰斩（DAU 120→48）+ 工单激增 3 倍，主因是 9 月 API 变更未通知」 |

- **产出**：`risk_reason`
- **过关条件**：`health.risk_reason` 通过（红线客户非空且具体）

### Step 5 · 升级路径与证据（该不该惊动上级）
```bash
python harness.py escalation --input <升级.json>
```
判定三件事：**是否该升级**、**升级到哪一级**、**证据够不够**。
证据不足的升级＝打扰上级，会消耗真正的紧急通道。

- **产出**：`knowledge.route` + `knowledge.evidence`
- **过关条件**：路由合法且证据链完整

### Step 6 · 跑门禁
```bash
python harness.py health     --input <客户健康分.json>
python harness.py risk       --input <风险清单.json>
python harness.py escalation --input <升级.json>
```

- **过关条件**：三道全部退出码 0

## §5 质量门（一票否决，不过不给交付）

1. **客户名非空**（`health.name`）；
2. **四维分齐全且各有依据**；
3. **`band` 与加权分一致**（`risk.band_consistency`）；
4. **`at_risk` 客户必须有具体 `risk_reason`**（`health.risk_reason`）；
5. **临期（≤90 天）客户全部标记**，临期且 <70 分列为最高优先级；
6. **升级路由合法**（`knowledge.route`）；
7. **升级证据链完整**（`knowledge.evidence`）。

> 验收命令：`python harness.py health --input <健康分.json>` 及其它两道
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许把红色改成黄色让门禁变绿**。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 四维简单平均当健康分 | 必须按 **30/25/25/20** 加权；usage 权重最高 |
| EX-02 | 用登录次数当 `usage` | 用核心功能使用与数据增量；刷出来的活跃不算 |
| EX-03 | 红线客户归因写"客户不太满意" | 必须指到事实：指标变化 + 事件 + 主因 |
| EX-04 | 只看绝对分，不看环比 | 08 分掉到 65 比稳定 60 更危险，delta 必看 |
| EX-05 | 只看分数，不看续约日期 | 90 天内到期是独立预警信号，必须单列 |
| EX-06 | 没依据就打个 60 分 | 没依据按 0 分并标注"缺失"，不许猜中间值 |
| EX-07 | 为了不让老板紧张把红色调成黄 | 分数只降不升；要改善就改事实，不改分数 |
| EX-08 | 所有客户一起报给上级 | 只有证据充分的高优先级才升级；滥升级会钝化通道 |
| EX-09 | 升级只写"需要支持" | 写清要什么：调查 / 修复 / 决策 / 批准（investigate/fix/decide/approve） |
| EX-10 | QBR 只讲成绩不提风险 | QBR 必须含风险页与续约动作，否则是汇报不是经营 |
| EX-11 | 承诺"照这个做就能续约" | 只给风险判定与行动建议，不承诺续约率 |
| EX-12 | VOC 用销售转述 | 用客户原话 + 出处；转述会失真且不可追溯 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `harness.py` 跑不了 | 按 §6 人工逐项核对，标注「未跑门禁」；**不得标记"可续约"** |
| 某维度无数据 | 该维记 0 并标注"缺失按 0 计"，在交付物说明影响（会拉低总分，属如实反映） |
| 无上期分 | 不做 delta 标记，标注"无上期对比，本次为首期基线" |
| 客户要求特殊处理 | 记录为 VOC，不因客户压力改分数；风险判定保持独立 |
| 续约日期不明 | 必须问；仍不明则标注"续约日期未知"，优先级无法判定 |
| 涉及合同条款变更 | 转 `r14` + `r03`，本技能不出法律与财务意见 |
| 客户已明确要退 | 转升级流程 + `r01`；不做挽留话术（归 `r13` 客服域） |

**明确不做**
- 不报价、不谈折扣、不签合同（归 `r14` + 创始人）；
- 不做产品承诺与路线图承诺（归 `r07`）；
- 不保证续约率与 NPS 提升；
- 不修改客户提供的原始诉求（VOC 原样记录）。
