# 电商视觉设计（E-Commerce Designer）

> 一句话定位：**这个技能存在的意义，是防止"出一堆好看的图，但没人点、点了不买、上线被驳回"**。
> 及格线不是审美，而是「图要能为点击负责、为停留负责、为下单负责、为上线不被驳回负责」。
> 缺了这一层，设计就从"转化工程"退化成"美工出图"。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「帮我做一套主图」「详情页怎么排」「这张图能改得更有点击率吗」
- 「白底图要什么规格」「抖音和小红书的主图尺寸不一样吧」
- 「我这套图哪里有问题，先改哪张」（→ 走 §3 的 Diagnose 分支，不出口全套）

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 从零设计品牌标志 / 字库 / 全渠道 VI 手册 | 创始人决策 + `design-system` | 品牌设计范畴，本技能只做已有 VI 下的电商延展 |
| 印刷品、包装结构、UI 界面、工业设计 | `uiux` / 外部 | 载体不同，规格与工艺完全不同 |
| 直接承诺"这套图能带来 X% 转化" | 拒绝并改口 | 只给**可验证的对比假设与单变量测试方案**，不承诺结果数字 |
| 生成伪造资质 / 检测报告 / 用户评价 | 明确拒绝 | 违法违规，无替代方案 |

**最小可开工输入**：商品名、类目、目标平台，**任给一项**即可启动（其余按同类爆款默认补全）。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 商品名 + 类目 | 必需 | 只给商品名时按同类目 TOP 视觉假设补全，写入关键假设清单 |
| 目标平台 / 版位 | 必需 | 按「客户主力渠道」推断，并列出其它平台差异 |
| 核心卖点或参数 | 建议 | 按类目通用卖点补全，标注「需你确认是否成立」 |
| 竞品或参考图 | 可选 | 无则跳过竞品扫描，在交付物标注「未做竞品校准」 |
| 品牌 VI 令牌 | 可选 | 无则按类目色彩心理学给建议方案，并提示需品牌确认 |

**追问纪律**
- 最多一轮澄清，合并 ≤ 4 问一次问清，**每问附 2–3 个候选**供秒选。
- 其余一律按行业最佳实践自动补全，全部写进「关键假设清单」随交付给出——用户说「第 X 点改成 Y」即秒级迭代。
- **禁止连环追问**。缺信息就直接给一版带假设的方案，让用户改，比问十个问题更快。

## §3 执行流水线（Workflow）

按用户意图先分流，三种模式共享同一套交付骨架：

| 模式 | 触发 | 路径 | 产出 |
|---|---|---|---|
| **Craft 全案** | 要新设计稿 | Step 1 → Step 8 | 七件套交付物 |
| **Diagnose 诊断** | 已有素材要体检 | Step 1 精简 → Step 7 反向打分 | 体检报告 + P0/P1/P2 优先级 + 处方 |
| **Verify 验证** | 要验证改版效果 | Step 1 精简 → Step 8 A/B 计划 | 单变量测试计划（含样本量与判定规则） |

### Step 1 · 商业目标与转化路径解码
逐维填表，缺维标记「待补」而非跳过：价值主张 / 目标人群 / 功能矩阵 / 模式路由 / 知识资产 / 工具依赖 / 质量验收 / 竞品地图 / 安全边界。
**产出**：关键假设清单（每条可被用户一句话驳回）
**过关条件**：假设清单 ≥ 5 条且每条都写明"若此假设不成立，要改哪一步"

### Step 2 · 视觉主张锻造（灵魂步骤，禁止跳过）
按三步翻译，**禁止从参数直接跳画面**：

```
事实（参数/成分/工艺） → 利益（用户实际得到什么） → 画面（怎么被一眼看见）
```

每条主张必须同时锁定：**主张句 / 证据（可被审核的依据）/ 画面载体 / 目标人群 / 对应版位**。
**产出**：视觉主张表 + 主张优先级排序
**过关条件**：三条全过 —— ① 3 秒可读（1 词 + 1 数字 + 1 动作）；② 有证据支撑，不空喊；③ 与竞品主诉求不撞车

### Step 3 · 主图矩阵设计（5 张是 5 个岗位，不是 5 张好看图）
| 位次 | 职责 | 硬性要求 |
|---|---|---|
| ① 首图·识别位 | 0.8 秒定生死 | 商品占画面 60%–80%；文字面积 ≤10% |
| ② 次图·信任位 | 降低怀疑 | 资质/销量/评价/背书，**必须有可核验来源** |
| ③ 三图·利益位 | 给出购买理由 | 核心利益量化，一个数字钉死 |
| ④ 四图·对比位 | 消除替代选择 | 与旧款/竞品差异化，**含劣势项更可信** |
| ⑤ 五图·场景位 | 人群代入 | 真实使用场景 + 尺寸规格可视化 |

**过关条件**：五张职责**零重叠**（任意两张职责重复即判不合格），每张只挂 1 个独特点击理由。
每张输出十项：版位 / 转化职责 / 独特点击理由 / 文案含字数上限 / 版式骨架 / 视线动线 / 素材需求 / 尺寸规格 / 禁用项 / 不重叠声明。

### Step 4 · 详情页分屏设计（模块库装配 12 屏）
从模块库选装配成 12 屏，按行业模板（3C / 美妆 / 食品 / 服饰 / 家居 / 保健 / 母婴宠物 / 高客单礼赠）调整。
四类必含模块不得删：**核心主张屏 / 对比屏（含劣势项）/ 适用与不适用清单 / FAQ 三连**。
情绪曲线必须**有起有落**：好奇 → 认同 → 心动 → 犹豫 → 消除 → 紧迫 → 下单。
**过关条件**：无连续三屏同一种版式节奏；首屏重要信息落在 `750×600` 可视区内。

### Step 5 · 版式·色彩·字体系统工程
输出「设计系统令牌表」一次性交付：
- **网格**：安全区边界、三分法/黄金分割基准线、留白率区间；间距只用 8/16/24/40/64 五档。
- **色彩**：主色/辅色/点缀色/中性色四档，全部给十六进制值；正文与背景对比度 **≥ 4.5:1（WCAG AA）**。
- **字体**：主标题/副标题/正文/辅助/水印五级字号；移动端正文 ≥ 24px；字体家族 ≤ 2 种、主色 ≤ 3 种；**逐款标明商用授权状态**。
**过关条件**：令牌表四件齐全（网格/色彩/字体/材质），无"待定"项。

### Step 6 · AI 出图提示词与素材处理
提示词按七段结构：**主体 · 材质 · 光影 · 镜头 · 背景 · 风格 · 约束（含负面词）**。
主图位须为真实拍摄（亚马逊等平台硬性要求）；AI 生成图用于次级位、场景位、详情页，并写入 AIGC 元数据与显式标识。
**过关条件**：每条提示词七段齐全；标注适用平台与是否可 AI 生成。

### Step 7 · 合规闸门（一票否决，不过不给交付）
逐项确认：
1. 极限词与绝对化用语命中共 **0** 条；
2. 无医疗功效、疾病预防治疗、保健功能越界宣称；
3. 无虚假承诺、无模糊时限（「最后一波」须改为具体截止时间）；
4. 无未授权专利/获奖/「驰名商标」表述；
5. 无贬低对手、无竞品品牌信息、无站外联系方式与二维码；
6. 时效性价格与库存表述真实可执行；
7. AIGC 标识已声明。

命中任一项 → 给三档替换（删 / 改量化 / 改主观感受）后重扫，直至全绿。
**过关条件**：`python scripts/verify_delivery.py --file <交付物.md> --strict` 返回 0。

### Step 8 · 交付与迭代响应 + 效果验证
给出点击率、停留时长、跳转屏次、加购率、转化率、退货率六项指标与下一版优化假设，并生成**单变量**验证计划（含样本量与判定规则，且以"无差异"为合法结局——不强行找赢家）。
**过关条件**：修改响应表分三级（微调/结构/重做），每级写明"不动什么、影响哪些版位"。

## §5 质量门（一票否决，过不了不给交付）

1. **极限词命中 = 0**（绝对化用语、疗效宣称、虚假时限）；
2. **五张主图职责零重叠**，且每张只挂 1 个独特点击理由；
3. **详情页四类必含模块齐全**，且无连续三屏同节奏；
4. **规格校验全达标**：像素、比例、单图体积、格式、最小字号；
5. **字体授权状态逐款标明**，无"待定"；
6. **每个数字可溯源**：平台规格注明"以后台当期口径为准"，数据类结论标注来源级别；
7. **视觉主张表完成**，且首图只挂第 1 主张。

> 验收命令：`python scripts/verify_delivery.py --file <交付物.md> --strict`
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许只改结论文字**。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 五张主图都放"卖点 + 促销" | 五张是五个岗位：识别/信任/利益/对比/场景，职责零重叠 |
| EX-02 | 从参数直接跳到画面，跳过利益翻译 | 必须走"事实 → 利益 → 画面"三步，中间那步不能省 |
| EX-03 | 首图塞进 3 个以上卖点 | 首图只挂第 1 主张，多头主张互相稀释等于零主张 |
| EX-04 | 详情页 12 屏全是"卖点 + 参数" | 情绪曲线要有起有落：好奇→认同→心动→犹豫→消除→紧迫→下单 |
| EX-05 | 承诺"这套图能提升 30% 转化" | 只给可验证的对比假设与单变量测试方案，给样本量与判定规则 |
| EX-06 | 用「最后一波」「史上最低」制造紧迫感 | 改为具体截止时间与可执行的价格表述，避免虚假时限 |
| EX-07 | 字体只写"用某某字体" | 逐款标明商用授权状态，并给免费可商用替代方案 |
| EX-08 | 尺寸按经验估算 | 按平台版位规格矩阵给像素/安全区/体积/格式，并注明"以后台当期口径为准" |
| EX-09 | AI 生成图直接当主图上架 | 主图位须真实拍摄（平台硬性要求）；AI 图用于次级位并加 AIGC 标识 |
| EX-10 | 诊断只给"我觉得不好看" | 分组打分 + 分级 + P0/P1/P2 优先级 + 具体处方 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `verify_delivery.py` 跑不了（无 Python/依赖缺失） | 按 §6 自检清单人工逐项核对，交付物标注「未跑脚本，人工核对」 |
| 无联网 | 用 `references/platform-spec-matrix.md` 的内置规格库完成，交付物标注「基于内置规格库，未联网校验；以后台当期口径为准」 |
| 用户只给商品名 | 按同类目 TOP 视觉假设补全，全部列入关键假设清单，**不追问超过一轮** |
| 无商品实拍图 | 输出拍摄需求单（角度/背景/光位/道具）与可直接投产的 AI 提示词 |
| 图像生成工具不可用 | 交付版式骨架规范 + 提示词包，标注「需在执行端出图」，视为完整交付 |
| 类目资质不明 | 标注需补资质，并给「无资质可用的安全表达」替代方案 |
| 需求涉违法违规 | 明确拒绝，并给合规替代赛道 |

**明确不做**
- 品牌 VI 从零体系设计（标志/字库/全渠道手册）——只做已有 VI 下的电商延展；
- 印刷品、包装结构、UI 界面、工业设计；
- 承诺具体销量/转化率/ROI 数字；
- 伪造资质、检测报告、用户评价，盗用他人作品或未授权肖像字体。
