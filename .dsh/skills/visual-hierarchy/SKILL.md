# 视觉层级与构图（Visual Hierarchy）

> 一句话定位：**「好看」不是一个感受，是十三条可查的原则。**
> 绝大多数「不好看」都能归到其中三条：层级不清、对齐不齐、留白不足。
> 这张卡给的是**判据 + 阈值 + BAD/GOOD 对照**，不是审美偏好。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这个页面好看吗」「怎么改才好看」
- 「哪里别扭」「改稿该先改哪」
- 「主图/详情页/落地页怎么排」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 写实现代码 | `r09` 的 `web-app-development` | 本卡只出判据与改法 |
| 设计令牌与色板 | `r10` 的 `design-system` | 那是体系，不是构图 |
| 电商转化与卖点排序 | `r10` 的 `ecommerce-designer` | 那是转化导向 |
| 可访问性合规清单 | `r09` 的 `frontend-design` | 那是工程规范 |

**最小可开工输入**：**一张现有界面/物料**（有图才能判）。

## §3 执行流水线（Workflow）

### Step 1 · 先定「一眼要看到什么」（层级的前提）
写一句话：用户进来第一眼该看到什么。
**判据**：这句话说不出来 → 后面十三条都无从判起，先回需求。

### Step 2 · 数层级（≤3 级）
把页面元素按视觉权重分三级：**主信息 / 支撑信息 / 辅助信息**。

| 档 | 判据 |
|---|---|
| 一级 | 删掉它用户会做错事 |
| 二级 | 需要时才看的依据 |
| 三级 | 极少用（设置/帮助/版权） |

**阈值**：一屏 **≤3 个层级**；超过 3 级说明没分主次。

### Step 3 · 量比例（层级之间要差够）
**阈值**：相邻层级**字号差 ≥1.5×**；主次按钮**权重必须不同**（填充 vs 描边）。

实测反例：五行文字全 14px 常规同色 → 层级差 **1.0×**，不及格。
改成 12px 灰标签 / 14px 正文 / 24px bold 合计 → 24/14 = **1.7×**，达标。

### Step 4 · 查对齐（视觉轴）
**阈值**：同组元素**共用一条对齐轴**；金额类**右对齐**；表单单列左对齐。
**判据**：把它们的中点连起来，能连成直线吗？

### Step 5 · 验留白（只用刻度）
**阈值**：间距只用 **4/8/12/16/24/32/48**；同组 4–8、异组 16–24、区块 32–48。

### Step 6 · 查对比度（可测量）
**阈值**：正文 **≥4.5:1**；大字（≥18px 粗 / ≥24px）≥3:1；非文本 ≥3:1。
**铁律**：颜色不能是唯一信息载体。

### Step 7 · 灰化反看（判结构还是判装饰）
把稿子转灰度：**层级还成立吗？** 不成立说明你依赖的是颜色，不是结构。

## §5 质量门（一票否决）

1. 一屏 **≤3 个层级**，且层级之间字号差 **≥1.5×**；
2. **主操作与取消/危险操作视觉权重不同**；
3. 同组元素**共用对齐轴**；金额右对齐；
4. 间距**全部落在 4/8/12/16/24/32/48**；
5. 正文对比度 **≥4.5:1**（实测，不靠眼）；
6. **375 宽度无横向滚动**，触控目标 **≥44×44**。

> 本卡无自动门禁。任一项不过即不得交付；可配合 `python agent.py uiux screen --input <规格.json>`
> 做结构性校验（间接，判不了美观）。

## §6 交付前自检清单

- [ ] 我能一句话说出这一屏要让人做什么
- [ ] 层级不超过 3 级，且相邻层级字号差 ≥1.5×
- [ ] 主按钮和取消按钮一眼能分开（不是同填充色）
- [ ] 同组元素的中点在一条直线上
- [ ] 所有间距都在刻度里（没有 13px、18px）
- [ ] 对比度用工具量过，正文 ≥4.5:1
- [ ] 转灰度后层级仍然成立
- [ ] 375 宽度下实际拉过，没有横向滚动
- [ ] 触控热区 ≥44×44（不是图标视觉尺寸）
- [ ] 改稿清单按 P0→P1→P2 排序，不是列一堆

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 所有元素视觉权重差不多 | 分三层，字号差 ≥1.5× |
| EX-02 | 一屏七八个字号 | ≤5 级字号，≤3 个层级 |
| EX-03 | 主操作与取消同样式 | 填充 vs 描边，必须能一眼分开 |
| EX-04 | 元素各对齐各的 | 同组共用一条轴 |
| EX-05 | 金额左对齐或居中 | 金额右对齐成竖线 |
| EX-06 | 间距随手 13/18px | 只用七档刻度 |
| EX-07 | 对比度靠肉眼 | 用工具量 ≥4.5:1 |
| EX-08 | 只用颜色区分类别 | 加形状/文字/图标 |
| EX-09 | 强调靠加边框加阴影 | 靠字号与字重，不靠装饰 |
| EX-10 | 留白不足，塞满 | 区块 32–48，敢留空 |
| EX-11 | 只在一种宽度看 | 375 / 768 / 1280 三档都过 |
| EX-12 | 一上来就调颜色 | 先修 P0（层级/对齐/对比），颜色最后 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 只有文字描述没有图 | 只给原则 + 规格，标注「未看图，不可判定」 |
| 品牌令牌缺失 | 只判结构（层级/对齐/留白），不判配色合法性 |
| 无设计工具 | 用文字描述版式骨架 + 刻度表，仍可交付 |
| 全站改版 | 先修一屏作样板，再复制判据 |
| 印刷物料 | 另加出血/分辨率/CMYK 检查，本卡不含 |
| 客户要求「照竞品抄」 | 借鉴结构与层级，不复制视觉资产 |

**明确不做**
- 不写代码、不做令牌体系、不做转化策略、不做印刷工艺。
