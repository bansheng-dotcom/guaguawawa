# 证据账本（Evidence Ledger）

> 一句话定位：**这个技能存在的意义，是防止"一份读起来很有道理、但一句都查不到出处的研究报告"**。
> 研究报告最贵的失败不是结论错，而是**无法复核**：
> 数字没有来源、来源没有日期、结论比证据强、缺材料却当成"已经研究过了"。
> 一旦报告被引用去做决策，这些缺口就变成了不可逆的风险。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这个市场有多大」「帮我做个行业研究」「竞品现在什么情况」
- 「这条结论有依据吗」「数据哪来的」
- 「这份研究报告能信吗」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 直接拍板做不做 | `r01` CEO | 本技能只给有据的结论，不替人拍板 |
| 算指标、做显著性 | `r06` 分析师 | 本技能不做统计推断 |
| 写营销文案 | `r11` 内容 | 本技能输出研究结论，不输出传播稿 |
| 保证"这个赛道能赚钱" | 拒绝 | 只给证据与情景，**不给收益承诺** |

**最小可开工输入**：**一个具体问题**（不是"帮我研究一下 AI 行业"）。问题越窄，证据越能立住。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 研究问题（一句话，可证伪） | 必需 | 太宽泛必须收窄，否则不出报告 |
| 决策用途（给谁、用来定什么） | 必需 | 缺则无法定证据强度要求，必须问 |
| 时间范围 / 地域 | 建议 | 缺则按最近 12 个月 + 中国大陆，并标注 |
| 已有材料 | 可选 | 缺则从空白开始，标注"无既有材料" |
| 可接受的来源级别 | 建议 | 缺则默认 S/A/B 可用，C 只作线索 |

**追问纪律**：最多一轮，只问**问题是什么、给谁用**。其余按默认执行并标注。

## §3 执行流水线（Workflow）

### Step 1 · 收窄问题（宽问题必然得到空结论）
一个可研究的问题必须含三要素：**对象 + 维度 + 判定口径**。
- ✅「2026 年中国大陆 SaaS 客服工具的 CR3 是多少」
- ❌「帮我研究下客服 SaaS」

**判据**：写不出"什么数字能回答它"，说明问题还没收窄。

- **产出**：研究问题 + 判定口径
- **过关条件**：问题能被一个具体数字或事实回答

### Step 2 · 研究计划（先定步骤与查询规格，再动手）
```bash
python harness.py plan --input <研究计划.json>
```
计划必须含三件：
| 字段 | 要求 |
|---|---|
| `question` | 与 Step 1 一致，不再扩张 |
| `analytical_step` | 分析步骤（≥2 步，每步产出什么） |
| `query_spec` | 查询规格：查什么词、查哪里、要拿到什么字段 |

**为什么先写查询规格**：不写就会"边搜边想"，最后搜到的和要回答的对不上。
门禁实测：缺 `analytical_step` / `question` / `query_spec` 任一即 FAIL。

- **产出**：研究计划
- **过关条件**：`harness.py plan` 退出码 0

### Step 3 · 材料清单与缺口（缺什么就写明缺什么）
```bash
python harness.py materials --input <材料清单.json>
```
材料必须分两类登记：**已获取**（含路径/链接/日期）与**缺口**（含缺什么、影响哪条结论）。

**铁律**：缺口必须写进报告。把缺口藏起来，报告的可信度就是零——
因为读者无法判断哪部分没研究。

- **产出**：材料清单 + 缺口清单
- **过关条件**：`harness.py materials` 退出码 0

### Step 4 · 来源分级（S/A/B/C 四档）
| 级别 | 定义 | 可用性 |
|---|---|---|
| **S** | 一手数据：官方财报、平台后台、监管文件 | 可直接支撑结论 |
| **A** | 权威二手：行业协会、头部研究机构、上市招股书 | 可支撑，需标日期 |
| **B** | 媒体/自媒体转述，能追到原始出处 | 仅作辅助，须追源 |
| **C** | 无法追溯出处的说法、AI 生成、匿名爆料 | **只作线索，不作论据** |

每条证据必须记：`level / source / date / locator`（页码/章节/链接锚点）。

- **产出**：证据账本条目
- **过关条件**：每条都有级别、来源、日期、定位

### Step 5 · 结论与证据强度对齐（最容易越界的一步）
| 证据情况 | 允许的结论措辞 |
|---|---|
| 2+ 个 S/A 级来源交叉一致 | "可以确认…" |
| 单一 S/A 来源 | "据 X（日期），…" |
| 仅 B 级 | "有报道称…，尚未证实" |
| 仅 C 级 | "有说法认为…，**待核实**" |
| 无来源 | **不许出结论**，只列"待查问题" |

> **禁止句式**：「业内普遍认为」「大家都知道」「显而易见」——
> 这三句是"我没有来源"的三种说法。

- **产出**：结论 + 每条的支撑证据编号 + 强度标注
- **过关条件**：措辞与证据级别匹配，无越界表述

### Step 6 · 跑结论门禁（反幻觉 + 措辞 + 证据链）
```bash
python harness.py verdict --input <研究结论.json>
```
校验三件：`findings` 结构、**证据链是否非空**、措辞是否有猜测性表述。
门禁实测：`verdict_bad` 同时命中 `harness:findings` 与 `harness:evidence_chain`。

- **产出**：`verdict` 结论
- **过关条件**：`harness.py verdict` 退出码 0

## §5 质量门（一票否决，不过不给交付）

1. **研究问题可被具体事实回答**，不是宽泛方向；
2. **研究计划三件齐全**（question / analytical_step / query_spec）；
3. **材料清单含缺口**，且缺口影响已写明；
4. **每条结论都有证据编号支撑**，无孤证结论；
5. **每条证据有 level / source / date / locator**，缺一定位即不合格；
6. **结论措辞与证据级别匹配**（无 C 级来源支撑确定性表述）；
7. **无空泛表述**（"业内普遍认为""显而易见"）。

> 验收命令：`python harness.py verdict --input <结论.json>` + `materials` + `plan`
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许删掉缺口让报告看起来完整**。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 问题太大（"研究下 AI 行业"） | 收窄到"对象 + 维度 + 口径"，能被一个数字回答 |
| EX-02 | 边搜边想，不做查询规格 | 先写 `query_spec`：查什么词、查哪里、要什么字段 |
| EX-03 | 把缺口藏起来，报告显得完整 | 缺口必须写，并说明影响哪条结论 |
| EX-04 | 结论只有一句"市场很大" | 每个判断挂证据编号，孤证不算结论 |
| EX-05 | 来源只写"网上查到" | 四要素：级别 / 来源 / 日期 / 定位（页码或锚点） |
| EX-06 | 用 C 级来源支撑确定性表述 | C 级只作线索，措辞必须"待核实" |
| EX-07 | 写"业内普遍认为" | 这就是"没有来源"的另一种说法，删掉或补证据 |
| EX-08 | 引用二手报道不追原始出处 | B 级必须追到原始来源，追不到降为 C |
| EX-09 | 数据不写采集日期 | 市场数据半年就过期；无日期的数据不可引用 |
| EX-10 | 把 AI 生成的"研究结果"当来源 | AI 输出不是来源；只能当线索并标"待核实" |
| EX-11 | 用绝对化表述（最大/唯一/第一） | 改量化：给具体数字 + 统计口径 + 来源 |
| EX-12 | 报告只写支持的证据 | 必须列反证与不一致来源，否则是论证不是研究 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 无联网 / 检索不可用 | 用内置资源库，标注「基于内置库，未联网校验」；结论强度整体下调一级 |
| 只有 C 级来源 | 只出「待查问题清单」，不出结论；或出结论但全篇标"待核实" |
| 用户要求"给个大概数字" | 给区间 + 来源级别 + 不确定性说明，**不给单点伪精确数字** |
| 材料缺口影响核心结论 | 明确写"该结论无法验证"，不降级为"可能"糊过去 |
| 问题涉及未公开/内幕信息 | 拒绝；只使用公开可检索来源 |
| 用户要求删掉不利证据 | 拒绝；可调整表述强度，不可删证据 |
| 时间紧、无法充分检索 | 缩小问题范围，产出"有限结论 + 明确缺口"，不硬撑全面研究 |

**明确不做**
- 不替创始人拍板（归 `r01`）；
- 不做投资建议与收益预测；
- 不做统计分析（归 `r06`）；
- 不产出传播稿（归 `r11`）。
