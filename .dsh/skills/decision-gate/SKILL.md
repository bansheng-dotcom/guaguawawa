# 硬决策闸门（Decision Gate）

> 一句话定位：**这个技能存在的意义，是防止"一个本该慢慢想清楚的不可逆决定，被当成日常小事顺手做掉了"**。
> 决策的质量不取决于结论多漂亮，而取决于三件事：**可逆性判对了吗、撤回成本算清了吗、谁签字了**。
> 缺了这一层，"经营判断"就退化成"拍脑袋 + 事后解释"。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这个降价要不要做」「要不要冻结定价 90 天」「该不该砍掉这条产品线」
- 「这个决定风险多大」「万一错了能不能退回来」
- 「帮我出个决策卡 / 记一下这个决定」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 要一份方案 / PRD / 分析报告 | `r07` / `r06` / 对应专业角色 | 本技能只管"拍不拍、怎么退"，不生产方案 |
| 要我判断这个交付物合不合格 | `r04` 评审官 | 质量结论（pass/fail）只有 R04 出 |
| 要我签合同 / 打款 / 裁员 | 创始人 | 本技能只做**升级判定**，不做签署 |
| 问"怎么提升利润" | `r07` → `r06` | 那是经营优化链路，本技能只在"要改定价/关停"这类不可逆节点介入 |

**最小可开工输入**：一句话说明**要决定什么**（如"自助版定价 99→149"）即可启动。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 决策主题 | 必需 | 无法推断，必须问 |
| 至少 2 个选项（含"什么都不做"） | 必需 | 按同类决策默认补全，写入关键假设清单 |
| 可逆性直觉判断 | 建议 | 由 §3 Step 1 判定，不问用户 |
| 撤回成本口径 | 建议 | 按 §3 Step 1 的时间口径估算，标注"估算值" |
| 成功/杀死标准 | 建议 | 给建议值，标"待你确认"——**但不许空缺** |

**追问纪律**
- 最多一轮，合并 ≤ 4 问一次问清，每问附 2–3 个候选。
- **"什么都不做"永远是选项之一**，用户没想到也要补上（门禁强制：选项 ≥ 2）。
- 其余按同类决策默认补全，全部写进「关键假设清单」随决策卡给出。

## §3 执行流水线（Workflow）

### Step 1 · 可逆性分级 + 决策前五问
先判三级可逆性，再逐条答五问。**五问不答完，门禁直接 BLOCKER。**

| 级别 | 判据 | 处置 |
|---|---|---|
| 可逆（双向门） | 撤回 < 2 周且成本 < 1 人月 | 快速决策，可直接执行 |
| 难逆（部分可逆） | 撤回 1–6 个月，或影响已签合约 | 加人工审批点 + 反方质询 |
| 不可逆（单向门） | 撤回 > 6 个月，或无法撤回 | **禁止自动执行，必须创始人签发** |

**决策前五问**（原样答，不许改写问题）
1. 最弱假设是什么？
2. 证据是否可复现？
3. 谁为这个决定的失败负责？
4. 撤回成本是多少？
5. 是否把可逆决策当成不可逆在拖延（是 = 逃避）？

- **产出**：`{"topic","reversibility","cost_if_wrong","action","before_decide":[...]}`
- **过关条件**：`python harness.py reversibility --input <卡>` 返回 `ok=true`（五问逐条命中）

### Step 2 · 锻造十字段决策卡
逐字段填写，缺一项即 BLOCKER：

```
topic / reversibility / options / recommendation / rationale /
rollback_plan / success_criteria / kill_criteria / owner / deadline
```

硬规则：
- `options` ≥ 2，且**必含"什么都不做"**；
- `success_criteria` 与 `kill_criteria` 必须是 `{metric, threshold, deadline}` 三件套，
  且**必须在决策前写死**——事后补的不算；
- `rollback_plan` 对"难逆/不可逆"是 CRITICAL 级必填，不是建议；
- `deadline` 是决策自身的到期日，不是执行完成日。

- **产出**：`decision_card.json`
- **过关条件**：十字段齐全 + 三件套齐全 + 选项合规（由 Step 4 门禁统一验）

### Step 3 · 预公告测试（立不住 = 没准备好）
用 2–3 句话写一段"如果这个决定明天被公开，我怎么解释"的公告草稿。
写不出来、或写出来自己都觉得站不住 → **回 Step 1 重判，不要往下走**。
这一段同时也是事后复盘时的原始立场记录。

- **产出**：`announcement_draft`
- **过关条件**：能说清"为什么做 / 凭什么现在做 / 错了怎么退"三件事

### Step 4 · 跑门禁（一票否决）
```bash
python harness.py card --input <决策卡.json>
```
15 项检查，分 OK / BLOCKER / CRITICAL。任一 BLOCKER 或 CRITICAL → `ok=false`、退出码 1。

- **过关条件**：退出码 0 且 `grade=PASS`

### Step 5 · 升级判定
```bash
python harness.py escalate --input <决策卡.json>
```
规则：**反转成本 > 6 个月公司时间 → 升级为 cross-eval + 人工**（`escalate.rule`）。

- **产出**：`{"must_escalate","reasons","human_signoff_required"}`
- **过关条件**：`human_signoff_required` 与可逆性等级一致（不可逆却为 false = 违规）

### Step 6 · 落决策日志
把 `topic / 结论 / 依据 / 可逆性 / owner / deadline / 杀死标准` 写入决策日志，并在
下一次同类决策前先查冲突（`DO_NOT_RESURFACE` / 矛盾 / 歧义）。

- **产出**：日志条目
- **过关条件**：条目可被"下次决策"检索到；冲突项已显式标注

## §5 质量门（一票否决，不过不给交付）

1. **五问逐条已答**，不是"已考虑"（BLOCKER）；
2. **十字段齐全**，缺任一即不过（BLOCKER）；
3. **选项 ≥ 2 且含"什么都不做"**（BLOCKER）；
4. **成功/杀死标准是 `{metric, threshold, deadline}`**，且在决策前写死（BLOCKER）；
5. **难逆/不可逆必须有回滚计划**（CRITICAL）；
6. **公告草稿已写**（BLOCKER）；
7. **不可逆决策 `human_signoff_required=true`**，且不得自动执行。

> 验收命令：`python harness.py card --input <决策卡.json>` 与 `python harness.py escalate --input <决策卡.json>`
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许只改结论文字**。

## §6 交付前自检清单

- [ ] 决策主题是一句话能说清的具体决定，不是"关于定价的思考"
- [ ] 可逆性级别有判据支撑（撤回时长 + 成本），不是拍脑袋
- [ ] 五问逐条作答，第 5 问单独检查过"是否在拖延可逆决策"
- [ ] 选项至少 2 个，且"什么都不做"在里面
- [ ] 推荐选项有 `rationale`，且说清"相对其它选项为什么是它"
- [ ] 成功标准与杀死标准都是 `{metric, threshold, deadline}` 三件套
- [ ] 难逆/不可逆决策有具体回滚触发条件（含阈值与时限）
- [ ] 公告草稿能回答"为什么做/凭什么现在/错了怎么退"
- [ ] `owner` 是具体角色而非"团队"，`deadline` 是决策到期日
- [ ] `python harness.py card` 退出码 0
- [ ] `python harness.py escalate` 的 `human_signoff_required` 与可逆性一致
- [ ] 决策日志条目已写入且可被检索

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 只给一个选项，把"什么都不做"漏掉 | 选项 ≥ 2 且必含"什么都不做"，它是所有决策的基准线 |
| EX-02 | 五问写成"已考虑风险"这种概括 | 五问必须逐条原样作答，门禁按问题文本逐条匹配 |
| EX-03 | 先拍板，事后补成功/杀死标准 | 标准必须在决策前写死；事后补的不算，也无法复盘 |
| EX-04 | `rollback_plan` 写"如有问题及时回滚" | 必须给触发阈值 + 时限 + 回滚动作，如"转化率跌 >20% 且持续 7 天 → 回滚 99" |
| EX-05 | 把可逆决策当不可逆反复上会 | 第 5 问专门查这个：拖延也是错误，且成本更高 |
| EX-06 | 不可逆决策 `human_signoff_required=false` 直接执行 | 不可逆 → 必须 founder 签发；`escalate` 门禁会判违规 |
| EX-07 | 公告草稿写成公关话术 | 它是对自己的压力测试：写不立住说明还没想清 |
| EX-08 | `owner` 写"团队"/`deadline` 写"尽快" | 一 owner 一到期日；"共同负责 = 没人负责" |
| EX-09 | 决策卡只存在对话里 | 必须落 `decision_card.json` 并进决策日志，否则无法检索冲突 |
| EX-10 | 结论被推翻就把旧条目删掉 | 保留原条目 + 追加新条目（`DO_NOT_RESURFACE`），决策日志不可覆盖 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `harness.py` 跑不了（无 Python/依赖缺失） | 按 §6 自检清单人工逐项核对，交付物标注「未跑门禁，人工核对」；**不可逆决策在这种情况下不得执行** |
| 用户只给一句话 | 按同类决策默认补全选项与标准，写入关键假设清单，**不追问超过一轮** |
| 用户拒绝回答五问 | 不出决策卡；只在聊天里给"建议"，并明确写"未过门禁，不可据以执行" |
| 决策涉及合同/资金/裁员 | 只出升级判定，明确 `human_signoff_required=true`，不代为执行 |
| 证据不可复现（五问第 2 条为否） | 决策卡可出，但必须标 `evidence_reproducible=false`，且不得判为"可逆快速决策" |
| 同一主题已有历史决策 | 先跑冲突检查（`DO_NOT_RESURFACE` / 矛盾 / 歧义），再出新卡 |

**明确不做**
- 不替专业部门生产方案、不写 PRD、不做数据分析；
- 不签质量结论（`pass/fail` 归 R04）；
- 不签合同、不调动资金、不执行裁员；
- 不因为"老板说要快"就跳过一次门禁——**不可逆动作不接受口头豁免**。
