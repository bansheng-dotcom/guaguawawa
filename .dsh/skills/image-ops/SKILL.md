# 本地图片处理（Image Ops）

> 一句话定位：**这个技能存在的意义，是防止「批量处理完才发现原图被覆盖、透明底变成黑底」**。
> 批量图片处理最贵的失败不是效果不好，而是**不可逆**：
> 原地覆盖原图、RGBA 转 JPG 后透明变黑、缩放奇数边导致模糊、水印压到主体上。
> 这些操作都"成功"了，但素材回不来了。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「批量改成一米宽」「这堆图太小了压一下」
- 「加个水印」「裁成正方形」「白底补边」
- 「这张图什么尺寸什么格式」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 设计稿/主图方案 | 本角色的 `ecommerce-designer` | 那是视觉设计，不是批处理 |
| AI 生图 | `nano-banana` 类工具能力 | 那是生成，不是处理 |
| 印刷色彩管理（CMYK/ICC） | 外部 | 本包只做 RGB 数字端 |
| 视频音频 | 本角色 `media` 域 | 那是另一套工具链 |

**最小可开工输入**：**一张图 + 一句要做什么**（如"压到 200KB 以内"）。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 图片文件路径 | 必需 | 无文件无法处理 |
| 目标操作（resize/crop/compress/pad/watermark） | 必需 | 缺则先 `info` 再问 |
| 目标尺寸/比例/体积 | 操作相关必需 | 缺则给建议值并标注 |
| 输出目录 | 建议 | 缺则默认**不覆盖原图**，写同目录 `_out` |

**追问纪律**：最多一轮，只问**要变成什么样、输出到哪**。

## §3 执行流水线（Workflow）

### Step 1 · 先探测（不做探测就动手＝赌博）
```bash
python agent.py imgops info --input <图片>
```
必须拿到：尺寸、格式、色彩通道（RGB/RGBA）、体积。
**没有 Pillow 时它会如实报缺失**——此时停止，不得伪造"处理完成"。

实测：对一份伪装成 `.png` 的文本文件，`info` 直接失败（exit 1），不会当成图片处理。

- **产出**：图片信息卡
- **过关条件**：`imgops info` 退出码 0

### Step 2 · 操作白名单（只做这六种）
| 操作 | 用途 | 关键参数 |
|---|---|---|
| `resize` | 改尺寸 | 宽/高，**保持比例** |
| `crop` | 裁剪 | 比例或框 |
| `compress` | 压体积 | 质量或目标 KB |
| `pad` | 补边（白底/透明） | 目标比例、填充色 |
| `watermark` | 加水印 | 位置、透明度、缩放 |
| `info` | 只读探测 | —— |

**不在这六种里的需求，先说明做不到**，不要用脚本硬凑。

### Step 3 · 防覆盖（默认不覆盖原图）
**铁律**：输出必须写到新路径，除非用户显式要求覆盖，且覆盖前先备份。
批量处理时最惨的事故是"处理了 200 张，发现参数错了，原图全没了"。

- **产出**：输出路径清单
- **过关条件**：输出路径 ≠ 原路径（或已备份）

### Step 4 · 四条技术校验
| 校验 | 判据 | 为什么 |
|---|---|---|
| 偶数边 | 缩放后宽高取偶 | 视频/H.264 编码要求，奇数边会糊 |
| 透明通道 | RGBA 输出必须 PNG/WEBP | 转 JPG 透明变黑底 |
| 体积上限 | 目标平台上限内 | 超限上传失败或被强压 |
| 比例 | 与目标一致（±1px） | 比例不符会被裁切 |

### Step 5 · 批量与幂等
- 批量前先**跑一张**验证参数，再跑全量；
- 同一批重跑结果应一致（不引入随机水印位置等）；
- 失败要逐张记录，不能一张失败整批中断且无日志。

| # | 交付物 | 载体 | 骨架出处 |
|---|---|---|---|
| 1 | 图片信息卡（逐张） | 终端 JSON | `imgops info` 输出 |

| 3 | 输出路径清单（含是否覆盖） | `.md` | 本文 §3 Step 3 |

- 命名：`imgops_<批次短码>_<YYYYMMDD>/`
- **输出目录必须与原图分离**；混在一起就无法判断哪张被处理过。

## §5 质量门（一票否决，不过不给交付）

1. **处理前跑过 `info`**，拿到尺寸/格式/通道/体积；
2. **操作在六种白名单内**；
3. **不覆盖原图**（或已显式备份）；
4. **缩放后宽高为偶数**；
5. **RGBA 输出用 PNG/WEBP**，不转 JPG；
6. **输出体积在目标上限内**；
7. **批量前先单张验证过参数**。

> 验收命令：`python agent.py imgops info --input <图片>`（探测）+ 对应操作
> 命中任一项不过 → 回 §3 对应 Step，**不允许覆盖原图"省事"**。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 不 `info` 直接处理 | 先探测尺寸/格式/通道/体积 |
| EX-02 | 原地覆盖原图 | 输出到新目录；要覆盖先备份 |
| EX-03 | 缩放后奇数边长 | 宽高取偶，避免编码糊 |
| EX-04 | RGBA 转成 JPG | 透明用 PNG/WEBP，否则黑底 |
| EX-05 | 压完没验体积 | 按目标平台上限复核 |
| EX-06 | 批量直接跑全量 | 先单张验证参数，再全量 |
| EX-07 | 水印压到主体上 | 位置避开主体，透明度适中 |
| EX-08 | 拉伸不保持比例 | 用 crop 或 pad，不硬拉 |
| EX-09 | 失败静默中断 | 逐张记录失败原因 |
| EX-10 | 无 Pillow 却说处理成功 | 如实报"后端缺失"，不伪造 |
| EX-11 | 用白底 pad 处理透明图 | 明确指定填充色与是否保留 alpha |
| EX-12 | 一次改多个参数 | 一次只改一个，便于回滚与对比 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 无 Pillow | 如实报缺失（`imgops` 会探测），**不得伪造执行**；给安装命令 |
| 无 ffmpeg（视频相关） | 转 `media` 域，标注"视频未处理" |
| 图片损坏/格式伪装 | `info` 会失败，直接报错，不猜 |
| 需要 CMYK / ICC | 转专业工具，本包只做 RGB |
| 批量含多种格式 | 按格式分组处理，逐组记录 |
| 目标体积压不到 | 给"降质量 / 缩尺寸 / 换格式"三档方案，让用户选 |
| 用户要求覆盖原图 | 先备份到 `_orig/`，再覆盖 |

**明确不做**
- 不做设计稿与主图方案（归 `ecommerce-designer`）；
- 不做 AI 生图（归生成类工具）；
- 不做印刷色彩管理；
- 不做视频音频（归 `media` 域）。
