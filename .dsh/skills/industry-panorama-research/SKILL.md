# 行业全景研究（Industry Panorama）

> 一句话定位：**这个技能存在的意义，是防止「一句『这个行业很大』就当研究过了」**。
> 行业研究最容易糊弄的三件事：格局只说"竞争激烈"、集中度不给数、市场规模给一个精确到小数点的假数字。
> 这三件事都能做成可校验的结构，所以没理由靠形容词。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这个行业什么情况」「赛道值不值得进」
- 「市场有多大」「集中度怎么样」
- 「行业里都有谁、我们排第几」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 直接拍板做不做 | `r01` CEO | 本技能只给结构化事实与情景 |
| 竞品逐个拆解与打法 | 本角色的 `market-intelligence-radar` | 那是竞品情报 |
| 用户需求与购买行为 | 本角色的 `deep-research-assistant` / `r07` | 那是需求侧研究 |
| 财务测算与投资回报 | `r03` / `r06` | 本技能只做规模与集中度 |

**最小可开工输入**：**一个具体行业 + 一个地域与时间范围**（如"2026 年中国大陆 SaaS 客服工具"）。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 行业名称与边界（含 / 不含什么） | 必需 | 边界不清则数字全不可比，必须问 |
| 地域 | 必需 | 缺则默认中国大陆并标注 |
| 时间范围 | 必需 | 缺则默认最近 12 个月并标注 |
| 口径（营收/出货量/用户数） | 必需 | 缺则给"按营收"默认并标注 |
| 已有数据源 | 建议 | 缺则按公开来源做，标注缺口 |

**追问纪律**：最多一轮，只问**行业边界与口径**。这两个不定，后面全白做。

## §3 执行流水线（Workflow）

### Step 1 · 定义行业边界（先划圈，再数数）
写清三件事：**含什么 / 不含什么 / 与相邻行业的区别**。

| 反例 | 问题 |
|---|---|
| 「AI 行业」 | 边界过宽，任何数字都无意义 |
| 「客服工具」 | 没说含不含呼叫中心、含不含外包 |

**判据**：能列出 3 家"算在内"和 2 家"不算在内"的公司名，边界才算清楚。

### Step 2 · 行业格局地图（分层 + 玩家位置）
```bash
python agent.py industry landscape --input <行业格局.json>
```
必须给出分层（如 基础设施 / 平台 / 应用 / 服务）与每层的主要玩家及位置。
门禁实测：缺分层或玩家结构不合法即 FAIL（`industry_landscape_dirty`）。

- **产出**：分层结构 + 每层玩家
- **过关条件**：`agent.py industry landscape` 退出码 0

### Step 3 · 市场集中度（CR3 / CR5 必须给数与口径）
```bash
python agent.py industry concentration --input <集中度.json>
```
三条硬要求：
1. **必须给 CR3 或 CR5 具体数值**，不能只说"集中"或"分散"；
2. **必须给口径**（按营收 / 按用户数 / 按出货量）——口径不同结论可能相反；
3. **必须给数据年份与来源**。

**读法**：CR3 < 30% 视为分散（有机会）；30–60% 需差异化；> 60% 慎入。

门禁实测：缺集中度数值或口径即 FAIL（`industry_concentration_dirty`）。

- **产出**：CR3/CR5 + 口径 + 年份 + 来源
- **过关条件**：`agent.py industry concentration` 退出码 0

### Step 4 · 市场规模测算（给区间与路径，不给单点）
```bash
python agent.py sizing size --input <规模测算.json>
```
必须含：**计算路径**（自下而上/自上而下）、**关键假设**、**结果区间**。

| 方式 | 做法 | 适合 |
|---|---|---|
| 自上而下 | 大盘 × 渗透率 | 有权威大盘数据时 |
| 自下而上 | 目标客户数 × 客单价 × 付费率 | 有客户侧数据时 |

**铁律**：输出**区间**（如 80–120 亿），不给"约 97.3 亿"这种单点伪精确。
数字精度不能超过输入精度——用百分比估算出来的数，就不该有小数点。

- **产出**：测算路径 + 假设 + 区间
- **过关条件**：`agent.py sizing size` 退出码 0

### Step 5 · 敏感性分析（哪个假设最要命）
```bash
python agent.py sizing sensitivity --input <敏感性.json>
```
对每个关键假设做 ±20%（或合理区间）扰动，看结果变化幅度。
**变化最大的那个假设，就是最该去验证的**。

门禁实测：缺敏感性结构即 FAIL（`sizing_sensitivity_dirty`）。

- **产出**：敏感性表 + "最敏感假设"
- **过关条件**：`agent.py sizing sensitivity` 退出码 0

## §5 质量门（一票否决，不过不给交付）

1. **行业边界可验证**：能列出 3 家在、2 家不在的公司；
2. **格局地图有分层与玩家结构**（`industry landscape`）；
3. **集中度有 CR3/CR5 数值 + 口径 + 年份 + 来源**（`industry concentration`）；
4. **规模测算有路径 + 假设 + 区间**（`sizing size`），无单点伪精确；
5. **敏感性分析覆盖所有关键假设**（`sizing sensitivity`）；
6. **每个数字标来源类型**（检索核实 / 用户提供 / 经验参考值）；
7. **缺口写明**：哪些数据没拿到、影响哪条结论。

> 验收命令：`python agent.py industry landscape|concentration`、`python agent.py sizing size|sensitivity`
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许把区间收窄成单点让结论"更有力"**。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 行业边界不定义就开始数 | 先划圈：含什么/不含什么/邻接谁 |
| EX-02 | 格局只说"竞争激烈" | 给分层 + 每层玩家 + 位置 |
| EX-03 | 集中度只写"很集中" | 给 CR3/CR5 数值 |
| EX-04 | 集中度不给口径 | 营收/用户/出货量口径不同，结论可能相反 |
| EX-05 | 规模给单点"约 97.3 亿" | 给区间；精度不超过输入精度 |
| EX-06 | 测算路径不写 | 写清自上而下还是自下而上，别人才能复核 |
| EX-07 | 假设不列，直接给结果 | 每条假设都要列，且可验证 |
| EX-08 | 不做敏感性分析 | 至少对关键假设做 ±20% 扰动 |
| EX-09 | 用一份来源就下结论 | 至少两个独立来源交叉 |
| EX-10 | 数据缺口藏起来 | 缺口必须写，并说明影响哪条结论 |
| EX-11 | 把"大盘增长"当"我们能增长" | 区分行业增速与自身份额变化 |
| EX-12 | 结论里出现"行业肯定" | 只给事实与情景，判断留给决策者 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `agent.py` 门禁跑不了 | 按 §6 人工核对，标注「未跑门禁」；**不得标记"结论可用"** |
| 无权威大盘数据 | 只用自下而上，标注"无自上而下交叉验证" |
| 集中度数据找不到 | 写"集中度待核实"，并说明该缺口如何影响结论 |
| 行业边界有争议 | 给两个边界版本（窄/宽），分别测算 |
| 只有海外数据 | 明确标注"海外数据，中国大陆未验证"，不直接外推 |
| 用户要求"给个准数" | 给区间 + 关键假设 + 敏感性，说明为什么不能给准数 |
| 涉及未公开信息 | 拒绝；只用公开可检索来源 |

**明确不做**
- 不替创始人拍板（归 `r01`）；
- 不做投资建议与收益预测；
- 不做竞品逐个拆解（归 `market-intelligence-radar`）；
- 不做财务测算（归 `r03` / `r06`）。
