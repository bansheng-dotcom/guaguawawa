# 财务模型审计（Model Audit）

> 一句话定位：**这个技能存在的意义，是防止"报表每一行都算得出结果，但三张表之间对不上"**。
> 财务模型最贵的错误不是算错一个数，而是**勾稽断了却没人发现**：
> 资产不等于负债加权益、现金推算与申报差 500、总账与子账各 50% 匹配、审计证据缺采集人。
> 这些错误不会让公式报错，只会让决策建立在假数字上。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「帮我审一下这个财务模型」「这套报表对不对」
- 「三表勾稽有没有问题」「总账和子账差了 3 笔」
- 「审计证据齐不齐」「这个控制点有证据吗」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 出一份持牌审计意见 | 外部会计师事务所 | 本技能只做内部核验，**不出持牌意见** |
| 把模型改对 | 模型所有者（`r06` / 财务） | **只读**：审计不修改被审对象，改了就无法复核 |
| 判断这笔投资该不该做 | `r01` + `r05` | 那是决策，不是审计 |
| 做税务申报口径 | `r03` 的税务域（`tax` 系列门禁） | 审计与税务是两套口径，别混 |

**最小可开工输入**：**待审对象 + 一份可比对的第二来源**。二者缺一即无法判勾稽，只能给"无法核验"。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 被审模型（三表 / 总账 / 子账 / 控制点清单） | 必需 | 缺则 `BLOCKED`，不做猜测评价 |
| 可比对的第二来源（申报值 / 另一套账 / 原始凭证） | 必需 | 缺则该维度标"无对照，未核验"，不判通过 |
| 期间与口径（会计期、货币、含税与否） | 必需 | 缺则问一次；仍无 → 标注"口径未声明"，结论降级 |
| 审计证据清单（控制点 → 证据 → 采集人/时点） | 证据类审计必需 | 缺则只做勾稽、不做证据完整性 |
| 上期问题日志 | 可选 | 有则逐条确认是否已闭环 |

**追问纪律**：最多一轮，只问三件事——**审什么、跟什么比、什么口径**。其余按会计常识默认并标注。

## §3 执行流水线（Workflow）

### Step 1 · 锁定审计范围与口径（先写死，不许边审边改）
写清：审计对象、期间、货币单位、含税与否、对照来源。
**口径不一致的比对没有意义**——含税对不含税、期末对期中，比出来的差异全是噪声。

- **产出**：审计范围卡（对象/期间/口径/对照来源）
- **过关条件**：四项齐全，且对照来源可指到具体文件

### Step 2 · 三表勾稽（模型审计的第一道关）
三项必须各自成立：

| 勾稽 | 公式 | 常见断点 |
|---|---|---|
| 资产负债表 | 资产 = 负债 + 权益 | 漏记当期损益结转 |
| 现金流量 | 期初现金 + 经营 + 投资 + 筹资 = 期末现金 | 手工调期末数凑平 |
| 利润表 | 收入 − 成本 = 毛利 | 毛利直接填而不计算 |

> 门禁实测口径：`cfo healthcheck` 会分别校验三项，任一不等即 FAIL。
> 例：期初 50000 + 经营 9500 = 59500，但申报期末 60000 → 报"现金勾稽：推算 59500 = 申报 60000"。

- **产出**：三项勾稽结论（各自推算值 vs 申报值）
- **过关条件**：三项全部相等（差额为 0，不是"差异很小"）

### Step 3 · 总账与子账对账（第二道关）
逐笔按 `key` 匹配，四个维度都要对：**金额 / 数量 / 记账时点 / 是否存在**。

| 破差类型 | 含义 |
|---|---|
| GL only | 总账有、子账无（可能漏转） |
| 子账 only | 子账有、总账无（可能未过账） |
| 金额差 | 同 key 金额不等 |
| 数量差 | 同 key 数量不等 |
| 时点差 | 同 key 记账日期不同（跨期风险） |

**门禁口径**：匹配率 ≥ 95% 且破差条数 = 0。实测一个 6 笔的样本匹配率 50%、
破差 3 条（子账多 1 笔、金额差 1、时点差 1）→ 判 FAIL。

- **产出**：匹配率 + 破差清单（按类型分桶）
- **过关条件**：匹配率 ≥ 95% 且破差 = 0

### Step 4 · 证据链完整性（第三道关，审计专属）
每个控制点必须有证据，每条证据必须有**三件套**：

| 字段 | 缺失后果 |
|---|---|
| `artifact`（证据载体） | 无法定位 |
| `collected_at`（采集时点） | 无法判断时效 |
| `collector`（采集人） | **无人负责，证据不可采信** |

> 门禁口径：`audit evidence` 逐条校验字段齐备性并算证据完整率。
> 实测一个 2 控制点样本，因 CM-02 证据缺 `collector` → 完整率 1/2 → FAIL。

- **产出**：证据完整率 + 缺口清单
- **过关条件**：完整率 100%，无缺字段

### Step 5 · 差异归因（数字对不上时必须解释为什么）
材料性差异（超过阈值的）**必须写 driver**，且不能只是复述数字：

| 反例 | 正例 |
|---|---|
| 「marketing 差 1200」 | 「marketing 差 1200，因为 9 月新增两场投放未入预算，见 PO-2026-0912」 |

> 门禁口径：`financial variance` 对触发评论的行校验 driver 是否解释 why。
> 实测：3 行触发评论、1 个账户注解缺口 → FAIL。

- **产出**：差异清单 + 每条的 driver 说明
- **过关条件**：所有超阈差异都有 driver，且 driver 解释了原因

### Step 6 · 输出问题日志（只报不改）
每条问题固定六列：

```
| # | 位置 | 严重度 | 类别 | 问题描述 | 建议动作 |
```

- `位置`：表名 + 单元格/科目/条目 key（必须能定位）
- `严重度`：`BLOCKER`（勾稽断/证据缺失）> `CRITICAL`（破差）> `MAJOR`（无 driver）> `MINOR`（格式）
- `建议动作`：写**该怎么改**，不写"已改"

> **只读红线**：审计过程中不得修改被审模型。改了 = 原始证据消失 = 审计结论不可复核。

- **产出**：问题日志
- **过关条件**：每条问题都有可定位的"位置"

### Step 7 · 跑门禁（注意：必须走包装器）
```bash
# 三表勾稽
python scripts/audit_gate.py cfo healthcheck --input <三表.json>
# 对账
python scripts/audit_gate.py financial recon --input <对账.json>
# 证据链
python scripts/audit_gate.py audit evidence --input <证据.json>
# 其它可用门禁（按需）
python scripts/audit_gate.py cfo unitecon        --input <单位经济.json>
python scripts/audit_gate.py financial variance  --input <差异.json>
python scripts/audit_gate.py audit mockaudit     --input <整改.json>
```

> **必须用 `audit_gate.py`，不要直接跑 `harness.py`**——实测 `harness.py` 在 `ok=false` 时仍 exit 0，
> 无法被 CI 拦截。`agent.py <skill> <action>` 虽已正确传递退出码，但缺少正反例自检与失败摘要。
> 本包的 `audit_gate.py` 两者都补上。详见 §9 已知缺陷。

- **过关条件**：本次涉及的门禁全部退出码 0

## §5 质量门（一票否决，不过不给交付）

1. **审计范围与口径已写死**（对象/期间/货币/含税/对照来源）；
2. **三表勾稽三项全平**（差额为 0，不接受"差异很小"）；
3. **对账匹配率 ≥ 95% 且破差 = 0**；
4. **证据完整率 100%**，每条证据都有 `artifact` / `collected_at` / `collector`；
5. **所有超阈差异都有 driver**，且 driver 解释 why 而不是复述数字；
6. **问题日志每条都有可定位的"位置"**；
7. **全程未修改被审对象**（只读）；
8. **门禁经 `audit_gate.py` 包装后退出码 0**。

> 验收命令：`python scripts/audit_gate.py --self-test`（6 项，含 3 个反例）
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许把差异说成"口径问题"糊过去**。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 差额 500 说"差异很小，可接受" | 勾稽差额必须为 0；不为 0 就是断，必须查到底 |
| EX-02 | 期末现金直接手填凑平 | 期末 = 期初 + 经营 + 投资 + 筹资；不许手调 |
| EX-03 | 毛利直接填，不由收入−成本计算 | 毛利必须可复算；填出来的数不算勾稽 |
| EX-04 | 对账只看金额，不看数量与时点 | 四维都看；时点差会造成跨期错报 |
| EX-05 | 匹配率 96% 就判通过 | **匹配率 ≥95% 且破差 = 0**，两个条件同时成立 |
| EX-06 | 审计证据只有截图，没有采集人 | 三件套缺一不可；缺 `collector` 即不可采信 |
| EX-07 | 差异说明写"marketing 差 1200" | 必须解释 why：原因 + 单据号 + 影响面 |
| EX-08 | 发现问题顺手把模型改对 | 只读红线；改了原始证据就没了，结论不可复核 |
| EX-09 | 问题日志只写"数据有问题" | 六列齐全，位置精确到科目/单元格/key |
| EX-10 | 直接跑 `harness.py` 看它 exit 0 就以为过了 | r03 原生 harness 恒 exit 0；必须用 `audit_gate.py` 包装 |
| EX-11 | 用含税数对不含税数，差异当问题报 | 先统一口径再比对；口径不一致的比对是噪声 |
| EX-12 | 出"审计意见已出，可以放心" | 本技能不出持牌意见；结论只能是"内部核验结果" |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `harness.py` / `audit_gate.py` 跑不了 | 按 §6 人工逐项核对，标注「未跑门禁，人工核对」；**不得出"勾稽通过"结论** |
| 没有第二来源可对照 | 该维度标"无对照，未核验"，不得判通过；只做单表内部自洽检查 |
| 口径不明（含税/跨期/合并范围） | 先问一次；仍不明则整份结论降级为"待口径确认" |
| 被审对象不可只读（系统无只读权限） | 停止审计，要求只读副本；**在有写权限的环境里做审计不可信** |
| 历史遗留差异已有结论 | 不重复审；标注"沿用上期结论，见审计底稿 #N" |
| 模型用的是外部黑箱（第三方算的） | 只审输入与输出，中间过程标"不可验" |
| 用户要求"顺手把问题改掉" | 明确拒绝，只出问题日志与建议动作 |

**明确不做**
- 不出持牌审计意见（需外部会计师事务所）；
- 不修改被审模型（只读）；
- 不执行支付、签约、报税（归 `r14` / `r03` 税务域）；
- 不判断投资是否该做（归 `r01` / `r05`）。

> **`r03-washouxian-cfo/harness.py` 在 `ok=false` 时仍然 exit 0。**
