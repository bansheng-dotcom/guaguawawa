# 正反例对照写作法（BAD/GOOD Contrast）

> 一句话定位：**这张卡解决的是「说了很多但没法判」的问题**。
> 「要做得清晰」「要专业一点」「这样不够好」——这些话都对，但都不构成判据。
> 可判定的规范只有一种写法：**同一场景的错例与对例并排，标出差在哪，并给一个阈值**。
>
> 这是 P1 八张范式卡的第一张。它写好之后，其余七张（`quantified-taste` /
> `visual-hierarchy` / `chart-honesty` / `review-tiering` / `narrative-structure` /
> `tone-axes` / `rubric-calibration`）都照它的结构写。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这样不够好」——但说不清哪里不好
- 「写个规范」「沉淀成文档」「让别人也能照做」
- 「评审这张卡能不能判」
- 「为什么每次都要返工同一类问题」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 判断视觉好不好看 | `r10` 的 `visual-hierarchy` | 那有专属 13 条原则 |
| 判断图表诚不诚实 | `r06` 的 `chart-honesty` | 那有 Tufte 判据 |
| 判断文案像不像品牌 | `r11` 的 `tone-axes` | 那有语调三轴 |
| 判断评审漏没漏 | 本角色的 `review-tiering` | 那有 Tier A/B 分级 |
| 给产物打总分 | `r04` 的评审报告 | 本卡只管「规范怎么写」 |

**最小可开工输入**：**一句抽象要求**（如「按钮要显眼」）。

| 输入 | 是否必需 | 缺失时怎么办 |

| 已知的一个坏例子 | 建议 | 缺则先找一个真实翻车样本 |
| 谁来判断（人/机器） | 建议 | 缺则按「人工 + 双评」默认 |

**追问纪律**：最多一轮，只问**那句话是在什么场景下说的、手上有没有一个坏例子**。

## §3 执行流水线（Workflow）

### Step 1 · 把抽象要求还原成场景
抽象要求（「要清晰」）不能直接改，先还原成**一个具体场景**：
「新用户第一次打开结算页，要在 3 秒内找到『确认支付』」。

**判据**：这句话里有没有**人 + 动作 + 时限/条件**？缺一项就不是场景。

### Step 2 · 找一个真实错例（不是编的）
用真实翻车样本。编出来的错例往往错得太明显，失去了训练价值。

**判据**：这个错例是你**真的见过**的，还是为了举例造出来的？造的就退回重找。

### Step 3 · 写对例（同一场景，只改该改的）
对例必须与错例**同场景、同内容**，只在判据点上不同。改了内容就不构成对照。

| 反例（无效对照） | 正例（有效对照） |
|---|---|
| 错例是结算页，对例是首页 | 同一张结算页，只调按钮权重与位置 |
| 错例三行文字，对例换成一张图 | 同样三行文字，只调字号与灰度 |

### Step 4 · 标差异点（差在哪，几条）
逐条写出「错在哪 → 改成什么」，**每条对应一个可观测的差异**。

**判据**：差异点必须是**能指出来给人看**的（位置/字号/词/顺序），不是「感觉更好」。

### Step 5 · 给阈值（至少一条带数字）
每条原则至少配一个数字阈值，没有数字的条目降级为「参考」。

| 原则 | 无阈值（不合格） | 带阈值（合格） |
|---|---|---|
| 层级分明 | 「主次分明」 | 相邻层级**字号差 ≥1.5×** |
| 突出重点 | 「按钮要显眼」 | 主按钮与次按钮**权重不同**（填充 vs 描边） |
| 文案具体 | 「写具体点」 | **形容词 ≤3 处/千字**，每处配数字 |
| 图表诚实 | 「别误导」 | **饼图 ≤5 类**；截断轴必标 |

### Step 6 · 反看一遍（灰化/去色/盲读）
把产物**去掉颜色、或遮住标题**再看一遍：判据还成立吗？
不成立说明你依赖的是装饰，不是结构。

## §5 质量门（一票否决）

1. 每个原则都有 **≥1 组** 同场景错/对例；
2. 错例是**真实样本**，有出处（截图/链接/时间）；
3. 对例与错例**同场景同内容**，只改判据点；
4. 差异点**逐条可指认**（位置/字号/词/顺序），不是「感觉更好」；
5. 每条原则**至少一个数字阈值**；
6. 抽象句占比 **≤20%**（通篇都是「要清晰」即不合格）。

> 本卡无自动门禁。**任一项不过即不得作为规范发布**，须在文档里标注「逐项人工核对」。
> 可配合 `python agent.py harness materials --input <材料.json>` 校验交付材料是否齐备（间接）。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 只写「要清晰、要专业」 | 落到场景 + 错对例 + 阈值 |
| EX-02 | 只给对例不给错例 | 错例才是让人「认出来」的东西 |
| EX-03 | 错例是编的，错得太明显 | 用真实翻车样本，附出处 |
| EX-04 | 错对例不是同一场景 | 同场景同内容，只改判据点 |
| EX-05 | 差异点写「感觉更好」 | 写位置/字号/词/顺序等可指认项 |
| EX-06 | 通篇无量化的阈值 | 每条原则 ≥1 个数字 |
| EX-07 | 阈值给得离谱（≥10×） | 阈值要能实际做到，宁保守 |
| EX-08 | 一条原则配 10 组对照 | 1–2 组足够，多了没人看 |
| EX-09 | 沿用英文 tech demo 原文 | 换成我们自己的场景与中文表达 |
| EX-10 | 写完不做双评就发布 | 双评一致率 ≥80% 才算可判定 |
| EX-11 | 把审美偏好写成规范 | 规范只写可判定的，偏好归人 |
| EX-12 | 依赖颜色/装饰承载判据 | 灰化后判据仍应成立 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 找不到真实错例 | 标注「错例为构造，训练价值有限」，并优先补真实样本 |
| 该领域确实无客观阈值 | 只写「结构判据」，明确标注「审美判断不在此列」 |
| 场景无法复现（一次性活动） | 抽象成「同类场景」再写，并注明抽象依据 |
| 判定依赖专业设备/环境 | 写清前置条件（屏幕、色域、打印），否则不可判 |
| 双评不一致（<80%） | 先改 rubric（多半是差异点写得不够可指认），不是怪评审人 |
| 用户要求「直接告诉我怎么改」 | 给对例 + 差异点，不给结论式命令 |

**明确不做**
- 不做领域判断（视觉/文案/财务/图表各归专属卡）；
- 不给产物打总分（归 `r04` 评审报告）；
- 不裁量审美高下（偏好不是规范）。
