# 快速原型（Rapid Prototype）

> 一句话定位：**这个技能存在的意义，是防止"原型做得像成品，于是被当成成品上线"**。
> 原型最贵的失败不是粗糙，而是**边界不清**：
> 没写成功标准（做完不知道算不算成）、没登记偷懒（把 mock 当实现）、
> 没过截图与设计 QA（自己没看过就发出去）。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「先做个原型看看」「切个 MVP 出来」
- 「做个落地页」 「能不能给用户看一眼」
- 「这个原型还差什么才能上」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 生产级代码与测试覆盖 | `r09` 工程 | 原型不追工程质量 |
| 完整 PRD | `r07` 产品 | 本技能只切「最小可验证」 |
| 视觉规范与品牌 | `r10` 设计 | 原型用临时样式即可 |
| 承诺上线日期 | `r02` 排期 | 原型的时间盒不是交付期 |

**最小可开工输入**：**要验证什么假设** + **给谁看**。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 要验证的假设 | 必需 | 无假设的原型＝做玩具，必须问 |
| 成功标准 | 必需 | 缺则门禁不通过（`mvp.criteria`） |
| 杀死标准 | 必需 | 缺则无法判断"该停" |
| 时间盒 | 必需 | 缺则按 3 天默认并标注 |
| 目标用户与场景 | 建议 | 缺则标注"未定向"，影响 landing 文案 |

**追问纪律**：最多一轮，只问**验证什么、给谁看**。

## §3 执行流水线（Workflow）

### Step 1 · 切片（只做能验证假设的最小集）
```bash
python harness.py mvp --input <MVP切片.json>
```
必须含 `criteria`：至少 1 条成功标准 + 1 条杀死标准，且都要可判定。
门禁实测：缺 criteria 即 FAIL（`mvp.criteria`）。

**切片三问**
1. 去掉它，假设还测得出来吗？（测得出来 → 不做）
2. 它需要真实后端吗？（不需要 → 用 mock）
3. 它能被误当成成品吗？（能 → 加"原型"标识）

- **产出**：切片清单 + 成功/杀死标准 + 时间盒
- **过关条件**：`harness.py mvp` 退出码 0

### Step 2 · 捷径账本（把偷懒写下来）
每一条"故意不做"的，都要登记：`什么 / 为什么现在不做 / 上线前必须补`。

| 典型捷径 | 风险 | 备注 |
|---|---|---|
| 数据 mock | 被当成真实现 | 界面上必须标"示例数据" |
| 无鉴权 | 被误部署到公网 | README 首行警告 |
| 无错误处理 | 演示时崩 | 至少给一条兜底提示 |
| 固定文案 | 被当成最终文案 | 标注"占位" |

**没有捷径账本的原型，等于埋雷**——接手的人不知道哪些是假的。

### Step 3 · 落地页（社会证明必须可核验）
```bash
python harness.py landing --input <落地页.json>
```
门禁校验 `proof`（社会证明）：必须有可核验来源。
门禁实测：缺 proof 即 FAIL（`landing.proof`）。

**禁止**：编造用户数、伪造评价、用无出处的"行业领先"。
没有真实证明就不放证明区——**空格比假话安全**。

- **产出**：落地页结构 + 证明区
- **过关条件**：`harness.py landing` 退出码 0

### Step 4 · 交付前 QA（自己先看一眼）
```bash
python harness.py qa --input <QA记录.json>
```
三项必过：`typecheck`（类型/语法）/ `screenshot`（有截图证据）/ `design_qa`（设计自检）。
门禁实测：任一缺失即 FAIL（`qa.typecheck/screenshot/design_qa`）。

> **没截图的"已完成"不算完成**。截图是"我真的跑起来看过"的唯一证据。

- **产出**：QA 记录 + 截图
- **过关条件**：`harness.py qa` 退出码 0

## §4 交付物清单

| # | 交付物 | 载体 | 骨架出处 |
|---|---|---|---|
| 1 | MVP 切片（含成功/杀死标准 + 时间盒） | `.json` | `examples/mvp.json` |
| 2 | 捷径账本（做了什么/没做什么/上线前补什么） | `.md` | 本文 §3 Step 2 |
| 3 | 落地页结构与证明区 | `.json` | `examples/landing.json` |
| 4 | QA 记录 + 截图 | `.json` + `.png` | `examples/qa.json` |
| 5 | 三份门禁结论 | 终端 JSON | `harness.py mvp/landing/qa` |

- 命名：`proto_<短码>_<YYYYMMDD>/`
- 产物目录首行必须有 `README.md` 写明"这是原型，不是成品"。

---

## §5 质量门（一票否决，不过不给交付）

1. **成功标准与杀死标准各 ≥1 且可判定**（`mvp.criteria`）；
2. **时间盒已声明**；
3. **捷径账本齐全**，每条含"上线前必须补什么"；
4. **落地页证明区可核验**（`landing.proof`），无编造数据；
5. **类型/语法检查通过**（`qa.typecheck`）；
6. **有截图证据**（`qa.screenshot`）；
7. **设计自检通过**（`qa.design_qa`）。

> 验收命令：`python harness.py mvp|landing|qa --input <json>`
> 命中任一项不过 → 回 §3 对应 Step，**不允许把 mock 说成实现**。

## §6 交付前自检清单

- [ ] 我能一句话说清"这个原型要验证什么假设"
- [ ] 成功标准与杀死标准都可判定，不是"感觉好不好"
- [ ] 时间盒写死了（如 3 天），到点就停
- [ ] 每条捷径都登记了"为什么现在不做"与"上线前必须补"
- [ ] 界面上有"原型/示例数据"标识，不会被误当成品
- [ ] 落地页的证明区有可核验来源，没编数据
- [ ] 我自己跑起来看过，并留了截图
- [ ] 类型检查通过，控制台没有报错
- [ ] 移动端宽度下没有横向滚动
- [ ] 产物 README 首行写了"这是原型"
- [ ] 三道门禁均退出码 0

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 只写"做个原型"，不写要验证什么 | 先写假设；无假设的原型是玩具 |
| EX-02 | 没有杀死标准 | 必须写"什么情况下停"，否则会无限磨 |
| EX-03 | mock 数据不标注 | 界面必须标"示例数据"，README 也要写 |
| EX-04 | 原型无鉴权被部署到公网 | README 首行警告 + 不提供公网地址 |
| EX-05 | 超过时间盒还在加功能 | 时间盒到点就停，做不完就砍范围 |
| EX-06 | 落地页编造用户数与评价 | 证明必须有来源；没有就不放证明区 |
| EX-07 | 没截图就报"已完成" | 截图是"真的跑过"的唯一证据 |
| EX-08 | 跳过类型检查直接交付 | 语法错误会让演示当场崩 |
| EX-09 | 只在自己桌面宽度看 | 必须在移动端宽度验证无横向滚动 |
| EX-10 | 把原型当成品交出去 | 产物首页必须写明"这是原型" |
| EX-11 | 捷径不登记 | 接手的人会把 mock 当实现去扩 |
| EX-12 | 用原型承诺上线时间 | 原型时间盒≠交付期；排期归 `r02` |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `harness.py` 跑不了 | 按 §6 人工逐项核对，标注「未跑门禁」；**不得标记"可给用户看"** |
| 无真实社会证明 | 不设证明区，或写"暂无公开数据"，不编造 |
| 无截图工具 | 手工截图并记录时间，标注"手工截图" |
| 时间盒内做不完 | 砍范围（不是延期），并在账本记录砍了什么 |
| 用户要求"顺便做成能上线的" | 明确区分：原型与生产是两次交付，后者归 `r09` |
| 涉及真实用户数据 | 一律用脱敏/示例数据，不接生产库 |
| 需要登录/支付 | 用假流程并显著标注，不接真实凭证 |

**明确不做**
- 不做生产级工程质量与完整测试覆盖（归 `r09`）；
- 不做完整 PRD（归 `r07`）；
- 不做视觉规范（归 `r10`）；
- 不承诺上线时间（归 `r02`）。
