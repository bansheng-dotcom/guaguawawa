# 数据校验（Data Validation）

> 一句话定位：**这个技能存在的意义，是防止"用一份脏数据算出了一个漂亮数字，然后拿它做决策"**。
> 分析出错最贵的形态不是算错，而是**数据本身不该被算**：
> 25% 的 id 缺失、整行重复、日期写成 `not-a-date`、金额是 `abc`、指标口径自创枚举。
> 这些问题不会让代码报错——`pandas` 会把它们变成 NaN 或字符串，然后照常算出结果。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这份数据能用吗」「先看看数据质量」
- 「指标口径对不上」「这个字段是什么类型」
- 「为什么算出来的数比后台少」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 直接给分析结论 | `r06` 的分析域（explore / rootcause） | 本技能只做**算之前**的校验 |
| 建数据管道 / 调度 | `r18` 数仓 | 那是工程侧 |
| 出正式财务口径 | `r03` 财务 | 本技能不出发票级结论 |
| 做显著性检验 | `r06` 的 abtest / ttest | 本技能只判数据是否支持检验 |

**最小可开工输入**：**一份数据文件 + 一句"要算什么"**。没有口径就无法判"这数据够不够用"。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 数据文件（CSV/表格） | 必需 | 无数据即无法审计 |
| 要算的指标 | 必需 | 缺则只能做通用质量审计，无法判"够不够用" |
| 主键与时间列 | 建议 | 缺则无法判唯一性与及时性，标注"未判" |
| 指标语义模型 | 建议 | 缺则跳过口径校验，标注"未校口径" |
| 下游口径（后台/财报数） | 建议 | 缺则无法做交叉核对，标注"无对照" |

**追问纪律**：最多一轮，只问**数据在哪、要算什么、跟什么数对**。

## §3 执行流水线（Workflow）

### Step 1 · 六维质量审计（先看数据能不能用）
在**角色根目录**执行（`<根>` = 角色团根目录，包装器在 `<根>/scripts/` 下）：
```bash
python <根>/scripts/gate_wrap.py --cwd . --input tests/dirty.csv -- agent.py quality audit
```
> 为什么必须包装：`agent.py quality audit` **原生恒 exit 0**（实测 4 条 HIGH 仍 exit 0），
> 只有包装器会按 findings 严重度判退出码。

六维与判据：

| 维度 | 看什么 | 阈值（项目阈值） |
|---|---|---|
| `completeness` | 字段缺失率 | ≥ 5% 即 WARN |
| `accuracy` | 类型/值域是否合法（日期、金额、枚举） | 有非法值即扣分 |
| `consistency` | 跨字段逻辑（金额=单价×数量） | 不一致即扣分 |
| `timeliness` | 时间列是否覆盖目标区间、是否断档 | 断档即扣分 |
| `uniqueness` | 整行重复、主键重复 | 有重复即扣分 |
| `validity` | 格式合法性（日期解析失败、数值越界） | 有非法即扣分 |

> **门禁实测**：一个 5 行 4 列的脏 CSV（id 缺失 25%、整行重复 1 行、日期 `not-a-date`、金额 `abc`）
> 报 4 条 HIGH，`overall_score` 8.2 却仍判"可用-仅小问题"——**必须看 findings 而不是只看总分**。

- **产出**：六维分 + findings 清单
- **过关条件**：无 HIGH/CRITICAL 级 finding（包装器判定）

### Step 2 · 字段级清洗决策（不是全清，是分类处置）
每个问题字段必须归到四类之一：

| 类别 | 处置 | 例 |
|---|---|---|
| 可修 | 规则明确、可脚本化 | 日期格式统一、金额去货币符号 |
| 需问 | 口径不明，必须问上游 | "已完成"是否含退款 |
| 应剔 | 无法修复的脏行 | 主键为空且无法追溯 |
| 保留标注 | 业务上合法但需说明 | 节假日单量为 0 |

**禁止**：无差别 `dropna()`。删掉的行就是被隐藏的信息，会系统性偏乐观。

- **产出**：字段处置表
- **过关条件**：每个问题字段都有类别与理由

### Step 3 · 指标语义建模校验（口径能不能站住）
```bash
python harness.py semantic --input <指标语义模型.json>
```
校验实体 / 维度 / 度量的**类型枚举**：

| 对象 | 合法枚举 |
|---|---|
| 实体 `type` | `primary` / `foreign` / `natural` / `unique` |
| 维度 `type` | `categorical` / `numeric` / `time` |
| 度量 `agg` | `sum` / `avg` / `count` / `count_distinct` / `max` / `min` |
| 指标 `type` | `simple` / `ratio` / `derived` / `cumulative` |

> **已知局限（必读）**：该门禁**只校验枚举合法性，不校验"有没有定义"**。
> 实测一份 entities/dimensions/measures 全为空的语义模型，仍返回 `ok:true`。
> 所以 §6 自检里"每个指标都定义了度量"这一条**门禁抓不到，必须人工核**。

- **产出**：`semantic` 结论 + 错误清单
- **过关条件**：退出码 0 且 `errors` 为空

### Step 4 · 来源分级（每个数字都要有出处）
每个数字必须属于三类之一：

| 类型 | 标注方式 | 可信度 |
|---|---|---|
| **检索核实** | 来源 + 采集日期 | 高 |
| **用户提供** | "用户提供，<日期>" | 中（口径未知） |
| **经验参考值** | 明确写"经验参考值，仅供参考" | 低 |

**禁止伪精确**：查不到就写"暂未核实"，不写"约 1200"。
一个假精确的数字比一个空白更危险——空白会被追问，假数字会被引用。

- **产出**：数字来源表
- **过关条件**：每个数字都有类型标注

### Step 5 · "谁不在这个数据集里"（幸存者偏差检查）
必答三问：
1. 这个数据集**排除了**谁？（已退订用户、失败订单、被拦截的流量）
2. 排除的比例有多大？超过 10% 就必须在结论里声明。
3. 如果补上他们，结论会不会翻转？

> 这是最难自动化的一步，也是最高价值的一步。
> 一个"活跃用户留存提升"的结论，如果分母里剔掉了流失用户，就是自证。

- **产出**：排除人群说明 + 影响评估
- **过关条件**：三问都有回答，且比例已量化

### Step 6 · 交叉核对（对不上就先别算）
用第二个来源验证关键数字（后台看板 / 财务账 / 抽样手算）。

| 差异 | 处置 |
|---|---|
| 完全一致 | 通过 |
| < 1% 且可解释（舍入/时区） | 通过并标注 |
| ≥ 1% 或不可解释 | **停止分析**，先查口径 |

- **产出**：核对表（数字 / 我方 / 对照 / 差异 / 结论）
- **过关条件**：关键数字均有对照或明确标"无对照"

## §5 质量门（一票否决，不过不给交付）

1. **无 HIGH/CRITICAL 级质量 finding**（经共享 `gate_wrap.py` 包装判定）；
2. **每个问题字段都有处置类别与理由**，无无差别 `dropna`；
3. **语义模型枚举合法**（`harness semantic` 退出码 0 且 `errors` 为空）；
4. **每个数字都有来源类型标注**，无伪精确数字；
5. **"谁不在数据集里"三问已回答**，排除比例已量化；
6. **关键数字有交叉核对**，或明确标"无对照"。

> 验收命令：`python harness.py semantic --input <语义模型.json>` + 包装后的 `quality audit`
> 命中任一项不过 → 回 §3 对应 Step，**不允许把脏行删掉让分数变绿**。

## §6 交付前自检清单

- [ ] 我跑了六维审计，并逐条看了 findings（不只看总分）
- [ ] 字段缺失率、重复行数、非法值我都量化了，不是"看起来还行"
- [ ] 每个问题字段都归了类（可修/需问/应剔/保留标注）
- [ ] 我没有无差别删除空值行
- [ ] 每个指标都定义了度量与聚合方式（**门禁抓不到这条，必须人工核**）
- [ ] 语义模型的类型都在白名单内，没有自创枚举
- [ ] 每个数字都标了来源类型（检索核实/用户提供/经验参考值）
- [ ] 没有"约""大概""左右"这类伪精确表述
- [ ] 我回答了"谁不在这个数据集里"，并量化了排除比例
- [ ] 关键数字与第二来源对过，差异已解释
- [ ] 时间列覆盖了目标区间，没有断档
- [ ] 结论里声明了所有已知的口径限制

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 无差别 `dropna()` 清洗 | 分类处置：可修/需问/应剔/保留标注；删行=隐藏信息 |
| EX-02 | 只看 `overall_score` 不看 findings | 8.2 分也可能带 4 条 HIGH；逐条看 findings |
| EX-03 | 自创度量聚合（`sum_of`） | 只允许白名单：sum/avg/count/count_distinct/max/min |
| EX-04 | 语义模型只填了名字没填度量 | 每个指标必须能指到一个度量；**门禁抓不到，人工核** |
| EX-05 | 数字写"约 1200" | 要么给来源，要么写"暂未核实"，不许伪精确 |
| EX-06 | 分母里剔掉流失用户还算留存 | 必须先答"谁不在这个数据集里"并量化排除比例 |
| EX-07 | 时区/日期不统一直接算趋势 | 统一到同一时区与粒度再算；断档要显式说明 |
| EX-08 | 与后台对不上就改口径迁就我方 | 先查口径差异；差异 ≥1% 且不可解释就停止分析 |
| EX-09 | 把"数据可用"当默认结论 | 必须 1+3+4+5+6 共同支撑，缺一只能写"部分可用" |
| EX-10 | 用经验参考值当实测值 | 三类来源必须标注；经验值只能做量级参考 |
| EX-11 | 重复行不去重就统计 | 整行重复会放大计数类指标；先去重再算并记录去重量 |
| EX-12 | 缺失率高还继续算均值 | 缺失 ≥5% 必须说明缺失机制（随机/非随机），非随机则均值不可信 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `harness.py` / `agent.py` 跑不了 | 按 §6 人工逐项核对，标注「未跑门禁」；**不得出"数据可用"结论** |
| 只有抽样数据 | 明确标注"抽样 n=…，代表性未知"，结论降级为"该样本内成立" |
| 无主键 | 无法判唯一性，标注"主键缺失，未判重复" |
| 无对照来源 | 标注"无交叉核对"；关键结论必须写"未经第二来源验证" |
| 数据含个人隐私字段 | 先脱敏再处理；不得把原始 PII 写进交付物 |
| 用户要求"别管脏数据先算" | 可以算，但结论必须标"基于未清洗数据，仅供参考"，且不得用于对外 |
| 数据量过大跑不动 | 抽样 + 分层，标注抽样方案；不硬跑全量 |

**明确不做**
- 不出分析结论与因果判断（归 `r06` 分析域）；
- 不做正式财务口径（归 `r03`）；
- 不建管道与调度（归 `r18`）；
- 不保证数据覆盖所有人群（那是数据源的问题）。

## §9 资源地图（按需读取，禁止全量加载）

### 两条既有门禁的边界（2026-11-11 已修一条）

1. ✅ **`harness.py semantic` 已补非空校验**（此前只校验枚举，entities/dimensions/measures 全空也返回 `ok:true`）。
   现在：每个 semantic_model 必须有 ≥1 entities 且 ≥1 measures；`semantic_models` 与 `metrics` 不得同时为空。
