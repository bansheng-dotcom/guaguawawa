# 选品评分（Smart Product Selector）

> 一句话定位：**这个技能存在的意义，是防止「我觉得这个会火」直接变成备货单**。
> 选品最贵的失败不是选错，而是**没有可推翻的判断**：
> 五维分数随口给、数据来源写"网上查的"、推荐了但没有验证指标。
> 这三件事都能变成结构化字段，所以没理由靠直觉。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这几个品选哪个」「这个品能不能做」
- 「打个分」「值不值得备货」
- 「为什么推荐这个」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 选完之后的定价与投放 | `r12` 的 `campaign-plan` | 那是增长执行 |
| 采购与库存单据 | `r15` 的 `po-validate` | 那是单据校验 |
| 订单与履约 | 本角色的 `order-lifecycle` | 那是交易链路 |
| 市场规模与集中度 | `r05` 的 `industry-panorama-research` | 那是行业研究 |

**最小可开工输入**：**2–5 个候选品名**（少于 2 个无法比较，选品的价值在对比）。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| `products[]`（≥1，建议 ≥2） | 必需 | 无候选无法评分 |
| 每品 `name` | 必需 | 门禁拦 |
| `dims`（五维，各 1–5） | 必需 | 缺维无法比较 |
| `source_types`（枚举内） | 必需 | 写错枚举直接 BLOCKER |
| `hypothesis`（四指标） | 推荐级必需 | 缺则禁止交付（SP-09） |
| `risks`（≥1 条） | 必需 | 无风险的推荐不可信 |

**追问纪律**：最多一轮，只问**候选是哪几个、目标平台**。

---

## §3 执行流水线（Workflow）

### Step 1 · 五维评分（1–5，不给小数）
```bash
python agent.py selection score --input <候选.json>
```
五个维度固定（权重由上游文档归一化）：

| 维度 | 键 | 文档权重 | 判据 |
|---|---|---|---|
| 市场容量 | `capacity` | 30 | 目标人群规模是否撑得起量 |
| 增长趋势 | `growth` | 20 | 近 12 个月是涨还是跌 |
| 竞争可进入性 | `entry` | 25 | 有没有缝隙，还是红海 |
| 毛利空间 | `margin` | 30 | 扣完平台费/物流/退货还剩多少 |
| 供应链可控性 | `supply` | 15 | 交期、起订量、质量稳定性 |

**实测：任一维超出 1–5 即 BLOCKER**（写 9 分不会"更高分"，会被直接拦）。

- **产出**：五维分数表
- **过关条件**：`selection.dims` 全通过

### Step 2 · 数据来源必须在枚举内
`source_types` 只接受三种：

| 枚举值 | 含义 | 可信度 |
|---|---|---|
| `检索核实` | 查过公开数据/工具 | 高 |
| `用户提供` | 客户/供应商给的 | 中 |
| `经验参考值` | 我的经验判断 | 低（必须标注） |

**实测：写 `['1688']` 或 `['随便找的']` 都是 BLOCKER**——
来源不是"从哪看的"，是"这条数据的可信等级"。

### Step 3 · 假设卡（推荐级必须带四指标）
评分落在 **强烈推荐 / 值得尝试** 时，必须附假设卡：

```json
"hypothesis": {"click_rate": "8%", "cvr": "2.5%", "margin": "35%", "verify_at": "2026-12-31"}
```

| 指标 | 作用 |
|---|---|
| `click_rate` | 主图/标题能不能拉住 |
| `cvr` | 详情页能不能转 |
| `margin` | 扣完费用还剩多少 |
| `verify_at` | 什么时候用真实数据回验 |

**四指标缺一即禁止交付**（SP-09）。这是整个包里最硬的一条：
没有验证时点的推荐，等于永远不会被证伪。

### Step 4 · 风险（至少 1 条）
`risks` 为空直接拦。风险要具体："季节性明显""认证成本高"，
不写"有一定风险"——那不是风险，是免责声明。

### Step 5 · 单件利润测算（可选但建议）
```bash
python agent.py selection profit --input <利润参数.json>
```
给售价、成本、平台费、物流、退货率，算真实单件利润。
**毛利率不等于利润**——平台费与退货率经常吃掉一半。

| # | 交付物 | 载体 | 骨架出处 |
|---|---|---|---|

- 命名：`selection_<平台>_<YYYYMMDD>.json`
- **假设卡必须随推荐交付**；没有验证时点的推荐不成立。

## §5 质量门（一票否决，不过不给交付）

1. **候选 ≥1，每个有 name**（`selection.name`）；
2. **五维分数都在 1–5**（`selection.dims`）；
3. **`source_types` 全在枚举内**（`selection.sources`）；
4. **推荐级必须带假设卡四指标**（`selection.hypothesis`，SP-09）；
5. **每个候选 ≥1 条具体风险**（`selection.risks`）；
6. **有效评分 ≥1 个**（`selection.ranked`）。

> 验收命令：`python agent.py selection score --input <候选.json>`
> 命中任一项不过 → 回 §3 对应 Step，**不允许把评分改成 5 分"提一提"**。

---

## §6 交付前自检清单

- [ ] 我有 ≥2 个候选在比（单个候选谈不上"选"）
- [ ] 五个维度都打了 1–5 分，没有 0 分或 9 分
- [ ] 每个分数我都知道依据是什么
- [ ] 数据来源标的是枚举值（检索核实/用户提供/经验参考值）
- [ ] 推荐级候选的假设卡四指标都填了
- [ ] `verify_at` 是一个具体日期，不是"以后"
- [ ] 每个候选至少有 1 条具体风险
- [ ] 我算过单件利润，不是只看毛利率
- [ ] 结论用"强烈推荐/值得尝试/观望/放弃"，不是"还不错"

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 只有 1 个候选就"选" | ≥2 个候选；选品的价值在对比 |
| EX-02 | 维度打 9 分想拉高 | 1–5 分制，超范围直接被拦 |
| EX-03 | 全部维度都给 4 分 | 分数要能区分候选，否则等于没评 |
| EX-04 | 来源写 `['1688']` | 写枚举值（检索核实/用户提供/经验参考值） |
| EX-05 | 用"经验参考值"但不标注 | 低可信来源必须明说 |
| EX-06 | 推荐了但没有假设卡 | 四指标缺一即禁止交付（SP-09） |
| EX-07 | `verify_at` 写"以后" | 写具体日期，到期回验 |
| EX-08 | 风险写"有一定风险" | 写具体风险（季节性/认证/退货率） |
| EX-09 | 毛利率当利润 | 扣平台费/物流/退货率才算单件利润 |
| EX-10 | 结论写"还不错" | 四级结论：强烈推荐/值得尝试/观望/放弃 |
| EX-11 | 评分不写依据 | 每维一句依据，否则无法复核 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `agent.py` 门禁跑不了 | 按 §6 人工核对，标注「未跑门禁」；**不得据以备货** |
| 只有 1 个候选 | 说明"无法比较"，给"再找 2 个"的建议 |
| 数据全靠经验 | 全部标 `经验参考值`，并降低推荐等级 |
| 新品无历史数据 | 用同类品数据代替并标注"替代指标" |
| 平台费用不明 | 给区间测算，标注"费率待确认" |
| 涉及侵权风险 | 明确提示需查专利/商标，本包不做法律判断 |

**明确不做**
- 不做定价与投放（归 `r12`）；
- 不做采购与库存单据（归 `r15`）；
- 不做订单履约（归 `order-lifecycle`）；
- 不承诺销量与爆款。
