# 全渠道电商经营诊断（omnichannel-commerce-assistant）

> 归属：R14　消费：r12, r02　版本：v1.1（2026-11-17 补齐结构）
> 店铺经营诊断：流量、转化、客单、复购、库存五条线，每条线给一个数、一个对照、一个动作，最后收敛成一张优先级表。

## §1 何时使用 / 何时不用

**当…时使用**：当店铺/多平台经营数据需要一次体检、判断先修哪条线时使用；当月度复盘要解释「为什么 GMV 掉了」时使用。

**不用于**：不做投放执行（归 R12）、不做库存采购决策（归 R15）、不出财务口径（归 R03）。

## §2 输入与输出

| 方向 | 内容 |
|---|---|
| 输入 | 分渠道流量与转化数据；订单明细（含客单与复购）；库存周转数据 |
| 输出 | 五线诊断表（指标/本期/对照/判断）；优先级动作清单（含停止条件） |

## §3 执行流程

1. 对齐口径：GMV、客单、转化率的分子分母先写清。
2. 逐线算：流量 → 转化 → 客单 → 复购 → 库存，每线一个数。
3. 找对照：同比/环比/目标三选一，写清跟谁比。
4. 定瓶颈：五线里最短板的一条决定优先动作。
5. 给动作：每条动作带前置条件与停止条件。
6. 交 `review.py` 做对抗评审（数字必须能复算）。

## §5 脚本与门禁入口

| 用途 | 命令 | 判据 |
|---|---|---|
| 订单编排校验 | `python agent.py order order --input <order.json>` | 状态机与金额自洽 |
| 经营诊断 | `python agent.py revenue events --input <data.json>` | 五线指标复算 |
| 评审 | `python review.py <packet.json>` | 数字不可追溯直接 FAIL |

## §6 交付前自检

- [ ] 五个指标都能从明细复算出来
- [ ] 每个指标都有对照对象与差值
- [ ] 优先级只给一条主瓶颈，不是并列五条
- [ ] 动作带停止条件，支付/退款类动作标注 `blocked`

## §7 常见错误对照

| 编号 | 错误 | 正确做法 |
|---|---|---|
| OMNI-01 | GMV 口径混用（含退款/不含退款） | 口径写在表头，全篇一致 |
| OMNI-02 | 五条线都给建议，没有优先级 | 只保留一条主瓶颈 + 两条备选 |
| OMNI-03 | 把行业均值当自己的目标 | 用自身基线或明确标注为外部参照 |

## §8 异常与降级

| 情况 | 处理 |
|---|---|
| 缺库存数据 | 五线改四线，明确标注「库存未观测」 |
| 多平台口径不一 | 先对齐口径再合并，无法对齐则分平台出结论 |
| 退款数据缺失 | GMV 用毛口径并注明未扣退款 |
