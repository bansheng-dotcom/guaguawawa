## 0. 一句话

**分析不是"写观点"，是"在面板上做运算"。**
先把领域面板建出来（tidy 结构、够密），再谈拆卡、图表和报告。

---

## 1. 第一性原理：分析 = 面板上的运算

### 1.1 三个基本事实

1. **观测是原子**：`(entity, dimensions, period, metric, value)`。
   数据量 = 实体数 × 维度组合 × 期次 × 指标数。
2. **没有面板就没有分析**：8 个事实点只能写备忘录；
   要做"哪个城市哪个品类有机会"，至少需要「城市 × 品类 × 年」的矩阵。
3. **面板不够，图就是假的**：排序要 ≥10 个实体、趋势要 ≥12 期、热力图要 ≥8×5。

### 1.2 Tidy Data 三原则（Wickham）

| 原则 | 对我们的含义 |
|---|---|
| 每个变量一列 | `metric_id / entity / period / value / unit / scope` 各占一列 |
| 每个观测一行 | 一行 = 一个实体在某期的一个指标 |
| 每类观测单元一张表 | 零售面板、门店面板、供应链面板分开，不混在一张表 |

**常见错误**（我们之前就犯）：把年份做成列（宽表）、把多个指标塞进一个单元格、把不同观测单元混在一张表。

### 1.3 粒度（Kimball）

**先声明 grain，再选维度与指标**；不同 grain 不进同一张表、不同图。
例：`grain = 城市 × 品类 × 年`；`grain = 门店 × SKU × 周`。

## 2. 面板层（Data Panel）

### 2.1 规模公式与目标

```
行数 N = E × D × T × M
```

| 场景 | 面板 | 行数 |
|---|---|---|
| 北京机会 | 16 区 × 8 品类 × 3 年 | **384** |
| 城市对比 | 4 城 × 5 品类 × 12 月 | **240** |
| 品牌竞争 | 10 品牌 × 5 渠道 × 3 年 | **150** |
| 单店模型 | 3 形态 × 8 成本项 × 4 城 | **96** |
| 门店动销（一手） | 20 店 × 30 SKU × 12 周 | **7200** |

### 2.2 四条来源（按成本）

| 路 | 来源 | 标记 |
|---|---|---|
| A 公开结构化 | 统计年鉴、海关、协会榜单、上市公司分区域收入、招股书 | `source` |
| B 平台/付费 | 生意参谋、久谦、魔镜、飞瓜、美团 | `source` |
| C 一手 | POS、走访、访谈、问卷 | `primary` |
| D 推演 | 总量 × 结构拆分 | **`estimated` + 公式 + 可回算** |

D 的三条铁律：标 `estimated`、写公式与输入行、能被新数据覆盖。

### 2.3 面板的 tidy 结构

| 列 | 例 |
|---|---|
| `metric_id` | `retail.sales` |
| `entity_type` / `entity` | `city` / `朝阳` |
| `period` | `2025` |
| `value` / `unit` | `3126` / `亿元` |
| `scope` | `限额以上` |
| `source_id` / `locator` | `r05:S1` / `p.12` |
| `method` | `source` / `primary` / `estimated` |
| `formula` | 仅 estimated：`278万只 × 4052元` |

### 2.4 分析查询（面板 → 图）

| 分析 | 查询 | 图 |
|---|---|---|
| 排名 | `group by entity, order by value desc` | 排序条/点图 |
| 趋势 | `group by period` | 折线/面积 |
| 构成 | `value / sum(value)` | 占比条/树图/环图 |
| 矩阵 | `pivot(entity × category)` | 热力/矩阵 |
| 相关 | `x vs y` | 散点 |
| 异常 | `|v - median| > k·MAD` | 点图+标注 |

**图不是画出来的，是查询结果的编码**（Vega-Lite：字段 → mark + channel）。

## 3. 接活：12 问 + brief + 用户签字

### 3.1 12 问（少于 10 个有效回答不拆卡）

**问题与决策（4）**：真问题、支持哪个决定、不做会怎样、成功长什么样。
**上下文（4）**：已有数据、行业硬约束、对标、时间预算。
**交付（4）**：最想要的 3 个判断、给谁看、口径偏好、哪些结论不能出现。

依据：DBA 调研 30% 客户希望代理多问；OpenAI Deep Research 先给计划让用户改。

### 3.2 brief（用户签字后才拆卡）

```yaml
brief:
  problem: 一句话问题
  decision: 支持哪个决定、谁拍板
  audience: 谁看
  success: 成功判据
  scope: {in: [...], out: [...]}
  panel_plan: 要建哪几张面板、行数量级、来源
  questions: 12 问摘要
  challenges: R01 的反驳与替代问法
signature: {by: 用户, at: ..., sha: ...}
```

## 4. 拆卡：DoR 9 项 + 评分

### 4.1 DoR 9 项（硬门禁，缺一不发）

依据 Ken Rubin 的 Definition of Ready：

1. 业务价值清楚
2. 细节足够（R02 能判断能否做）
3. 依赖已识别、无外部阻塞
4. 人手/能力匹配
5. 可估且规模合适（一轮能完成）
6. 验收标准可测
7. 性能/质量口径可测
8. 能演示（有可看的产物）
9. **数据可得性**（我们加的：来源与等级明确）

### 4.2 评分 10 项（0–20，仅排序与抽检）

可测 / 决策相关 / MECE / 反例 / 行动 / 视角 / 红队 / 数据可得 / 预期行数 / 口径边界。
<16 不发；R02 打分，R04 抽查 20%。

### 4.3 卡片 = 面板切片

```
panel: 北京分区×品类零售（目标 384 行）
你的切片：16 区 × 3 品类 × 2023–2025 = 144 行
metric: retail.sales（亿元，grain=区×品类×年）
交不满：标 unavailable + 已试来源；缺口走 R02
```

## 6. 角色交什么

**行 + 一句判断。不写长文、不画图。**

- 行必须 tidy（一变量一列、一观测一行）；
- 一句判断 ≤80 字、含数字；
- 交不满写 `unavailable` + 已试来源。

类比 [Briefer Agent](https://www.ycombinator.com/launches/N4w-briefer-agent-your-ai-data-analyst-built-into-a-powerful-data-workspace)：
AI 分析师在**数据工作区**里干活（SQL/DataFrame/图），不是聊天里编结论。

## 7. 综合与写作

### 7.1 theses（R01）

每条：`claim + support_rows(≥3) + contradiction + decision + gaps`。
跨题聚类、矛盾检测、按决策影响排序；**章节 = 论点**。

### 7.2 写作：SCQA + 五块

```
节 = SCQA（背景 → 冲突 → 问题 → 答案）
支撑 = 证据(图) + 机理 + 反例 + 动作
```

- 答案先行（金字塔原理）；
- 单段 ≤300 字，写不下拆节；
- 深度来自证据行数/机理链/反例，不来自字数。

---

## 8. 图表：query(panel) → encoding → charts_pro

- 图只许从面板查询生成，**关闭从段落反推**；
- 图数据点 = 查询返回行数；
- 表 = `pivot(panel)`，与图同源；
- 图表 owner：r06/r09；图覆盖率 100% 或写 `chart_skip_reason`。

---

## 9. 验证：三层（对应 MAST FC3）

| 层 | 验什么 | 失败 |
|---|---|---|
| 行级 | metric 已注册、entity/period/source 齐、单位可换算 | 拒该行 |
| 指标级 | 同键唯一、冲突已裁决、grain 一致 | 进 conflicts |
| 论点级 | ≥3 行支撑、有反例、覆盖 must Q | 退回补行 |

---

## 10. 旧契约退役（flow 不动）

- **只有 flow 一条渲染线**；paper 已删；
- 退役的是 flow 内的旧契约：段落优先、图从段落反推、按问题分节、r02/r04 进执行池；
- `chart_engine=legacy` 保留为未覆盖图型回退，计量目标 <10%；
- 删除条件：flow 上连续 5 份新契约报告过门禁 + 迁移误差 <5%。

## 11. 路线

| 阶段 | 交付 | 验收 |
|---|---|---|
| M0 | 开关、metrics 注册表 | 旧报告可跑 |
| M1 | 12 问 + brief + 签字 | 有效回答 ≥10 |
| M2 | DoR + 评分 + 新卡 | 均分 ≥16 |
| M3 | 面板 spec + 采集 + raw | 面板覆盖 ≥80% |
| M4 | theses + SCQA 写作 | must Q 覆盖 100% |
| M5 | query(panel) 图表 | 图覆盖 100% |
| M6 | 迁移与旧契约退役 | 5 份过门禁 |

---

## 12. 验收指标

| 指标 | 目标 |
|---|---|
| 面板行数 / 目标 | ≥80% |
| 维度覆盖 | 每维 ≥2 值（矩阵 ≥5） |
| 时间跨度 | ≥3 年或 ≥12 月 |
| 缺失率 | ≤20% |
| estimated 占比 | ≤30%，全部可回算 |
| 图覆盖 | 100% 或写理由 |
| 论点覆盖 | must Q 100% |
| 每论点支撑 | ≥3 行 |
| 每图数据点 | ≥ 图型最低要求 |

---

## 13. 不做什么

1. 不用 8 个事实点做分析；
2. 不用字数验收；
3. 不让角色交文章/图；
4. 不从段落反推数字；
5. 不按问题数分节；
6. 不让调度/验收角色进执行池；
7. 不把 estimated 冒充实测。
