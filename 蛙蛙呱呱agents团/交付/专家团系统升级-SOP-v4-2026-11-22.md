## 1. 外部依据

### 1.1 DBA：接活先问，问三类

[DBA 的文章](https://www.dba.org.uk/rediscovering-the-creative-brief/) 给了三个硬事实：

1. **30% 的客户希望代理多问问题、往深里挖**（“They should be more challenging around my brief and push back”）；
2. 提问分三组：**问题（problem）/ 上下文（context）/ 交付（deliverables）**；
3. 好 brief 的结构：问题、机会、受众、核心主张、支撑证据、成功标准、边界与不可动项。

这直接支持“R01 先交互 ≥10 问”。

### 1.2 MAST：失败多来自规格与协调

多智能体失败 41.8% 来自**规格问题**、36.9% 来自**智能体间错位**。
卡写得含糊 = 规格问题；角色各行其是 = 错位。评分卡与行契约分别治这两类。

## 2. R01 接活：12 问 + brief 契约

### 2.1 接活 12 问（少于 10 个有效回答，不许拆卡）

**A 问题与决策（4）**
1. 你要解决的**真问题**是什么？（不是“做个调研”）
2. 这份东西支持**哪个决定**？谁拍板？
3. 不做会怎样？不做也可以的话，为什么要做？
4. 成功长什么样？三个月后什么算“这活干成了”？

**B 上下文（4）**
5. 现在你手上已有哪些数据/结论/报告？（避免重复采）
6. 你所在行业/区域有什么硬约束？（监管、渠道、预算）
7. 竞争对手或对标是谁？你更想赢哪一点？
8. 时间、预算、人手各是什么量级？

**C 交付（4）**
9. 你最想要哪 3 个判断？最不想要什么？
10. 报告给谁看？他习惯什么格式（一页纸/长报告/PPT）？
11. 口径有偏好吗？（全国/区域、平台/统计、含税/不含）
12. 哪些结论**不能出现**？（合规、政治、内部敏感）

**硬规则**：
- 有效回答 <10 → 不许拆卡（`clarify` 状态为 `incomplete`）；
- 必须至少一次**反驳**：指出问题定义可能错在哪，给替代问法；
- 回答落 `clarify.json` 的 `intake` 字段，逐条可追溯。

### 2.2 brief 契约（R01 产出，用户确认后才拆卡）

```yaml
brief:
  problem: 一句话问题（可证伪）
  decision: 支持哪个决定、谁拍板
  audience: 谁看、看什么
  success: 成功的判据
  scope: {in: [...], out: [...]}
  constraints: [时间, 预算, 合规]
  mandatories: 不能动的口径/结论
  questions: 12 问的回答摘要
  challenges: [R01 的反驳与替代问法]
```

## 3. 拆卡：五测 + 评分卡（发卡前门禁）

### 3.1 五道测试（保留）

MECE / 可测（metric+entity+period）/ 有反例 / 可行动 / 决策相关。

### 3.2 卡片评分卡（10 项，每项 0/1/2，总分 20）

| # | 项 | 0 分 | 2 分 |
|---|---|---|---|
| 1 | 问题可测 | 无法落成指标 | 绑定已注册 metric_id |
| 2 | 决策相关 | 不知道也不影响 | 直接改变某个决定 |
| 3 | MECE | 与其他卡重复/漏项 | 互斥且穷尽 |
| 4 | 反例条件 | 没有 | 可观测阈值 |
| 5 | 行动落点 | 无 | 人/钱/时间齐 |
| 6 | 视角覆盖 | 单一视角 | ≥3 视角 |
| 7 | 红队记录 | 无 | 有质询与回应 |
| 8 | 数据可得 | 无来源 | 有明确来源与等级 |
| 9 | 预期行数 | <2 | ≥3（可成图） |
| 10 | 口径边界 | 无 | scope/期次/单位齐 |

**门禁**：<16 分不发卡；R02 打分，R04 抽查 20%。

### 3.3 卡片长什么样（R02 发下去的内容）

```
## 你负责的判断（1–3 个）
J1：<一句判断的占位>（必须含数字）
## 你负责的指标（已注册）
- breakeven.monthly（万元/月，grain=store×month，owner=r03）
## 你必须交的行（≥3）
| metric_id | entity | period | 期望口径 |
## 反例要求
如果 <条件>，你的判断作废
## 红队记录
R05 质询：<问题>；你的回应：<…>
## 交付
rows.json + 一句判断；不写长文、不画图
```

## 4. R02：派工与契约

| 检查 | 判据 |
|---|---|
| 能力匹配 | 角色能力目录里有该 metric 域 |
| 容量 | 单角色 ≤24 行/轮，超出排队 |
| 依赖 | 派生指标等输入；下钻等上级 |
| 卡片评分 | ≥16/20 才发 |
| 缺口路由 | 接不了 → 下一候选 / 采购 / 一手 / 缩范围 |
| 账本 | 每次派工/退回/超时留痕 |

## 5. 正文谁写：R01

**角色不写正文，只交“行 + 一句判断”。正文由 R01 写成，依据是 theses。**

### 5.1 写作契约（每个论点一节，五块）

| 块 | 内容 | 来源 |
|---|---|---|
| 结论 | 1 句判断 + 数字 | thesis.claim |
| 证据 | 图 + 1–2 句图注 | chart + findings |
| 机理 | 驱动/约束/传导链 | thesis.warrant |
| 反例/边界 | 什么情况下不成立 | thesis.rebuttal + qualifier |
| 所以/动作 | 读者做什么 | thesis.action |

### 5.2 深度规则（不设全文字数上限）

- 一个论点写不下 → **拆成两个论点**，不是把段落拉长；
- 单段 ≤300 字（可读性），每块 1–3 段；
- 深度由**证据行数 + 机理链长度 + 反例质量**决定，不由形容词决定；
- 报告节数 = 论点数；一个问题可以对应多节。

### 5.3 为什么正文不会变短

角色的“一句判断”是**输入**，不是正文。R01 要写的是：
**这个判断为什么成立（机理）、什么时候不成立（反例）、读者该做什么（动作）**——
这些都无法由角色代写，也不会因为角色交行而消失。

## 6. 图表接线：raw → query → encoding → charts_pro

```
query(raw, metric_id, entities, periods)     ← 只查 raw
      ↓
encoding（mark + channels）                   ← Vega-Lite 子集
      ↓
chart_grammar 选型（意图 × 形状）             ← 已有 70 型引擎
      ↓
charts_pro 渲染                               ← 已升级的图表系统
```

硬规则：
- 图的数据点 = 查询返回行数（少一个点即不合格）；
- 表 = `pivot(raw)`，与图同源；
- 角色不交图；图表由 r06/r09 统一出；
- 图覆盖率 100%，画不了要写 `chart_skip_reason`。

## 7. 全链路（含 R01 接活与写作）

```
用户指令
  → R01 接活 12 问 + brief（用户确认）
  → R01 拆卡（五测 + 评分卡）→ R02 派工（能力/容量/依赖/评分）
  → 角色交 rows + 一句判断
  → collect：行级校验 → raw.xlsx + metrics.json（冲突/缺口回流 R02）
  → R01 综合：theses（聚类/矛盾/排序，每条挂 support_rows）
  → R01 写作：theses → 五块正文
  → r06/r09：query(raw) → 图/表
  → 装配：report.html（章节=论点）
  → R04：三层校验 + flow 门禁
  → 交付：数据房 + 报告
```

## 8. 路线

| 阶段 | 动作 | 验收 |
|---|---|---|
| **P1 接活** | 12 问 intake + brief 契约；不足 10 答不拆卡 | intake 完整率 100%；反驳 ≥1 |
| **P2 评分卡** | 10 项评分 + R02 门禁 + R04 抽查 | 发卡均分 ≥16；低于门槛 0 张 |
| **P3 写作层** | R01 按五块写；节=论点 | 每节五块齐；单段 ≤300 字 |
| **P4 图表接线** | query(raw) → encoding → charts_pro | 图覆盖 100%；数据点=行数 |
| **P5 反馈** | 论点支撑不足退回补行 | 退回闭环率 100% |

数据层（P0）已完成：`core/data_model.py` + collect 自动产出 raw。

## 10. 不做什么

1. 不在 intake 不足 10 答时拆卡；
2. 不发评分 <16 的卡；
3. 不让角色写正文或画图；
4. 不从段落反推数字；
5. 不用字数验收；
6. 不按问题数决定节数。
