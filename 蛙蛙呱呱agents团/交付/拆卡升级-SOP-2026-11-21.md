## 0. 一句话

**每一问，下发时必须同时给出：谁在看（视角）、看哪几面（维度）、用什么尺子量（度量）、
证据够不够硬（证据）、说到哪一阶（因果）。**

v1.1 只解决了"格子填没填"；v1.3 要求"**填的东西经不经得起追问**"。

### 四个词各对应什么机制

| 你要的 | 机制 | 门禁 |
|---|---|---|
| 多维 | 视角（6 类）+ 维度（6 维）+ 层级下钻 | G13 / G6 |
| 全面 | MECE（互斥穷尽）+ 覆盖矩阵 + 饱和 | G14 / G1 |
| 深入 | 因果三阶（关联/干预/反事实）+ 驱动树 | G15 / G2 |
| 精准 | 度量类型 + 粒度契约 + 口径五要素 + 质量六维 | G16 / G17 / G18 |

## 1. 五轴

### 1.1 L0 问题树（MECE）

把总问题拆成**互斥且穷尽**的子问题；每条结论先写"**要成立，需要什么**"（假设驱动）。

判定：
- 子项相加 = 总体（构成类必须 100%，或说明为什么不是）；
- 没有两个子问题回答同一件事；
- 拆到"可以用一个度量回答"为止。

### 1.2 L1 视角（谁在看）—— v1.3 新增

至少 3 个视角，每个视角至少 1 问。默认六类，可按业务线加减：

| 视角 | 会问什么（个护例子） | 报告里最常缺的 |
|---|---|---|
| 消费者 | 买什么、为什么换、复购多久 | 有 |
| 门店 | 陈列、动销、缺货、导购话术 | **缺** |
| 经销商 | 账期、库存周转、退换货、返利 | **缺** |
| 竞品 | 价格动作、上新节奏、投放 | 部分 |
| 监管 | 备案、功效宣称、特殊化妆品 | 有 |
| 供应链 | 产地、仓、干线、区域仓 | 部分 |

**规则**：视角问题合并去重后进六维网格；一个视角都没覆盖的轴，视为"没分析"。
模板见 `交付/perspectives.template.yaml`。

### 1.3 L2 维度（看哪几面）

六维网格：对象 / 空间 / 时间 / 结构 / 机制 / 边界。
每维要求**层级下钻**：空间至少到盟市、品类至少到子类、时间至少 2 期。

规则：不适用最多 2 维且写原因；每适用维 ≥2 格；单问 ≤24 格。

### 1.4 L3 度量（用什么尺子）—— v1.3 换成 dbt 五类

| 类型 | 必填参数 | 典型指标 |
|---|---|---|
| `simple` | agg / expr / time_granularity | 零售额、门店数 |
| `cumulative` | input_metric / window / grain_to_date | 年累计销量、MTD |
| `ratio` | numerator / denominator | 同比、份额、转化率、均价 |
| `derived` | expr / input_metrics | 单店月销、坪效、客单 |
| `conversion` | base_metric / conversion_metric / window / entity | 试用到复购、进店到成交 |

另两个必填字段：
- `non_additive_dimension`：这个指标在哪个维度上不可加（如库存不可跨时间加）；
- `fill_nulls_with`：缺失怎么处理（默认**不补零**，写 `null` 并标注）。

**粒度契约（Kimball）**：先声明 grain，再选维度与指标；不同 grain 不得进同一张表、同一张图。

### 1.5 L4 证据（够不够硬）

三层判定：

1. **来源等级** A 官方 / B 行业 / C 平台 / D 二手；
2. **质量六维**：完整 / 准确 / 一致 / 及时 / 唯一 / 有效——每格标注，缺项降级；
3. **三角验证**：关键结论 ≥2 个独立来源；只有一个时写明为什么。

每个格子带：`source_file / grade / period / unit / scope / calc`。

### 1.6 L5 因果（说到哪一阶）—— v1.3 新增

| 阶 | 证据要求 | 允许的措辞 | 不允许 |
|---|---|---|---|
| **A 关联** | 相关 + 控制变量 | "伴随/同向变化" | "导致/因为/带来" |
| **I 干预** | 试点/AB/自然实验 | "推动/提升（有实验）" | "必然" |
| **C 反事实** | 对照/合成控制 | "如果没有 X，会少 Y" | 无对照的"本来会" |

**机制结论必须标阶**。只有 A 阶的"机制"，只能写进 `hypotheses`，不得进结论。

配套**驱动树**：结果指标 = 驱动因子相乘/相加（零售额 = 门店数 × 单店动销 × 客单）。
驱动树是"机制"的可算版本；写不出驱动树，说明还没到机制。

## 3. 流程（S1–S9）

### S1 澄清
```bash
report clarify --intent "…" --out <项目>
report clarify --dir <项目> --answer C1=…
```
输出含 `must_not_start_when`（数据条件不满足就别承诺结论）。

### S2 问题树 + MECE
产出 `issue_tree.yaml`：子问题 + 假设 + MECE 校验（加总/互斥）。

### S3 视角枚举
产出 `perspectives.yaml`：≥3 视角，每视角 ≥1 问，合并去重。

### S4 候选拆解 + 评分
每 must 问 ≥2 种拆法，按 决策相关性25 / 覆盖广度20 / 可获取性20 / 机制可证20 / 成本15 打分，
落选写 `decomposition_log.yaml`。

### S5 生成网格 + 绑定度量
`grid.json` 每格带：维度坐标 + `measure` + `entities` + `grain` + `period` + 因果阶目标。

### S6 语义层校验（grain 先行）
`semantic_layer.yaml` 与 grid 双向对齐：每个维度有实体、每个度量被引用；
**先声明 grain，再允许选维度与图型**。

### S7 出映射表并发卡
```bash
report brief --dir <项目> --plan
report brief --dir <项目> --plan --confirm
```
人审先看：格子数 <8、深度 <L3、候选拆法 =1、视角 <3 → 退回。

### S8 收卡 + 验证回流
```
collect → backfill_request.json（缺格/冲突/过期/比率误用）
       → R02 路由（接棒/采购/一手/缩范围）→ 只重跑受影响节 → 二次收卡
       → 仍缺 → 未答清单
```

### S9 出报告（结构不变）
报告是报告：叙事 + 图 + 边界。变化只在数据从"一个数"变成"一格矩阵"。

## 4. 门禁（G1–G18）

| 门禁 | 判据 | 不通过 |
|---|---|---|
| G1 覆盖率 | 已填/应有 ≥70% | 回流 |
| G2 深度 | must ≥1 格 L3 | 退卡 |
| G3 证据字段 | period/unit/source/grade 齐；A+B ≥50% | 退卡 |
| G4 口径唯一 | 同 scope+period+measure 一个值 | conflicts |
| G5 诚实 | unavailable 带 tried+why | 退卡 |
| G6 结构 | 每适用维 ≥1 格 | 退卡 |
| G7 度量代数 | ratio 不得求和/平均；不得混 grain/scope | 退卡 |
| G8 图全量 | 图的数据点 ≥ grain 覆盖 | 图不合格 |
| G9 新鲜度 | 不早于 freshness，超期标 stale | 降级 |
| G10 回流闭环 | backfill 每条有处理结果 | 不许发 |
| G11 分支日志 | 每 must 问 ≥3 条 stop | 视为没深入 |
| G12 候选拆解 | ≥2 拆法 + 评分 + 落选理由 | 退回重拆 |
| **G13 视角** | ≥3 视角，每视角 ≥1 问 | 退回补视角 |
| **G14 MECE** | 构成类加总=100%，或说明为何不是 | 退回 |
| **G15 因果阶** | 机制结论标 A/I/C；A 不得写因果词 | 改措辞或降级 |
| **G16 度量参数** | derived/ratio/conversion 必填公式与输入指标 | 退卡 |
| **G17 grain 先行** | 未声明 grain 不得选维度/图型 | 退回 |
| **G18 质量六维** | 每格标 完整/准确/一致/及时/唯一/有效 | 降级 |

## 5. 图合同

```yaml
chart:
  chart_id: c1
  claim_to_prove: "口腔 CR5 仅 33.3%，是新品牌唯一入口"
  why_visual_not_text: "七个份额的分布，文字列不出形状"
  decision_role: dominant | supporting | optional
  focus_target: "其他 66.7%"
  required_metrics: [share]
  required_annotations: ["前五累计 37.4%", "其他=长尾"]
  failure_conditions: ["口径混用平台与统计公报", "份额求和"]
  data_points: 6        # 必须等于语义层声明的粒度覆盖
  causal_level: A       # 这张图证明到哪一阶
```

图型选择由 **度量类型 × 覆盖度** 驱动（不是关键词）：
ratio×多主体→排序/帕累托；ratio×构成→份额/树图；flow×时间→线/面积；flow×两实体→矩阵/桑基。

## 6. 失败与降级

| 情况 | 处理 |
|---|---|
| 某维/某视角无公开数据 | 标 unavailable，进未答清单，不静默删 |
| 只有 C/D 级来源 | 可填，但不得作为 must 结论唯一证据 |
| 机制只有 A 阶 | 降级为 hypotheses，不得写成结论 |
| grain 无法统一 | 拆图/拆节，不混比 |
| 格子 >24 | 拆成两问 |
| 回流一次仍缺 | 进未答清单，口径页可见 |

## 7. 与产线接口

```
clarify.json  (Q + tier + must_not_start_when)
   │ S2 issue_tree.yaml（MECE + 假设）
   │ S3 perspectives.yaml（≥3 视角）
   │ S4 decomposition_log.yaml（候选拆解评分）
   │ S5 grid.json（维度 × 度量绑定）
   │ S6 semantic_layer.yaml（grain 先行、双向对齐）
   ▼
plan.json (R02 签发契约：owner/acceptance/deadline) → TASK.md → claims.json(cells[])
   │
collect → backfill_request.json → 定向补数 → 二次收卡
   │ G1–G18
   ▼
report（不变）
```
