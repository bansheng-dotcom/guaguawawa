## 2. 现状（审查结论）

### 2.1 角色

- **20 个角色，16 个标记"进报告"**；但最近一次只用了 **5 个**（r03/r05/r06/r12/r14）。
- **r02（调度）、r04（评审）也在执行池里**——这是设计缺陷：调度与验收不该交数据。
- r08/r09/r10/r17 被排除在报告外，但其中 r09 是图表/设计、r18 是数仓，**恰恰是 raw 层与图表层最该用的人**。
- 每个角色都能写 3 节、交 100+ 个数字，但**没有一个角色对"数据表结构"负责**。

### 2.2 产线

```
clarify → plan → 发卡 → 各角色 claims.json → collect 合并 → run-line 渲染
```

- 有：澄清、拆卡、收卡、合并、门禁、渲染。
- **没有**：原始数据层（raw）、综合层（论点）、图表 owner。
- 图表由渲染层在最后一步"从段落数字反推"，所以图差。

### 2.3 产物

| 产物 | 现状 | 问题 |
|---|---|---|
| `report.html` / `.pdf` | 14 节，章节=问题 | 不是论点，是答问拼接 |
| `数据与证据.xlsx` | **477 行 `01 关键数字`**（角色/指标/数值/单位/期次/来源/等级）+ 三形态模型、北京盘子、用品分层、玩家、问句对账、来源账本、缺口 | **智能体用 Excel 技能顺手做的副产物，产线不读它**；指标名是自由文本，单位 48 种 |
| `claims_merged.json` | 476 个数字 | 图从段落反推，口径不齐 |
| `manifest.json` | 门禁/来源/降级 | **没有 raw 覆盖率、没有论点覆盖** |

### 2.4 门禁

- 24 条卡门禁（G1–G24）：管覆盖/深度/证据/因果/质量。
- flow 门禁：管图源、边界、重复句、falsifier。
- **缺口**：没有一条门禁检查"这张图是否来自 raw 表""这个数字是否已注册""这一节是否服务某个论点"。

## 3. 六个断点（按严重度）

| # | 断点 | 证据 | 后果 |
|---|---|---|---|
| 1 | **raw 表没有成为唯一数据源** | 477 行 Excel 存在，但渲染不读 | 图/表各算各的，口径漂移 |
| 2 | **指标名是自由文本** | 476 个数字、19 组重名、48 种单位 | 跨角色无法合并，图混指标 |
| 3 | **没有综合层** | 14 节=14 问，无跨题聚类/矛盾/排序 | 报告是拼装，不是思考 |
| 4 | **角色不交"行"，交"段落"** | claims 里 0 张图、段落 1000+ 字 | 文图两张皮 |
| 5 | **调度与验收混入执行池** | r02/r04 有 claims 模板 | 自己派自己、自己验自己 |
| 6 | **图表没有 owner** | 5 个角色各写各的图，渲染再猜 | 图型单一、画不全 |

## 4. 目标形态（系统最终长什么样）

### 4.1 用户视角

```
输入：一句话 + 项目目录
 ↓
一次跑批产出「数据房」：
  out/raw.xlsx          原始数据（6 张表：说明/原始数据/度量注册/冲突/覆盖/来源）
  out/theses.md         论点（3–7 条，每条带支撑行/反例/决策含义）
  out/report.html       报告（章节 = 论点）
  out/manifest.json     门禁与溯源
 ↓
人只做三件事：审论点、改口径、批动作
```

### 4.2 角色新分工

| 层 | owner | 交付 |
|---|---|---|
| 行（数据） | 研究/分析角色（r05/r06/r07/r12/r14/r15/r18） | `rows.csv`：metric_id/entity/period/value/unit/scope/source |
| 度量注册 | **r18 蛙数仓**（新增职责） | `metrics.json`：id/unit/grain/可加性/公式 |
| raw 表 | **r18** | `raw.xlsx` 六张表 |
| 综合（论点） | **R01**（r02 排期） | `theses.json/md` |
| 图表 | **r09/r06**（单一 owner） | 图/表，全部 query(raw) |
| 验收 | r04 | 门禁结论 |

### 4.3 产物契约

| 文件 | 必须含 | 验收 |
|---|---|---|
| `raw.xlsx` | 原始数据/度量注册/冲突/覆盖/来源 | 行可溯源 100%；冲突显式 |
| `theses.md` | 每条论点：claim/支撑行/反例/决策/缺口 | must Q 覆盖 100% |
| `report.html` | 节=论点，图来自 raw | 图覆盖 100% 或写明不可画 |
| `manifest.json` | raw 行数/指标数/冲突数/论点覆盖 | 四项可查 |

## 5. 升级路线（P0–P4）

| 阶段 | 动作 | 产物 | 验收 |
|---|---|---|---|
| **P0** | 把 `01 关键数字` 提为 raw：定行 schema、指标归一、单位归一、冲突表、覆盖表 | `raw.xlsx` + `metrics.json` | 477 行 → 归并后行数；指标归并率 ≥80%；冲突显式 |
| **P1** | 加综合层：跨题聚类、矛盾检测、按决策影响排序 | `theses.json/md` | must Q 覆盖 100%；每论点 ≥3 行支撑 |
| **P2** | 图表 owner 化：只允许 query(raw) 出图；关掉"从段落反推" | 图/表 | 图覆盖 100%；图数据点=查询行数 |
| **P3** | 卡片 v5：交行 + 一句判断；未注册 metric 拒收；r02/r04 移出执行池 | 新卡模板 | 每行进 raw；越权拒收 |
| **P4** | 旧报告迁移 + 新旧对比 | 对比报告 | 同数据：图↑、字数↓、可追溯↑ |

**P0 是唯一必须先做的**：没有 raw，P1 是空谈，P2 是猜。

## 6. 拆卡升级到行业专家水准

### 6.1 五道测试（发卡前）

| 测试 | 判据 |
|---|---|
| MECE | 子问题互斥穷尽；构成类加总 100% |
| 可测 | 能被 `metric_id + entity + period` 回答 |
| 有反例 | 每条判断带可观测的作废条件 |
| 可行动 | 能落到人/钱/时间 |
| 决策相关 | 不知道这条会不会改变决定 |

### 6.2 专家级拆卡流程

```
问题 → 问题树（≤3 层） → 视角枚举（6 类）
     → 每视角出子问题（STORM 式）
     → 绑 metric/entity/period
     → 红队质询（另一个角色问"不知道会怎样"）
     → 五测通过才发卡
```

### 6.3 行业问题库（示例：宠物用品）

| 视角 | 专家会问 | 需要的行 |
|---|---|---|
| 消费者 | 单只年消费、品类偏好、复购 | `spend.per_pet`、`pref.category`、`repurchase.cycle` |
| 门店 | 单店月销、坪效、洗美占比 | `sales.per_store`、`sales.per_sqm`、`mix.grooming` |
| 经销商 | 库存周转、账期、退换 | `inventory.weeks`、`dso.days`、`return.rate` |
| 竞品 | 份额、价格带、上新 | `share.brand`、`price.band`、`new_sku.count` |
| 监管 | 备案周期、宣称限制 | `reg.lead_time` |
| 供应链 | 到岸成本、时效 | `landed.cost`、`lead_time.days` |

## 7. 验收指标（替代字数/图数）

| 指标 | 目标 |
|---|---|
| 行可溯源率 | 100% |
| 指标归并率 | ≥80% |
| 冲突显式率 | 100% |
| 图覆盖率 | 100% 或写明不可画 |
| 论点覆盖率 | must Q 100% |
| 支撑密度 | 每论点 ≥3 行 |
| 正文节数 | = 论点数 |

## 8. 不做什么

1. 不再用字数验收；
2. 不再让角色交文章/图；
3. 不再从段落反推数字；
4. 不再按问题数决定节数；
5. 不再让 r02/r04 进执行池。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 477 行指标归一工作量大 | 先自动归并（去括号/城市/品牌），人工只审冲突 |
| 角色嫌交行麻烦 | 模板 + 校验器，不合规拒收 |
| 综合层写成"再写一遍" | 论点必须挂 support_rows |
| 旧报告迁移难看 | 迁移只保真，不承诺好看 |
