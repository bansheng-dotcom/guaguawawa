## 0. 一页结论

**这次升级只做一件事：把系统从「写全」改成「可决策」。**

| 改什么 | 怎么改 | 验收 |
|---|---|---|
| 文字 | 一页决策纸 + 正文 ≤7 条主判断 + 单段 ≤300 字；其余进附录 | 读者 3 分钟能说出「做不做、先做哪个、钱怎么分」 |
| 图表 | 先 slice 再 encoding；每条主判断 1 图 + 1 表；同图同单位同主体；baseline/annotate 真画出来 | 50 张图 0 张混单位 |
| 排版 | 封面放决策数；结论式短标题 ≤20 字；决策页/正文/附录四层 | 封面 3 个数字能改变决定 |
| 门禁 | 计划可答性 → 证据覆盖 → 读者可决策 → 呈现可读，四层 | 负向用例 20 条必须被拦 |

**时间表**：4 周，两个止血点（D2、W1 末）+ 两个重构点（W2 末、W4 末）。
**不做什么**：不砍数据（进附录）、不改 flow 主题、不做多用户、不追求「每节都有图」。
**成功标准**：你说「对」——不是门禁说 PASS。

## 3. 目标架构

### 3.1 一人四视角（一份报告，四个入口）

| 视角 | 你想要什么 | 放在哪 |
|---|---|---|
| 创始人 | 3 分钟拍板：做不做、先做哪个、钱怎么分 | 第 1 页决策纸 |
| 团队 | 90 天动作、负责人、预算、验收、停止条件 | 正文「动作」页 + 附录动作表 |
| 客户/合作方 | 证据、口径、来源、边界 | 附录（证据账本） |
| 投资人 | 大盘、增速、竞争、为什么现在 | 正文「市场」主判断 + 附录数据 |

**不为四个角色做四份报告**；做一份，但四层入口都能在 30 秒内找到。

### 3.2 三层交付

```
L1 决策纸（1 页）：5–7 条主判断，每条 1 句 + 1 数 + 1 动作 + 1 停止条件
L2 正文（≤7 条主判断）：每条五块（结论/证据/机理/反例/动作），1 图 + 1 表
L3 附录（不限）：支撑判断、全量数据、来源账本、缺口与假设、图表画廊
```

**页数不限**：L3 可以长；L2 必须有取舍；L1 必须能拍板。

### 3.3 数据流（v4）

```
Facts（度量×维度×期次）
  → Slice（metric + subject + contrast + period + rows）
  → Encoding（mark + channel）
  → Findings（extreme/gap/trend/concentration/crossover/outlier）
  → Claim（Toulmin：claim/warrant/rebuttal/qualifier/action）
  → Realization（五块；文字只写图上看不出的判断）
```

**硬约束**：一个 claim 恰好一张图；`chart.data_points == len(slice.rows)`；同图同单位同主体。

### 3.4 五块 section

| 块 | 内容 | 硬约束 |
|---|---|---|
| 结论 | 1 句判断 + 关键数字 | ≤80 字；不含「可能/或许」 |
| 证据 | 1 图 + 1 表；每个数字带 refs | 图必须画全 slice |
| 机理 | 驱动/约束/传导链 | ≥1 条可算关系（两个度量 + 方向） |
| 反例/边界 | 什么情况下不成立 | 必须有；找不到写「未找到 + 怎么找的」 |
| 动作 | 读者该做什么 | 1–2 条；落到人/钱/时间；证据不足写「待验证」 |

**单段 ≤300 字**；写不下 = 判断没拆开 → 拆下一节，不是写长。

### 3.5 单一事实源：`configs/report_contract.yaml`

```yaml
report:
  paragraph_max_chars: 300
  section_max_chars: null        # 不设上限
  main_claims_max: 7
  title_max_chars: 20
  chart_per_main: 1
  table_per_main: 1
  appendix: true
  decision_page: true
  gap_page: true
  source_grades: [S, A, B]       # C 只作线索
  chart_unit_strict: true        # 同图同单位
  chart_entity_strict: true      # 同图同主体层
  chart_baseline_required: true
  chart_annotate_required: true

```

**所有模块只读这一份**：`report_dispatch`、`prose_style`、`report_layout`、`dispatch`、`report_quality`、`report_flow`、`claims_v4`。
**删除/改写**：`prose_style.DEFAULTS.chars_per_section`、`chars_hard_min`、`report_layout._FALLBACK.section_chars`。

### 3.6 图表语法（关系 → 图型）

不做「数字个数 → 图型」，做「论证关系 → 图型」。下面是最小映射；完整 48 型见 §10.1。

| 关系 | 首选 | 备选 | 禁止 |
|---|---|---|---|
| 类别对比/排名 | hbar | dot/lollipop | 饼图 |
| 两期变化 | slope | dumbbell | 双轴 |
| 多期趋势 | line | area | 饼图 |
| 构成（合计≈100） | stacked_bar | pct_stacked/donut | 折线 |
| 分布/集中度 | pareto | box/violin | 饼图 |
| 漏斗/转化 | funnel | waterfall | 折线 |
| 区间/目标 | target_band | bullet | 饼图 |
| 正负偏离 | diverging | waterfall | 全正数用 diverging |
| 地理 | choropleth | symbol_map | 3D |
| 两变量关系 | scatter | bubble | 柱状 |
| 构成随时间 | streamgraph | stacked_area | 饼图 |

**80 例最低标准**：`scripts/gen_chart_gallery.py` 从 48 型 + 10 关系生成 80 个示例（同型不同数据形状算两个），输出 `docs/CHART-GALLERY.html`，CI 快照防退化。

### 3.7 编辑层（R01 的砍稿权）

1. **选**：从 N 条 claim 里选 ≤7 条 `tier=main`；其余 `tier=support` 进附录。
2. **砍**：删除跨节重复句；合并同一判断的多个版本；每节只留一个「所以」。
3. **排**：主判断按决策顺序排（做不做 → 选哪个 → 钱 → 渠道 → 合作）。
4. **提**：封面 3 个决策数、决策纸 7 条、目录短标题，全部从 main claims 来。
5. **查**：每条 main claim 必须有 1 图 + 1 表 + 1 反例 + 1 动作；缺一不进正文。

### 3.8 门禁四层

| 层 | 查什么 | 不过的后果 |
|---|---|---|
| Plan gate | 每个 must 格有来源/字段/检索式；可获取=0 的拆解淘汰 | 不发卡 |
| Evidence gate | 覆盖率、S/A/B、引文回抓、数字→单元格 | 不出报告 |
| Reader gate | 决策纸、≤7 主判断、单段 ≤300、1 图 1 表、标题 ≤20 | 退回编辑 |
| Presentation gate | 图单位/主体一致、baseline/annotate 已渲染、图点=slice 行数、无自动 filler 表 | 不渲染 |

### 4.8 核验后的 5 个信号（会改结论）

**核验后调整了 8 个结论**：

| # | 材料 | 原结论 | 新结论 | 原因 |
|---|---|---|---|---|
| 16 | Chart-to-Text | adopt | partial | GPL-3.0；2024 停更；132 stars；只借 schema |
| 19 | chart-llm | adopt | partial | 2024 停更；140 stars；只借 guided discovery |
| 21 | jsRealB | adopt | partial | 27 stars；仅英/法；借结构不接代码 |
| 22 | FactCC | adopt | partial | 仓库已归档；只借 claim-source 校验思路 |
| 23 | TabFact | adopt | partial | 2023 停更；数据集；借数字→单元格 schema |
| 36 | AutoGen | partial | reject | 已归档；高星但不可作长期依赖 |

**结论**：真正可以「装进产线」的是 **15 个 adopt**；其余 32 个是「借机制/借 schema/借版式」，3 个 reject 只作为反例。这个区分比「50 个都学会」更重要。

**核验后新增的选型规则（写进 `requirements` 评审）**：

1. **默认依赖门槛**：stars ≥1,000、最近 6 个月有推送、license 为 MIT/Apache-2.0/BSD、`archived=false`；四条缺一，只能进「参考」栏。
2. **GPL/AGPL 只做独立进程调用**：Pandoc、Vivliostyle、Chart-to-Text、ChartQA 不静态链接、不复制代码进闭源包；需要分发时先过法务。
3. **数据集只借 schema**：ToTTo/TabFact/ChartQA/SciCap 只借「高亮单元格→句子」「数字→（行,列）」的结构，不 pin commit、不把数据集当运行时依赖。
4. **低星/停更只借设计**：Papa（4 stars）、GenAI Consulting（17）、jsRealB（27）、Good Docs（2022 归档）只借阈值/版式，不押发布流程。
5. **长期依赖选活跃赢家**：Typst、Altair、LangGraph、PydanticAI、promptfoo、Vale、textlint、ADR（17.5k，2026-11-20 仍在推送）。

## 8. 验收

### 8.1 创始人 3 分钟测试（人工）

**通过**：5 问答出 4 条，且每条能指到报告里的一个数字/动作。
**不通过**：任何一条答不出，或需要在正文里翻 3 页以上。

- [ ] 决策页 1 页，5–7 条主判断

- [ ] 单段 ≤300 字

- [ ] 封面 3 个决策数
- [ ] 0 张混单位图
- [ ] 0 条无来源数字
- [ ] 缺口独立成页
- [ ] 附录含全部 support + 来源账本
- [ ] 页脚无内部审计信息
