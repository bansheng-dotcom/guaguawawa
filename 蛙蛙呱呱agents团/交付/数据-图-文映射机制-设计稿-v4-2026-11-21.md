# 数据 → 图 → 文 映射机制（系统级设计稿 v4）

> 2026-11-21 · 待审 · 不写代码
> 目标：把"一图配一段文字"升级为**可机检的映射流水线**，用结构解决"内容多、图不好、文图两张皮"，不靠字数限制。

## 0. 为什么之前都在打补丁

现在的链路是 **text-first**：角色先写结论和段落，图是事后配的（或者渲染层从数字反推）。
所以：
- 数据多 → 文字越写越长；
- 图不是从数据长出来的 → 只能画个大概；
- 文和图各说各的 → 只能靠门禁事后抓。

**正确顺序是 data-first**：数据 → 切片 → 编码（图）→ 发现 → 判断 → 文字。
文和图共享同一个 `slice_id`，一致性由构造保证，不靠检查。

依据：
- Vega-Lite 的图形语法：**数据字段 → mark + encoding channel**，图是映射的产物（[Encoding 文档](https://vega.github.io/vega-lite-v1/docs/encoding.html)）；
- NLG-for-Vis 综述的流水线：**内容选择（发现）→ 微规划 → 表面实现**，文本不是"写"出来的，是从发现生成的（[arXiv:2409.19747](https://arxiv.org/html/2409.19747v1)）；
- Toulmin 论证模型：**claim / data / warrant / rebuttal / qualifier**，正好对应结论/证据/机理/反例/边界（[模型说明](http://files.eric.ed.gov/fulltext/EJ1495464.pdf)）；
- 叙事结构：作者驱动 vs 读者驱动、线性 vs 非线性（Segel & Heer 的 narrative visualization 框架），决定"主判断进正文、支撑判断进附录"。

## 1. 六层流水线

```
L1 事实 Facts      度量 × 维度 × 期次（已有语义层）
L2 切片 Slice      一次比较：metric + subject + contrast + period
L3 编码 Encoding   字段 → mark/channel（Vega-Lite 子集），产出 chart spec
L4 发现 Finding    在 slice 上跑检测器：极值/差距/趋势/集中度/交叉/异常
L5 判断 Claim      Toulmin：claim=发现；warrant=机理；rebuttal=反例；qualifier=边界
L6 表达 Realization 每发现一句；文字只写图上看不出的判断
```

**核心约束：一个 claim 恰好一张图，图必须画完整 slice。**
这条替代了"每节 ≥N 字"和"每节必须三段"——长度是 findings 数量的自然结果。

## 2. 数据结构（替代 sections/reading）

```yaml
slice:
  id: S1
  metric: 盈亏平衡点
  subject: [社区自雇店, 社区雇人店, 前置仓]
  contrast: 三形态
  period: 2026
  rows: 3            # 图必须画全 3 行

encoding:            # Vega-Lite 子集
  mark: bar
  x: {field: 平衡点, type: quantitative}
  y: {field: 形态, type: nominal}
  color: {field: 形态, type: nominal}

findings:
  - {id: F1, type: extreme, text: "最低 5.85 万（社区自雇）", refs: [N1]}
  - {id: F2, type: gap,     text: "与前置仓差 8 倍", refs: [N1, N3]}
  - {id: F3, type: crossover, text: "5.85 万只在自雇结构成立", refs: [N3]}

claim:
  id: C1
  qid: Q7
  slice_id: S1
  finding_ids: [F1, F2, F3]
  claim: "10 万预算只有社区自雇店能打平，平衡点 5.85 万/月"
  warrant: "平衡点 = 固定成本 ÷（毛利率 − 变动费用率）"
  rebuttal: "面积 80㎡、2.5 人时同营收不成立"
  qualifier: "北京四环内社区底商、2026 年价格"
  action: "先做自雇店；10 万预算不做前置仓"
```

渲染时：
| 块 | 取自 |
|---|---|
| 结论 | `claim.claim` |
| 证据块 | `encoding` → 图；`findings` → 图注 1–2 句 |
| 机理 | `warrant` |
| 反例/边界 | `rebuttal` + `qualifier` |
| 所以/动作 | `action` |

## 3. 图从编码来，不从偏好来

| 数据形状（slice） | encoding | 图 |
|---|---|---|
| 1 维 × 3–8 主体 | mark=bar, x=value, y=category | 横条/排序 |
| 1 维 × 2 期 | mark=line, x=period, y=value | 斜率/折线 |
| 构成（合计≈100） | mark=arc / rect, theta / area=share | 环图/树图/占比条 |
| 正负偏离 | mark=bar, x=value 含负 | 正负条 |
| 两变量 | mark=point, x/y=两字段 | 散点 |
| 区间 | mark=rule, x=low..high | 区间图 |

**门禁**：`chart.data_points == len(slice.rows)`，少一个点就是图不全。

## 4. 发现检测器（文字的真正来源）

| 检测器 | 输出 | 用于 |
|---|---|---|
| extreme | 最大/最小 + 值 | 结论句 |
| gap | 两个主体的差/倍数 | 对照句 |
| trend | 期次上的方向与幅度 | 趋势句 |
| concentration | 前 N 名占比 | 集中度句 |
| crossover | 排序变化/反超 | 转折句 |
| outlier | 偏离中位数的点 | 反例句 |

**文字规则**：每个 finding 一句；claim 段 = findings 的合并，不重复图上的数字（图上已标），只写判断。
这样"文字多不多"由**发现多不多**决定，不由字数配额决定。

---

## 5. 规模问题的解法：分层，不是压缩

数据源多 → claim 多。报告不把每个 claim 都写长，而是：

| 层 | 内容 | 数量 |
|---|---|---|
| 执行摘要 | 3–5 条主判断 | 3–5 |
| 正文 | 主判断（decision-relevant） | 5–7 |
| 附录 | 支撑判断、口径、来源、反例 | 不限 |

**主判断的筛选**：按"是否改变决策"排序，前 5–7 进正文，其余进附录。
这就是"内容非常多非常大"的正确解法——**不是把每节写短，而是把不改变决策的内容移出正文**。

## 6. 与现有系统的关系

| 保留 | 替换 |
|---|---|
| 语义层（度量代数/粒度） | `sections[].reading` → `claims[]` + `findings[]` |
| 六维网格（拆卡） | 卡片交付"判断单元"而非"段落" |
| 24 条门禁 | 新增映射门禁 C1–C5 |
| 图表引擎 charts_pro | 图型选择由 encoding 决定，不由关键词 |

**新增门禁**：
- C1 每个 claim 有且仅有一个 slice；
- C2 图的数据点 = slice 行数；
- C3 claim 的 finding 必须由 slice 计算得到（不能手写数）；
- C4 warrant 必须是一条可算的关系（≥2 个度量）；
- C5 主判断 ≤7，其余进附录。

## 7. 用宠物报告第 1 节验证（同一批数据）

| 层 | 内容 |
|---|---|
| slice | 三形态 × 盈亏平衡点 × 2026 |
| encoding | bar，y=形态，x=平衡点 |
| findings | 最低 5.85；与前置仓差 8 倍；5.85 只在自雇成立 |
| claim | 10 万预算只有社区自雇店能打平 |
| warrant | 平衡点 = 固定成本 ÷（毛利率 − 变动费用率） |
| rebuttal | 80㎡、2.5 人不成立 |
| action | 先做自雇店，不做前置仓 |

图、文、证据同源；读者先看判断，再看图，再看为什么。

## 8. 迁移（不推倒重来）

1. 旧 `sections` 迁移：`python scripts/migrate_claims_v4.py --project <项目>`（每个 reading 变成 1 个 claim + 1 个 finding，legacy 标记），先保证能渲染；
2. 新卡按 v4 交付 `claims[]`，collect 走 C1–C5；
3. 渲染器加五块映射，旧路径保留一个版本；
4. CI 用同一批数据对比新旧报告，确认"信息量不减、长度下降、图覆盖率 100%"。

**验收标准（替换字数）**：
- 每个主判断：1 图 + 1 结论 + 1 机理 + 1 反例 + 1 动作；
- 图覆盖率 = 100%（或写明不可画理由）；
- 正文主判断 ≤7；
- 单段 ≤300 字（可读性），但**不设每节总量**。
