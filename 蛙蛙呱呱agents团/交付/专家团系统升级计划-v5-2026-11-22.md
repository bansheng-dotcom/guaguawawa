# 专家团系统升级计划 v5（执行版）

> 2026-11-22 · 依据已确认的四条：12 问接活、DoR 9 项、SCQA+五块、双签机制。
> 本计划回答三件事：**怎么接入现有系统、角色怎么协同、旧产线怎么下沉**。

---

## 0. 目标与范围

**目标**：报告从"角色答问拼装"升级为"数据房 → 论点 → SCQA 正文 → 查询出图"，且每一步有签字、可回滚、旧线可迁移。

**范围内**：R01 接活/拆卡、R02 派工、角色交行、collect 数据层、论点层、写作层、图表层、验收、manifest。
**范围外**：20 角色的能力边界（不改）、行业方法库（只加不改）、报告视觉风格（不改）。

## 2. 目标架构（五层 + 两签 + 两回流）

```
用户指令
  → R01 接活 12 问 → brief（用户签字）        ← 签字①
  → R01 拆卡 → R02 DoR 9 项 + 评分 + 派工      ← 签字②
  → 角色交 rows + 一句判断
  → collect：行级校验 → raw.xlsx + metrics.json
  → R01 综合：theses（聚类/矛盾/排序）
  → R01 写作：SCQA + 五块 → 节=论点
  → 图表 owner：query(raw) → encoding → charts_pro
  → 装配 report.html
  → R04 三层校验 + 双签复核 → manifest
```

**两回流**：数据回流（冲突/缺口 → R02 路由）、论点回流（支撑不足 → 补行）。

## 2.5 第一性原理：分析的单位是「面板」，不是「事实点」

**分析 = 面板上的运算。** 没有面板，只有观点；
8 行数据能写备忘录，做不了分析，也画不出有信息量的图。

### 2.5.1 面板的规模公式

```
行数 N = 实体数 E × 维度组合 D × 期次数 T × 指标数 M
```

| 场景 | 面板 | 行数量级 |
|---|---|---|
| 北京机会（分区×品类×年） | 16 区 × 8 品类 × 3 年 | **384** |
| 城市对比（城×品类×月） | 4 城 × 5 品类 × 12 月 | **240** |
| 品牌竞争（品牌×渠道×年） | 10 品牌 × 5 渠道 × 3 年 | **150** |
| 单店模型（形态×成本项×城） | 3 形态 × 8 成本项 × 4 城 | **96** |
| 门店动销（门店×SKU×周） | 20 店 × 30 SKU × 12 周 | **7200**（一手） |

**目标不是"每个角色交几行"，而是"这个领域的面板要有多少行"。**

### 2.5.2 面板从哪来（四条路，按成本排序）

| 路 | 来源 | 成本 | 标记 |
|---|---|---|---|
| A 公开结构化 | 统计年鉴（分区/分行业）、海关、协会榜单、上市公司分区域收入、招股书 | 低 | `source` |
| B 平台/付费 | 生意参谋、久谦、魔镜、飞瓜、美团 | 中 | `source` |
| C 一手 | POS、门店走访、经销商访谈、问卷 | 高 | `primary` |
| D 推演 | 总量 × 结构拆分（如"北京宠物消费 = 278 万只 × 单只年消费"） | 最低 | **`estimated` + 公式 + 可回算** |

**D 不是造假**：它是统计上常用的合成估计，但必须满足三条——
1. 标 `estimated`，不得冒充实测；
2. 写清公式与输入行；
3. 能被新数据回算覆盖。

### 2.5.3 卡片按「面板切片」发

卡片不再说"找 3 个数"，而是"填这张面板的哪几行"：

```
## 你要填的面板切片
panel: 北京分区×品类零售（目标 384 行）
你的切片：16 区 × 3 品类 × 2023–2025 = 144 行
可用来源：统计年鉴分区表 / 平台区域报表
交不满：标 unavailable + 已试来源；缺口走 R02 路由
```

### 2.5.4 图与分析对面板的要求

| 要做的事 | 面板最低要求 |
|---|---|
| 排序（谁高谁低） | 同一 metric ≥10 个实体 |
| 趋势（涨跌） | 同一 metric ≥12 期（月度）或 ≥3 年 |
| 热力图（城×品类） | 矩阵 ≥8×5 |
| 构成（占比） | ≥6 个部分，加总 88–112% |
| 相关/散点 | ≥30 个观测 |
| 异常/分布 | ≥50 个观测 |

**面板不够，就换分析问题或补面板，不是硬画。**

### 2.5.5 三层（术语从"规格"升级为"面板"）

```
L0 面板定义（Panel Spec）  E × D × T × M 的矩阵 + 来源计划
L1 面板采集（Acquire）     角色/爬取/导出/推演，按切片填
L2 面板整备（Raw）         归一/去重/冲突/覆盖（core/data_model.py 已实现）
```

### 2.5.6 验收（面板级，不是角色级）

| 指标 | 目标 |
|---|---|
| 面板行数 / 目标行数 | ≥80% |
| 维度覆盖 | 每个维度 ≥2 个值（矩阵类 ≥5） |
| 时间跨度 | ≥3 年或 ≥12 个月 |
| 缺失率 | ≤20% |
| estimated 占比 | ≤30%，且全部可回算 |
| 每图数据点 | ≥ 该图型最低要求 |

**一句话**：先有面板，再谈分析；面板不够，报告只能写观点，不能写结论。

## 3. 系统接入（代码级）

| 现有 | 改动 | 新接口 | 兼容 |
|---|---|---|---|
| `report clarify` | 加 `intake` 12 问、`brief` 生成与签字 | `clarify.json.intake`、`brief.json.signed` | 旧 clarify 仍可读，缺 intake 标 `legacy` |
| `report_dispatch.write_plan` | 加 DoR 9 项校验与评分 | `plan.json.cards[].dor` | 未过 DoR 的卡不写 |
| `report_dispatch.issue` | 卡片正文改为"行清单+判断+红队" | `cards/*/TASK.md` v5 | 旧卡模板保留开关 |
| `dispatch.collect` | 行级校验 + data_model（已接） | `raw.xlsx`、`metrics.json` | 无 rows 的旧卡走 legacy 路径 |
| `core/claims_v4` | 保留，作为"旧稿→节"的适配器 | — | 新路径不再用 |
| **新增 `core/theses.py`** | 从 raw 聚类/矛盾/排序 | `theses.json/md` | — |
| **新增 `core/writer.py`** | theses → SCQA+五块正文 | `sections[]` | 旧 sections 路径保留 |
| **新增 `core/query.py`** | raw 查询 → encoding → chart spec | `chart` | 旧"从段落反推"关闭 |
| `report_flow.build_sections_contract` | 优先读 theses/writer | — | legacy draft 仍可渲染 |
| `manifest` | 加双签、DoR、raw 覆盖、论点覆盖 | `manifest.signatures` | 旧 manifest 字段不删 |

**接入原则**：
1. **新路径默认开、旧路径可回退**（`GUAGUA_LEGACY_PROSE=1`）；
2. 所有新产物**追加**，不覆盖旧字段；
3. 任一阶段失败 → 停在原地，不半写。

### 4.1 RACI（升级后）

| 环节 | R | A | C | I | 产物 |
|---|---|---|---|---|---|
| 接活 | R01 | 用户 | R05/R06 | R02 | `intake.json`、`brief.md` |
| 拆卡 | R01 | R01 | R02 | R04 | `issue_tree`、`grid` |

| 论点 | R01 | R01 | R02/R04 | 全体 | `theses.md` |
| 写作 | R01 | R01 | R11（文风） | R04 | `sections` |
| 图表 | R06/R09 | R01 | 数据角色 | R04 | `charts` |
| 验收 | R04 | R04 | R01/R02 | 全体 | `manifest` |

### 4.2 双签（进 manifest，不可绕过）

```yaml
signatures:
  brief: {by: 用户, at: 2026-11-22T10:00, sha: <brief sha>}
  ready: {by: r02, at: 2026-11-22T11:00, sha: <plan sha>}
```

- brief 未签 → `clarify` 状态 `awaiting_user`，拆卡命令直接拒绝；
- 就绪未签 → `issue` 拒绝发卡；
- R04 抽查 20%，发现越权 → 整批退回。

### 4.3 异常路径

| 异常 | 处理 | 记录 |
|---|---|---|
| 用户不签 brief / 改主意 | 回 intake，最多 3 轮 | `brief.revisions` |
| DoR 不达标 | 退回 R01 重拆，附缺项 | `plan.rejected[]` |
| metric 未注册 | 转 R18 评审，占位 `pending` | `metrics.pending[]` |
| 冲突 | R02 路由 → owner 裁决 | `conflicts[]` |
| 论点支撑 <3 行 | 退回补行 | `theses.backfill[]` |
| 角色交不了 | 请求路由（接棒/采购/一手/缩范围） | `requests[]` |

## 5. 旧产线处理（术语修正）

### 5.0 先纠正一个错词：没有"第二条产线"可下沉

当前系统**只有一条渲染线：flow**（`report run-line` / `report flow`）。
`paper` 文档线已在 2026-11-21 删除（`core/report_renderer.py` 里直接 raise）。
所以**不存在"把另一条线沉掉、保 flow"这回事**——flow 是升级对象，不是被保对象。

我之前说的"旧产线下沉"，准确说是三件不同的事：

| 名字 | 是什么 | 处理 |
|---|---|---|
| **flow 线** | 唯一的渲染产线（Paper 已删） | **升级，不下沉** |
| **flow 内的旧契约** | 段落优先：claims→sections、图从段落反推、按问题分节、r02/r04 进执行池 | **退役**（M4–M6） |
| **两个兼容开关** | `dispatch_mode=legacy`（无 nonce 的旧卡）、`chart_engine=legacy`（未覆盖图型的回退） | 前者退役；后者保留为回退并计量 |

另外，`decision_report`（数据线）不是第二条渲染线，它是 flow 的另一种输入；它也要迁到同一套契约，不需要单独"下沉"。

### 5.1 双轨运行（M0–M5）

- flow 上新契约默认开；
- flow 内旧契约保留开关 `GUAGUA_LEGACY_PROSE=1`；
- 每批同时记录两套 manifest，便于对比。

### 5.2 迁移器（M6）

| 旧产物 | 迁移到 | 规则 |
|---|---|---|
| `claims_merged.sections` | `theses` | 每节 → 1 个 thesis；support_rows 取 refs；warrant 取机理段；rebuttal 取反例段 |
| 旧图（chart） | `query(raw)` 重建 | 若旧图数据点能在 raw 找到，保留；否则重算并标 `regenerated` |
| `evidence_pack` | `raw.xlsx` | 走 data_model 归一，冲突显式 |
| `manifest` | 新 manifest | 旧字段保留，新增双签/覆盖字段 |

### 5.3 退役与删除时间表（只删旧契约，不删 flow）

| 阶段 | 退役什么 | 删除条件 |
|---|---|---|
| M4 | 关闭"从段落反推图" | 新路径图覆盖率 ≥95% |
| M5 | 关闭旧卡模板（无 nonce 的 legacy dispatch） | DoR 就绪率 100% |
| M5 | r02/r04 移出执行池 | 新卡不再给调度/验收发执行卡 |
| M6 | 删除 `GUAGUA_LEGACY_PROSE` 路径代码 | flow 上连续 5 份新契约报告过门禁 + 迁移误差 <5% |
| 长期 | `chart_engine=legacy` | **不删**：作为未覆盖图型的回退，持续计量，目标占比 <10% |

**一句话**：升级 flow 本身，退役 flow 里的旧契约，最后删旧契约代码；flow 这条线不动。

### 5.4 回滚

- 任一阶段异常 → 关新开关（`GUAGUA_LEGACY_PROSE=1`），旧契约继续出报告；
- 数据层失败 → 报告标 `raw_missing`，不阻断 flow 渲染；
- 图表层失败 → 退回旧图，manifest 标 `chart_fallback`。

## 6. 分阶段计划

| 阶段 | 改动 | 产物 | 验收 | 回滚 |
|---|---|---|---|---|
| **M0 准备** | freeze、开关、metric registry 初版 | `metrics.json`、开关 | 旧报告仍能跑 | 无需 |
| **M1 接活** | 12 问 + brief + 签字 | `intake.json`、`brief.md`、`signatures.brief` | 有效回答 ≥10；未签不可拆 | 关 `intake` 开关 |
| **M2 派工** | DoR 9 项 + 评分 + 新卡模板 | `plan.json`、`cards/*` | 发卡均分 ≥16；DoR 全过 | 用旧卡模板 |
| **M3 交行** | rows schema + collect 行级校验 | `rows.json`、`raw.xlsx` | 行可溯源 100%；未注册拒收 | legacy claims |
| **M4 论点+写作** | theses + SCQA writer | `theses.md`、`sections` | must Q 覆盖 100%；五块齐 | 旧 sections |
| **M5 图表** | query(raw) + encoding；关段落反推 | `charts` | 图覆盖 100%；数据点=行数 | 旧图回退 |
| **M6 迁移收口** | 迁移器、对比、弃用清理 | 对比报告、清理 PR | 连续 5 份过门禁；误差 <5% | 保留 legacy 一版 |

**依赖**：M1→M2→M3 串行；M4 依赖 M3；M5 依赖 M3；M6 依赖 M5。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 12 问让用户不耐烦 | 允许"快速模式"：先答 6 问，其余边做边补，但需签字 |
| DoR 太严导致发不出卡 | 先做 3 份试点，按缺项调阈值 |
| 写作层又变成"模板填空" | SCQA 结构校验 + R04 抽查论证链 |
| 迁移误差 | 保留旧稿对照，差异 >5% 不删旧路径 |
| 图表重算与旧图不一致 | 标 `regenerated` 并保留旧图一版 |
