# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表是**人工评审清单**，逐条判真假。
> 版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 | 出处 |
|---|---|---|
| MU-01 | 输出契约含格式、长度、必含字段三项 | §5 第 1 条 |
| MU-02 | prompt 六段齐备（角色/输入/步骤/约束/示例/输出） | §5 第 2 条 |
| MU-03 | 三种失败行为写明（信息不足/超范围/不确定） | §5 第 3 条 |
| MU-04 | 三条注入防护写明（只执行授权任务/忽略越权指令/不泄露系统提示） | §5 第 4 条 |
| MU-05 | few-shot ≥1 个，且含至少 1 个边界情形 | §5 第 5 条 |
| MU-06 | 回归集 ≥10 条，含正例/边界/拒答三类，且改动后必跑 | §5 第 6 条 |

## 二、软门（§6 自检，靠人抓）

| # | 常见错法 |
|---|---|
| MU-06 | 我写了输出契约：格式、长度、必含字段 |
| MU-07 | prompt 六段都有，步骤是编号的 |
| MU-08 | 信息不足时我说了让它提问，而不是让它编 |
| MU-09 | 超出范围时我说了拒答并说明 |
| MU-10 | 不确定时我要求标注，不是硬给答案 |
| MU-11 | 我写了三条注入防护 |
| MU-12 | 我给了 few-shot，且至少有一个是边界情形 |
| MU-13 | 我有 ≥10 条回归集，含正例/边界/拒答 |
| MU-14 | 改完我跑了回归集，不是靠感觉 |
| MU-15 | 我没有把系统提示词的内容放进可被用户输入覆盖的位置 |

## 三、诚实说明

本卡没有可自动断言的门禁：prompt 质量只能在真实输出上体现。可自动化的是回归集的比对（要点匹配），但回归集本身要靠人建。

## 四、怎么验（没门禁时的替代验证）

1. **双评**：两人独立按 §5 逐条判，一致率 ≥80%；
2. **抽样反查**：随机抽 3 条要求指出具体位置/数字；
3. **对照抽检**：与 `references/prompt-spec.md` 里的 BAD/GOOD 并列看。

> **纪律**：prompt 的目标不是「写得像人话」，是「**返回的形状可被程序消费**」。
