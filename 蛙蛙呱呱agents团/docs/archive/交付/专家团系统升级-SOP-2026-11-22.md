# 专家团系统升级 SOP（v2）

> 2026-11-22 · 目标：把"20 个角色答 10 个问题、拼成一份报告"升级为
> **"一份原始数据 + 一组论点 + 一组图表"** 的专家团工作制。
> 本 SOP 管系统，不管某一份报告。

---

## 0. 诊断：三个断点

| 断点 | 现象 | 证据（宠物报告） |
|---|---|---|
| **没有原始数据层** | 476 条数字散落在 claims 里，48 种单位、自由文本指标名、19 组重名 | `raw` 不存在，图只能从段落里反推 |
| **没有综合层** | 14 节 = 14 个问题的答案，没有跨题聚类/矛盾/排序 | 报告是"答问拼接"，不是"想完再写" |
| **没有共享契约** | 5 个角色各起各的指标名；图由渲染层猜 | 同一指标在 r03/r05/r06 各写一遍 |

**结论**：不是排版问题、不是字数问题，是**缺三层地基**。

## 1. 参考项目（高星、可借机制）

| 项目 | 机制 | 借什么 |

## 2. 目标架构：五层 + 两个契约

```
L1 行（Row）        角色只交这一种东西
L2 raw.csv/xlsx     归一、去重、冲突、溯源
L3 度量注册表        metric_id 唯一定义
L4 论点（Theses）    跨题聚类、矛盾、排序
L5 图表             单一 owner，query(raw) → encoding → chart
   报告             章节 = 论点，不 = 问题
```

### 2.1 行契约（角色交付物）

| 字段 | 必填 | 说明 |
|---|---|---|
| `role` / `question_id` | ✅ | 谁、回答哪一问 |
| `metric_id` | ✅ | 必须在注册表里；新指标走"提案-评审" |
| `entity_type` / `entity` | ✅ | 城市/品牌/品类/渠道/门店 |
| `value` / `unit` | ✅ | 数值 + 单位（原样），归一在 L2 做 |
| `period` | ✅ | YYYY / YYYY-MM / 区间 |
| `scope` | ✅ | 限额以上/平台/样本 |
| `source_id` / `locator` | ✅ | 来源 + 页码/锚点 |
| `method` | ⬜ | 实测/推算/访谈 |
| `confidence` | ⬜ | A/B/C |

**一句判断**（≤80 字）+ 行，是角色的全部交付。**不写段落、不画图。**

### 2.2 度量注册表（L3）

```yaml
metric_id: breakeven.monthly
name: 月盈亏平衡点
unit: 万元/月
grain: [store, month]
additivity: flow          # flow/stock/ratio/index
formula: fixed_cost / (gross_margin - variable_cost_rate)
non_additive_dimension: [month]
owner: r03
```

规则：**未注册的 metric_id 一律拒收**；同名不同义必须拆成两个 id。

### 2.3 raw 层（L2）

处理顺序：
1. 指标名 → `metric_id`（注册表匹配，匹配不上进"待评审"）；
2. 单位归一：存 `value_base + unit_base + display_unit`；
3. 实体抽取：城市/品牌/品类从名字里拆出来；
4. 去重：键 = `metric_id + entity + period + scope`；
5. 冲突：同键不同值 → `conflicts.csv`，标 grade 与来源；
6. 溯源：每行必须能回指 `source_id + locator`。

产物：`raw.csv`、`raw.xlsx`（raw / conflicts / coverage 三张表）、`metrics.json`。

### 2.4 论点层（L4）

输入：raw + 问题清单。
处理：
1. **跨题聚类**：同一驱动/实体/指标在多个问题里出现 → 一个论点；
2. **矛盾检测**：同 metric 不同方向/量级；
3. **排序**：决策影响 = 规模 × 效应量 × 可行动性；
4. **产出**：

```yaml
thesis:
  id: T1
  claim: "10 万预算只有社区自雇店能打平"
  support_rows: [R001, R004, R009]
  contradiction: "连锁品牌单店营收更高，但固定成本是 3 倍"
  decision: "先做自雇店；前置仓不进"
  evidence_gaps: ["缺 3 家门店实测"]
```

**报告章节 = 论点**；问题只用来校验覆盖（每个 must Q 至少被一个论点覆盖）。

### 2.5 图表层（L5）

- **单一 owner**（建议 r06 数据/图表），角色不交图；
- 图 = `query(raw, metric_id, entities, periods)` + encoding；
- 表 = `pivot(raw)`，与图同源；
- 验收：图的数据点数 = 查询返回行数。

## 3. 拆卡升级到"行业专家水准"

现在的卡只做到"问得全"，专家级要过**五道测试**：

| 测试 | 判据 | 反例 |
|---|---|---|
| **MECE** | 子问题互斥穷尽；构成类加总 100% | "市场怎么样" 拆成"规模+增速"漏了结构 |
| **可测** | 每个子问题能被 `metric_id + entity + period` 回答 | "品牌力如何" 无法落成一行 |
| **有反例** | 每条判断都有可观测的反例条件 | 只写"因为需求增长" |
| **可行动** | 结论能落到人/钱/时间 | "建议关注" |
| **决策相关** | 不知道这条会不会改变决策 | 收集了 476 个数，一半不改变结论 |

### 3.1 专家级拆卡流程

```
问题
 → 问题树（MECE，3 层以内）
 → 视角枚举（消费者/门店/经销商/竞品/监管/供应链）
 → 每视角生成子问题（STORM 式多视角提问）
 → 每个子问题绑定 metric_id + entity + period（可测测试）
 → 红队质询（另一角色问："不知道这条会怎样？"）
 → 通过五道测试才发卡
```

### 3.2 行业问题库（按业务线，可扩展）

以宠物用品为例：

| 视角 | 专家会问的 | 需要的行 |
|---|---|---|
| 消费者 | 单只年消费、品类偏好、复购周期 | `spend.per_pet`、`pref.category`、`repurchase.cycle` |
| 门店 | 单店月销、坪效、洗美占比 | `sales.per_store`、`sales.per_sqm`、`mix.grooming` |
| 经销商 | 库存周转、账期、退换货 | `inventory.weeks`、`dso.days`、`return.rate` |
| 竞品 | 份额、价格带、上新 | `share.brand`、`price.band`、`new_sku.count` |
| 监管 | 备案周期、宣称限制 | `reg.lead_time` |
| 供应链 | 到岸成本、时效 | `landed.cost`、`lead_time.days` |

**每新增一个业务线，先补这张问题库，再拆卡。**

### 3.3 专家级判据（发卡前自检）

- [ ] 每个子问题都有 `metric_id`（注册表里存在）
- [ ] 每个子问题有 entity 与 period
- [ ] 有反例条件
- [ ] 有"不知道会怎样"的回答（红队记录）
- [ ] 子问题之间不重复（MECE）
- [ ] 预计行数 ≥3（否则不足以成图）

## 4. 协作协议（角色之间怎么接）

| 规则 | 说明 |
|---|---|
| **一行一来源** | 没有 `source_id + locator` 的行不收 |
| **一个指标一个 id** | 未注册拒收；同名不同义拆 id |
| **冲突不静默** | 同键不同值进 conflicts，由 metric owner 裁决 |
| **角色不画图** | 图由 chart owner 统一出，避免 5 个人 5 种画法 |
| **交接看行** | 签收判据 = 行数/覆盖率/可溯源率，不看字数 |
| **综合归 R01** | 论点由 R01 汇总，角色不写"章节" |

---

## 5. 实施顺序（每阶段可验收）

| 阶段 | 交付 | 验收 |
|---|---|---|
| **P0** | `raw.csv/xlsx` + `metrics.json` | 行可溯源 100%；指标归并率 ≥80%；冲突显式 |
| **P1** | `theses.json` | 论点覆盖 must Q 100%；每论点 ≥3 行支撑 |
| **P2** | 图表由 raw 查询生成 | 图覆盖率 100%；图/表同源 |
| **P3** | 卡片 v5（交行 + 一句判断） | 每行进 raw；未注册指标拒收 |
| **P4** | 旧报告迁移对比 | 同数据：图覆盖↑、字数↓、论点可追溯 |

---

## 6. 验收指标（替代"字数/图数"）

| 指标 | 目标 |
|---|---|
| 行可溯源率 | 100% |
| 指标归并率（unique metric / 原始指标名） | ≥80% |
| 冲突显式率（有冲突必记录） | 100% |
| 图覆盖率（有图的节 / 总节） | 100% 或写明不可画 |
| 论点覆盖率（被论点覆盖的 must Q） | 100% |
| 支撑密度（每论点支撑行数） | ≥3 |
| 正文节数 | = 论点数（不再 = 问题数） |

---

## 7. 明确不做

1. 不再用字数验收（300/1000 都是拍脑袋）；
2. 不再让角色交"文章"或"图"；
3. 不再从段落里反推数字；
4. 不再按"问题数"决定节数。

---

## 8. 风险

| 风险 | 应对 |
|---|---|
| 指标注册表变成瓶颈 | 先允许"待评审"占位，但不得进图 |
| 角色嫌交行麻烦 | 模板 + 校验器；不合规直接拒收 |
| 综合层变成"再写一遍" | 论点必须有 support_rows，不能凭空写 |
| 旧报告迁移难看 | 迁移只做"保真"，不承诺好看；新报告走 v5 |
