02断点 A · 契约落地

目标：任何业务线，网格只能由语义层“算”出来，不能由模板“抄”出来；交付必须能被 join。

A1 · 网格改为 measure × grain 生成

现在的 grid 是模板复制。改成：以案例层 semantic_layer.yaml 为唯一输入，按下列规则生成候选格。

输入：semantic_layer.yaml
  entities:          region(levels) / category(levels) / brand / channel / gender / period / price_band
  grain_declarations: G_region_category_year / G_gender_category_year / G_channel_year / ...
  measures:          market_size / share / yoy / penetration / asp / gross_margin / unit_cost / ...

生成规则（顺序不可换：grain 先行）
  for m in measures:
      g = m.grain                              # 度量已声明自己的 grain
      assert g in grain_declarations
      for e in entities_of(g, question_scope): # 只用该 grain 维度上的实体
          cell = {qid, dim: dim_of(m, g), entity: e, measure_id: m.id,
                  grain_id: g, period, causal_level}
      # 比率类额外带 non_additive_dimension，禁止求和

禁止：
  × 从旧模板复制格（本项目的 18 个串场格就是这么来的）
  × 给度量换 grain（ad_cost 挂到“空间”维）
  × 实体不在 entities.levels 或本项目 clarify 白名单里

验收信号：重新生成的网格，measure_id 100% 命中语义层；ad_cost 类格子为 0；跨业务线实体为 0。

A2 · 收卡校验升级（core/cells_claims.py）

把“写了就行”改成“对得上才收”。每个交付格必须带齐下列字段，缺一退卡。

字段必填规则
measure_id必填∈ 语义层 measures[].id
grain_id必填∈ grain_declarations，且 等于该度量的声明 grain
caliber.denominator比率必填ratio 类无分母直接退卡
caliber.scope必填全渠道 / 线上 / 天猫平台 …
caliber.period必填与 period 一致，不一致以 caliber 为准并告警
caliber.currency必填CNY / USD；跨币种不得直接比
caliber.price_basis必填含税/不含税、零售价/出厂价/到岸价
quality 六维必填completeness / accuracy / consistency / timeliness / uniqueness / validity
status必填measured / estimated / projected / unavailable
tried + whyunavailable 必填缺口必须可解释，不许静默消失
同时清理：cells_claims.py:112-121 里写死的“毛绒与手办”“看头部 IP 集中度”等话术要删掉，改为从 plan.json 的问句与 semantic_layer 的度量名生成。通用模块不得含单条业务线的词。

A3 · 只有一张长表，角色只提交行

决策④定为单一表，取消“每角色一张表 / 一册多 sheet”两种形态。协同不靠事后 join，靠提交时就写进同一张表。

项规定
表全局唯一 l1_obs，唯一键 obs_id
角色交付按 l1_obs 的列交行片段（rows），系统 append，不新建表
禁止× 自建 r05_market.xlsx 之类独立表
× 一册多 sheet
× 列名自造或改名
冲突处理同一 obs_id 重复提交 → 拒收并指出与哪张卡冲突，不静默覆盖
 
角色提交格式（与 l1_obs 同列，只交自己负责的行）
{
  "role": "r05",
  "rows": [
    {"metric_id":"share", "entity_id":"杜蕾斯", "grain_id":"G_region_category_year",
     "period":"2026", "region_l1":"全国", "caliber_scope":"全渠道",
     "caliber_currency":"CNY", "caliber_price_basis":"零售价",
     "value":40, "unit":"%", "status":"measured",
     "source_id":"S02", "cell_id":"Q2.对象.杜蕾斯"}
  ]
}

为什么必须一张表：多表方案要靠 manifest 声明覆盖范围，再做事后 join；一旦某张表漏写 grain 或口径，join 静默丢行。单表把“对齐”从事后检查变成写入约束——写不进去就是没对齐。

03L1 长表 l1_obs · 字段定义

全局唯一一张表，一行一个观测。图、表、正文数字都从这里取。

L1-1 · 八条设计原则

  1. 只有一张表：l1_obs 是唯一数据层；角色交行，不建表、不分 sheet。
  2. 一行一观测：不要宽表，不要“一行一个实体多列指标”。
  3. 缺口也入表：status='unavailable'、value=NULL。缺口要能被统计，不能消失。
  4. 区间不取中值：用 value_low / value_high + point_type='range'，禁止把 0.42–3.18 写成 1.8。
  5. grain 不可混：不同 grain_id 不进同一张图、同一张表。
  6. 比率不可加：share/yoy/gross_margin 不得跨行求和，也不得直接平均。
  7. 口径五要素随行：每个观测自带分母/范围/期次/币种/价格基准。
  8. 血缘可追：每行能回到 card_role → cell_id → source_id → quote。

04断点 B · 编排层 edit()

回答问题是对的；缺的是拿到答案之后“决定这份报告主张什么”。

B1 · 现状 vs 目标

现在目标
做什么enrich()：补 verdict / kicker / rail / actionsedit()：选主张、消冲突、排顺序、砍重复

砍稿不砍砍，且留痕可审计

B2 · 四步编排

S1 抽候选主张

从每节的 verdict（第一条“结论”句）抽一条候选，记下它引用的 metric_id、source_grade、跨卡同向次数。

S2 冲突消解

同一 (metric_id, entity_id, period) 出现多个值，按 caliber_scope 分组：

  • 不同口径 → 并列保留，写成“口径 A 为 X，口径 B 为 Y”，不平均、不取中值
  • 同口径不同源 → 保留 grade 最高者，其余进 conflicts[]
  • 差值超过 20% 且无法解释 → 降级为“边界说明”，不进主判断

S3 选 ≤7 条主判断

可复算的四维打分，满分 10：

维度分值规则
决策相关性0–3直接回答“能不能做/做哪段/怎么赚/何时停”=3；支撑=2；背景=0
证据强度0–3A=3，B=2，C=1，D=0（取最低源级）
跨卡一致性0–2≥2 张卡同向=2；单卡=1；有冲突=0
可证伪性0–2有量化 falsifier=2；定性=1；无=0

额外硬约束：入选 7 条必须覆盖四个决策问题各至少 1 条；同 metric_id 最多 1 条主判断。
