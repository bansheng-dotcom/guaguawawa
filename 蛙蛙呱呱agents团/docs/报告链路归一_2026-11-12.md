## 一、问题定位（凭证据，不凭感觉）

下午 15:20 的内核 v1.1（`fb1f8d90`）加了三样东西：`report_specs/`（20 角色规格）、
`core/report_kernel/`、版式四规则 + `check_report_layout.py`。但当天以后新增的报告出口没有跟上：

| 现场 | 证据 | 后果 |
|---|---|---|
| 17 个角色走 `role_runtime.emit → shared/report_engine.py`（REP-001） | `grep -r "report_kernel" shared/` 无命中 | 内核的保真分数、版式四规则、spec 校验**对这些角色完全没生效** |
| r08 `htmlreport` 自带渲染器 + 自带六条规则 | `s09_htmlreport.py` 149 行内含 `_validate`/`_render` | 同一份报告「技能里一套尺子、内核里一套尺子」 |
| `scripts/contract_test.py` 里还有一份 `_layout_errors` | 与 REPORT-STANDARD 第四条规则重复描述 | 规则改一处、另一处不知道 |
| r05 `agent.py manifest` 直接崩 | `AttributeError: module 'skills.s09_matched' has no attribute 'ACTIONS'` | 该角色 manifest/注册不可用，2 个测试红 |

一句话：**新内核已经存在，但只接上了 r06 与项目产线；技能链路、角色产线、外部镜像都还停在旧接口上。**

## 四、修掉的 5 个真问题

1. **r05 manifest 崩溃**：`s09_matched.py` / `s10_tam_mc.py` 没有 `ACTIONS`，`make_manifest()` 直接 `AttributeError`。
2. **r05 `make_manifest` 重复赋值**：`skills = [...]` 写了两遍，第一遍是死代码（字段还不全），删掉。
3. **三套引擎**：内核 / REP-001 / r08 自绘 → 收敛为「内核优先 + REP-001 回落」，渲染器始终只有 `core/report_renderer.py` 一个。
4. **规则三份副本**：六条结构规则 2 份、版式四规则 2 份 → 各 1 份。
5. **嵌套子进程挂起**：内核路径原先用 `report_bridge.render_html`（子进程），在「pytest → agent.py → 渲染器」三层嵌套下 Windows 管道继承导致 r14 卡死 9 分钟。改为**进程内渲染**后 7 秒通过。
