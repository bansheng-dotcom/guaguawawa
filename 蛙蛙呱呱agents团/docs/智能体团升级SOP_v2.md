## 1. 六条原则（违反任一条，升级无效）

1. **咨询是流程，不是报告**：没有 8 阶段与门禁，写得再长也只是「报告工厂」。
2. **方法先于数据**：没有方法，接再多 MCP 也只是「更快的浅」。
3. **评测先于扩编**：不加角色，先把「答案质量」量出来。
4. **可证伪**：每条结论必须有「什么证据会推翻它」。
5. **证据分级**：A（官方/一手）/ B（行业/二手）/ C（估算），C 级必须做敏感性。
6. **不碰不可逆**：裁员/关停/签合同/动资金一律人工签字；MCP 写操作需审批。

## 3. 能力模型

```
L0 角色层（20 个，不动）
  └─ L1 方法层（method pack）        怎么想：决策问题/问题树/假设/证据/方法/输出契约
       └─ L2 咨询工作流（8 阶段）    怎么做：定义→MECE→聚焦→计划→分析→整合→建议→打包
            └─ L3 知识层（playbook）  知道什么：框架、行业基准、案例
                 └─ L4 数据层（MCP）  看到什么：行情/统计/财报/平台/专家/内部库
                      └─ L5 评估层    证明什么：金题、评分卡、judge、回归
                           └─ L6 记忆层 记住什么：客户上下文、假设、决策、复盘
```

### 咨询闭环（业务触达）

```
澄清六问 → 问题树（MECE） → 假设（可证伪） → 分析计划（分支×数据×方法）
 → 证据（A/B/C + 口径 + 冲突） → 综合（So what） → 建议（选项/取舍/风险）
 → 实施（90 天） → 价值追踪（基线/KPI） → 复盘（回写方法与技能）
```

|---|---|---|---|

| 1.5 | 回放：上次「133% 价差」应被拦下 | R04 | 回放记录 |

### 4.2 方法包六段（缺一不可）

1. 决策问题（决策者/成功标准/非目标）
2. 问题树（3—5 支 MECE + critical branch）
3. 假设与证伪（可测 + 杀死标准 + ≥2 竞争解释）
4. 证据分级（A/B/C + 缺口/冲突）
5. 方法与陷阱（3—5 默认方法 + 5 个行业陷阱）
6. 输出契约（claim/evidence/confidence/falsifier）

### 4.3 门禁

- 方法包 ≥80；R04 方法门禁生效；`guagua.py check` 20/20。

## 5. P1 · 评估层（第 2—4 周）

### 5.1 结构（照 Inspect AI 的 Task = Dataset + Solver + Scorer）

| 组件 | 我们的实现 | 文件 |
|---|---|---|
| Dataset | 20 道咨询金题（输入 + 必答要点 + 常见错误 + 金标准） | `evals/consulting/tasks.json` |
| Solver | 团队管道（澄清→问题树→分析→建议） | 未来 `scripts/run_consult_eval.py` |
| Scorer | 五维 rubric（0—25）+ LLM judge | `evals/consulting/rubric.md` |
| Logs | 每次运行的答案 + 分数 + 理由 | `workspace/evals/` |

### 5.2 步骤

| # | 动作 | 负责人 | 产物 |
|---|---|---|---|
| 1.1 | 20 题（已完成；覆盖市场/定价/单位经济/渠道/供应链/竞争/组织/现金/增长/产品/留存/风险） | R05+R06 | tasks.json |
| 1.2 | 每题写必答要点、常见错误、金标准（已完成） | 角色 owner | 同上 |
| 1.3 | 人工标 10 题（2 人独立，分歧 >3 分讨论） | R04+创始人 | 标注集 |
| 1.4 | 训 judge，算一致率（±1 分） | R06 | 一致率报告 |
| 1.5 | 回归：改方法/技能后跑 20 题，降 >2 分回滚 | R06 | 快照 |

### 5.3 评分卡

问题定义 / 证据质量 / 分析深度 / 洞察力 / 行动性，各 0—5；合格 18，咨询级 21。
一票否决：headline 无对照 → 分析深度 ≤2；建议无负责人/阈值 → 行动性 ≤2。

### 5.4 门禁

- judge 一致率 ≥0.7 才可用于回归；否则人工评。
- 对外交付先过同域题（≥18 分）。

## 6. P2 · 咨询工作流（第 4—7 周，本版核心）

### 6.1 8 阶段 × 角色 × 交付 × 门禁

| 阶段 | 主责 | 参与 | 交付 | 门禁 |
|---|---|---|---|---|
| 1 定义问题 | R01 | R05 | 问题定义（决策/成功标准/非目标） | partner 确认 |
| 2 逻辑地图 | R05 | R01/R06 | MECE 问题树 + 假设 | 分支无重叠/无遗漏；≥1 个 critical branch |
| 3 80/20 聚焦 | R01 | R05 | 聚焦计划（≤3 支 + 为什么不做其余） | 资源/时间确认 |
| 4 分析计划 | R05 | R06/R03 | 工作流 × 数据 × 方法 × 负责人 | 每支有降级方案 |
| 5 执行分析 | R06 | R03/R15 | 发现台账（四件套） | R04 方法核查 |
| 6 整合答案 | R05 | R01 | 1—3 条核心信息（answer-first） | 红队三问 |
| 7 形成建议 | R01 | R03/R02 | 3 选项 + 经济性 + 风险 + KPI | 经济性复核 + partner 签字 |
| 8 打包交付 | R05 | R04 | memo/deck + 附录 + 价值追踪 | R04 终审 |

### 6.2 每阶段双门禁（硬规则）

- **Input gate**：客户/上游提供背景、数据、约束；缺就停，不许猜。
- **Review gate**：partner（R01）或独立评审（R04）签字；不过门不进下一阶段。
- **YAML 可回溯**：建议 → 答案 → 发现 → 分析 → 分支 → 原始问题，六层链不断。

### 6.3 交付物标准（7 件套，缺一不算完成）

| # | 交付 | 标准 |
|---|---|---|
| 1 | 问题定义 | 一句话决策 + 成功标准 + 非目标 |
| 2 | 问题树 | MECE + 假设 + critical branch |
| 3 | 分析计划 | 数据源 + 方法 + 降级 + 负责人 |
| 4 | 发现台账 | 四件套 + 冲突单列 + 区间 |
| 5 | 建议书 | 3 选项 + 经济性 + 风险 + KPI + 回滚 |
| 6 | 执行摘要 | 结论先行，1 页 |
| 7 | 价值追踪 | 基线 + 目标 + 口径 + 复盘日 |

### 6.4 咨询项目工作簿

`templates/CONSULTING-ENGAGEMENT.template.md`：8 阶段勾选 + 双门禁 + 7 件套 + 复盘。
每个项目复制一份，落在 `projects/<engagement_id>/`。

### 6.5 质量机制

- **独立挑战评审**（R04）：storyline、证据、逻辑、建议各挑 3 个问题；
- **partner 挑战会**（R01）：红队三问「如果结论是错的，最可能因为什么」；
- **answer-first 检查**：一页纸先给答案，再看证据；
- **返工规则**：R04 FAIL → 回对应阶段，不许在最后一页打补丁。

## 7. P3 · 知识层（第 6—9 周）

### 7.1 三库一表

| 资产 | 内容 | 格式 |
|---|---|---|
| 框架库 | MECE / 问题树 / 3C / 五力 / 价值链 / 单位经济 / 80/20 / 金字塔原理 / 情景树 | `knowledge/frameworks/*.md` |
| 行业 playbook | 生鲜/快消/制造服务：关键指标、成本结构、常见打法、陷阱 | `knowledge/playbooks/*.md` |
| 基准比率库 | 毛利/费用率/周转/损耗/人效，每条带来源+年份+口径 | `knowledge/benchmarks.json` |
| 案例库 | 成功/失败各 10 个，含「当时判断错在哪」 | `knowledge/cases/*.md` |

### 7.2 规则

- 每条基准必须有来源、年份、口径；没有来源的进「待核实」区。
- 基准与本次数据冲突 → 单列冲突，不取平均。
- 渐进披露：角色按需加载，不整包塞 prompt。

| company-finance | 工商/财报/股权 | r03 | 竞品、客户、财务 |

| logistics-map | 地图/运价/路线 | r15 | 链路成本、时效 |
| internal-db | 内部订单/库存/客户 | r18 | 单位经济、留存 |
| knowledge-base | 知识库/文档 | r05 | 框架、案例、playbook |

> 后续可加咨询专用槽位：**expert-network（专家访谈）**、**survey（问卷）**、**crm（客户）**、**benchmark-db（基准库）**；先留位，等你说接。

### 8.2 接入一个 MCP 的 7 步

1. 选槽位（`mcp_doctor.py list`）；
2. 填 owner/consumers/scopes/data_class/fallback；
3. 填 `command`+`args` 或 `url`（Windows 的 npx 用 `cmd /c`）；
4. `enabled: true`；
5. `python scripts/mcp_doctor.py doctor` 握手 + 列工具；
6. 工具映射进能力卡（capability entry + 触发语 + owner）；
7. 在方法包登记「哪条结论必须用它 + 降级 + 审计」。

### 8.3 安全与降级（硬规则）

- 只读优先；写工具需人工审批；
- 密钥只放环境变量，不进 registry/git；
- 数据分级 public/internal/confidential/restricted，restricted 只允许聚合；
- 每次调用写 `workspace/mcp_calls.jsonl`；
- MCP 不可用 → 自动回 `fallback`，报告标注「降级数据」；
- 每角色最多 20 个工具。
