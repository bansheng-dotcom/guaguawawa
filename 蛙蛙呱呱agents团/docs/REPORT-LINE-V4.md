# 报告产线 v4：数据台 → 方法库 → 纲领 → 成稿

> 2026-11-15 升级。目标不是再写一个模板，而是把「以前那几份好报告是怎么分析出来的」
> 变成产线能重复执行的能力：**方法按数据结构选、判断按业务场景写、数字逐个可复算**。
>
> 与上一版（v3 `report_produce`）的关系：v3 解决「技能有没有真跑」，
> v4 解决「跑出来的东西会不会分析」。两者共用同一条渲染与过账链（`report_flow`）。

---

## 一、为什么上一版还是「模板」

`report_produce` 的章节计划写死在 profile 里：

```python
{"role": "r06", "skill": "describe", "input": "data/category_long2.csv", ...}
```

三个后果：

1. **换项目就跑不动**——文件名、列名、品类都是某个项目的；
2. **只有一阶描述**——「growth 均值 7.45%」是统计量，不是判断；
3. **没有业务动作**——说得出「均价 7.45%」，说不出「白条鸡该做利润品、鸡蛋只能做引流品」。

v4 把这三层断点分别补上：数据台（归一）、方法库（会算）、纲领（会选）。

## 二、四层结构

```
项目目录（csv/json）
   │
① core/analysis_desk.py      数据台
   │   识别时间轴/实体轴/数值列/单位，把每行摊成 Observation
   │   价格统一到「元/斤」（元/公斤 ÷2），否则批零不可比
   │   Desk 同时是证据索引：每个数字有 id、期、来源文件
   │
② core/analysis_methods.py   方法库（12 个方法，命中即产出）
   │   structure / momentum / trajectory / contribution / economics
   │   transmission / arbitrage / breakeven / sensitivity / risk / sample / ledger
   │   每条产出 Finding：标题带数、解读带 refs、边界、so_what、动作
   │   统计与成本类步骤真调角色技能（r06 / r19 / r15），失败只降级
   │
③ core/report_thesis.py      纲领（research / operations / remediation / chain / forecast）
   │   同一批 finding，按「这份报告要回答什么」重排、重写开篇与结论
   │   缺的节记缺口，不补形容词
   │
④ core/report_compose.py     成稿
   │   装配章节 → 写 evidence_pack + draft_sections
   │   交给 report_flow 逐节过账（数字必须由 refs 解释）→ 唯一渲染器
   │   R04 物料清点 → analysis_trace.json（技能/覆盖/缺口/门禁）
```

**一条命令：**

```bash
python guagua.py report produce \
  --intent "内蒙古肉禽蛋市场调研" \
  --dir 内蒙古肉禽蛋调研_2026-11-12 \
  --out workspace/reports/meat_v4_research
```

`--profile market_research` 仍然可用（走 v3 老画像）；不传 profile 时按 `--intent` 自动选纲领，
也可以用 `--thesis research|operations|remediation|chain|forecast` 强制。

## 三、方法库：每个方法解决一个「分析的断点」

| 方法 | 回答的问题 | 关键计算 | 典型二阶判断 |
|---|---|---|---|
| structure | 品类之间怎么分化 | 首末变化率、均值/中位/标准差 | 均值被深跌品类拖低，中位数才是体感 |
| momentum | 环比与同比矛盾时信谁 | 环比×同比四象限 | 高位回落 ≠ 需求转弱，只做周度随行 |
| trajectory | 是趋势还是噪声 | 首末、CV、最大回撤、引擎复核 | 4 期不足 6 期，引擎拒出斜率，报告不补 |
| contribution | 净差小是不是没变化 | 涨端/跌端毛变动 | 净 −0.39 元背后是 ±1 元级换手 |
| economics | 批零差扣完成本还剩多少 | 零售×(1−损耗)−批发−冷链 | 白条鸡 22.4%，牛肉 −0.48%，鸡蛋 −1.68% |
| transmission | 利润被哪一段吃掉 | 产地→批发→零售三段价差 | 白条鸡产地 8.90 > 批发 8.50，倒挂必须关 |
| arbitrage | 跨市价差扣运费还剩多少 | 卖出价×(1−损耗)−买入−运费−冷链 | 鸡蛋 −8.44%，禁止跨市调运 |
| breakeven | 提价还是降本 | 保本零售价、保本直采占比 | 牛肉提 0.5% 即可，鸡蛋要提 1.69% |
| sensitivity | 哪个假设最敏感 | 零售/损耗/冷链三档情景 | 冷链 +20% 影响小于零售 −10% |
| risk | 哪些结论现在不能用 | 期数、CV、回撤、基准价覆盖 | 7 个品类都不足 8 期，趋势不外推 |
| sample | 这点差异判得动吗 | Wilson 区间 + 每组所需样本 | 方向可以说，显著性不能说 |
| ledger | 结论能不能回源 | r05 台账：claim→source | 覆盖率 100% 才允许发布 |

**口径纪律（写进代码）：**

- 活畜价（活牛/育肥牛/羔羊）不参与「产地→批发」价差：与白条不是同一交易环节，
  牛羊因此不进传导表，并在边界里说明「不是漏算，是不可比」；
- 平台价（元/公斤）与门店价（元/500克）先归一到元/斤再比；
- 损耗率与冷链成本是**声明的假设**（牛羊 1.5%/0.90、禽 2%/0.55、蛋 1%/0.25），
  写进该节 `assumptions`，不冒充台账；
- 技能拒绝（样本不足、口径不合）照原话写进报告，不自己补一个斜率。

## 四、和「以前好的」是什么关系

| 以前的资产 | 学到的部分 | 没有照搬的部分 |
|---|---|---|
| `deep_analysis` 七步链（质量/趋势/时序/分解/帕累托/分布/显著性） | 「每步都留下可复算数字 + 单步失败只降级」的链路纪律 | 它只吃单列 CSV、不认价格与单位；v4 用数据台统一口径 |
| `report_specs/` 规格层（archetype/frame/writing） | 「一类报告 = 一组问题」的抽象 | 规格层按角色写死，v4 按数据能力选题（有批发价才做经营） |
| `report_engine` / `report_generator` 的版式能力 | 结论先行、指标带、边界声明的版式 | 旧引擎的「杜邦分解/内生失衡」是套话，v4 只写算得出来的 |
| 家居百货 v2 手写稿（模型写、逐节过账） | 「模型写稿 + 规则过账」的质量上限 | 不再是人工一次性稿件，方法库自动产出初稿 |

一句话：**旧资产提供「分析链纪律 + 版式 + 过账」，v4 提供「可移植的口径与判断规则」。**

## 五、门禁与验收

```bash
python guagua.py report produce --intent "…" --dir <项目> --out <目录>

```

`analysis_trace.json` 记录：纲领、命中/缺失的方法、每次技能调用的角色与动作、
覆盖的技能数/角色数、数字条数与派生量、R04 物料清点结果。
**技能覆盖低于 6 个或角色低于 4 个，本报告视为未完成。**

## 六、当前边界（先说清，避免误读）

1. **没有销量/金额权重**：贡献度只能按价格拆，不能按金额拆；报告里写缺口，不虚构权重。
2. **没有企业台账**：损耗率、冷链成本是品类经验值，不是这家企业的实际费用。
3. **序列太短**：肉禽蛋只有 4 个采价期，r06 引擎拒绝出斜率，报告只报首末变化。
4. **营销方案不在本版**：人群、渠道、内容数据不在项目目录里，硬写就是编；
   营销类需要 r11/r12 的渠道与人群输入，另开数据接口后可复用同一套方法库。
5. **PDF 依赖本机 Chrome**：本轮渲染器返回 `failed`，交付以单文件 HTML（含打印样式）为准。
