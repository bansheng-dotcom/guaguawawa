# 智能体团升级 SOP v1.0

> 适用：`D:\蛙蛙呱呱\蛙蛙呱呱agents团`（20 角色 / 81 能力 / 19 门禁）
> 目标：把团队从「会写报告」升级为「会做咨询」——**更广、更深、更专业**，并为 MCP 数据接入预留标准接口。
> 原则：**先方法、再评测、后数据；不换框架、不加角色、不重写引擎。**

---

## 0. 一页总览

| 阶段 | 周期 | 核心动作 | 硬验收 |
|---|---|---|---|
| **P0 方法层** | 2 周 | 6 个 P0 角色写方法包；R04 加「方法门禁」 | 方法包 ≥80 分；能拦下「无对照/无基线」的 headline |
| **P1 评估层** | 2 周 | 20 题金题集 + 五维评分卡 + 人工校准 judge | judge 与人工一致率 ≥0.7；基线分 vs 升级分 |
| **P2 知识层** | 3 周 | 3 个行业 playbook + 基准比率库 + 案例库 | 每个 playbook ≥10 条可引用基准 |
| **P3 数据/MCP 层** | 3 周 | 8 个 MCP 槽位；按需接入 1—3 个；降级路径 | `mcp_doctor doctor` 全绿；审计日志可查 |
| **P4 业务触达** | 3 周 | 咨询闭环 + 交付模板 + 1 个真实试点 | 试点交付 5 件套；客户评分 ≥4/5 |

**总周期 12 周，可并行；每周五出「升级周报」一页（做了什么 / 卡在哪 / 下周）。**

---

## 1. 五条原则（违反任一条，升级无效）

1. **方法先于数据**：没有方法，接再多 MCP 也只是「更快的浅」。
2. **评测先于扩编**：不增加角色，先把「答案质量」量出来。
3. **可证伪**：每条结论必须有「什么证据会推翻它」。
4. **证据分级**：A（官方/一手）/ B（行业/二手）/ C（估算），C 级必须做敏感性。
5. **不碰不可逆**：裁员/关停/签合同/动资金，一律人工签字；MCP 写操作需审批。

## 3. 目标能力模型

```
L0 角色层（20 个，不动）
  └─ L1 方法层（method pack）      怎么想：决策问题/问题树/假设/证据/方法/输出契约
       └─ L2 知识层（playbook）    知道什么：行业基准、框架、案例
            └─ L3 数据层（MCP）    看到什么：行情/统计/财报/平台/地图/内部库
                 └─ L4 评估层      证明什么：金题、评分卡、judge、回归
                      └─ L5 记忆层 记住什么：客户上下文、假设、决策、复盘
```

### 咨询闭环（业务触达的标准动作）

```
澄清六问 → 问题树（MECE） → 假设（可证伪） → 分析计划（分支×数据×方法）
 → 证据（A/B/C + 口径 + 冲突） → 综合（So what） → 建议（选项/取舍/风险）
 → 实施（90 天） → 价值追踪（基线/KPI） → 复盘（回写方法与技能）
```

每个箭头必须有产物与门禁；没有产物的箭头 = 没发生。

## 4. P0 · 方法层（第 1—2 周）

### 4.1 步骤

| # | 动作 | 负责人 | 产物 |
|---|---|---|---|
| 1.1 | 复制 `templates/METHOD-PACK.template.md` 到 `rXX/references/method-pack.md` | 角色 owner | 6 段方法包 |
| 1.2 | 按角色写「决策问题 + 问题树（表）+ 假设与证伪 + 证据分级 + 方法与陷阱 + 输出契约」 | 角色 owner | 同上 |
| 1.3 | 跑 `python scripts/audit_method.py rXX`，<80 退回重写 | R04 | 审计分 |
| 1.4 | R04 加「方法门禁」：headline 无对照/基线/匹配 → FAIL | R04 | 门禁规则 |
| 1.5 | 用上次水果报告做回放：133% 价差那条应被拦下 | R04 | 回放记录 |

### 4.2 方法包六段（缺一不可）

1. **决策问题**：支持哪个决策、决策者是谁、成功标准、不回答什么。
2. **问题树**：3—5 支 MECE，每支写「问题→数据→方法→证据」，标 critical branch。
3. **假设与证伪**：可测假设 + 支持/反对证据 + 杀死标准 + ≥2 个竞争解释。
4. **证据分级**：A/B/C 定义、允许用法、缺口与冲突处理。
5. **方法与陷阱**：3—5 个默认方法（适用条件/最小样本/输出）+ 5 个行业陷阱。
6. **输出契约**：claim / evidence / confidence / falsifier 四件套。

### 4.3 门禁

- `audit_method.py rXX` ≥ 80（P0 六角色当前：100/95/90/86/84/83）。
- R04 方法门禁：无对照/基线/匹配 → FAIL；无区间 → 标「点估计，未验证」。
- 回归：`python guagua.py check` 20/20。

## 5. P1 · 评估层（第 2—4 周）

### 5.1 步骤

| # | 动作 | 负责人 | 产物 |
|---|---|---|---|
| 1.1 | 金题从 12 题扩到 20 题（覆盖市场/定价/单位经济/渠道/供应链/竞争/组织/现金/增长/产品/留存/风险） | R05 + R06 | `evals/consulting/tasks.json` |
| 1.2 | 每题写「必答要点 + 常见错误 + 金标准要点」 | 角色 owner | 同上 |
| 1.3 | 人工标 10 题（2 人独立，分歧 >3 分讨论） | R04 + 创始人 | 标注集 |
| 1.4 | 用 `rubric.md` 训 LLM judge，算一致率（±1 分） | R06 | 一致率报告 |
| 1.5 | 每次改方法包/skill 跑 20 题，分数降 >2 分回滚 | R06 | 回归快照 |

### 5.2 评分卡（0—25）

问题定义 / 证据质量 / 分析深度 / 洞察力 / 行动性，各 0—5。
合格 18，咨询级 21；一票否决：headline 无对照 → 分析深度 ≤2；建议无负责人/阈值 → 行动性 ≤2。

### 5.3 门禁

- judge 一致率 ≥0.7 才可用于回归；否则只做人工评。
- 每份对外交付必须先过 20 题中的同域题（≥18 分）。

## 6. P2 · 知识层（第 4—7 周）

### 6.1 步骤

| # | 动作 | 产物 |
|---|---|---|
| 1.1 | 选 3 个行业（生鲜/快消/制造服务），每个写 1 份 playbook | `knowledge/playbooks/*.md` |
| 1.2 | 建基准比率库：毛利/费用率/周转/损耗/人效，每条带来源与年份 | `knowledge/benchmarks.json` |
| 1.3 | 建案例库：成功/失败各 10 个，含「当时判断错在哪」 | `knowledge/cases/*.md` |
| 1.4 | 接入渐进披露：角色按需加载，不整包塞 prompt | `shared/knowledge_base.py` 改造 |

### 6.2 门禁

- 每个 playbook ≥10 条可引用基准，且每条有来源与年份。
- 基准与本次数据冲突时，必须在报告里单列冲突，不许取平均。

## 7. P3 · 数据与 MCP 层（第 6—9 周）

### 7.1 已预留的 8 个槽位

`shared/mcp/registry.json`：market-price / gov-stats / company-finance / ecommerce / search / logistics-map / internal-db / knowledge-base。
全部 `enabled=false`，每个都写了 owner_role、consumers、scopes、data_class、fallback。

### 7.2 接入一个 MCP 的 7 步（你指定后按这个走）

| # | 动作 | 命令/产物 |
|---|---|---|
| 1 | 选槽位 | `python scripts/mcp_doctor.py list` |
| 2 | 填 owner / consumers / scopes / data_class / fallback | 编辑 `registry.json` |
| 3 | 填连接：stdio 用 `command`+`args`；HTTP 用 `url`（Windows 的 npx 用 `cmd /c`） | 同上 |
| 4 | 启用 | `enabled: true` |
| 5 | 体检：握手 → tools/list | `python scripts/mcp_doctor.py doctor` |
| 6 | 把 tools 映射进能力卡（capability entry + 触发语 + 负责人） | `shared/capabilities/catalog.json` |
| 7 | 在方法包登记「哪条结论必须用它 + 降级路径 + 审计日志」 | 角色 `method-pack.md` |

### 7.3 安全与降级（硬规则）

- **只读优先**：写工具（下单/改价/发消息）必须人工审批，默认不启用。
- **密钥**：只放环境变量，不写 registry、不进 git。
- **数据分级**：public / internal / confidential / restricted；restricted 只允许聚合查询。
- **审计**：每次调用写 `workspace/mcp_calls.jsonl`（时间/角色/工具/参数哈希/结果状态）。
- **降级**：MCP 不可用 → 自动回落到 `fallback`（现有采集脚本/人工录入），并在报告里标注「本段用了降级数据」。
- **上限**：每个角色最多 20 个工具，超出必须裁剪。

### 7.4 门禁

- `mcp_doctor doctor` 全绿；新增槽位必须有 fallback。
- 任一结论引用 MCP 数据，必须带「来源 + 拉取时间 + 工具名」。

## 8. P4 · 业务触达（第 9—12 周）

### 8.1 咨询交付五件套

| 交付 | 内容 | 负责人 |
|---|---|---|
| 诊断备忘（2 页） | 问题、证据、初步判断、下一步 | R05 + R01 |
| 问题树与分析计划 | MECE 分支、数据、方法、时间 | R01 + R06 |
| 分析报告 | 结论四件套 + 附录全量 | R06 |
| 建议与路线（90 天） | 选项、取舍、风险、负责人、阈值 | R01 + R02 |
| 价值追踪表 | 基线、目标、口径、复盘日 | R03 |

### 8.2 试点要求

- 1 个真实客户/业务，4 周内跑完闭环；
- 交付五件套齐全；
- 复盘产出 ≥3 条方法修订（回写 method pack）；
- 客户评分 ≥4/5（五个维度：问题理解、证据、洞察、可执行、沟通）。

## 11. 风险与回滚

| 风险 | 触发 | 回滚 |
|---|---|---|
| 方法包写成八股 | audit 高分但评测不涨 | 以评测分为准，方法包降级重写 |
| judge 不可信 | 与人工一致率 <0.7 | 停用 judge，改人工标注 |
| MCP 数据污染 | 口径冲突/延迟 | 关 enabled，回 fallback，报告标注 |
| 评测题泄漏 | 分数虚高 | 每季度换 30% 题目 |
| 升级拖期 | 单阶段超 1.5 倍 | 砍范围：先保 P0/P1，P2 延后 |
