## 1. 默认是什么

**flow 一条流**：封面 → 摘要 → 目录 → 正文连续 → 动作 → 附录 → 尾页；PDF 自动分页 + 后置页码。
默认值在 `configs/report_flow.yaml` 的 `flow.default_layout`，改配置即改默认。

## 2. 三条入口

| 入口 | 内容来自 | 默认版式 | 交付命令 |
|---|---|---|---|
| `report "…" --claims x.json` | 专家 claims 卡（数字/引文/证伪） | flow | 加 `--prose-hard` |
| `report "…" --dir <项目>` | 方法库 + 决策契约 | flow | 加 `--prose-hard` |
| `report flow --project <目录>` | `facts.py` + `charts.py`（+`prose_specs.py`） | flow | 加 `--prose-hard --gate-hard` |

## 3. 门禁：什么时候跑、什么会拦

| 层 | 跑的条件 | 拦的条件 | 开关 |
|---|---|---|---|
| 章节过账（数字可解释） | 总是 | 有数字解释不了 | 硬拦（无开关） |
| 文笔 `prose_style` | 总是 | 每节 <850 字 / 缺块 / 数字密度 <35 | `--prose-hard` |
| r04 五项（覆盖/数据/图表/版式/文笔） | 项目有 `coverage/` 三件套 | 任一层 FAIL（页数按 **PDF 实际页数**） | `--gate-hard` |
| 三层质检（证据/编辑/呈现） | 仅 `report flow` 的 paper 项目线（已不在 run-line 主链） | 任一层 FAIL | 硬拦 |

不加 `--prose-hard / --gate-hard` 时只记录，不拦——**交付稿必须加**，否则闸门只是装饰。

## 4. v3 的“思考顺序”现在落在哪

```
TaskFrame → CoveragePlan → SourceLedger → pre_gate(G1–G10)
   → facts(SECTIONS) → prose_specs(十段) → prose_gen(千字)
   → charts(SVG) → kit(版式) → flow(一条流) → PDF
   → prose_style + r04(五项，页数读 PDF)
```

- 前四步：项目目录提供 `coverage/*.json`，`report flow` 自动读取并跑 r04；
- 中三步：`facts.py / prose_specs.py / charts.py`，模板在 `templates/flow-report/`；
- 后三步：core 全包（`core/report/flow_report.py` + `core/report_theme/{kit,flow,chartkit}.py`）。
