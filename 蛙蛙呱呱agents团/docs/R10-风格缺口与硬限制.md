# R10 风格缺口与结构性硬限制

> 2026-11-11 · 从外部资料补齐「我们还有什么不能出」，并把结论落进注册表 v1.1。
> 结论先给：**缺的不是风格数量，缺的是「哪些根本不该靠生图做」这条边界。**

## 一、这次读到的两份原始资料

| 资料 | 关键结论 | 我们用在哪 |
|---|---|---|
| [Rendering text reliably inside logos](https://github.com/MohamedAbdallah-14/prompt-to-asset/blob/main/docs/research/08-logo-generation/8c-text-rendering-in-logos.md) | 字标是文生图最难的测试；到 2025/26 年「可读的拉丁文字字标」已是产品级已解决，但**精确字体、逐像素字距、多语种、长句仍未解决**；中/日/韩字标只有极少数模型能到 A/B 级，多数 C/D 级 | 定 `text_policy` 与 8 条硬限制 |

该资料给出的失败模式：拼写错、字母重复、幽灵字符、连字断裂、字距塌陷、基线漂移、字体风格漂移、重复字标、缩小后不可读。这些和我们 11 号实测的 `Duobraid` / 伪中文 / 伪拉丁文完全对得上——**不是我们的提示词不够狠，是这类任务本身越界**。

## 二、当前 43 条里，哪些是「配方不足」而不是「模型不行」

分两类，别混：

**A. 撞文字墙（结构性，加多少负向都没用）**

| 风格 | 为什么必坏 |
|---|---|
| `technical-blueprint` | 蓝图天然带标注、尺寸线、编号 → 必出伪文字 |
| `zine` / `photo-collage` | 报纸/杂志碎片自带正文 → 必出乱码（伪中文已实测） |
| `comic-ink` | 分镜带对白框 → 空框或乱码 |
| `editorial` / `scientific`（新） | 图表标签、引线注释 → 数据不可信 |

处置：这些风格一律 `text_policy=overlay-later`，只生成版式与容器，文字后期排。

**B. 配方太泛（能出，但每次不一样）**

| 风格 | 问题 | 处置 |
|---|---|---|
| `geometric` | 只写了「圆形与条块」 | 补「严格网格 + 三色上限」 |
| `memphis` | 「糖果色 + 涂鸦」太宽 | 补「80 年代限定色板 + 三种母题」 |
| `engraving` | 排线密度没上限，容易糊成灰块 | 补「线宽 ≤0.5pt、明暗靠密度不靠灰阶」 |
| `gongbi` | 工笔细节在 1024 下糊化（实测） | 补「主体占画幅 40% 以上，减少细碎纹样」 |
| `pixel` | 已实测失败（893 色桶 / 有抗锯齿） | 补「32 色以内 + nearest-neighbor 放大」，仍属高风险 |

## 四、8 条结构性硬限制（任何风格都绕不过）

| 限制 | 兜底做法 |
|---|---|
| 精确字体/字重/字距、指定字库 | AI 只出图形，文字在 Figma/AI 重排 |
| 中/日/韩字标可读性 | 字标只生成图形部分，中文后期排 |
| 复刻真实商标/品牌资产 | 不生成，用授权矢量文件 |
| 确定数字、百分比、图表刻度 | 生成容器与配色，数据后期填 |
| 同一角色多视角一致 | 单张定稿 + 参考图/LoRA，三视图人工修 |
| 多格漫画跨格一致 | 逐格生成 + 统一参考图 |
| 可直接编辑的矢量路径 | 位图 → VTrace → 手工修节点 |
| 严格物理尺寸/出血/印刷规格 | 后期按规格裁切、补出血、打样 |

这些写进 `style_registry.json` 的 `hard_limits`，并在 `catalog.html` 里单列一节。

## 五、代码层的两处升级

1. **载体级文字策略默认**：`poster / banner / infographic / ui-screen / packaging / comic / character-sheet / mockup / social-card / storyboard` 默认 `overlay-later`，不再靠调用方记得写。
2. **文字型载体硬限制提醒**：这类载体若显式把 `text_policy` 设成 `none`，门禁给 `WARN`（`hard_limit=exact-typography`），提示会出乱码标签。不拦，但记录。
