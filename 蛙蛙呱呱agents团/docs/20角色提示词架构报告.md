# 20 角色提示词架构报告

> 2026-11-11 · 目标：让每个角色都能「把生成交给大模型、把判定留在 Python」，
> 既用满模型能力，又不让智能体退化成聊天框。
> 适用：`蛙蛙呱呱agents团` 全部 20 个角色。r10 作为已落地的范本单列。

---

## 0. 一句话结论

**基础设施已经有了，缺的是「每层的职责划分」和 7 个角色的领域块。**

每个角色都已经有 `prompt_profile.json`（6–9 KB），里面已经有：词表、默认假设、追问、动作路由、
语义字段、`l2_prompt_blocks`、`output_contract`。
问题在于：

1. **7 个角色没有 L2 领域块**（r03/r06/r14/r15/r16/r18/r20），模型拿到的只有字段，没有方法；
2. 没有统一的 L0（角色宪法）与 L3（判定/回退）拼装器，prompt 靠人临时写，质量随人波动；
3. 模型输出没有强制过 `contracts.validate_output`，等于「生成完没人核对」。

## 2. 统一四层架构

每个角色对模型的一次调用，都拼这四层（缺一层就会出现「答得漂亮但没法验」）：

| 层 | 内容 | 来源 | 谁维护 |
|---|---|---|---|
| **L0 角色宪法** | 身份、领域边界、绝不做的事、语气 | 新写（每角色 150–250 字） | 一次写死 |
| **L1 任务契约** | 本次输入字段（`semantic_fields`）、必答问题（`questions`）、默认假设（`assumptions`） | `prompt_profile.json` | 已有，自动拼 |
| **L2 领域方法** | 该专业的推理骨架（怎么算、看什么、按什么顺序） | `l2_prompt_blocks` | **7 个角色待补** |
| **L3 判定与回退** | 输出 schema（`output_contract`）、硬门禁、失败回退 | `contracts.py` + 角色 gates | 已有，需强制接入 |

### 关键原则：谁生成、谁判定

```
大模型生成  →  L0 + L1 + L2 拼出的 prompt  →  结构化 JSON
                                   ↓
Python 判定  →  contracts.validate_output（schema）
             →  角色自己的确定性门禁（算数/勾稽/守恒/脱敏/无环…）
             →  不通过：打回重写 or 回退到 skills 的规则实现
```

模型永远不直接给结论，它给「候选结论 + 证据字段」；**结论成立与否由代码算**。
这就是 r10 已经在用的那套（`imagegen compose` 出提示词，门禁判合格），只是要推广到 19 个角色。

## 3. 每个角色怎么做

> 格式：**交给模型** / **Python 守** / **要补的 L2 块** / **典型失败**

### r01 蛙全局 · CEO
- 交给模型：意图澄清、决策卡正文、跨部门拆解、权衡叙述。
- Python 守：可逆性分级（不可逆必须人工签）、一票一事（一个决策一个 owner）、责任人非空。
- 补 L2：`决策五问`（可逆吗/最坏损失/谁签/何时复盘/失败怎么退）。
- 典型失败：把「建议」写成「已决定」；拆解出没有 owner 的任务。

### r02 蛙排布 · COO
- 交给模型：工作拆解、依赖排序、交接包撰写。
- Python 守：容量上限、并行度、交接三件套（产物/复现命令/验收标准）齐备。
- 补 L2：`跨角色接口`（谁交付给谁、字段是什么、验收人是谁）。
- 典型失败：排期不考虑在跑任务；交接包缺复现命令。

### r03 蛙守线 · CFO（L2 空白）
- 交给模型：财报解读、差异归因叙述、风险登记描述。
- Python 守：资产=负债+权益、账期与币种、凭证号存在、不含投资建议。
- **补 L2 `口径与勾稽`**：
  > 先声明口径（合并/单体、含税/不含税、权责/收付），再做勾稽；
  > 每个数字必须挂凭证号或报表行号；三表对不上时先报差异，不给结论。
- 典型失败：用同比解释环比；把预测当已发生。

### r04 蛙挑刺 · 独立评审（L2 已够）
- 交给模型：按判据找问题、写评审意见。
- Python 守：pass/fail 由硬门禁决定（不是模型说 pass 就 pass）、身份红线（不得评审自己产物）、证据定位。
- 补 L2：`只判不改`（发现即记录，不代改）。
- 典型失败：给出「整体不错」这类不可复核结论。

### r05 蛙深远 · 研究
- 交给模型：检索计划、来源分级、结论综合与置信度。
- Python 守：证据账本完整性、来源级别枚举、无来源不下定性结论。
- 补 L2：`反幻觉门`（三处以上来源交叉才算事实）。
- 典型失败：一段话里混入未标注来源的数字。

### r06 蛙得清 · 数据分析（L2 空白）
- 交给模型：口径解释、洞察叙述、图表选型建议。
- Python 守：样本量、时间窗、显著性计算、口径一致性（同环比不可混）。
- **补 L2 `口径与因果`**：
  > 先写指标定义与口径，再写结论；相关不等于因果，因果需给识别策略；
  > 每个结论必须带样本量与置信区间，异常值单独交代。
- 典型失败：拿 30 个样本的差异当规律；把趋势外推成预测。

### r07 蛙得明 · 产品（L2 已够）
- 交给模型：PRD 叙述、用户故事、验收标准。
- Python 守：四段（触发/规则/结果/状态）齐备、非目标必填、验收可判定。
- 补 L2：`非目标优先`（先写不做什么，再写做什么）。
- 典型失败：验收标准写成「体验流畅」。

### r08 蛙建成 · MVP
- 交给模型：切片方案、落地页文案、验收步骤。
- Python 守：成功/杀死标准、类型检查、截图证据存在。
- 补 L2：`时间盒与偷懒登记`（哪些是故意简化的）。
- 典型失败：MVP 里塞进三个以上未验证假设。

### r09 蛙稳码 · 工程
- 交给模型：技术方案、接口设计、实现步骤。
- Python 守：测试通过、lint、回滚命令、依赖边界。
- 补 L2：`可验证交付`（每条改动对应一条验证命令）。
- 典型失败：只说「已优化」，没有基准数字。

### r10 蛙成美 · 视觉设计（**范本**）
- 已实现：57 条风格注册表 + 载具轴 + `text_policy` 三档 + 8 条结构性硬限制；
  `compose` 确定性出词、`refs` 查 31 套真实设计系统、`inspire` 39 站检索与版权三档；
  门禁三值（core/extended/experimental）、`catalog` 四态、mock 引擎一律拒绝。
- 其他角色可以照抄的结构：**资产化输出**（提示词本身是产物，可版本化、可复核）。
- 典型失败：把「参考」当成「复刻」。

### r11 蛙点题 · 内容
- 交给模型：选题、钩子、正文、多平台改写。
- Python 守：平台字数限制、禁词、术语替换闭环、AI 辅助声明。
- 补 L2：`平台差异`（同一观点在三个平台的不同写法）。
- 典型失败：标题党与正文承诺不一致。

### r12 蛙引流 · 增长
- 交给模型：增长假设、渠道组合、实验设计。
- Python 守：预算上限、显著性门槛、停止条件、归因口径。
- 补 L2：`预注册`（开跑前写死主指标与停止条件）。
- 典型失败：跑完再挑指标。

### r13 蛙客成 · 客户成功
- 交给模型：健康分归因、QBR 叙述、跟进话术。
- Python 守：四维加权分（使用/支持/VOC/互动）、三色区间、续约临期计算。
- 补 L2：`归因必写`（高风险客户必须写清是哪一维掉的）。
- 典型失败：只给分数不给原因。

### r14 蛙交易 · 交易履约（L2 空白）
- 交给模型：异常解释、客服话术、对账摘要。
- Python 守：订单/支付/履约三态一致、金额守恒、退款前置条件。
- **补 L2 `三态一致`**：
  > 任何结论先对齐三态：订单状态、支付状态、履约状态必须互不矛盾；
  > 金额改动必须守恒（原额-退款=净额）；终态不可再迁。
- 典型失败：把「已支付未发货」写成「已完成」。

### r15 蛙供应 · ERP（L2 空白）
- 交给模型：采购建议、供应商评估叙述、补货说明。
- Python 守：单据链（采购单→收货→入库/出库）数量守恒、供应商准入状态。
- **补 L2 `单据链`**：
  > 每个数量必须能追到单据号；收货不得超订单量；库存分录用途必须在白名单。
- 典型失败：占用与在途混算。

### r16 蛙人事 · HR（L2 空白）
- 交给模型：JD、面试问题、评估摘要。
- Python 守：PII 脱敏、评分维度一致、禁止排名与歧视性表述。
- **补 L2 `合规与公平`**：
  > 只写与岗位相关的可观察证据；禁止年龄/性别/婚育等推断；
  > 输出前自查是否出现可识别个人信息。
- 典型失败：把「感觉不合适」写成结论。

### r17 蛙织网 · 自动化（L2 已有 2，建议补 1）
- 交给模型：集成方案、字段映射建议、失败处理说明。
- Python 守：凭据边界、幂等键、重试上限、死信队列。
- 补 L2：`幂等与审计`（每条 webhook 必须有幂等键与审计留痕）。
- 典型失败：重试没有上限。

### r18 蛙数仓 · 数据工程（L2 空白）
- 交给模型：建模方案、分层说明、测试设计。
- Python 守：DAG 无环、每张模型有测试、增量与回填策略合法。
- **补 L2 `分层与测试`**：
  > staging→intermediate→mart 三层不可越级；每层声明物化方式；
  > 每张模型至少 unique / not_null / 枚举 三类测试之一。
- 典型失败：一步从源表算出宽表。

### r19 蛙智模 · 模型评估（L2 已够）
- 交给模型：实验设计、评估报告、模型卡。
- Python 守：评分器版本、数据集版本、回归门槛、新旧绿集对比。
- 补 L2：`发布门禁`（回归未过不许发）。
- 典型失败：只报新模型分数，不报旧基线。

### r20 蛙值守 · SRE（L2 空白）
- 交给模型：复盘叙述、根因假设、对外沟通模板。
- Python 守：时间线单调、分级正确、RPO/RTO 实测值、恢复验证证据。
- **补 L2 `时间线与根因`**：
  > 事件时间必须单调递增且带时区；根因不得写「人为失误」；
  > 恢复必须给实测 RPO/RTO，不能写「已恢复」。
- 典型失败：复盘里没有恢复验证。

| 阶段 | 动作 | 影响角色 | 判据 |
|---|---|---|---|

## 5. 验收方法（每角色统一）

1. **黄金样例 3 条**：1 条干净、1 条脏数据、1 条越界；模型输出必须分别 pass / 被拦 / 被拦。
2. **schema 必过**：`contracts.validate_output` 不通过即视为失败，不允许「内容不错但格式自由」。
3. **禁用词扫描**：沿用各角色已有 `禁用词与反例` 块（赋能/闭环/抓手/打造）。
4. **回退可用**：模型不可用时，同一动作必须能由 skills 的确定性实现跑出可验收结果（r10 的 `compose` 就是范例：无 LLM 也能出词）。

## 6. 附：可直接复用的模板

**L0 角色宪法（占位版）**

```
你是「{角色名}」，负责 {领域}。你的产出必须能被代码复核。
边界：{绝不做的三件事}。
禁止：赋能/闭环/抓手/打造/整体不错 等不可验证表述。
输出：只输出 JSON，字段见 schema；不写解释性段落。
```

**L1 任务契约（自动从 profile 拼）**

```
本次输入：{semantic_fields}
必答：{questions}
默认假设：{assumptions}（未确认前不得扩写范围）
```

**L3 判定与回退**

```
输出必须通过：contracts.validate_output(skill, action)
并通过角色硬门禁：{gate_list}
任一不过 → 打回重写（最多 2 次）→ 仍不过则回退 skills 规则实现，
并在产物里标注 fallback=true 与原因。
```

## 9. 提示词增强（2026-11-12）

原来 `build()` 只拼「宪法 + 2 个块 + 字段」，实测 20 角色平均 **550 字**，确实覆盖不了能力域。
已改为七段式，实测 **2711–3916 字**：

| 段 | 内容 | 来源 |
|---|---|---|
| 角色宪法 | 身份 + 三件不做的事 + 全局禁用词 | `prompt_constitutions.json` |
| **能力全景** | 该角色全部技能与动作（技能说明 + 动作说明 + 触发词 + 需填字段） | `skills/*.py` 的 NAME/DESC/ACTIONS + `prompt_profile.actions` |
| 当前技能/动作 | 本次落在哪个技能、哪个动作 | 入参 |
| **领域方法** | 该技能模块 docstring（含门禁口径） | `skills/sNN_*.py` 的模块文档 |
| 方法块 | 全部 L2 块（原为 2–3 句） | `l2_prompt_blocks` |
| **判定阈值** | 本角色 `thresholds.json` 节选（≤1600 字） | `experience/thresholds.json` |
| 输出要求 | 必含小节 + 只输出 JSON | `output_contract` |

自检门槛同步抬高：`check_prompt_pack.py` 现在断言 **length ≥ 2000、必须含【能力全景】、
动作覆盖 ≥ 8**，20 角色全部通过。

设计取舍：**当前动作给深（docstring + 方法 + 阈值），其余动作给索引**（触发词 + 需填字段），
避免把 10 个动作的方法全塞进去导致注意力稀释。
