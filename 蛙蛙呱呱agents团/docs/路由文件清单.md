# 路由文件清单（20 角色）

> 2026-11-12 · 一条请求从「人/编排器」到「某个技能动作」经过哪些文件。
> 结论先说：**20 个角色是同一套六件套，没有例外**，差异只在技能数量与 `local_*`。

---

## 一、四层路由

| 层 | 决定什么 | 文件 |
|---|---|---|
| **编排层** | 哪个角色接这个活 | `guagua.py`、`core/registry.py`、`core/dispatcher.py`、`core/runner.py` |
| **角色入口层** | 这个角色的哪条命令 | `<role>/agent.py`（启动时从 `prompt_profile.json` 读意图表） |
| **技能分发层** | 命令落到哪个动作 | `<role>/skills/__init__.py` + `<role>/skills/sNN_*.py` |
| **语义与契约层** | 参数够不够、输出合不合格 | `<role>/prompt_profile.json`、`<role>/contracts.py`、`<role>/harness.py` |

LLM 网关插在**角色入口层之前**：`shared/role_runtime.handle_meta_command` 在所有角色
`main()` 的第一行被调用，所以在这里拦一次就覆盖 19 个角色（r10 自带 imagegen 路径）。

---

## 二、顶层路由文件

| 文件 | 作用 | 坏了会怎样 |
|---|---|---|
| `guagua.py` | 人类入口：`roles / info / chat / plan / dispatch / status / check / capabilities / skills / doctor` | 所有命令行入口失效 |
| `core/registry.py` | 角色注册表：id → 目录、输入、输出、能力 | `roles/info` 乱，cross-agent 调不到 |
| `core/dispatcher.py` | 任务工单 → 角色 CLI 调用 | 编排执行断链 |
| `core/runner.py` | 角色间子进程调用（上下文隔离） | 角色互相调不动 |
| `core/prompt_kernel.py` | `clarify` / `fallback_route`：意图不清时追问或兜底 | 模糊需求直接报错 |
| `shared/role_profiles.py` | 读取角色 profile | `chat/info` 缺信息 |
| `shared/role_runtime.py` | 元命令（report/test/logs）**+ LLM 网关接入点** | 元命令与网关同时失效 |
| `shared/prompt_gateway.py` | 新增：模型优先、规则兜底 | 不影响默认路径（默认关闭） |
| `shared/chat_cli.py` | `chat` 的知识注入 prompt | chat 变成裸聊 |
| `configs/rNN.yaml` | 角色配置**源**（生成 agent-packs 用） | `gen_agent_packs --check` 漂移 |
| `agent-packs/` | 渲染产物，**不参与运行时路由** | 不影响运行 |

## 三、每个角色的六件套（全部 20 个都有）

| 文件 | 路由职责 |
|---|---|
| `<role>/agent.py` | CLI 入口；`_load_intent_routes()` 从 profile 读中文意图→`(skill, action)`；`manifest/demo/run` 等元命令 |
| `<role>/skills/__init__.py` | `SKILLS` 列表 → `SKILL_BY_NAME` 字典，技能名到模块 |
| `<role>/skills/sNN_*.py` | `add_parser` 声明动作；`run()` 里 `if args.action == ...` 分发；部分动作含 `--need` 等参数 |
| `<role>/prompt_profile.json` | **语义路由唯一出处**：`intent_routes[]`（关键词→动作）、`actions[]`、`questions`、`assumptions`、`l2_prompt_blocks`、`output_contract` |
| `<role>/contracts.py` | 每个动作的输入/输出 schema（`validate_input` / `validate_output`） |
| `<role>/harness.py` | `_VALIDATORS`：动作 → 确定性校验函数（算数/勾稽/守恒等硬门禁） |

角色特有：

| 文件 | 谁有 | 作用 |
|---|---|---|
| `local_actions.py` | r08 / r10 / r11 / r12 / r13 | 纯本地动作（不联网、不发布） |
| `local_exec.py` | r14 / r15 / r16 / r17 / r18 / r19 / r20 | 本地执行器（金额、幂等、状态校验） |
| `review.py` / `verify_loop.py` / `cases.py` | 除 r01 外都有 `verify_loop.py`，其余全有 | 对抗评审 / 闭环矩阵 / 案例库，不参与主路由但会读同一批契约 |

## 五、一条请求的完整路径（以 r14 `catalog image` 为例）

```
python agent.py catalog image --need "冷凉蔬菜礼盒白底主图"
  │
  ├─ 1. shared/role_runtime.handle_meta_command(argv, "r14")
  │      └─ prompt_gateway.maybe()：默认关闭 → None，继续
  ├─ 2. agent.py 解析 → skill=catalog, action=image
  │      └─ 若从自然语言进来：_INTENT_ROUTES(r14:64) 命中「主图/商品图」→ ("catalog","image")
  ├─ 3. skills/__init__.py → SKILL_BY_NAME["catalog"] → skills/s01_catalog.py
  ├─ 4. s01_catalog.run(args) → _image(args)
  ├─ 5. skills/imagegen_bridge.py → subprocess 调 r10 agent.py imagegen compose
  │      └─ r10：注册表解析风格 → 拼 prompt → 落盘 workspace/prompts/
  ├─ 6. 返回结果（prompt / negative / image_size / risks / hard_limits）
  └─ 7. contracts.validate_output("catalog","image")（走评审时）
         → emit __AGENT_RESULT__ {json}
```

## 六、排障对照

| 现象 | 先看哪个文件 |
|---|---|
| 中文需求没被识别成动作 | `<role>/prompt_profile.json` 的 `intent_routes[]` |
| 动作存在但参数总报缺 | `<role>/prompt_profile.json` 的 `actions[].requires` |
| 输出结构对但不合规 | `<role>/contracts.py` |
| 数字/状态不对但 schema 过了 | `<role>/harness.py` 的 `_VALIDATORS` |
| 模型被调用但结果没落地 | `shared/prompt_gateway.py`（是否返回 None 回退） |
| 跨角色调不动 | `core/runner.py` + 目标角色 `agent.py` |
| 编排层不派活 | `core/registry.py` / `core/dispatcher.py` |

## 七、这次新增的两处

- `shared/prompt_gateway.py`：LLM 网关，默认关闭；
- `shared/role_runtime.py`：在 `handle_meta_command` 开头插入网关调用（15 行）。

这两处就是「全员接线」的全部改动点，其余 19 个角色的 `agent.py` **一行没动**。
