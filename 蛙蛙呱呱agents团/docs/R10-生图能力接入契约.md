## 二、调用契约（无引擎也能用）

任意角色目录下执行：

```bash
python <repo>/r10-wachengmei-design/agent.py imagegen compose \
       --need "中秋蔬菜礼盒主图，暖色调，突出高原冷凉和新鲜度" \
       --style 3d-food
```

标准输出最后一行是机器可读结果：

```
__AGENT_RESULT__ {"ok": true, "prompt": "...", "negative_prompt": "...",
                  "image_size": "square_hd", "text_policy": "none",
                  "resolved_style": "3d", "level": "extended",
                  "risks": ["蔬菜塑料感", "水珠变成气泡"],
                  "hard_limits": [...], "artifacts": [".../3d.md", ".../3d.json"],
                  "style_defaulted": false}
```

字段契约：

| 字段 | 用途 |
|---|---|
| `prompt` / `negative_prompt` | 直接复制进任意生图工具 |
| `image_size` | 已按画幅换算（square_hd / landscape_4_3 / portrait_4_3 / landscape_16_9） |
| `text_policy` | `none` / `overlay-later` / `render-attempt`，决定文字怎么处理 |
| `risks` | 该风格的已知失败模式，验收时逐条对 |
| `hard_limits` | 结构性不能做的（精确字体、CJK 字标、确定数字…），提前告知需求方 |
| `artifacts` | 落盘的 `.md`（可粘贴）与 `.json`（机读） |

**必须给业务主体**（`--need` / `subject` / `concept` 之一），否则 `ok=false` 并返回示例——
不允许用通用模板冒充业务内容。

## 三、有引擎时怎么切

R10 探测到引擎后，同一套 `brief` 直接走 `generate`：

```bash
python .../agent.py imagegen engines       # 看有哪些引擎、缺哪个 env
COMFYUI_URL=http://127.0.0.1:8188          # 或任一云端 key
python .../agent.py imagegen generate --input brief.json
```

没有引擎时 `generate` **自动降级**为 `compose`（`degraded=true`），返回的仍是提示词，
不会产出占位图，也不会报假成功。对上游角色来说，两种模式返回结构一致，**不需要改调用代码**。

## 四、边界：数据分析的图不走这里

数据图表、看板、趋势图属于**确定性渲染**，与 AI 生图是两条路：

| 类型 | 走哪 | 为什么 |
|---|---|---|
| 数据图表 / 看板 / 趋势图 | `r06` / `r18` 的 `chart_lib` / `echarts` | 数值必须精确，AI 画不出来 |
| 营销物料版式（海报、Banner 的版式层） | `r10` 的 `s09_render`（SVG） | 版式可参数化，SVG 可编辑 |
| 主视觉 / 插画 / 产品场景图 | `r10` 的 `imagegen compose` | 这类才是生成式内容 |

`hard_limits` 里已经写明：**确定数字、百分比、图表刻度不可靠**——数据图交给 AI 生图是错误路径，
不该因为「r10 能出图」就把数据可视化并进来。

---

## 五、验收口径

上游角色拿到结果后，按这三条验收，不要只看 `ok=true`：

1. `risks` 是否命中（命中即降级处理）；
2. `hard_limits` 是否触及本次需求（触及就改交付形态，不要硬跑）；
3. `style_defaulted=true` 时确认默认风格是否可接受。
