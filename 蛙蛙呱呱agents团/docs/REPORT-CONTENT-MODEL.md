# 报告内容模型（不是模板）

> 目的：把“报告长什么样”从固定版式里解耦。模板可以换，模型不能换。

## 1. 五段链

```
claim → slice → encoding → blocks → renderer
```

| 段 | 回答的问题 | 硬约束 |
|---|---|---|
| claim | 这一节到底判断什么？ | 一句结论，≤80 字；标题 ≤20 字 |
| slice | 用哪组数证明？ | 同一指标族、同一单位、同一期次；≥2 点，≤12 点 |
| encoding | 这组数是什么关系？ | 比较 / 构成 / 趋势 / 分布 / 流向 / 相关 |
| blocks | 怎么讲清楚？ | 事实 / 机理 / 反例 / 所以；每块有正文，不空挂标签 |
| renderer | 用什么图、什么页？ | 关系选图型；内容选页型；附录是容器，不是页型 |

## 2. 两套适配器

### 旧稿（sections）

- `reading` 里保留 `strong`；
- 没有 `strong` 时，编译层从 `【事实】/【机理】/【反例】/【所以】` 前缀还原；
- 拆段后**每段继承块标签**，避免全部落进“事实”；
- 旧稿不强行改写成 claims，只在渲染前补 `slice / encoding` 的缺省值。

### 新稿（claims 映射层，原 claims_v4 已并入）

- `claim` + `rows` + `encoding` + `findings` + `warrant` + `action` + `falsifier`；
- 主判断 ≤7；第 8 条起 `tier=support`；
- 每条主判断 1 图 + 1 表；
- `validate_v4` 查混单位、缺表、缺动作、缺停止条件。

## 3. 关系 → 图型（当前默认）

| 关系 | 默认图型 | 说明 |
|---|---|---|
| 比较（谁高谁低） | `dot` | 带基线/参考带，能看出“落在区间内还是区间外” |
| 构成（占多少） | `share_bar` | 份额必须能加总到 100% |
| 趋势（往哪走） | `vbar` / `line` | 有期次才用 line；没有期次不假装趋势 |
| 分布（散不散） | `dot` / `hist` | 点数 <8 不画分布 |
| 流向（从哪到哪） | `funnel` / `sankey` | 有阶段用漏斗；有节点与 links 用桑基 |
| 关系（谁连谁） | `network` | 必须有 nodes + edges；没有就不画 |
| 相关（两变量） | `scatter` / `heatmap` | 必须有 x/y 两组值；只有一组 y 不画 |

图型不是越多越好：**没有同一 slice，就不画图**；宁可用表。

## 4. 页型

| 页型 | 用途 | 约束 |
|---|---|---|
| 封面 | 标题 + 3 个决策数 | 数字来自 `decision.items`，不是背景数 |
| 决策纸 | 5 条判断 + 数字 + 动作 + 停止 | 一页 |
| 正文节 | 结论 + 图/表 + 四块 | 单段 ≤300 字；节长不设上限 |
| 附录 A | 数据来源（记录层） | **一页**，86 条全量，编号可回溯 |
| 附录 B | 支撑判断 + 缺口 | 单列，不和来源并排 |
| 口径与分数 | 生成方式/证据规模/自检 | **单独一节**，末节 |

## 5. 门禁

- `check_report_flow.py`：成品门禁（图来源、边界、深度、末节口径）；
- `audit_report_contract.py`：渲染前结构审计（段落、主判断、图单位、决策纸、标题）；
- `report_contract.yaml`：唯一数字源，代码只读它，不各写一套默认值。

## 6. 结构 profile

`configs/report_structures.yaml` 定义 research / decision / diagnostic / brief 四套模块集合；
同一套内容模型，按任务类型组装页序，不再所有报告都长成同一个模板。

**规则冲突时：以 `report_contract.yaml` 为准；旧模板的硬编码必须删，不允许两套阈值并存。**
