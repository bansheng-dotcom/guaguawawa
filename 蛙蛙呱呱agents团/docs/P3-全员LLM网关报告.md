## 一、架构：一处接入点，而不是改 19 个文件

```
角色 agent.py
   └─ main()
        ├─ role_runtime.handle_meta_command(argv, ROLE)   ← 唯一接入点
        │     ├─ PROMPT_PACK_LLM 未开 / 无 Key → 返回 None（原样走规则）
        │     ├─ 开了 → 识别 skill/action/--input
        │     │      ├─ 拼 L0+L1+L2+L3 → 调模型
        │     │      ├─ 校验 schema + 禁用词
        │     │      ├─ 通过 → 打印 __AGENT_RESULT__，main 直接返回
        │     │      └─ 不通过/异常 → 返回 None（回落到角色规则实现）
        │     └─ 其余情况返回 None
        └─ 原有 CLI 解析与技能分发（完全不变）
```

选择这个接入点的原因：19 个角色的 `agent.py` 结构各不相同（有的 `build_parser()`，
有的 `run_cli()`），逐文件改会制造 19 种分叉；而**所有角色都会调用
`handle_meta_command`**，所以在这里拦一次就够。

## 二、三种运行状态

| 状态 | 条件 | 行为 |
|---|---|---|
| **默认（规则）** | 不设 `PROMPT_PACK_LLM` | 与接线前完全一致，零行为变化 |
| **半开** | 设了 flag 但没 Key | 仍然走规则；`maybe()` 直接返回 None |
| **全开（模型优先）** | `PROMPT_PACK_LLM=1` + `OPENAI_API_KEY`/`DEEPSEEK_API_KEY` | 拼 prompt → 调模型 → 校验 → 通过则接管，否则回退规则 |

回滚：`unset PROMPT_PACK_LLM` 即恢复，不需要改代码。

## 四、启用方式

```powershell
# 1) 配好任一 OpenAI 兼容 Key
$env:DEEPSEEK_API_KEY = "sk-..."

# 2) 打开网关
$env:PROMPT_PACK_LLM = "1"

# 3) 正常调用角色，模型会先出手，不过 schema 就自动回落
python agent.py prd prd --input examples/prd.json
```

返回里会带 `"llm": true`、`"payload"`、`"gate": "schema+forbidden-words passed"`，
`next` 会提醒**还要过本角色硬门禁**（算数/勾稽/守恒/脱敏），因为 schema 只保证结构，
不保证业务正确。

## 七、已知限制（不要读成「全自动」）

1. **LLM 路径未经真 Key 端到端验证**：本机没有 Key，只验证了构建、校验、回退三段；
   真实模型输出质量要你们接 Key 后跑一批才知道。
2. **schema 通过 ≠ 业务正确**：网关只查必含字段与禁用词；算数、勾稽、守恒、脱敏
   仍由各角色自己的门禁决定，`next` 里已提示。
3. **r10 未接网关**：它有自己的 `imagegen` 全套（compose/refs/inspire/engines），
   重复接入会造成两条路径打架。
4. **网关只接管带 `--input` 文件的调用**：无输入文件的命令（如 `manifest`）一律走原路径。
