# 专业分析报告标准 v9 · 通用五模块框架

> 目标：不换业务、不换主题，也能稳定产出同一专业水准的分析报告。
> 做法：把「专业分析」拆成与行业无关的五模块 + 可校验标准；业务只交数据，框架自动选维度。

## 一、五模块与专业标准

| 模块 | 回答什么 | 必备内容 | 专业标准 | 校验节点 |
|---|---|---|---|---|
| **M1 问题定义与边界** | 回答什么、不回答什么、按什么口径 | 结论先行 / 适用范围 / 不适用范围 / 口径与期次 | 标题即判断且带数字；边界三件事齐全；顶层问题 MECE 拆 3—5 个并与章节一一对应 | M1 不过 → 停止生成，先补问题定义 |
| **M2 数据采集与校验** | 数据从哪来、凭什么信、能不能互证、缺什么 | 来源清单 / A-B-C-D 等级 / 交叉验证 ≥1 组 / 缺口清单 | 每条事实带来源、期次、单位、地区、等级；C 级只做量级判断；D 级进假设表；缺口写「缺什么→影响哪条→怎么补」 | M2 不过 → 相关结论降级为「待验证」，不进动作清单 |
| **M3 结构化逻辑推导** | 按 MECE 维度拆开，每维度一条判断链 | 维度覆盖 ≥3 个 MECE 组 / 观察→对照→机理→落点→证伪 / 每条结论有 refs | 同组维度互斥；判断带数字带对照；机理写传导且两端可在数据里找到；证伪条件可观测 | M3 不过 → 删除该维度，不用估算补 |
| **M4 风险与局限** | 哪些结论不能下、依赖什么假设、什么会推翻 | 风险清单（概率×影响）/ 假设敏感度 / 证伪条件 / 回退方案 | 风险给触发指标与应对；C/D 假设给敏感度；核心结论配证伪；回退写清回到哪一步、谁决定 | M4 不过 → 不得发布 |
| **M5 可落地结论** | 做什么、谁做、什么时候、什么算做完、什么时候停 | 动作清单 / owner / 时点 / 验收口 / 停止条件 / 不做清单 | 动作四要素齐全；停止条件可观测；不做清单与动作同等重要；按依赖顺序排 | M5 不过 → 只能当分析稿，不能当决策稿 |

## 二、数据可信度等级（全模块共用）

| 等级 | 含义 | 典型来源 | 使用规则 |
|---|---|---|---|
| **A** | 一手 / 官方 | 统计公报、政府文件、审计财报、一手监测 | 可直接引用；口径/期次/地区写全，不做二次换算 |
| **B** | 行业 / 机构 | 行业协会、企业公告、券商研报 | 注明机构、年份、口径；跨机构不可直接相加 |
| **C** | 平台 / 媒体 | 电商报价、媒体报道、抽样估算 | 只做量级判断，不能与 A 级混算，必须标 C |
| **D** | 假设 / 判断 | 专家判断、模型假设、经验值 | 必须单列 assumptions，给敏感性，不能写成事实 |

派生数字的等级 = 输入中最低等级。来源冲突时取低等级，并在 M4 说明。

## 三、MECE 维度库（17 维 / 5 组）

维度按「问题」定义，不按行业定义。组间互斥、组内维度不重叠。

| MECE 组 | 维度（key） | 对应方法族 |
|---|---|---|
| 需求侧 | 市场规模（market_size）、需求结构（demand_structure）、增长趋势（growth）、价格量价（price）、客群口碑（customer） | size / structure / growth / volume / reviews |
| 供给侧 | 供给能力（supply）、成本结构（cost）、链路传导（chain） | supply / unit_econ / transmission |
| 竞争与渠道 | 竞争格局（competition）、渠道内容（channel）、产品结构（product） | concentration / channel / priority |
| 财务与经营 | 单位经济（unit_economics）、投入回报（capital_return）、经营周转（store_ops） | unit_econ / roi / store |
| 风险与执行 | 政策合规（policy）、风险缺口（risk）、执行组织（execution） | policy / coverage / sla |

其中 `risk`、`execution` 只在 M4/M5 展开，不重复进 M3。

### 场景自适应规则（不为场景定制）

匹配分 = **主题关键词命中 ×10 + 已命中方法 ×4 + 数据能力 ×1**。

1. 先保证 5 个 MECE 组各选 1 个维度（覆盖优先）；
2. 再按分数补维度，同组最多 2 个，总数 ≤8；
3. 同组方法重叠则不重复选；同一 finding 只能进一个维度；
4. **没有关键词命中时，按数据能力兜底**（数据驱动，不写死行业）；
5. 维度不足 3 个 → 不出报告，走缺口稿。

同一主题换一套数据，维度会随可用方法变化；同一套数据换主题，维度会随关键词变化。两者都不需要改代码。

## 四、执行流程 S0—S9

| 步骤 | 做什么 | 产出 | 质量校验 |
|---|---|---|---|
| **S0 输入** | 读主题、项目数据、事实表；识别数据能力（事实/价格/业务表） | 能力清单与缺口 | 主题非空；数据目录可读 |
| **S1 问题定义** | 写回答/不回答/口径；MECE 拆 3—5 个问题 | M1 | 标题带数字；边界三件事齐 |
| **S2 数据采集** | 登记来源、期次、单位、地区、等级；C/D 进假设 | M2 来源表 | 无来源不登记；等级可查 |
| **S3 数据校验** | 多路径/两口径/上下游至少一组交叉验证；列缺口 | M2 校验 | ≥1 组交叉验证；缺口写补数动作 |
| **S4 维度匹配** | 关键词 + 数据能力选维度，保证 ≥3 组 | 维度蓝图 | 组覆盖 ≥3；同组不重叠 |
| **S5 结构化推导** | 每维度走 观察→对照→机理→落点→证伪，数字全部登记 | M3 各维度 | 每条结论有 refs；数字可解释 |
| **S6 风险与局限** | 风险按概率×影响排序；C/D 假设给敏感度；写证伪与回退 | M4 | 核心结论有证伪；有回退 |
| **S7 结论与动作** | 动作四要素 + 停止条件 + 不做清单 | M5 | 无 owner 的动作剔除 |
| **S8 成稿门禁** | 深度门禁 + 成品门禁 + 专业标准门禁 | report.html / md | Q1—Q7、F1—F9、M1—M5 全过 |
| **S9 复核** | R04 独立评审：抽 3 条结论回溯来源、抽 2 条动作查 owner | 评审记录 | 任一条回溯失败 → 退回 S3 |

## 五、三道门禁（命令）

```bash
# 1 深度门禁：Q1—Q7 + C1
python -m core.report_quality <report.html>

# 2 成品门禁：F1—F9
python scripts/check_report_flow.py <report.html>

# 3 专业标准门禁：M1—M5 + MECE 预检
python scripts/check_professional_standard.py <report.html> \
  --dir <项目目录> --topic "<分析主题>"
```

专业标准门禁检的是结构与标准，不看文风：

- M1 有边界与口径，标题带数字；
- M2 有来源、A/B/C/D 分布、交叉验证、缺口；
- M3 维度节 ≥3、MECE 组 ≥3、每节有「判断→对照→机理→落点→证伪」标签链；
- M4 有证伪与回退；
- M5 有停止条件与验收/owner；
- S1 节数 ≥6；S2 等级落表；S3 禁用空话清零；
- 给了 `--dir/--topic` 时，额外检查 MECE 组覆盖 ≥3、维度不重叠。

两份报告的维度、方法、章节完全不同，但用的是同一套框架、同一个装配器、同一组门禁。

## 七、接入一个新业务（不改框架）

1. 项目 `data/` 放数据：`facts.json`（带 grade）、价格表、`obs_*.json`（带 url/quote/grade）；
2. `python -m core.report_framework --topic "<主题>" --dir <项目>` 预览维度蓝图；
3. `python guagua.py report produce --intent "<主题>" --dir <项目> --out <目录>`；
4. 三道门禁；不过就按对应模块回退（M1 回 S1、M2 回 S3、M3 删维度、M4/M5 补风险与动作）。

业务专用方法可以继续加（如 `cheese_*`），框架会优先选它们；没有专用方法时，
通用方法照常工作——这就是「加业务不加框架」的边界。

## 八、已知限制

1. 通用方法的部分表格仍可能有未登记数字，框架会优先选业务专用方法；纯价格项目需先补登记。
2. 维度匹配是关键词+能力规则，不是语义模型；主题写得越具体，维度越准。
3. M3 维度上限 8 个，超出的维度会被截断；需要更多维度时按 MECE 组补，不硬塞。
4. 专业标准门禁检结构，不替代人审；S9 的来源回溯仍必须人工抽检。
