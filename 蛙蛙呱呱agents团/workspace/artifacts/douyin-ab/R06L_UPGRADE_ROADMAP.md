# R06L 数据分析报告升级路线

## 目标定位

R06L 不是单一的统计脚本，也不是单一的 HTML 模板，而是一条可复核的决策报告生产线：

```text
原始数据 -> 语义与质量门禁 -> 统计计算 -> 证据包 -> 图表/文字契约 -> HTML -> 结构/视觉复核
```

当前样例已经完成了“r06 计算 + DAAR 风格呈现”的原型，但距离可长期复用仍需要把关键环节从人工拼接升级成机器可验证的接口。

## 方向总览与优先级

| 优先级 | 方向 | 要解决的问题 | 验收标准 |
|---|---|---|---|
| P0 | 统计口径与数据门禁 | 防止脏数据、重复用户、第三组、二值指标误用近似检验 | 输入失败有明确原因；二值指标输出双比例检验；每个数字可回溯 |
| P0 | 结构化分析交接包 | 计算结果与报告渲染解耦，消除手工复制数字 | JSON schema 固定；报告只能消费 JSON；结果 hash/版本齐全 |
| P0 | 结果一致性校验 | 防止 JSON、HTML、原始数据三者数字漂移 | lift、p、SRM、决策、HTML关键数字自动比对 |
| P1 | 统一证据与图表契约 | 每张图回答一个问题，文本不超出证据边界 | finding/chart/text ID 可追溯；DAAR harness 通过 |
| P1 | 实验诊断能力 | 从一次性 A/B 结果升级为实验诊断 | SRM、重复用户、曝光污染、分层结果、护栏指标齐全 |
| P1 | 功效与序贯监控 | 防止样本不足或反复偷看导致假阳性 | 开实验前算样本量；明确停止规则和最终分析窗口 |
| P2 | 自动化报告流水线 | 从脚本原型升级为可配置 CLI/任务 | 一条命令完成校验、计算、交接、报告、验证 |
| P2 | 真实店铺接入 | 对接抖音电商后台导出的字段和周期 | CSV/Excel 字段映射、脱敏、增量运行、运行日志 |
| P2 | 决策闭环 | 从“建议 ship”到放量、监控、回滚 | 生成行动登记表、监控指标、回滚阈值和复盘记录 |
| P3 | 多实验平台能力 | 从单一商品详情页扩展到主图、价格、素材、投流 | case/semantic layer 可配置，计算引擎不改代码 |

## 当前实施批次：P0

本批次直接实现四件事：

1. **输入门禁**：字段、用户 ID 唯一性、分组只能是 control/treatment、converted 必须为 0/1、amount 非负、日期可解析。
2. **统计口径升级**：保留 r06 Welch 结果用于兼容，但新增二比例 z 检验结果，主决策采用二比例检验；同时输出差异的绝对百分点与相对 lift。
3. **审计元数据**：记录输入文件 SHA-256、行数、分析代码版本、阈值、方法、数据质量报告。
4. **一致性门禁**：交接包必须声明 decision、metric、method、source_hash；JSON 输出可被下游 DAAR 消费，不允许下游重新计算或改写数字。

## 后续升级顺序

### P1：实验可信度

- 以 user_id 为实验粒度去重，重复用户进入 `data_quality.errors`，默认阻断。
- 增加分层结果（新客/老客、来源、商品 SKU）和多重比较提醒。
- 增加护栏指标：退款率、客单价、履约/差评率；主指标显著但护栏恶化时自动 `guardrail_hold`。
- 增加随机化完整性：曝光后固定分组、跨组污染、进入实验前数据排除。

### P2：工程化与接入

- 把 `stitch_result.py` 改成 CLI：`--input --config --output`。
- 支持 CSV 和 XLSX 字段映射，生成 run manifest、事件日志和可重跑缓存。
- 接入 DAAR 的 plan/material/chart/text/assembly/output validator，失败回流而不是继续渲染。

### P3：运营闭环

- 生成灰度计划、监控窗口、回滚条件和实验复盘。
- 记录决策版本与实际放量后的效果，形成经验库。
- 支持多商品、多实验并行，避免实验间流量干扰。

## 关键原则

- **计算层可信优先于页面好看**：所有页面数字必须来自结构化计算包。
- **显著不等于值得放量**：同时检查效应阈值、功效、SRM、护栏指标和业务边界。
- **因果结论以随机化为前提**：没有随机分流、唯一用户和无污染证据，只输出描述性结果。
- **失败要停在正确层**：数据错回数据层，统计口径错回计算层，文字/图表错回 DAAR 对应 Agent，不在 HTML 层掩盖。
