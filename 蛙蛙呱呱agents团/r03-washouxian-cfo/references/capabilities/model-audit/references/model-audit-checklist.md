## 一、审计范围卡（先填完再动手）

```markdown
| 项 | 内容 |
|---|---|
| 被审对象 | <模型/报表/账套名称 + 版本号> |
| 期间 | <起止日期；期末时点> |
| 货币与单位 | <CNY 元 / 千元；是否含税> |
| 合并范围 | <单体 / 合并；含哪些主体> |
| 对照来源 | <申报表 / 另一套账 / 原始凭证；须可指到文件或系统> |
| 只读确认 | <已获得只读副本；无写权限> |
| 上期日志 | <底稿编号；无则写"无"> |
```

**为什么先写这张卡**：口径不一致的比对，差异全是噪声。
"含税 vs 不含税""期末 vs 期中""单体 vs 合并"是三大高频噪声源。

## 二、三表勾稽速查

| 勾稽 | 公式 | 报错长什么样 |
|---|---|---|
| 资产负债表 | `assets = liabilities + equity` | 「资产 160000.00 = 负债+权益 160000.00」→ OK |
| 现金流量 | `cash_begin + operating + investing + financing = cash_end` | 「现金勾稽：推算 59500.00 = 申报 60000.00」→ FAIL |
| 利润表 | `revenue - cogs = gross_profit` | 「毛利勾稽：推算 9500.00 = 申报 9500.00」→ OK |

**判定**：三项都必须**严格相等**。差额 0.01 也算断——差额要么是舍入（应统一口径消除），
要么是真错（必须查）。**不存在"差异很小可接受"**。

## 三、问题日志（六列，唯一可交付结论）

```markdown
| # | 位置 | 严重度 | 类别 | 问题描述 | 建议动作 |
|---|---|---|---|---|---|
| F-01 | 现金流量表!D18 | BLOCKER | 勾稽 | 期末现金申报 60000，推算 59500，差 500 | 核对 9 月筹资流水，确认是否漏记一笔 500 或期末数被手调 |
| F-02 | 总账 vs 子账 key=t3 | CRITICAL | 破差-金额 | 总账 800 / 子账 760，差 40 | 查 t3 对应的两张凭证，确认哪一侧少记 40 |
| F-03 | 子账 key=t4 | CRITICAL | 破差-子账only | 子账有 t4 3300，总账无 | 确认是否未过账；若为在途，标注跨期影响 |
| F-04 | 营销费用差异 | MAJOR | 无driver | 差 1200，注解只复述数字 | 补原因 + 单据号（如 PO-2026-0912） |
| F-05 | 控制点 CM-02 证据#1 | BLOCKER | 证据缺失 | 缺 collector 字段 | 补采集人与采集时点，否则证据不可采信 |
```

### 严重度分级

| 级别 | 判据 | 典型 |
|---|---|---|
| `BLOCKER` | 勾稽断 / 证据不可采信 / 违反只读 | 现金对不上、证据缺采集人 |
| `CRITICAL` | 破差 / 匹配率不达标 | 金额差、时点差、子账 only |
| `MAJOR` | 解释缺失，数字本身对 | 超阈差异无 driver |
| `MINOR` | 格式、命名、单位 | 千元与元混写 |

**校准**：两处审计对同一问题的分级，允许差一级，不允许差两级。差两级先修判据。

## 五、只读红线的三条实操

1. **拿副本不拿原件**：审计在只读副本上做，原件不动；
2. **发现问题只记录**：写进问题日志 + 建议动作，**不动被审模型**；
3. **改后要重审**：模型所有者改完，出一版新副本，重新走一遍门禁——
   不能在旧副本上手改后"验证通过"。

> 为什么这条最贵：审计价值来自"原始状态可复现"。
> 一旦审计者改过模型，任何后续争议都分不清"原本就错"还是"改出来的错"。

## 六、门禁与人工的分工

| 门禁能判 | 门禁判不了 |
|---|---|
| 三表三项勾稽是否相等 | 勾稽公式本身选得对不对 |
| 对账四维是否匹配、匹配率 | 破差背后的业务原因 |
| 证据字段是否齐备 | 证据是否真实（需外部核验） |
| 差异是否有 driver 文本 | driver 说得对不对（需业务判断） |

> **纪律**：门禁过 ≠ 模型可信。门禁只保证"数字自洽、证据齐备"，
> 保证不了"账背后有真实交易"。后者需外部凭证核验，也是持牌审计的领域。
