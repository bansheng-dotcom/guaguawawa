# 招聘评分卡（Hiring Scorecard）

> 一句话定位：**这个技能存在的意义，是防止"面试凭印象，决策凭感觉，出事无痕迹"**。
> 招聘里最贵的错误不是招错人，而是**没有可复核的判断依据**：
> 岗位需求没写清、候选人评估没留证据、结论只有一个"感觉不太合适"。
> 没有评分卡的面试，本质上是在给第一印象找理由。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这个岗位要招什么样的人」「帮我写岗位需求」
- 「这个人怎么样」「面试该问什么、怎么打分」
- 「能不能发 Offer 了」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 谈薪 / 定级 / 签合同 | `r03` 财务合规 + 创始人 | 本技能只判"匹配度"，不判"给多少钱" |
| 背景调查 / 学历核验 | 外部机构 | 本技能不负责真实性核验 |
| 批量排名 / 排序候选人 | **拒绝** | 评分卡用于单个候选人**逐项打分**，不用于横向排名 |
| 组织架构调整 | `r16` 组织域 + `r01` | 那是编制与组织决策 |

**最小可开工输入**：**岗位需求（做什么、要什么能力）+ 一份候选人材料**。只有岗位需求时，可先出评分卡模板。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 岗位名称与职责 | 必需 | 缺则无法定义维度，必须问 |
| 必选项（must-have） | 必需 | 缺则按同类岗位默认补全并标注 |
| 加分项（nice-to-have） | 建议 | 缺则标注"仅按必选项评" |
| 候选人材料 | 评估时必需 | 缺则只出评分卡，不评分 |
| 面试记录/证据 | 评估时必需 | 缺则该项记"未验证"，不得给分 |
| 编制与预算 | 建议 | 缺则标注"编制未确认"，不影响评分卡 |

**追问纪律**：最多一轮，只问**岗位要做什么、必选项是什么**。其余按同类默认并标注。

## §3 执行流水线（Workflow）

### Step 1 · 岗位需求（必选项 ≤5，加分项 ≤3）
```bash
python harness.py opening --input <岗位需求.json>
```
判据：
- `required`：**必选项 ≤ 5 条**（超过 5 条基本等于"什么都想要"）；
- `vacancies`：招聘人数 ≥ 1；
- 每条必选项必须**可验证**（能通过面试题、作品或测试判断）。

**反例**：「沟通能力强」「有责任心」——不可验证，无法打分。
**正例**：「能独立把一个模糊需求拆成 3 个可交付里程碑，并给出排期」。

- **产出**：`required[]` + `nice_to_have[]` + `vacancies`
- **过关条件**：`harness.py opening` 退出码 0

### Step 2 · 评分维度与权重（先定后评，不许事后调）
每个维度必须有：**维度名 / 权重 / 判据 / 证据来源**。

| 维度示例 | 权重 | 判据 | 证据来源 |
|---|---|---|---|
| 专业硬技能 | 40% | 能在 60 分钟内完成 X 类任务 | 现场作业 |
| 问题拆解 | 25% | 能把模糊需求拆成里程碑 | 面试题 + 追问 |
| 协作沟通 | 20% | 能说清一次冲突的处理过程 | 行为面试 |
| 价值观匹配 | 15% | 对质量与速度的取舍有一致判断 | 情景题 |

**铁律**：权重必须在见候选人**之前**定死。见了人再调权重，等于给印象配分数。

- **产出**：维度表 + 权重
- **过关条件**：权重合计 100%，每维都有判据与证据来源

### Step 3 · 逐项打分（每项必须留证据）
```bash
python harness.py applicant --input <候选人评估.json>
```
每个维度打分必须带三件：`score`（1–5）/ `evidence`（面试原话或作品位置）/ `verdict`。

| 分 | 含义 |
|---|---|
| 5 | 明显超出要求，有直接证据 |
| 4 | 满足要求，有直接证据 |
| 3 | 基本满足，证据间接 |
| 2 | 不满足，有反证 |
| 1 | 明显不满足 |

**没有证据的维度记 `未验证`，不得给 3 分充数**——3 分是最容易被滥用的"和稀泥分"。

- **产出**：逐项分 + 证据
- **过关条件**：`harness.py applicant` 退出码 0（含 email/status 合法性）

### Step 4 · 结论三选一（不给排名）
| 结论 | 条件 |
|---|---|
| **推进** | 所有必选项 ≥ 3 分，且加权总分 ≥ 阈值 |
| **待定** | 有 1–2 项未验证，补验证后可定 |
| **不推进** | 任一必选项 ≤ 2 分 |

**禁止**：给候选人排名、给"综合印象分"、用"感觉不合适"作为唯一理由。

- **产出**：结论 + 关键依据（哪几项决定）
- **过关条件**：结论与分数一致，且写明决定项

### Step 5 · Offer 前置校验
```bash
python harness.py offer --input <Offer.json>
```
校验前置状态链：**面试完成 → 评估推进 → 编制确认 → 薪酬审批 → 才能发 Offer**。
门禁实测：前置状态不合法即 FAIL（`offer.prior`）。

- **产出**：`offer` 结论
- **过关条件**：`harness.py offer` 退出码 0

| # | 交付物 | 载体 | 骨架出处 |
|---|---|---|---|
| 1 | 岗位需求（必选项 ≤5 / 加分项 ≤3） | `.json` | `examples/opening.json` |

| 3 | 候选人评分卡（逐项分 + 证据） | `.json` | `examples/applicant.json` |
| 4 | 结论与决定项 | `.md` | 同上 §四 |
| 5 | Offer 前置校验结论 | 终端 JSON | `harness.py offer` |

- 命名：`hiring_<岗位短码>_<候选人代号>_<YYYYMMDD>.json`
- **评分卡必须落盘**；口头"我觉得还行"不构成招聘决策依据。

## §5 质量门（一票否决，不过不给交付）

1. **必选项 ≤ 5 条**，且每条可验证（`opening.required`）；
2. **招聘人数 ≥ 1**（`opening.vacancies`）；
3. **权重合计 100%**，且见面之前已定；
4. **每个维度打分都有证据**，无证据记"未验证"（`applicant.*`）；
5. **候选人状态合法**（`applicant.status`）、**邮箱格式合法**（`applicant.email`）；
6. **结论与分数一致**，且写明决定项；
7. **Offer 前置状态链完整**（`offer.prior`）。

> 验收命令：`python harness.py opening|applicant|offer --input <json>`
> 命中任一项不过 → 回 §3 对应 Step，**不允许事后调权重让结论成立**。

---

## §6 交付前自检清单

- [ ] 必选项不超过 5 条，每条都能通过具体方式验证
- [ ] 权重在见候选人之前就定好了（改动痕迹可查）
- [ ] 每个维度分都附了证据（面试原话/作品位置/作业结果）
- [ ] 没有把未验证项打 3 分充数
- [ ] 结论是推进/待定/不推进三选一，不是"综合感觉"
- [ ] 写清了"哪几项决定了结论"
- [ ] 没有给候选人排名或排序
- [ ] Offer 前已确认编制、薪酬审批、评估结论
- [ ] 评估中没有任何歧视性维度（性别/年龄/婚育/籍贯）
- [ ] 三道门禁均退出码 0

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 必选项写 8 条，"什么都要" | ≤5 条，且每条可验证 |
| EX-02 | 必选项写"沟通能力强" | 写成可验证行为："能说清一次冲突的处理过程" |
| EX-03 | 见完人再调权重 | 权重必须见人前定死，事后调＝给印象配分 |
| EX-04 | 未验证的维度打 3 分 | 记"未验证"，3 分是最容易滥用的和稀泥分 |
| EX-05 | 打分不带证据 | 每项必须附面试原话或作品位置 |
| EX-06 | 结论写"综合感觉不太合适" | 三选一 + 写明决定项（哪几项不达标） |
| EX-07 | 给候选人排名 | **禁止排名**；评分卡用于单人逐项评估 |
| EX-08 | 前置未完成就发 Offer | 面试→评估→编制→薪酬审批，链条完整才能发 |
| EX-09 | 评估维度含年龄/婚育/籍贯 | 违法且无效；一律禁止 |
| EX-10 | 用"文化匹配"当否决理由 | 必须落到具体行为证据，否则等于"我不喜欢他" |
| EX-11 | 面试题与评分维度不对应 | 每道题必须对应某个维度的判据 |
| EX-12 | 候选人材料不全仍给结论 | 缺关键材料只能出"待定"，不出"推进" |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `harness.py` 跑不了 | 按 §6 人工逐项核对，标注「未跑门禁」；**不得发出 Offer** |
| 只有岗位需求无候选人 | 只交付评分卡模板，不评分 |
| 缺面试记录 | 该维度记"未验证"，结论最多"待定" |
| 用户要求"给这几个人排个序" | 拒绝排名；可逐个出评分卡，由人综合决定 |
| 用户要求按年龄/婚育筛 | 明确拒绝（违法），并给合规替代（按能力维度评估） |
| 薪酬未审批 | 标注"薪酬未审批"，不生成 Offer |
| 编制未确认 | 标注"编制未确认"，可出评估不出 Offer |

**明确不做**
- 不谈薪、不定级、不签合同（归 `r03` + 创始人）；
- 不做背景调查与真实性核验（外部机构）；
- 不排名、不排序候选人；
- 不承诺录用结果。
