# 评分卡设计与反歧视规则（scorecard-design）

> 被 §3、§5、§7 按需引用。版本：v2.0.0（项目自建，v1）

---

## 一、岗位需求的写法

```json
{
  "title": "数据分析师（增长方向）",
  "vacancies": 1,
  "required": [
    "能独立把'转化率为什么跌'拆成 3 个可验证假设并设计验证",
    "熟练写窗口函数级 SQL（能现场手写）",
    "能向非技术人员讲清一个统计结论的局限"
  ],
  "nice_to_have": ["做过 A/B 实验的平台侧设计", "有增长团队协作经验"]
}
```

| 规则 | 判据 |
|---|---|
| 必选项 ≤ 5 | 超过 5 条基本等于"什么都想要"，筛不出人 |
| 每条可验证 | 能通过面试题/作业/作品**具体判断** |
| 不写性格形容词 | "有责任心""沟通强"不可验证，换成行为 |

**可验证性检测**：把每条必选项读一遍，问"我能设计一道题来判断它吗？"
答不上来 → 这条要重写。

## 二、权重设计（见面之前定死）

| 维度 | 建议权重 | 判据 | 证据来源 |
|---|---|---|---|
| 专业硬技能 | 35–45% | 现场作业或作品 | 作业评分 |
| 问题拆解 | 20–30% | 面试题 + 追问 | 面试记录 |
| 协作沟通 | 15–25% | 行为面试（讲一次冲突） | 面试记录 |
| 价值观/质量观 | 10–20% | 情景题（质量 vs 速度） | 面试记录 |

**三条纪律**
1. 权重合计必须 **100%**；
2. 权重在**见到候选人之前**确定，改动要留痕（谁改的、为什么）；
3. 任一单项权重不超过 **50%**——单维决定一切时，其他维度的面试就白做了。

## 三、打分规则（1–5 分，必须带证据）

| 分 | 定义 | 证据要求 |
|---|---|---|
| 5 | 明显超出要求 | 有直接证据（作业/作品/追问细节） |
| 4 | 满足要求 | 有直接证据 |
| 3 | 基本满足 | 有间接证据 |
| 2 | 不满足 | 有反证 |
| 1 | 明显不满足 | 有反证 |
| **未验证** | 没问到 / 没材料 | —— |

**关于 3 分**：3 分是评分卡里最危险的分数——它同时可以表示"刚好够"和"我不确定"。
所以规则是：**能验证就用 1/2/4/5，不确定就写"未验证"**，不要用 3 分和稀泥。

## 四、结论三选一

| 结论 | 条件 | 输出 |
|---|---|---|
| **推进** | 所有必选项 ≥3，加权总分 ≥ 阈值 | 决定项（哪几项支撑） |
| **待定** | 1–2 项未验证 | 待补验证清单 |
| **不推进** | 任一必选项 ≤2 | 决定项（哪几项不达标） |

### 禁止清单

| 禁止 | 为什么 |
|---|---|
| 给候选人**排名** | 评分卡是单人逐项工具；排名会诱导"相对好看"而非"真的合适" |
| 给**综合印象分** | 印象分无法复核，等于把判断黑箱化 |
| 以**"感觉不合适"**为唯一理由 | 无法复核，也无法给候选人反馈 |
| 用**"文化匹配"**当否决项 | 除非落到具体行为证据，否则常是偏见的外衣 |

## 五、反歧视红线（违法成本最高的部分）

| 禁止评估的维度 | 说明 |
|---|---|
| 性别、婚育状况、生育计划 | 常见问句："你打算什么时候要孩子"——违法 |
| 年龄 | 除极少数法定岗位 |
| 籍贯、民族、地域 | —— |
| 宗教信仰、政治面貌 | 除法定要求 |
| 健康状况 | 除岗位确有法定体检要求 |
| 外貌、身高体重 | 除特殊表演类岗位 |

**若岗位确实有法定限制**（如特种作业证书），必须写明**法律依据**，而不是写成"我们要求"。

## 六、Offer 前置状态链

```
面试完成 → 评估结论=推进 → 编制确认 → 薪酬审批 → 方可发 Offer
```

| 断点 | 后果 |
|---|---|
| 评估未推进就发 Offer | 门禁判 `offer.prior` 失败 |
| 编制未确认 | 可能招进来没坑位 |
| 薪酬未审批 | 承诺无法兑现，最伤雇主品牌 |

> 这四步的顺序不能换。**先承诺再审批**是招聘里最常见的自伤。

---

## 七、与门禁的对应关系

| 门禁 | 覆盖哪一节 | 判不了什么 |
|---|---|---|
| `harness.py opening` | §一 必选项数量、人数、必填字段 | 判不了必选项是否可验证 |
| `harness.py applicant` | §三 分数结构、§四 status/email 合法性 | 判不了分数是否诚实 |
| `harness.py offer` | §六 前置状态链 | 判不了薪酬是否合理 |

> 门禁保证"流程没跳步、结构没缺"，**保证不了"这个人合适"**。
> 后者只有面试官能给，且必须落到证据上。
