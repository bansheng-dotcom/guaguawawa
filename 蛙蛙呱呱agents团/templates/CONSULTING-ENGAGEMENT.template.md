# 咨询项目工作簿（Engagement Workbook v1）

> 用法：每个咨询项目复制一份，按 8 阶段推进；每阶段有「输入门」与「评审门」，不过门不进下一阶段。
> 元数据必须填，结论必须能沿 YAML 链回溯到问题。

```yaml
engagement:
  client: ""            # 客户/业务单元
  engagement_id: ""     # 项目编号
  partner: r01          # 拍板人
  lead: r05             # 项目经理
  team: [r06, r03, r15] # 参与角色
  start: ""             # YYYY-MM-DD
  deadline: ""
  decision: ""          # 本次要支持的决策（一句话）
  success_metric: ""    # 决策质量如何衡量
  scope_out: ""         # 明确不做什么
```

## 阶段 1 · 定义问题（Frame the Question）

- [ ] 决策问题一句话（不是「分析一下」）
- [ ] 决策者与最怕错的地方
- [ ] 成功标准（指标 + 阈值 + 时间）
- [ ] 非目标（明确不回答什么）
- [ ] 输入门：客户提供背景、约束、已有数据
- [ ] 评审门：partner 确认问题定义

**产出**：`01-question.md`

## 阶段 2 · 逻辑地图（Map the Logic / MECE）

| 分支 | 要回答 | 假设 | 需要数据 | 方法 | owner | 状态 |
|---|---|---|---|---|---|---|
| B1 | | | | | | |
| B2 | | | | | | |
| B3 | | | | | | |

- [ ] 分支互斥且穷尽（不重叠、不遗漏）
- [ ] 每条分支有可证伪假设
- [ ] 标出 critical branch（最可能推翻结论的那支）
- [ ] 输入门：数据可得性初判
- [ ] 评审门：partner 确认问题树

**产出**：`02-issue-tree.md`

## 阶段 3 · 聚焦（Focus the Work / 80/20）

- [ ] 选出 ≤3 个「最可能改变答案」的分支
- [ ] 写明其余分支为什么先不做（成本/边际影响）
- [ ] 评审门：partner 确认聚焦计划

**产出**：`03-focus.md`

## 阶段 4 · 分析计划（Plan the Analyses）

| 工作流 | 数据源 | 方法 | 输出 | 负责人 | 截止 |
|---|---|---|---|---|---|
| | | | | | |

- [ ] 每条工作流有数据来源与降级方案
- [ ] 每条工作流有输出契约（claim/evidence/confidence/falsifier）
- [ ] 评审门：partner 确认资源与时间

**产出**：`04-analysis-plan.md`

## 阶段 5 · 执行分析（Run the Analyses）

- [ ] 证据台账：每条 finding 挂来源、口径、级别、区间
- [ ] 冲突单列，不取平均
- [ ] 缺口写「缺什么/影响什么/怎么补」
- [ ] 评审门：R04 事实与方法核查

**产出**：`05-findings.md` + `evidence-ledger.json`

## 阶段 6 · 整合答案（Integrate the Answer）

- [ ] 把 findings 收敛成 1—3 条核心信息（answer-first）
- [ ] 每条信息有机制解释与竞争解释排除
- [ ] 评审门：partner 挑战会（红队三问）
- [ ] 产出 `06-answer.md`

## 阶段 7 · 形成建议（Shape the Recommendation）

- [ ] ≥3 个选项（做/不做/条件做）
- [ ] 每个选项：经济性、风险、前置条件、时间
- [ ] 负责人、阈值、KPI、回滚条件
- [ ] 评审门：R03 经济性复核 + partner 签字

**产出**：`07-recommendation.md`

## 阶段 8 · 打包交付（Package the Story）

- [ ] 一页纸执行摘要（结论先行）
- [ ] 董事会/管理层材料（memo 或 deck 大纲）
- [ ] 附录：全量证据、缺口、复盘
- [ ] 评审门：R04 终审 + partner 签发

**产出**：`08-deliverable/`

## 交付物清单（缺一不算完成）

| # | 交付 | 标准 |
|---|---|---|
| 1 | 问题定义 | 一句话决策 + 成功标准 + 非目标 |
| 2 | 问题树 | MECE + 假设 + critical branch |
| 3 | 分析计划 | 数据源 + 方法 + 降级 + 负责人 |
| 4 | 发现台账 | 四件套 + 冲突单列 |
| 5 | 建议书 | 3 选项 + 经济性 + 风险 + KPI |
| 6 | 执行摘要 | 结论先行，1 页 |
| 7 | 价值追踪 | 基线 + 目标 + 复盘日 |

## 复盘（项目结束 2 周内）

- [ ] 哪条假设错了？为什么？
- [ ] 哪个数据源缺失导致返工？
- [ ] 哪一步方法可以写回 method pack？
- [ ] 客户评分（5 维：问题理解/证据/洞察/可执行/沟通）
