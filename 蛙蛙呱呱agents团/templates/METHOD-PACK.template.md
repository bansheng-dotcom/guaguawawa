# 方法包模板（METHOD PACK v1）

> 用法：每个角色复制到 `rXX-*/references/method-pack.md`，按 6 段填写。
> 验收：`python scripts/audit_method.py rXX` ≥ 80 分；每段至少 3 条可检查项。
> 原则：**方法包写「怎么想」，SKILL.md 写「什么时候用、做完交什么」。**

## 1. 决策问题（Decision Question）

- 这个角色被找来，最终要支持哪一个**决策**？（不是「分析一下」，是「选 A 还是 B / 做不做 / 什么时候做」）
- 决策者是谁？他最怕错在哪？
- 判断成功的标准是什么（决策质量，不是报告厚度）？

**必须写**：一句话决策问题 + 决策者 + 成功标准 + 本次不回答什么（非目标）。

## 2. 问题树（Issue Tree，MECE）

- 把决策问题拆成 3—5 个互斥且穷尽的分支（MECE：不重叠、不遗漏）。
- 每个分支写：**要回答什么 → 需要什么数据 → 用什么方法 → 产出什么证据**。
- 标出「最可能推翻结论的分支」（critical branch），资源优先给它。

**反模式**：按部门拆（市场/运营/财务）而不是按问题拆；分支之间互相包含；只列问题不列数据与方法。

## 3. 假设与证伪（Hypothesis & Falsification)

- 每个分支先给一个**可证伪**的假设（含方向、幅度、时间），不是「可能有影响」。
- 每条假设必须写：**支持证据 / 反对证据 / 杀死标准（什么情况下我认错）**。
- 至少列 **2 个竞争解释**，并说明用什么证据排除。

**反模式**：假设不可测；只找支持证据；结论出来后才补假设。

## 4. 证据分级与来源（Evidence Grading）

| 级别 | 定义 | 用法 |
|---|---|---|
| A | 官方/一手、可复算、口径明确（统计公报、交易所、政府监测） | 可进结论与合同 |
| B | 行业/二手、口径基本清楚（协会、研究机构、市场报价） | 只做方向与区间 |
| C | 估算/假设/单点访谈 | 必须标注，且做敏感性 |

**规则**：每条结论挂来源 ID；同名不同口径必须单列；缺口要写「缺什么、影响什么、怎么补」。

## 5. 分析方法与陷阱（Method & Traps）

- 本角色**默认方法**（3—5 个）：例如匹配对照、同期基线、分解归因、情景分析、单位经济。
- 每个方法写：适用条件、最小样本、输出字段、常见误用。
- **陷阱清单**：本行业最容易犯的 5 个错（如把规格差当区域差、把波动小当水平正常、用单点当趋势）。

## 6. 输出契约（Output Contract）

每条结论必须四件套：

```
claim        一句话结论（含方向 + 幅度 + 时间/范围）
evidence     来源 ID + 观测行/页码 + 口径
confidence   A/B/C + 区间（没有区间就写「点估计，未验证」）
falsifier    什么新证据会推翻它
```

**门禁**：缺任一项 → 不得进入报告首页；headline 缺对照/基线/匹配 → 直接 FAIL。

## 附：自检 10 问（交付前逐条回答）

1. 我回答的是决策问题，还是一个数据问题？
2. 问题树有没有重叠或遗漏？critical branch 找到了吗？
3. 每个假设都能被证伪吗？杀死标准写了吗？
4. 竞争解释列了几个？排除了几个？
5. 每个数字都能回指观测吗？口径冲突单列了吗？
6. 有对照组/基线吗？匹配了吗？
7. 结论带区间吗？没有区间的地方标了吗？
8. 最可能错的地方是什么？我怎么知道它错了？
9. 建议的动作有负责人、阈值、时间吗？
10. 如果决策者只有 30 秒，我先说哪一句？
