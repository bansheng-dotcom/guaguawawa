# 契约、切片与鉴权（web-app-delivery）

> 被 §3、§5、§7 按需引用。版本：v2.0.0（项目自建，v1）

---

## 一、模块契约表（先定，再写）

```json
{"modules": [
  {"name": "auth",    "inputs": ["credential"], "outputs": ["token"]},
  {"name": "billing", "inputs": ["token"],      "outputs": ["invoice"]}
]}
```

**三条判据**

| 判据 | 不满足的后果 |
|---|---|
| 每个模块 inputs/outputs 都非空 | 无法对接，等于没设计 |
| 每个 outputs 都有下游消费 | 孤儿输出＝白写的代码 |
| 每个 inputs 都有上游生产 | 无源输入＝永远跑不通 |

**画法**：把所有模块的 outputs 列成一列、inputs 列成一列，连线。
连不上的地方就是契约断裂点——**写代码前先连一遍，比写完再查便宜十倍**。

## 二、端到端切片的四个必段

| 段 | 判据 | 缺了会怎样 |
|---|---|---|
| 入口 | 用户从哪触发 | 不知道从哪开始 |
| 业务逻辑 | 中间做了什么判断/计算 | 只有 CRUD 没有业务 |
| 数据落库 | 写进哪里、什么结构 | 刷新就没了 |
| 可见结果 | 用户看到什么 | 做完了但"点了没反应" |

**切片的粒度**：一条链路能在 1–3 天内跑通。超过就再切小。

> "只做前端"或"只做后端"都不是切片——它们是切片的两半，各自都无法验证。

## 三、鉴权三规则（越权是安全事故，不是 bug）

### 规则一：服务端校验

```text
❌ 前端 if (!isAdmin) hideButton()
✅ 服务端每个受保护接口独立验权（中间件或装饰器）
```

前端隐藏只是体验优化，**攻击者可以直接调接口**。

### 规则二：默认拒绝

| 写法 | 风险 |
|---|---|
| 白名单（默认拒，显式放行） | ✅ 新接口忘了配 = 进不去，安全 |
| 黑名单（默认放行，显式拦） | ❌ 新接口忘了配 = 谁都能进，事故 |

**新增接口默认进不去**，这个"不方便"是刻意的。

### 规则三：越权测试

| 测试 | 做法 |
|---|---|
| 横向越权 | 用 A 账号的 token 访问 B 账号的资源 |
| 纵向越权 | 用普通用户 token 访问管理员接口 |
| 未登录 | 不带 token 访问受保护接口 |

三条都必须被拒（401/403），且**返回体不泄露资源是否存在**。

## 四、依赖方向

```
入口层（路由/控制器）
    ↓
业务层（用例/服务）
    ↓
数据层（仓储/DAO）
    ↓
公共层（工具/类型）
```

**只能向下依赖**。反向依赖（数据层 import 业务层）会造成：
循环依赖、无法单测、改一处崩一片。

**检查法**：看 import 图有没有环。有环就抽公共模块。

## 五、交付材料四件（缺一不可）

| 件 | 内容 | 反例 |
|---|---|---|
| 改动清单 | 行为级变化 | "改了 12 个文件" |
| 复现步骤 | 可直接执行 | "按正常流程" |
| 验证命令 | 可粘贴 | "跑一下测试" |
| 影响面 | 哪些模块/调用方受影响 | 不写 |

## 六、与门禁的对应关系

| 门禁 | 覆盖哪一节 | 判不了什么 |
|---|---|---|
| `agent.py spec spec` | §一 契约结构 | 判不了契约**是否合理**（业务上该不该这么分） |
| `agent.py spec arch` | §四 依赖结构 | 判不了分层是否恰当 |
| `agent.py fullstack feature` | §二 切片字段 | 判不了链路**真的**跑通了（需实测） |
| `agent.py fullstack auth` | §三 规则结构 | 判不了服务端**真的**验了（需越权实测） |
| `harness.py materials` / `testreport` | §五 材料与报告 | 判不了内容质量 |

> 门禁保证"结构完整"，保证不了"真的能跑"。
> **越权测试与端到端实跑，是这两件唯一能证伪的事，必须人工做。**
