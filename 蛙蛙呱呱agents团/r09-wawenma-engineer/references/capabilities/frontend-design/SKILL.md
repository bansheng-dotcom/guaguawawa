# 前端界面设计（Frontend Design）

> 一句话定位：**这个技能存在的意义，是防止「看起来挺好看，一用就处处别扭」**。
> 界面设计的失败很少是"丑"，而是六件可判定的事没做：层级不清、间距乱、对比度不够、
> 组件状态只做了正常态、只在一个宽度下看过、键盘和读屏用不了。
> 这六件事都能查，所以没理由靠"感觉"。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这个页面怎么设计」「帮我看看这个界面」
- 「给前端写个设计规格」「间距字号怎么定」
- 「为什么用起来别扭」「哪里该先改」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 直接写出页面代码 | `r08` 原型 / `r09` 本角色的实现域 | 本包只出设计规格与判定 |
| 品牌 VI 从零（标志/字库/手册） | `r10` 设计官 | 品牌设计是独立范畴 |
| 电商主图与详情页 | `r10` 的 `ecommerce-designer` | 那是转化导向的视觉，不是界面 |
| 可用性测试与用户访谈 | `r07` 的 `user-research-toolkit` | 本包给判据，实测归研究 |

**最小可开工输入**：**一句"给谁用什么"**（用户 + 核心任务），或**一张现有界面截图**。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 目标用户与核心任务（一句话） | 必需 | 没任务就没有层级依据，必须问 |
| 界面截图或描述 | 设计时必需 | 无则可出规格，不可评审 |
| 技术约束（框架/组件库） | 建议 | 缺则给框架无关的令牌与规范 |
| 品牌令牌（色板/字体） | 建议 | 缺则给建议方案并标注"需品牌确认" |
| 目标断点 | 建议 | 缺则按 375 / 768 / 1280 三档 |

**追问纪律**：最多一轮，只问**给谁用、要完成什么任务**。其余按默认断点与令牌推进。

## §3 执行流水线（Workflow）

### Step 1 · 定主任务与层级（先定"一眼看到什么"）
一句话写清主任务，然后回答：**用户进来第一眼该看到什么、第二眼、第三眼**。
三眼之外的内容，要么下沉，要么删。

| 层级 | 判据 |
|---|---|
| 一级 | 不看就会做错事的信息（当前状态/主操作） |
| 二级 | 需要时才看的依据（详情/参数） |
| 三级 | 极少用（设置/帮助） |

**反例**：把"取消"和"确认"做成同样的视觉权重——这不是设计问题，是事故。

- **过关条件**：能用一句话说出第一眼该看什么

### Step 2 · 间距与字号阶梯（只用刻度，不用感觉）
- 间距只用 **4 / 8 / 12 / 16 / 24 / 32 / 48** 七档；
- 字号 ≤ 5 级（如 12 / 14 / 16 / 20 / 28）；
- 行高：正文 1.5、标题 1.2–1.3；
- 正文最小 **14px**（移动端不低于 14，可读性下限）。

**判据**：任何间距值都必须能在刻度里找到。出现 13px、18px 就是拍脑袋。

### Step 3 · 色彩与对比度（可测量，不靠眼）
| 用途 | 对比度要求 |
|---|---|
| 正文文字与背景 | **≥ 4.5:1**（WCAG AA） |
| 大字（≥18px 粗体或 ≥24px） | ≥ 3:1 |
| 图标/边框等非文本 | ≥ 3:1 |
| 禁用态 | 允许低于 3:1，但必须**另加语义**（不能只靠颜色变淡） |

**颜色不能是唯一信息载体**：错误状态除了红色，必须有图标或文字。

### Step 4 · 组件状态覆盖（最常漏的一步）
每个交互组件至少覆盖 **6 态**：

```
默认 / 悬停 / 焦点 / 禁用 / 加载 / 空或错误
```

| 状态 | 常见漏洞 |
|---|---|
| 焦点 | 只有鼠标样式，没有 `:focus-visible` 环 |
| 加载 | 点完没反馈，用户重复点击 |
| 空 | 空白页，没有"为什么空、怎么开始" |
| 错误 | 只说"出错了"，没说哪错、怎么改 |
| 禁用 | 只变灰，不说明为什么不能点 |

- **过关条件**：每个组件在规格里都列了 6 态

### Step 5 · 响应式断点（三档起步）
| 断点 | 判据 |
|---|---|
| 375 | 无横向滚动；触控目标 ≥ 44×44 |
| 768 | 栅格从 1 列转 2 列 |
| 1280 | 内容最大宽度受限（如 1200px），不无限拉伸 |

**必须验证**：在 375 宽度下没有横向滚动条。这是最容易被忽略也最容易被用户骂的一条。

### Step 6 · 可访问性（可判定的四条）
| 检查 | 判据 |
|---|---|
| 键盘可达 | Tab 能走完全部可交互元素，顺序合理 |
| 焦点可见 | 每个焦点都有可见环，不能 `outline: none` 了事 |
| 语义化 | 标题层级 h1→h6 不跳级；按钮用 button 不用 div |
| 替代文本 | 有意义的图有 alt，装饰图 alt 为空 |

## §5 质量门（一票否决，不过不给交付）

1. **主任务一句话说清**，且第一眼元素与它一致；
2. **间距全部落在 4/8/12/16/24/32/48 刻度内**；
3. **正文字号 ≥14px**，字号级数 ≤5；
4. **正文对比度 ≥4.5:1**，非文本 ≥3:1；
5. **每个交互组件覆盖 6 态**（含焦点、加载、空、错误）；
6. **375 宽度无横向滚动**，触控目标 ≥44×44；
7. **键盘可走完、焦点可见、语义化、替代文本**四项齐全。

> 验收命令：`python harness.py materials --input <材料清单.json>`（本角色材料门禁）
> 界面本身的六条判据无自动门禁（输入是界面而非固定 schema），按 §6 逐项人工核对，未核对项在交付物标注「未核」。
> 命中任一项不过 → 回 §3 对应 Step 重做。

## §6 交付前自检清单

- [ ] 我能一句话说出"用户进来第一眼看什么"
- [ ] 主操作与取消/危险操作在视觉权重上明显不同
- [ ] 所有间距值都能在 4/8/12/16/24/32/48 里找到
- [ ] 字号不超过 5 级，正文 ≥14px，行高按 1.5 / 1.2 设
- [ ] 正文对比度用工具量过 ≥4.5:1，不是肉眼判断
- [ ] 颜色不是唯一信息载体（错误态有图标或文字）
- [ ] 每个交互组件都写了 6 态，焦点环没被 `outline:none` 掉
- [ ] 375 宽度下我实际拉过，没有横向滚动
- [ ] 触控目标 ≥44×44
- [ ] Tab 键能走完全部可交互元素，顺序合理
- [ ] 标题层级不跳级，按钮用语义标签
- [ ] 有意义的图有 alt，装饰图 alt 为空

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 所有元素视觉权重差不多 | 一级信息必须显著更重；主操作与取消要能一眼分开 |
| EX-02 | 间距随手写 13px / 18px | 只用 4/8/12/16/24/32/48 七档 |
| EX-03 | 字号 6–8 级 | 不超过 5 级；正文 ≥14px |
| EX-04 | 对比度靠肉眼"看着够" | 用工具量，正文 ≥4.5:1 |
| EX-05 | 只用颜色表达错误 | 颜色 + 图标 + 文字，三重编码 |
| EX-06 | 组件只做正常态 | 六态齐全：默认/悬停/焦点/禁用/加载/空或错 |
| EX-07 | `outline: none` 去掉焦点环 | 保留 `:focus-visible` 可见环，或用自定义替代 |
| EX-08 | 只在 1280 宽度看过 | 375 / 768 / 1280 三档都过，尤其 375 无横向滚动 |
| EX-09 | 点击目标只有图标那么大 | 触控目标 ≥44×44，视觉可以小但热区要够 |
| EX-10 | 加载时没反馈，用户重复提交 | 提交即禁用 + loading，成功/失败都有明确反馈 |
| EX-11 | 空状态留白一片 | 说明"为什么空 + 怎么开始" |
| EX-12 | 错误只说"出错了" | 说清哪错了、怎么改、是否可重试 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 只有截图没有实现 | 只出评审与规格，不出代码 |
| 无品牌令牌 | 给建议色板并标注"需品牌确认"，不擅自定稿 |
| 无设计工具 | 用文字描述版式骨架 + 令牌表，仍算完整交付 |
| 组件库已固定 | 按库的令牌映射，不另造一套 |
| 对比度算不了 | 给出颜色值让实现方用工具核，标注"未实测" |
| 用户要求"照这个竞品抄" | 可借鉴结构与层级，不复制其视觉资产与文案 |
| 需求涉及暗色模式 | 两套对比度都要过，不能只调背景色 |

**明确不做**
- 不写生产代码（归实现域 / `r08` 原型）；
- 不做品牌 VI 从零（归 `r10`）；
- 不做电商主图与详情页（归 `r10` 的 `ecommerce-designer`）；
- 不做可用性测试与用户访谈（归 `r07` 的 `user-research-toolkit`）。
