# 负向测试集（misuse cases）

> **本包为规范型**（`verify: "null"`），没有可自动断言的固定 schema，
> 因此本表是**人工评审清单**，逐条由评审者判真假。
> 版本：v2.0.0

---

## 一、可判定项（P0：会导致误操作或不可用）

| # | 错误做法 | 为什么算错 | 怎么验 |
|---|---|---|---|
| MU-01 | 主操作与取消/危险操作视觉权重相同 | 误触且不可挽回 | 截图灰化后仍能一眼分清主次吗 |
| MU-02 | `outline: none` 去掉焦点环且无替代 | 键盘用户完全失去位置 | Tab 走一遍，看有没有可见环 |
| MU-03 | 375 宽度出现横向滚动 | 手机上直接不可用 | 设备模拟 375 横向拖动 |
| MU-04 | 自定义 div 当按钮，无 tabindex/role | 键盘进不去、读屏读不出 | Tab 能否到达该元素 |
| MU-05 | 只用颜色表达错误/成功 | 色盲与灰度场景失效 | 灰度截图后信息是否还在 |
| MU-06 | 提交后无 loading、按钮不禁用 | 用户重复提交产生重复数据 | 点击后立刻观察状态 |

## 二、可判定项（P1：影响理解与效率）

| # | 错误做法 | 为什么算错 | 怎么验 |
|---|---|---|---|
| MU-07 | 组件只做正常态 | 真实交互一用就露馅 | 按 §4 六态矩阵逐格打勾 |
| MU-08 | 空态留白一片 | 用户不知道能做什么 | 空态是否回答了"为什么空/怎么开始" |
| MU-09 | 错误提示只说"出错了" | 用户无法自救 | 是否说清哪错/怎么改/可否重试 |
| MU-10 | 标题层级跳级（h1→h3） | 读屏导航混乱 | 看 heading 序列 |
| MU-11 | placeholder 代替 label | 一输入提示就消失 | 聚焦并输入后还能否知道字段含义 |
| MU-12 | 触控目标小于 44×44 | 手机误触率高 | 量热区尺寸（不是图标尺寸） |

## 三、可判定项（P2：一致性）

| # | 错误做法 | 为什么算错 |
|---|---|---|
| MU-13 | 间距出现 13px / 18px | 不在 4/8/12/16/24/32/48 刻度内 |
| MU-14 | 字号超过 5 级 | 视觉节奏失控 |
| MU-15 | 正文小于 14px | 可读性下限 |
| MU-16 | 正文对比度低于 4.5:1 | AA 不达标（大字可 3:1） |

## 四、机器可跑的一道门禁

```bash
python agent.py uiux screen --input <界面规格.json>
```

它校验界面规格的结构（分区 ≥3、组件带状态、五态覆盖、a11y 字段），
**校验不了"好不好看"和"对比度是否真的够"**——后者用工具量。

---

## 五、自检

- [ ] P0 六条全部人工验过，没有一条"看起来没问题"就跳过
- [ ] 375 宽度实际拉过，不是想象的
- [ ] 对比度用工具量过，不是肉眼判断
- [ ] 六态矩阵每一格都打勾，空态能回答两个问题
- [ ] 间距/字号/对比度三项能用刻度表逐条对照

> **纪律**：这类规范型能力最容易"写完就以为做到了"。
> 六条 P0 里任何一条没验，这份界面规格都不该交付。
