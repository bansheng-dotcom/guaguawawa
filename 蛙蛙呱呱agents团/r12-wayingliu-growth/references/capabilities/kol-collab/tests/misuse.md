# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表为人工评审清单。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 |
|---|---|
| MU-01 | 四维筛选（匹配度一票否决），非只看粉丝量 |
| MU-02 | brief 四件齐备：卖点 ≤3 / 必提 / 禁提 ≥3 / 交付物 |
| MU-03 | 佣金结构三选一且与目标（曝光/带货/背书）一致 |
| MU-04 | 验收 = 交付物 + 保留 ≥30 天 + 窗口内发布，不含效果 |
| MU-05 | 归因入口写死（口令/专属链接/UTM） |
| MU-06 | 六条合规红线写进 brief 并要求确认 |

## 二、软门（§6 自检）

| # | 常见错法 |
|---|---|
| MU-06 | 我筛人不只看粉丝量，匹配度不过关的我直接排除了 |
| MU-07 | brief 里卖点不超过 3 个 |
| MU-08 | 我写了「必提」（规格/售后），不只是卖点 |
| MU-09 | 我写了 ≥3 条禁提（极限词/功效/贬低竞品） |
| MU-10 | 佣金结构是按目标选的，没有混用 |
| MU-11 | 验收标准不含「卖了多少单」 |
| MU-12 | 我给了可归因入口（口令/链接/UTM） |
| MU-13 | 我把六条合规红线写进去了，并要求达人确认 |

## 三、诚实说明

本卡没有可自动断言的门禁：达人匹配与内容质量只能由数据与人工判断。

> **纪律**：达人合作的目标不是「买曝光」，是「**付了钱能说清买到了什么**」。
