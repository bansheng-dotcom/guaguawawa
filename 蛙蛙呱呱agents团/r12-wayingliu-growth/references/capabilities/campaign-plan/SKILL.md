# 增长 Campaign 设计（Campaign Plan）

> 一句话定位：**这个技能存在的意义，是防止"钱花了、数据涨了、但说不清是不是这次投放的功劳"**。
> 增长方案最常见的失败不是渠道选错，而是三件事：
> **没写停止条件**（亏损了还在跑）、**主指标不唯一**（每个指标都能找出一个好数字）、
> **没有预注册**（事后挑一个显著的结果宣布成功）。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这次投放怎么分配预算」「要不要投抖音/搜索」
- 「帮我设计个 A/B 实验」「怎么判断这次投放有效」
- 「这个 campaign 计划能开跑吗」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 写文案 / 素材 / 落地页 | `r11` 内容 / `r10` 设计 | 本技能只管方案与判据，不产出素材 |
| 做数据显著性检验 | `r06` 分析师 | 本技能写**判据**，实算交给 r06 |
| 修产品留存 / 定价 | `r07` / `r01` | 那不是投放问题，投再多也救不回 |
| 保证 ROI / 排名 | 拒绝 | 只给**可验证假设与停止条件**，不承诺结果 |

**最小可开工输入**：**增长阶段 + 北极星指标 + 可用预算**，任给两项即可开工。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 增长阶段（探索/成长期/成熟期） | 必需 | 按产品现状推断并标注"假设阶段" |
| 北极星指标 | 必需 | 按阶段给默认值（成长期=付费用户数），标注待确认 |
| 预算与周期 | 必需 | 缺则给"最小可验证预算"建议，不硬凑 |
| 现有 LTV / CAC / 回本周期 | 建议 | 缺则标"待 r06 补"，并在停止条件里写明依赖 |
| 渠道白名单 | 建议 | 缺则用 `references/campaign-matrix.md` 默认矩阵 |

**追问纪律**：最多一轮，只问**阶段、指标、预算**。其余按同类默认补全并标注。

## §3 执行流水线（Workflow）

### Step 1 · 定增长阶段（决定打法，不是形式）
| 阶段 | 主目标 | 不该做的 |
|---|---|---|
| 探索期 | 找到可复现的获客渠道 | 大额投放、追求规模 |
| 成长期 | 放大已验证渠道 + 提转化 | 开全新渠道、追品牌曝光 |
| 成熟期 | 提留存与客单价、降 CAC | 只靠买量续命 |

**判据**：写不出"我们现在为什么在这个阶段"，说明还没到能投的时候。

- **产出**：`growth_stage` + 阶段判据
- **过关条件**：阶段与判据一致（成长期却没有已验证渠道 → 自相矛盾）

### Step 2 · 锁单一北极星 + 护栏指标
- `northstar`：**只能一个**；
- `guardrail`：防止按下葫芦浮起瓢（如投放提升新客却抬高退款率）；
- `ltv` / `cac` / `payback_months`：没有就别编，标"待补"。

> 多主指标等于没有主指标——每个渠道都能找到自己好看的那一个。

- **产出**：`metrics{}`
- **过关条件**：`northstar` 唯一，`guardrail` 至少一条

### Step 3 · 渠道矩阵与 20/60/20 预算
按 `references/campaign-matrix.md` 的矩阵逐渠道打分：`Reach × Cost × Engagement × Relevance`。
预算按 **20/60/20** 分三段：

| 段 | 占比 | 用途 |
|---|---|---|
| 试探 | 20% | 试新渠道/新素材，允许失败 |
| 主力 | 60% | 投已验证渠道，追求规模 |
| 保留 | 20% | 留作追加或应对突发 |

**铁律**：**禁止 100% 投一个渠道**。单渠道依赖是最常见的一夜归零原因。
每个渠道必须填四要素：`channel` / `audience` / `creative` / `budget`。

- **产出**：渠道矩阵 + 预算分配 + 每渠道四要素
- **过关条件**：渠道在白名单内、四要素齐全、无单渠道 100%

### Step 4 · 预注册实验（这一步决定能不能下结论）
每条实验必须在**开跑前**写死四件：

```json
{"hypothesis": "…", "metric": "唯一主指标", "significance": 0.05, "sample_size": "…"}
```

- `hypothesis`：可证伪的陈述，不是"试试看"；
- `metric`：**唯一主指标**；
- `significance`：显著性门槛（默认 0.05）；
- `sample_size`：预估样本量（没有就写"待 r06 估算"，不许空着）。

**预注册的意义**：事后挑指标 = 自欺。开跑前不写，结果出来后就不许称"显著提升"。

- **产出**：`experiments{}`
- **过关条件**：四项齐全，主指标唯一

### Step 5 · 写死停止条件（最容易被跳过、最贵的一条）
```json
"stop_condition": {"kill_criteria": "…", "guardrail": "…", "owner": "…"}
```

| 字段 | 必须可执行 |
|---|---|
| `kill_criteria` | 带阈值 + 时间窗，如"连续四周低于基线即停" |
| `guardrail` | 合规红线，如"不刷单、不伪造评价" |
| `owner` | 一个具体角色，不是"团队" |

- **产出**：`stop_condition{}`
- **过关条件**：三项齐全，`kill_criteria` 含阈值与时间窗

### Step 6 · 投放前四要素与显著性校验
```bash
python harness.py media --input <单渠道投放.json>   # 四要素 + 渠道白名单 + ROI 实算
python harness.py cro   --input <实验.json>         # 显著性门槛与实验三件套
python harness.py plan  --input <campaign计划.json> # 阶段/指标/实验/停止条件总闸门
```

- **产出**：三份门禁结论
- **过关条件**：三道全部退出码 0

## §5 质量门（一票否决，不过不给交付）

1. **增长阶段与判据一致**（`plan:growth_stage`）；
2. **北极星指标唯一**（`plan:metrics`）；
3. **每条实验有 hypothesis / metric / significance / 样本量**（`plan:experiments`）；
4. **停止条件三项齐全**，`kill_criteria` 含阈值与时间窗（`plan:stop_condition`）；
5. **每个渠道四要素齐全**（`paid.media_fields`）；
6. **渠道在白名单内**（`paid.channel`），**无单渠道 100% 预算**；
7. **实验显著性门槛明确**（`paid.significance`）。

> 验收命令：`python harness.py plan --input <计划.json>` 及其它两道
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许删掉停止条件让门禁变绿**。

- [ ] LTV / CAC / 回本周期要么有数，要么明确标"待补"

- [ ] 每条实验只挂一个主指标，并写了显著性门槛
- [ ] 每条实验都给了样本量，或明确"待 r06 估算"
- [ ] 停止条件有阈值 + 时间窗 + 一个具体 owner

- [ ] 三道门禁（plan / media / cro）均退出码 0

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 预算 100% 投一个渠道 | 20/60/20 三档；单渠道依赖是最大的一夜归零风险 |
| EX-02 | 停止条件写"效果不好就停" | 必须给阈值 + 时间窗 + owner，如"连续四周低于基线即停" |
| EX-03 | 实验写"试试看能不能提升转化" | 可证伪陈述："简化注册页把激活率从 40% 提到 50%" |
| EX-04 | 一次实验挂三个主指标 | **唯一主指标**；多指标 = 事后总能挑出一个好看的 |
| EX-05 | 开跑后补实验设计 | 预注册必须在开跑**前**写死，否则不得称"显著提升" |
| EX-06 | 没有样本量估算就开始跑 | 让 `r06` 算功效与样本量；没有就先做最小可验证投放 |
| EX-07 | 渠道不在白名单（野渠道/灰产） | 只用白名单渠道；灰产一律拒绝 |
| EX-08 | 投放四要素缺 budget 或 creative | 四要素齐全才算可执行；缺一项就是"想法"不是"方案" |
| EX-09 | 成长期却全开新渠道 | 成长期应放大已验证渠道；开新渠道放探索期 |
| EX-10 | 只看 CAC 不看回收期 | 回收期 > 12 个月的投放，规模越大现金流越紧 |
| EX-11 | 承诺"投了就有 ROI 3.0" | 只给假设与停止条件；结果由数据验证 |
| EX-12 | 护栏指标缺失 | 必须写合规红线（不刷单、不伪造评价、不诱导分享） |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `harness.py` 跑不了 | 按 §6 人工逐项核对，标注「未跑门禁」；**不得标记"可开跑"** |
| 没有历史 LTV / CAC | 写"待 r06 补"，并把停止条件挂到这些数上（没数就先小规模试） |
| 预算未定 | 给"最小可验证预算"建议，标注为建议值，不硬凑方案 |
| 用户要求全押一个渠道 | 拒绝并解释风险；可给"单渠道上限 60% + 20% 备用"折中 |
| 渠道涉灰产（刷单/买量作弊） | 明确拒绝，不做替代方案 |
| 平台规则/费率不明 | 标注"待平台后台当期口径确认"，不写死费率 |
| 要求承诺 ROI / 排名 | 只给假设与判定规则，不承诺结果 |

**明确不做**
- 不写文案与素材（归 `r11` / `r10`）；
- 不算显著性（归 `r06`）；
- 不保证 ROI、排名、转化率；
- 不做产品与定价改动（归 `r07` / `r01`）。
