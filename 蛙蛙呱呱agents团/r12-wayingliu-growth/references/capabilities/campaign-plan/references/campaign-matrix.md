# 渠道矩阵与预注册规则（campaign-matrix）

> 被 §3、§5、§7 按需引用。版本：v2.0.0（项目自建，v1）

---

## 一、渠道矩阵（打分后选，不凭感觉）

对每个候选渠道按四维打分（1–5），再乘权重求总分：

| 维度 | 含义 | 权重 | 打分依据 |
|---|---|---|---|
| `Reach` | 能触达多少人 | 25% | 目标人群覆盖规模（用真实活跃，不用注册） |
| `Cost` | 单位获客成本 | 30% | 该渠道历史 CAC 或行业区间（缺则 3 分） |
| `Engagement` | 触达后的互动质量 | 20% | 点击率/停留/回访 |
| `Relevance` | 与目标人群匹配度 | 25% | 人群重合度，非"看起来像" |

**输出**：`{channel, reach, cost, engagement, relevance, score, selection}`。
`Selection` 打勾只给总分 ≥ 3.5 的渠道；低于 3.5 的写进"暂不投"并写明理由。

> **不要全渠道铺开**。3 个渠道打满，好过 8 个渠道各投一点——后者数据量都不够做显著性判断。

## 二、20/60/20 预算法

| 段 | 占比 | 用途 | 允许失败 |
|---|---|---|---|
| 试探 | 20% | 新渠道 / 新素材 | ✅ 允许，这是它的目的 |
| 主力 | 60% | 已验证渠道放大 | ❌ 必须有历史数据支撑 |
| 保留 | 20% | 追加或应急 | — |

**三条纪律**
1. **单渠道上限 60%**，任何情况下不 100%；
2. 20% 试探段必须**预先写好"失败也算成功"的判据**（拿到了什么信息）；
3. 20% 保留段不许提前花掉——那是应对"某个渠道突然爆了"的弹药。

## 三、预注册实验模板（开跑前写死）

```json
{
  "hypothesis": "简化注册页把激活率从 40% 提到 50%",
  "metric": "activation_rate",
  "significance": 0.05,
  "sample_size": 2400,
  "duration_days": 14,
  "guardrail": "退款率不上涨超过 0.5pp"
}
```

| 字段 | 硬要求 |
|---|---|
| `hypothesis` | 可证伪：含**具体指标 + 变化方向 + 幅度** |
| `metric` | **唯一主指标**（其他都是观测指标） |
| `significance` | 默认 0.05；放宽到 0.1 必须在方案里写明理由 |
| `sample_size` | 由 `r06` 功效分析给出；没有就写"待估算"并先做小规模 |
| `duration_days` | 覆盖至少一个完整业务周期（通常 ≥ 14 天） |
| `guardrail` | 一条护栏指标，防止"赢了主指标、输了大盘" |

### 为什么必须预注册

事后挑指标是增长里最常见的自欺：
一次跑了 8 个指标，总有 1 个"显著"；然后宣布"这次实验成功"。
**预注册把"看哪个指标"这个自由度在开跑前就锁死**，结论才可信。

### 样本量粗算（先用这个量级判断，正式交 r06）

```
每组样本 ≈ 16 × p(1-p) / (相对提升)²
例：基线 40%，想看到相对 +25%（40%→50%）
    每组 ≈ 16 × 0.4 × 0.6 / (0.25)² ≈ 61 … 实际需按绝对差与功效重算
```
> 上式只是量级直觉，**正式样本量必须用 `r06` 的 `power` 工具算**。
> 写方案时若样本量差一个数量级，说明这个实验做不出来，应该改指标或延长周期。

## 四、停止条件（最贵的一条）

```json
"stop_condition": {
  "kill_criteria": "转化率连续四周低于基线 20% 即停",
  "guardrail": "不刷单、不伪造评价、不诱导分享",
  "owner": "r12"
}
```

| 反例 | 问题 |
|---|---|
| 「效果不好就停」 | 无阈值、无时间窗，等于不停 |
| 「持续观察」 | 没有停止点，亏损会继续 |
| 「团队决定」 | 没有 owner，出事找不到人 |

**判据三件套**：阈值（多少）+ 时间窗（多久）+ owner（谁按开关）。

## 五、投放四要素（每个渠道必填）

```json
{"channel": "搜索广告", "audience": "…", "creative": "…", "budget": "月预算 5000 元", "return": 15000.0, "spend": 5000.0}
```

| 字段 | 缺了会怎样 |
|---|---|
| `channel` | 无法判白名单 |
| `audience` | 无法判是否触达对的人 |
| `creative` | 无法归因（不知道是哪个素材起效） |
| `budget` | 无法算 ROI 与回收期 |

`return` / `spend` 用于 ROI 实算；缺则 ROI 标"未算"，不得估一个数字充数。

## 六、与门禁的对应关系

| 门禁 | 覆盖本文件哪一节 | 判不了什么 |
|---|---|---|
| `harness.py plan` | §三 预注册、§四 停止条件、阶段与指标 | 判不了假设是否成立 |
| `harness.py media` | §五 四要素、渠道白名单、ROI 实算 | 判不了渠道是否真的合适 |
| `harness.py cro` | §三 显著性门槛与实验三件套 | 判不了样本量算得对不对 |

> 三道门禁合起来保证"方案可执行、可判定"，**保证不了"这个方案会成功"**。
> 后者只能靠真实投放与 r06 的显著性检验。
