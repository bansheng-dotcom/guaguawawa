# 实验协议（experiment-protocol）

> 样本量 · 分流 · 护栏 · 停止 · 结论词表 · 8 组 BAD/GOOD。版本：v1

---

## 一、样本量估算（每组）

**近似公式**（α=0.05，power=0.8）：

```
n ≈ 16 × p(1−p) / MDE²
```

例：基线转化 p=2%，想检测到 2.4%（相对 +20%，MDE=0.4pp=0.004）

```
n ≈ 16 × 0.02 × 0.98 / 0.004²
  ≈ 16 × 0.0196 / 0.000016
  ≈ 19,600 每组
```

日流量 1,000 → 每组需 19.6 天 → **约 40 天跑完**。
**如果跑不起，就改小目标或放弃**——不要用「先跑一周看看」代替。

---

## 二、分流规则

| 规则 | 说明 |
|---|---|
| 单元 | 用户级（不是会话级） |
| 稳定性 | 同一用户始终同组（用 id hash） |
| 比例 | 50/50 优先；80/20 可加速但周期更长 |
| 干扰 | 多实验并行需正交分层，同一用户可进不同实验但不同时进同层 |

---

## 三、护栏指标（至少 2 个）

| 类型 | 例 | 恶化阈值 |
|---|---|---|
| 体验 | 页面加载、崩溃率 | +10% |
| 商业 | 退款率、毛利率 | +2pp |
| 服务 | 客诉数、工单时长 | +15% |

**铁律**：护栏恶化超阈值 → **无论主指标多好都判失败**。

---

## 四、停止规则（跑之前写死）

1. 达样本量停；
2. 护栏恶化立即停；
3. （可选）主指标提前达显著且已跑 ≥7 天。

**禁止**：中途看 p 值后决定「再跑几天」——这会把假阳性率从 5% 抬到很高。

---

## 五、结论词表

| 情形 | 可以说 | 不可以说 |
|---|---|---|
| p<0.05 且护栏没恶化 | 「实验组比对照组高 X（95% CI: a–b）」 | 「这个功能有效」 |
| p≥0.05 且样本量达设计值 | 「未检测到差异（样本量足够）」 | 「没有效果」 |
| p≥0.05 且样本量不足 | 「证据不足，无法判断」 | 「不显著所以不行」 |
| 护栏恶化 | 「主指标提升但护栏恶化，判失败」 | 「整体还是赚的」 |

## 六、8 组 BAD/GOOD

| # | 场景 | ❌ | ✅ |
|---|---|---|---|
| 1 | 假设 | 「改版会有影响」 | 「改版使转化从 2.0% 到 2.4%」 |
| 2 | 样本量 | 「先跑一周」 | 「需 19,600/组，约 40 天」 |
| 3 | 分流 | 会话级 | 用户级 hash |
| 4 | 护栏 | 无 | 退款率与客诉数，阈值 +2pp/+15% |
| 5 | 偷看 | 每天看 p 值 | 预设停止规则，不看过程 |
| 6 | 结论 | 「没效果」 | 「证据不足（样本 40%）」 |
| 7 | 异质 | 「对 25 岁用户特别有效」（当结论） | 「探索性发现：25 岁组差异更大，未预设」 |
| 8 | 失败判定 | 主指标好就算成功 | 护栏恶化即失败 |

## 七、来源

- 样本量近似公式：两比例检验的常用近似（α=0.05, power=0.8）
- 停止规则与 p-hacking：序贯检验与预注册思想
- 结论词表：把统计结论翻译为业务语言时的用语纪律
- 与本团队衔接：`campaign-plan` 负责预注册，本卡负责判定
