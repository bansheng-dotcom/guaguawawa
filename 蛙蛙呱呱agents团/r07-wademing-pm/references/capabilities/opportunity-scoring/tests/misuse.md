# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表为人工评审清单。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 |
|---|---|
| MU-01 | 四个评估维度与权重固定，且声明季度内不改 |
| MU-02 | 评分公式公开，他人可复算出同一排名 |
| MU-03 | 置信度分 A/B/C 三级，前三名中无 C 级 |
| MU-04 | 每个维度至少有 2 档差异（否则该维度无区分度） |
| MU-05 | 写明本轮不做什么，以及再评估触发条件 |
| MU-06 | 异议只针对打分依据，不针对排序结果 |

## 二、软门（§6 自检）

| # | 常见错法 |
|---|---|
| MU-06 | 我的四个维度和权重是固定的，没有为某个需求临时加维度 |
| MU-07 | 评分公式写出来了，别人能算出同样的排名 |
| MU-08 | 前三名里没有纯直觉的（C 级） |
| MU-09 | 每个维度上候选之间有差异，没有全给 5 分 |
| MU-10 | 我写了不做什么 |
| MU-11 | 我写了什么信号出现会重新排 |
| MU-12 | 干系人的异议我按「依据」处理，没有直接改排名 |
| MU-13 | 我没有把「老板想做」写成紧迫性 A 级 |

## 三、诚实说明

本卡没有可自动断言的门禁：维度选择与依据强度无法机器判定，可复算的只有公式（人对人复算）。

> **纪律**：优先级的目标不是「排出顺序」，是「**让下季度的排序能和这季度比**」。
