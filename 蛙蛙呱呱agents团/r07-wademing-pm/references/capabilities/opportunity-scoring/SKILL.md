# 机会评估与需求优先级（opportunity-scoring）

> **优先级排序最大的问题不是算错，是「每次用的维度不一样」。** 上季度按营收排、这个季度按老板关心排，两个结论无法比较，团队也就学不到东西。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**

- 「先做哪个需求」
- 「这个机值不值得投入」
- 「为什么排在这个后面」
- 「需求太多做不完」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 写 PRD | r07 的 `prd-authoring` | 那是文档 |
| 用户研究 | r07 的 `user-research-toolkit` | 那是需求来源 |
| 排期与容量 | r02 | 那是执行计划 |
| 机会的行业判断 | r05 的 `industry-panorama-research` | 那是外部研究 |

**最小可开工输入**：**3 个以上候选需求 + 一个统一的评估维度表**。只有一个需求时不需要排序。

## §2 前置输入与最省追问

| 输入 | 是否必需 |
|---|---|
| 候选需求清单（≥3） | 必需 |
| 评估维度与权重 | 必需 |
| 成本估算（人天） | 必需 |
| 置信度依据（数据/访谈/直觉） | 必需 |
| 紧迫性来源（合同/竞争/时间窗） | 建议 |

**追问纪律**：最多一轮，只问**这次用哪四个维度**。维度不定，排序结果无法跨季度比较。

## §3 执行流水线（Workflow）

### Step 1 · 定维度表（四个，跨季度不变）
固定四维：**影响面**（多少用户/多少收入）、**置信度**（依据强度）、**成本**（人天）、**紧迫性**（有无时间窗）。权重固定，季度内不改。

**判据**：四维与权重写死，并声明「本季度沿用」

### Step 2 · 打分并算分（公式公开）
评分 = 影响面 × 置信度 ÷ 成本 ×（紧迫性加权）。**公式写出来，任何人可复算**。

**判据**：公式写明，且可被他人复算出同一排名

### Step 3 · 置信度分级（不许全给高）
**A 有数据**（埋点/实验）/ **B 有访谈**（≥3 人）/ **C 有直觉**（只有判断）。C 级不得排进前三。

**判据**：置信度分级明确；前三名无 C 级

### Step 4 · 检查分布（防「全给 5 分」）
若某维度所有候选同分，说明该维度没区分度，删掉或改度量方式。

**判据**：每个维度至少有 2 档差异

### Step 5 · 写「不做什么」与再评估触发
明确：本轮不做哪几个、为什么；以及**什么信号出现会重新排**（如数据反转、成本变化）。

**判据**：不做的项与再评估触发都写明

### Step 6 · 对齐干系人（一次，不反复）
把维度表、打分、不做的理由一次讲清；**收集异议只针对打分依据，不针对排序结果**。

**判据**：异议集中在依据层，不在结果层

## §5 质量门（一票否决）

1. 四个评估维度与权重固定，且声明季度内不改；
2. 评分公式公开，他人可复算出同一排名；
3. 置信度分 A/B/C 三级，前三名中无 C 级；
4. 每个维度至少有 2 档差异（否则该维度无区分度）；
5. 写明本轮不做什么，以及再评估触发条件；
6. 异议只针对打分依据，不针对排序结果；

> 本卡无自动门禁。评分公式可人工复算，这是最硬的自我验证。

## §6 交付前自检清单

- [ ] 我的四个维度和权重是固定的，没有为某个需求临时加维度
- [ ] 评分公式写出来了，别人能算出同样的排名
- [ ] 前三名里没有纯直觉的（C 级）
- [ ] 每个维度上候选之间有差异，没有全给 5 分
- [ ] 我写了不做什么
- [ ] 我写了什么信号出现会重新排
- [ ] 干系人的异议我按「依据」处理，没有直接改排名
- [ ] 我没有把「老板想做」写成紧迫性 A 级

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 每次换维度 | 四维固定，季度内不改 |
| EX-02 | 评分公式不公开 | 写公式，可复算 |
| EX-03 | 全给 5 分 | 每维至少 2 档差异 |
| EX-04 | 纯直觉排第一 | C 级不得进前三 |
| EX-05 | 只排做的不排不做的 | 写清不做项 |
| EX-06 | 不设再评估触发 | 写明什么信号会重排 |
| EX-07 | 把老板偏好当紧迫性 | 紧迫性要有客观来源 |
| EX-08 | 成本估算拍脑袋 | 给估算依据（类似项目人天） |
| EX-09 | 排序后不解释 | 每项给一句理由 |
| EX-10 | 一次排 20 个 | 先排 Top 5，其余进待评估池 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 无成本估算 | 给区间（如 5–10 人天），标注「区间估」 |
| 无数据无访谈 | 全部标 C 级，并建议先做小样本验证 |
| 需求来自合同承诺 | 紧迫性直接置顶，其余照常排 |
| 多团队争资源 | 统一维度表后合排，不各自评 |
| 需求无法拆分 | 标「需先拆解」再评 |
| 时间窗内必须定 | 按 C 级最短路径先出一版，标注「依据不足」 |

**明确不做**：不写 PRD、不做用户研究、不做排期、不做行业判断。
