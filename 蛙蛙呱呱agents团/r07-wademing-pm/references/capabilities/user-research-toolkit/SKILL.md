# 用户研究工具箱（user-research-toolkit）

> **这是 knowledge 卡**：没有可执行门禁（`entry: null`），价值在「方法可依」而非「结果可判」。
> 它现在有 `SKILL.md` 载体，因此会出现在技能索引里、能被模型按需读取；
> 在此之前它是 `README.md`，**模型根本不知道它存在**。

## §1 何时用 / 何时不用

**该用**：做用户访谈、设计问卷、跑可用性测试、或验证一个产品假设

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 写 PRD 与需求优先级 | `prd-authoring` | 那是需求文档 |
| 市场与竞品研究 | `r05` | 那是市场层 |
| 做 A/B 实验 | `r12` | 那是增长实验 |

**最小可开工输入**：一个待验证的产品假设

## §2 前置输入与最省追问

| 输入 | 是否必需 |
|---|---|
| 一个待验证的产品假设 | 必需或建议 |
| 目标用户画像 | 必需或建议 |
| 可用时间与样本渠道 | 必需或建议 |

**追问纪律**：最多一轮，缺什么按 §8 降级处理，不连环追问。

## §3 执行流水线（Workflow）

### Step 1 · 写可证伪假设
假设必须写成「如果我们做 X，Y 类用户会 Z」，可被数据否证。

**判据**：不可证伪的假设不许开始研究

### Step 2 · 选方法
**为什么**用访谈（探索动机）；**有多少**用问卷（量化分布）；**能不能用**用可用性测试；**真实行为**用日志分析。

**判据**：方法与问题不匹配＝白做

### Step 3 · 守提问纪律
访谈不问「你想要什么」（会得到礼貌的谎话），问「上次遇到这个问题时你做了什么」。

**判据**：问过去行为，不问未来意愿

### Step 4 · 定样本与饱和
探索性访谈 5–8 人可到饱和；问卷 ≥100 份才谈分布。

**判据**：少于阈值只写「方向性观察」

### Step 5 · 出三态结论
每个假设给「成立 / 不成立 / 证据不足」三态，不许只写「有启发」。

**判据**：证据不足也是有效结论

## §5 质量门（一票否决）

1. 每个假设可被否证；
2. 方法与问题匹配并说明理由；
3. 样本量达到该方法的最低阈值；
4. 结论用三态，不用「有启发」；

> 本卡无自动门禁。**任一项不过即不得交付**，且必须在交付物里写明「逐项人工核对」。
> 可用 `python agent.py prdguard check` 做间接校验（若该命令存在）。

## §6 交付前自检清单

- [ ] 假设写成「如果做 X，Y 用户会 Z」
- [ ] 方法选择有理由（为什么不用另一种）
- [ ] 访谈问的是过去行为，不是未来意愿
- [ ] 样本量达标（访谈 5–8 / 问卷 ≥100）
- [ ] 原始记录已去标识
- [ ] 每个假设都有三态结论之一

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 问「你想要什么」 | 问上次遇到时的具体行为 |
| EX-02 | 拿 3 个用户当结论 | 标「方向性观察」，或补样本 |
| EX-03 | 问卷题目有引导性 | 中性表述，避免「是不是觉得很好」 |
| EX-04 | 只记支持假设的证据 | 反例必须记录 |
| EX-05 | 结论写「有启发」 | 三态：成立/不成立/证据不足 |
| EX-06 | 样本全是熟人 | 说明样本偏差 |
| EX-07 | 不做去标识 | 姓名/联系方式必须移除 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 找不到目标用户 | 用邻近用户并标注「非目标样本」 |
| 无法做访谈 | 改用问卷或日志，标注方法局限 |
| 样本量不足 | 只出方向性观察，不出比例结论 |
| 用户要求保密 | 只留摘要与匿名编号 |
| 时间只够一轮 | 优先验证最贵的那个假设 |

**明确不做**：不写 PRD、不做增长实验、不把个体意见当结论。
