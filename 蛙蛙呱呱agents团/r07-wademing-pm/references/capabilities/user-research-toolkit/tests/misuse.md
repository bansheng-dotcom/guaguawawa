# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`，无命令门禁），因此本表是**人工评审清单**。
> 每条都由评审者判真假，判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| MU-01 | 每个假设可被否证 | §5 第 1 条 |
| MU-02 | 方法与问题匹配并说明理由 | §5 第 2 条 |
| MU-03 | 样本量达到该方法的最低阈值 | §5 第 3 条 |
| MU-04 | 结论用三态，不用「有启发」 | §5 第 4 条 |

## 二、软门（§6 自检，靠人抓）

| MU-04 | 假设写成「如果做 X，Y 用户会 Z」 |
| MU-05 | 方法选择有理由（为什么不用另一种） |
| MU-06 | 访谈问的是过去行为，不是未来意愿 |
| MU-07 | 样本量达标（访谈 5–8 / 问卷 ≥100） |
| MU-08 | 原始记录已去标识 |
| MU-09 | 每个假设都有三态结论之一 |

## 三、诚实说明

本卡**没有**可自动断言的门禁：它的输入是判断与决策，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——这比没有门禁更糟。

> **纪律**：knowledge 卡的价值在「有方法可依」，不在「有分数可刷」。
