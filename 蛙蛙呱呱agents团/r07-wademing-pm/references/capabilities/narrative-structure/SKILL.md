# 叙事结构（Narrative Structure）

> 一句话定位：**读者读不懂，往往不是理解力问题，是结构让他一路走到一半才知道你要什么。**
>
> 三种结构解决三类场景：**说服**用 PR/FAQ，**汇报**用金字塔，**评审**用结论先行。
> 选错结构比写得差更致命——用金字塔写提案会显得傲慢，用 PR/FAQ 写周报会显得啰嗦。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这份提案怎么写」「怎么让老板同意」
- 「汇报材料重点在哪」「为什么读不懂」
- 「PRD 怎么组织」「这个故事讲不清」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| PRD 的功能四段（触发/规则/结果/状态） | `r07` 的 `prd-authoring` | 那是文档规格 |
| 报告排版与章节 | `r08` 的 `html-report-presentation` | 那是呈现格式 |
| 讲给人听（页数与节奏） | `r08` 的 `ppt-generator` | 那是演示 |
| 长文写作与论据分级 | `r11` 的 `longform-article` | 那是稿件 |

**最小可开工输入**：**读者是谁 + 你要他做什么决定**。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 读者（决策者/同行/外部） | 必需 | 不确定读者就无法定详略 |
| 要读者做的决定或动作 | 必需 | 说不出动作 → 先回去想目的 |
| 场景类型（说服/汇报/评审） | 必需 | 缺则按「说服」默认，用 PR/FAQ |
| 已有素材与数据 | 建议 | 缺则标注「待补证据」 |

**追问纪律**：最多一轮，只问**读者要做什么决定**。

## §3 执行流水线（Workflow）

### Step 1 · 先写「一句话主张」（写不出就别开始）
格式：**「我建议 <做什么>，因为 <最关键的一个理由>。」**

**判据**：这句话如果自己都不信，说明还没想清楚——不是写作问题。
**阈值**：这一句必须**≤40 字**，且含动词与理由。

### Step 2 · 选结构（场景决定结构）
| 场景 | 用 | 骨架 | 为什么 |
|---|---|---|---|
| **说服**（要资源/要同意） | PR/FAQ | 问题→现状→方案→收益→风险→行动 | 先让他认同问题，才谈方案 |
| **汇报**（同步进展/结论） | 金字塔 | 结论→3 条论据→细节 | 决策者只要结论与依据 |
| **评审**（要 pass/fail） | 结论先行 | 判定→证据→风险→建议 | 评审要能快速定位问题 |
| **叙事**（复盘/案例） | 时间线 | 起点→转折→现在→教训 | 故事需要因果顺序 |

**判据**：**一次只用一种**。混用会让读者失去预期（以为在读提案，突然变成周报）。

### Step 3 · 逐段填必答问题（缺一段就是洞）
**PR/FAQ 六段的必答问题**

| 段 | 必答 |
|---|---|
| 问题 | 谁在什么场景下遇到什么痛点？（要有具体人和场景） |
| 现状 | 现在怎么解决的？成本是什么？（不写"没有解决方案"） |
| 方案 | 我们做什么？**不做什么**？（范围两面都要写） |
| 收益 | 能量化吗？不能量化就写"影响什么决策" |
| 风险 | 最可能失败的原因是什么？怎么缓解？ |
| 行动 | 请读者做什么决定？什么时候要？（具体到日期） |

**金字塔三层的必答**

| 层 | 必答 |
|---|---|
| 结论 | 一句话结论（放最前） |
| 论据 | 3 条（不多不少；多了说明没提炼） |
| 细节 | 每条论据下的数据与来源 |

### Step 4 · 做「一句话复述」检验
把稿子给一个没参与的人，让他用一句话复述你的主张。

**判据**：
- 复述**与你的主张一致** → 结构成立；
- 复述成「大概是在讲 X 方面的事」 → 结构失败，回 Step 1。

**阈值**：复述准确率须 **≥2/3 的人**能做到一致。

### Step 5 · 补「反方回应」（说服场景必做）
写出最强的反对意见，并回应它。

**判据**：如果你写不出反对意见，说明你没站在对方角度想——你的提案会被这条意见击穿。

### Step 6 · 删开头（最常见的病）
把第一段删掉，读一遍：还通吗？
- 还通 → **第一段是废话，就该删**（"在当今快速发展的时代…" 属于此类）；
- 不通 → 第一段有必要。

## §5 质量门（一票否决）

1. 有**一句话主张**（≤40 字，含动作与理由）；
2. **只用一种结构**（PR/FAQ 或金字塔或结论先行），不混用；
3. **每段必答问题都有答案**（缺一段即洞）；
4. **一句话复述检验通过**（≥2/3 的人复述一致）；
5. 说服场景**有反方意见与回应**；
6. **首段不是废话**（删掉后仍通顺的，就该删）。

> 本卡无自动门禁。可配合 `python agent.py prdguard check --input <PRD.json>` 校验结构字段（间接）。

## §6 交付前自检清单

- [ ] 我能用 ≤40 字说出主张（做什么 + 为什么）
- [ ] 我只用了一种结构，没有中途换体裁
- [ ] 每段的必答问题我都答了，没有跳过「风险」段
- [ ] 我找 ≥2 个没参与的人做过一句话复述
- [ ] 说服场景里我写了最强反方意见并回应
- [ ] 我删过第一段，确认它不是废话
- [ ] 结论在前面，背景在后面
- [ ] 行动项写了具体日期与具体人（不是"尽快推进"）

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 没有一句话主张就开始写 | 先写 ≤40 字主张 |
| EX-02 | 「在当今…时代」开头 | 首段直接给主张 |
| EX-03 | 混用提案与周报体裁 | 一次只用一种结构 |
| EX-04 | 只写做什么，不写不做什么 | 范围两面都写 |
| EX-05 | 不写风险段 | 风险是最能建立信任的一段 |
| EX-06 | 收益无法量化就含糊 | 改为「影响什么决策」 |
| EX-07 | 论据列 7 条 | 3 条，多了说明没提炼 |
| EX-08 | 不写反方意见 | 写最强反对意见并回应 |
| EX-09 | 行动项写"尽快推进" | 写具体日期与人 |
| EX-10 | 不做复述检验 | 找 2 人复述，一致率 ≥2/3 |
| EX-11 | 背景写三页 | 背景 ≤1 段 |
| EX-12 | 从头讲到尾不给结论 | 结论先行（金字塔/评审） |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 找不到人做复述检验 | 自己隔 2 小时再读，标注「未做他人复述」 |
| 收益确实无法量化 | 改为「影响哪个决策/哪个环节」 |
| 读者是外部客户 | 少讲内部背景，多讲与他们相关的利益 |
| 材料涉密不能外传 | 复述检验用脱敏版 |
| 需要同时说服与汇报 | 拆两份：提案给决策者，周报给团队 |
| 时间极紧 | 只保「一句话主张 + 结论先行 + 行动项」三件 |

**明确不做**
- 不排版、不做视觉、不校验数据、不替老板拍板。
