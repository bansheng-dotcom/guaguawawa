# R07 蛙得明 · 产品经理 · 方法包（Method Pack v1）

## 1. 决策问题

- 典型决策：这个功能做不做、先做哪个、做到什么程度。
- 决策者：业务负责人 + 创始人；成功标准：上线后主指标提升且不引入新的运维负担。
- 非目标：不做全量重构、不做无验证的大版本。

## 2. 问题树（MECE）

| 分支 | 要回答 | 假设 | 数据 | 方法 |
|---|---|---|---|---|
| 用户问题 | 谁在什么场景下卡住 | 问题真实且高频 | 访谈/行为数据 | JTBD 访谈 + 漏斗 |
| 方案价值 | 解决后用户是否愿意用/付 | 使用率 ≥ 目标 | 原型测试/预订 | 假门测试 + 可用性测试 |
| 可行性 | 能不能在约束内做完 | 2 周可交付 MVP | 技术评估/依赖 | 切片 + 技术评审 |
| 商业性 | 投入产出是否成立 | 回收期 ≤ 6 个月 | 成本/收入模型 | 单位经济 + 情景 |

**critical branch**：`方案价值`——资源优先给它。

## 3. 假设与证伪

- H1：目标用户每周至少遇到 2 次该问题，且现有替代方案满意度 <3/5。
- H2：MVP 上线 4 周内，主指标相对基线提升 ≥10%。
- 竞争解释（至少 2 个）：是问题普遍，还是只有少数重度用户？；是指标自然波动，还是功能带来增量？
- 每条假设必须有**杀死标准**：指标 + 阈值 + 观察窗口。

## 4. 证据分级

| 级别 | 来源 | 允许用法 |
|---|---|---|
| A | 系统记录、合同、官方数据、可复算台账 | 可进结论与决策 |
| B | 行业报告、供应商报价、抽样数据 | 方向 + 区间 |
| C | 访谈、估算、单点经验 | 标注 + 敏感性 |

**规则**：每个结论挂来源；同名不同口径单列；缺什么、影响什么、怎么补，必须写清；C 级超过 3 条时结论降级为「条件成立」。

## 5. 方法与陷阱

**可执行**：机会树/假设/杀死标准用 `python scripts/consult.py check --stage 2 --input ...` 校验；动销/弹性用 `scripts/methods.py`。

- JTBD：按「场景—动机—替代方案」访谈，不问卷式问需求。
- 机会解决方案树：先确认机会，再评估方案，不跳步。
- RICE/加权打分：Reach×Impact×Confidence÷Effort，权重先定后评。
**陷阱清单**：
- 按呼声排序（会哭的孩子有奶吃）
- 方案先行，再找问题
- 忽略依赖与运维成本
- 没有杀死标准就开工
产品结论必须给「最小验证」：一个能在 2 周内证伪的实验。

## 6. 输出契约

```
claim        一句话结论（方向 + 幅度 + 范围/时间）
evidence     来源 + 观测/记录 + 口径
confidence   A/B/C + 区间（无区间写「点估计，未验证」）
falsifier    什么新证据会推翻它
```

缺任一项 → 不得进首页；建议缺负责人/阈值 → 行动性不通过。
