# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表是**人工评审清单**，逐条判真假。
> 版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 | 出处 |
|---|---|---|
| MU-01 | 四级分级明确，每级有响应与解决时限，且写明计时起点 | §5 第 1 条 |
| MU-02 | 每类问题话术含四段：承认 / 解释 / 动作 / 时间 | §5 第 2 条 |
| MU-03 | 禁词零出现（系统繁忙、操作失败、敬请谅解、应该、大概） | §5 第 3 条 |
| MU-04 | 补偿有授权上限与审批人；承诺项不超出当前能力 | §5 第 4 条 |
| MU-05 | 三条升级触发写死，交接带四项信息（客户/摘要/已做/诉求） | §5 第 5 条 |
| MU-06 | 按 P 级统计首响达标率与解决达标率 | §5 第 6 条 |

## 二、软门（§6 自检，靠人抓）

| # | 常见错法 |
|---|---|
| MU-06 | 我分了四级，每级有时限，并写明从什么时候开始计时 |
| MU-07 | 每类问题我的话术都有承认/解释/动作/时间四段 |
| MU-08 | 我没有用「系统繁忙」「操作失败」「敬请谅解」 |
| MU-09 | 不确定的地方我明说了不确定，并给了给结论的时间 |
| MU-10 | 补偿我写了上限和谁批 |
| MU-11 | 我没有承诺未上线的功能 |
| MU-12 | 升级触发和时间节点我写死了 |
| MU-13 | 交接时我带了客户/摘要/已做/诉求四项 |
| MU-14 | 我按 P 级统计了首响与解决达标率 |

## 三、诚实说明

本卡没有可自动断言的门禁：话术是否安抚客户无法自动判定，SLA 履约率需要真实工单数据。禁词可机器扫，但那只覆盖一小部分。

## 四、怎么验（没门禁时的替代验证）

1. **双评**：两人独立按 §5 逐条判，一致率 ≥80%；
2. **抽样反查**：随机抽 3 条要求指出具体位置/数字；
3. **对照抽检**：与 `references/sla-playbook.md` 里的 BAD/GOOD 并列看。

> **纪律**：客服的目标不是「让客户不生气」，是「**让客户知道接下来会怎样**」。
