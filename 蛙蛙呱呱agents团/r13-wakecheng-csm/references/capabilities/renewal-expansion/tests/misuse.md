# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表是**人工评审清单**，逐条判真假。
> 版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 | 出处 |
|---|---|---|
| MU-01 | 客户按「健康分 × 金额」归入四象限，资源按象限分配 | §5 第 1 条 |
| MU-02 | 价值复盘含客户侧数字 ≥2 个，且不罗列功能 | §5 第 2 条 |
| MU-03 | 三档方案（保底/目标/理想）提前写好金额与毛利 | §5 第 3 条 |
| MU-04 | 让步必须逐项对应「换回什么」，且总额不超授权上限 | §5 第 4 条 |
| MU-05 | 涨价有理由、提前 ≥60 天告知、并提供多年锁定选项 | §5 第 5 条 |
| MU-06 | 放弃条件写死（健康分/地板价/客户明确拒绝），且有体面退出方案 | §5 第 6 条 |

## 二、软门（§6 自检，靠人抓）

| # | 常见错法 |
|---|---|
| MU-06 | 我按健康分×金额给客户排了象限，不是按感觉 |
| MU-07 | 我的复盘讲的是客户得到的数，不是我们的功能 |
| MU-08 | 三档方案的金额和毛利我都提前算好了 |
| MU-09 | 我每次让步都换回了东西（年限/用量/案例/转介绍） |
| MU-10 | 让步总额没超过我的授权上限 |
| MU-11 | 涨价我给了理由，提前 60 天说，还给了锁定选项 |
| MU-12 | 我写清了什么情况下放弃，以及放弃时怎么体面退出 |
| MU-13 | 我没有在客户一说贵就降价 |

## 三、诚实说明

本卡没有可自动断言的门禁：谈判质量取决于准备与授权边界，只能事后由结果与毛利验证。

## 四、怎么验（没门禁时的替代验证）

1. **双评**：两人独立按 §5 逐条判，一致率 ≥80%；
2. **抽样反查**：随机抽 3 条要求指出具体位置/数字；
3. **对照抽检**：与 `references/renewal-playbook.md` 里的 BAD/GOOD 并列看。

> **纪律**：续约的目标不是「保住这个客户」，是「**保住的同时不教会他下次继续压价**」。
