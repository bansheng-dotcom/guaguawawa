# 长文与稿件（Long-form Article）

> 一句话定位：**这个技能存在的意义，是防止「一篇读起来很顺、读完什么都没记住的文章」**。
> 长文最贵的失败不是文笔差，而是**没有承诺**：
> 读者不知道这篇要给他什么、结构撑不住篇幅、论据全是"业内人士认为"。
> 这三件事都能在写之前定下来，所以不该靠灵感。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「写一篇关于 X 的长文」「做个深度稿」
- 「这个选题值不值得写」「怎么组织结构」
- 「这篇能不能发了」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 小红书/短笔记 | 本角色的 `rednote-post` | 那是短内容结构，不是长文 |
| 品牌语调清洗与禁词 | 本角色的 `brand-voice` | 那是终稿校验 |
| 投放与分发 | `r12` 增长 | 那是渠道 |
| 事实研究本身 | `r05` 的 `evidence-ledger` | 本包要求论据有据，但不去做研究 |

**最小可开工输入**：**读者是谁 + 他要带走什么**（一句话）。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 目标读者（具体到角色） | 必需 | 写"所有人"等于没人，必须问 |
| 读者要带走的一句话 | 必需 | 无承诺不可写 |
| 篇幅与形式（短文/长文/系列） | 建议 | 缺则按 2000–3000 字默认 |
| 可用素材（数据/访谈/案例） | 建议 | 缺则标注"无一手素材"，只做观点文 |
| 发布渠道 | 建议 | 缺则按通用书面语，标注"未按平台校准" |

**追问纪律**：最多一轮，只问**读者是谁、要带走什么**。

---

## §3 执行流水线（Workflow）

### Step 1 · 选题与承诺（先定"读完得到什么"）
三件套写清：
- **读者**：具体角色（"刚接增长的运营"而不是"运营人员"）
- **承诺**：读完能带走的一句话（可执行或可判断）
- **反承诺**：这篇**不谈**什么（防扩散）

**判据**：承诺句如果换成"了解一下 X"，说明还没定。

### Step 2 · 结构（要能一句话复述）
```bash
python agent.py copy article --input <稿件.json>
```
结构必须满足：
1. **能一句话复述**（"它讲了三件事：A、B、C"）；
2. **每节有独立结论**（不能"下一节再说"）；
3. **首段给出承诺**（不要"在当今时代…"式开场）。

门禁实测：结构字段缺失或不合规即 FAIL（`article_dirty`）。

常用三种结构：

| 结构 | 适合 | 骨架 |
|---|---|---|
| 问题-归因-解法 | 方法论 | 现象 → 三个原因 → 对应动作 |
| 结论先行 | 观点文 | 结论 → 三条论据 → 反方与回应 |
| 时间线 | 复盘/案例 | 起点 → 三个转折 → 现在 |

- **产出**：大纲 + 每节结论
- **过关条件**：`agent.py copy article` 退出码 0

### Step 3 · 论据分级（每个断言要有出处）
| 级别 | 类型 | 写法 |
|---|---|---|
| A | 一手数据/访谈 | 给数字 + 来源 + 时间 |
| B | 公开报告/权威媒体 | 给来源 + 时间，说明口径 |
| C | 个人经验/案例 | 明确写"我的经验是…" |
| ❌ | 无出处的"业内认为" | **删掉或降级为 C** |

**铁律**：观点可以主观，**事实必须可核**。

### Step 4 · 写作纪律（三条最容易违反的）
1. **一段一意**：一段只讲一件事，超过 5 行拆段；
2. **少用形容词**：把"极大提升"换成具体数字或场景；
3. **每个小标题都是结论**：不写"关于成本"，写"成本被低估了三倍"。

### Step 5 · 发布前扫描
```bash
python harness.py edit --input <终稿.json>        # 语调与禁词（与 brand-voice 共用，已验证 0/1）
```
- 禁词清零、绝对化用语清除；
- 标题与正文承诺一致（标题党＝失信）；
- 引用链接可打开（抽测 3–5 条）。

## §4 交付物清单

| # | 交付物 | 载体 | 骨架出处 |
|---|---|---|---|
| 1 | 选题卡（读者/承诺/反承诺） | `.md` | 本文 §3 Step 1 |
| 2 | 大纲（每节结论式小标题） | `.md` | `../../../examples/article.json` |
| 3 | 正文终稿 | `.md` | 同上 |
| 4 | 论据清单（级别 + 来源 + 时间） | `.md` | 本文 §3 Step 3 |
| 5 | 发布前扫描结果 | 终端 JSON | `agent.py copy voice` |

- 命名：`article_<主题短码>_<YYYYMMDD>/`
- **论据清单必须随稿交付**；只有正文没有出处，等于无法核查。

---

## §5 质量门（一票否决，不过不给交付）

1. **选题三件套齐全**（读者 / 承诺 / 反承诺）；
2. **结构可一句话复述**，每节有独立结论（`copy article` 门禁）；
3. **首段给出承诺**，无"当今时代"式开场；
4. **每个事实断言有 A/B/C 级出处**，无"业内认为"；
5. **小标题是结论句**，不是名词短语；
6. **标题与正文承诺一致**（无标题党）；
7. **禁词与绝对化用语清零**（`harness edit` 门禁）。

> 验收命令：`python agent.py copy article --input <稿件.json>` + `python agent.py copy voice`
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许删掉论据清单让门禁变绿**。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 读者写"所有人" | 具体到角色：刚接增长的运营 |
| EX-02 | 没有承诺句，边写边找 | 先写"读完带走什么"，再动笔 |
| EX-03 | 「在当今快速发展的时代…」开场 | 首段直接给承诺或结论 |
| EX-04 | 小标题是名词（"关于成本"） | 写成结论（"成本被低估了三倍"） |
| EX-05 | 一节里讲三件事 | 一段一意，一节一结论 |
| EX-06 | 「业内普遍认为」 | 给来源，或降级为"我的经验" |
| EX-07 | 数据不标时间 | 市场数据必须标采集时间 |
| EX-08 | 标题夸张正文接不住 | 标题与正文承诺必须一致 |
| EX-09 | 形容词堆叠（"极大提升效率"） | 换具体数字或场景 |
| EX-10 | 只写支持的证据 | 列反方观点并回应 |
| EX-11 | 引用链接没测过 | 抽测 3–5 条能打开 |
| EX-12 | 写完不扫描就发 | 跑 `copy voice` 清禁词与绝对化用语 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `agent.py` 门禁跑不了 | 按 §6 人工核对，标注「未跑门禁」；**不得标记"可发布"** |
| 无一手素材 | 只做观点文，标注"无一手数据"，所有断言降为 C 级 |
| 只有大纲没正文 | 交付大纲，标注"未成稿"，不算完成 |
| 篇幅不足以撑承诺 | 砍承诺而不是灌水；宁可写短 |
| 题目涉争议 | 可写，但必须列反方并回应 |
| 用户要求标题党 | 拒绝；可给"吸引但不夸张"的替代标题 |
| 涉虚假宣传 | 明确拒绝，并给合规表达 |

**明确不做**
- 不做投放与分发（归 `r12`）；
- 不做小红书短笔记结构（归 `rednote-post`）；
- 不做事实研究本身（归 `r05`，本包只要求有据）；
- 不承诺流量、排名、转化。
