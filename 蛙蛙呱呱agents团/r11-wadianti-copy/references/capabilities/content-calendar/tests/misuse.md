# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表为人工评审清单。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 |
|---|---|
| MU-01 | 栏目 2–4 个，各有「讲什么/不讲什么」 |
| MU-02 | 频次由实际工时倒推，且按 70% 折减 |
| MU-03 | 选题池覆盖 ≥4 周，标素材是否齐备 |
| MU-04 | 复用规则写明路径与「必须改写开头」 |
| MU-05 | 停更/降频三种条件写死，且有提前一周公告规则 |
| MU-06 | 排期只排 4 周并含 1 周缓冲 |

## 二、软门（§6 自检）

| # | 常见错法 |
|---|---|
| MU-06 | 栏目不超过 4 个，每个都写了不讲什么 |
| MU-07 | 频次是按我的实际工时算的，还打了 7 折 |
| MU-08 | 选题池有 4 周的量，标了素材齐不齐 |
| MU-09 | 复用我只改开头和案例，没有原文照搬 |
| MU-10 | 停更条件我提前写了，不是临时决定 |
| MU-11 | 停更我会提前一周公告 |
| MU-12 | 排期只有 4 周，留了 1 周缓冲 |
| MU-13 | 我没有按「理想状态」排期 |

## 三、诚实说明

本卡没有可自动断言的门禁：产能与稳定性只能由实际发布记录验证。

> **纪律**：内容日历的目标不是「排满」，是「**让断更成为一次明确决策**」。
