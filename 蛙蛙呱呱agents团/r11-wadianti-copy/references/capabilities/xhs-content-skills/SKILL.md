# 小红书笔记发布包（XHS Content）

> 一句话定位：**这个技能存在的意义，是防止「写得很用心，但标题超字数、正文太短、标签没埋词」**。
> 小红书笔记最贵的失败不是文笔，而是**不满足平台硬规则**：
> 标题超 20 字被截断、正文不到 550 字不给流量、
> 标签没复用核心词等于没做关键词、CTA 忘了写就没人互动。
> 这些都是可校验的，不该靠"感觉差不多了"。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「写篇小红书」「这篇笔记能发吗」
- 「标题怎么起」「标签打什么」
- 「为什么没流量」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 长文/公众号/深度稿 | 本角色的 `longform-article` | 那是长内容，规则完全不同 |
| 投放与达人合作 | `r12` 的 `campaign-plan` | 那是付费流量 |
| 品牌语调与禁词总则 | 本角色的 `brand-voice` | 本包只管笔记结构 |
| 主图与封面提示词 | `agent.py platform visual --need "..."`（调 `r10`） | 视觉本体由 r10 负责，本卡只发起委托 |

**最小可开工输入**：**写什么 + 给谁看 + 一个核心词**。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| `title`（≤20 字，前 10 字含核心词） | 必需 | 超字数直接被拦 |
| `body`（**550–650 字**） | 必需 | 最反直觉的一条：短了不给流量 |
| `tags`（3–8 个） | 必需 | 少于 3 或多于 8 都拦 |
| `core_keywords`（核心词） | 必需 | 无核心词无法做埋词 |
| `cta`（互动引导） | 必需 | 空则拦 |
| `ai_assisted`（是否 AI 辅助） | 建议 | 为真时必须带 `#AI辅助创作` |

**追问纪律**：最多一轮，只问**核心词是什么、要不要带 AI 声明**。

## §3 执行流水线（Workflow）

### Step 1 · 标题（≤20 字 + 前 10 字含核心词）
```bash
python agent.py xhs note --input <笔记.json>
```
两条硬规则实测：

| 规则 | 判据 |
|---|---|
| 长度 **1–20 字**（emoji 计 1 字） | `xhs.title.length` |
| **前 10 字**必须含核心词 | `xhs.title.keyword` |

**"前 10 字含核心词"是最容易被忽略的一条**：
标题写了 18 字，核心词在第 12 个字，等于没埋——用户滑过去只看到前 10 个字。

- **产出**：合规标题
- **过关条件**：`xhs.title.length` + `xhs.title.keyword` 通过

### Step 2 · 正文（**550–650 字**，这是硬区间）
**这条几乎所有人第一次都会踩**：写完觉得够了，一数只有 400 字。

| 实测 | 结果 |
|---|---|
| 414 字 | FAIL（差 136 字） |
| 538 字 | FAIL（差 12 字） |
| 596 字 | PASS |

**不许灌水凑字数**：差 100 字就多给一个具体场景或一组数据，
而不是重复观点。字数不够说明**信息密度不足**，不是"写少了"。

### Step 3 · 标签（3–8 个 + 埋词闭环 ≥2）
| 规则 | 判据 |
|---|---|
| 标签 3–8 个 | `xhs.tags.count` |
| **≥2 个标签复用核心词** | `xhs.tags.closure`（埋词闭环） |

**埋词闭环的含义**：标题、正文、标签三处都要出现核心词。
只在标题出现＝没形成闭环，平台无法确认这篇的主题。

### Step 4 · CTA 与禁词
```bash
python agent.py xhs compliance --input <笔记.json>
```
- `cta` 非空（"评论区聊聊""你们怎么选"都行）；
- 禁词清零：极限词（最/第一/绝对）、医疗功效、虚假承诺；
- **`ai_assisted` 为真时必须带 `#AI辅助创作`**，否则拦。

### Step 5 · 八项质量快检
```bash
python agent.py xhs score --input <笔记.json>
```
快检给分，但**分数不是发布门槛**——`note` 门禁才是。分数低但结构合规仍可发，
分数高但结构不合规不能发。

## §4 交付物清单

| # | 交付物 | 载体 | 骨架出处 |
|---|---|---|---|
| 1 | 笔记 JSON（标题/正文/标签/核心词/CTA） | `.json` | `tests/xhs-pass.json` |
| 2 | 埋词位置表（标题/正文/标签各出现几次） | `.md` | 本文 §3 Step 3 |
| 3 | 禁词扫描结果 | 终端 JSON | `agent.py xhs compliance` |

- 命名：`xhs_<主题短码>_<YYYYMMDD>.json`
- **埋词位置表必须随笔记交付**；否则无法确认关键词布局。

## §5 质量门（一票否决，不过不给交付）

1. **标题 1–20 字**（`xhs.title.length`）；
2. **标题前 10 字含核心词**（`xhs.title.keyword`）；
3. **正文 550–650 字**（`xhs.body.length`）；
4. **标签 3–8 个**（`xhs.tags.count`）；
5. **≥2 个标签复用核心词**（`xhs.tags.closure`）；
6. **CTA 非空**（`xhs.cta`）且**禁词清零**（`xhs.cta.blacklist`）；
7. **AI 辅助须带 `#AI辅助创作`**（`ai_assisted` 为真时）。

> 验收命令：`python agent.py xhs note --input <笔记.json>`
> 命中任一项不过 → 回 §3 对应 Step，**不允许灌水凑字数或删标签让门禁变绿**。

---

## §6 交付前自检清单

- [ ] 标题数过，≤20 字，且核心词在前 10 个字里
- [ ] 正文数过，在 550–650 字之间（不是"感觉够了"）
- [ ] 字数不够时补的是**具体场景/数据**，不是重复观点
- [ ] 标签 3–8 个
- [ ] 至少 2 个标签复用了核心词（埋词闭环）
- [ ] CTA 写了，且是具体互动引导
- [ ] 禁词扫描过，无极限词/医疗功效/虚假承诺
- [ ] 如果用了 AI 辅助，正文或标签里有 `#AI辅助创作`
- [ ] 标题和正文承诺一致，没有标题党

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 标题 25 字 | ≤20 字（emoji 计 1 字） |
| EX-02 | 核心词放在标题第 12 字 | 前 10 字必须含核心词 |
| EX-03 | 正文 400 字就投 | 550–650 字，硬区间 |
| EX-04 | 灌水凑字数 | 补具体场景/数据，不重复观点 |
| EX-05 | 标签只打 2 个 | 3–8 个 |
| EX-06 | 标签与核心词无关 | ≥2 个标签复用核心词 |
| EX-07 | 只标题埋词 | 标题+正文+标签三处闭环 |
| EX-08 | 忘了写 CTA | 给具体互动引导 |
| EX-09 | 用"最/第一/绝对" | 极限词必删 |
| EX-10 | 用了 AI 不声明 | 加 `#AI辅助创作` |
| EX-11 | 把 `score` 高分当发布许可 | `note` 门禁才是门槛 |
| EX-12 | 标题党正文接不住 | 标题与正文承诺一致 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `agent.py` 门禁跑不了 | 按 §6 人工核对，标注「未跑门禁」；**不得标记"可发"** |
| 素材不足以写 550 字 | 说明"信息不足"，宁可不发也不灌水 |
| 品类涉医疗/功效 | 明确不做功效宣称，只写使用体验 |
| 需要带商品链接 | 说明平台规则可能限流，标注风险 |
| 需要多平台适配 | 本包只出小红书形态；其他平台另走 |
| 有竞品对比 | 可写，但不点名贬低 |

**明确不做**
- 不做长文/深度稿（归 `longform-article`）；
- 不做投放与达人（归 `r12`）；
- 不做品牌语调总则（归 `brand-voice`）；
- 不承诺流量、排名、转化。
