# 品牌语调（Brand Voice）

> 一句话定位：**这个技能存在的意义，是防止"每一篇单看都对，放一起不像同一个品牌"**。
> 语调失守从来不是突然崩的，是三件小事累积：禁词漏了一次、术语这次叫 A 下次叫 B、
> 口吻跟着模板漂。等用户发现"你们文案风格差好多"时，已经污染了几十篇。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这段文案像不像我们」「帮我把黑话洗掉」「术语统一一下」
- 「这篇能不能发了」「有没有违规词」
- 「同一批 20 篇文风要一致」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 从零写一篇 | `r11` 的内容主笔（`article` / `copy`） | 本技能做**终稿清洗与校验**，不负责创作 |
| 投放与排期 | `r12` 增长 | 分发不是语调问题 |
| 视觉与排版 | `r10` 设计 | 视觉规范另有一套 |
| 保证关键词排名 | 拒绝 | 只做结构与合规扫描，**不承诺排名** |

**最小可开工输入**：**一段终稿文本** + **一份禁词表或术语表**（任一）。两者皆无 → 只能做通用扫描，结论降级。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 终稿 `text` | 必需 | 无文本即无法清洗，`voice.edit.text` BLOCKER |
| 禁词表 `forbidden_hits` | 必需 | 缺则用内置高频黑话表（标注"未使用品牌自定义词表"） |
| 术语替换 `term_fixes[{from,to}]` | 建议 | 缺则跳过术语统一，标注"未做术语统一" |
| 平台与受众 | 建议 | 缺则按通用书面语处理，标注"未按平台校准口吻" |
| 品牌风格指南 | 可选 | 缺失时按 `references/voice-rules.md` 的默认阶梯执行 |

**追问纪律**：最多一轮，只问**文本在哪、词表有没有**。其余按内置规则默认执行并标注。

## §3 执行流水线（Workflow）

### Step 1 · 定口吻基线（先确认"像谁在说"）
三件事定死：**人称**（我们/本平台/第三人称）、**语体**（口语/书面/专业）、**温度**（克制/热情）。
三者不一致是"AI 味"的主因——一段里既"亲"又"兹"，读起来就是拼的。

- **产出**：口吻基线三行
- **过关条件**：三项都写定，不能写"看情况"

### Step 2 · 禁词清零（一票否决）
把 `forbidden_hits` 当**列表**（不是字符串），逐条在终稿中检索并清除。
常见黑话：赋能、抓手、闭环、生态位、颗粒度、对齐一下、组合拳、护城河……

**硬规则**：禁词残留数必须为 **0**。清一遍就交付 = 必被打回。

- **产出**：`forbidden_hits[]` + 清除后的终稿
- **过关条件**：`voice.edit.hits`（列表结构）与 `voice.edit.residual`（残留=0）双过

### Step 3 · 术语统一（from → to，逐条替换到无残留）
每条 `{from, to}` 是一次确定性替换。注意两个坑：
- `to` 为空字符串 = **删除**该词，不是"待定"；
- 替换后必须复查：`from` 不能再出现（换完还留一半是常态）。

- **产出**：`term_fixes[]` + 替换后的终稿
- **过关条件**：每条含 `from`/`to` 且替换后 `from` 残留 = 0

### Step 4 · 口吻回归检查（比禁词更难）
禁词是硬指标，口吻是软指标。逐句问三件事：
1. 这句话**换个人说**还成立吗？成立 → 太泛，删或具体化；
2. 有没有**形容词堆叠**（"高效便捷智能"）？有 → 换成一个可验证的事实；
3. 有没有**模板腔**（"在当今快速发展的…"）？有 → 直接删。

- **产出**：逐段问题清单
- **过关条件**：无连续两句以上纯形容词或模板腔

### Step 5 · 结构与合规扫描（SEO / E-E-A-T / 引用）
```bash
python harness.py audit --input <文章审计.json>
```
检查三件事：
- **结构**：H2 层级、段落长度、可扫读性；
- **E-E-A-T**：有无过度承诺与空泛权威（"业内领先""专家都说"）；
- **引用**：外部数据是否标来源；无来源的断言必须软化或删除。

- **产出**：`seo.*` 结论
- **过关条件**：`audit` 退出码 0

### Step 6 · 术语与本地化一致性
```bash
python harness.py term --input <术语.json>
```
同一概念全篇同一叫法；中英混排、全半角、大小写也在此关统一。

- **产出**：`localize.*` 结论
- **过关条件**：`term` 退出码 0

### Step 7 · 跑终稿门禁（最终裁决）
```bash
python harness.py edit --input <终稿.json>
```
结构：`{text, forbidden_hits: [...], term_fixes: [{from, to}]}`。

- **产出**：`voice.edit.*` 结论
- **过关条件**：`edit` 退出码 0

## §4 交付物清单

| # | 交付物 | 载体 | 骨架出处 |
|---|---|---|---|
| 1 | 口吻基线（人称/语体/温度） | `.md` | `references/voice-rules.md` §一 |
| 2 | 清洗后终稿 | `.md` / `.json` | 本文 §3 输出 |
| 3 | 禁词命中与清除记录 | 终端 JSON | `harness.py edit` |
| 4 | 术语替换表（from→to） | `.json` 片段 | `tests/voice-pass.json` 的 `term_fixes` 字段 |
| 5 | 结构与合规审计结论 | 终端 JSON | `harness.py audit` |
| 6 | 术语/本地化一致性结论 | 终端 JSON | `harness.py term` |

- 命名：`voice_<平台>_<稿件短码>_<YYYYMMDD>.json`
- **只有清洗后的终稿 + 三份门禁结论一起交付才算完成**；单独一段"改好了的文本"不算。

## §5 质量门（一票否决，不过不给交付）

1. **终稿字段存在**（`voice.edit.text`）；
2. **`forbidden_hits` 是列表**（不是字符串，BLOCKER）；
3. **禁词残留 = 0**（`voice.edit.residual`，BLOCKER）；
4. **`term_fixes` 每条含 `from`/`to`**，替换后 `from` 残留 = 0；
5. **口吻基线三项写定**，且全文一致；
6. **无过度承诺与空泛权威**（E-E-A-T 扫描通过）；
7. **外部数据均有来源**，无来源断言已软化或删除。

> 验收命令：`python harness.py edit --input <终稿.json>` + `audit` + `term`
> 命中任一项不过 → 回 §3 对应 Step 重做，**不允许只把禁词表清空让门禁变绿**。

## §6 交付前自检清单

- [ ] 口吻基线（人称/语体/温度）三项都写了，没有"看情况"
- [ ] 终稿通读一遍，读起来像同一个人在说话
- [ ] 禁词逐条清过，不是"看一眼觉得没有"
- [ ] `forbidden_hits` 是列表结构，不是一串逗号文本
- [ ] 每条术语替换都有 `to`（要删就写空字符串，不留空待定）
- [ ] 替换后复查过：`from` 词一个都没剩
- [ ] 没有连续两句以上的纯形容词堆叠
- [ ] 没有"在当今快速发展的…"这类模板开场
- [ ] 外部数据都标了来源，或已软化表述
- [ ] 无"业内领先""专家都说"这类空泛权威
- [ ] `edit` / `audit` / `term` 三道门禁均退出码 0
- [ ] 清洗后的终稿已落盘，可被发布流程直接取用

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | `forbidden_hits` 写成 `"赋能,抓手"` 一串文本 | 必须是**列表** `["赋能","抓手"]`；字符串会被判 BLOCKER |
| EX-02 | 把要删的词写成 `{"from":"抓手","to":""}` 但以为"待定" | `to` 为空即**删除**，这是明确语义，不是没填 |
| EX-03 | 替换一半就交付（"抓手"换了，"闭环"没换） | 逐条替换后**复查**：每个 `from` 残留必须为 0 |
| EX-04 | 把禁词表清空让门禁通过 | 门禁查的是**终稿残留**，清表等于作弊，会被 `residual` 抓到 |
| EX-05 | 形容词堆叠当卖点（"高效便捷智能"） | 换成一个可验证的事实或数字 |
| EX-06 | 模板开场（"在当今快速发展的时代"） | 直接删；第一句就要说事 |
| EX-07 | 同一概念正文叫 A、标题叫 B | 术语表统一，`term` 门禁会抓 |
| EX-08 | 写"业内领先""专家一致认为" | 空泛权威；要么给具体来源，要么删 |
| EX-09 | 引用外部数据不标来源 | 无来源的断言必须软化（"据…公开资料"）或删除 |
| EX-10 | 只做一遍就交付 | 至少两遍：**先清词、再读口吻**；一遍只能抓机械问题 |
| EX-11 | 承诺"发了一定有流量" | 只做结构与合规，**不承诺排名与流量** |
| EX-12 | 中英混排、全半角、大小写不统一 | `term` 门禁覆盖本地化一致性，逐项过 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `harness.py` 跑不了 | 按 §6 人工逐项核对，标注「未跑门禁」；**不得标记"可发布"**，最多"待门禁复核" |
| 没有品牌自定义禁词表 | 用内置高频黑话表，交付物标注「未使用品牌自定义词表」 |
| 没有品牌风格指南 | 按 `references/voice-rules.md` 默认阶梯执行，标注「未按品牌指南校准」 |
| 只给一段话没给平台 | 按通用书面语处理，标注「未按平台校准口吻」 |
| 用户要求"写得夸张点好传播" | 可以调温度，但**禁词与绝对化用语不放开**；夸大事实一律拒绝 |
| 原文是别人写的（代改） | 保留原作者署名与观点，只做语调与术语层面修改，并标注改动范围 |
| 需求涉虚假宣传 | 明确拒绝，并给合规表达替代 |

**明确不做**
- 不承诺关键词排名、流量、转化（归数据侧验证）；
- 不做视觉与排版（归 `r10`）；
- 不做投放与分发（归 `r12`）；
- 不从零创作长文（归 `r11` 内容主笔）。
