# 口吻基线与禁词规则（voice-rules）

> 被 §3、§5、§7 按需引用。版本：v2.0.0（项目自建，v1）

---

## 一、口吻基线三要素（三行必须写定）

```markdown
- 人称：我们 / 本平台 / 第三人称（选一个，全篇不改）
- 语体：口语 / 半书面 / 专业书面（选一个）
- 温度：克制 / 中性 / 热情（选一个）
```

**为什么必须写定**：一段里既"亲们"又"兹"，读起来就是两个人拼的。
"AI 味"的根因不是用词错，是**同一段里混了三种基线**。

| 组合 | 适合 | 反例 |
|---|---|---|
| 我们 + 口语 + 克制 | 工具类产品、教程 | — |
| 本平台 + 专业书面 + 中性 | 公告、条款、财报口径 | — |
| 我们 + 半书面 + 热情 | 活动、社群 | — |
| 混用 | ❌ 任何场景 | "亲们，兹定于…" |

## 二、禁词与替换阶梯

### 2.1 高频黑话（内置默认表）

| 黑话 | 为什么该删 | 替换方向 |
|---|---|---|
| 赋能 | 空，说不清谁给谁什么能力 | 直接写"帮 X 做到 Y" |
| 抓手 | 内部术语，用户不懂 | "方法""切入点" |
| 闭环 | 内部术语 | "完整流程""走完一轮" |
| 颗粒度 | 内部术语 | "细化到什么程度" |
| 对齐 | 内部术语 | "确认""统一" |
| 生态位 | 咨询术语 | "在哪些场景不可替代" |
| 组合拳 | 空 | "三步一起做" |
| 护城河 | 空 | "为什么别人抄不走" |
| 降本增效 | 口号 | 给具体数字 |

### 2.2 替换阶梯（按顺序尝试）

| 档 | 做法 | 例 |
|---|---|---|
| A 删 | 整句删掉，语义仍完整 | "我们将持续赋能生态" → 删除 |
| B 具体化 | 换成"谁 对 谁 做什么" | "赋能商家" → "帮商家把上架时间从 2 小时压到 15 分钟" |
| C 换口语 | 换成人话同义词 | "抓手" → "方法" |

**铁律**：**A 删最优先**。大部分黑话删掉后句子更好，不是更差。

## 三、绝对化与空泛权威（合规相关，不是风格问题）

| 类型 | 样例 | 处置 |
|---|---|---|
| 绝对化 | 最好、第一、唯一、国家级、100% 有效 | 删或改量化（带来源与统计期） |
| 空泛权威 | 业内领先、专家一致认为、公认 | 给具体来源，或删 |
| 过度承诺 | 永久、终身、零风险、必涨 | 改具体条件与时限 |
| 模糊时限 | 限时、最后一波 | 改具体截止时间 |

> 与 `r10` 的广告法口径一致：**这两层共用同一套红线**，
> 区别只是 `r10` 面向视觉文案，本技能面向长文与终稿。

## 四、术语统一（同一概念只有一个叫法）

```json
"term_fixes": [
  {"from": "抓手", "to": "方法"},
  {"from": "闭环", "to": ""}
]
```

- `to` 为**空字符串** = 删除该词，这是明确语义（不是"没填"）；
- 替换后必须**复查**：`from` 残留数必须为 0；
- 一个概念在标题/正文/图注三处必须同名。

### 本地化一致性（`harness term` 覆盖）

| 项 | 规则 |
|---|---|
| 中英混排 | 中文与英文之间加空格（可配团队规范） |
| 全半角 | 标点统一用全角（代码/URL 除外） |
| 大小写 | 产品名、专有名词大小写全篇一致 |
| 数字 | 同一篇内"3 天"与"三天"不混用 |

## 五、口吻回归三问（禁词清完后必做）

逐句问：

1. **换个人说还成立吗？** 成立 → 太泛，删或具体化。
2. **有形容词堆叠吗？**（"高效便捷智能"）有 → 换成一个可验证的事实。
3. **有模板腔吗？**（"在当今快速发展的…"）有 → 直接删。

**判据**：全文不允许出现**连续两句以上**的纯形容词或模板腔。
一句空话可以忍，两句连排就是水。

## 六、两遍法（省时间的实操）

| 遍 | 只关注 | 产出 |
|---|---|---|
| 第 1 遍 | 机械项：禁词、术语、全半角、大小写 | 用脚本跑 `edit` / `term` |
| 第 2 遍 | 口吻项：基线一致、形容词堆叠、模板腔 | 人工逐段读 |

**不要一遍同时干两件事**——一遍只能抓机械问题，两遍才抓得住口吻。
反过来，用人工去找"赋能"这类词是浪费，交给脚本。

## 七、与门禁的对应关系

| 门禁 | 覆盖本文件哪一节 | 判不了什么 |
|---|---|---|
| `harness.py edit` | §二 禁词残留、§四 术语替换 | 判不了口吻好不好 |
| `harness.py audit` | §三 绝对化与空泛权威、结构 | 判不了品牌是否真这么说话 |
| `harness.py term` | §四 本地化一致性 | 判不了术语选得对不对 |

> 三道门禁合起来能保证"没有硬伤"，**保证不了"写得好"**。
> 后者只能靠人读，以及长期维护一份品牌风格指南。
