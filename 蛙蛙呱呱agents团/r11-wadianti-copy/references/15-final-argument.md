# 15 终稿：论证流与 AI 味密度

## 方法

终稿不是把章节拼起来，而是检查论证流是否闭合。每节按“结论 → 证据 → 边界”排列：
- 结论：一句可反驳的判断；
- 证据：来源原文与数字，数字必须能追到 claims；
- 边界：这条判断在什么条件下失效。

终检四类：
1. 结构完整：H1 + 与细纲一一对应的 H2 + 结尾“边界与后续”；
2. 论证流：每节含数字、含边界句、至少两句；
3. AI 味密度：每千字套话命中 ≤0.5；
4. 事实与长度：正文数字 ⊆ claims 数字 ∪ 专名数字；正文字符数落在平台区间。

专名里的数字（如 R11）不算事实数字，但也不允许把专名改成别的数字。

## 适用边界

- 只做终检与整合，不在终稿阶段新增章节或事实；
- 平台长度按 brief 的 constraints 读取，缺省 800–6000 字；
- 套话密度是入口指标，命中 0 也不代表文章一定好；
- 数字核对只保证“可追溯”，不保证来源本身可靠。

## 误用反例

- 每节都写“综上所述”：套话密度超阈值，`final.ai_fluff` 判 FAIL。
- 结论段没有任何数字：`final.argument_flow` 判 FAIL。
- 正文出现 claims 里没有的“增长 300%”：`final.fact_check` 判 FAIL 并列出多余数字。
- 全文 700 字却要求 1200 字以上：`final.platform_length` 判 FAIL。
