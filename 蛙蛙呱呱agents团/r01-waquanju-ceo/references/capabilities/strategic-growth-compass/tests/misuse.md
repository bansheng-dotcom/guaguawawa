# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`，无命令门禁），因此本表是**人工评审清单**。
> 每条都由评审者判真假，判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| MU-01 | 每条路线都写了「放弃什么」 | §5 第 1 条 |
| MU-02 | 增长来源落到四个杠杆之一，并说明天花板 | §5 第 2 条 |
| MU-03 | 季度动作 ≤6 个，每个有可验证指标 | §5 第 3 条 |
| MU-04 | 每条路线都有停止条件 | §5 第 4 条 |

## 二、软门（§6 自检，靠人抓）

| MU-04 | 我写清了当前增长主要靠哪个杠杆 |
| MU-05 | 每条路线都有「放弃」栏且不是空的 |
| MU-06 | 季度动作不超过 6 个 |
| MU-07 | 每个动作都有能被验证的指标（不是「加强」「优化」） |
| MU-08 | 每条路线都写了停止条件 |
| MU-09 | 我能一句话说清「为什么不做另外两条」 |

## 三、诚实说明

本卡**没有**可自动断言的门禁：它的输入是判断与决策，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——这比没有门禁更糟。

> **纪律**：knowledge 卡的价值在「有方法可依」，不在「有分数可刷」。
