# 战略与增长罗盘（strategic-growth-compass）

> **这是 knowledge 卡**：没有可执行门禁（`entry: null`），价值在「方法可依」而非「结果可判」。
> 它现在有 `SKILL.md` 载体，因此会出现在技能索引里、能被模型按需读取；
> 在此之前它是 `README.md`，**模型根本不知道它存在**。

## §1 何时用 / 何时不用

**该用**：战略与增长罗盘

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 执行排期与资源分配 | `r02` COO | 那是把方向落成排期 |
| 财务测算与现金流 | `r03` CFO | 那是数字校验 |
| 具体增长实验设计 | `r12` 增长 | 那是执行层 |

**最小可开工输入**：当前业务的三个关键数字（收入/客户数/留存）

## §2 前置输入与最省追问

| 输入 | 是否必需 |
|---|---|
| 当前业务的三个关键数字（收入/客户数/留存） | 必需或建议 |
| 一句话现状判断 | 必需或建议 |
| 想比较的 2–3 条路线 | 必需或建议 |

**追问纪律**：最多一轮，缺什么按 §8 降级处理，不连环追问。

## §3 执行流水线（Workflow）

### Step 1 · 拆增长来源
把增长拆成四个杠杆：**获客 / 留存 / 客单 / 复购**。指出当前主要靠哪一个，以及它的天花板。

**判据**：四个杠杆必须逐一判断，不许只讲一个

### Step 2 · 给每条路线写代价
每条路线必须写清 **放弃什么**（钱/人/时间/某个客群）。写不出代价的路线是愿望，不是战略。

**判据**：没有「放弃」栏的路线直接作废

### Step 3 · 反推季度动作
把选中的路线反推成 4–6 个季度动作，每个动作要有 **负责人类型 + 可验证指标**。

**判据**：动作超过 6 个说明没聚焦

### Step 4 · 定停止条件
每条路线写「什么信号出现就停」。这是防止「沉没成本继续投」的唯一机制。

**判据**：无停止条件不许提交

## §5 质量门（一票否决）

1. 每条路线都写了「放弃什么」；
2. 增长来源落到四个杠杆之一，并说明天花板；
3. 季度动作 ≤6 个，每个有可验证指标；
4. 每条路线都有停止条件；

> 本卡无自动门禁。**任一项不过即不得交付**，且必须在交付物里写明「逐项人工核对」。
> 可用 `python agent.py intent brief` 做间接校验（若该命令存在）。

## §6 交付前自检清单

- [ ] 我写清了当前增长主要靠哪个杠杆
- [ ] 每条路线都有「放弃」栏且不是空的
- [ ] 季度动作不超过 6 个
- [ ] 每个动作都有能被验证的指标（不是「加强」「优化」）
- [ ] 每条路线都写了停止条件
- [ ] 我能一句话说清「为什么不做另外两条」

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 只讲方向不讲放弃 | 写清每条路线放弃什么 |
| EX-02 | 增长来源含糊「多获客」 | 落到四杠杆之一并给天花板 |
| EX-03 | 季度动作列 12 个 | ≤6 个，多了说明没聚焦 |
| EX-04 | 指标写「提升转化」 | 写「转化从 2% 到 3.4%」 |
| EX-05 | 没有停止条件 | 每条路线写清什么信号出现就停 |
| EX-06 | 路线之间不可比 | 用同一组维度（钱/人/时间/风险）对比 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 只有定性判断无数字 | 标注「无数据」，同时给判断依据 |
| 只能给一条路线 | 说明为什么排除其他，而不是假装比较过 |
| 创始人已决定方向 | 转为「反推季度动作 + 停止条件」，不重开战略 |
| 涉及融资/裁员 | 升级创始人 + `r03`，本卡只给方向不签字 |
| 多业务线并行 | 每条业务线各做一份，不合并在一个罗盘里 |

**明确不做**：不排期、不算财务、不拍板、不签合同。
