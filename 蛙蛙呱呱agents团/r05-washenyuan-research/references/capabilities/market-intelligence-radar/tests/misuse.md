# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`，无命令门禁），因此本表是**人工评审清单**。
> 每条都由评审者判真假，判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| MU-01 | 3–8 家竞品，六维齐全 | §5 第 1 条 |
| MU-02 | 每条情报有时间与来源 | §5 第 2 条 |
| MU-03 | 每条重要情报有一句判断 | §5 第 3 条 |
| MU-04 | 至少记录 3 条「本季度变化」 | §5 第 4 条 |

## 二、软门（§6 自检，靠人抓）

| MU-04 | 六维表里没有空格（拿不到就写「未知」） |
| MU-05 | 每条情报都有时间和来源 |
| MU-06 | 超过 6 个月的标了「可能过期」 |
| MU-07 | 每条重要情报都有「意味着什么」 |
| MU-08 | 我记的是变化不只是状态 |
| MU-09 | 没有把对手方案直接当我们的方案 |

## 三、诚实说明

本卡**没有**可自动断言的门禁：它的输入是判断与决策，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——这比没有门禁更糟。

> **纪律**：knowledge 卡的价值在「有方法可依」，不在「有分数可刷」。
