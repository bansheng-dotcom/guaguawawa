# 深度研究（deep-research-assistant）

> **这是 knowledge 卡**：没有可执行门禁（`entry: null`），价值在「方法可依」而非「结果可判」。
> 它现在有 `SKILL.md` 载体，因此会出现在技能索引里、能被模型按需读取；
> 在此之前它是 `README.md`，**模型根本不知道它存在**。

## §1 何时用 / 何时不用

**该用**：做一次有明确问题的专题研究、验证一个假设、或搞清一个陌生领域

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 快速摸行业格局 | `industry-panorama-research` | 那是结构化行业研究 |
| 竞品逐家拆解 | `market-intelligence-radar` | 那是竞品情报 |
| 替创始人决策 | `r01` | 研究只给事实 |

**最小可开工输入**：一个具体的待研究主题

## §2 前置输入与最省追问

| 输入 | 是否必需 |
|---|---|
| 一个具体的待研究主题 | 必需或建议 |
| 研究目的（决策/学习/写作） | 必需或建议 |
| 时间预算 | 必需或建议 |

**追问纪律**：最多一轮，缺什么按 §8 降级处理，不连环追问。

## §3 执行流水线（Workflow）

### Step 1 · 立研究问题
把主题拆成 3–5 个**可回答**的问题（能被一条证据支持或否证的）。

**判据**：问题不能是「了解一下X」这种不可回答的

### Step 2 · 逐题收证
每题至少 2 条独立来源，标注等级：A 一手数据 / B 权威报告 / C 经验判断。

**判据**：同一来源不能当两条用

### Step 3 · 记录矛盾
两条证据冲突时必须并列记录，不许挑一条丢一条。

**判据**：矛盾点是最有价值的产出

### Step 4 · 出三栏结论
分「已知（有 A/B 级证据）/ 未知（缺证据）/ 矛盾（证据冲突）」三栏。

**判据**：未知项要写清缺什么证据


## §4 交付物清单

| # | 交付物 | 载体 |
|---|---|---|
| 1 | 研究问题清单（3–5 个） | `.md` |
| 2 | 证据台账（含等级与来源） | `.md` |
| 3 | 已证/未知/矛盾三栏结论 | `.md` |

## §5 质量门（一票否决）

1. 研究问题 3–5 个且都可回答；
2. 每题 ≥2 条独立来源并标等级；
3. 矛盾点已并列记录；
4. 三栏结论齐全，未知项写明缺什么；

> 本卡无自动门禁。**任一项不过即不得交付**，且必须在交付物里写明「逐项人工核对」。
> 可用 `python agent.py research question` 做间接校验（若该命令存在）。

## §6 交付前自检清单

- [ ] 每个问题都能被一条证据支持或否证
- [ ] 每题至少两条独立来源
- [ ] 我标了来源等级（A/B/C）
- [ ] 冲突的证据我并列写了，没挑着用
- [ ] 未知项写清了「缺什么证据才能回答」
- [ ] 结论里没有「业内普遍认为」

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 问题太大「研究一下AI」 | 拆成可回答的小问题 |
| EX-02 | 一个来源当多条用 | 独立来源才算，转载不算 |
| EX-03 | 冲突证据挑着用 | 并列记录并说明为何采信一条 |
| EX-04 | 把 C 级判断写成结论 | C 级必须标明是判断 |
| EX-05 | 未知项不写 | 未知项是研究价值所在 |
| EX-06 | 不做来源分级 | 逐条标 A/B/C |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 找不到一手数据 | 只用 B 级并标注「无一手验证」 |
| 时间预算不足 | 缩减问题数，不缩减来源标准 |
| 只有中文来源 | 标注「未覆盖英文/海外来源」 |
| 涉密或不可公开 | 写「不可公开核·来源类型」并用 C 级 |
| 结论与客户预期相反 | 照实写，附证据强度 |

**明确不做**：不做投资建议、不做行业全景、不替客户下结论。
