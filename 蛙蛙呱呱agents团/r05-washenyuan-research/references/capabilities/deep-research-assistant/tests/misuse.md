# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`，无命令门禁），因此本表是**人工评审清单**。
> 每条都由评审者判真假，判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| MU-01 | 研究问题 3–5 个且都可回答 | §5 第 1 条 |
| MU-02 | 每题 ≥2 条独立来源并标等级 | §5 第 2 条 |
| MU-03 | 矛盾点已并列记录 | §5 第 3 条 |
| MU-04 | 三栏结论齐全，未知项写明缺什么 | §5 第 4 条 |

## 二、软门（§6 自检，靠人抓）

| MU-04 | 每个问题都能被一条证据支持或否证 |
| MU-05 | 每题至少两条独立来源 |
| MU-06 | 我标了来源等级（A/B/C） |
| MU-07 | 冲突的证据我并列写了，没挑着用 |
| MU-08 | 未知项写清了「缺什么证据才能回答」 |
| MU-09 | 结论里没有「业内普遍认为」 |

## 三、诚实说明

本卡**没有**可自动断言的门禁：它的输入是判断与决策，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——这比没有门禁更糟。

> **纪律**：knowledge 卡的价值在「有方法可依」，不在「有分数可刷」。
