# 学术研究与写作（tashan-research-skills）

> **这是 knowledge 卡**：没有可执行门禁（`entry: null`），价值在「方法可依」而非「结果可判」。
> 它现在有 `SKILL.md` 载体，因此会出现在技能索引里、能被模型按需读取；
> 在此之前它是 `README.md`，**模型根本不知道它存在**。

## §1 何时用 / 何时不用

**该用**：写带文献支撑的分析、做方法论说明、或把研究写成可被同行审阅的文档

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 快速决策用研究 | `deep-research-assistant` | 那是轻量研究 |
| 商业报告排版 | `r08` 的 `html-report-presentation` | 那是呈现 |
| 替客户做投资判断 | `r01` | 研究不越界 |

**最小可开工输入**：研究问题

## §2 前置输入与最省追问

| 输入 | 是否必需 |
|---|---|
| 研究问题 | 必需或建议 |
| 已收集的文献/资料 | 必需或建议 |
| 目标读者（同行/客户/内部） | 必需或建议 |

**追问纪律**：最多一轮，缺什么按 §8 降级处理，不连环追问。

## §3 执行流水线（Workflow）

### Step 1 · 建文献表
每条文献记：作者/年份/标题/来源/可访问链接。缺链接的标「不可核」。

**判据**：不可核的文献不能作为主论据

### Step 2 · 写三段论证
每个主张都写「主张 → 证据 → 推理」。三段缺一即是观点而非论证。

**判据**：推理段要写清「为什么这条证据支持这个主张」

### Step 3 · 区分引用类型
直接引用加引号并给位置；转述要注明「据 X（年）」。

**判据**：混淆两者是学术不端

### Step 4 · 写明适用范围
结论必须写「在什么条件下成立、不适用什么场景」。

**判据**：无适用范围的结论是过度概括

## §5 质量门（一票否决）

1. 每条文献可追溯（有链接或标「不可核」）；
2. 每个主张都是三段论证；
3. 直接引用与转述已区分；
4. 结论写明适用范围与局限；

> 本卡无自动门禁。**任一项不过即不得交付**，且必须在交付物里写明「逐项人工核对」。
> 可用 `python agent.py research question` 做间接校验（若该命令存在）。

## §6 交付前自检清单

- [ ] 每条文献都有作者/年份/来源
- [ ] 主论据没有一条是「不可核」的
- [ ] 每个主张都写了推理段
- [ ] 直接引用加了引号并给出处
- [ ] 转述标了「据 X（年）」
- [ ] 结论写了适用范围和局限

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 引用无出处 | 每条文献给作者/年份/链接 |
| EX-02 | 只有主张没有推理 | 补「为什么这条证据支持它」 |
| EX-03 | 直接引用不标引号 | 加引号并给页码或段落 |
| EX-04 | 转述写成自己的话 | 注明「据 X（年）」 |
| EX-05 | 结论过度概括 | 写明适用范围与反例 |
| EX-06 | 不写局限 | 局限是可信度的一部分 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 文献拿不到全文 | 只引摘要并标注「未读全文」 |
| 无法获取页码 | 给章节或段落位置 |
| 文献为外语 | 保留原文标题 + 中文译名 |
| 研究涉及争议议题 | 并列多方观点，不站队 |
| 被要求删掉不利证据 | 拒绝；可加「证据强度有限」说明 |

**明确不做**：不代写论文、不承诺查重率、不伪造引用。
