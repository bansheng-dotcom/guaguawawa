# R06 蛙得清 · 商业分析分期的数据与口径规范

> 角色：R06 蛙得清（数据分析师，战略、数据与智能层）
> 主题：从数据侧讲清「商业分析分期」怎么落地
> 术语口径来源：`SKILL.md`、`references/00-capability-charter.md` 及 `references/01`–`06`
> 适用对象：需要复用本规范发起分析的业务方、产品方与协作角色（R07 / R03 / R18）

---

## 一、一句话定位

商业分析分期在数据侧的落地，就是把一个业务问题切成 **7 个有顺序、有产物、有门禁的分析阶段**：每一个阶段必须交出**可复算的证据**才允许进入下一阶段；任何一阶段门禁 FAIL，分析就停在原地，不许「先出结论再补数据」。

R06 的交付标准不是「给个分析」，是「**给个别人能重新算一遍的分析**」。

---

## 二、数据视角的 7 个阶段总览

| 阶段 | 阶段名 | 核心要回答的问题 | 对应能力域 | 谁负责 |
|---|---|---|---|---|
| P1 | 问题受理与可分析性判定 | 这个问题能不能被数据回答？口径争议在哪？ | 需求侧 + 指标语义建模（S01） | R06（主责），业务方提供背景 |
| P2 | 指标口径定义（7 问） | 这个指标到底怎么算？ | 指标语义建模（S01） | R06（主责），指标消费方确认 |
| P3 | 数据体检与质量门禁 | 这份数据能信吗？洗完之后剩多少？ | 数据清洗质量（S02） | R06（主责），R18 提供数据链路 |
| P4 | 探索与诊断 | 用户在哪一步流失？哪群客户最值钱？ | 探索与产品分析（S03） | R06 |
| P5 | 根因与贡献分解 | 营收下降到底是谁造成的？ | 根因贡献度（S04） | R06 |
| P6 | 统计与因果验证 | A 组真的比 B 组好吗？要多少样本？ | 统计因果实验（S05） | R06（探索前哨），复杂模型交 R19 |
| P7 | 结论组装与可审计报告 | 这堆数据怎么讲成一个站得住的故事？ | 可视化报告（S08） | R06（主责），R07 做优先级与决策汇报 |

**分期的三条铁律：**

1. **门禁前置**：门禁不是事后补救，是入口拦截。脏数据不许进决策层。
2. **阶段可回退**：P4/P5 发现口径歧义，必须退回 P2 重定义，不许就地打补丁。
3. **不制造确定性**：任一阶段数据不足，返回 `blocked` 或标「待核实」，不许用话术补足证据。

## 三、逐阶段规范（输入 / 输出 / 门禁 / 谁负责）

### P1 问题受理与可分析性判定

**目标**：把业务语言翻译成可分析的问题，并判断是否需要启动完整分期。

| 项目 | 内容 |
|---|---|
| 输入 | 业务问题陈述、决策场景、已知事件日历（发版/大促/停机） |
| 输出 | 问题定义卡片（要回答的指标、对比基线、时间窗口、粒度）、是否立案的判定 |
| 门禁（FAIL） | ① 问题无法映射到任何已有或可定义的指标 → FAIL，退回需求方；② 属于**已知原因**（节假日、计划内停机、大版本发布）的波动 → 不启动标准 RCA，记录结案；③ 要求「证明因果」但无实验条件也无观测混杂清单 → 降级为相关性探索，写入声明 |
| 谁负责 | R06 主责；业务方负责确认决策场景 |

**立案阈值（触发完整分期的门槛，来自 F1 / 模块F、模块B）：**

- 营收类指标：非预期偏离 **> 3%**
- 活跃/互动类指标：无法用已知原因解释的周环比（WoW）偏离 **> 5%**
- 异常/错误率：任何具有统计显著性的非预期突增（**Z-score > 1.5**）
- 常规日周波动在 **±1.5 个标准差**以内的，归为正常波动，记录并结案

---

### P2 指标口径定义（7 问）——**硬门禁阶段**

**目标**：让指标可被计算引擎直接执行。**7 问未答完 = 口径未定，禁止上线/汇报。**

| 7 问 | 要求 | 缺失后果 |
|---|---|---|
| 1. 这是什么 | 一句白话，业务人员一听就懂 | 无法对齐消费方理解 |
| 2. 怎么算 | SQL / 公式，精确到字段与函数 | 不可复算 |
| 3. 粒度 | 聚合的底层单位，一行代表什么（如「每账户每月」） | 聚合口径漂移 |
| 4. 纳入/排除 | 默认看不出的过滤条件（测试单、内部账号、退款、未支付） | 两套报表数不一致 |
| 5. 边界 Case | 升级如何计费、跨币种换算、试用转付费、30 天退款追溯 | 边界数据归属不明 |
| 6. 谁用，用于什么决策 | 消费方决定口径严格程度与时效要求 | 精度过度或不足 |
| 7. 多少算好 | 业务目标值 / 告警阈值 | 结论无法判定好坏 |

**输入**：P1 的问题定义卡片、业务先验、现有报表口径。
**输出**：语义层模型（指标类型标注：Simple / Ratio / Cumulative / Derived）+ 指标树。

| 项目 | 内容 |
|---|---|
| 门禁（FAIL） | ① **7 问未答完即不可复算**，本阶段 FAIL，退回补充，不得进入 P3；② 语义层 `agg/type` 不在白名单 → FAIL；③ **防幻觉联动：`semantics link` 校验每个 `expr` 引用的列必须真实存在，`hallucinated_count > 0` 即 `ok=false`**；④ 对账超容差 → `fail` |
| 谁负责 | R06 主责；指标消费方负责确认第 6 问，数据 owner 确认第 3、4 问 |

**对账容差铁律（口径不一致时的判定线）：**

| 场景 | 容差 |
|---|---|
| 财务总账 / 审计级 | **0%** |
| 财务经营分析 / 大盘汇总 | **< 0.1%** |
| 营销指标 | **< 1%** |
| 产品互动指标 | **< 2%** |
| 机器学习特征/标签 | **< 0.5%** |

对账不一致的六大根因（按出现频率排查）：过滤条件不同 > JOIN 类型不同（膨胀或丢失）> 粒度不同 > 时区（UTC vs 本地）> 定义漂移 > 刷新滞后。

**标准口径防坑提示**：
- **GMV** = 支付订单金额之和，不含退款/取消，**绝不等同于净收入**。
- **ARPU / ARPPU** 的分母与分子**时间窗口必须严格一致**。
- **留存率**必须声明 **bounded**（恰在第 N 期活跃，标准定义）还是 **unbounded/rolling**（第 N 期起任一时刻活跃），两者不可混。
- **快照类（总量、库存、粉丝数）取期末最新值，禁止求和**；新增、流失、净增按时段求和。

### P3 数据体检与质量门禁——**硬门禁阶段**

**目标**：不信任未经审计的数据源。在产出任何分析结论前完成质量审计。

**输入**：P2 的语义层模型 + 待检数据文件。
**输出**：六维质量记分卡（HTML/Markdown）、清洗后数据集。

**六维质量审计（权重与关注点）：**

| 维度 | 权重 | 核心关注点 |
|---|---|---|
| Completeness 完整性 | 20% | 空值率；区分结构性空值与随机空值 |
| Accuracy 准确性 | 20% | 跨字段逻辑自洽（`shipped_date >= order_date`）、财务恒等式复算 |
| Consistency 一致性 | 20% | 引用完整性（孤儿率）、跨系统对账差异 |
| Timeliness 及时性 | 15% | 流水线 SLA、回填延迟、断崖式掉量 |
| Uniqueness 唯一性 | 15% | 主键/自然键重复率、整行重复、区分版本迭代与 Fan-out |
| Validity 有效性 | 10% | 取值范围（年龄 0–120、百分比 0–1）、枚举一致性、格式校验 |

**评分机制**：0 = 系统失败、5 = 半数通过、8 = 仅小问题可用、10 = 全数通过。
**严重度定级**：CRITICAL / HIGH / MEDIUM / LOW。

| 项目 | 内容 |
|---|---|
| 门禁（FAIL） | ① **必须产出 `rows_after` + 各维度分 + `overall_score` 才放行**，缺任一项即不放行；② **脏数据必须 FAIL**：核心业务字段（交易金额、用户ID）空值率 **>30% 熔断 FAIL**（>5% 警告）；整行重复率 **>1% 熔断 FAIL**（>0% 预警排查）；主键/时间戳字段缺失率必须 **0%**（CRITICAL 级阻断）；③ 关联共线性：`|r| >= 0.8` 提示共线性风险，`|r| >= 0.95` 判定近同一度量，须降维或剔除；④ 排雷检验：先排除 ETL 延迟、Schema 变更、埋点丢失等基建故障，再谈业务归因 |
| 谁负责 | R06 主责；R18 负责数据链路与 SLA（**R18 管数据怎么流，R06 管数字说明什么**） |

**验收标准**：`harness verify` 对干净数据 **PASS**、对脏数据 **FAIL**——门禁不是摆设。

**离群点定性判定**：IQR 1.5 倍法则 `[Q1 - 1.5*IQR, Q3 + 1.5*IQR]`，或正态分布用 `|z| > 3`。命中后必须分类为：真实业务信号（保留并单独分层）/ 系统错误（清洗）/ 系统哨兵值（如 9999-12-31）。

### P4 探索与诊断

**目标**：在认账的数据上寻找结构：趋势、漏斗、留存、分群、画像。

**输入**：P3 放行的清洗后数据集 + P2 的口径定义。
**输出**：趋势/漏斗/留存/RFM/SaaS 指标、分群画像与策略映射、时间序列季节性与异常点。

| 项目 | 内容 |
|---|---|
| 门禁（FAIL） | ① 留存未声明 **bounded / rolling** 口径 → FAIL；② 漏斗破坏四要素（严格顺序、绝对互斥、分母锚定、时间窗口）→ FAIL；③ 时序 **`min_points < 6`** → 拒绝进行趋势定论或预测；④ 聚类 **轮廓系数 < 0.3** 或组内人数过少（通常预期每组 ≥ 100 人或占总量的 5% 以上）→ 分群不可用；⑤ 多个群体映射到同一策略 → 分群无效 |
| 谁负责 | R06 主责；业务方确认分群策略的可执行性 |

**关键口径提醒**：
- 留存需明确「回访事件」——登录不等于活跃，须有核心价值操作才算。
- 季节性强度 `= 1 - var(残差)/var(总量)`，**≥ 0.6 视为强季节性**，强季节指标优先看同比（YoY）。
- 分群必须映射到差异化动作（Retain & Expand / Monetise / Activate / Win-Back），分群不是为了分群，是为了差异化行动。

### P5 根因与贡献分解

**目标**：先定位「谁在拉动整体变化」，再深究「为何发生」。

**输入**：P4 的异动发现 + 事件日历。
**输出**：贡献度分解表、帕累托下钻结果、被证伪假设清单。

**绝对贡献度公式**：`分段贡献度 = (分段期末值 − 分段基线值) / 整体总变化量`
- 正贡献度 = 拉动大盘往变动方向移动的核心力量；负贡献度 = 逆势拖累的力量。
- **当总体变化量接近 0（各分段涨跌互抵）时百分比分母失效，必须直接排查绝对变动量（Absolute Change）。**

**三层微观效应分解（Volume-Rate-Mix）**：回答是「人少了」还是「人不肯花钱了」——
体积效应 `Δ受众数量 × 历史人均值`、率效应 `历史受众数量 × Δ人均效率`、结构效应 `(当期分段占比 − 基线期分段占比) × 整体基线期总量`。

| 项目 | 内容 |
|---|---|
| 门禁（FAIL） | ① **Δ 贡献 = 各维拆解之和必须等于总变化**，不等即 FAIL；② 未交付**被证伪假设清单**即视为交付不合格；③ 未下钻到最小颗粒度验证「率」的方向即下结论 → 触发辛普森悖论风险，FAIL |
| 谁负责 | R06 主责 |

**帕累托下钻**：按绝对变动量降序，累计解释 **80%** 变化的前 N 个细分段即为调查标靶。

### P6 统计与因果验证——**纪律最重的阶段**

**目标**：把「看起来有差异」变成「站得住的差异」，并严格区分相关与因果。

**输入**：P4/P5 的候选假设与分组数据。
**输出**：检验结果（p 值 + 效应量 + 95% 置信区间）、功效分析、A/B 结论、因果四步结论。

**方法选型清单**：
- 两组均值对比 → Welch's t-test（默认不等方差）
- 分类频次/比例对比 → 卡方检验 / 两比例 z 检验
- 多组均值对比 → ANOVA
- 前置检查：检验前用直方图或正态性检验评估分布前提

| 项目 | 内容 |
|---|---|
| 门禁（FAIL） | ① **单独报告 p 值 → FAIL：p 值 ≠ 效应量**，强制联合报告 `p 值 + 效应量 + 95% 置信区间`；② 按方法同报对应效应量：**lift / Cohen's d / η² / R² / Cramér's V**；③ **相关不写成因果**：相关场景只允许用「数据提示」「一致于」「不能排除」；「我们确信/证明」仅能用于通过严格受控实验（A/B）验证的结论；④ **A/B 第一步必检 SRM**：若 **SRM p < 0.01，立即停止后续指标解读**，分流机制存在严重 Bug，结论无效；⑤ 功效不足（如 **功效 < 0.8**）却下「无差异」结论 → FAIL；⑥ 因果结论超范围声明 → FAIL |
| 谁负责 | R06（探索前哨）；EconML 级 IV/双机器学习与生信重后端交 R19；正式统计意见交 R03 |

**因果四步（DoWhy 口径）**：**混淆识别 → 后门分层调整 → 安慰剂反驳**（＋ 建模 DAG、识别后门/前门/IV、估计 PSM/IPW）。

> **因果边界纪律（必须逐字落到结论 note 里）**：
> 因果关系无法被绝对证明，只能被反驳。**四步结论只对「已调整的观测混杂」成立；未观测混杂（隐藏的共同原因，如天气、竞对调价）不可消除，必须如实声明。**

**A/B 决策矩阵**：
- 主指标显著为正 + 护栏未破 = 建议上线（Ship）
- 主指标不显著 = 不上线
- 护栏指标显著恶化 = **绝对不上线**（即使主指标极好）

**防混杂三板斧**：时间混杂（对比同周天）、同期群混杂（按获客时期对齐生命周期）、选择混杂（检查分母基数人群构成是否漂移）。

### P7 结论组装与可审计报告

**目标**：把证据链组装成决策物，每个数字可回溯。

**输入**：P2–P6 的全部产物。
**输出**：编辑级报告（HTML/Markdown，含内嵌 SVG）、高管摘要、质量记分卡、置信度声明。

**交付物必备区块**：Top Insights（3–5 条带量化指标）→ Business Impact（风险/成本/收入机会）→ Evidence（关键图表与下钻）→ Call to Action（谁、何时、做什么）。图表标题必须是**结论**，不是描述。

| 项目 | 内容 |
|---|---|
| 门禁（FAIL） | ① **对抗评审 `review` 默认拦截**：6 项确定性挑战（契约 / 证据边界 / 驱动分解 / 建议授权 / 禁用词 / 报告价值）任一不通过 → FAIL 并按 react/writer/controller 回路由；② **结论超数据边界，`review` 点名即 FAIL**；③ 报告数字无法回溯到 result → FAIL；④ 缺少置信度与局限声明 → FAIL |
| 谁负责 | R06 主责；R07 承接做优先级与决策汇报 |

## 四、统计分期纪律（P6 展开，逐条可执行）

| 纪律 | 具体要求 | 反面写法（禁止） |
|---|---|---|
| p 值 ≠ 效应量 | p 值必须与 lift / Cohen's d / η² / R² / Cramér's V 同报，并附 95% 置信区间 | 「差异显著，建议上线」 |
| 效应量按方法配对 | 均值差 → Cohen's d；多组 → η²；回归 → R²；分类关联 → Cramér's V；实验 → lift | 只给一个 p 值 |
| 相关不写成因果 | 用「数据提示」「一致于」「不能排除」 | 「X 导致 Y」 |
| 因果表述受限 | 「我们确信/证明」仅限严格受控实验（A/B）验证的结论 | 观测数据写成「证明」 |
| 因果四步边界 | 只对**已调整的观测混杂**成立；未观测混杂不可消除、必须如实声明 | 宣称已排除全部混杂 |
| 证据质量分层 | A/B 测试 > 自然实验 > 同期群 > 相关性 | 拿相关性当最高证据 |
| 功效不足 | 功效 < 0.8 时不得下「无差异」结论，只能报「样本量不足以支撑该结论」 | 「流失不变」 |

## 五、降级纪律：数据不足时怎么办

| 情况 | 行为（不制造确定性） |
|---|---|
| 数据不足 / 样本不够 / `min_points < 6` | 返回 **`blocked`** 或标注「**待核实**」，只给范围与局限，不给点估计式结论 |
| 重依赖缺失（scipy / spaCy / doWhy / omicverse） | 后端门禁探测，**如实降级不假装会算**；生信重后端缺失时返回 **`blocked`**，只给 scaffold，**不编数值** |
| 要求正式财务/统计意见 | 移交 **R03**，不越权出正式意见 |
| 因果要求但无实验、无混杂清单 | 降级为相关性探索，并在结论中声明混杂不可控 |
| 结论超数据边界 | `review` 点名即 FAIL，按 react/writer/controller 回路由 |
| 口径存在争议且 7 问未答完 | 停在 P2，**禁止进入后续阶段**，不出任何数值结论 |

**核心句式**：不确定时，写「数据不足以支撑该结论，建议补充 X 数据后复算」，而不是用「趋势上倾向于」掩盖证据缺口。

## 七、验收清单（怎么算把 R06 用对了）

- [ ] 语义模型引用不存在的列时，**`hallucinated_count > 0 且 ok = false`**（防幻觉不是摆设）
- [ ] `harness verify` 对干净数据 **PASS**、对脏数据 **FAIL**（门禁不是摆设）
- [ ] 质量审计产出 **`rows_after` + 维度分 + `overall_score`**，缺一不放行
- [ ] 指标口径 **7 问全答**，否则不可复算、不许汇报
- [ ] 贡献分解 **Δ 贡献 = 各维拆解之和 = 总变化**
- [ ] 统计结论**同时报 p 值与效应量**，不把相关写成因果
- [ ] 因果结论**如实声明未观测混杂不可消除**
- [ ] 数据不足时返回 **`blocked` 或标「待核实」**，不制造确定性
- [ ] 报告由 `core/report_renderer.py` 生成，**每个数字可回溯到 result**

## 八、主要边界与降级条件（本规范的自我声明）

1. 本规范只约束**分析侧**的分期与口径，不代替业务取舍（R07）、正式财务/统计意见（R03）、工程实现（R09）。
2. 所有阈值与术语均取自本角色 `SKILL.md` 与 `references/` 既有口径，未新增未经来源支持的数字。
3. 因果类结论仅在**已调整的观测混杂**范围内成立；未观测混杂不可消除，必须在结论中如实声明。
4. 依赖缺失（scipy / spaCy / doWhy / omicverse 等）一律如实降级，不假装会算；生信重后端缺失返回 `blocked`。
5. 数据不足不制造确定性：优先返回 `blocked` 或标注「待核实」。
