## 一、 生信管线核心：后端探测与诚实降级

生信分析对后端算力与重依赖库（如 `scanpy`, `anndata`, `omicverse`）有极高要求。本角色的生信专项必须遵循**“后端门禁 + 诚实降级”**范式。

### 1.1 探测机制与三态返回
- 必须使用 `try-import` 探测依赖，绝对不允许导致系统崩溃。
- 返回状态机：
  - `available`：全量库就绪，可执行真实管线。
  - `blocked`：缺失核心依赖，**必须拦截**，绝不允许伪造计算结果。
  - `degraded`：部分依赖就绪（如仅 CPU 可用，GPU 缺失），需降级执行或仅登记能力。
- **纪律红线**：当状态为 `blocked` 或 `degraded` 时，**严禁编造任何数值结论**（如差异倍数、Cluster 数量、Marker 列表）。此时的交付物仅限提供 Scaffold（包含分析阶段清单、所需前置技能、数据格式要求），并明确标注**「未执行」**。

### 1.2 模块能力暴露清单
当执行 `domain list` 时，登记并暴露以下由 `omicverse.pp` 提供的 11 个预处理方法：
`preprocess` / `scale` / `pca` / `umap` / `leiden` / `louvain` / `qc` / `filter_cells` / `filter_genes` / `select_hvf_pegasus` / `identify_robust_genes`。

## 二、 单细胞预处理与多组学联合分析最佳实践

### 2.1 QC 质控与预处理阈值（业务基线）
在 `_qc` 与 `_preprocess` 阶段，必须严格记录并应用以下基线阈值，所有下游结论必须能追溯至此参数表：

| 参数 | 默认阈值 | 业务含义与调整指导 |
|---|---|---|
| `min_counts` / `nUMIs` | 500 | 最低 UMI 计数（过滤低质量细胞/空滴） |
| `max_counts` | — | 最高 UMI 计数（用于双细胞/Doublet 剔除） |
| `min_genes` / `detected_genes` | 250 | 每细胞最少检测基因数（过滤死细胞） |
| `mito_perc` | 0.2 (20%) | 线粒体基因比例上限（识别凋亡细胞） |
| `percent_cells` | 0.05 | 稳健基因在细胞群体中的最小表达占比 |
| `n_HVGs` / `n_top` | 2000 | 选取的高表达变异基因（HVG）数量 |
| `n_pcs` | 50 | PCA 降维保留的主成分数量 |

### 2.2 典型单模态管线执行顺序
必须遵循严格的因果链执行顺序：
**QC 过滤** → **计算稳健基因** → **HVG 选择 (shiftlog/pearson)** → **Scale 归一化** → **PCA 降维** → **Neighbors 图构建** → **UMAP/tSNE 嵌入** → **Leiden/Louvain 聚类** → **细胞注释** → **差异表达/富集分析**。

*防坑指南：在调用可视化（如 `color='leiden'`）前，必须进行防御性检查，确保 `neighbors` 和 `leiden` 步骤已真实计算并挂载在 `adata.obs` 中。*

### 2.3 多组学联合分析（RNA + ATAC 等）
在面对多组学数据时，需根据数据结构选择正确的集成策略（参考 omicverse multi-omics 规范）：
- **配对数据（Paired）**：源自同一细胞的 RNA+ATAC。使用 `MOFA` 算法提取共享特征与模态特异性因子。输入必须是模态分离的 `AnnData` 列表，而非拼接对象。
- **非配对数据（Unpaired）**：来自不同实验的 RNA与ATAC。必须先使用 `GLUE` 学习共享嵌入进行细胞对齐，而后输入 `MOFA`。
- **批次效应处理**：对于多批次的单模态整合，使用 `SIMBA`（构建图并学习批次校正嵌入）；注意在 `gen_graph` 前必须执行 `preprocess`，且需处理 Batch 列的 NaN 异常。
- **细胞注释传递**：使用 `TOSICA` 从已注释参考集转移标签，领域判断需满足**真实数据 + 领域审查**双条件。

## 三、 数据集成：Schema 映射与降级逻辑

跨平台或跨系统数据整合（如将生信临床数据与实验元数据对齐，或自媒体多平台数据汇总）需遵循严密的 Schema 映射与对账容差规范。

### 3.1 字段降级映射逻辑
在将复杂或异构的 Source Schema 映射至 Target Schema 时，必须记录转换规则（Transformation Rules）：
1. **直接映射**：字段名相同或仅重命名，无业务逻辑变化。
2. **派生映射**：需记录明确的 SQL/Python 转换逻辑，例如类型转换（`CAST`）、缺失值填补（`COALESCE`）、或字典查找。
3. **平台差异降级**：当源数据缺失目标模型所需的细粒度字段时，必须制定降级策略（如：使用默认值、聚合至更高层级）。所有降级行为需在 `assets/schema_mapping_template.md` 中留痕。

### 3.2 HHI 集中度与数据口径对账
- 引入**赫芬达尔-赫希曼指数 (HHI)** 或类似集中度指标，校验单一平台或批次在整体数据集中的主导程度。若某一数据源集中度异常（如单批次数据独占 100%），必须触发预警，防止分析结论过拟合。
- **跨表对账容差**：在执行多源数据联合时（如汇总 `grand_total` 与各分项之和），必须建立自动校验公式：
  - $\sum (分项数据) = 总计数据$
  - 允许设定合理的容差区间（如应对并发时间戳或汇率换算的微小差异）。若超出容差，则标记为数据流异常，降级分析结论。

## 四、 结论交付叙事结构

无论是单细胞注释还是数据归因分析，交付给业务方的结论必须结构化、可追溯，并杜绝技术黑盒。

### 4.1 归因分析三段论（以粉丝/细胞群落扩增为例）
必须采用高度结构化的三行结论输出：
1. **主要贡献源（L1 级）**：
   - *模板*：`[主导因素/平台] 贡献 [X.X]%（+N），是[次要因素]的 N.N 倍，其余合计贡献 [X.X]%`。
2. **次级分类贡献（L2 级/体裁）**：
   - *模板*：`[核心体裁/亚群] 贡献 [X.X]%（N个，均值+N），[次高体裁] 次之 [X.X]%，其余合计 [X.X]%`。
3. **最佳标杆/Marker（L3 级）**：
   - *模板*：`🏆 [Top 样本/基因截断名称] 驱动 +N（X.X%） · [属性分布]，核心特征：[如高表达/互动率>5%]`。

### 4.2 树形图与视觉阈值控制
为了防止信息过载或数据穿模，在生成树形图或分析报告时：
- **动态阈值控制**：设定阈值 = `min(10%总盘子, 前10名最小贡献)`。低于阈值的长尾数据必须合并为“其他小贡献 N 项”汇总卡片。
- **结构一致性**：确保视觉层级（根节点 → 平台/批次 → 分类/体裁 → 具体实例）的总数对账无误。

### 4.3 产出纪律复核
- **测试通过标准**：在无相关库的本地环境中运行 `domain run`，系统必须返回 `blocked`。
- **结论回指**：报告中的每一项分类、过滤与降维结论，都必须明确标注源自哪一特定参数（如 `n_top=2000`, `N_PCS=50`），实现“计算过程全透明”。
- 「该拦的时候真的拦」，是本角色维持专业信誉的绝对底线。
