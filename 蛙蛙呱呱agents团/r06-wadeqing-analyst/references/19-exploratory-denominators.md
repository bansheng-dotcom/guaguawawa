# 19 · 探索与分母（explore）：只描述发生了什么

> R06 分析链第 4 段的领域依据。核心是**分母一致**与**分段预注册**：explore 只产出发现，不解释原因。

## 1. 为什么分母比数字重要

“转化率下降 20%”至少有四种可能：

- 分子下降（下单少了）；
- 分母上升（低意图流量多了）；
- 分段结构变化（低转化渠道占比上升）；
- 口径变化（去重/时间窗/退款处理改了）。

不写分母，就无法区分这四种。本仓要求每个发现都带：

| 字段 | 含义 |
|---|---|
| `denominator` | 分母的文字定义（如“期内同口径总量”） |
| `denominator_value` | 分母数值 |
| `denominator_ref` | 分母来自计划哪一项（只允许 `plan.rounds[...].query_spec.metrics[0]`） |
| `segment_definition` | 分段列、取值集合、来源（plan 的 group_by） |
| `evidence.rows_before/after` | 样本量，证明不是空算 |

## 2. 分段先定义，再看数

explore 不接受临时分组。可用的分段只有 `plan.dimensions` 里的列；想按新维度拆，必须回到 plan 改计划。
这样做的代价是灵活性下降，收益是“看完数再挑维度”这条造假路径被堵住。

## 3. 只描述，不解释

explore 的输出是 `findings.json`，允许出现：

- 趋势（按日序列）；
- 分段前后期变化与贡献排序；
- 漏斗各环节计数（若计划指定 stage 列）；
- 单位经济（收入/成本 → 毛利率）。

不允许出现：

- “因为”“导致”“说明”等因果词；
- 没有驱动拆解的原因判断；
- 任何“建议动作”。

原因判断在 explain 段，且必须带替代解释与反事实。

## 4. 分段加总校验

对每个维度，分段前后期合计必须等于整体（容差 0.5%）。这条校验专门拦截：

- 改分母制造增长（分段分母与整体分母不一致）；
- 漏掉某个分段（合计对不上）；
- 重复计数（合计超过整体）。

发现对不上时不是“四舍五入问题”，而是口径问题，必须回到 profile/plan 修正。

## 5. 本仓落点

| 能力 | 代码 | 门禁 |
|---|---|---|
| 前后期切分 | `_period(date, split)` | split 来自 plan，缺失即失败 |
| 发现结构 | `analysis_chain/explore.py` | 分母/分段/证据/样本量逐项非空 |
| 分母一致 | `check()` 的分段加总校验 | 容差 0.5%，超出即 CRITICAL |
| 分母为 0 | `denominator_value == 0 且 delta != 0` | CRITICAL（禁止补零） |
| 漏斗顺序 | `--stage-order` 或按计数排序 | 顺序写入 `segment_definition` |

## 6. 适用边界

- 适合：有明确前后期或对照组、指标可加总的数据；
- 不适合：比率型指标直接对分段求和（此时分母应是各分段的分子/分母，需在计划里单独定义）；
- 不适合：跨口径合并（如把退款前后两套订单表直接相加）；
- 单位经济只做“毛利率”级别，不做完整三表。

## 7. 误用反例

| 反例 | 为什么错 | 本仓如何拦 |
|---|---|---|
| 缺数据补 0 | 制造虚假下滑/增长 | 分母为 0 且有变化 → CRITICAL |
| 用不同时间窗的分段与整体对比 | 分母不一致 | 分段合计校验 + split 唯一 |
| 只报增长分段，不报下滑分段 | 选择性呈现 | 每个分段都产出发现，按 |delta| 排序 |
| 把“占比上升”说成“增长” | 混淆存量结构与增量 | `type` 区分 segment/overall/trend |
| 把相关当因果写进发现 | 越权解释 | explore 不输出结论，explain 才做拆解 |

## 8. 来源

- Tukey, J. W. (1977). *Exploratory Data Analysis*：探索阶段只描述模式。
- Few, S. *Show Me the Numbers*：图表与分母标注的最小规范。
