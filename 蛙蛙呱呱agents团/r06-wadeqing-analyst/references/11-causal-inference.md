## 一、 因果推断 (DoWhy 四步法实战口径)

**核心纪律**：因果结论必须同时具备**识别策略**与**分解证据**。我们只消除**观测到的**混杂因素，对未观测到的因素保持诚实。

### 1. Model 建模 (显式定义因果图)
- **登记三角色**：必须明确指定结局变量 `--outcome`（数值型）、处理变量 `--treatment`（必须且仅能为二值，否则直接拒绝）以及混淆变量 `--confounders`。
- **纪律**：必须显式给出混杂列（后门集合），系统**绝不自动猜测**混杂因素。不显式建模即不主张因果。
- **数据门槛**：有效样本行数 ≥ 8，否则直接触发 `error`，不强行制造确定性。

### 2. Identify 识别 (评估混杂不平衡度)
- 逐个混杂因素计算**处理臂间不平衡度**（即实验组与对照组在混杂因素上的差异）：
  - **数值型混杂**：计算标准化均值差 $d = \frac{mean_t - mean_c}{pooled\_sd}$。**绝对值 $|d| > 0.2$ 则标记为 `imbalanced`**。
  - **类别的混杂**：计算各类别在两组中的份额差 $max|share_t - share_c|$。**差值 $> 0.1$ 则标记为 `imbalanced`**。
- **接口防杠纪律**：阈值必须硬编码为数字字段（如 `"threshold": 0.2`），不得隐藏在散文描述中（会被评审系统视为“不可追溯小数”而产生 BLOCKER）。

### 3. Estimate 估计 (后门分层调整 ATE)
- **离散化策略**：数值混杂列按**四分位**离散化以防止层数爆炸；类别列保持原样。
- **效应计算**：层内效应 = 层内处理组均值 - 层内对照组均值。总体平均处理效应（ATE）按各层样本量加权求和得出。
- **正性假设（Positivity）处理**：只有单一处理臂（仅有处理或仅有对照）的层必须剔除，并在 `skipped_detail` 中如实上报“positivity 受限”。
- **归因分解铁律 (Contribution)**：必须在结果的**最顶层键**输出分解公式：`unadjusted (naive) = treatment_effect (调整后因果效应) + confounding_bias (混杂偏差)`。嵌套在深层结构中会被判定为“点名因果无分解证据”的 BLOCKER。

### 4. Refute 反驳 (安慰剂置换检验)
- **实现方式**：固定随机种子，置换（Permute）处理标签，重新计算因果效应。默认进行 200 次（最低不少于 20 次）。
- **指标定义**：`placebo_p` = |置换效应| $\ge$ |原调整效应| 的比例。
- **判读方向铁律 (严禁写反)**：
  - **$p < 0.05$** $\rightarrow$ `survives=true`：说明随机打乱标签后无法复现该效应，因果估计**经受住**了安慰剂反驳，结论可信。
  - **$p \ge 0.05$** $\rightarrow$ `survives=false`：说明该效应与纯随机噪声无异，因果估计**不可信**。
- **边界说明**：当前代码仅内置“安慰剂置换”反驳器。若需要“随机共同原因”或“数据子集”等反驳器，必须如实声明需求，绝不假装已执行。

## 二、 统计方法与 A/B 测试 (严格检验纪律)

### 1. 统计检验选择
- **比例类指标（二分类，如转化率）**：必须使用**两样本比例 Z 检验（Two-proportion z-test）**。
- **均值类指标（连续值，如人均时长）**：必须使用**Welch's t检验（Welch's t-test）**（不假设两组方差齐性）。

### 2. SRM (Sample Ratio Mismatch 样本失调) 检查铁律
- 在解读任何业务指标前，必须**首选对流量分配进行卡方检验（Chi-square test）**。
- **红线阈值**：如果流量分配的 $P < 0.01$，即判定为 SRM 发生。
- **行动要求**：一旦发生 SRM，**立即停机调查随机化分流管道**。此时所有的 A/B 测试业务结论（无论多么显著）均**不得外推为因果结论**，严禁给出 Ship (上线) 建议。

### 3. Guardrail (护栏指标) 阻断
- 主指标显著提升，但任何**护栏指标发生统计显著的负向劣化**（如：转化率提升，但页面崩溃率显著增加），必须给出 **No-ship (不建议上线)** 结论。

## 三、 自媒体运营数据分析与归一化

参考自媒体工作台的 `business-ops-analysis` 插件逻辑，建立确定性的业务诊断规则，杜绝大模型随意发挥。

### 1. 核心指标与归一化逻辑
- **粉丝净增**：必须明确平台口径。如小红书采用内容归因涨粉，B站采用“新增关注-取消关注”。
- **收入计算**：必须明确是支付金额（如小红书）还是实际成交金额（如B站），并剔除退款。
- **数据新鲜度**：各平台容忍 T-1 延迟。如果 `dateMax` 超过阈值，必须打上 `WARN` 或 `CRITICAL` 标签，并在结论中明确标出“数据过期，结论待验证”。

### 2. 诊断规则与报警阈值
- **头部依赖度 (集中度风险)**：
  - 计算平台贡献占比及 HHI（赫芬达尔—赫希曼指数）。
  - $HHI > 0.75$ 或单平台占比过高（如收入占比 > 95%），触发 `CRITICAL` 报警：“极端单一平台依赖”。
  - Top1 内容曝光占比 > 50%，触发 `WARN` 报警：“内容极端头部化，断更风险高”。
- **转化效率归因**：
  - 核心评价指标：“涨粉效率 = 涨粉数 / 千次曝光”。指导产能向高转化体裁倾斜。
- **四象限内容资产盘点**：
  - 基于“阅读（曝光）”与“互动率”双轴划分：
    1. **明星**（高曝光高互动）：拆解复用。
    2. **潜力**（低曝光高互动）：优化封面标题。
    3. **流量**（高曝光低互动）：保留引流。
    4. **待淘汰**（双低）：削减此类产能。

## 四、 图表选择与数据可视化原则

图表是分析结论的交付界面，必须遵循以下“信噪比最大化”与“极简主义”原则：

### 1. 结论化标题 (Data Storytelling)
- 图表标题**严禁**使用描述性短语（如“各平台粉丝分布”）。
- **必须使用结论性标题**（如：“B站和小红书合计贡献78%粉丝，平台集中度偏高”）。标题直接陈述你要表达的业务洞察。

### 2. 极简主义与墨水占比 (Signal-to-noise ratio)
- 消除一切不传递数据价值的“墨水”：
  - 去除图表外边框；隐藏顶部和右侧的坐标轴脊线（Spines）。
  - 弱化网格线（Alpha 设置为 0.2）或直接移除。
  - 尽可能使用**直接标签（Direct Labeling）**代替图例。
- 突出关键信息：使用更粗的线、对比度更强的颜色（如品牌蓝、警示红）来强调需要关注的核心数据点，淡化其他对比序列。

### 3. 图表选型映射 (Chart Selection)
- **趋势分析**：折线图（标注关键拐点，加入 MoM/YoY 标签）。
- **结构贡献**：瀑布图（明确展示从起点到终点的分步增减，替代难以看出正负贡献的堆叠柱状图）。
- **分布与集中度**：环形图 + HHI 仪表盘。
- **内容表现定位**：散点图（配合四象限十字线划分策略区域）。

## 五、 防幻觉与诚实边界铁律

1. **相关 ≠ 因果**：Pearson r 高只代表相关；线性回归斜率显著也不等于因果。
2. **术语文案纪律**：
   - 使用 `一致于`、`数据提示`、`不能排除` 表达**相关性**。
   - 只有经过严格 A/B 测试或因果推断（四步法）验证的结论，才能使用 `我们确信`、`导致`、`驱动`、`归因于` 等**因果性**词汇。
3. **证据层级降维**：从强到弱依次为：受控实验(A/B) $\rightarrow$ 自然实验(因果推断) $\rightarrow$ 无混杂前后对比 $\rightarrow$ 分段统计 $\rightarrow$ 时序相关。如实上报所处层级。
4. **超出能力范围**：二值处理变量之外（如连续处理、多值处理、工具变量 IV、双重机器学习 DML）归 R19 角色承载，本角色如实降级退让，绝不硬算。
