> 本模块是把「原始数据 → 语义资产 → 可审计结论」闭环的基石：强调跨平台的容差降级逻辑、生信分析的后置阈值及降维实践，以及表结构向业务语言的精准翻译。数据不仅仅是技术结构的堆叠，必须具备明确的业务解释力与科学严谨度。

## D1. 字段映射与 Schema 编织 (Schema Mapper & Degradation)

在异构数据源（如多平台自媒体数据、多组学测序数据）整合中，字段的映射需超越单纯的重命名，落到业务口径和计算降级上。

**映射六步法：**
1. **源 Schema 盘点**：列出每个源表列名、类型、Nullable 状态及原业务描述。
2. **目标 Schema 规划**：基于分析产出需求（而非系统原样）定义统一业务宽表。
3. **逐列归因映射**：
   - **直接映射 (Direct)**：一对一字段更名。
   - **派生映射 (Derived)**：必须记录到精确表达式，例如 `CAST(amount_cents AS FLOAT)/100.0`，`COALESCE(first_name, email)`。
4. **差异与降级处理**：
   - 若某平台缺少全局核心指标，需制定降级替补规则（如某平台无 `read_count` 时，是否可用 `view_count * 0.8` 估算，或标注为 NULL 并在前端渲染 `[N/A]`）。
   - **缺口闭环**：目标列无源必须设定 `DEFAULT` 或明确弃用，不允许「悄悄丢列」。
5. **集中度校验 (HHI) 植入**：针对聚合后的多源分布，强制引入赫芬达尔-赫希曼指数 (HHI) 校验逻辑。
   - HHI = $\sum (P_i)^2$，其中 $P_i$ 是单平台/类别占比。
   - **阈值警报**：HHI < 0.25 (分散健康) / 0.25-0.75 (中度集中/WARN) / > 0.75 (极端集中/CRITICAL)。要求结构性结论必须带有 HHI 评定。
6. **产出映射契约**：生成全量字典并接受相关团队审查。

## D2. 复杂管线计算规则与生信降维实践 (Advanced Analytics & Omic Thresholds)

对于如生信测序等需高度提纯数据的场景，后端挂载与降维算法需遵循严格的阈值及调用范式。

**特定最佳实践：**
- **强后端挂载要求**：批次效应处理及大规模 PCA 必须依赖可靠的底层实现（如 RAPIDS/GPU 加速）。调用批量校正前，务必保留 `adata.layers['raw']` 存档。
- **动态阈值设定**：
   - **差异表达分析 (DEG)**：禁用硬编码截断。使用自适应阈值，如 `foldchange_set(fc_threshold=-1, pval_threshold=0.05)` 让系统根据 log2FC 分布自选截断。
   - **质控 (QC) 过滤**：设定 `mito_perc < 0.2`、`nUMIs > 500`。
- **降维规范 (PCA / UMAP / MDE)**：
   - 在进行特征缩放 (`scale`) 后方可执行 PCA，统一降维深度推荐 `n_pcs=50`。
   - 防御性编程：在按簇或标签生成 UMAP 等可视化图表时，代码层面必须前置检查目标列（如 `leiden` 簇、`batch` 批次）是否已存在，若不存在则强制回退执行邻居图 `neighbors` 与聚类，严防 NaN 断崖式报错。
- **小样本退化处理 (LOESS Failure)**：针对高变基因 (HVG) 筛选，当局部批次样本数过少导致 `seurat_v3` LOESS 拟合失败时，必须配置 `try-except` 并降级至 `cell_ranger` 或标准 `seurat` 方法。

## D3. SQL 转业务逻辑 (SQL-to-Business-Logic)

SQL 代码审查不可仅停留在执行计划，必须实现「代码到业务」的人话翻译，确保与业务域口径无缝对接。

**结构化翻译步骤：**
1. **输入锚定**：抓取 SQL 及业务原始提问。
2. **剖析 `FROM/JOIN`**：用业务语言解释为何这么连表。明确 Join 类型（Inner vs Left），并标注该 Join 是否引发了预期外的粒度扇出（Fan-out）。
3. **翻译 `WHERE` 滤网**：逐行转义为业务规则，如 `status='A'` 翻译为“仅包含已发货且未退款的订单”。
4. **解析 `GROUP BY` 与聚合 (Grain)**：清晰指出最终输出每一行的代表实体（如“每客户每月的汇总购买”）。
5. **列含义与容差边界**：列出每个 `SELECT` 字段的业务定义。特别标注异常处理：
   - NULL 的默认传播与跳过机制。
   - 货币的汇率/单位换算；日期的时区截断。
6. **校验提问 (Validation)**：总结出 3–5 个尖锐的业务口径对账问题（如：是否故意排除了特定类型的交易？跨表对账容差是多少？），要求查询作者书面确认。

## D4. 语义元数据目录 (Data Catalog Entry)

无论是自媒体面板数据还是生信 Anndata，元数据的完整性决定了资产的复用寿命。

**元数据六要素结构：**
- **技术结构**：表/文件路径、行/列数、主外键/稀疏度。
- **业务上下文**：核心解决什么问题、归属哪个职能团队、关键度 (Critical/High/Medium/Low)、展示标签。
- **字段语义与探查**：一句话描述 + 业务规则（如 HHI 等级的计算公式） + 真实示例值。
- **数据质量契约**：
   - 完整度（非空率）、唯一度（去重验证）。
   - **新鲜度门禁 (Freshness)**：上游更新延时容忍度（如 24 小时）。过期数据在前端强制渲染“数据未同步”标签。
- **血缘追踪**：数据的确切来源（含外部系统爬取或系统导出动作），以及下游看板消费方。
- **合规与治理**：敏感信息级别（PII / 财务）、访问权限级（Public / Restricted）、持久化保留策略。
