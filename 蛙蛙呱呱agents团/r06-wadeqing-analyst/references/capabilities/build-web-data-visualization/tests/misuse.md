# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`，无命令门禁），因此本表是**人工评审清单**。
> 每条都由评审者判真假，判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| MU-01 | 每张图对应一个明确问题 | §5 第 1 条 |
| MU-02 | 图形类型与问题匹配 | §5 第 2 条 |
| MU-03 | 轴标签、单位、时间范围齐全 | §5 第 3 条 |
| MU-04 | 截断坐标轴已显式标注 | §5 第 4 条 |
| MU-05 | 颜色语义一致且不单靠颜色编码 | §5 第 5 条 |

## 二、软门（§6 自检，靠人抓）

| MU-05 | 我能说出这张图回答的**一个**问题 |
| MU-06 | 图形类型和问题匹配 |
| MU-07 | 轴有标签、有单位、有时间范围 |
| MU-08 | 如果截断了坐标轴，我标注了 |
| MU-09 | 颜色含义全篇一致 |
| MU-10 | 类别超过 8 个时我换了图形或合并 |
| MU-11 | 单文件 HTML 能离线打开 |

## 三、诚实说明

本卡**没有**可自动断言的门禁：它的输入是判断与决策，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——这比没有门禁更糟。

> **纪律**：knowledge 卡的价值在「有方法可依」，不在「有分数可刷」。
