# Web 数据可视化（build-web-data-visualization）

> **这是 knowledge 卡**：没有可执行门禁（`entry: null`），价值在「方法可依」而非「结果可判」。
> 它现在有 `SKILL.md` 载体，因此会出现在技能索引里、能被模型按需读取；
> 在此之前它是 `README.md`，**模型根本不知道它存在**。

## §1 何时用 / 何时不用

**该用**：做数据看板、报告配图、或判断一张图会不会被误读

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 数据口径与质量 | `data-validation` | 那是前置校验 |
| 长报告与版式 | `r08` 的 `html-report-presentation` | 那是文档 |
| 视觉设计规范 | `r10` 的 `design-system` | 那是设计令牌 |

**最小可开工输入**：一组已校验的数据

## §2 前置输入与最省追问

| 输入 | 是否必需 |
|---|---|
| 一组已校验的数据 | 必需或建议 |
| 这张图要回答的一个问题 | 必需或建议 |
| 读者是谁（决策者/同行） | 必需或建议 |

**追问纪律**：最多一轮，缺什么按 §8 降级处理，不连环追问。

## §3 执行流水线（Workflow）

### Step 1 · 一句话定问题
先写「这张图要回答什么」。写不出就说明还不该画图。

**判据**：一个问题只能配一张图

### Step 2 · 选图形类型
按问题选类型：**比较→条形；趋势→折线；分布→直方/箱线；关系→散点；构成→堆叠或饼（≤5 类）**。

**判据**：类型与问题不匹配是最常见的错误

### Step 3 · 补坐标轴与单位
每张图必须有轴标签、单位、时间范围。截断坐标轴必须显式标注。

**判据**：截断坐标轴不标注＝误导

### Step 4 · 颜色承载语义
同一颜色全篇同义；类别 ≤8 且不靠颜色单一编码。

**判据**：色盲不可辨＝不可读

### Step 5 · 出单文件 HTML
样式内联、无外链、可离线打开。

**判据**：多文件工程无法发给别人看


## §4 交付物清单

| # | 交付物 | 载体 |
|---|---|---|
| 1 | 图要回答的问题（一句话） | `.md` |
| 2 | 图形类型与选择理由 | `.md` |
| 3 | 轴标签/单位/时间范围核对表 | `.md` |
| 4 | 单文件 HTML | `.html` |

## §5 质量门（一票否决）

1. 每张图对应一个明确问题；
2. 图形类型与问题匹配；
3. 轴标签、单位、时间范围齐全；
4. 截断坐标轴已显式标注；
5. 颜色语义一致且不单靠颜色编码；

> 本卡无自动门禁。**任一项不过即不得交付**，且必须在交付物里写明「逐项人工核对」。
> 可用 `python agent.py quality audit` 做间接校验（若该命令存在）。

## §6 交付前自检清单

- [ ] 我能说出这张图回答的**一个**问题
- [ ] 图形类型和问题匹配
- [ ] 轴有标签、有单位、有时间范围
- [ ] 如果截断了坐标轴，我标注了
- [ ] 颜色含义全篇一致
- [ ] 类别超过 8 个时我换了图形或合并
- [ ] 单文件 HTML 能离线打开

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 先画图后想问题 | 先写一句话问题再选图形 |
| EX-02 | 饼图切 12 份 | ≤5 类，多了改条形 |
| EX-03 | 截断 Y 轴不标注 | 必须显式标注截断 |
| EX-04 | 缺单位（元？万元？） | 轴上写清单位与口径 |
| EX-05 | 颜色一词多义 | 一色一义，全篇统一 |
| EX-06 | 只靠颜色区分类别 | 加形状/标签/纹理 |
| EX-07 | 双 Y 轴乱用 | 双轴只在量纲不同且相关时用，并标注 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 数据未校验 | 先走 `data-validation`，不带病出图 |
| 数据点太多 | 聚合或抽样，并说明方法 |
| 无法出交互图 | 出静态图 + 关键数字标注 |
| 品牌色与语义色冲突 | 语义优先，标注与品牌的偏离 |
| 读者是决策者 | 一图一结论，副标题写结论句 |

**明确不做**：不洗数据、不搭 BI 平台、不美化空信息图。
