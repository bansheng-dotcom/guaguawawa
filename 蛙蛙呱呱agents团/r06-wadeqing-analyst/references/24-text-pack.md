# 24 · 文字包（write）：unit packet、行长与对抗评审

> R06 报告链第 9 段的领域依据。文字只负责“把已验证的断言说清楚”，不负责发明结论。

## 1. unit packet 是什么

一个单元 = 一条断言 + 它的全部写作材料：

| 字段 | 作用 |
|---|---|
| `claim_id` | 指回 material pack，数字可追 |
| `title` | 带数字与判断词，先给结论 |
| `paragraphs` | 对照、驱动、机理、证伪、落点、边界、复算 |
| `bullets` | 证据、分母、来源、停止线 |
| `table` | 逐项数字，供读者复核 |
| `falsifier` | 若……则本节作废（可观测阈值） |
| `mechanism` | 一种解释 + 判别方法 |
| `implication` | 所以先做什么、不要做什么 |
| `line_fit` | 行长检查结果 |
| `numbers_used` | 本节用到的数字（用于可追门禁） |

## 2. 每节的最低骨架

1. 对照：跟谁比、差多少（带数字）；
2. 驱动：贡献与量价（没有就说明不能拆）；
3. 机理：一种解释 + 判别方法；
4. 证伪：若……则作废；
5. 落点：所以先……不要……；
6. 边界与复算。

缺任何一项，报告质检 Q8/Q9 会判失败；这也是本仓自检与 R01 质检对齐的地方。

## 3. 行长控制

中文报告单句建议 ≤90 字；超过就拆句或改成列表。
行长不是排版偏好：一行太长会让读者丢主语，也会让“结论—证据”对应关系模糊。

## 4. 对抗评审（独立于生成）

评审不重新写稿，只做判定：

- 每个数字能否追到 material pack；
- 是否有越权承诺（“必然”“保证”“全量上线”）；
- 是否有无据因果（“导致”“证明”“驱动了”）；
- 是否每节有证伪、机理、落点；
- 行长是否合格、是否有证据表。

不通过就返回 route（analysis/text），不是“建议修改”。

## 5. 本仓落点

| 能力 | 代码 | 门禁 |
|---|---|---|
| 文字包 | `analysis_chain/text_pack.py` | 单元字段齐全、行长合格 |
| 对抗评审 | 同上 `_review` | 数字可追、无越权、无无据因果 |
| 报告质检 | `core.report.report_quality.audit` | Q1–Q10（research/baseline 自动判档） |
| 可追 | `deliver.audit_trace` + `check_claim_trace.py` | 正文数字 100% 可追 |

## 6. 误用反例

| 反例 | 为什么错 | 本仓如何拦 |
|---|---|---|
| “效果显著，建议全量上线” | 越权承诺 | OVERREACH 词表 → 评审失败 |
| “因为折扣导致利润下滑” | 无实验却用因果词 | CAUSAL 词表 → 评审失败 |
| 只有结论没有表 | 读者无法复核 | 每节必须有证据表 |
| 一节写五条互不相关的结论 | 一节只回答一个问题 | unit 与 claim 一一对应 |
| 句子超过 120 字 | 主语丢失 | line_fit → 失败 |
