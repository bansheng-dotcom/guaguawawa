# R17 蛙智网 · 自动化 · 方法包（Method Pack v1）

## 1. 决策问题

- 典型决策：这个流程要不要自动化、先做哪段。
- 决策者：运营负责人；成功标准：省时且异常可控、维护成本低。
- 非目标：不做无异常处理的自动化、不做一次性脚本。

## 2. 问题树（MECE）

| 分支 | 要回答 | 假设 | 数据 | 方法 |
|---|---|---|---|---|
| 频率 | 多久跑一次、量多大 | 频率/量可测 | 流程日志 | 流程挖掘 |
| 规则 | 规则是否稳定可编码 | 规则明确 | SOP/样本 | 规则抽取 |
| 异常 | 异常怎么处理 | 异常有兜底 | 异常样本 | 异常率评估 |
| 维护 | 谁来维护、成本多少 | 维护成本 < 收益 | 工时估算 | ROI |

**critical branch**：`异常`——资源优先给它。

## 3. 假设与证伪

- H1：自动化后人工工时下降 ≥50%。
- H2：异常率 ≤5%，且有人工兜底。
- 竞争解释（至少 2 个）：慢是因为人工，还是因为规则本身复杂？；自动化后省的时间，是否被维护吃掉？
- 每条假设必须有**杀死标准**：指标 + 阈值 + 观察窗口。

## 4. 证据分级

| 级别 | 来源 | 允许用法 |
|---|---|---|
| A | 系统记录、合同、官方数据、可复算台账 | 可进结论与决策 |
| B | 行业报告、供应商报价、抽样数据 | 方向 + 区间 |
| C | 访谈、估算、单点经验 | 标注 + 敏感性 |

**规则**：每个结论挂来源；同名不同口径单列；缺什么、影响什么、怎么补，必须写清；C 级超过 3 条时结论降级为「条件成立」。

## 5. 方法与陷阱

- 流程挖掘：从日志找真实路径与瓶颈。
- ROI：节省工时 × 人力成本 − 维护成本。
- 异常设计：重试/死信/人工接管三件套。
**陷阱清单**：
- 为上系统而上
- 无异常处理
- 忽略维护
- 一次性脚本冒充产品
自动化结论必须给「异常兜底 + 维护人」，否则不上线。

## 6. 输出契约

```
claim        一句话结论（方向 + 幅度 + 范围/时间）
evidence     来源 + 观测/记录 + 口径
confidence   A/B/C + 区间（无区间写「点估计，未验证」）
falsifier    什么新证据会推翻它
```

缺任一项 → 不得进首页；建议缺负责人/阈值 → 行动性不通过。
