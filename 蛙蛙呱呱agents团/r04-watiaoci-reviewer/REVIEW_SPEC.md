# R04 独立评审官规范基准 (REVIEW_SPEC.md v1.0)

> 本规范对标 `awesome-design-md` 与 IEEE 1028 软件工程审查标准，统一定义 R04 挑刺评审全生命周期的硬性门禁判据、三级证据链要求与确定性打分扣分反模式。杜绝口径漂移与主观模糊判定。

---

## 1. 三级证据链标准 (Evidence Chain Levels)

评审提出的每一项缺陷或放行决议，必须绑定明确的证据链等级：

| 等级 | 判定标准 | 准入要求 |
| :--- | :--- | :--- |
| **L1 (物理存在性)** | 目标文件在磁盘物理存在，路径无非法字符，大小 > 0 字节 | 文件存在且非空 |
| **L2 (实质内容性)** | 杜绝 Stub、杜绝空函数、杜绝 `pass` / `raise NotImplementedError` 占位 | 核心逻辑行数 (SLOC) > 3 且无骨架假装 |
| **L3 (通路完整性)** | 与外界有输入输出流动，非孤岛文件；被测试用例覆盖或有明确调用者 | AST 依赖或入口可寻 |

## 2. 7 维门禁扣分反模式与容差基准

| 维度 ID | 扣分触发反模式 | 严重级别 | 扣分分值 |
| :--- | :--- | :--- | :--- |
| **P-THEATRE** | 命令含 `|| true`、`exit 0`、空 assert，伪装通过 | CRITICAL | -40 分 |
| **P-CIRCULAR** | 模块出现循环依赖或 DAG 执行环 | HIGH | -25 分 |
| **P-SLOP** | 评语包含假大空废话（如“整体良好、建议进一步加强”）且无确切行号 | MEDIUM | -10 分 |
| **P-UNSOURCED** | 事实性断言或度量指标缺乏上下文来源或溯源行 | HIGH | -20 分 |
| **P-UNBOUND** | 判据缺乏明确验收界限或布尔状态 (PASS/FAIL) | MEDIUM | -15 分 |
| **P-REGRESS** | 历史已收敛缺陷重新复发 (Regression) | CRITICAL | -35 分 |
| **P-STUB** | 生产代码中残留占位打桩标记 (`TODO`、`FIXME`、`NotImplemented`) | HIGH | -20 分 |

---

## 3. 终审放行基准 (Verdict Baseline)

- **PASS (绝对通过)**：综合得分 >= 85 分，且 0 处 CRITICAL 违规，0 处未溯源事实断言；
- **CONDITIONAL (有条件放行)**：综合得分 70 - 84 分，无 CRITICAL 违规，存在有限 MEDIUM 改进项；
- **REJECT (绝对驳回)**：综合得分 < 70 分，或存在任意 1 项 CRITICAL 门禁戏法/红线触碰。
