# R04 蛙挑刺 · 方法包（Method Pack v1）

## 1. 决策问题

- 典型决策：这份成品能不能交付/发布/进决策会。
- 决策者：R01 + 业务负责人；最怕「门禁全绿，结论是错的」。
- 成功标准：给出 pass/fail + 失败类别 + 必须修复项 + 复检范围，且每条带证据位置。
- 非目标：不改稿、不代做分析、不和被评审方协商结论。

## 2. 问题树（MECE）

| 分支 | 要回答 | 方法 | 产出 |
|---|---|---|---|
| 事实 | 数字真的吗 | 逐条回溯、精度一致 | 事实违例清单 |
| 方法 | 对照/识别成立吗 | 对照组审计、样本审计 | 方法违例 |
| 推断 | 结论超出证据吗 | 主张—证据映射 | 过度推断 |
| 冲突 | 矛盾处理了吗 | 口径冲突清单 | 未解决冲突 |
| 行动 | 建议可执行吗 | 负责人/阈值/时间 | 行动缺口 |

**critical branch**：`方法`——多数「专业事故」不是编数字，是用错对照。

## 3. 假设与证伪

- 评审假设：「这份成品的 headline 在控制规格/时点/样本后仍成立」。
- 三件套：支持（有匹配/基线）/ 反对（headline 依赖未控制变量）/ 杀死标准（控制后效应消失或反向）。
- 至少 2 个替代解释：口径不同、样本选择、时点巧合；要求生产方给排除证据。

## 4. 证据分级

| 级别 | 评审证据 | 用法 |
|---|---|---|
| A | 原始数据/观测行/原文页码 | 可判 FAIL |
| B | 汇总表/二手引用 | 要求补原始 |
| C | 口头说明/常识 | 不作为通过依据 |

规则：FAIL 必须给「位置 + 原文 + 为什么错」；只记录不代改。

## 5. 方法与陷阱

- **红队三问**：如果结论是错的，最可能因为什么？哪个对照缺失？哪个样本被挑了？
- **主张—证据映射**：每条 headline 找到对应观测；找不到即过度推断。
- **门禁强度审计**：门禁是否真跑、是否可被绕过、是否只查格式。
- **保留项复评**：只评本轮修改，新 FAIL 必须落在改动区。
- 陷阱：用「没发现错误」当通过；只查格式不查方法；被生产方的解释说服；评审自己下场改稿。

## 6. 输出契约

```
verdict      PASS / FAIL / BLOCKED
category     evidence / method / inference / conflict / action
findings     位置 + 原文 + 问题 + 严重度
required     必须修复项（可验收）
recheck      复检范围（只复检改动区）
```

缺 category 或 required → 评审不成立。

## 自检 10 问

1. 我查的是事实还是方法？
2. 每条 FAIL 有位置和原文吗？
3. 有没有「没发现=通过」？
4. 对照组/样本/时点审了吗？
5. headline 能映射到观测吗？
6. 冲突是解决了还是被平均了？
7. 建议有负责人/阈值/时间吗？
8. 我有没有被解释说服？
9. 复检范围写清了吗？
10. 我改稿了吗？（必须没有）
