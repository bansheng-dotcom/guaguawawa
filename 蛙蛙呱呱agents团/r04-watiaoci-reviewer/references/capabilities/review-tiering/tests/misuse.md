# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表是**人工评审清单**，逐条判真假。
> 判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 | 出处 |
|---|---|---|
| MU-01 | 每个评审项都标 A 或 B，附一句话判据 | §5 第 1 条 |
| MU-02 | A 项与提交交错（一致率 ≥80%），B 项中期勾选数为 0 | §5 第 2 条 |
| MU-03 | 无证据声称数为 0（每条完成声称有同轮证据） | §5 第 3 条 |
| MU-04 | 抽样反查 3/3 成功（能指出具体位置） | §5 第 4 条 |
| MU-05 | 结论是 pass / conditional / fail 三选一 | §5 第 5 条 |

## 二、软门（§6 自检，靠人抓）

| # | 常见错法 |
|---|---|
| MU-05 | 把「全部测试通过」当逐项项 |
| MU-06 | 把「改了哪些文件」留到最后看 |
| MU-07 | 一口气勾完所有项 |
| MU-08 | 只听说「已完成」就记通过 |
| MU-09 | 证据针对旧版本 |
| MU-10 | 结论写「总体还行」 |
| MU-11 | 因对方资深而放宽证据 |

## 三、诚实说明

本卡没有可自动断言的门禁：输入是判断与产物观感，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——比没有门禁更糟。

可做的替代验证：
1. **双评**：两人独立按 §5 打分，一致率 ≥80%；
2. **抽样反查**：随机抽 3 项要求指出具体位置；
3. **对照抽检**：与 `references/tiering.md` 里的 GOOD 样例并列看。

> **纪律**：规范的价值在「别人拿它能判出同样的结论」。
