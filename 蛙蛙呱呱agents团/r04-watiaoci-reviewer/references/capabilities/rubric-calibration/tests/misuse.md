# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表是**人工评审清单**，逐条判真假。
> 判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 | 出处 |
|---|---|---|
| MU-01 | 用途明确（排序/分档/一票否决三选一） | §5 第 1 条 |
| MU-02 | 维度 3–6 个，权重合计 =100 | §5 第 2 条 |
| MU-03 | 每个维度每个档位都有锚定样例（具体到可指认） | §5 第 3 条 |
| MU-04 | 总分口径写死（缺失值处理 + 是否可跨维补偿） | §5 第 4 条 |
| MU-05 | 做过双评（≥10 样本），一致率 ≥80% 或 kappa ≥0.6 | §5 第 5 条 |
| MU-06 | 写明校准周期与触发条件 | §5 第 6 条 |

## 二、软门（§6 自检，靠人抓）

| # | 常见错法 |
|---|---|
| MU-06 | 10 个维度 |
| MU-07 | 档位只写「良好/一般」 |
| MU-08 | 权重加不到 100 |
| MU-09 | 不说缺失值怎么办 |
| MU-10 | 允许高分拉平底线项 |
| MU-11 | 一致率 55% 还上线 |
| MU-12 | 一致率低就去调分数 |

## 三、诚实说明

本卡没有可自动断言的门禁：输入是判断与产物观感，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——比没有门禁更糟。

可做的替代验证：
1. **双评**：两人独立按 §5 打分，一致率 ≥80%；
2. **抽样反查**：随机抽 3 项要求指出具体位置；
3. **对照抽检**：与 `references/rubric-design.md` 里的 GOOD 样例并列看。

> **纪律**：规范的价值在「别人拿它能判出同样的结论」。
