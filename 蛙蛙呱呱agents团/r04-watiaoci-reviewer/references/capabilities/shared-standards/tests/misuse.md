# 负向测试集（misuse cases）

> **本卡是基准卡**，本表是人工核对清单 + 一道机器门禁。版本：v2.0.0

## 一、机器门禁（唯一可自动断言的）

```bash
python scripts/check_threshold_consistency.py            # 退出码 0 才合格
python scripts/check_threshold_consistency.py --self-test # 先证明检查器本身没坏
```

`--self-test` 是必需的：**一个永远返回 0 的检查器比没有检查器更糟**——
它会让「不一致」看起来像「一致」。本脚本自带 4 个注入冲突用例，必须全部被抓到。

## 二、人工核对（机器查不到的）

| # | 错法 | 为什么机器查不到 |
|---|---|---|
| MU-01 | 卡里写「地板 15%」而不引用 | 数字对了，但没有单一出处，改了不会跟 |
| MU-02 | 领域用了不同值但没登记 | 机器只查已知概念 |
| MU-03 | 先改卡再改基准 | 顺序问题，结果态可能自洽但过程混乱 |
| MU-04 | 概念表里没有的新概念被多处定义 | 未登记进 CANON |
| MU-05 | 一致率写「大家意见差不多」 | 无数字可查 |
| MU-06 | 「待校准」却已进质量门 | 状态与用法不符 |

## 三、诚实说明

本卡的机器门禁只覆盖 **6 个概念**（毛利率地板、一致率、kappa、抽样数、样本数、图表红线）。
超出这 6 个的共享数值，机器看不见——**发现新共享概念时要主动登记进 `CANON`**，
否则检查器会静默放过。

> **纪律**：单一出处的价值不在「数值统一」，在「**改一处，全场跟着变**」。
