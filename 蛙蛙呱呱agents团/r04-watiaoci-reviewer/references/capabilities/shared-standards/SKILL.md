# 全局基准与术语表（Shared Standards）

> 一句话定位：**技能库长到 67 张时，最大的风险不是缺卡，是同一句话在两个地方意思不同。**
>
> 实测：`地板线 15%` 出现在 3 张卡、`一致率 80%` 出现在 4 张卡、`停止条件` 出现在 3 张卡、
> `双评` 出现在 5 张卡——**每处都自己写了一遍**。改一处，其余不会跟着变。
>
> 本卡是这些数值的**唯一出处**。其他卡只能引用，不能重定义。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这两张卡的地板线为什么不一样」
- 「一致率到底 80% 还是 0.6 kappa」
- 「我要新增一张卡，要引用哪些数值」
- 「改了这个阈值，哪些卡要跟着改」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 视觉判据（层级/对比/留白） | `r10` 的 `visual-hierarchy` | 那是领域判据 |
| 图表诚实红线 | `r06` 的 `chart-honesty` | 那是领域判据 |
| 阈值怎么定（方法论） | `r04` 的 `quantified-taste` | 那讲**怎么定**，本卡给**定好的值** |
| 评分表怎么写 | `r04` 的 `rubric-calibration` | 那是表的写法 |

**最小可开工输入**：**一个待确认的数值或概念**。

## §3 执行流水线（Workflow）

### Step 1 · 查本卡 §4 的概念表（唯一出处）
所有共享数值在 §4。**表里没有的概念，说明它还不是共享概念**，可以留在领域卡内。

### Step 2 · 判断是「引用」还是「定义」
| 情形 | 做法 |
|---|---|
| 卡里需要这个数值 | 写「见 `shared-standards` §4」，**不复制数字** |
| 发现卡里已经写了另一组数字 | 以本卡为准，改卡 |
| 领域确实需要不同的值 | 必须在卡里写明「偏离理由」，并在此登记 |

### Step 3 · 改数值的顺序（先改基准，再改引用）
```
1. 改本卡 §4
2. 跑 python scripts/check_threshold_consistency.py   ← 会列出所有不一致处
3. 按输出逐张改卡
4. 再跑一次，直到 0 不一致
```

**铁律**：**不许先改卡再改基准**——那样中间态是混乱的，且很可能改漏。

### Step 4 · 新增卡时的引用清单
新卡只要用到下表任一概念，就必须引用本卡：

| 会用到 | 常见场景 |
|---|---|
| 三级阈值 | 任何写「地板/目标/优秀」的卡 |
| 一致率 | 任何写「双评/校准/多人判」的卡 |
| 抽样数量 | 任何写「抽检/反查」的卡 |
| 停止条件 | 任何写「什么时候停/放弃」的卡 |
| 强度三级 | 任何写「结论/措辞」的卡 |

### Step 5 · 定期跑一致性检查（已进 CI）
```bash
python scripts/check_threshold_consistency.py          # 人读报告
python scripts/check_threshold_consistency.py --json
```
退出码 0 = 全部一致；1 = 有不一致。

## §4 概念表（唯一出处，改这里）

### 4.1 三级阈值（地板 / 目标 / 优秀）

| 档 | 含义 | 依据 | 达不到怎么办 |
|---|---|---|---|
| **地板** | 不可低于，低于即拒收 | 约卡掉 10% 历史产物（≤P90） | 必须改 |
| **目标** | 应该达到 | 约 70% 可达（≤P70） | 记录并说明 |
| **优秀** | 标杆 | 约前 10%（≤P10） | 不要求所有人 |

**具体数值（跨卡统一）**

| 用途 | 地板 | 目标 | 优秀 | 使用它的卡 |
|---|---|---|---|---|
| **毛利率**（含平台费与退货损耗后） | **15%** | 25% | 35% | `pricing-strategy` / `renewal-expansion` |
| 形容词密度（每千字） | 6 | 3 | 1 | `tone-axes` |
| 相邻层级字号比 | 1.25× | 1.5× | 2.0× | `visual-hierarchy` |
| 单函数有效行数 | 80 | 40 | 20 | （代码类，暂未成卡） |

**底线类指标（只有一档，归零）**：涉及诚实性的量不分级，一律 **0**

| 指标 | 值 | 使用它的卡 |
|---|---|---|
| 图表欺骗性操作数 | **0** | `chart-honesty` |
| 无证据声称数 | **0** | `review-tiering` |
| 禁用词出现数 | **0** | `tone-axes` |

### 4.2 双评与一致率

| 项 | 值 | 说明 |
|---|---|---|
| 最少样本数 | **10** 个 | 少于 10 个算不出稳定一致率 |
| 一致率门槛 | **≥80%** | 低于则先修判据，不怪评审人 |
| kappa 门槛（≥3 人时） | **≥0.6** | 排除偶然一致 |
| 双评人数 | **2** 人 | 各自独立，不交流 |
| 分歧处置 | 分差 **≥2 档** → 重写该段/该判据 | 不是调分数 |
| 自评 | **禁止** | 产出者不得参与对自己的评判 |

### 4.3 抽样数量

| 场景 | 抽样数 | 判据 |
|---|---|---|
| 评审反查（能否指到具体位置） | **3 项** | 3/3 才过 |
| 引用链接抽查 | **3–5 条** | 全部可打开 |
| 产物质量抽检 | **5 个** | 与 GOOD 样例并列比 |

### 4.4 停止条件（三类，通用骨架）

| 类 | 触发 | 动作 |
|---|---|---|
| **达标停** | 达到预设的样本量/时间窗/次数 | 立即停止，不追加 |
| **恶化停** | 护栏/底线指标恶化超阈值 | 立即停止，不权衡 |
| **时间停** | 到了约定日期 | 到期即判，不延期 |

**禁止**：中途看结果后决定「再跑几天」——那会让所有概率保证失效。

### 4.5 结论强度三级

| 级 | 允许的说法 | 支撑要求 |
|---|---|---|
| **观察到** | 「是」「为」「从 A 到 B」 | 数据直接显示 |
| **推断** | 「主要来自」「可能源于」「与…一致」 | 拆解 + 排除 |
| **因果** | 「导致」「使」「带来」 | 实验或准实验 |

**词表纪律**：跳级使用词 = 结论不成立，不管数字多好看。

## §5 质量门（一票否决）

1. 本卡 §4 的概念表是所有卡的**唯一数值出处**；
2. 任何卡引用上述概念时**不复制数字**，只写「见 `shared-standards` §4」；
3. 领域需要偏离时，卡内写明**偏离理由**，并在本卡 §6 登记；
4. `check_threshold_consistency.py` **退出码 0**（无不一致）；
5. 改数值时**先改本卡再改引用**。

> 验收命令：`python scripts/check_threshold_consistency.py`（这是本卡唯一可自动化的一道门）。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 在卡里直接写「地板 15%」 | 写「见 shared-standards §4.1」 |
| EX-02 | 两张卡对同一概念给不同值 | 以本卡为准，改卡 |
| EX-03 | 先改卡再改基准 | 先改基准，再跑检查逐张改 |
| EX-04 | 领域需要不同值但不登记 | 卡内写理由 + 本卡 §6 登记 |
| EX-05 | 一致率写「差不多都同意」 | 给 80% 门槛与样本数 |
| EX-06 | 抽检只抽 1 个 | 按 §4.3 给数量 |
| EX-07 | 中途看结果决定延长 | 按 §4.4 预设停止条件 |
| EX-08 | 用「导致」但只有数据 | 降级为「推断」或补实验 |
| EX-09 | 产出者自评 | 换人双评 |
| EX-10 | 改完不跑一致性检查 | 必须跑，退出码 0 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 检查脚本跑不了 | 人工按 §4 逐项比对（表只有 5 个概念，可手查） |
| 概念表里没有的新概念 | 先判断它是否跨 ≥2 张卡；是则登记进本卡，否则留在领域卡 |
| 领域确实需要不同值 | 卡内写偏离理由 + 本卡 §6 登记 |
| 历史卡已写了不同值 | 以本卡为准统一；若历史值更合理，改本卡（并说明） |
| 数值有待实证 | 标「待校准」，但仍需全站统一 |

**明确不做**
- 不做领域判据、不做具体打分、不替代 `quantified-taste`（它讲方法论，本卡给结论值）。
