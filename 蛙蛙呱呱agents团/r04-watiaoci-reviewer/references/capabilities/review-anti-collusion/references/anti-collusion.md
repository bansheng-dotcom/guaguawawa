# 反合谋五条与结论契约（anti-collusion）

> 被 §3 与 §5 按需引用。**本文件定义"什么算一次真正的评审"。**
> 版本：v2.0.0（项目自建，v1）

---

## 一、五条红线（对应 `review.py` 的五项检查）

| # | 检查名 | 红线 | 触发后路由 |
|---|---|---|---|
| 1 | `self_review_gate` | `reviewer == producer`：自己评自己 | `react`（换人重做） |
| 2 | `never_fixes` | 评审输出含 `applied_fixes` / `modified` 等修复声明 | `react`（退回生产者） |
| 3 | `evidence_gate` | `verdict=PASS` 却无任何证据字段 | `react`（补证据再验） |
| 4 | `keep_list_integrity` | 上轮 `keep` 项被降级/删除且无 `resolution_reason` | `react`（补理由或恢复） |
| 5 | `hedge_words` | 文本含 `should` / `probably` / `seems to` / `I believe`（及中文「应该/可能/似乎/我觉得」） | `writer`（改写措辞） |

**三条路由语义**

| 路由 | 含义 | 什么时候用 |
|---|---|---|
| `react` | 重做 / 重算 / 换人 | 结构性问题：身份、证据、修复、保留项 |
| `writer` | 只改措辞 | 结论本身没问题，表达含猜测 |
| `controller` | 丢弃该产出 | 材料不可用（`BLOCKED` 后） |

> 优先顺序固定：**身份 > 修复红线 > 证据 > 降级 > 措辞**。
> 先判身份——身份错了，后面全无意义。

## 二、结论契约（`verdict` 三个字段）

```json
{
  "verdict": "PASS",
  "findings": [],
  "criteria_results": [
    {"id": "AC-01", "status": "pass", "reason": "evidence_specific", "evidence": "landing.html:12"}
  ]
}
```

| 字段 | 取值 | 硬规则 |
|---|---|---|
| `verdict` | `PASS` / `FAIL` | `BLOCKED` **不是**结论，是中止状态，不进这个字段 |
| `findings[]` | 数组 | 每项带 `severity`：`BLOCKER` / `CRITICAL` / `MAJOR` / `MINOR` |
| `criteria_results[]` | 数组 | 每项 `{id, status, reason, evidence}`；`status=pass` 必须有 `evidence` |

**自相矛盾检测**：存在 `BLOCKER` 级 finding 却判 `PASS` → 结论无效。

## 三、"拒绝评判"清单（Declined to judge）

以下情况**主动声明不评判**，而不是勉强给结论。写进报告是加分项，不写是失职：

| 情况 | 为什么拒绝 | 怎么写 |
|---|---|---|
| 专业领域超出能力（如持牌法律/医疗意见） | 越界即误导 | 「此部分超出本评审范围，需持牌方出具」 |
| 判据缺失或互相冲突 | 无可判之处 | 「判据 AC-03 与 AC-07 冲突，需先裁决」 |
| 成品不可完整访问（只有片段/截图） | 看不到全貌 | 「仅收到片段，未评全局一致性」 |
| 价值判断类问题（好不好看、值不值） | 主观，非可判定 | 「审美属主观判断，仅评可用性与规范符合度」 |
| 需要真实业务数据但未提供 | 无法验证 | 「未提供后台数据，转化类结论不予评判」 |

> 「拒绝评判」不是摆烂，它保护的是**结论的可信边界**。
> 一份敢写"这我不评"的报告，比一份什么都敢判的报告可信得多。

## 四、严重度校准（不许凭手感）

| 级别 | 判据（满足任一） | 典型例子 |
|---|---|---|
| `BLOCKER` | 错到不能用，或违反红线（合规/安全/身份） | 极限词违规、无证据判 PASS、自己评自己 |
| `CRITICAL` | 能用但结论不成立，会误导决策 | 数据口径错、结论与证据不符、缺关键字段 |
| `MAJOR` | 影响体验/可信度，不致命 | 缺降级说明、错误提示不可执行、格式不可读 |
| `MINOR` | 打磨项 | 措辞、排版、大小写 |

**校准测试（互相校验用）**：把同一份评审交给两个人，同一发现允许差一级，**不允许差两级**。
差两级说明判据没写清，先修判据再评审。

## 五、只记录不修复：为什么这条最贵

看起来"顺手改掉更好"，实际代价是：

1. **职责坍塌**：改完你就是生产者，而生产者不能自评 → 下一轮没人能校验；
2. **证据消失**：你改掉了问题，"问题是否真实存在"再也无法复核；
3. **责任错位**：出问题时分不清是评审判断错，还是修复引入的错。

**正确动作**：把问题写成 `findings` 的一条，附定位与整改建议，退回生产者。
**允许的动作**：给最小复现（如"把 A 改成 B 就错了"），但不落盘改成品。

## 六、与门禁的接线

| 判什么 | 命令 | 判不了什么 |
|---|---|---|
| 记录结构 + 证据链 | `python harness.py verdict --input <结果.json>` | 判不了证据是否**真**（需人工复核定位） |
| 评审产出五类系统病 | `python review.py --packet <评审包.json>` | 判不了评审**判断质量**（需第二评审或抽检） |

> 两个门禁加起来能保证"这次评审形式上没作弊"，**保证不了"这次评审判断是对的"**。
> 后者只能靠：抽检证据定位 + 双人交叉 + 定期用历史坏例子做回归。
