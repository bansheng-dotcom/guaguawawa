# 阈值设计样例（threshold-design）

> 五类领域的「可计数的量 + 三级阈值 + 分布回测」样例。
> **数值是可换的，方法不可换**。版本：v1（P1 起步）

---

## 一、先看方法：三级分档怎么落到分布上

拿历史产物算出一个量，得到分布，然后这样切：

```
                    P10     P50     P70    P90
历史分布   ─────────┼───────┼───────┼──────┼────────▶  数值越大越差
                    │       │       │      │
优秀线  ←───────────┘       │       │      │           ≤ P10
目标线  ←───────────────────┘       │      │           ≤ P70
地板线  ←───────────────────────────┘      │           ≤ P90（拒收线）
```

**三条经验法则**

| 法则 | 数值依据 | 违背的后果 |
|---|---|---|
| 地板应卡掉约 **10%** 历史产物 | ≤ P90 | 门槛形同虚设 |
| 目标应让约 **70%** 达标 | ≤ P70 | 目标无指引作用 |
| 优秀约前 **10%** 能达到 | ≤ P10 | 无人可达 → 被忽略 |

> 这不是数学定律，是**行为设计**：门槛太高会被放弃，太低会被无视。

## 二、设计类：层级字号比

**量**：相邻信息层级的字号比（大字号 ÷ 小字号），取一页里最小的一对。

| 档 | 值 | 含义 |
|---|---|---|
| 地板 | **≥1.25×** | 低于此，视觉上分不出层级 |
| 目标 | **≥1.5×** | 正常可辨 |
| 优秀 | **≥2.0×** | 层级一眼分明（如 28px vs 14px） |

**怎么量**：取设计稿里相邻两级的字号值相除，取整页最小值。
**谁量**：评审者（非设计者本人）。
**何时量**：每次交付。

**分布回测**：抽 10 张历史页面，若 7 张都在 1.1–1.2× → 说明历史产物普遍弱，
地板设 1.25× 会卡掉多数；此时**先把地板降到 1.15× 过渡一个季度**，再抬到 1.25×。

## 三、数据类：图表诚实度

**量**：一张图里「未标注的欺骗性操作」个数（截断轴未标 / 双轴未说明 / 饼图 >5 类 / 3D 效果）。

| 档 | 值 | 含义 |
|---|---|---|
| 地板 | **0 个** | 有 1 个即拒收（诚实问题不设缓冲） |
| 目标 | 0 个 | 同上 |
| 优秀 | 0 个 + 主动标注口径与样本量 | 标杆 |

> 这是**特例**：涉及诚实性的量，三级合一，全部为 0。
> 阈值不是永远要分三档——**底线类指标只有一档**。

**怎么量**：逐图核对四类操作，计数。
**谁量**：分析师以外的人（避免自审）。
**何时量**：每次出报告前。

## 四、代码类：单函数复杂度

**量**：单函数有效行数（不含空行与注释）。

| 档 | 值 | 含义 |
|---|---|---|
| 地板 | **≤80 行** | 超过即要求拆分 |
| 目标 | **≤40 行** | 正常 |
| 优秀 | **≤20 行** | 单一职责清晰 |

**分布回测**：跑一遍现有代码库，若 P90 = 120 行 → 地板若设 40 行会卡掉一半，
先设 80 行、季度后收紧到 60 行。

**配套量**：单字母变量数（地板 0 个，除循环下标）— 这类「归零型」指标同样只有一档。

## 五、文案类：具体度

**量**：每千字形容词/程度副词数（好、很棒、超高、一流、极致…）。

| 档 | 值 | 含义 |
|---|---|---|
| 地板 | **≤6 处/千字** | 超过说明靠形容词撑场面 |
| 目标 | **≤3 处/千字** | 正常 |
| 优秀 | **≤1 处/千字** | 几乎全靠事实说话 |

**配套量**：每个结论的可核查参数个数（地板 ≥1 个）。这个量方向相反（越大越好），
分档写成 `地板 ≥1 / 目标 ≥2 / 优秀 ≥3`。

> **注意方向**：有的量越小越好（形容词密度），有的越大越好（参数个数）。
> 三级表里必须写清方向，否则容易被反向执行。

## 六、运营类：客户健康（复用开源量化样例）

**量的参考**（来源：`customer-success-manager` 类开源 agent 定义，采用 30% / 成果 25% /
关系 20% / 支持 15% / 商业 10% 的加权结构）：

| 指标 | 地板 | 目标 | 优秀 |
|---|---|---|---|
| 已购席位活跃率 | ≥40% | **≥60%** | ≥80% |
| 首次价值实现 | ≤60 天 | **≤30 天** | ≤14 天 |
| 会议到场率 | ≥60% | ≥80% | ≥90% |

**这条样例的价值**：它证明「客户健康」这种听起来很软的东西，能落成三档数字。
我们的 `qbr-health` 已有四维加权，缺的正是**每个维度的三档阈值**。

## 七、回测模板（照这个填）

```markdown
## 量：<名称>
方向：越小越好 / 越大越好
怎么量：<步骤>
样本：<N> 个历史产物，取期 <起止>

| 样本 | 实测值 |
|---|---|
| #1 | |
| ... | |

分布：P10=__  P50=__  P70=__  P90=__

定档：
- 地板 = __（依据：约卡掉 10%）
- 目标 = __（依据：约 70% 可达）
- 优秀 = __（依据：约前 10%）

区分度：好样本 3 个均值 = __；差样本 3 个均值 = __；能否分开：能/不能
校准周期：每季度 / 分布位移时
```

## 八、五条容易踩的坑

| 坑 | 表现 | 后果 |
|---|---|---|
| **只有一个数** | 「≥90%」 | 只有过/不过，卡在线上的人无法改进 |
| **玻璃地板** | 90% 产物都过 | 门槛等于没有 |
| **天花板** | 无人能达到 | 整条规范被放弃 |
| **不可数的量** | 「专业度 8 分」 | 谁打分都能争，等于没有判据 |
| **不回测** | 拍脑袋定 | 一定偏，且没人知道偏了 |
