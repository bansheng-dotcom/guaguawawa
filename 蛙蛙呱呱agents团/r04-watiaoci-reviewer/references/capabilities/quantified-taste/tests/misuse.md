# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表是**定阈值时的常见错法清单**，
> 由评审者逐条判真假。版本：v2.0.0

## 一、硬门（§5，任一不过即不得写进其他卡的质量门）

| # | 错法 | 判据 | 怎么验 |
|---|---|---|---|
| MU-01 | 阈值对应的量不可数 | 两人能数出同一个数 | 让第二个人独立量一遍 |
| MU-02 | 只给一个阈值 | 必须三级：地板/目标/优秀 | 数档位 |
| MU-03 | 无分布回测 | ≥5 个历史产物实测，或标「未校准」 | 要回测表 |
| MU-04 | 无区分度检验 | 好/差各 3 个能被这个量分开 | 看两组实测均值 |
| MU-05 | 缺测法三句 | 怎么量/谁量/何时量 | 逐项核对 |
| MU-06 | 无校准周期 | 写明每季度或分布位移时 | 看文档 |

## 二、软门（§6 自检，靠人抓）

| # | 错法 | 问题 |
|---|---|---|
| MU-07 | 地板卡掉一半以上历史产物 | 团队会直接放弃整条规范 |
| MU-08 | 目标 90% 产物都轻松达到 | 「变好」没有指引 |
| MU-09 | 用「专业度/质感/高级感」当量 | 不可数 → 谁打分都能争 |
| MU-10 | 产出者自己量 | 自评必然宽松 |
| MU-11 | 为「显得严格」抬高标准 | 阈值服务于行为，不服务于姿态 |
| MU-12 | 未校准值直接进质量门 | 参考值不能一票否决 |
| MU-13 | 一次调多个阈值 | 无法判断行为变化由哪个引起 |
| MU-14 | 不写方向（越小越好/越大越好） | 容易被反向执行 |
| MU-15 | 底线类指标也硬凑三档 | 诚实类应全部归零，只有一档 |

## 三、这套方法怎么被验收

本卡没有机器门禁。可验收的只有两件事：

1. **回测表存在**：5–20 个样本的实测值与 P10/P50/P70/P90 分布；
2. **区分度成立**：好样本与差样本在该量上的均值差足以分开（不能重叠）。

若两者都不具备，这个阈值只能标注「参考」，**不得写进任何卡的 §5**。

## 四、诚实说明

阈值合理性的最终判据是**行为**：定了之后团队是「改进了」还是「放弃了」。
三个月后回看：若达标率接近 0 或接近 100%，这个阈值就是错的——
前者太高，后者太低。这不是数学问题，是设计问题。

> **纪律**：好的阈值让人知道往哪走，坏的阈值让人知道不用走。
