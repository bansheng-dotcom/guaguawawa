# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表是**人工评审清单**，逐条判真假。
> 版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 | 出处 |
|---|---|---|
| MU-01 | 变更按不可逆性分级（一级可逆/二级半可逆/三级不可逆），三级须创始人签字 | §5 第 1 条 |
| MU-02 | 影响面含功能清单、客户范围、最坏后果三项 | §5 第 2 条 |
| MU-03 | 回滚预案含触发条件/步骤/预计耗时/验证方式；一级变更回滚 ≤15 分钟 | §5 第 3 条 |
| MU-04 | 灰度有阶梯（1/10/50/100%）与放量条件，每档观察 ≥30 分钟 | §5 第 4 条 |
| MU-05 | 发布窗口避开周五下午、节假日前、大促期；冻结期变更需升级审批 | §5 第 5 条 |
| MU-06 | 发布单六项齐备；24 小时内完成事后回看三项 | §5 第 6 条 |

## 二、软门（§6 自检，靠人抓）

| # | 常见错法 |
|---|---|
| MU-06 | 我给变更分了级，三级我确认过需要创始人签字 |
| MU-07 | 我写清影响哪个功能、影响哪些客户、最坏会怎样 |
| MU-08 | 我的回滚预案有触发条件、步骤、耗时、验证方式 |
| MU-09 | 一级变更回滚 ≤15 分钟，超过的我重设计了 |
| MU-10 | 灰度是 1%→10%→50%→100%，每档观察 ≥30 分钟 |
| MU-11 | 放量条件写死了（错误率/延迟/业务指标） |
| MU-12 | 我没在周五下午或节假日前发 |
| MU-13 | 发布单六项我都填了 |
| MU-14 | 24 小时内我回看过灰度、意外影响、回滚可用性 |

## 三、诚实说明

本卡没有可自动断言的门禁：回滚是否真能跑通只能靠演练验证，影响面是否准确只能靠事后对照。结构可校验，有效性不可。

## 四、怎么验（没门禁时的替代验证）

1. **双评**：两人独立按 §5 逐条判，一致率 ≥80%；
2. **抽样反查**：随机抽 3 条要求指出具体位置/数字；
3. **对照抽检**：与 `references/release-runbook.md` 里的 BAD/GOOD 并列看。

> **纪律**：发布的目标不是「发出去」，是「**发出去之后能回来**」。
