# R20 蛙值守 · SRE · 方法包（Method Pack v1）

## 1. 决策问题

- 典型决策：能不能发、故障怎么复盘。
- 决策者：技术负责人；成功标准：SLO 达标、故障可恢复。
- 非目标：不做无回滚的变更、不把人为失误当根因。

## 2. 问题树（MECE）

| 分支 | 要回答 | 假设 | 数据 | 方法 |
|---|---|---|---|---|
| 变更 | 这次变更风险多大 | 风险可评估 | 变更记录 | 变更评审 + 灰度 |
| 容量 | 扛不扛得住 | 容量有余量 | 压测 | 容量规划 |
| 监控 | 坏了能不能发现 | 告警有效 | 监控指标 | SLO/告警 |
| 恢复 | 多久能恢复 | RTO/RPO 达标 | 演练 | 备份恢复演练 |

**critical branch**：`恢复`——资源优先给它。

## 3. 假设与证伪

- H1：发布后 1 小时内错误率不超过基线 1.5 倍。
- H2：故障时 15 分钟内可回滚或切流。
- 竞争解释（至少 2 个）：故障是变更引起，还是流量/依赖？；恢复慢是工具问题，还是流程问题？
- 每条假设必须有**杀死标准**：指标 + 阈值 + 观察窗口。

## 4. 证据分级

| 级别 | 来源 | 允许用法 |
|---|---|---|
| A | 系统记录、合同、官方数据、可复算台账 | 可进结论与决策 |
| B | 行业报告、供应商报价、抽样数据 | 方向 + 区间 |
| C | 访谈、估算、单点经验 | 标注 + 敏感性 |

**规则**：每个结论挂来源；同名不同口径单列；缺什么、影响什么、怎么补，必须写清；C 级超过 3 条时结论降级为「条件成立」。

## 5. 方法与陷阱

- 变更评审：影响面/回滚/观察窗口三件套。
- SLO：错误预算 + 告警阈值。
- 复盘：时间线 + 根因（系统/流程）+ 行动项。
**陷阱清单**：
- 人为失误当根因
- 无回滚
- 告警风暴
- 复盘无行动项
稳定性结论必须给「回滚/切流 + 观察窗口」，否则不发布。

## 6. 输出契约

```
claim        一句话结论（方向 + 幅度 + 范围/时间）
evidence     来源 + 观测/记录 + 口径
confidence   A/B/C + 区间（无区间写「点估计，未验证」）
falsifier    什么新证据会推翻它
```

缺任一项 → 不得进首页；建议缺负责人/阈值 → 行动性不通过。
