# SOP：可用性跌破 SLA 的故障演练复盘（R20 蛙守直）

## 1. 逻辑导图

```text
[异常/诉求输入] → [L1 数据与证据真实性] → [L2 维度下钻：系统可用性]
                → [L3 外部锚点对齐] → [决策指令] → [护栏熔断] → [阶梯灰度]
```

## 2. 核心指标口径

| 指标 | 公式 | 单位 | 目标 | 告警 |
| :--- | :--- | :---: | :---: | :--- |
| 系统可用性 | `(总分钟 − 不可用分钟) / 总分钟` | % | ≥ 99.95 | 跌出 99.95 启动 P0 |
| RTO 实测值 | `演练恢复耗时` | 分钟 | ≤ 30 | 超时判不可恢复 |

## 3. 分步诊断动作

1. 定 SLA：核心路径可用性目标与统计口径。
2. 铺探活：HTTP/TCP 探活 + 业务探活双覆盖。
3. 配告警：分级升级链，P0 直达值班。
4. 做演练：按月恢复演练，记录 RTO/RPO。
5. 复盘：改进项挂责任人与验收时间。

## 4. 门禁（不满足即阻断）

| 编号 | 触发条件 | 判定 | 处置 |
| :---: | :--- | :---: | :--- |
| G1 | 核心路径无探活 | BLOCKER | 禁止上线 |
| G2 | 备份不可验证恢复 | BLOCKER | 视为无备份 |
| G3 | RTO 超目标 | CRITICAL | 立项整改并压缩目标 |

## 5. 归因路径

- **L1 数据层**：先排除脏数据、断流、重复计数，确认是真实异动。
- **L2 经营层**：按维度下钻，锁定贡献度 ≥70% 的因子（本角色主维度见 KPI 表）。
- **L3 商业层**：对齐外部锚点，区分内因外因；未接入外部数据时只声明口径，不虚构大盘数字。

## 6. 禁用词与反例

- ❌「大幅提升」「表现良好」「值得期待」等无数据锚定的形容词。
- ❌ 只给建议不给阈值；只给阈值不给回滚动作。
- ❌ 把历史个案当通用结论，不做样本量说明。
