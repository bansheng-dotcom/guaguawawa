# R10 蛙成美 · 设计 · 方法包（Method Pack v1）

## 1. 决策问题

- 典型决策：这套视觉/页面能不能用、先改哪一张。
- 决策者：业务负责人；成功标准：信息层级清楚、品牌一致、可用性达标。
- 非目标：不做品牌 VI 从零、不做纯审美争论。

## 2. 问题树（MECE）

| 分支 | 要回答 | 假设 | 数据 | 方法 |
|---|---|---|---|---|
| 信息层级 | 用户先看什么 | 主卖点唯一 | 用户任务 | 层级排序 + 5 秒测试 |
| 品牌一致 | 是否偏离品牌 | 令牌内不越界 | DESIGN.md | 令牌校验 + 对比度 |
| 可用性 | 能不能完成任务 | 关键路径 ≤3 步 | 可用性测试 | 任务走查 |
| 交付 | 工程能不能落地 | 规格齐全 | 标注/切图 | 交付检查单 |

**critical branch**：`信息层级`——资源优先给它。

## 3. 假设与证伪

- H1：用户在 5 秒内能说出主卖点。
- H2：关键任务完成率 ≥80%，无需解释。
- 竞争解释（至少 2 个）：用户没看懂，还是没兴趣？；转化低是视觉问题，还是价格/流量问题？
- 每条假设必须有**杀死标准**：指标 + 阈值 + 观察窗口。

## 4. 证据分级

| 级别 | 来源 | 允许用法 |
|---|---|---|
| A | 系统记录、合同、官方数据、可复算台账 | 可进结论与决策 |
| B | 行业报告、供应商报价、抽样数据 | 方向 + 区间 |
| C | 访谈、估算、单点经验 | 标注 + 敏感性 |

**规则**：每个结论挂来源；同名不同口径单列；缺什么、影响什么、怎么补，必须写清；C 级超过 3 条时结论降级为「条件成立」。

## 5. 方法与陷阱

- 5 秒测试：只看首屏，复述看到什么。
- 令牌校验：颜色/字体/间距必须在设计系统内。
- 状态覆盖：空/错/加载/禁用四态齐全。
**陷阱清单**：
- 好看不好用
- 首屏堆三个卖点
- 忽略空态与错误态
- 只改颜色不改结构
设计结论必须能回答「改哪一张、为什么、预期提升什么指标」。

## 6. 输出契约

```
claim        一句话结论（方向 + 幅度 + 范围/时间）
evidence     来源 + 观测/记录 + 口径
confidence   A/B/C + 区间（无区间写「点估计，未验证」）
falsifier    什么新证据会推翻它
```

缺任一项 → 不得进首页；建议缺负责人/阈值 → 行动性不通过。
