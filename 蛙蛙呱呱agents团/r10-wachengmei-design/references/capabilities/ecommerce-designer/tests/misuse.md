# 负向测试集（misuse cases）

> **用途**：把"什么算错"变成可断言的事实，而不是靠评审官临场发挥。
> 每条给一份**故意做错**的最小交付片段，以及**应当拦住它的门禁**。
> 运行方式：`python scripts/verify_delivery.py --file <该片段存成的 .md> --strict` → **必须返回 1**。
> 版本：v2.0.0

---

## 一、结构类

| # | 错误交付片段 | 应被拦住的判定 | 期望门禁 |
|---|---|---|---|
| MU-01 | 关键假设写成「假设 1：客单价 199 元。」（无"若此假设不成立"从句） | 假设不可被驳回 | G01 WARN（strict 下 FAIL） |
| MU-02 | 主图矩阵只写「首图：放商品大图，突出卖点」 | 十项缺九项 | G03 WARN → strict FAIL |
| MU-03 | 详情页 12 屏里没有 M29 适用与不适用清单 | 必含模块缺失 | G04 FAIL |
| MU-04 | 令牌表只给颜色，不写字号与授权 | 四件缺两件 | G05 WARN → strict FAIL |
| MU-05 | 提示词只写「高级商业摄影风格，主体清晰」 | 七段缺五段 | G06 WARN → strict FAIL |
| MU-06 | 交付物通篇没说规格从哪来 | 规格不可溯源 | G09 WARN → strict FAIL |

## 四、自检

- [ ] 上表每条错误片段都能被**指定的**门禁拦住（MU-14~MU-18 除外，它们需要人工/评审）
- [ ] 新增错误类型时，先加进本表，再决定加脚本还是加自检项
- [ ] 每次改 `scripts/verify_delivery.py` 后重跑 `--self-test`，并抽 3 条本表片段验证未失效

> **纪律**：本表是"门禁的测试用例"，不是"错误大全"。
> 一条错误若既抓不到也无人负责，就不该写进本表——它会产生虚假的安全感。
