# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`，编排层，不含 API 调用），
> 本表是**批次编排的常见错法**。版本：v2.0.0

## 一、硬门（§5，任一不过即不得开跑或不得交付）

| # | 错法 | 判据 | 怎么验 |
|---|---|---|---|
| MU-01 | 多张图合并成"都按主图出" | 每张图独立任务卡（六项） | 数任务卡行数 |
| MU-02 | 版数拍脑袋 | 按风险档位：试水 4 / 正式 8 / A/B 每向 4 / 补数 2 | 对档位表 |
| MU-03 | 总版数超 8×张数 | ≤ 8 × 张数 | 算一遍 |
| MU-04 | 无预算上限与止损线 | 写明上限 + 80% 暂停 + 单卡重试 ≤2 | 看文档 |
| MU-05 | 文件名不含 seed | 含 seed 或等价可复现标识 | 看文件名 |
| MU-06 | 无 manifest | 每批必产出台账，字段齐全 | 检查 json |
| MU-07 | 未过规格闸就进候选 | 进候选版本 100% 过规格闸 | 对 reject 标记 |

## 二、软门（§6 自检，靠人抓）

| # | 错法 | 问题 |
|---|---|---|
| MU-08 | 同一 prompt 无限重试 | 2 次后必须改 prompt |
| MU-09 | 构图漂移就换 seed | 那是 prompt 太虚，改 prompt |
| MU-10 | 尺寸不对靠后处理裁 | 规格要写进 prompt 第 6 段 |
| MU-11 | 有文字残留就再生成 | 补负向词，不碰运气 |
| MU-12 | 出图直接给人看 | 先跑规格闸 |
| MU-13 | 不留 manifest | 事后无法复现、无法核算成本 |
| MU-14 | 补数时重出全套 | 只出 2 版补备选 |
| MU-15 | 用「多出几版」代替想清楚 prompt | 版数达上限即停，回 prompt |
| MU-16 | 被 reject 的版本删掉 | 不删，留档用于成本核对 |

## 三、失败分类表怎么用（这张表是本卡核心）

每次"再来一次"之前必须能填出归因：

| 现象 | 归因 | 动作 |
|---|---|---|
| 偶发畸变/多余手指 | 随机性 | 换 seed 重试（≤2 次） |
| 构图每版都漂 | 构图段太虚 | 改 prompt |
| 主体材质每版都错 | 主体段太虚 | 改 prompt |
| 尺寸/比例不对 | 规格没写 | 改 prompt 第 6 段 |
| 文字/水印残留 | 负向缺失 | 改 prompt |
| 都合规但都不好 | 方向/版数 | 加版数或换方向 |

**填不出归因 = 你在碰运气**，此时正确动作是停下来改 prompt。

## 四、诚实说明

本卡**刻意不封装任何图像模型 API**：团队 55 个包保持零依赖离线可跑，
引入外部调用会让 CI 失效、门禁无从验证。真正的模型调用由外部工具承担。

因此本卡没有可自动断言的门禁；可机器做的只有规格闸与品牌色闸两件
（`imgops info` / `brandcheck check`）。

> **纪律**：批次编排的目标不是"出更多图"，是「**在花完预算之前，知道该改什么**」。
