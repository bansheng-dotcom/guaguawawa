# 出图编排层（Image Gen Pipeline）

> 一句话定位：**这张卡不调模型，它决定"这批图该出几版、花多少钱、什么时候放弃"。**
>
> 真正烧钱的失败不是模型不行，是**批次失控**：
> 一个 prompt 重试 20 次、八张图出了 60 版、落盘文件名对不上、
> 事后想复现却不知道当时用了什么参数。
> 这些都不是模型问题，是编排问题。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这批主图怎么排」「出几张几版」
- 「为什么这次出图花了这么多」
- 「上次那批图用的什么参数」
- 「重试几次该放弃」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 写/改提示词 | `r10` 的 `image-prompt-structure` | 那是描述层 |
| 多版挑哪张 | `r10` 的 `image-candidate-selection` | 那是筛选层 |
| 真的把图生成出来 | 外部工具（如 `nano-banana-pro` 类封装） | 本卡不含 API |
| 裁剪/压缩/加水印 | `r10` 的 `image-ops` | 那是后处理 |
| 判断图好不好看 | `r10` 的 `visual-hierarchy` | 那是判据 |

**最小可开工输入**：**一个商品 + 要出几张图 + 每张的用途**。

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| 主体与卖点清单 | 必需 | 无卖点无法定张数 |
| 每张的用途与平台 | 必需 | 决定规格与版数 |
| 单图成本或总预算 | 必需（对外付费时） | 缺则按「每张 ≤4 版」默认并标注 |
| 可用的生成工具 | 必需 | 缺则只出编排与 manifest，标注「未执行」 |
| 交付截止时间 | 建议 | 缺则按「不可压缩版数」处理 |

**追问纪律**：最多一轮，只问**要出几张、预算上限多少**。

## §3 执行流水线（Workflow）

### Step 1 · 任务卡（一张图一行，先锁死再出图）
每张图写清六项，缺一项就容易白出：

| 字段 | 例 |
|---|---|
| 用途 | 淘宝主图 / 详情第 2 屏 / 小红书封面 |
| 平台规格 | 1:1，2400×2400 |
| 承载卖点 | 静音（≤45dB） |
| 主体版本 | 深灰 / 白 |
| 版数 | 4 |
| 验收要点 | 主体占 70%，右上留文字位 |

**阈值**：**每张图一个任务卡行**，不允许"这批图都按主图出"这类合并。

### Step 2 · 定版数（按风险，不按心情）
| 风险 | 版数 | 判据 |
|---|---|---|
| **试水**（新主体/新风格） | **4 版** | 不确定 prompt 能否复现 |
| **正式**（prompt 已验证可复现） | **8 版** | 已知方向，求挑出最优 |
| **A/B**（要对比两个方向） | **每方向 4 版** | 方向未定 |
| **补数**（已有 1 版合格，补备选） | **2 版** | 只要备选 |

**阈值**：单批总版数 = Σ(每张版数)，且 **≤ 8 × 张数**。
超过说明你在用"多出几版"代替"想清楚 prompt"。

### Step 3 · 预算与止损（先写上限，再开始）
```
批次预算上限 = 单版成本 × 总版数 × (1 + 重试余量 20%)
```
**阈值**：
- 花费达到预算 **80%** → 暂停并汇报，由人决定是否继续；
- 同一任务卡重试 **>2 次**仍不合格 → **停止重试**，回 Step 5 判因。

> 不设上限的批次，最后一定超支——因为"再来一版"永远很便宜。

### Step 4 · 命名与落盘（事后能复现的唯一保障）
```
<批次>/<序号>_<用途>_<主体>_v<n>_<seed>.<ext>
例：20261111_coffee/01_main_dark_v3_88123.png
```

**目录结构**
```
20261111_coffee/
├── manifest.json        ← 批次台账（见 §4）
├── 01_main_dark_v1_1101.png
├── 01_main_dark_v2_1102.png
└── selected/            ← 筛选后放入主选与备选
```

**阈值**：文件名**必须含 seed 或等价可复现标识**；否则无法复现同一张图。

### Step 5 · 失败分类（该重试还是该改 prompt）
**这是本卡最核心的判断。** 出图不满意时，先分类再动作：

| 现象 | 归因 | 动作 |
|---|---|---|
| 偶发畸变、多余手指 | 随机性 | **同 prompt 换 seed 重试**（≤2 次） |
| 构图每版都漂 | prompt 构图段太虚 | **改 prompt**（写角度与占比） |
| 主体材质每版都错 | prompt 主体段太虚 | **改 prompt**（写材质与颜色） |
| 尺寸/比例不对 | 规格没写进 prompt | **改 prompt 第 6 段** |
| 有文字/水印残留 | 负向词缺失 | **改 prompt**（补负向） |
| 都合规但都不好 | 方向或版数问题 | **加版数**或换方向 |
| 规格对但主体被切 | 构图占比过大 | **改 prompt**（降占比） |

**阈值**：**同一 prompt 连续 2 次重试仍失败 → 不许再重试**，必须改 prompt 或降级交付。

> 90% 的"再试一次"其实应该改成"改一句描述"。

### Step 6 · 规格闸（出图后立刻自动核）
不等人看，先过机器能判的两条：

```bash
python agent.py imgops info --input <候选.png>        # 比例/像素/通道
python agent.py brandcheck check --input <产物>.json --design DESIGN.md   # 品牌色
```
- 规格不符 → 该版直接标记 `rejected:spec`，不进候选；
- 通道不对（要 PNG 给了 JPG 透明变黑）→ `rejected:channel`。

**阈值**：进候选池的版本 **100% 通过规格闸**。

### Step 7 · manifest 落账（交接给筛选层的唯一凭证）
每批必须产出一份 `manifest.json`（格式见 §4 / references）。没有 manifest 的批次，
**筛选层无法工作，下一轮也无法复现**。

## §5 质量门（一票否决）

1. **每张图有独立任务卡**（用途/规格/卖点/版数/验收要点齐备）；
2. **版数按风险档位定**，且总版数 ≤ 8 × 张数；
3. **写明了预算上限与止损线**（80% 暂停 / 单卡重试 ≤2 次）；
4. **文件名含 seed 或等价可复现标识**；
5. **每次重试前有失败分类**（该重试 vs 该改 prompt）；
6. **产出 manifest.json**，且进候选的版本 100% 过规格闸。

> 本卡无自动门禁。规格闸可用 `python agent.py imgops info` 执行（部分自动）。

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 一个 prompt 重试到底 | 重试 ≤2 次，之后必须改 prompt |
| EX-02 | 不设预算上限 | 先写上限 + 80% 暂停线 |
| EX-03 | 所有图都按"正式 8 版"出 | 试水先 4 版，验证可复现再加 |
| EX-04 | 文件名只有 `1.png` | 含用途/主体/版本/seed |
| EX-05 | 不留 manifest | 每批必产出台账 |
| EX-06 | 出图直接给人看 | 先跑规格闸，不符的不进候选 |
| EX-07 | 构图漂移就换 seed | 构图漂移是 prompt 太虚，要改 prompt |
| EX-08 | 尺寸不对靠后处理裁 | 规格写进 prompt 第 6 段 |
| EX-09 | 有文字残留就再生成 | 补负向词，不是碰运气 |
| EX-10 | 批次不记录成本 | manifest 记每版成本与合计 |
| EX-11 | 补数时重出全套 | 只出 2 版补备选 |
| EX-12 | 用"多出几版"代替想清楚 | 版数超 8×张数即停，回 prompt |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| 无生成工具/无 API | 只出任务卡 + 版数方案 + manifest 空模板，标注「未执行」 |
| 预算极低 | 全部降为试水 4 版，优先保主图 |
| 时间极紧 | 砍张数不砍版数（版数不足等于没得挑） |
| 生成工具不稳定 | 记录失败率，必要时换工具；本卡不含工具选型 |
| 需要人像 | 加「人像一致性」风险项，版数上调 |
| 生成涉第三方商标 | 明确拒绝进入批次；改用不具名替代 |
| 已出图但没 manifest | 立即补录（参数从工具日志捞），标注「事后补录」 |

**明确不做**
- 不封装 API、不写调用代码、不做后处理、不挑图、不判美观。
