# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`，无命令门禁），因此本表是**人工评审清单**。
> 每条都由评审者判真假，判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| MU-01 | 图类型单一（架构/流程/关系） | §5 第 1 条 |
| MU-02 | 每个节点有类型与名称 | §5 第 2 条 |
| MU-03 | 每条连线有方向与协议 | §5 第 3 条 |
| MU-04 | 分层显式且无穿层线 | §5 第 4 条 |
| MU-05 | 交付可编辑格式而非截图 | §5 第 5 条 |

## 二、软门（§6 自检，靠人抓）

| MU-05 | 这张图只表达一件事（架构/流程/关系之一） |
| MU-06 | 每个节点都写了类型 |
| MU-07 | 每条线都有方向，并标了协议 |
| MU-08 | 分层画出来了，没有一条线穿三层 |
| MU-09 | 交的是可编辑文件，不是截图 |
| MU-10 | 外部系统与团队边界标了 |
| MU-11 | 命名全图统一（不混中英、不混大小写风格） |

## 三、诚实说明

本卡**没有**可自动断言的门禁：它的输入是判断与决策，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——这比没有门禁更糟。

> **纪律**：knowledge 卡的价值在「有方法可依」，不在「有分数可刷」。
