# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`），本表为人工评审清单。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| # | 判据 |
|---|---|
| MU-01 | 每个元素标注尺寸/间距/色值/字重四项 |
| MU-02 | 每个组件覆盖 6 态；每屏 ≥3 断点 |
| MU-03 | 资源命名遵循 `<模块>_<元素>@<倍率>`，可矢量优先 SVG |
| MU-04 | 每个动效标注触发/时长/缓动，且尊重 reduced-motion |
| MU-05 | 每次改稿产出变更单并标注影响面 |
| MU-06 | 工程能独立复述页面结构与状态（不需要再问） |

## 二、软门（§6 自检）

| # | 常见错法 |
|---|---|
| MU-06 | 每个元素我都标了尺寸、间距、色值、字重 |
| MU-07 | 每个组件 6 态都画了（包括加载和空态） |
| MU-08 | 375/768/1280 三档都给了 |
| MU-09 | 切图命名是按规则来的，不是 `1.png` |
| MU-10 | 能用 SVG 的我没给 PNG |
| MU-11 | 动效标了时长和缓动，也标了减弱动效行为 |
| MU-12 | 我出了变更单，写清影响哪些已开发部分 |
| MU-13 | 我让工程复述过一次，他能说清结构 |

## 三、诚实说明

本卡没有可自动断言的门禁：交付是否完整，唯一判据是「工程还需不需要再问」。

> **纪律**：交付的目标不是「我画完了」，是「**他一句话都不用问就能做**」。
