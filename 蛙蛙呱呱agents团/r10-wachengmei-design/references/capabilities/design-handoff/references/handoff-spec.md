# 交付规范细则（handoff-spec）

> 标注 · 六态 · 命名 · 变更单 · 6 组 BAD/GOOD。版本：v1

## 一、标注四件

| 项 | 例 | 常见漏法 |
|---|---|---|
| 尺寸 | 按钮 120×44 | 只给宽度 |
| 间距 | 与上一元素 16 | 写「适当留白」 |
| 色值 | `#0F172A`（令牌 primary） | 手填且与令牌不符 |
| 字重 | 14px / 500 / 行高 1.5 | 只给字号 |

## 二、六态清单（每个交互组件）

默认 / 悬停 / 焦点 / 禁用 / 加载 / 空或错误

**最少要画的是「焦点」和「错误」**——这两个最常被漏，也最常在实现时被自由发挥。

## 三、命名规则

```
<模块>_<元素>@<倍率>.<ext>
btn_primary@2x.png
icon_cart@1x.svg
card_product_bg@3x.png
```

**禁用**：`1.png`、`未标题-1.png`、`切图/新建文件夹/…`

## 四、变更单模板

```markdown
## 变更单 v2
改动：结算页按钮从描边改为填充
影响断点：375 / 1280
影响已开发：结算页按钮组件（需重写样式）
原因：主操作权重不足（对比度 2.1:1 → 4.8:1）
```

## 五、6 组 BAD/GOOD

| # | 场景 | ❌ | ✅ |
|---|---|---|---|
| 1 | 标注 | 只给一屏主状态 | 6 态 + 3 断点 |
| 2 | 间距 | 「看着差不多」 | 16px（刻度内） |
| 3 | 命名 | `1.png` | `btn_primary@2x.png` |
| 4 | 格式 | 全 PNG | 图标用 SVG |
| 5 | 动效 | 「淡入」 | 200ms ease-out，减弱动效时直接切换 |
| 6 | 改稿 | 微信里说一句 | 变更单 + 影响面 |

## 六、来源

- 标注四件与六态：设计交付（design handoff）通行做法
- 命名规则：前端资源命名约定
- 与相邻卡分工：判据在 `visual-hierarchy`，令牌在 `design-system`
