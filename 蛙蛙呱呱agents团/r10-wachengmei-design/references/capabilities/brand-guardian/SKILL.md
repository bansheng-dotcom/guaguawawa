# 品牌一致性守卫（Brand Guardian）

> 一句话定位：**这个技能存在的意义，是防止「每个页面都说是按规范做的，但拼起来有七种蓝」**。
> 品牌一致性不是审美问题，是**可度量问题**：
> 用色在不在令牌里、单页主色几个、对比度够不够、字体几种。
> 这四项都能机器比，所以没理由靠"设计师看一眼"。

## §1 何时用 / 何时不用

**该用（用户真实会这么说）**
- 「这套物料还符合品牌吗」「新页面有没有跑偏」
- 「颜色怎么又不一样了」「字体为什么多了」
- 「上线前过一下品牌检查」

**不该用，转给谁**

| 用户其实想要 | 转给 | 理由 |
|---|---|---|
| 定设计令牌本身 | 本角色的 `design-system` | 本包只做**比对**，不造令牌 |
| 好不好看、层级是否清晰 | 本角色的 `frontend-design` | 那是界面设计 |
| 广告法极限词扫描 | `r11` 的 `brand-voice` | 那是文案合规 |
| 电商主图转化优化 | 本角色的 `ecommerce-designer` | 那是转化导向 |

**最小可开工输入**：**一份产物描述（用色/字体/文本对）+ 一份 DESIGN.md**。

---

## §2 前置输入与最省追问

| 输入 | 是否必需 | 缺失时怎么办 |
|---|---|---|
| `colors`（产物用到的十六进制） | 必需 | 无颜色无法比对 |
| `fonts`（字体族） | 建议 | 缺则跳过字体数量检查 |
| `text_pairs`（前景/背景对） | 建议 | 缺则跳过对比度检查 |
| `DESIGN.md`（品牌令牌） | 必需 | 无令牌无法判"越界" |

**追问纪律**：最多一轮，只问**DESIGN.md 在哪**。没有令牌文件就无法做一致性检查。

---

## §3 执行流水线（Workflow）

### Step 1 · 用色在不在令牌内（越界即拦）
```bash
python agent.py brandcheck check --input <产物描述.json> --design <DESIGN.md>
```
门禁把产物颜色与 DESIGN.md 的令牌逐一比对，**不在令牌内的颜色直接 BLOCKER**。
实测：产物用了 `#1e3a5f` 而令牌是 `#0F172A`，即使"看起来差不多"也判越界。

> 这一条最容易被抱怨"太严"。但品牌跑偏就是从"差不多"开始的：
> 差一点的蓝、差一点的灰，攒到第七个就成了新品牌。

- **产出**：越界色清单
- **过关条件**：`brandcheck check` 退出码 0

### Step 2 · 单页主色数量（≤8）
单页主色超过 8 个，视觉就不再有主次。
**判据**：色相差异明显的算不同主色；同色系深浅算同族。

### Step 3 · 文本对比度（正文 ≥4.5:1）
对每对 `text_pairs` 计算对比度：
| 用途 | 最低 |
|---|---|
| 正文 | 4.5:1 |
| 大字（≥18px 粗 / ≥24px） | 3:1 |

实测：`#EEEEEE` 文字放在 `#FFFFFF` 背景上，对比度约 1.1:1 —— 几乎不可读，门禁直接拦。

### Step 4 · 字体数量（≤2 种）
品牌字体超过 2 种，视觉就开始"拼"。逐款还要标明商用授权状态。

### Step 5 · 出结论（三选一）
| 结论 | 条件 |
|---|---|
| **合规** | 四项全过 |
| **有条件通过** | 仅字体授权待确认等非视觉项 |
| **不合规** | 有越界色 / 对比度不足 / 主色超限 |

## §4 交付物清单

| # | 交付物 | 载体 | 骨架出处 |
|---|---|---|---|
| 1 | 越界用色清单（产物色 vs 令牌色） | 终端 JSON | `agent.py brandcheck check` |
| 2 | 主色数量与字体数量统计 | 终端 JSON | 同上 |
| 3 | 对比度逐对结果 | 终端 JSON | 同上 |
| 4 | 一致性结论（合规/有条件/不合规） | `.md` | 本文 §3 Step 5 |

- 命名：`brandcheck_<产物短码>_<YYYYMMDD>.json`
- **越界色必须给出令牌内的替代色**，只报错不给出路等于没帮上忙。

---

## §5 质量门（一票否决，不过不给交付）

1. **所有颜色都在令牌内**（`brand.colors.known`，越界即 BLOCKER）；
2. **单页主色 ≤8**（`brand.colors.count`）；
3. **文本对比度达标**（正文 ≥4.5:1，大字 ≥3:1）；
4. **字体 ≤2 种**，且逐款标明授权；
5. **结论明确**（合规 / 有条件通过 / 不合规）。

> 验收命令：`python agent.py brandcheck check --input <产物.json> --design <DESIGN.md>`
> 命中任一项不过 → 回 §3 对应 Step，**不允许把颜色改成"最近似令牌"却不更新 DESIGN.md**。

## §6 交付前自检清单

- [ ] 产物的每个颜色我都拿去和 DESIGN.md 令牌比过
- [ ] 越界的颜色都给了令牌内的替代色
- [ ] 单页主色数量数过（≤8）
- [ ] 每对文字/背景都算过对比度
- [ ] 字体不超过 2 种，且授权状态标明
- [ ] 结论是三选一，不是"基本一致"
- [ ] 如果确实是令牌缺了这个颜色，我提了"更新令牌"而不是放行

## §7 易犯错误对照表

| # | 易犯错法 | 正确做法 |
|---|---|---|
| EX-01 | 颜色"看起来差不多"就放行 | 必须精确比对令牌，差一点也是越界 |
| EX-02 | 越界了只报错不给替代色 | 给令牌内最接近的替代方案 |
| EX-03 | 单页塞 10 个主色 | ≤8，且同色系算同族 |
| EX-04 | 只看颜色不看对比度 | 每对文本/背景都要算 |
| EX-05 | 灰字白底（1.1:1）当"高级感" | 正文必须 ≥4.5:1 |
| EX-06 | 字体 3 种以上 | ≤2 种，逐款标授权 |
| EX-07 | 令牌确实缺这个色，就直接用了 | 走"更新令牌"流程，不是绕过 |
| EX-08 | 结论写"基本一致" | 三选一：合规 / 有条件 / 不合规 |
| EX-09 | 只查单页，不查跨页一致性 | 跨页也要对齐同一套令牌 |
| EX-10 | 把 brandcheck 当审美评审 | 它只查四项可度量项，审美归人 |

## §8 降级与边界

| 触发情况 | 处置 |
|---|---|
| `agent.py` 门禁跑不了 | 按 §6 人工核对，标注「未跑门禁」；**不得标记"品牌合规"** |
| 没有 DESIGN.md | 无法判越界；先让 `design-system` 出令牌，或标注"无令牌可比" |
| 产物是图片（非结构化） | 先导出主色列表再比对，标注"颜色为提取值" |
| 令牌确实缺该颜色 | 提"更新令牌"建议，不直接放行 |
| 多品牌/子品牌 | 各自的令牌分别比，不混用 |
| 需要广告法合规 | 转 `brand-voice`，本包不管文案 |

**明确不做**
- 不造设计令牌（归 `design-system`）；
- 不做界面视觉与可用性（归 `frontend-design`）；
- 不做文案合规（归 `brand-voice`）；
- 不做审美判断（本包只查四项可度量项）。
