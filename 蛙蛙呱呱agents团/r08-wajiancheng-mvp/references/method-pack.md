# R08 蛙建成 · MVP 原型 · 方法包（Method Pack v1）

## 1. 决策问题

- 典型决策：最小可验证切片是什么、值不值得做原型。
- 决策者：产品负责人；成功标准：7 天内拿到可判断的用户反馈。
- 非目标：不做生产级工程、不做完整设计系统。

## 2. 问题树（MECE）

| 分支 | 要回答 | 假设 | 数据 | 方法 |
|---|---|---|---|---|
| 核心假设 | 最该验证什么 | 假设可被一次实验证伪 | 访谈/数据 | 假设优先级排序 |
| 最小切片 | 做到什么程度够验证 | 1 条主链路可跑通 | 流程拆解 | 切片 + 假接口 |
| 验证成本 | 人天/工具/依赖 | ≤7 天、≤1 人 | 工时估算 | 时间盒 |
| 风险 | 会不会误导判断 | 样本/场景代表性 | 样本设计 | 对照 + 预注册 |

**critical branch**：`核心假设`——资源优先给它。

## 3. 假设与证伪

- H1：用户愿意为这条主链路付出真实动作（留资/试用/付费）。
- H2：原型结论能外推到真实产品（样本与场景代表）。
- 竞争解释（至少 2 个）：用户说喜欢，但不会用；原型好用是因为有人在旁边教
- 每条假设必须有**杀死标准**：指标 + 阈值 + 观察窗口。

## 4. 证据分级

| 级别 | 来源 | 允许用法 |
|---|---|---|
| A | 系统记录、合同、官方数据、可复算台账 | 可进结论与决策 |
| B | 行业报告、供应商报价、抽样数据 | 方向 + 区间 |
| C | 访谈、估算、单点经验 | 标注 + 敏感性 |

**规则**：每个结论挂来源；同名不同口径单列；缺什么、影响什么、怎么补，必须写清；C 级超过 3 条时结论降级为「条件成立」。

## 5. 方法与陷阱

- MVP 切片：只做一条主链路，其余用假数据/人工后端。
- Pretotype：先验证需求，再写代码。
- 成功/杀死标准：上线前写死指标、样本量与停止条件。
**陷阱清单**：
- 把原型当成品
- 没有杀死标准
- 样本全是熟人
- 忽略埋点导致无法判断
原型交付必须附「结论可用/不可用」的判断，不许只交截图。

## 6. 输出契约

```
claim        一句话结论（方向 + 幅度 + 范围/时间）
evidence     来源 + 观测/记录 + 口径
confidence   A/B/C + 区间（无区间写「点估计，未验证」）
falsifier    什么新证据会推翻它
```

缺任一项 → 不得进首页；建议缺负责人/阈值 → 行动性不通过。
