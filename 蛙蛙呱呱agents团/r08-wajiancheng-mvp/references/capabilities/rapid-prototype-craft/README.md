# 高保真可交互原型（rapid-prototype-craft）

> 归属：R08　消费：r10, r09　版本：v1.1（2026-11-17 补齐结构）
> 从想法/PRD 到可点击原型：单文件优先、假数据、无真实后端，目标是让对方 3 分钟内看懂主流程，而不是做一个产品。

## §1 何时使用 / 何时不用

**当…时使用**：当需要在 1 天内把 PRD 变成可点击原型、用于评审或用户测试时使用；当要验证信息架构与主流程是否成立时使用。

**不用于**：不做生产级工程（归 R09）、不做视觉品牌系统（归 R10）、不接真实支付/登录。

## §2 输入与输出

| 方向 | 内容 |
|---|---|
| 输入 | PRD 或一句话需求；主流程 3–5 步；目标设备（桌面 / 移动） |
| 输出 | 单文件 HTML 原型（内联样式与脚本）；主流程走查说明；已知偷懒清单（哪些是假的） |

## §3 执行流程

1. 圈定主流程：只做一条链路，其余入口置灰。
2. 画三屏：入口 → 主操作 → 结果，先低保真确认信息层级。
3. 改高保真：套设计令牌（颜色/字号/间距），数据全部用假数据。
4. 加交互：点击态、加载态、空态、错误态四态齐备。
5. 自测：本地点开走一遍，记录断点。
6. 交付：附「偷懒清单」（哪些没做、哪些是假数据）。

## §5 脚本与门禁入口

| 用途 | 命令 | 判据 |
|---|---|---|
| 原型生成 | `python agent.py prototype prototype --input <brief.json>` | 输出单文件 HTML |
| 页面拆解 | `python agent.py prototype screen --input <brief.json>` | 先出线框再上高保真 |
| 验收 | `python agent.py qa qa --input <artifact.json>` | 四态与断点检查 |

## §6 交付前自检

- [ ] 单文件可直接双击打开，无外部依赖
- [ ] 四态（点击/加载/空/错误）都能看到
- [ ] 假数据有标注，未冒充真实业务数据
- [ ] 「偷懒清单」写清了哪些没做

## §7 常见错误对照

| 编号 | 错误 | 正确做法 |
|---|---|---|
| PROTO-01 | 三条链路一起做，每条都不完整 | 只做一条主流程，其余置灰 |
| PROTO-02 | 高保真但点不动 | 先保证可点击，再谈像素 |
| PROTO-03 | 用真实用户数据做演示 | 一律假数据，避免隐私与误导 |

## §8 异常与降级

| 情况 | 处理 |
|---|---|
| 没有设计稿 | 先用默认设计令牌，交付时说明待品牌化 |
| 交互太复杂 | 砍到 3 屏，剩余写成「后续版本」 |
| 移动端未定 | 先做响应式单页，断点写进说明 |
