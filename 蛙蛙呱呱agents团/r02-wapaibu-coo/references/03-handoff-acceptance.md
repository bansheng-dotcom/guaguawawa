# 模块3 · 交接与验收追踪





>








> 整合自 anthropics__knowledge-work-plugins 的 operations/status-report


> 与 engineering/documentation、standup。


> 核心主张：**交接失败不是态度问题，是包不完整**——


> 工单四要素+复现命令是底线，验收逐条对证据。





## 3.1 交接包门禁（s03/package）





工单四要素缺一即拦：


1. **做了什么**——变更内容一句话说得清；


2. **怎么验证**——验收人自己能跑的判定步骤；


3. **影响面**——动了哪些东西、谁会被波及；


4. **回滚方式**——出问题怎么退回安全态。





**复现命令 ≥ 1** 是硬门禁：没有复现命令的交接包出不了门。


验收人不应依赖交接人在场才能看懂。





包号 `HP-` + sha8 指纹（取交接内容摘要），同内容同包号，


天然防重复交接。输出带 `downstream_count / criteria_count`


计数，供下游清点。





## 3.2 验收规则（s03/accept）





逐条判：每条标准 `pass` 且**带证据**才计通过。


- 全过 → `PASS`；


- 任一条 fail → `FAIL` 并**退回**（不是「带病通过」）；


- `pass=true` 但证据空 → 拦下——**无证据不许过**，


  「我觉得没问题」不是验收。





## 3.3 审计链路（s03/trace）





事件白名单校验 + 链路追踪：


1. 事件类型必须在白名单内（乱造事件名 = 链路噪声）；


2. 时间戳**单调递增**——时间倒流即拦（已验证负例）；


3. 首事件 `created` → 末事件 `closed` 才算闭环，


  悬空链路（有 created 无 closed）标记未闭环。





## 3.4 站会与状态上报的衔接





站会（process/meeting）发现阻塞 → 开交接包；


交接包触发下游任务 → 下游完工走 accept；


accept FAIL → 退回的包在 trace 里留 `rejected` 事件。


状态上报（portfolio/status）的 RAG 映射吃这条链路的闭环状态。





## 3.5 实战踩坑





- 复现命令要**在新环境可跑**——依赖本机路径/手工步骤的命令过得了


  门禁过不了实际验收，写命令时按「验收人第一次见这个包」来写。


- 证据字段宁可是链接/命令输出摘要，也别留空——


  accept 的证据门禁不认「口头确认」。


- 链路事件用 ISO 时间戳，`trace` 的单调校验按字符串比较，


  时区混用会误报时间倒流。


- 四要素的文案黑词（「尽快」「推进中」等）由 review 对抗评审的


  vague_gate 拦，不归本技能重复实现。
