# 负向测试集（misuse cases）

> **本卡是 knowledge 卡**（`entry: null`，无命令门禁），因此本表是**人工评审清单**。
> 每条都由评审者判真假，判不了的写「不可判定」。版本：v2.0.0

## 一、硬门（§5，任一不过即不得交付）

| MU-01 | 口径已声明且计划/实际同口径 | §5 第 1 条 |
| MU-02 | 三段偏差可加总回到总偏差 | §5 第 2 条 |
| MU-03 | 偏差定位到具体环节 | §5 第 3 条 |
| MU-04 | 每条整改动作都有验证指标与回看时间 | §5 第 4 条 |

## 二、软门（§6 自检，靠人抓）

| MU-04 | 计划值与实际值同口径（退款/税费/时间窗） |
| MU-05 | 三段偏差相加等于总偏差 |
| MU-06 | 我指到了具体环节，没停在「大盘」 |
| MU-07 | 每条整改动作都有负责人类型 |
| MU-08 | 每条动作都有可验证指标 |
| MU-09 | 写了何时回看（具体日期） |

## 三、诚实说明

本卡**没有**可自动断言的门禁：它的输入是判断与决策，不是固定 schema。
写一个「永远 exit 0」的脚本只会制造假绿——这比没有门禁更糟。

> **纪律**：knowledge 卡的价值在「有方法可依」，不在「有分数可刷」。
