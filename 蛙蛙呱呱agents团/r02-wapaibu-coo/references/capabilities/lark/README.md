# 飞书协作（不接入）（lark）

> 归属：R02　消费：r13, r16, r17　版本：v1.1（2026-11-17 补齐结构）
> 飞书类协作工具的**边界卡**：本团队不接第三方 SaaS 账号、不代发消息，只产出可直接粘贴到飞书文档/多维表格的结构化内容。

## §1 何时使用 / 何时不用

**当…时使用**：当需要把排期、交接包、复盘记录交给团队在飞书里协作时使用；当有人要求「直接同步到飞书 / 建群通知 / 写多维表格」时，用本卡说明边界并转为导出物。

**不用于**：不用于账号授权、Webhook 配置（归 R17）、组织人事流程（归 R16）。

## §2 输入与输出

| 方向 | 内容 |
|---|---|
| 输入 | 排期/交接包的 Markdown 或 JSON；目标文档结构（章节或表格列） |
| 输出 | 可粘贴的 Markdown 片段；多维表格列定义（CSV 表头 + 示例行） |

## §3 执行流程

1. 确认协作载体：文档 / 多维表格 / 群公告三选一，不混用。
2. 按载体把内容压成「一屏能读完」的结构：标题 ≤ 20 字、每段 ≤ 3 行。
3. 表格类产出先给表头与 2 行示例，避免空表。
4. 产物交 `harness.py` 做结构校验（字段齐备、无占位符）。
5. 在交付说明里写「需人工粘贴」，不声称已同步。

## §5 脚本与门禁入口

| 用途 | 命令 | 判据 |
|---|---|---|
| 结构校验 | `python harness.py handoff --input <pkg.json>` | 字段缺失 / 空段落直接 FAIL |
| 角色入口 | `python agent.py schedule sprint --input <plan.json>` | 排期类产物由 R02 生成 |

## §6 交付前自检

- [ ] 内容里没有任何 API Key、群 ID、webhook 地址
- [ ] 标题 ≤ 20 字，段落 ≤ 3 行，表格有表头与示例行
- [ ] 交付说明明确写「需人工粘贴」，没有「已同步」这类假声明
- [ ] 产物过了 `harness.py` 且退出码为 0

## §7 常见错误对照

| 编号 | 错误 | 正确做法 |
|---|---|---|
| LARK-01 | 把「生成可粘贴内容」说成「已同步到飞书」 | 交付说明加「需人工粘贴」，状态写 `simulated` |
| LARK-02 | 把群 ID / 机器人 token 写进产物 | 凭据一律走环境变量，产物只留占位名 |
| LARK-03 | 表格只给空表头 | 至少给 2 行示例，避免接收方无法判断字段含义 |

## §8 异常与降级

| 情况 | 处理 |
|---|---|
| 无网络 / 无账号 | 仍产出可粘贴内容，标注 `blocked: 未接入` |
| 目标文档结构未知 | 按默认三段（背景 / 计划 / 待办）出稿，并在交付说明里请对方替换 |
| 内容超一屏 | 拆成多段并在开头给目录，不压缩字号 |
