# 交接契约与验收细则（handoff-contract）

> 被 §3、§5、§7 按需引用。版本：v2.0.0（项目自建，v1）

---

## 一、交接包字段（`package` 门禁逐项校验）

| 字段 | 必填 | 判据 | 缺了的后果 |
|---|---|---|---|
| `process_doc` | ✓ | 非空 | 接收方不知道按什么流程验收 |
| `artifact` | ✓ | 非空 | 无可交付物 |
| `artifact_type` | ✓ | 在白名单（code/data/design/doc…） | 接收方按错方式处理 |
| `owner` | ✓ | 具体角色，不是"团队" | 出事找不到人 |
| `rev` | ✓ | 版本号 | 无法区分哪一版被验收 |
| `handoff_to` | ✓ | 具体角色 | 交接对象不明 |
| `repro_commands` | ✓ | **≥ 1 条可粘贴命令** | 接收方跑不起来 = 没交 |
| `downstream_fields` | ✓ | **≥ 1 个** | 下游不知道要消费什么 |
| `acceptance_criteria` | ✓ | **≥ 1 条可判定标准** | 无法验收 |
| `must_read` | 建议 | 必读清单 | 接收方漏看关键说明 |

### 复现命令的写法

```json
"repro_commands": ["unzip landing_v2.zip && python serve.py --port 8080"]
```

反例：「按 README 操作」「环境配好就能跑」「找 XX 要」。这类写法等于没有复现。

## 二、验收记录（`accept` 门禁逐项校验）

```json
{
  "package_id": "HP-a1b2c3d4",
  "criteria": [
    {"criterion": "Lighthouse ≥ 90", "passed": true, "evidence": "报告 91 分（workspace/lh.html）"},
    {"criterion": "首屏 < 1.5s", "passed": false, "reason": "实测 2.3s，超出 0.8s"}
  ]
}
```

| 规则 | 口径 |
|---|---|
| `passed=true` + 无 `evidence` | **不算通过**（门禁实测：会报"口头通过不算过"） |
| `passed=false` + 无 `reason` | 记为未达标准且无说明，退回补齐 |
| 最终 `verdict` | 由"通过数/总数"决定，不由接收方一句话决定 |

**"证据"的三种合法形态**
1. 可定位文件 + 行/页：`workspace/lh.html:12`
2. 命令 + 输出：`pytest -q → 42 passed`
3. 截图 + 采集时间：`截图 2026-11-11 10:02（含时间戳）`

**不合法**：「我看了没问题」「团队都确认过了」「客户说可以」。

## 三、交接结论三选一

```markdown
## 交接结论

- 结论：**退回补齐**
- 依据：package 门禁 3 项未过
- 缺项：
  1. `repro_commands` 为空 → 需要一条可粘贴命令
  2. `downstream_fields` 为空 → 需列出下游消费字段
  3. `acceptance_criteria` 为空 → 需给可判定标准
- 责任人：r08（上交方）
- 期限：下一工作日
```

| 结论 | 触发条件 | 后果 |
|---|---|---|
| **可签收** | 三道门禁全过 | 记录签收人 + 时间，交接完成 |
| **退回补齐** | 交接包缺字段 | 退回上交方，不计入验收 |
| **验收不通过** | 有验收项未过或证据缺失 | 退回生产方，列未过项 |

## 四、审计轨迹（`trace` 门禁）

```json
{"events": [
  {"ts": "2026-11-11T09:00:00", "actor": "r08", "action": "handoff", "target": "r09"},
  {"ts": "2026-11-11T10:30:00", "actor": "r09", "action": "accept_start"},
  {"ts": "2026-11-11T11:15:00", "actor": "r09", "action": "accept_pass"}
]}
```

| 检查 | 规则 |
|---|---|
| 时间单调 | `ts` 必须递增；倒序说明被补写或漏记 |
| 字段齐全 | 每条含 `ts` / `actor` / `action` |
| 主体具体 | `actor` 是角色 ID，不是"系统"/"团队" |

> **补记规则**：历史缺失只能**追加补记条目**并标 `"backfilled": true`，
> 不修改原 `ts`。伪造时间让轨迹"看起来连续"，是审计上最严重的失信。

## 五、与相关角色的边界

| 动作 | 归谁 | 不归谁 |
|---|---|---|
| 判"交接是否完整" | **r02（本技能）** | r04 |
| 判"成品质量好不好" | r04 评审官 | r02 |
| 生产成品 | r08 / r09 / r10 | r02 |
| 排期与资源 | r02 的 schedule / capacity | 本技能 |
| 验收豁免 | 创始人 | 本技能 |

> 最容易混的两件事：**验收 ≠ 质量评审**。
> 验收回答"是不是按契约交了"，质量评审回答"这东西好不好"。别用一个回答另一个。
