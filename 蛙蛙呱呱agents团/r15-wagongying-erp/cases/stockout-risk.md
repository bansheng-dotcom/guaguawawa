# SOP：核心品类安全库存与断货预警（R15 蛙供应）

## 1. 逻辑导图

```text
[异常/诉求输入] → [L1 数据与证据真实性] → [L2 维度下钻：安全库存天数]
                → [L3 外部锚点对齐] → [决策指令] → [护栏熔断] → [阶梯灰度]
```

## 2. 核心指标口径

| 指标 | 公式 | 单位 | 目标 | 告警 |
| :--- | :--- | :---: | :---: | :--- |
| 安全库存天数 | `可用库存 / 日均消耗` | 天 | ≥ 14 | < 7 紧急补货 |
| 库存周转天数 | `平均库存 / 日均销货成本` | 天 | ≤ 45 | > 60 清库 |

## 3. 分步诊断动作

1. 算安全库存：可用 + 在途 vs 日均消耗。
2. 查三单匹配：PO / 收货 / 发票是否一致。
3. 算周转：识别慢动销 SKU。
4. 出补货单：核心品类优先，附到货时间。
5. 自动化：补货触发做成流水线，带人工审批。

## 4. 门禁（不满足即阻断）

| 编号 | 触发条件 | 判定 | 处置 |
| :---: | :--- | :---: | :--- |
| G1 | 安全库存 < 7 天 | BLOCKER | 当日下补货单 |
| G2 | 三单匹配率 < 95% | BLOCKER | 暂停付款 |
| G3 | 周转 > 60 天 | WARN | 启动清库与促销 |

## 5. 归因路径

- **L1 数据层**：先排除脏数据、断流、重复计数，确认是真实异动。
- **L2 经营层**：按维度下钻，锁定贡献度 ≥70% 的因子（本角色主维度见 KPI 表）。
- **L3 商业层**：对齐外部锚点，区分内因外因；未接入外部数据时只声明口径，不虚构大盘数字。

## 6. 禁用词与反例

- ❌「大幅提升」「表现良好」「值得期待」等无数据锚定的形容词。
- ❌ 只给建议不给阈值；只给阈值不给回滚动作。
- ❌ 把历史个案当通用结论，不做样本量说明。
