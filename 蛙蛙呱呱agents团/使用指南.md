## 0. 60 秒跑通

```bash
cd "D:\蛙蛙呱呱\蛙蛙呱呱agents团"

python guagua.py doctor

python guagua.py info r06

# 4) 跑一个确定性的数据校验
```

## 1. 三个入口，先用哪一个

| 入口 | 适合谁 | 怎么用 |
|---|---|---|
| **统一入口** `guagua.py` | 第一次使用、想快速找角色/跑通 | `python guagua.py roles` / `call` / `plan` / `check` |
| **单角色入口** `rXX/agent.py` | 已经明确要找某个角色、要看完整参数 | `cd r06-wadeqing-analyst && python agent.py --help` |
| **知识注入入口** `chat.py` | 想把角色知识、案例、规则组装成 LLM Prompt | `python chat.py --role r06 --intent "..."` |

三者关系：

```text
guagua.py
  ├─ roles / info         → 读 core/registry.py
  ├─ call <role> ...      → 转发到 rXX/agent.py（全部技能）
  ├─ chat ...             → 转发到 chat.py
  ├─ plan / dispatch      → 转发到 r01/agent.py 的编排器
  └─ check / doctor       → 体检 20 个 agent.py
```

**记住一句话：** 只要角色 `agent.py` 支持的功能，`guagua.py call` 都能调用。

## 2. 统一入口 guagua.py 命令参考

以下命令默认在 `D:\蛙蛙呱呱\蛙蛙呱呱agents团` 下执行。

### 2.1 角色发现

```bash
python guagua.py roles
python guagua.py info r01
python guagua.py info 蛙得清
python guagua.py info r06-wadeqing-analyst
```

`info` 支持：角色 ID（`r06`）、数字（`06`）、中文代号（`蛙得清`）、目录名（`r06-wadeqing-analyst`）。

### 2.2 调用任意角色、任意功能

```bash
# 看角色全部子命令
python guagua.py call r06 --help

# 看某个技能组的参数
python guagua.py call r06 explore --help
python guagua.py call r06 explore funnel --help

# 执行
python guagua.py call r06 explore funnel --input workspace/_loop_clean.csv --stage status
```

规则：`call` 的第一个参数是角色，**后面的参数全部原样传给 `agent.py`**。因此：

- 角色支持 `manifest`，就能 `call r06 manifest`；
- 角色支持 `demo`，就能 `call r06 demo`；
- 角色支持 `run --task`，就能 `call r06 run --task <id>`；
- 角色以后新增任何子命令，都不需要改 `guagua.py`。

### 2.3 生成知识注入 Prompt

```bash
python guagua.py chat --role r06 --intent "分析订单漏斗与留存"
python guagua.py chat --role r03 --intent "检查这份合同的付款与责任条款" --output prompt.txt
python guagua.py chat --role r07 --intent "把这段需求整理成 PRD" --domains "prd,priority"
```

参数：

| 参数 | 说明 |
|---|---|
| `--role` | 必填，角色 ID |
| `--intent` | 必填，你的目标/问题 |
| `--domains` | 可选，限定知识域，逗号分隔 |
| `--output` | 可选，写入文件 |
| `--vector` | 可选，启用向量语义检索（需环境已配置） |

### 2.4 让 R01 拆分与执行

```bash
# 拆成任务卡
python guagua.py plan "停车场一年营收最大化"

# 查看任务依赖与状态
python guagua.py status

# 执行所有依赖就绪的任务
python guagua.py dispatch --all

# 只执行一张卡
python guagua.py dispatch --task <task_id>

# 限制本轮执行数量
python guagua.py dispatch --all --limit 3
```

### 2.5 Demo、体检、诊断

```bash
python guagua.py demo r06       # 单个角色 demo
python guagua.py demo --all     # 依次跑全部角色 demo
python guagua.py check          # 20 个 agent.py --help 体检
python guagua.py doctor         # 环境 + 入口体检（含记忆池体积）
python guagua.py gc --dry-run   # 记忆池护栏：只出报告
python guagua.py gc             # 记忆池护栏：裁快照 / 隔离超限文件
```

说明：

- `demo --all` 会逐个角色运行，部分角色会写 `workspace/artifacts/`，耗时取决于角色；
- R03 没有 `demo` 子命令，`demo --all` 会跳过并提示用专家技能；
- `check` 只验证“入口能启动”，不验证业务结果；
- `gc` 扫描全部 `rXX-*/workspace/session_state*.json`：>2 MB 裁到最近 50 条快照，
  >100 MB 整份改名隔离为 `*.oversize-<时间>.bak`（不删除、不解析），详见 `PROTOCOL.md` 第六节。

### 2.6 直接使用老入口（等价）

```bash
cd r06-wadeqing-analyst
python agent.py --help
python agent.py manifest
python agent.py demo
python agent.py semantics validate --input examples/semantic_model.json
```

统一入口不会替代老入口，只是让你少记目录。

## 7. 自检、测试与排错

### 7.1 先做全量入口体检

```bash
cd "D:\蛙蛙呱呱\蛙蛙呱呱agents团"
python guagua.py check
```

正常输出：

```text
通过 20/20
全部角色入口可用。
```

如果某个角色失败，先看错误摘要，再进入该角色目录执行：

```bash
cd rXX-*/
python agent.py --help
```

### 7.2 单角色测试

```bash
cd r06-wadeqing-analyst
python run_tests.py
python verify_loop.py
```

不同角色测试入口不完全一样：有的叫 `run_tests.py`，有的还有 `verify_loop.py`、`tests/`。先看目录里有什么，不要假设统一。

### 7.3 常见问题

#### 问题 1：`ModuleNotFoundError: No module named 'core'`

原因：没有在 `蛙蛙呱呱agents团` 目录下执行，或 `PYTHONPATH` 不对。

```bash
cd "D:\蛙蛙呱呱\蛙蛙呱呱agents团"
$env:PYTHONPATH = (Get-Location).Path
python guagua.py check
```

#### 问题 2：`FileNotFoundError: examples/...`

原因：`--input` 是相对路径，角色默认相对自己的目录解析。

```bash
# 推荐：用统一入口，它会在角色目录执行
python guagua.py call r06 semantics validate --input examples/semantic_model.json

# 或者先进入角色目录
cd r06-wadeqing-analyst
python agent.py semantics validate --input examples/semantic_model.json
```

#### 问题 3：`ok=false`，但程序没崩

这不是崩溃，是门禁在工作。看返回 JSON 里的 `checks`、`next`，通常是：

- 输入数据缺列 / 有脏数据；
- 指标口径不完整；
- 缺少验收判据；
- 财务/合同/隐私红线被触发。

#### 问题 4：中文乱码

在 PowerShell 中先设置：

```powershell
$env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
```

`guagua.py` 自身也会设置 UTF-8 环境。

#### 问题 5：`demo --all` 很慢或部分角色跳过

- R03 没有 `demo`，会被跳过；
- 部分 demo 会写文件、跑计算，耗时较长；
- 只想验证入口是否可用，用 `python guagua.py check`，不要用 `demo --all`。

### 7.4 查看某个角色的完整参数

```bash
python guagua.py call rXX --help
python guagua.py call rXX <技能组> --help
python guagua.py call rXX <技能组> <动作> --help
```

这是最可靠的“全部功能”查询方式，不依赖文档是否及时更新。

## 8. 能力边界与安全约定

1. **本地确定性 ≠ 线上已执行**
   角色可以校验契约、生成工件、跑本地计算；但外部发布、支付、部署、真实 CRM/ERP 写入未接入时，会标为 `simulated` 或 `blocked`，不会假装成功。

2. **R03 是专家技能入口，不是任务卡入口**
   R03 蛙守线没有 `run --task` 子命令，使用 `python guagua.py call r03 ...` 直接调用；其余 19 个角色支持任务卡入口。

3. **不可逆动作必须人工授权**
   裁员、关停、签约、付款、删除快照、灾难切换、生产恢复等，任何角色都不能自动执行。

4. **质量结论只归 R04**
   其他角色可以自检，但不能给自己签 `pass`；`reviewer == producer` 直接 FAIL。

5. **不要把敏感信息写进工件**
   真实密钥、身份证、银行卡、生产凭据不要写入 `--input` 文件；R03/R16/R20 有相应红线检查，但第一道防线是你。

6. **先小后大**
   先跑 `check` 和单角色 demo，再跑 `plan` / `dispatch --all`。涉及资金、合同、生产环境的任务，先在副本或测试环境验证。
