## 一、SQL「精通」的真实标准

### 1.1 大厂面试考什么（挂人最多的点）

大厂SQL面试用**递进式出题**：先简单热身 → 中等难度 → 困难压轴。90%的题目要在10分钟内写出。

| 难度 | 考察内容 | 典型题目 | 通过率 |
|------|---------|---------|--------|
| 简单 | WHERE/GROUP BY/ORDER BY/LIMIT | 基础聚合统计 | ~80% |
| 中等 | 窗口函数 + 多表JOIN + 自关联 | 留存率/TopN/行列转换 | ~40% |
| 困难 | 递归CTE + 复杂session + 多层嵌套 | 连续登录最大天数/用户session划分 | ~18% |

### 1.2 SQL能力金字塔

```
L5: SQL架构能力
  数据仓库设计、ETL流程设计、数据质量治理、指标口径定义
  考察方式：系统设计面 → "10亿行日志表，设计一个日活统计方案"

L4: SQL优化能力
  EXPLAIN解读、索引策略、反模式识别(SELECT */隐式转换/深分页)
  数据倾斜诊断与解决(加盐/MAPJOIN/两阶段聚合)
  考察方式：给你一个慢查询 → 优化前后性能对比

L3: SQL复杂查询能力 (面试主力层)
  窗口函数全系(ROW_NUMBER/RANK/LAG/LEAD/SUM OVER)
  留存分析(次日/7日/30日)、漏斗分析(多步转化)
  Gap-and-Island(连续登录)、复购率、中位数计算
  考察方式：手写SQL + 讲解思路 + 追问边界情况

L2: SQL基础查询能力
  SELECT/JOIN(5种)/GROUP BY/HAVING/子查询/CTE
  聚合函数/条件聚合(CASE WHEN)/日期处理
  考察方式：入职后的日常取数能力

L1: SQL入门
  SELECT/FROM/WHERE/ORDER BY/LIMIT
  考察方式：笔试第一题
```

**大厂"精通"的分界线在L3-L4之间。** L3以下=不及格，L3=合格，L4=加分。

### 1.3 各厂偏爱

| 公司 | 偏爱考点 | 原因 |
|------|---------|------|
| 字节 | 漏斗分析、行列转换、中位数计算 | 产品迭代快，漏斗是核心指标 |
| 腾讯 | 连续登录、留存率、复杂分组聚合 | 社交/游戏产品重留存 |
| 网易 | 留存分析、用户行为路径 | 游戏分析核心能力 |
| 美团 | 多表JOIN+复杂业务逻辑 | 外卖/到店业务多维度 |
| 小红书 | 漏斗+留存+内容消费分析 | 社区+电商双业务 |

### 1.4 SQL精通的日常表现

不是"面试能写出来"，而是：

| 场景 | 及格线 | 精通线 |
|------|--------|--------|
| PM要一个数 | 30分钟内写出正确SQL | 5分钟内写出，附带验证SQL确认数据无误 |
| 数据不对 | 重跑一遍看是不是自己写错了 | 检查数据血缘，定位是ETL问题还是口径问题 |
| 慢查询 | 等它跑完 | 看EXPLAIN，加索引，改写SQL，10秒→0.5秒 |
| 新人代码review | 看不出问题 | 一眼看出SELECT *、隐式转换、深分页 |

## 二、Python「精通」的真实标准

### 2.1 大厂面试考什么

大厂Python面试不是考你背函数，是live coding——共享屏幕，给脏数据，现场清洗+分析+出图。

| 环节 | 考察内容 | 典型题目 |
|------|---------|---------|
| 笔试 | Pandas基础操作 | "用Pandas合并两个CSV并去重" |
| 技术面 | Live coding | 给一份脏数据，现场清洗→聚合→可视化 |
| 项目深挖 | 代码审查 | "GitHub上这个项目的groupby为什么用transform而不是agg？" |
| 业务场景面 | 数据分析实战 | "计算用户复购率""RFM分群""GMV归因分析" |

### 2.2 Python能力金字塔（数据分析方向）

```
L5: 数据工程能力
  构建自动化数据管道(Airflow/DolphinScheduler)
  分布式计算(PySpark/Dask)、CI/CD
  性能瓶颈定位(cProfile)、内存优化(category/Int8/Parquet)
  考察方式：系统设计 → "10GB日志处理方案"

L4: 向量化+大数据处理能力 (高级分界线)
  NumPy broadcasting/ufunc 替代for循环
  分块处理(chunksize=10**6)、大数据加速(Modin/Dask)
  数据类型优化(astype('category')内存减半)
  考察方式："这个分析跑一次要30分钟，你怎么优化？"

L3: Pandas全量应用能力 (面试主力层)
  groupby全系(agg/transform/filter/apply)
  merge(4种how+indicator+行数膨胀检测)
  pivot_table/melt/crosstab
  datetime处理(dt访问器/重采样/滚动窗口)
  字符串处理(str访问器+正则提取)
  链式调用优化(pipe/assign)
  考察方式：Live coding: 脏数据→清洗→特征工程→聚合→可视化

L2: Pandas基础操作
  read_csv/head/info/describe
  筛选(loc/iloc/布尔索引)、排序、分组聚合基础
  基础图表(matplotlib/seaborn)
  考察方式：入职后日常分析工作

L1: Python基础语法
  变量/数据类型/控制流/函数/文件IO
  考察方式：校招笔试
```

**大厂"精通Python"的分界线在L3-L4之间。** L2以下=不及格，L3=合格，L4=高级加分。

### 2.3 Python精通的日常表现

| 场景 | 及格线 | 精通线 |
|------|--------|--------|
| 分析需求 | 在Jupyter里一步步写，中间多次查文档 | 链式调用一气呵成，代码可复用 |
| 数据太大 | 采样分析 | 分块读取+迭代聚合，或用Dask加速 |
| 代码慢了 | 等它跑完 | 检查是不是for循环可以向量化，是不是类型可以优化 |
| 重复分析 | 每次重新写 | 写成函数+脚本，crontab自动跑，结果自动发邮件 |
| 新人问问题 | "查文档" | 指出对方代码里的SettingWithCopyWarning，解释为什么 |

| 数据清洗全量 | 2天 | W4周一-周二 |

## 六、总结

1. **SQL精通 = L3（窗口函数/留存/漏斗能10分钟内写出）+ L4（能优化慢查询/识别反模式）起步**
2. **Python精通 = L3（pandas全量+数据清洗+可视化独立完成）+ L4（向量化/分块/内存优化）起步**
3. **v4.0计划覆盖了L3的大部分，但缺少L4的以下内容**：向量化性能对比、分块读取、内存优化、Hive提前、Git提前、SQL持续练习
4. **建议**：上述P0/P1项融入后，v5.0计划可达到SQL L4-、Python L4-的水平，完全满足大厂3年以内数据分析师的技术要求
