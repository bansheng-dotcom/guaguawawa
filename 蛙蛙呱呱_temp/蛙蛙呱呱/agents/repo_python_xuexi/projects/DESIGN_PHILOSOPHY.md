# 项目设计哲学 — 为什么是这七个项目

> 记录这7个项目的设计思路、取舍逻辑、以及跟美团优选社区团购业务的对应关系。

---

## 一、设计原则

在动手写任何代码之前，定了三条铁律：

### 原则1: 每个项目必须能放进简历

不是"做完就忘的练习"，而是"面试官能追问30分钟的项目"。
每个项目都有：真实业务场景 → 完整分析链路 → 可展示的产出 → 面试话术。

### 原则2: 场景必须跟你的履历咬合

你的简历写的是美团优选社区团购。
如果项目场景是"电商推荐"、"金融风控"——面试官追问"你们团购业务跟电商有什么不同？"你会卡住。
所以每个项目都锚定在社区团购的具体业务问题上：爆品选品、团长留存、履约成本、生鲜损耗、优惠券。

### 原则3: 从基础到进阶，不能跳级

统计→SQL→指标体系→ML→生存分析→时间序列→因果推断。
这个顺序是故意的：后面项目需要前面项目的基础知识。
A/B实验的假设检验是因果推断的前提；SQL的窗口函数是RFM和留存的前提。

## 二、七个项目的设计逻辑

### 项目一: A/B实验设计（为什么第一个？）

**面试高频排名第一。** "你们怎么做A/B测试的？"几乎是数据分析师面试的必考题。

但这个项目的真正价值不是"教会你t检验"——是让你理解**"用数据做决策"的完整框架**：
- 决策前：用什么指标评判？（指标体系思维 → 衔接项目三）
- 决策中：怎么判断"显著"？（假设检验 → 衔接项目四的模型评估）
- 决策后：对所有用户都有效吗？（辛普森悖论 → 分策略思维）

**设计的难点：** 辛普森悖论的场景怎么选？你的社区团购经验里，最自然的混淆变量是"城市等级"——一线城市和三五线城市的供给结构、用户画像、团长密度完全不同。这个设计同时让你能讲"我在美团优选发现低线城市数据稀疏/供给不稳定导致算法失效"——跟你简历的供给重构经验直接咬合。

**为什么不是电商场景？** 电商的辛普森悖论通常选Mobile vs Desktop，跟你履历无关。城市等级×推荐策略的交互，面试官追问任何细节你都能用真实业务逻辑回答。

---

### 项目二: SQL复杂查询（为什么第二个？）

**数据分析师80%的时间在写SQL。** 面试手撕SQL题是硬门槛——窗口函数、留存计算、漏斗分析必须闭眼写。

**设计的核心决策：** 不用现成数据集（Kaggle的Olist），自己生成数据。原因：
1. 现成数据集的表结构跟社区团购对不上——没有团长表、没有履约表、没有行为日志
2. 生成数据的过程中，你被迫理解"每条记录代表什么业务动作"——这是数据敏感度的训练

**漏斗为什么是"分享→点击→加购→下单→自提"而不是电商的"首页→商品页→购物车→支付"？**
因为社区团购的起点是"团长分享"而不是"用户打开APP"。这个漏斗同时训练了两个能力：SQL窗口函数 + 对社区团购业务链路的理解。

**RFM的阈值为什么跟电商不一样？**
电商RFM的R(recency)通常用30/60/90天，团购用了3/7/14天——因为生鲜是日消品，用户可能每天买。面试时你能解释"为什么阈值不同"本身就是加分项。

---

### 项目三: 指标体系（为什么第三个？）

**数据分析师不是取数工具人——你要能"设计指标体系"。**

前面两个项目训练的是"分析能力"（给你问题，你分析），项目三训练的是"框架能力"（你定义什么叫"问题"）。

**OSM模型的选择：** 不是拍脑袋选的——OSM是字节/美团/阿里内部通用的指标设计框架。面试官大概率用过OSM，你一提他能听懂。

**四层指标体系的设计：** 北极星/健康度/规模/效率——这四层对应了GMV公式的分解：
```
净利润 ≈ GMV × (1 - 履约成本率 - 损耗率 - 退货率)
GMV = 用户数 × 人均GMV
人均GMV = 件数 × 件单价
```

**每一层指标都可以用公式证明"我不是在堆指标，我在衡量利润公式的每个因子"。**

**异动监控的设计：** 10条规则不是随便写的——GMV/履约/损耗/团长/品类，覆盖了社区团购"人货场"的三个核心维度。每条规则都有"条件+等级+归因方向+建议动作"四要素——这是生产环境监控系统的设计模式。

---

### 项目四: ML流失预测（为什么第四个？）

**前三个项目是"分析师"的技能，项目四是"数据科学家"的起点。**

**为什么选流失预测而不是其他ML问题？**
1. 流失预测是二分类——ML入门最自然的任务
2. 社区团购的流失问题真实且重要——获客成本高，挽留比拉新便宜5倍
3. 特征工程有天然的业务解释性——recency/frequency/行为比率/团长关联，每个特征都能翻译成业务语言

**为什么强调"特征工程占了80%的工作量"？**
因为真实ML项目中，模型选LR还是RF往往不重要（AUC差2-3%），但特征构造的好坏能让AUC差10-20%。项目四故意做了30+特征、6类特征族——让你体验"特征决定了模型天花板"。

**噪声注入的设计：** 数据生成时故意加了噪声让AUC从0.999降到0.82——因为真实世界的AUC就是0.75-0.85。如果给你一个AUC=0.999的数据，你会以为ML很容易。这不是欺骗——是在模拟真实。

### 项目五: 团长LTV+生存分析（为什么第五个？）

**社区团购的独有分析视角——团长是核心资产。**

普通电商没有"团长"这个角色，所以团长的生命周期分析是你区别于纯电商分析师的核心竞争力。

**为什么引入生存分析而不是简单的"平均存活月数"？**
因为删失(censoring)——观测期内仍在活跃的团长不能被简单忽略。用K-M正确处理删失是专业性体现。

**Cox回归的变量选择：** 城市等级、团长密度、团长质量——这三个变量的业务含义：
- 城市等级=外部市场环境
- 团长密度=竞争强度
- 团长质量=个人能力
→ "个人能力比外部环境更重要"——这个结论如果面试时讲出来，证明你不仅会跑模型，还能从数据中提炼洞察。

**LTV/CAC的逻辑：** 直接连接财务——"招募一个团长花3000元，他终身价值多少？"答案直接决定BD策略。

---

### 项目六: 时间序列预测（为什么第六个？）

**从"解释过去"到"预测未来"。**

前面五个项目都是"事后分析"——已经发生的事情。项目六是"事前预测"——还没发生但需要预估。

**为什么选GMV预测？** 最通用、最直接、业务方最需要。每周一早上运营总监问"这周GMV预估多少"，你要能回答。

**ARIMA vs Prophet的对比设计：** 不是让你选一个更好的——是让你理解"不同场景用不同工具"。ARIMA适合短序列、无复杂节假日的数据；Prophet适合有节假日效应、需要可解释组件的场景。

**滚动预测的实现：** 最重要的一行代码——每次只用"到目前为止"的数据训练，避免look-ahead bias。面试时提到这个细节，面试官就知道你不是"调个包就完了"。

---

### 项目七: 因果推断（为什么第七个？）

**最难、最容易被忽视、但最能拉开差距的项目。**

90%的数据分析师不会因果推断——他们会算相关性，但不会区分"相关"和"因果"。
如果面试时你能说"我们做的优惠券效果评估不是简单对比，而是用PSM消除了选择偏差"，你直接超越了90%的竞争者。

**为什么选择偏差是因果推断的入门案例？**
运营不是随机发券——他们发给"看起来更需要"的用户。这种"非随机分配处理"在日常业务中无处不在：
- 顶配团长才给额外补贴 → 补贴效果被高估（他们本来就强）
- 高风险用户才给挽留券 → 券效果被低估（他们本来就快走了）

**PSM + DiD 两步走的设计：**
PSM解决"两组用户不一样"的问题，DiD解决"时间趋势"的问题。两个方法叠加 → 最接近随机对照实验。

**为什么没有做工具变量(IV)和断点回归(RDD)？**
这两个方法需要更强的假设和更特殊的数据。作为第一个因果推断项目，PSM+DiD够用且实用。工具变量和RDD可以作为进阶扩展。

## 四、没做的项目（以及为什么不做）

| 不做 | 原因 |
|------|------|
| 推荐系统(协同过滤) | 偏工程,跟数据分析师岗位关联弱 |
| NLP(团长聊天分析) | 需要大量真实文本数据,模拟太假 |
| 实时数据处理(Flink) | 偏数据工程,不是分析师核心技能 |
| 深度学习(LSTM预测) | 社区团购数据量级不够,用深度学习是杀鸡用牛刀 |
| 供应链优化(运筹学) | 需要OR背景,对面试帮助有限但学习成本极高 |

**七个项目覆盖了数据分析师面试的95%考点。再多不是"学不会"，而是"面试官问不到那么深"。**

## 五、如果只学3个项目

如果时间有限,优先级排序：

```
必学: 项目一(A/B实验) + 项目二(SQL)
      → 面试最高频 + 日常工作最常用

次选: 项目四(ML流失预测)
      → 拉开跟纯业务分析师的差距

进阶: 项目五(LTV) 或 项目七(因果推断)
      → 体现"深度思考"能力
```
