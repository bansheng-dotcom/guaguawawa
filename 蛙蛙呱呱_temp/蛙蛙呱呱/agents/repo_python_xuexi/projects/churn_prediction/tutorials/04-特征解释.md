# 04 特征重要性 — 什么行为最预示流失?

---

## 一、为什么运营团队需要看这个

产品经理问："你是通过什么判断用户要流失的？"

你说："AUC 0.82" → 产品经理："所以呢？"

你说："**recency(最近购买天数)是最重要的因子。用户超过20天没下单+下单趋势在下降+他的团长也不活跃了 → 大概率要流失。**"

产品经理："懂了,那我们每天给>15天没下单的用户推一条爆品push。"

**特征重要性把黑盒变成可执行的业务动作。**

---

## 二、两种方法

### 随机森林内置的特征重要性

每棵树在分裂时统计：用了特征X分裂后，分类的"纯度"(Gini)改善了多少？所有树的所有分裂累加 → 特征重要性。

**优点：** 快，内置  
**缺点：** 偏向高基数特征(如果有特别多取值的特征，会被高估)

### 逻辑回归系数

```python
recency_days: 系数=+0.06 → recency每+1天,流失log-odds增加0.06
frequency_30d: 系数=-0.10 → 每多下一单,流失log-odds减少0.10
```

**优点：** 方向+大小都有明确含义  
**缺点：** 只捕捉线性关系，看不到特征交互

### SHAP值（理想但慢）

基于博弈论——"如果把特征X从数据里拿掉，预测会变差多少？"在所有可能的特征子集上平均这个贡献。

## 三、实际输出解读

```
RF Feature Importance TOP5:
  1. recency_days         0.152   ← 遥遥领先
  2. activity_decay       0.098
  3. frequency_30d        0.072
  4. monetary_30d         0.065
  5. leader_churn_risk    0.058

LR Coefficients:
  recency_days:        +0.061  ← 每多1天没买,流失风险增加
  frequency_30d:       -0.098  ← 每多买1次,流失风险降低
  activity_decay:      +0.032  ← 活跃衰减越快,流失风险越高
  leader_churn_risk:   +0.051  ← 团长不稳=用户不稳
```

**recency在两种方法中都排第一 → 这是最稳健的发现。**

---

## 四、从特征重要性到业务动作

| 重要特征 | 业务含义 | 可执行动作 |
|---------|---------|----------|
| recency_days | 越久没买越危险 | >15天 → 自动push+优惠券 |
| frequency_30d | 买得越频繁越安全 | <2次 → 纳入"低活唤醒"计划 |
| activity_decay | 行为在冷却 | 衰减加速 → 触发"爆品推荐" |
| leader_churn_risk | 团长不稳定影响用户 | 团长异常 → 自动推荐附近其他团长 |
| wow_change | 下单趋势 | 连续2周下降 → 人工客服跟进 |
