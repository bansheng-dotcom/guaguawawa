# 社区团购「今日爆品」推荐策略 A/B实验

## 业务背景

美团优选首页的「今日爆品」坑位（每日6-8个SKU），是社区团购最高频的流量入口，
目前由**各城市运营团队手动选品**。

争议焦点：
- **运营侧**："我知道本地人爱吃什么、今天本地能拿到什么货，算法懂个屁"
- **算法侧**："用户历史行为 + 社区画像 + 履约成本数据，能比人挑得更准"

本实验模拟对"城市运营手动选品(Control)"与"算法个性化推荐(Treatment)"
进行完整A/B测试，评估算法是否在**不恶化履约成本与损耗率**的前提下
提升人均GMV和人均件数。

## 实验设计

| 参数 | 设定 |
|------|------|
| 对照组 | 城市运营手动选品(当前线上方案) |
| 实验组 | 算法个性化推荐(每人6-8个不同SKU) |
| 分流比例 | 1:1 |
| 实验周期 | ≥14天(覆盖两个完整周,消除周末囤货效应) |

## 指标体系

| 层级 | 指标 | 说明 |
|------|------|------|
| 🎯 北极星 | 人均GMV | 综合衡量推荐效果与变现能力 |
| 🎯 北极星 | 人均件数 | 社区团购核心——用户一次买几件 |
| 🛡 护栏 | 履约成本率 | 命门——推了远距离供应商的品,履约成本会爆 |
| 🛡 护栏 | 生鲜损耗率 | 推了高损耗品但次日卖不完,直接烂掉 |
| 🛡 护栏 | 退货率 | 算法瞎推不合适的品,退货率会涨 |
| 📊 探索 | 爆品贡献占比 | 这6-8个坑位贡献了当日GMV的% |
| 📊 探索 | 首单转化率 | 新用户首次下单比例(增长放缓背景下很关键) |

## 辛普森悖论场景

```
整体: 算法组 GMV 比运营组高 ~+4%

分城市等级:
  一线/新一线: 算法组 +7~8%   → 算法优势明显
  三五线城市:  算法组 -2~3%   → 运营反而更强
```

根源：低线城市用户购买数据稀疏(团长代下单普遍)、供给不稳定(算法
推的品当地网格仓不一定有货)、团长密度低导致履约路径长——算法
如果在推荐时忽略这些约束,效果反而不如熟悉本地情况的城市运营。

