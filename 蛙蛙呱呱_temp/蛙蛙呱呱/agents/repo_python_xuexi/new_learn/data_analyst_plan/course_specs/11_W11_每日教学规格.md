## W11D1：因果推断全景 + Rubin潜在结果框架

### 能力簇
**建立因果推断的思维框架** —— 理解"相关≠因果"的根本原因（混杂/对撞/中介），掌握Rubin潜在结果框架（因果推断的通用语言），构建"不能做AB时该用什么方法"的决策树。入职后PM给你一份观察性数据问"这个策略有效吗"——你能判断"能不能分析、用什么方法、结论有多可靠"。

### 为什么今天重要
你入职后大部分分析问题不是AB实验——策略已经全量上线了、活动已经做完了、竞品出了新功能——这些都不可能做AB。但你仍然需要回答"有效吗、如果有效有多大"。今天建立因果推断的三个核心概念（混杂/对撞/中介）→它们是所有因果推断方法的共同基础。理解这些=你能判断"这个数据能得因果结论吗"，而不是拿来数据就跑回归。

### 具体知识清单

**1. "相关≠因果"的三个根本原因——每一种都可能导致完全错误的结论**

**1.1 混杂因子（Confounder）——最常见的因果陷阱**
- 定义：一个变量Z同时影响X（策略/原因）和Y（结果），导致X和Y看起来"相关"，但实际没有因果
- 经典例子：冰激凌销量和溺水死亡正相关（r=0.8）→"冰激凌导致溺水"?→不！夏天（混杂）→更多人吃冰激凌+更多人游泳→冰激凌和溺水"同步涨"。如果控制夏天→冰激凌和溺水不再相关
- **因果推断的核心任务**：识别和控制混杂因子。如果所有混杂因子都被控制了→X和Y的"剩余关联"就是因果效应
- Python模拟——亲眼看到"控制混杂前后结论反转"：
  ```python
  # 构造数据：夏天(Z)→冰激凌销量(X)+溺水死亡(Y)。X和Y本身无因果
  np.random.seed(42)
  season = np.random.binomial(1, 0.5, 10000)  # 0=冬天,1=夏天
  X = 100 + 50*season + np.random.normal(0, 10, 10000)  # 冰激凌：夏天多
  Y = 5 + 3*season + np.random.normal(0, 2, 10000)      # 溺水：夏天多（X无影响）
  # 不控制季节：X和Y强相关(r≈0.7)→"冰激凌导致溺水！"
  # 控制季节（只看夏天的子集或回归中加入season）：X和Y不再相关(r≈0)→正确
  ```
- 混杂因子和AB实验的关系：随机化为什么能得因果结论→随机化"切断"了所有混杂因子和X的关系（X=随机分配→不受任何因素影响→没有混杂因子）

**1.2 对撞因子（Collider）——控制错了反而引入虚假关联**
- 定义：一个变量Z同时被X和Y影响。**控制Z（如在回归中加入Z或只分析Z=某值的数据）→反而引入X和Y之间的虚假关联**
- 经典例子：一部电影只有"评分高"或"票房高"才会被你看→你看的电影里"评分和票房负相关"→不是因为评分高导致票房低→而是因为你只看"至少有一个好的"电影。控制"你看过的电影"→引入虚假负相关
- 为什么重要：数据分析中频繁做"只分析某类用户"→可能就是对一个对撞因子的conditioning→引入虚假关联→得出错误结论
- **怎么识别对撞**：X→Z←Y（箭头指向Z）→Z是对撞。**不能控制对撞！** X←Z→Y（箭头从Z发出）→Z是混杂→必须控制Z。X→Z→Y（Z在中间）→Z是中介→控制Z会"阻断"因果路径（见下一节）

**1.3 中介（Mediator）——因果路径上的中间变量**
- 定义：X通过Z影响Y。控制Z→X对Y的效应被"阻断"→你会低估（甚至完全消除）X的真实效果
- 经典例子：教育(X)通过提高技能(Z)来提高收入(Y)。如果控制技能→教育和收入的关联消失→你会错误地认为"教育不能提升收入"。实际上教育通过技能在起作用——控制技能=把因果路径切断了
- **什么时候该控制中介**：如果你想知道"X对Y的**直接效应**（不经过Z的路径）"→控制Z。如果你想知道"X对Y的**总效应**（经过Z+不经过Z的所有路径）"→不控制Z
- **在数据分析中**：如果你控制了"中间行为指标"→可能低估策略的总效果。如新推荐算法(X)→增加阅读时长(Z)→提升用户留存(Y)。如果控制阅读时长→你会低估推荐算法对留存的总效果（因为"阅读时长增长"本身就是算法起作用的一部分）

**1.4 DAG（有向无环图）——画图辅助判断**
- 画法：每个变量一个节点→箭头表示因果方向→检查"X到Y的路径上有没有混杂/对撞/中介"
- 用DAG判断"该控制哪些变量"：①列出所有可能路径②判断每条路径是否被"阻断"③确定控制哪些变量能让"非因果路径"被阻断→只留下因果路径
- **入职场景**：PM让你分析"新用户引导流程是否提升了留存"→你画DAG：引导流程(X)→使用时长(Z)→留存(Y)。但"用户兴趣"(W)→同时影响引导完成(X)和使用时长(Z)→W是混杂因子→必须控制（如加入用户注册时填的兴趣标签作为控制变量）。"引导完成后的首次阅读时长"(Z)是中介→不控制（否则低估引导的总效果）

**2. Rubin潜在结果框架——因果推断的通用语言**

**2.1 基本概念**
- 对每个个体i：Y_i(1)=如果接受处理的结果。Y_i(0)=如果不接受处理的结果。我们永远只能观测到其中一个→另一个是"反事实"（counterfactual）
- **因果推断的根本难题**：你永远看不到同一个用户"同时接受处理和不接受处理"→不能直接算个体因果效应τ_i=Y_i(1)-Y_i(0)
- **所有因果推断方法的本质**：在群体层面估计平均因果效应ATE=E[Y(1)]-E[Y(0)]。不同方法的区别=怎么构造"可比的对照组"来估计E[Y(0)]（处理组如果不接受处理的结果）
- AB实验：随机化保证处理组和对照组"统计等价"→对照组直接用作E[Y(0)]的估计。DID：用"实验前后的变化"和"对照组的变化"的差值。PSM：匹配"在处理组和对照组中特征相似的人"来构造可比的子群体。RDD：用"断点附近的人"来模拟随机实验

**2.2 因果效应衡量**
- ATE（Average Treatment Effect）=E[Y(1)-Y(0)]：对所有用户的平均因果效应
- ATT（Average Treatment Effect on the Treated）=E[Y(1)-Y(0)|T=1]：对**实际接受了处理**的用户的因果效应。PSM通常估计ATT
- ATU（Average Treatment Effect on the Untreated）=E[Y(1)-Y(0)|T=0]：对**未接受处理**的用户的因果效应
- **入职场景**：会员体系改版评估→ATT=对于"实际注册了新会员"的用户，新体系提升了多少消费。ATE=如果所有用户都改版，平均提升多少。通常先汇报ATT（更直接），再讨论ATE

**3. 🔥因果推断方法决策树——入职后最重要的选择框架**
```
能做AB实验吗？→能→做AB实验（黄金标准,结果最可靠）
↓ 不能（已全量/历史决策/策略类）
有"实验前后+实验对照"的数据吗？→有→DID（双重差分）
↓ 没有
能匹配到"和实验组特征相似"的对照组个体吗？→能→PSM（倾向得分匹配）
↓ 不能
有明确的断点（如分数线/评分阈值）吗？→有→RDD（断点回归）
↓ 没有
能找到"影响X但不直接影响Y"的工具变量吗？→能→IV（工具变量）
↓ 不能
有多个控制地区/产品可供合成"虚拟实验组"吗？→能→SCM（合成控制法）
```

### 必须覆盖的陷阱
1. **控制对撞因子引入虚假关联**：数据分析中频繁"只看某类用户"→可能是在condition on对撞→得到虚假负/正相关
2. **控制中介低估总效应**：如果策略通过中间行为起作用→控制中间行为=切断了因果路径→低估真实效果
3. **不可观测的混杂无法控制**：DAG上有些混杂因子是你没有数据的（如用户心情/竞品活动）→这些混杂会威胁因果结论→需要讨论"如果存在不可观测混杂→结论有多可靠"
4. **相关≠因果≠"不能分析"**：因果推断方法的存在就是为了处理相关≠因果的问题→关键是用对方法+承认局限

## W11D2：双重差分法(DID)——原理+手算+实操

### 能力簇
**当策略已经全量上线但有"实验前后+对照组"数据时** —— DID是互联网最常用的因果推断方法。入职后leader说"这个功能3月全面上线了,没做AB,帮我看看效果怎么样"——你如果能找到"没上线时段的同一人群"或"没上线的相似产品"做对照组→DID就是你的武器。

### 为什么今天重要
DID是大厂数据分析师最常用的因果推断方法（仅次于AB实验）。补贴/策略/功能→经常是全量上线或逐步扩大→没有标准的AB实验数据→但有"上线前后"数据和"没上线期间/没上线产品的数据"→DID就能派上用场。今天学会2×2手算DID（理解本质）→Python实现→平行趋势检验→安慰剂检验→写DID分析报告。

### 具体知识清单

**1. DID的核心思想——用"双重差分"消去两种混淆**
- 为什么不能只看"上线前后的差异"：前后对比=时间趋势+策略效果。可能恰好在涨→高估
- 为什么不能只看"和对照组的差异"：组间差异=策略效果+组间固有差异。两组本来就不同→不能比
- DID怎么做：**实验组前后变化-对照组前后变化=策略效果**。公式：DID=(Y_treat,after-Y_treat,before)-(Y_control,after-Y_control,before)
- 消去了什么：`-对照组前后变化`→消去了时间趋势（两组都有的"随时间自然变化"）。`实验组-对照组`→消去了组间固有差异。最后剩下=策略效果
- **DID的直觉**：对照组告诉我们"如果没有策略，趋势应该是怎样的"。实验组的实际变化-对照组告诉我们的"应当有的变化"=策略带来的额外变化

**2. 🔥2×2手算DID——动手算一遍,彻底理解**
- 构造一个例子：某城市2025年3月上线补贴→你是该城市（实验组），隔壁城市没上线（对照组）
  | | 上线前(2月) | 上线后(4月) | 前后变化 |
  |---|---|---|---|
  | 实验城市 | 完单量=1000 | 完单量=1300 | +300 |
  | 对照城市 | 完单量=800 | 完单量=900 | +100 |
- DID=+300-(+100)=+200→补贴的真实效果=200（不是表面的300!）
- **如果不用DID会怎样**：如果只看实验城市前后变化→+300→高估（其中100是自然趋势）。如果只看实验vs对照（某个时点）→差别200但混了组间差异→无法归因。DID消去了两者→得到+200
- Python手算：
  ```python
  # 2×2 DID 手算
  treat_before, treat_after = 1000, 1300
  control_before, control_after = 800, 900
  did = (treat_after - treat_before) - (control_after - control_before)
  print(f"DID估计={did}")  # 200
  ```

**3. 🔥平行趋势假设——DID的生命线**
- **平行趋势假设**：如果没有策略，实验组和对照组的趋势会平行→即"实验组的变化-对照组的变化"只会是策略造成的。这是DID最重要的假设
- **怎么验证平行趋势**：画"实验前"两组的时间序列→如果两组在策略前的变化趋势是平行的→平行趋势成立。如果实验前两组趋势就不同→DID不可靠
- Python实现：
  ```python
  # 画策略前两组的趋势→目测是否平行
  fig, ax = plt.subplots()
  ax.plot(treat_pre_trend, label='实验组', marker='o')
  ax.plot(control_pre_trend, label='对照组', marker='s')
  ax.axvline(x=policy_date, color='red', linestyle='--', label='策略上线')
  ax.legend()
  # 如果上线前两条线基本平行→平行趋势成立→DID可信
  ```
- **平行趋势不成立怎么办**：①加控制变量（控制那些"让趋势不平行"的因素,如城市GDP/人口）②改用"合成控制法SCM"(W11D5)来构造更"像"的对照组③承认DID不适合→换方法
- **入职场景**：你评估"某城市上线补贴的效果"→画实验前趋势图→发现实验城市在策略前3个月已经在涨了（趋势比对照城市陡）→平行趋势可能不成立→DID会高估效果→你报告里标明"平行趋势假设可能不成立→DID估计可能上偏→额外用PSM做敏感性分析"

**4. 安慰剂检验——验证DID结果的稳健性**
- **时间安慰剂**：假设策略在"实际时间之前"就发生了→用假时间做DID→如果假DID=0→好（说明没有"预期的效果"提前显现）。如果假DID≠0→可能不存在策略效果,或策略有"预期效应"（如人们知道补贴要来→提前改变行为）
- **组别安慰剂**：随机交换"谁是实验组、谁是对照组"→重新算DID→如果大部分假DID接近0→好。如果有正有负→DID结果不够稳健
- Python实现：
  ```python
  # 时间安慰剂：假设策略在3个月前发生
  placebo_did = did_estimate(data, fake_policy_date='2025-01-01')
  # 如果placebo_did≈0→good。如果placebo_did≠0→policy effect可能不是真实的
  ```

**5. 多期DID（Staggered DID）——策略在不同时间对不同组生效**
- 问题：不是所有城市同一天上线补贴→不同城市在不同时间加入→传统的"2×2 DID"不够用
- Staggered DID的陷阱（最近学术界热点）：**如果不同组在不同时间接受处理→简单的"两期DID的加权平均"可能产生负权重→估计有偏**。需要特殊的估计方法（Callaway & Sant'Anna或Sun & Abraham方法）
- 如果你遇到"不同时间上线"的场景→用专门的Staggered DID方法→不要简单加权平均!
- **入职场景**：补贴从1月到12月逐步扩大到全国→不同城市在不同月份加入→你评估"补贴的长期效果"→不能用简单2×2 DID→用staggered DID→报告里注明"使用了Callaway & Sant'Anna(2021)方法处理不同时间加入"

**6. DID分析的完整报告要素**
1. 背景（为什么不能做AB/策略是什么/为什么选这几个城市做实验组和对照组）
2. 平行趋势检验（画实验前趋势图+判断）
3. DID回归结果（DID估计值+p值+置信区间）
4. 安慰剂检验（时间安慰剂+组别安慰剂）
5. 稳健性检验（控制变量/换对照组/换时间窗口→结果是否稳定）
6. 局限（平行趋势可能不成立/对照组可能有溢出效应/不可观测的混杂）
7. 结论与建议

1. **平行趋势假设不可验证（只能验证"策略前"是否平行）**：策略前平行≠策略后平行。如果策略后发生了"对照组独有的冲击"（如对照城市竞品进入）→DID有偏。要讨论"策略后可能存在的不平行"
2. **溢出效应**：如果实验组的策略"溢出"到对照组（如实验城市补贴→对照城市用户跨城打车→对照城市也被间影响）→DID低估真实效果
3. **Staggered DID不能用简单的2×2平均**：不同时间接受处理的组→简单的DID加权平均可能产生负权重→估计有偏→用专门的Staggered DID方法
4. **DID估计的是"处理组的处理效应"（ATT）**：不是ATE。如果"先上线的城市"和"后上线的城市"不同→ATT≠ATE→结论不能直接推广到全国

## W11D3：倾向得分匹配(PSM)——原理+实操+局限

### 能力簇
**当用户自己选择是否接受处理时** —— PSM在"非随机数据"中构造"可比的对照组"。入职后leader说"会员体系是用户自己选择加入的,没法做AB——帮我评估加入会员后消费有没有提升"→你用PSM给每个会员找一个"没加入但特征相似"的用户→对比他们的消费差异→估计"加入会员的因果效应"。

### 为什么今天重要
互联网产品中大量策略是用户"自选"的：加入会员、关注作者、参与活动、领取优惠券。自选=选择偏差(self-selection bias)→选择加入的用户本来就"更活跃/更有意愿"→不能直接和"没加入的"比。PSM解决的就是这个问题：在"没加入"的用户中，找到那些"特征上和加入了的人很像"的用户→把这些"匹配到的对照组"和"加入了的人"对比→消除了可观测的选择偏差。

### 具体知识清单

**1. PSM的核心思想——在非随机数据中构造"可比"的对照组**
- 问题：用户自己选择加入会员→加入的人本来就对产品更忠诚→他们消费更高→不能简单说"加入会员提升了消费"（可能他们不加入会员也会消费得更高）
- PSM怎么做：
  1. 用Logit回归估计每个用户"加入会员的概率"（倾向得分P-Score），基于可观测特征（历史消费/活跃度/注册天数/城市/...）
  2. 给每个"加入了会员"的用户，在"没加入"的用户中找一个P-Score最接近的人→配对
  3. 对比配对后的两组→差异=因果效应（在可观测特征上的选择偏差被"匹配"消除了）
- **PSM只能消除"可观测的"选择偏差**：如果选择基于"不可观测的因素"（如用户的内在动机→没数据）→PSM无法消除这种偏差→结论可能有偏

**2. 🔥PSM的完整实现步骤——Python实操**
```python
from sklearn.linear_model import LogisticRegression
# Step1: 估计倾向得分
ps_model = LogisticRegression()
ps_model.fit(df[['历史消费','活跃天数','注册天数','城市等级','年龄']], df['member'])
df['pscore'] = ps_model.predict_proba(df[...])[:, 1]

# Step2: 匹配（近邻匹配）
from sklearn.neighbors import NearestNeighbors
treat = df[df['member']==1]
control = df[df['member']==0]
nn = NearestNeighbors(n_neighbors=1, metric='euclidean')
nn.fit(control[['pscore']])
distances, indices = nn.kneighbors(treat[['pscore']])
matched_control = control.iloc[indices.flatten()]

# Step3: 平衡性检验——检查匹配后两组在特征上是否"变得相似"了
# 计算每个特征的SMD(标准化均值差)=|mean_treat-mean_control|/pooled_std
# SMD<0.1→匹配后两组平衡→好
# SMD>0.2→匹配后仍有差异→该特征未被充分匹配→PSM可能不可靠

# Step4: 计算ATT
att = treat['消费'].mean() - matched_control['消费'].mean()
```

**3. 匹配算法的选择——不同场景下用不同算法**
- **近邻匹配（KNN,最常用）**：给每个处理组用户找k个P-Score最接近的对照组用户。k=1→最精确但方差大。k=5→方差小但可能引入一些不完美的匹配
- **卡尺匹配（Caliper）**：只匹配P-Score差距<阈值的配对。超出阈值的处理组用户"找不到匹配"→被排除。threshold=0.2×std(pscore)→常用
- **核匹配（Kernel）**：用所有对照组用户的加权平均（权重=P-Score距离）。不丢弃任何数据→但可能引入不太像的对照组用户
- **半径匹配（Radius）**：和卡尺类似但阈值更严格
- **选择建议**：近邻+卡尺组合→k=1,caliper=0.2→既匹配最像的人,又不匹配不像的人（超出卡尺的找不到匹配→说明"处理组和对照组在某些区域没有可比的人"→PSM在这个区域的估计不可靠）

**4. 平衡性检验——PSM结果可信吗？**
- **匹配前**：两组在所有特征上差异显著（p<0.05,SMD>0.5）→选择偏差严重
- **匹配后**：两组在所有特征上的**SMD应该<0.1**（最好是0.05以下）→匹配消除了可观测的选择偏差
- 如果匹配后某个特征SMD仍然>0.2→匹配对这个特征不够好→PSM结果对这个特征敏感→需要改进（换算法/加控制变量/考虑分层PSM）
- **为什么要做平衡性检验**：如果匹配后两组"看起来不像"→你构造的对照组不靠谱→PSM结论不靠谱

**5. PSM的致命局限——不可观测的选择偏差**
- PSM假设：所有影响"是否选择处理"的变量都被观测到了（可忽略性假设,Ignorability）。**如果存在不可观测的变量影响选择→PSM结论有偏**
- 例子：用户"加入会员"的倾向受"消费意愿"影响→这个变量没有直接数据→无法加入PSM。如果"消费意愿高"的人既更可能加入会员、也更可能高消费→PSM会高估会员的效果（因为匹配时没有控制"消费意愿"）
- **敏感性分析（Rosenbaum Bounds）**：检验"如果存在不可观测的选择偏差→大到什么程度→PSM结论会被推翻"。如果即使很小的不可观测偏差也能推翻→PSM结论不稳健
- **入职场景**：你用PSM评估会员效果→估计ATT=+15%。leader追问："如果"消费意愿"这个不能观测的变量→同时影响加入会员和消费→你的估计会怎么偏？"→你回答："如果消费意愿高的人更可能加入会员→PSM会高估→真实效果可能<15%。敏感性分析显示：如果不可观测因素让"加入会员"的几率提高20%→PSM估计可能偏高约5pp→实际效果可能只有+10%"→leader觉得你考虑周全

**6. 什么时候PSM够用、什么时候不够**
- PSM够用：①选择主要基于可观测特征（如会员资格基于历史消费/活跃度）②你有很多丰富的用户特征数据③不可观测因素可能影响不大
- PSM不够：①选择基于强烈的主观意愿（如"我是否对这个产品有信心"→不可观测）②你只有很少的协变量③缺乏关键的"选择决定因素"数据
- **面试/工作判断标准**："PSM能消除可观测的选择偏差。但如果你怀疑存在重要的不可观测选择因素→PSM结论需要附敏感性分析,并讨论'可能存在上偏/下偏'"。

2. **匹配后"找不到匹配"的处理组用户**：卡尺之外的处理组用户→PSM的ATT只适用于"能找到匹配"的用户→不是ATE
3. **PSM的ATT≠ATE**：PSM估计的是"对于处理组用户"的效果（ATT）。如果处理组和对照组用户本质上不同→ATT≠ATE→不能推到"如果所有人都加入"的效果
4. **过分依赖PSM而不解释局限**：入职后最常见的错误="做了PSM就认为得到因果结论"。必须讨论不可观测偏差+敏感性+方法局限

## W11D4：断点回归(RDD)——原理+实操

### 能力簇
**当有明确的断点（分数线/评分阈值/门槛）时** —— RDD是"最接近AB实验"的观察性因果推断方法。入职后leader说"我们给评分>4.5的商家流量倾斜,帮我评估效果"→评分4.5是一个断点→评分4.49和4.51的商家本质上没有区别→他们是"近乎随机"被分到"有倾斜"和"没倾斜"两组→你用RDD估计流量倾斜的真实效果。

### 为什么今天重要
互联网产品中大量策略基于"阈值"：评分>4.5给流量、信用分>600给额度、消费>500发券、等级>10开新功能。断点附近的人/商家/用户→在断点左右"几乎相同"（评分4.49和4.51的商家→用户对它们的评价差不多）→他们被"近乎随机"地分到了接受/不接受处理→形成一个"局部的随机实验"。RDD利用这个"局部随机性"来估计因果效应。比DID和PSM更可信（不太依赖假设）——因为断点附近的"随机性"是自然的。

### 具体知识清单

**1. RDD的核心直觉——断点附近的人"近乎随机"**
- 精确RDD（Sharp RDD）：处理概率在断点处从0跳到1。如"评分>4.5=给流量倾斜,评分≤4.5=不给"→4.51=给,4.49=不给→确定性
- 模糊RDD（Fuzzy RDD）：处理概率在断点处跳跃但不是0→1。如"评分>4.5获得流量倾斜的概率从30%跳到70%"→只是概率变化
- **为什么断点附近的人是"近乎随机"的**：评分4.49和4.51的商家→用户的满意度评价几乎一样→两者的差异可能只是因为"某个用户恰好给了4分或5分"→这个差异近乎随机→所以两个商家"是否得到流量倾斜"也近乎随机→可以对比
- **和AB实验的类比**：断点=随机分组的"分流机制"。断点附近的个体=被随机分配到"接受处理"和"不接受处理"两组的个体→所以RDD是"最接近AB实验"的观察性方法

**2. RDD的完整实现——Python实操**
```python
# Step1: 画断点图——看断点处是否有跳跃
df['running_var_centered'] = df['rating'] - 4.5  # 中心化:断点处=0
fig, ax = plt.subplots()
ax.scatter(df['running_var_centered'], df['traffic'], alpha=0.1, s=1)
ax.axvline(x=0, color='red', linestyle='--', label='断点:评分=4.5')
# 在断点两侧分别拟合局部线性回归→看断点处是否有跳跃

# Step2: 局部线性回归(Local Linear Regression)
# 只使用断点附近一定带宽内的数据（"局部"）
bandwidth = 0.3  # 只用评分4.2-4.8的商家
df_local = df[(df['running_var_centered'] >= -bandwidth) & 
              (df['running_var_centered'] <= bandwidth)]

# Step3: RDD回归
# Y = treat + running_var + treat:running_var（允许断点两侧斜率不同）
df_local['treat'] = (df_local['running_var_centered'] >= 0).astype(int)
# Y ~ treat + running_var + treat:running_var → treat系数=RDD估计(断点处的跳跃)
```

**3. 带宽选择——RDD最关键的设计决策**
- 带宽=断点附近多大的范围用来做分析。小带宽=只用离断点很近的个体（更接近"随机"但样本量小→标准误大）。大带宽=用更多数据（样本量大→标准误小但可能离断点太远→不再"可以比"）
- **偏误-方差权衡**：小带宽=小偏误(更符合"近乎随机")+大方差。大带宽=可能更大的偏误(离断点远的人不一定可比)+小方差
- 选择方法：
  - **CCT方法（Calonico, Cattaneo, Titiunik）**：数据驱动选带宽→平衡偏误和方差→目前学术界的标准方法
  - **交叉验证**：选让"预测误差"最小的带宽
  - **敏感性分析**：给不同带宽(如0.2/0.3/0.5)→看RDD估计是否随带宽变化→如果不随→RDD估计稳健。如果随→RDD估计对带宽选择敏感→不稳健
- **入职场景**：你用RDD评估效果→带宽=0.3→估计=+15%。带宽=0.1→估计=+18%。带宽=0.5→估计=+10%。估计不太稳定→说明"离断点远的人不太可比"→报告里用CCT带宽(如0.25)→估计=+16%→标注"在不同带宽下估计在+10%~+18%→方向一致→结论基本稳健"

**4. 🔥McCrary操纵检验——检测"有人操纵断点吗？"**
- 问题：如果商家知道"评分>4.5给流量"→可能刷分→评分4.5右侧（刚过4.5）的商家数量异常多→"有人操纵断点"
- McCrary检验：看"running variable"在断点处的**密度**是否连续。如果密度在断点处跳跃→有人操纵→RDD无效
- Python实现：
  ```python
  # 画断点附近的密度直方图→目测密度是否在0处跳跃
  ax.hist(df['running_var_centered'], bins=50, density=True)
  ax.axvline(x=0, color='red', linestyle='--')
  # 如果0左侧和0右侧的密度很平滑→无操纵。如果0右侧突然高→有人为"刚过线"刷分
  ```
- **入职场景**：你评估流量倾斜效果→画McCrary→发现断点右侧（4.5-4.6）的商家数量是左侧的2倍！→有人刷分→"刚过4.5的商家"可能和"刚不足4.5的商家"不同质→RDD结论可能不成立→建议："需要排除刷分嫌疑→用'刷分检测算法'清洗后再分析"

**5. RDD的局限**
- **只估计断点附近的局部效应（LATE）**：RDD估计的是"评分刚好在4.5附近的商家→得到流量倾斜的效果"。不能直接推广到"评分3.0的商家如果给流量会怎样"→他们和4.5附近的商家本质不同
- **断点附近样本量可能很小**：如果断点附近只有几十个商家→标准误太大→Power不够→检不出效果
- **模糊RDD需要工具变量**：如果断点处不是确定性处理(Sharp)→需要用模糊RDD→用"断点"作为"是否接受处理"的工具变量

1. **RDD估计的是断点附近的局部效应(LATE)，不是全局效应**：不能直接推广到"远离断点的人/商家"
2. **McCrary检验不过→有人操纵断点→RDD不成立**：如果人为"刚过线"的人/商家特别多→断点附近的近似随机性被破坏
3. **带宽选择影响估计**：太窄→噪声大。太宽→可能引入可比性差的个体→附带宽敏感性分析
4. **Sharp vs Fuzzy RDD**：不检查处理是否是"确定性"的就直接Sharp→如果实际是Fuzzy→低估效果

## W11D5：工具变量(IV) + 合成控制法(SCM) + 方法全景对比

### 能力簇
**当所有"常规"因果推断方法都不适用时** —— IV用"只影响X但不直接影响Y的第三方变量"来切断混杂。SCM用"多个控制单元合成一个虚拟实验组"。今天学会"什么情况用什么方法"的最终决策框架→面试中给任何场景都能判断"该用哪个方法+为什么+局限"。

### 为什么今天重要
IV和SCM是因果推断的"最后手段"——当DID/PSM/RDD都不适用时。IV适合"有好的工具变量"的场景（如"下雨→影响外卖配送→影响用户消费"→"下雨"影响配送但不直接决定用户想不想花钱）。SCM适合"处理单元只有一个但有很多候选对照"（如"某城市实施新政策→用多个未实施城市合成一个'虚拟该城市'"）。今天学完=你的因果推断武器库完整了。

### 具体知识清单

**1. 工具变量(IV)——用"只影响X不影响Y"的变量来切断混杂**

**1.1 IV的两个条件（缺一不可）**
- **相关性（Relevance）**：工具变量Z必须和X相关。"下雨"和"外卖送达时间"相关→✓。检验：第一阶段回归X~Z→如果Z的系数不显著→弱IV→不能用。F-stat>10→强IV→可用
- **外生性（Exogeneity/Exclusion Restriction）**：Z不直接影响Y（除了通过X这条路径）。"下雨"不直接影响"用户今天想不想花钱"→✓。"降雨量"直接影响"用户想不想出门吃饭"→如果Y=外卖消费,则"降雨量"可能同时影响X和Y→不是好的IV
- **直觉**：IV把X的变化"分解"成①由Z驱动的那部分（外生的,不受混杂影响）+②由混杂驱动的那部分（内生的,和Y的关联是假的）。只用"由Z驱动的那部分X的变化"来估计X→Y的因果效应→这部分的效应是"干净的"
- **经典案例**："距离最近大学的距离"(Z)→影响"受教育年限"(X)→影响"收入"(Y)。距离大学的远近和学生"个人的能力/动机"(混杂)无关→好的IV

**1.2 两阶段最小二乘法(2SLS)——IV的实现方法**
- 第一阶段：X~Z（用Z预测X）→得到X̂（X中"被Z解释"的部分→外生的）
- 第二阶段：Y~X̂（用"外生的X"来估计Y）→X̂的系数=IV估计的因果效应
- 为什么是"两阶段"：第一阶段"提取"X的外生部分。第二阶段用"外生的X"去估计对Y的影响→消除了混杂的干扰
- **陷阱1-弱IV**：如果Z和X的相关性弱(F<10)→X̂几乎全是噪声→第二阶段的标准误巨大→估计不可靠
- **陷阱2-外生性不可验证**：IV的外生性只能在理论上论证,不能用数据检验。"你怎么确定Z不直接影响Y?"→只能用"业务逻辑"论证→这是IV最被质疑的地方

**1.3 什么时候IV适用——"找个好的工具变量非常难"**
- IV在经济学研究中常用（如"殖民地时期的制度→影响现代制度→影响经济发展"）。在互联网数据分析中,好的IV很少见
- 可能的IV场景：①天气/自然事件（影响X但不直接影响用户需求）②系统bug/故障（影响服务但不影响用户意愿）③政策/规则变化（只影响特定群体但不影响其他群体）
- **入职场景**：外卖平台→某城市"下大雨那天"→配送时长飙升（X=配送时长）→你评估"配送时长对外卖消费的影响"→用"降雨量"作IV→"降雨量"影响配送时长（相关性✓）→"降雨量"不直接影响"用户今天想不想花钱"（外生性?——可能需要论证:下雨天用户更想点外卖→增加了需求→所以降雨可能直接影响Y→外生性存疑!）

**2. 合成控制法(SCM)——用多个控制单元合成"虚拟实验组"**

**2.1 SCM的核心思想**
- 问题：只有一个"实验城市"实施了政策→去哪找"可比的对照组"→单个控制城市可能不够（可能和实验城市本来就不同）
- SCM解法：用**多个**未实施政策的城市→加权合成一个"虚拟实验城市"→这个"虚拟城市"在政策前的各项指标和真实实验城市尽可能相似→政策后的差异=政策效果
- 直觉：没有一个城市是完美的对照→但多个城市的"加权组合"可以模拟出"如果实验城市没实施政策会怎样"
- **和DID的对比**：DID用单个对照组→SCM用多个对照组的加权平均→SCM更灵活（不需要"城市之间完全可比"假设）

**2.2 SCM的实现**
```python
# 用所有控制城市的历史数据→学习最优权重w（让合成结果在政策前和实验城市尽可能接近）
# 政策后的真实实验城市-合成虚拟城市=政策效果
```
- 选择控制城市：选在"政策前"和实验城市趋势相似的城市→排除了"政策前趋势就不一样"的城市（它们会加大合成误差）
- 权重约束：权重≥0且权重之和=1（"合成"是各控制城市的凸组合）
- 推断：把同一方法逐个应用于每个控制城市（假装它们是"实验组",实际没实施政策）→看"真正的实验城市"在所有城市中的效果排名→如果排名第1→效果显著

**2.3 SCM的局限**
- 需要长期历史数据（政策前需要足够长的时间序列来训练权重）
- 只有一个处理单元→无法估计标准误差（需要用"排列检验"来推断显著性）
- 控制城市的选择影响结果→附敏感性分析（删一个控制城市→结果是否稳定）

**3. 🔥因果推断方法全景对比——最终决策框架**

| 方法 | 适用场景 | 核心假设 | 可检验吗 | 可信度 | 什么时候用 |
|------|---------|---------|---------|--------|----------|
| AB实验 | 能随机分流 | SUTVA+随机化 | AA+SRM | ★★★★★ | 能做AB就做AB |
| DID | 有前后+对照组 | 平行趋势 | ✓(策略前趋势图) | ★★★★ | 已全量但有对照组 |
| RDD | 有明确断点 | 断点附近"局部随机" | ✓(McCrary) | ★★★★☆ | 策略基于阈值 |
| PSM | 自选但有丰富特征 | 可忽略性(所有混杂可观测) | ✓(平衡性检验SMD) | ★★★ | 可观测特征足够多 |
| SCM | 只有一个处理单元 | 合成单元在策略前拟合好 | ✓(策略前拟合) | ★★★ | 多个候选对照可合成 |
| IV | 有好的工具变量 | 相关性+外生性 | 相关性✓/外生性✗ | ★★ | 实在没办法且IV好 |

**优先级排序**：AB＞DID＞RDD＞PSM≈SCM＞IV。**能用高优先级的不用低优先级的。越低优先级→假设越多+越难验证→结论越不可靠→报告里必须讨论"方法局限"**

**4. 入职后完整因果推断分析的标准流程**
1. 判断"能做AB吗"→能→做AB。不能→继续
2. 画DAG→识别混杂/对撞/中介→确定"需要控制什么"
3. 根据数据结构选方法（用决策树）
4. 验证核心假设（平行趋势/McCrary/平衡性/外生性论证）
5. 做稳健性检验（换方法/换参数/换样本→结论是否稳定）
6. 写报告：方法论证+假设验证+估计结果+稳健性+局限+结论
7. 给PM/leader沟通：用白话解释"我们用了什么方法、为什么、结论有多可靠"

## W11D6：因果推断综合实战——两个完整场景

### 场景1：滴滴城市补贴效果评估（用DID）
某城市2025年3月上线新补贴→你评估"补贴是否提升了完单率"→对照组:4个没有补贴的相似城市→数据:2024年1月-2025年6月,月度完单率+司机量+乘客量+补贴成本
- 完整DID分析：平行趋势检验→DID回归→安慰剂检验（时间+组别）→稳健性(换对照组)→写结论
- 附加：如果平行趋势不成立→用PSM匹配"更相似的对照组子集"→对比DID vs DID+PSM的结果

### 场景2：番茄阅读新推荐算法效果评估（用PSM+RDD）
新推荐算法2025年4月全量上线（无法AB）→你评估效果。数据：用户行为（阅读时长/留存/付费）+用户特征（历史活跃度/偏好/注册天数）
- 方法1：PSM——用历史特征匹配"上线前"和"上线后"的可比用户→评估效果
- 方法2：如果算法对"高活跃用户"(活跃天数>20天)和"低活跃用户"效果不同→用"活跃天数=20天"作为断点→RDD评估"高活跃vs低活跃"的效果差异
- 写完整报告：两方法结论是否一致→如果不一致→分析原因→给出综合结论
