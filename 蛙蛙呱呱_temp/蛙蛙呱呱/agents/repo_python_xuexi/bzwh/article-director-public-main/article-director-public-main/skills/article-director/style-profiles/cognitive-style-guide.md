# 作者认知与逻辑风格指南

本文件补充 `style-guide.md`。`style-guide.md` 描述句式和语气，本文件描述作者如何理解一个问题、如何组织认知、如何把读者从 0 带到 1。

## 一、核心原则

作者真正的风格不是“口语化”四个字，而是下面这套理解路径：

1. 先找真实场景，不先背定义。
2. 先指出常见误解，再给自己的判断。
3. 先从一个小切口进入，再长出框架。
4. 先解释为什么有用，再讲概念叫什么。
5. 先给读者能感知的例子，再给抽象模型。
6. 先讲取舍和边界，再讲完整性。

写作时要模仿这条认知路径，而不是只模仿词语。

## 二、从 0 到 1 的理解路径

### 1. 入口：真实困惑

每节都应该能回答一个具体困惑：

- 新手会在哪一步理解断掉？
- 市面上的常规解释哪里没用？
- 如果按错误理解去做，会发生什么？
- 这件事在真实工作里长什么样？

不要从“X 是什么”开始，除非这个定义本身就是读者的关键障碍。

### 2. 拆解：先抓主矛盾

作者不喜欢把内容平均铺开。更接近的方式是：

- 先判断这个问题最关键的变量是什么。
- 再解释其他变量为什么暂时不是重点。
- 最后把被排除的部分放到边界条件或后续延伸里。

如果有三种方案，不要平铺三种方案。先说日常最该用哪种，再解释另外两种什么时候才值得看。

### 3. 推理：让判断过程显形

写作要展示“我为什么这么想”：

- 看到什么现象。
- 怀疑什么原因。
- 排除什么解释。
- 得到什么判断。
- 这个判断能指导什么动作。

不要直接给一套完整框架。框架要像是从具体问题里长出来的。

### 4. 解释：用人话压住术语

术语第一次出现时，要先给读者抓手：

- 先说它解决什么问题。
- 再说它在流程中的位置。
- 最后才说它的正式名称。

术语解释不能像词典，也不能像论文摘要。它要服务当前段落的判断。

### 5. 收束：给下一步而不是空总结

段落和章节结尾不要重复“因此很重要”。更适合的收束方式：

- 给一个操作判断。
- 给一个检查问题。
- 给一个边界条件。
- 自然引出下一节为什么必须出现。

## 三、作者常用逻辑动作

| 逻辑动作 | 写法要求 | 避免 |
| --- | --- | --- |
| 纠正常见误解 | 先说误解，再说为什么错，再给正确看法 | 只说“很多人误解”但不指出误解内容 |
| 从业务场景进入 | 让读者看到真实工作里的问题 | 用抽象概念替代场景 |
| 建立分析顺序 | 说明为什么先看 A 再看 B | 一上来列完整目录 |
| 做取舍 | 明确当前文章不解决什么 | 为完整性补无关背景 |
| 给判断 | 直接说哪个方案更现实 | 永远“视情况而定” |
| 桥接术语 | 先解释用途，再出现术语 | 堆定义 |

## 四、写作节点必须遵守

写每一节时，先在内部完成这 5 个问题，再输出正文：

1. 这一节的真实困惑是什么？
2. 读者最可能的错误理解是什么？
3. 作者会先看哪个变量？为什么？
4. 这节最重要的取舍是什么？
5. 结尾要把读者推向哪个下一步？

输出正文时不要把这 5 个问题写成标签，但段落逻辑必须能看出来。

## 五、修订节点必须检查

修订时不要只改词。优先检查：

- 有没有从真实问题开始。
- 有没有解释判断怎么得出。
- 有没有作者自己的优先级和取舍。
- 有没有把术语放回人的理解路径里。
- 有没有把“完整但没用”的段落删掉或压缩。

如果一段话只是顺，但没有上述认知动作，应当重写为“问题 -> 判断 -> 原因 -> 例子/边界 -> 下一步”的结构。
