# 渭河文风 Profile

## 定义

渭河文风是一种“业务分析报告思维的教学化表达”。它不追求漂亮总结，而是把一个问题从真实场景里拆开，让读者看到作者如何判断、如何取舍、如何验证、如何落到业务动作。

适用内容：

- 数据分析报告。
- 经营分析、业务复盘、周报月报。
- 知识科普中的业务方法论讲解。
- 面向分析师、业务同学、管理者的经验型文章。

不适用内容：

- 纯营销文案。
- 只需要情绪感染的短内容。
- 不需要业务判断的百科定义。
- 学术论文式证明。

## 1. 结论生成机制

### 1.1 从真实问题进入

渭河文风的结论通常不是从定义或模型推出，而是从一个真实业务困惑进入：

- 指标为什么变了。
- 目标为什么完不成。
- 业务为什么焦虑。
- 策略为什么没效果。
- 初学者为什么会误判。

写作要求：开头先让读者知道“这个问题为什么在真实工作中会出现”，再进入分析。

### 1.2 先排除表层答案

常见结构是先指出一个看似正确但不够用的理解：

- 只按公式拆。
- 只看相关性。
- 只上模型。
- 只展示指标。
- 只给泛泛建议。

写作要求：不要直接给答案，先告诉读者“为什么常规答案不够”。

### 1.3 用可干预性筛选结论

渭河文风重视“能不能推动业务动作”。一个因素能解释现象，不代表它应该成为报告重点。

写作要求：每个核心结论都要判断：

- 它只是解释变量，还是行动变量。
- 它能不能被业务改变。
- 它是否值得进入看板、专项、复盘或资源配置。

### 1.4 结论通常是阶段性的

作者不会假装一次性看穿全部问题。常见结论是：

- 当前只能判断到这里。
- 这个判断需要继续下钻。
- 验证和继续拆解要同步。
- 下一步要看某个指标或场景。

写作要求：结论不要写成万能闭环，要保留真实分析的过程感。

## 2. 论述组织机制

### 2.1 开篇偏好

常见开篇顺序：

```text
系列/背景
-> 真实工作场景
-> 读者可能的误解
-> 本文要解决的问题
```

开篇不追求“金句”，而是先搭建读者的业务处境。

### 2.2 中段推进

常见推进顺序：

```text
抛出问题
-> 常规拆法
-> 说明不够
-> 换一个业务视角
-> 指标拆一层
-> 横向观察场景变量
-> 得到阶段性判断
-> 继续往下一层
```

注意：它不是树状大纲，而是台阶式推进。每往下一层，都要停下来解释这一层对应什么业务场景。

### 2.3 结尾收束

结尾通常不只是复述观点，而是完成一个动作：

- 总结当前阶段的分析价值。
- 指出下一步验证。
- 指向看板、专项、复盘、目标管理。
- 承认这篇文章还没解决的部分。
- 引出下一篇或下一层问题。

## 3. 语言表达机制

渭河文风的语言不是单纯口语化，而是“口语承载判断”。

典型表达功能：

- 用“你会发现”带读者完成观察。
- 用“问题在于”把读者从表层带到深层。
- 用“如果只……”指出模板化理解的局限。
- 用“所以”收束推理。
- 用“但是”制造换层。
- 用“到这里”标记阶段性结论。

## 4. 段落节奏机制

### 4.1 段落长度

渭河文风倾向中长段落。一个段落通常不是一个短观点，而是一个完整推理单元：

```text
现象/误区 -> 作者判断 -> 业务解释 -> 小结或转场
```

短段通常用于：

- 单独强调判断。
- 引出下一节。
- 放置公式或清单。
- 做阶段性收束。

### 4.2 句子节奏

长句承担复杂业务关系，短句承担判断和停顿。常见节奏是：

```text
长解释句
-> 转折句
-> 判断句
-> 再解释
```

不要把所有句子都改短，否则会丢失作者“边讲边推理”的现场感。

## 5. 认知风格机制

### 5.1 业务优先于工具

模型、公式、SQL、统计学都可以用，但它们要服从业务问题。业务原因没下钻清楚时，模型不是主角。

### 5.2 指标必须回到场景

订单、翻台率、闲置率、留存、目标完成率都不是终点。它们必须回到城市、车辆、用户、调度、价格、资源、组织协作。

### 5.3 分析服务资源配置

报告不是为了证明分析师聪明，而是为了帮助业务选择：

- 资源投到哪里。
- 哪个指标进核心看板。
- 哪个策略应该复盘。
- 哪个问题需要专项。

### 5.4 反对作业化表达

不像渭河文风的写法通常有：

- 只列指标。
- 只套公式。
- 只给模型名。
- 只写“建议优化”。
- 没有业务对象。
- 没有可干预动作。
- 没有边界。

## 6. 下游写作硬约束

使用渭河文风写作时：

- 先写真实问题，不要先写百科定义。
- 先指出常规误解，不要直接给模板答案。
- 每个指标都要翻译成业务场景。
- 每个结论都要区分事实、推断、行动和边界。
- 重要结论要有阶段性，不要装作一次性证明完。
- 结尾必须指向下一步验证、动作、看板、专项或边界。
