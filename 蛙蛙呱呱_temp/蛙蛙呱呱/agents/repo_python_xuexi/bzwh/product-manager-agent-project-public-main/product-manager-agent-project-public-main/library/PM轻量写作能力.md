# PM 轻量写作能力

## 1. 定位

这是产品管理 person 自己拥有的写作能力，不依赖外部写作 agent。

它服务三类产物：

- 给用户看的汇报、决策说明、确认报告。
- 给执行者看的 PRD、需求卡、brief、验收说明。
- 给后续自己看的归档、纠错、经验摘要。

它不负责正式长文、营销稿、发布稿、强风格内容生产。

## 2. 写作流程

| 步骤 | 动作 | 产物 |
| --- | --- | --- |
| 读者判断 | 先判断谁要读、读完要做什么决定 | 读者与决策点 |
| 结论先行 | 先写一句话结论，不先铺背景 | answer-first 结论 |
| 结构搭建 | 把报告拆成 3-7 个决策问题 | 报告骨架 |
| 证据分层 | 区分事实、推断、建议、假设 | 证据层 |
| 人话改写 | 把技术词转成用户影响和操作后果 | 人类可读版 |
| 自审 | 检查是否空泛、AI 味、不可拍板 | 修订版 |
| 归档 | 重要报告写清路径、状态、下一步 | 归档说明 |

## 3. 默认报告骨架

```md
# 一句话结论

## 这份内容帮你决定什么

## 我理解的真正问题

## 关键判断

## 证据、依据或当前假设

## 选项对比

## 风险和未决点

## 下一步最小动作
```

## 4. 自审门禁

| 门禁 | 通过标准 |
| --- | --- |
| 决策门禁 | 用户知道现在要拍板什么 |
| 人话门禁 | 非技术读者能看懂影响和代价 |
| 证据门禁 | 事实、推断、建议没有混写 |
| 结构门禁 | 每一节回答一个问题，不堆模板 |
| 行动门禁 | 下一步能执行、能验证、能回退 |

## 5. 禁止

- 不用长文掩盖判断不清。
- 不把假设写成事实。
- 不写“优化、支持、智能化”但没有动作、状态和验收。
- 不把正式长文、品牌文案、发布稿当成本能力的默认范围。
