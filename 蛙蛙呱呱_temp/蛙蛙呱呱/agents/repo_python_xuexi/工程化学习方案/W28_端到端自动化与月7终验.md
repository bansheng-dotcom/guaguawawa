### 数据溯源的完整实现——从邮件到 SQL 的可追溯链

```python
def generate_data_provenance(start_time: float, df_raw: pd.DataFrame,
                             git_commit: str = None) -> dict:
    """生成数据溯源信息——日报邮件正文或 metadata.txt 中。

    回答四个问题:
    1. 数据从哪来？（数据源 + 最后刷新时间）
    2. 谁处理的？（代码版本 + 处理时间）
    3. 处理了多少数据？（行数 + 关键统计量）
    4. 如果数据有问题——怎么追溯？（数据源表名 + SQL 查询）
    """
    elapsed = time.time() - start_time

    if git_commit is None:
        import subprocess
        result = subprocess.run(['git', 'rev-parse', '--short', 'HEAD'],
                               capture_output=True, text=True)
        git_commit = result.stdout.strip()

    provenance = {
        'data_source': {
            'table': 'dws_daily_city_kpi',
            'database': 'xianguoduo_dw',
            'last_refresh': df_raw['dt'].max() if 'dt' in df_raw.columns else 'N/A',
            'description': 'DWS 层——每日聚合表——数据延迟 T+1'
        },
        'processing': {
            'script': 'main.py',
            'git_commit': git_commit,
            'start_time': datetime.fromtimestamp(start_time).isoformat(),
            'elapsed_seconds': round(elapsed, 1),
            'python_version': sys.version.split()[0]
        },
        'data_stats': {
            'n_rows_raw': len(df_raw),
            'n_rows_clean': 'TBD after cleaning',
            'date_range': f'{df_raw["order_date"].min()} to {df_raw["order_date"].max()}'
        },
        'traceability': {
            'how_to_reproduce': f'git checkout {git_commit} && python main.py --date={df_raw["dt"].max()}',
            'contact': 'data-team@xianguoduo.com'
        }
    }
    return provenance
```

### 自动化监控的三层体系——从检测到告警到自动恢复

**第一层——检测(pipeline_health_check):** 数据量异常/运行时长异常/输出文件存在性——三项自动检查——任一项不通过->进入告警。

**第二层——告警(alert_if_needed):** 按严重程度分级——WARN 只记日志——ERROR 发邮件——CRITICAL(连续3天 ERROR)发邮件+即时消息。告警内容含"可能的原因"——不是"出了不知道什么问题"。

**第三层——自动恢复(如可能):** 某些失败可以自动恢复——不需要人工介入:

| 失败类型 | 能否自动恢复 | 恢复策略 |
|---------|-----------|---------|
| 数据加载失败 | 能——重试 | run_with_retry(max_retries=3, wait_seconds=30) |
| 数据量异常低 | 否——需人工判断 | 告警——可能数据源问题——也可能业务突变 |
| 输出文件缺失 | 能——重跑 | 重跑最后一步——生成缺失的文件 |
| 依赖缺失 | 否——需人工修复 | 告警——pip install 某个包 |
| 数据库连接失败 | 能——重试+切换 | 重试 3 次——仍失败切换备用数据库(如有) |

**面试时——面试官问"你的自动化出过问题吗——怎么处理的"——你回答——"我的管道有三层防护。第一层——自动检测——数据量/运行时长/输出文件——三项检查。第二层——分级告警——不是有错就发邮件——按严重程度——只有需要人工介入的才告警。第三层——如果可能——自动恢复——比如数据加载失败自动重试 3 次。我还没遇到过连续 3 天告警——因为自动重试处理了大部分瞬时故障。"**

### 自动化监控的完整实现——从检测到告警到恢复

```python
def pipeline_health_check(df_raw, df_clean, start_time, expected_row_range=(0.5, 2.0)):
    """管道健康检查——三项全部通过才标记为 success。

    Check 1: 数据量异常——今天加载的行数 vs 过去 7 天平均——超出范围告警
    Check 2: 运行时长异常——今天跑了多久 vs 过去 7 天平均——超出 3x 告警
    Check 3: 输出文件存在性——确认所有必需输出文件已生成
    """
    issues = []

    # Check 1: 数据量异常检测
    n_rows = len(df_raw)
    avg_rows = get_weekly_avg('row_count')  # 过去 7 天平均行数
    if avg_rows > 0:
        ratio = n_rows / avg_rows
        if ratio < expected_row_range[0]:
            issues.append({
                'check': 'data_volume',
                'severity': 'error',
                'detail': f'行数异常低: {n_rows} vs 7天平均 {avg_rows:.0f} (ratio={ratio:.2f})',
                'possible_causes': ['数据源未更新', 'ERP 导出失败', '上游数据管道中断']
            })
        elif ratio > expected_row_range[1]:
            issues.append({
                'check': 'data_volume',
                'severity': 'warn',
                'detail': f'行数异常高: {n_rows} vs 7天平均 {avg_rows:.0f} (ratio={ratio:.2f})',
                'possible_causes': ['数据源重复导入', '历史数据回填', '业务突变(如促销)']
            })

    # Check 2: 运行时长异常
    elapsed = time.time() - start_time
    avg_elapsed = get_weekly_avg('elapsed_seconds')
    if avg_elapsed > 0 and elapsed > avg_elapsed * 3:
        issues.append({
            'check': 'performance',
            'severity': 'warn',
            'detail': f'运行时长异常: {elapsed:.0f}s vs 7天平均 {avg_elapsed:.0f}s',
            'possible_causes': ['数据量增长', '数据库响应慢', '代码引入性能退化']
        })

    # Check 3: 输出文件存在性
    expected_outputs = ['output/daily_kpi.parquet', 'output/daily_report.md', 'output/city_breakdown.parquet']
    for path in expected_outputs:
        if not Path(path).exists():
            issues.append({
                'check': 'output',
                'severity': 'error',
                'detail': f'缺失输出文件: {path}'
            })

    all_passed = len([i for i in issues if i['severity'] == 'error']) == 0

    if not all_passed:
        alert_if_needed(issues, get_consecutive_failures())

    # 记录到 weekly_stats 表——用于未来 7 天的基线比较
    update_weekly_stats(n_rows, elapsed)

    return {'passed': all_passed, 'issues': issues}
```

**这个函数的价值——不是"等运营总监来告诉你数字不对"——是"管道自己知道数字可能不对——并且告诉你可能的原因"。** 面试时——面试官问"你的自动化可靠吗"——你回答——"管道有健康检查——数据量异常/运行时长异常/输出文件缺失——自动检测——自动告警——告警含可能的原因——不是'出了不知道什么问题'——是'出了可能是 X/Y/Z 的问题'。"
