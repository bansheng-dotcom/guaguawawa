## 〇、你应该先读这个

### 这份材料和旧版有什么不同？

旧版（`工程化专项计划.md` + `工程化每日任务清单.md`）是**操作手册**——告诉你"做什么"，不告诉你"为什么"。

这份材料是**学习方案**——每天一个深度概念，按这个顺序：

```
🔴 认知冲突（先让你意识到"现有知识不够用"）
  ↓
📖 核心原理（讲清楚这个概念为什么存在、怎么工作的）
  ↓
🏢 鲜果多案例（在真实场景中用一次）
  ↓
✍️ 动手练习（自己写代码验证理解）
  ↓
✅ 自检反馈（做对了吗？常见误解是什么？）
  ↓
🔗 与主课联动（今天主课学了什么，工程化如何加固）
  ↓
📎 参考速查（需要模板时回到旧文档）
```

### 每天需要多长时间？

- **学习日**（周一至周五）：20-30 分钟
- **周项目日**（周六）：30-45 分钟
- **审计日**（周日）：15-20 分钟

### 旧文档还有用吗？

有。`工程化专项计划.md` 保留作为**代码模板速查**——当你需要复制 CI yaml、logging 配置、README 模板时，回去翻它。但它不再是你学习工程化的主材料。

## 三、贯穿案例：鲜果多水果电商 🏢

每周、每天的学习都发生在同一个场景里。你不是在抽象的"项目"中练习——你是在**鲜果多**工作。

### 公司画像

- **行业**：生鲜电商（水果垂直品类）
- **阶段**：B 轮，日均订单 2000-5000 单
- **技术现状**：数据团队只有你一个人。公司以前用 Excel 做报表，现在数据量大了，Excel 打开要 5 分钟，公式动不动就崩。
- **你的角色**：一号位数据分析师，直接汇报给运营总监。你的前任留下了一堆 `.xlsx` 文件和零散的 Python 脚本，没有任何文档。
- **8 月的任务**：搭建公司第一条可复现的数据分析管线——从原始订单数据到经营分析报告，全流程自动化。

### 数据资产

| 表名 | 格式 | 关键字段 | 行数 |
|------|------|---------|------|
| `orders.csv` | CSV, UTF-8 | order_id, user_id, order_date, product_id, quantity, unit_price, total_amount, city, payment_method, status | ~10万行/月 |
| `users.csv` | CSV, GBK | user_id, register_date, city, channel, device | ~5万行 |
| `products.csv` | CSV, UTF-8 | product_id, product_name, category, supplier, cost_price, shelf_life_days | ~500行 |

### 你将遇到的真实问题

- 前任的脚本在 `C:\Users\前任\Desktop\分析\` 下，路径写死了，你运行直接报错
- `users.csv` 是 GBK 编码，`orders.csv` 是 UTF-8，同一个 `pd.read_csv()` 一个乱码一个正常
- 运营总监说"把上个月的 GMV 拉一下"，你跑完脚本后他反问"这个数和你上周二给我的为什么不一样？"
- 公司换了一台新电脑给你，你花了两天还没把前任的脚本跑通

这些不是虚构的困难。这是每一个野生数据分析师变成职业数据分析师的过程中，真实踩过的坑。这份材料就是帮你**提前踩**，有指导地踩，踩完知道怎么爬出来。

3. **先读 🔴 认知冲突**——不要跳过。感受一下"现有知识不够用"的瞬间
4. **再读 📖 核心原理**——理解这个概念为什么存在
5. **接着看 🏢 鲜果多案例**——看这个概念在真实场景中怎么用
