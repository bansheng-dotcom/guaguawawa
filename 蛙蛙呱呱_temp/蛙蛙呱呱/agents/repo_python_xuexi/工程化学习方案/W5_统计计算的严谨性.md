## D1（周一 8/25）：浮点数不是实数——为什么你的统计计算可能静默出错

> 📓 今日主课：概率论基础——三种概率理解/大数定律/条件概率/独立≠互斥/期望方差

---

### 🔴 认知冲突

你在 Python 里算了一个简单的东西：
```python
>>> 0.1 + 0.2
0.30000000000000004
```

不是 0.3。差了一丁点——小数点后第 17 位。这点误差在日常生活里无关紧要。但在统计计算中——当你做 10 万次累加、求方差、算概率——这一丁点误差会**累积**。

更隐蔽的是——你的 scipy t-test 算出来的 p 值是 `0.04999999999999999`。你和同事的 Excel——他的是 `0.05`。你的结论："显著（p < 0.05）"。同事的结论："不显著（p = 0.05）"。一个 17 位的浮点误差，改变了"是否统计显著"的判断。

**问题**：为什么计算机会把 0.1 + 0.2 算错？这不是 Python 的 bug——所有语言都是这样。根因在哪？

---

### 📖 核心原理

**计算机不是用十进制存储数字的。它用二进制。**

你用十进制写 `0.1`——这是 1/10。但 1/10 在二进制里是**无限循环小数**——就像 1/3 在十进制里是 0.33333... 永远写不完。

计算机只能存储有限位（64 位的 IEEE 754 标准——这是所有现代 CPU 的浮点数标准）。所以 `0.1` 被存成了一个**近似值**——不是精确的 0.1。

```python
# 看 0.1 实际存了多少位
>>> format(0.1, '.55f')
'0.1000000000000000055511151231257827021181583404541015625'
# 0.1 被存成了略大于 0.1 的一个数
```

**三个你必须在统计计算中注意的浮点陷阱**

**陷阱一：相等比较**
```python
>>> 0.1 + 0.2 == 0.3
False  # ！不是 Python 的 bug——计算机根本没法精确表示这三个数

# 正确做法：用近似相等
>>> abs((0.1 + 0.2) - 0.3) < 1e-10
True
```

**陷阱二：累计误差**
```python
# 1 万次累加 0.1——期望是 1000.0
>>> total = 0.0
>>> for _ in range(10000):
...     total += 0.1
>>> total
999.9999999999065  # 偏差约 0.00000000009——但实际数据分析中累加次数可能是百万级
```

**陷阱三：灾难性抵消（Catastrophic Cancellation）**
```python
# 两个非常接近的大数相减——损失精度
>>> a = 1.000000000000001
>>> b = 1.000000000000000
>>> (a - b) * 1e15
0.8881784197001252  # 期望是 1.0，但算出来是 0.888
# 原因：a 和 b 的有效位数在相减时被消耗掉了
```

在统计计算中，方差公式 `Σ(x-μ)²` 就会触发这个问题：先算均值 μ，再算每个值减 μ 的平方——这个"减 μ"就是一个大数减一个接近大数的操作。

**你的统计代码应该怎么处理？**

在你的阶段，两个规则：
1. **永远不要用 `==` 比较浮点数。** 用 `np.isclose()` 或 `abs(a - b) < 1e-10`。
2. **知道问题存在。** 当你看到 `p = 0.0499999999` 时——你知道这其实是 0.05。当你和 Excel 结果在小数点第 15 位不一致时——你知道根因可能是浮点精度差异，而不是你的代码写错了。

---

### 🏢 鲜果多案例

你在鲜果多算各城市客单价的方差。手算用的公式是：
```python
variance = (sum(x**2) - sum(x)**2 / n) / (n - 1)
```

这个公式在数学上是正确的。但在计算机上——`sum(x**2)` 是一个大数（百万级），`sum(x)**2 / n` 也是个大数——两个大数相减，损失精度。结果方差可能是**负数**（在数学上不可能，但在浮点运算中可能发生）。

正确做法：用 `np.var(x, ddof=1)`——NumPy 内部用了数值稳定的算法（Welford 方法），不会出现负方差。

## D2（周二 8/26）：随机性的工程管理——为什么你每次跑结果都不一样

> 📓 今日主课：五大分布——二项/泊松/正态/指数/幂律 + QQ 图/Shapiro-Wilk/KS 检验

---

### 🔴 认知冲突

你写了一个模拟实验验证中心极限定理——从偏态分布里抽样 1000 次，取均值，画直方图。每次跑代码——图形都差不多但细节不同。同事说"我用你的代码跑出来不一样"——你发现你没设随机种子。

你加了 `np.random.seed(42)`。但后来你升级了 NumPy——相同种子跑出来的结果变了，因为 NumPy 内部改了随机数生成算法。

**问题**：随机种子到底是什么？为什么设了种子就能复现？`np.random.seed` 和 `np.random.default_rng` 有什么区别，为什么后者是新推荐的做法？

---

### 📖 核心原理

**计算机不会产生真正的随机数。它产生的是"伪随机数"（Pseudo-Random Numbers）。**

伪随机数由一个确定的数学公式生成——给定一个初始值（种子），后续所有"随机数"都是确定的。同一个种子 → 同一串数字。这就是为什么设了种子就能复现。

就像玩 Minecraft——同一个 seed 生成完全一样的世界。

**`np.random.seed` 的问题——全局状态**

```python
np.random.seed(42)
np.random.randn(3)  # 你的代码
# ... 中间可能有其他代码也调了 np.random ...
np.random.randn(3)  # 结果被中间调用改变了！
```

`np.random.seed` 设置了一个**全局状态**。你的代码中间如果引入了第三方库（比如 matplotlib、seaborn、scipy），它们内部也可能调用 `np.random`——从而改变了序列。你得到的随机数取决于整个程序的调用顺序——不是你设了 seed 就能完全控制。

**`np.random.default_rng` 的解法——独立的随机数生成器**

```python
rng = np.random.default_rng(42)
rng.normal(0, 1, 100)  # 这 100 个正态随机数由 rng 自己管理
# 即使中间 matplot 调了全局 np.random——rng 不受影响
```

`default_rng` 返回一个**独立的随机数生成器对象**。它有自己独立的状态——不和全局 `np.random` 共享。多个 rng 之间也互相独立（给不同的 seed）。

这也是 NumPy 官方推荐的新做法——`np.random.seed` 是旧的全局方式（legacy）。

**三个关键场景**

| 场景 | 做法 | 原因 |
|------|------|------|
| **需要复现**（分析报告/实验） | `rng = np.random.default_rng(42)` | 固定种子 → 结果可复现 |
| **不需要复现**（一次性的探索） | `rng = np.random.default_rng()`（不传 seed，自动用系统时间生成） | 每次不同的结果——但每次也都是"真随机"感受 |
| **需要多个独立序列**（并行实验） | `rng1 = default_rng(42); rng2 = default_rng(43)` | 两个独立序列，互不干扰 |

---

### 🏢 鲜果多案例

你给鲜果多做了一个"模拟未来 30 天 GMV"的预测模型——用了 `np.random.seed(42)`。运营总监看后说"能帮我算最坏情况吗？"。你重新设置 `seed(None)`（不固定种子），跑了 1000 次模拟，取第 5 百分位作为最坏情况。

后来你想"验证自己写的模拟逻辑没有 bug"——你把 seed 设回 42，重跑了单次——结果和第一次完全一样。你知道你的代码是**可复现的**。

这就是随机性管理的两层：**开发阶段——固定种子，确保代码行为可复现。生产阶段——用系统时间生成种子，确保每次模拟是独立的。**

## D3（周三 8/27）：统计函数的"假设透明"——你的 t-test 和 Excel 为什么结果不一样

> 📓 今日主课：描述统计 + EDA 八步——中心趋势/离散度/偏度峰度/箱线图/EDA

---

### 🔴 认知冲突

你用 Python 跑了一个 Welch's t-test，p 值 = 0.043。同事用 Excel 的 T.TEST 函数，p 值 = 0.051。你们的结论相反——一个显著一个不显著。

排查后发现：
- 你用 `scipy.stats.ttest_ind(df['A'], df['B'], equal_var=False)`——Welch's t-test，假设方差不等
- 同事在 Excel 里选了 `T.TEST(range1, range2, 2, 2)`——双尾、等方差假设

你们没意识到你们用的是**两种不同的检验**。参数的一个微妙差异——`equal_var` True/False——改变了分析结论。

**问题**：统计函数的"假设"往往不是写在函数名里的——而是藏在默认参数里。怎么让代码的使用者（包括三个月后的你）知道这个函数做了什么假设？

---

### 📖 核心原理

**统计代码的工程化标准——假设透明（Assumption Transparency）。**

一个统计函数如果只返回数字——别人无法判断它是否正确。除了数字，它还必须声明：

1. **输入假设**：对输入数据做了什么假设？（正态？等方差？独立同分布？）
2. **缺失值处理**：遇到 NaN 怎么处理？（删除？填充？报错？）
3. **数值方法**：内部用了什么算法？（Welford 方差？Welch 自由度校正？）
4. **输出解释**：输出的数字应该怎么解读？（p 值不是"原假设为真的概率"）

**示范——一个"假设透明"的 t-test 函数**

```python
from typing import Dict, Tuple
import numpy as np
from scipy import stats
import logging

logger = logging.getLogger(__name__)


def welch_ttest(
    group_a: np.ndarray,
    group_b: np.ndarray,
    alpha: float = 0.05,
    alternative: str = 'two-sided'
) -> Dict:
    """Welch's t-test（不假设等方差）。

    重要假设（使用者必须确认）：
    1. 两组样本独立（不是配对数据，不是重复测量）
    2. 每组内观测近似正态分布（样本量≥30时此假设可放宽，由CLT保证）
    3. 不假设两组方差相等——这是Welch's t 与 Student's t 的核心差异。
       如果不确定方差是否相等，优先使用此函数。

    缺失值处理：自动删除各组内的 NaN，并报告删除数量。
    注意：只能删除完全随机缺失(MCAR)的 NaN。如果缺失机制是 MAR/MNAR，
    删除会引入偏差——请先做缺失机制分析。

    Args:
        group_a: 组A的观测值（如对照组）
        group_b: 组B的观测值（如实验组）
        alpha: 显著性水平，默认 0.05
        alternative: 'two-sided'（双尾）/ 'less'（A < B）/ 'greater'（A > B）

    Returns:
        Dict 含:
            statistic: t 统计量
            p_value: 在原假设为真时，观察到当前或更极端差异的概率。
                     注意：p 不是"原假设为真的概率"——那是常见的误解。
            effect_size: Cohen's d（效应量）。0.2/0.5/0.8 分别对应小/中/大。
            mean_diff: 均值的绝对差值（B - A）
            n_clean_a / n_clean_b: 删除 NaN 后的有效样本数
            n_dropped_a / n_dropped_b: 被删除的 NaN 数
            significant: p < alpha
            assumption_note: "不假设等方差。若需假设等方差，使用 scipy.stats.ttest_ind(equal_var=True)。"
    """
    # NaN 处理——透明报告
    clean_a = group_a[~np.isnan(group_a)]
    clean_b = group_b[~np.isnan(group_b)]
    n_drop_a = len(group_a) - len(clean_a)
    n_drop_b = len(group_b) - len(clean_b)
    if n_drop_a > 0:
        logger.info("组A删除 %d 个 NaN（%.1f%%）", n_drop_a, n_drop_a / len(group_a) * 100)
    if n_drop_b > 0:
        logger.info("组B删除 %d 个 NaN（%.1f%%）", n_drop_b, n_drop_b / len(group_b) * 100)

    # Welch's t-test
    t_stat, p = stats.ttest_ind(clean_a, clean_b, equal_var=False, alternative=alternative)

    # Cohen's d
    pooled_std = np.sqrt((np.var(clean_a) + np.var(clean_b)) / 2)
    d = (np.mean(clean_b) - np.mean(clean_a)) / pooled_std if pooled_std > 0 else 0.0

    return {
        'statistic': t_stat,
        'p_value': p,
        'effect_size': d,
        'mean_diff': np.mean(clean_b) - np.mean(clean_a),
        'n_clean_a': len(clean_a),
        'n_clean_b': len(clean_b),
        'n_dropped_a': n_drop_a,
        'n_dropped_b': n_drop_b,
        'significant': p < alpha,
        'assumption_note': '不假设等方差。若需假设等方差，使用 scipy.stats.ttest_ind(equal_var=True)。'
    }
```

这个 docstring 和返回值告诉使用者一切——函数做了什么假设、怎么处理 NaN、结果怎么解读。这就是"假设透明"。

**Excel 和 Python 结果不一样——排查清单**

1. **检验方法不同**：Python 用了 Welch's t（`equal_var=False`），Excel 用了 Student's t（`equal_var=True`）？
2. **NaN 处理不同**：Python 自动忽略了 NaN？Excel 把 NaN 当 0？
3. **单双尾不同**：Python `alternative='two-sided'` vs Excel 的尾数参数？

## D4（周四 8/28）：p 值深度理解——通过模拟"看到"p 值的分布

> 📓 今日主课：推断统计（上）——抽样分布/SE vs σ/CLT/CI 正确解读/Bootstrap

---

### 🔴 认知冲突

你背了 p 值的定义："在原假设为真时，观察到当前或更极端结果的概率。"面试时你说出了这句话——面试官点了点头，然后问：

"如果原假设为真（两组没有差异），p 值的分布应该是什么形状？"

你答不上来。你背了定义但不理解定义的含义。如果你真正理解这个定义——你会推导出：**在原假设为真时，p 值服从 [0, 1] 上的均匀分布。**

**问题**：为什么 H0 为真时 p 值服从均匀分布？怎么用代码证明这一点？为什么这个性质很重要——它和"p-hacking"有什么关系？

---

### 📖 核心原理

**"p 值在原假设为真时服从均匀分布"——用白话解释。**

p 值是"在原假设为真时，观察到当前或更极端结果的概率"。这等价于说——"如果原假设为真，p 值落在 [0, 0.05] 的概率是 5%。"

那么：
- 你做 100 次实验，原假设全都是真的（两组之间确实没有差异）
- 你会得到 100 个 p 值
- 这 100 个 p 值应该均匀分布在 [0, 1] 之间——大约 5 个落在 [0, 0.05]，大约 5 个落在 [0.05, 0.10]，依次类推
- **所以 p < 0.05 只代表"在原假设为真的情况下，只有 5% 的概率看到 p ≤ 0.05"——而不是"有 95% 的概率备择假设为真"**

**用代码验证——这是本周最重要的动手练习。**

```python
import numpy as np
from scipy import stats
import matplotlib.pyplot as plt

rng = np.random.default_rng(42)

# 模拟 10000 次实验：每次取两组来自同一总体 → H0 为真
n_sims = 10000
p_values = np.zeros(n_sims)

for i in range(n_sims):
    # 两组来自完全相同的总体——H0为真（没有差异）
    group_a = rng.normal(100, 15, 30)  # 均值100, 标准差15, 每组30人
    group_b = rng.normal(100, 15, 30)  # 和A完全相同的总体
    # t-test
    _, p = stats.ttest_ind(group_a, group_b, equal_var=True)
    p_values[i] = p

# 画 p 值的直方图——H0为真时应该是均匀的
fig, axes = plt.subplots(1, 2, figsize=(12, 5))

axes[0].hist(p_values, bins=20, color='steelblue', edgecolor='white')
axes[0].axhline(n_sims / 20, color='red', ls='--', label='期望均值 (均匀分布)')
axes[0].set_title(f'H0为真时 p 值的分布\n{p_values < 0.05:.1%} 的 p < 0.05（应该是约 5%）')
axes[0].legend()

# 累积分布应该接近对角线（均匀分布的CDF）
axes[1].ecdf(p_values)  # 或 sorted_p = np.sort(p_values); axes[1].plot(sorted_p, np.arange(n_sims)/n_sims)
axes[1].plot([0, 1], [0, 1], 'r--', label='理论期望 (均匀分布)')
axes[1].set_title('p 值累积分布 (H0为真时)')
axes[1].legend()
```

运行这段代码。你会看到：
- 直方图几乎是平的（均匀分布）
- 大约 5% 的 p < 0.05——即使两组之间确实没有差异
- **这就是为什么 p < 0.05 不是"有 95% 概率有效应"——因为 H0 为真时也有 5% 的概率得到 p < 0.05（这就是第一类错误率）**

**这和 p-hacking 有什么关系？**

p-hacking = 你不固定分析方案，反复换分析方式，直到 p < 0.05。本质——你在利用"均匀分布在 [0, 1]"这个性质：做 20 次不同的分析，H0 为真时期望有 1 次 p < 0.05。你只报告那 1 次——这叫 p-hacking。

**p 值的三个常见误解——用你自己的代码验证**

| 误解 | 正确解读 | 代码里怎么验证 |
|------|---------|-------------|
| "p = 0.04 意味着 H0 为真的概率是 4%" | ❌ p 值不是"H0 为真的概率"——H0 要么真要么假，不存在概率 | — |
| "p > 0.05 意味着两组没有差异" | ❌ p > 0.05 只说明"证据不足以拒绝 H0"——不等于"H0 为真"（可能是样本量不够） | 样本量减小→p 值增大——即使真实效应量不变 |
| "p 越小效应越大" | ❌ p 值同时受效应量和样本量影响。大样本下微小差异也有小 p 值 | 构造数据：大样本+微小差异→p 极小但 d 极小 |

---

### 🏢 鲜果多案例

你在鲜果多做了"北京和上海客单价对比"的 t-test——p = 0.043，显著。运营总监认为"这说明北京的客单价确实比上海低"。

p 值 + 效应量 + 置信区间 = 完整的推断。只报 p 值 = 不完整的推断。

## D5（周五 8/29）：辛普森悖论——不只是"造一个例子"，是如何检测和防御

> 📓 今日主课：推断统计（下）——假设检验/p 值 5 大误解/Cohen's d/Welch's t/非参检验/参数 vs 非参决策表

---

### 🔴 认知冲突

你知道辛普森悖论是什么。你甚至能用 Python 造出一个例子（旧版 W5D6 就教了）。但今天你在鲜果多真实数据里看到了一个诡异的模式：

- 北京新用户客单价 80 元，上海新用户客单价 85 元——上海高
- 北京老用户客单价 120 元，上海老用户客单价 125 元——上海高
- **但合计起来：北京整体客单价 110 元，上海整体客单价 95 元——北京高？**

你检查了数据——不是数据错误。北京老用户多（占 70%），上海新用户多（占 60%）。老用户天生客单价高（因为买得多）——**分组权重不同**让合计结论和分组结论反转了。

这就是辛普森悖论在真实工作中的样子——不是教科书里构造的整洁例子，而是混在几百行数据里、你没有特意去检查时就会漏掉的模式。

**问题**：你每天做 groupby。你有多大概率在某个真实的 groupby 里遇到了辛普森悖论但没注意到？怎么系统地检查？

---

### 📖 核心原理

**辛普森悖论的根因公式：当分组权重（每个子组的样本量占比）和组内效应（子组内的指标差异）方向相反时，合计结论可能与分组结论方向相反。**

```
方向公式：
合计方向 = Σ(子组权重 × 子组方向)

如果每个子组的方向相同（北京新用户 > 上海新用户，北京老用户 > 上海老用户），
但权重差异足够大（北京老用户多很多，而老用户客单价远高于新用户）
→ 合计方向可能和子组方向相反
```

**在真实数据分析中检测辛普森悖论的三个信号**

1. **分组结论不一致**：整体趋势和分组趋势方向相反。
2. **子组权重极端不均匀**：某个子组占总体的 > 70%。
3. **子组间基线不同**：新用户和老用户的客单价天然不同（这不是悖论的原因——这是条件变量）。

**系统性检查——"分组扫描"**

```python
def simpson_scan(df: pd.DataFrame, outcome: str, groupby: str, category: str) -> Dict:

    2. 按 {groupby} × {category} 二分法，计算每个子组的均值和权重

    subgroups = df.groupby([groupby, category])[outcome].agg(['mean', 'count'])
```

你不必现在就实现完整版 `simpson_scan`——但你要知道这个方法存在，并在做 groupby 时有意识地看一眼"分组后的合计和子组结论是否一致"。

**不是所有反转都是辛普森悖论**

辛普森悖论的统计定义：分组效应 ≠ 边际效应——由于存在一个混杂变量同时影响分组变量和结果变量。

如果你的反转不是因为混杂变量，而是因为数据错误、缺失值、异常值——那是数据质量问题（W3D1 的验证金字塔），不是辛普森悖论。

---

### 🏢 鲜果多案例

鲜果多运营总监看到"北京客单价 110，上海 95"——说"加大北京投放力度！"

你用分组扫描发现——北京和上海在"新用户 vs 老用户"这个维度上，每个子组上海都更高。合计结论反转纯粹因为北京老用户多。

这就是工程化对分析能力的影响——你不仅"知道辛普森悖论是什么"，还能在真实数据中识别它、量化它、用它影响决策。

### 📝 8 道概念自测题

**Q1**：为什么 `0.1 + 0.2 != 0.3`？在统计计算中，这个问题什么时候会变成实际问题（不是理论问题）？

**Q2**：`np.random.seed(42)` 和 `rng = np.random.default_rng(42)` 的区别是什么？为什么后者是 NumPy 官方推荐的做法？

**Q3**：统计函数的"假设透明"至少应该声明哪四件事？为什么对统计函数的要求高于对工具函数的要求？

**Q4**：在原假设为真时，p 值的分布是什么？怎么用代码验证？这个性质为什么能用来理解 p-hacking？

**Q5**："p < 0.05 意味着有 95% 的概率备择假设为真"——这句话为什么是错的？

**Q6**：辛普森悖论发生的条件是什么？你在日常 groupby 中怎么系统地检查有没有被它误导？

**Q7**：你的 t-test 结果 p = 0.043，同事 Excel 结果 p = 0.051——可能的原因有哪些？（至少说出 4 个）

**Q8**：你跑了一次模拟实验验证 CLT，同事用你的代码跑了得到的结果不一样——最可能的原因是什么？怎么避免？

---

### ✅ 参考答案

**Q1**：因为 0.1 在二进制中是无限循环小数，计算机只存了近似值。问题场景：t-test 的 p 值接近 α 阈值（如 0.0499999 vs 0.05）时——一个 1e-17 的浮点误差可能改变"是否显著"的结论。偏差：只说了"因为二进制"——要接着说"这个问题在统计检验中什么时候变成实际问题"。

**Q2**：旧方式用全局状态——中间如果其他代码也调用了 np.random，会改变状态序列。新方式用独立生成器——每个 rng 有自己的状态，互不干扰。偏差：说不出来"全局状态"的问题——这正是 D2 的核心。

**Q3**：①输入假设（正态？等方差？独立？）②缺失值处理策略（删/填/报错）③数值方法（Welch 校正？Welford 方差？）④输出解读（p 值不是"原假设为真概率"）。统计函数假设多且误用后果严重——静默的错误结论比代码崩溃更可怕。偏差：漏了"输出解读"——这是最常见的：t-test 输出 p 值但使用者不知道"p 不是原假设为真的概率"。

**Q4**：H0 为真时 p 值服从 [0, 1] 均匀分布。代码验证：模拟 10000 次 A/B（来自同一总体），t-test → p 值直方图均匀。p-hacking 原理：做 20 次不同分析，期望 1 次 p<0.05——你只报告那 1 次。偏差：说"p 值服从正态分布"——完全错。p 值在 [0,1] 上，正态分布是 (-∞,+∞)。

**Q5**：p 值是在 H0 为真条件下观察到当前结果的概率——P(数据 | H0)，不是 P(H0 | 数据)。这两个概率方向相反。打个比方：P(地面湿 | 下过雨) ≠ P(下过雨 | 地面湿)——因为地面湿还可能是洒水车。偏差：只说"p 值不是后验概率"但解释不了——对照记忆里的教学反馈，用户需要例子。

**Q6**：发生条件——分组权重方向和组内效应方向相反。系统检查——任何 groupby 后多看一眼分群数据，确认子组结论和合计结论方向一致。特别警惕"某个子组占比 > 70%"的情况。偏差：知道定义但说不出日常检查方法——这正是旧版的问题（只教"造例子"，不教"检测"）。

**Q7**：①检验方法不同（Welch's t vs Student's t——equal_var 参数）②NaN 处理不同（Python 默认 ignore vs Excel 可能当作 0）③单双尾不同 ④浮点精度差异 ⑤数据源不同（中间被 Excel 改了格式）。偏差：只能说一两个——这个是 D3 的核心内容。

**Q8**：没设随机种子（或设了但用了全局 seed 被中间代码干扰）。避免：用 `rng = np.random.default_rng(固定seed)`，所有随机操作通过 rng。偏差：说"代码有问题"——不，代码没问题，是随机性没被管理。
