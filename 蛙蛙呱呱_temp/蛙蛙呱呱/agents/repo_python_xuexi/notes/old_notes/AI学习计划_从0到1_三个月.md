## 0.1 机器学习到底在干什么？

一句话：**机器学习 = 从数据中自动找出规律（函数）**

```
传统编程：  输入 + 规则 → 输出（规则是人写的）
机器学习：  输入 + 输出 → 规则（机器从数据中学）
```

### 三种学习范式

| 范式 | 数据特点 | 例子 |
|------|---------|------|
| **监督学习** | 有标注（输入+正确答案） | 猫狗分类、房价预测 |
| **无监督学习** | 只有输入，无标注 | 聚类、降维、生成 |
| **强化学习** | 与环境互动，奖励信号 | AlphaGo、RLHF |

LLM 的训练就是**监督学习**：给模型上文（输入），让模型预测下一个词（正确答案）。

---

## 0.2 模型到底是什么？

**模型 = 一个带参数的数学函数**

```
房价预测模型：price = w₁ × 面积 + w₂ × 房间数 + b

w₁, w₂, b 是参数（模型要学的东西）
```

GPT-4 的模型也一样，只是参数有**上万亿个**，函数巨复杂，但本质上仍然是：
```
输入文字 → 数学运算（万亿参数参与） → 输出下一个字的概率
```

## 0.3 模型怎么"学习"？——梯度下降（核心中的核心）

```
步骤1：猜一个答案（当前的模型参数）
步骤2：计算"差多少"（损失函数 Loss）
步骤3：算每个参数该调多少（反向传播 + 梯度）
步骤4：微调参数，让Loss变小（梯度下降）
步骤5：重复步骤1-4，直到Loss足够小
```

**直观类比**：
> 你在山顶，蒙着眼想走到谷底。
> 每走一步，用脚探一下四周哪里更低，往最低的方向走一步。
> 反复重复 → 最终走到谷底。

```
损失函数值
    │
    │  ●  ← 初始参数（山顶）
    │   ╲
    │    ╲
    │     ●  ← 训练中...
    │      ╲
    │       ╲
    │        ● ← 最优参数（谷底）
    └─────────────→ 参数值
```

**核心公式**（理解即可，不用推导）：

```
新参数 = 旧参数 - 学习率 × 梯度

θ_new = θ_old - η × ∇L(θ)
        ↑          ↑      ↑
      参数      步长    往哪个方向走
```

- **学习率太大** → 跳来跳去不收敛
- **学习率太小** → 学得太慢
- **梯度方向** → 损失函数上升最快的方向，所以要"减去梯度"才是下降

---

## 0.4 关键概念速通

| 概念 | 一句话解释 |
|------|-----------|
| **损失函数（Loss）** | 衡量模型"错得有多离谱"的数字 |
| **反向传播（Backprop）** | 从最后一层往前，逐层算每个参数对Loss的贡献（链式法则） |
| **过拟合（Overfitting）** | 模型考试满分但换个题目就不会 → 死记硬背 |
| **欠拟合（Underfitting）** | 模型根本没学会 → 训练数据上表现都差 |
| **正则化（Regularization）** | 防止过拟合的方法（罚复杂模型） |
| **Batch Size** | 每次拿多少数据算梯度（大了稳定但慢，小了快但震荡） |
| **Epoch** | 全部数据被模型"看"过一遍 |
| **激活函数（ReLU等）** | 引入非线性，否则多层=一层 |

## 0.5 神经网络层级结构

```
输入层          隐藏层          隐藏层          输出层
  ↓              ↓              ↓              ↓
 [x₁] ────→ [h₁₁] ────→ [h₂₁] ────→ [y₁]
 [x₂] ────→ [h₁₂] ────→ [h₂₂] ────→ [y₂]
 [x₃] ────→ [h₁₃] ────→ [h₂₃]
              ↑              ↑
         每个连接有权重     通过梯度下降更新
```

### Transformer 的核心：Self-Attention

Transformer 的核心创新是 **Self-Attention**（自注意力），每个词会和句子中所有其他词"算一个关系分数"。

```
"我把苹果吃了" → "苹果"和"吃"关系紧密
"苹果发布了新手机" → "苹果"和"发布"、"手机"关系紧密

同一个词"苹果"，靠 Self-Attention 找到不同的关联词，从而理解不同含义。
```

## 0.6 动手：从零训练第一个模型

```python
import torch
import torch.nn as nn
import torch.optim as optim

# 最简数据：y = 2*x + 1
x_data = torch.tensor([[1.0], [2.0], [3.0], [4.0]])
y_data = torch.tensor([[3.0], [5.0], [7.0], [9.0]])

# 定义模型：只有一层的线性模型
model = nn.Linear(1, 1)  # 输入1维 → 输出1维

# 损失函数 + 优化器
loss_fn = nn.MSELoss()             # 均方误差
optimizer = optim.SGD(model.parameters(), lr=0.01)  # 随机梯度下降

# 训练循环
for epoch in range(500):
    y_pred = model(x_data)           # 前向传播：算预测值
    loss = loss_fn(y_pred, y_data)   # 算损失
    optimizer.zero_grad()            # 清零梯度
    loss.backward()                  # 反向传播：算梯度
    optimizer.step()                 # 梯度下降：更新参数

    if epoch % 100 == 0:
        print(f"Epoch {epoch}: loss={loss.item():.4f}")

# 查看学到的参数
print(f"学到的权重w: {model.weight.item():.4f}")  # 应该接近 2.0
print(f"学到的偏差b: {model.bias.item():.4f}")    # 应该接近 1.0
# 预测
print(f"输入5 → 预测: {model(torch.tensor([[5.0]])).item():.4f}")  # 应接近 11.0
```

## 第一讲：什么是生成式AI？

### 核心定义
**生成式AI = 机器产生复杂、有结构的物件（文字、图片、语音等）**

关键区别：
- **分类问题**（传统AI）：从有限选项中选一个 → 不是生成式AI
- **生成问题**（生成式AI）：输出空间近乎无限穷举 → 必须"创造"训练时没见过的东西

### 生成策略

**自回归生成（Autoregressive Generation）**：把复杂物件拆成小单位，按固定顺序逐一生成。

这就是 ChatGPT 的核心策略：
```
输入："今天天气"
模型逐字生成： "今天天气" → "真" → "好" → "，"
→ "晴" → "空" → "万" → "里"
```

每一步的输出，会成为下一步的输入。这就是"文字接龙"的本质。

---

## 第二讲：从"工具"变成"工具人"

以前的AI是**工具**——你说一句，它回一句。
现在的AI是**工具人**——它能自己规划、使用工具、完成一个完整任务。

Agent（AI代理人）的核心能力：
1. 理解你的意图
2. 自己规划步骤
3. 调用外部工具（搜索引擎、代码执行、API）
4. 检查结果并修正
5. 给你最终答案

## 第三~五讲：【重点】不训练模型，如何强化LLM？

五种不训练模型就能增强能力的方法：

### 方法1：Chain of Thought（CoT）— "神奇咒语法"

**核心思想**：在提问时加上"请一步步思考"——模型推理能力大幅提升。

普通提问：
> "小明有5个苹果，给了小红2个，又买了3个，还剩几个？"

CoT提问：
> "小明有5个苹果，给了小红2个，又买了3个，还剩几个？**让我们一步一步思考。**"

效果：模型会展示推理过程，准确率大幅提高。

**关于Prompt的技巧（论文验证）**：
- ❌ "请"、"谢谢" → **没用的客套话**
- ✅ "如果做得好给你小费" → **有用！**
- ✅ 直接说做什么 → **正指令比负指令有效**
  - 好："输出JSON格式"
  - 差："不要输出其他格式"

### 方法2：提供额外信息

**In-context Learning（上下文学习）**：给模型提供例子，它不需要重新训练就能学会。

```
请把以下句子翻译成英文：

中文：今天天气很好
英文：The weather is very nice today

中文：我饿了
英文：
```

给一两个例子，模型立刻就能照着做。这就是 Few-shot Learning。

**还可以直接喂文件**：把PDF、文档作为上下文，让模型基于你的资料回答。

### 方法3：拆解问题

**核心思路**：复杂任务不要一步完成，拆成子任务逐步解决。

具体技巧：
- **Self-Consistency**：让模型多次推理，选最一致的答案（投票法）
- **Tree of Thoughts（ToT）**：每步产生多个候选方案，评估后选最好的继续
- **Self-Reflection（自我反思）**：让模型检查自己的错误

```
提问：你刚才的答案正确吗？请反思并给出最终答案。
```

⚠️ **关键认知**：让模型"反省"并不会改变模型本身的参数！只是在下一次对话中，利用反省的文本来获得更好的输出。

### 方法4：提供工具

**RAG（检索增强生成）**：给模型接上你的数据库/知识库

核心流程：
```
用户问题 → 向量检索 → 找到相关文档 → 拼入Prompt → 发给LLM → 得到答案
```

**让模型写代码执行**：模型生成代码 → 执行 → 拿结果 → 继续推理
（ChatGPT 的 "Analyzing" 就是它在写Python代码）

**Function Calling / Plugin**：模型调用外部API、搜索引擎、计算器等

### 方法5：让模型彼此合作（多Agent）

**核心发现**：
- 不同模型各有擅长 → 各司其职，1+1>2
- **讨论 > 反省**：多个模型互相讨论，比单一模型自我反思效果好得多
- 模型之间讨论的次数越多，效果越好
- 引入不同角色（如：批评者、校对者、执行者）能显著提升质量

**开源参考**：
- MetaGPT：模拟软件公司（PM→架构师→工程师→测试）
- ChatDev：虚拟软件开发团队

**未来方向**：不需要全能大模型，而是专业分工的模型社区。

## 第六讲：大语言模型修炼史 — 第一阶段「自我学习，积累实力」

### 文字接龙就是一切

LLM 的本质 = 学会"文字接龙"。

训练数据不同 → 学到的能力不同：
- 用全网文本训练 → 学会语言知识和世界知识
- 用代码训练 → 学会编程

训练过程：给模型大量文本，让它预测下一个字。预测对了加分，错了扣分。不断调整参数，直到"文字接龙"接得好。

**重点**：这个阶段老师不介入——模型自己从海量文本中学。学的是"这段文字长什么样"，而不是"怎么用"。

---

## 第七讲：大语言模型修炼史 — 第二阶段「名师指点，发挥潜力」

### Instruction Fine-tuning（指令微调）

模型学了很多知识，但不知道"怎么用"。需要人类老师教。

训练数据格式：
```
用户：1+1等于几？
AI：1+1等于2
```

大量这种"问答对"喂给模型 → 模型学会"对话模式"。

**ChatGPT 的核心流程**：
1. 预训练（Pre-training）：从海量文本学知识（第一阶段）
2. 指令微调（Instruction Fine-tuning）：学会对话（第二阶段）
3. RLHF（人类反馈强化学习）：让回答更符合人类偏好

## 第一课：模型、提示词和解析器（Models, Prompts & Parsers）

### LangChain 三件套
- **Model（模型）**：你用的LLM（GPT-4、千问、Kimi等）
- **Prompt（提示词）**：你给模型的输入模板
- **Parser（解析器）**：把模型输出转成结构化格式

### 基础代码模式

```python
from langchain_openai import ChatOpenAI
from langchain.prompts import ChatPromptTemplate

llm = ChatOpenAI(temperature=0.3, model="gpt-4")

prompt = ChatPromptTemplate.from_template(
    "请说出一个中国公司名称，这家公司生产产品 {product} ？"
)

# 组合成链
from langchain.chains import LLMChain
chain = LLMChain(llm=llm, prompt=prompt)
result = chain.run("智能手机")
# 输出：华为（Huawei）是一家中国公司，生产智能手机。
```

**关键参数**：
- `temperature`：越低越确定（适合代码/事实），越高越有创意（适合写作）
  - 0.0 ~ 0.3：严肃任务
  - 0.7 ~ 1.0：创意任务

## 第二课：记忆（Memory）

### 为什么需要记忆

LLM 本身是**无状态**的——每次对话都是"失忆"的。需要我们自己管理对话历史。

### 四种记忆类型

| 类型 | 说明 | 适用场景 |
|------|------|---------|
| **ConversationBufferMemory** | 完整保存所有对话 | 短对话 |
| **ConversationBufferWindowMemory** | 只保留最近N轮 | 中等长度对话 |
| **ConversationSummaryMemory** | 自动摘要历史对话 | 长对话 |
| **ConversationSummaryBufferMemory** | 摘要+保留最近N轮 | 最优方案 |

### SummaryBufferMemory 原理

```
当对话太长 → 自动把"旧的对话"压缩成摘要
同时保留"最近几轮"的完整对话
这样既不会超出token限制，又能记住重要信息
```

## 第三课：链（Chains）

### LLMChain
最基础的链 = LLM + Prompt 模板

### SimpleSequentialChain
将多个链**串行连接**，上一个的输出 = 下一个的输入

```
链1: "生产{product}的公司是谁？" → "华为"
链2: "写一段20字介绍{华为}" → "华为是全球领先的ICT解决方案提供商"
```

> ⚠️ SimpleSequentialChain 只支持**单输入单输出**

### SequentialChain
支持**多输入多输出**的串行链

```python
chain_one: 输入 product → 输出 review（评价）
chain_two: 输入 product + review → 输出 response（回复）
```

### Router Chain（路由链）⭐重点

**核心思想**：根据问题类型，自动选择最合适的"专家链"

```
用户问题 → 路由判断 → 
    ┌→ 物理问题？  → 物理专家链
    ├→ 数学问题？  → 数学专家链
    ├→ 历史问题？  → 历史专家链
    └→ 都不匹配？  → 默认通用链
```

代码示例：
```python
# 定义不同的提示词模板
physics_template = """
你是一位著名的物理学教授。
你非常擅长以简洁且易于理解的方式解答物理学问题。
如果你不知道答案就回答不知道。

下面是问题：
{input}
"""

math_template = """
你是一位著名的数学家。
你非常擅长解答数学问题。
你擅长将复杂的数学问题分解为多个小问题，最后合并解决。

下面是问题：
{input}
"""

# 定义候选提示词信息
prompt_infos = [
    {"name": "物理", "description": "擅长回答物理学问题",
     "prompt_template": physics_template},
    {"name": "数学", "description": "擅长回答数学问题",
     "prompt_template": math_template},
]

# 构建路由链
from langchain.chains.router import MultiPromptChain
from langchain.chains.router.llm_router import LLMRouterChain, RouterOutputParser

# 构建 destination_chains 字典
destination_chains = {}
for p_info in prompt_infos:
    name = p_info["name"]
    prompt_template = p_info["prompt_template"]
    prompt = ChatPromptTemplate.from_template(template=prompt_template)
    chain = LLMChain(llm=llm, prompt=prompt)
    destination_chains[name] = chain

# 创建默认链
default_chain = LLMChain(llm=llm, prompt=ChatPromptTemplate.from_template("{input}"))

# 构建路由提示词
destinations = [f"{p['name']}: {p['description']}" for p in prompt_infos]
destinations_str = "\n".join(destinations)

MULTI_PROMPT_ROUTER_TEMPLATE = """请为下面的原始输入选择最适合的候选提示词。\
你将获得候选提示词的提示名称和适合领域的描述。\

<< 格式 >>
请返回包含 JSON 对象的 Markdown 格式：
```json
{{
    "destination": string,
    "next_inputs": string
}}
```
其中："destination" 必须是下面候选提示词的名称或 "DEFAULT"

<< 候选提示词 >>
{destinations}

<< 原始输入 >>
{{input}}

<< 输出 (记得包含 ```json)>>"""

router_template = MULTI_PROMPT_ROUTER_TEMPLATE.format(destinations=destinations_str)
router_prompt = PromptTemplate(
    template=router_template,
    input_variables=["input"],
    output_parser=RouterOutputParser(),
)

router_chain = LLMRouterChain.from_llm(llm, router_prompt)
chain = MultiPromptChain(
    router_chain=router_chain,
    destination_chains=destination_chains,
    default_chain=default_chain,
    verbose=True
)

# 使用
chain.run("什么是丁达尔效应？")  # 自动路由到"物理"链
chain.run("什么是九一八事变？")  # 自动路由到"历史"链
```

## 第四课：基于文档的问答（RAG）⭐重点

### 完整流程

```
步骤1: 文档加载 (CSVLoader, PDFLoader, JSONLoader...)
步骤2: 文本分割 (TextSplitter → 切成小块)
步骤3: 向量嵌入 (Embedding → 文字→数字向量)
步骤4: 存入向量数据库 (Chroma, Faiss, Pinecone...)
步骤5: 用户提问 → 向量检索 → 找最相似的文档块
步骤6: 文档块 + 问题 → 拼成Prompt → 发给LLM → 得答案
```

### 什么是Embedding（嵌入）？

```
"你好" → [0.52, -1.34, 2.17, 0.89, -0.43, ...]（数千维向量）
"您好" → [0.51, -1.32, 2.15, 0.91, -0.41, ...]（非常接近）
"苹果" → [1.23, 0.87, -0.34, -1.56, 2.01, ...]（差异很大）
```

相似文字 → 相似向量。这就是语义搜索的基础。

### 步骤分解实现

```python
from langchain_community.document_loaders import CSVLoader
from langchain_community.embeddings import OllamaEmbeddings
from langchain_community.vectorstores import DocArrayInMemorySearch
from langchain.chains import RetrievalQA

# 步骤1：加载文档
loader = CSVLoader(file_path="product.csv")
docs = loader.load()

# 步骤2+3：创建嵌入
embeddings = OllamaEmbeddings(base_url="http://localhost:11434", model="qwen2")

# 步骤4：存入向量数据库
db = DocArrayInMemorySearch.from_documents(docs, embeddings)

# 步骤5+6：创建问答链
retriever = db.as_retriever()
qa = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=retriever,
    verbose=True
)

# 提问
response = qa.run("请列出带有智能功能且节能环保的电器")
```

### 四种问答链类型（chain_type）

| 类型 | 方式 | 优点 | 缺点 |
|------|------|------|------|
| **stuff** | 所有文档块一起发给LLM | 简单有效 | 文档多了超token限制 |
| **map_reduce** | 每个文档块单独回答，再汇总 | 可并行，无数量限制 | 独立处理，丢失关联 |
| **refine** | 逐块处理，每次基于上次结果 | 保留文档间关联 | 串行，速度慢 |
| **map_rerank** | 每块打分，选最高分答案 | 快速 | 多次调API，费用高 |

实践推荐：文档量小 → stuff；文档量大 → map_reduce

## 第五课：Agent（代理）⭐最重要

### Agent 是什么

Agent = LLM 不只是回答问题，而是作为**推理引擎**自主决策：

```
用户："帮我查一下2024诺贝尔物理学奖得主，并总结他的贡献"

Agent思考：
1. 我需要知道得主是谁 → 调用维基百科搜索
2. 查到了得主 → 需要总结贡献 → 再调用维基百科搜索
3. 信息够了 → 生成总结
4. 返回用户
```

### Agent核心循环：ReAct 范式

```
Observation（观察）: 用户说了什么？当前有什么信息？
    ↓
Thought（思考）: 我需要什么才能回答问题？
    ↓
Action（行动）: 调用工具（搜索、计算、读文件...）
    ↓
Observation（观察）: 工具返回了什么？
    ↓
... 循环直到可以回答 ...
    ↓
Final Answer（最终答案）
```

### Agent 的组成

```
Agent = LLM + 工具集 + 决策逻辑

决策逻辑：
- 我现在有足够信息回答吗？ → 回答
- 不够？需要哪个工具？ → 调用工具
- 工具结果对吗？ → 不对就换一个工具
```

### 内置工具 vs 自定义工具

**LangGraph 内置工具示例**：
```python
from langchain_community.tools.wikipedia.tool import WikipediaQueryRun
from langchain_community.utilities.wikipedia import WikipediaAPIWrapper
from langgraph.prebuilt import create_react_agent

# 维基百科工具
wikipedia = WikipediaQueryRun(api_wrapper=WikipediaAPIWrapper())

# 文件管理工具
from langchain_community.tools.file_management import ListDirectoryTool
list_dir = ListDirectoryTool()

# 创建 Agent
tools = [wikipedia, list_dir]
agent = create_react_agent(llm, tools)
```

**自定义工具**：
```python
from langchain.tools import tool

@tool
def get_current_time(text: str) -> str:
    """获取当前时间，当用户问"现在几点"时调用"""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")
```

## 第五课（续）：评估（Evaluation）

### 为什么要评估

当构建一个复杂的 LLM 应用时，比较重要但又困难的是如何去评价应用的效果。切换不同的 LLM 模型、向量数据库或参数时，如何去评价结果是变好了还是变坏了。

### 使用 QAGenerateChain 自动生成测试题

```python
from langchain.evaluation.qa import QAGenerateChain

# 创建测试集生成链
example_gen_chain = QAGenerateChain.from_llm(llm)

# 自动为每条文档生成测试问题和答案
new_examples = example_gen_chain.apply_and_parse(
    [{"doc": t} for t in data[:5]]
)
```
