## 零、内容深度保证机制 v3.1

> **v3.1核心变更：notebook的内容深度由每周详细教学规格驱动，而非从v5.0学习计划的高层摘要"脑补"。**

### 为什么需要这一节

v5.0学习计划提供的是**高层描述**（如"W1D1：变量/赋值、int/float/str/bool/None"）。但每周详细教学规格包含了真正决定深度的内容：

- **底层机制**：动态数组O(1)摊销、哈希表原理、IEEE 754双精度、`id()`对象身份……
- **陷阱细节**：`lst2=lst1`是引用不是拷贝、`(1)`不是tuple、`{}`是空dict不是空set、elif条件顺序……
- **跨天连接**：D1的容器→D2的遍历对象、D2的for+if→D3函数体的"肌肉"、D3的函数→D4的IO封装……
- **深度检测标准**：L2/L3/L4的具体检测问题

**教学规格是单一事实来源（Single Source of Truth）。** notebook不是从标题"脑补"深度的——它从教学规格中**提取**深度。

### 教学规格文件定位

```
notes/course_specs/{月份序号}_{周标识}_每日教学规格.md
```

| 周 | 文件路径 |
|----|---------|
| W1 | `notes/course_specs/01_W1_每日教学规格.md` |
| W2 | `notes/course_specs/02_W2_每日教学规格.md` |
| W3 | `notes/course_specs/03_W3_每日教学规格.md` |
| ... | ... |

每个文件中以`## W{X}D{Y}：{能力簇名称}`标记对应天的规格。

## 零-A、生成前强制流程（Phase 0——不可跳过）

**每个notebook生成前，必须先完成以下5步，缺一不可。** 跳过此流程直接生成 → 内容必然肤浅。

### 步骤1：读取教学规格

根据W{X}D{Y}定位教学规格文件 → 读取对应天的完整规格（从`## W{X}D{Y}`标题到下一个`## W{X}D{Y+1}`标题之间的全部内容）。

### 步骤2：提取深度知识清单

从教学规格的"具体知识清单"中提取**每一个条目和子条目**，形成`深度覆盖清单`。例如W1D1的清单：

```
□ 变量与赋值
  □ 变量名规则（字母/数字/下划线，不能数字开头）
  □ 动态类型（同一变量可先后指向不同类型）
  □ =是"贴标签"不是"装盒子"（引用语义）
  □ id()查看对象身份
  □ 多重赋值 a, b = 1, 2
□ 核心数据类型
  □ int任意精度（不溢出）
  □ float IEEE 754双精度（0.1+0.2!=0.3）
  □ str不可变
  □ bool真值测试（bool(0)=False, bool([])=False）
  □ None不是0/空字符串/False
  □ type()查看类型
...（list/dict/set/tuple的全部子条目）
```

**约束**：每个子条目都必须有对应cell覆盖。不能合并、不能简化、不能跳过。

### 步骤3：提取陷阱清单

从教学规格的"必须覆盖的陷阱"中提取**全部陷阱**。规格中列了几个就覆盖几个，不能只挑"最常见的"。

### 步骤4：提取连接点

从教学规格的"连接点"中提取所有跨天/跨周关系。这些内容分配到各概念讲解的③段（"跟你X天前学的XX的关系"）。

### 步骤5：深度覆盖检查

逐项确认清单上的每个知识点都已分配到具体cell。通过后才能开始写notebook正文。未通过 → 补充分配 → 再检查。

**关键约束**：
- 规格中写了`id()` → notebook必须讲`id()`，不能省略
- 规格中写了"IEEE 754双精度" → notebook必须讲`0.1+0.2!=0.3`，不能省略
- 规格中写了"底层：动态数组，append均摊O(1)" → notebook的④段必须包含此描述
- 规格中写了"陷阱：`if a==3 or 4`→永远True" → 陷阱cell必须包含此陷阱
- 规格中的全部陷阱都要进入陷阱cell，**不能只挑"最常见的"几个**

## 一、底层原理：人类到底是怎么学会的（不变的基础）

### 原理1：好奇心先于内容（Zeigarnik效应）
→ 每个能力簇由认知冲突引出。禁止"今天我们来学X"。
**大脑不保留它没有主动想要的信息。** 未完成的认知任务会产生心理张力，驱动你去完成它。这就是为什么"猜谜语"比"看答案"记得更牢。

→ **设计决策**：每个概念必须由一个"你现有知识搞不定的微问题"引出。用户必须先感受到"我需要新武器"，再看到新武器。禁止上来就"今天我们来学X"。


### 原理2：具象先于抽象
→ 白话类比先于术语。先看到3个例子再归纳规律。
**人类大脑通过具体案例归纳出规律，不是通过抽象定义演绎出应用。** 先看到3个不同的"筛选订单"的例子，自然理解"筛选"这个概念；先看到定义再做题，大脑没有锚点。

→ **设计决策**：每个概念先说"说白了就是..."举一个生活中的例子，再说"在我们的数据里它长这样"。术语放在最后。


### 原理3：提取练习效应（Retrieval Practice）
→ **硬性：练习cell ≥ 讲解cell。每日练习cell ≥7个。目标占比 ≥55%。**

**主动回忆并应用信息的记忆效果，是被动重读的3-5倍。** 挣扎着解出一道题，比顺畅地看完一段讲解，记忆强度差一个量级。

→ **设计决策**：每个notebook至少50%的cell是练习（不是阅读）。用户必须在没有提示的情况下独立写出代码。练习之间不要插入讲解。


### 原理4：工作记忆上限（4±1 chunks）
→ 每天2-4个概念，但打包成1个"能力簇"（协同使用的概念群）。

### 原理5：错误驱动的学习（Error-Driven Learning）
→ 每个练习后必须有偏差诊断表：≥3种常见错误→误解→补救路径。
**犯错后纠正形成的记忆，比直接做对更强。** 但前提是反馈必须即时、具体、附带"为什么错了"的解释。

→ **设计决策**：每个练习后面不是"答案：XX"，而是"如果你的答案跟参考不同，你可能的误解是XX。如果是偏差A→回到cell Y重看，如果是偏差B→做额外练习Z"。


### 原理6：间隔重复（Spaced Repetition）
→ 概念在D+2/D+4/W+1/W+3强制复现。每周SQL持续练习。周日复习日刻意召回。
**一次学透>学完一周后全忘。** 新概念必须在第2天、第4天、第7天、第30天重新出现，每次出现间隔拉长，记忆才能固化。

→ **设计决策**：每周六的复习notebook会刻意召回前5天的概念；每周日的周项目要求同时使用本周所有概念；第4周会重新用到第1-2周的概念。


### 原理7：连接到已有知识
→ 每个能力簇必须说明"跟你X天前学的XX是什么关系，能组合做什么"。
**新信息只有挂在旧信息上才能被检索到。** "这个就像你之前学的XX，但用在YY场景"——这种类比构建记忆的提取路径。

→ **设计决策**：每个新概念的讲解中，必须有一句"这个跟你X天前学的XX是什么关系"。每天的第一个cell必须列出今天所需的前置知识。

### 原理8：情感投入决定记忆强度
→ 贯穿沙盘从生活经验出发。进阶题换行业场景。项目周给真实业务问题。
**大脑优先记住"对我重要"的信息。** 如果用户觉得"学这个干嘛，跟我有什么关系"，再好的讲解也白搭。

→ **设计决策**：贯穿案例必须从用户的生活经验出发，角色设定让用户有代入感（"你是数据分析实习生，mentor要你..."）。每天解决的业务问题必须让用户觉得"这个问题确实需要解决"。

## 二、Notebook类型与结构

v5.0计划中有4种Notebook类型：

| 类型 | 使用日 | 核心特征 |
|------|--------|---------|
| **新概念日** | 周一-周四、部分周六 | 认知冲突→讲解→7+练习→反馈→自检 |
| **综合练习日** | 部分周五 | 全周概念混合，8+道题 |
| **周项目日** | 周六 | 贯穿沙盘，完整业务问题 |
| **复习日** | 周日 | 闭卷自测+错题回溯+知识漏洞清单 |

---

### 类型1：新概念日（最重要，占60%天数）

#### 硬性约束

| 约束项 | 标准 | 不达标后果 |
|--------|------|-----------|
| 练习cell数 | **≥7个** | 练不够=学不会 |
| 练习cell占比 | **≥45%**（因新增逐概念讲解cells，总cells数增加） | 讲解太多=被动接收 |
| 核心概念数 | 2-4个，打包为1个能力簇 | 多了消化不了 |
| 场景多样性 | **≥2个不同行业/产品场景** | 不换场景=无法迁移 |
| 陷阱/坑专题 | **教学规格中列出的全部陷阱**，每个含❌✅代码对比 | 少一个=用户就可能踩那个坑 |
| 偏差诊断 | **≥3种**常见误解 | 只有答案=不知道错在哪 |
| 知识点覆盖率 | **教学规格"具体知识清单"100%覆盖** | 漏一个=用户少学一个知识点 |

#### Cell 结构（约24-28 cells，v3.1重构）

**核心变化（v3.1）**：旧版的[cell 3]"核心能力簇讲解"把2-4个概念全塞进一个cell——变成文字墙，深度内容被压缩。新版**每个概念独立展开**，拥有自己的微认知冲突→四段式讲解→落地代码→即时小练习。

```
=== 开头（3 cells）===

[cell 0]  标题 + 今日目标 + 知识清单预览
          ↑ v3.1新增：列出教学规格中今天的全部知识点条目，作为用户的"学习地图"
[cell 1]  🔴 认知冲突（全局微问题）
[cell 2]  沙盘衔接（仅周二起需要，周一跳过）

=== 概念逐个展开（2-4个概念，每个3-4 cells = 6-16 cells）===

[cell 3a] 概念1的微认知冲突（markdown）
          针对这一个概念，三模式选一
[cell 3b] 概念1的四段式讲解（markdown）
          ①白话 ②沙盘用法 ③与前置概念的关系 ④为什么这样设计
          ↑ ④段必须包含教学规格中的底层机制描述
[cell 3c] 概念1落地代码（≤8行）
[cell 3d] 概念1即时小练习（code cell，可选——大概念必做，小概念可跳过）

[cell 4a-4d] 概念2同上
[cell 5a-5d] 概念3同上
...（最多4个概念）

=== 综合练习（7个code cells）===

[cell N]   基础练习×2（L2：能用，沙盘场景照猫画虎）
[cell N+1] 进阶练习×2（L3：能讲，换行业场景，至少1题新行业）
[cell N+2] 挑战练习×2（L4：能判断，开放性问题）
[cell N+3] 迁移练习×1（L4：全新领域，用户自己选武器）

=== 陷阱与反馈（3 cells）===

[cell traps]     常见陷阱（教学规格列出的全部陷阱，每个❌✅代码对比）
[cell feedback]  参考答案 + 偏差诊断（≥3种常见误解+补救路径）
[cell closure]   回到冲突（用今天的武器解决开头的问题）

=== 自检与预告（2 cells）===

[cell selfcheck] 自检清单 + 教学规格深度覆盖确认
                 ↑ v3.1新增：概念掌握检查表——教学规格知识点逐项打勾
[cell preview]   明日预告 + 今日概念在本周知识网络中的位置
```

---

#### 逐Cell规范

##### Cell 0：标题 + 今日目标 + 知识清单预览

```markdown
# W{X}D{Y}：{能力簇名称——能做什么}

**今天要解决的问题**：{用"你"开头，业务语言，不是技术语言}
**你要用到的武器**：{2-4个概念名，用+连接}
**需要的前置知识**：{诚实列出，没有写"无"}

---

### 📋 今日知识地图

{从教学规格"具体知识清单"提取全部条目，以checkbox列表呈现}

- [ ] 变量与赋值：变量名规则、动态类型、`=`是贴标签、`id()`、多重赋值
- [ ] 核心数据类型：int/float/str/bool/None、type()、类型转换
- [ ] list：创建/索引/切片/方法、底层动态数组O(1)、`lst2=lst1`陷阱
- [ ] tuple：不可变/可哈希/单元素逗号
- [ ] dict：创建/取值/遍历、底层哈希表O(1)、key必须不可变
- [ ] set：去重/成员判断O(1)、`{}`是空dict陷阱
- [ ] 容器选择决策树：7种场景选容器+论证

---
```

**约束**：知识清单直接来自教学规格，不能删减条目。

##### Cell 1：🔴 认知冲突（全局）

**三种模式选其一**：

| 模式 | 适用场景 | 示例框架 |
|------|---------|---------|
| **撞墙型** | 引入全新能力 | 给一个任务，用户用现有工具做不了或极其费劲 |
| **错误暴露型** | 引入防护/纠偏概念 | 展示"看起来对了但藏了致命bug"的代码 |
| **对比冲击型** | 引入效率/工具概念 | 展示"用新工具1行"vs"用旧工具30行" |

**约束**：
- 1个cell，不更长
- 不要用户答对——答不对才说明"需要新武器"
- 结尾一句过渡："你刚才遇到的问题，今天要学的XX就是专门解决它的。"
- 场景必须在用户生活经验范围内（外卖/电商/短视频/出行/游戏/社交）

##### Cell 2：沙盘衔接（周二起需要）

```markdown
**回到{公司名}**：昨天你{做了什么}，mentor{反馈}。今天{新情况}：

> {mentor口语原话}
```

≤5行。mentor话必须口语化。周一跳过此cell。

##### Cell 3a-3d / 4a-4d / ...：概念逐个展开（v3.1核心重构）

**每个概念独立一组cells，不可多个概念合并。**

###### 概念微认知冲突（每个概念的cell a）

```markdown
### 🤔 {概念名}——你现有的知识够用吗？

{一个针对该概念的微问题。三模式选一：}

- 撞墙型："你现在用list可以存5笔订单金额，但如果小王问你'第3笔是谁的订单'——list只知道金额不知道谁是谁，怎么办？"
- 错误暴露型："下面这段代码创建了一个'集合'，但运行后type()显示是dict——哪里错了？"
- 对比冲击型："用list判断'上海在不在10000个城市里'→10000次比较。用set→1次。差10000倍。"

{结尾过渡：}"你刚才撞到的这个墙，{概念名}就是专门解决它的。"
```

**约束**：1个markdown cell，微问题必须针对该概念而非整个能力簇。

###### 概念四段式讲解（每个概念的cell b）

```markdown
### {概念名}

**① 说白了就是**：{一句人话类比，从生活经验出发。假设读者完全不懂}

**② 在沙盘里怎么用**：{3-5句话，具体到数据、操作、结果}

**③ 跟你{X天前}学的{前置概念}的关系**：{一句话+一个组合用法}
   {来自教学规格"连接点"的内容}

**④ 为什么这样设计**：{来自教学规格的底层机制描述。必须覆盖规格中的内容，不能简化。}
   {例如list：底层动态数组→append均摊O(1)、insert O(n)→什么时候用list什么时候不用}
   {例如dict：底层哈希表→O(1)查找→key必须不可变（哈希值不能变）→list不能做key}
   {例如float：IEEE 754双精度→0.1+0.2!=0.3→金融计算用Decimal}
```

**约束**：
- 禁止术语先于白话
- "说白了"不能出现代码
- ④段**必须**包含教学规格中该概念的底层机制描述——这是深度的关键来源
- ④段不只是"为什么需要它"，还包括"没有它的时候人们怎么做"和"设计带来的代价"
- 教学规格的"连接点"内容必须出现在③段

###### 概念落地代码（每个概念的cell c）

```markdown
### {概念名}长这样：

{极简代码示例，≤8行}
```

**约束**：代码≤8行、数据必须来自沙盘、不能是后面练习的答案、注释标注关键语法点。

###### 概念即时小练习（每个概念的cell d，可选）

```markdown
**{概念名}小练**：{一句话任务}

{留code cell给用户写代码}
```

**约束**：仅1题，只检验该概念的掌握度。大概念（list/dict/for/def）必须有。小概念（tuple/enumerate/三元表达式）可跳过或合并到综合练习。即时反馈放在cell d末尾（≤3行参考答案）。

---

##### 递进练习（7个code cells，结构不变）

**v3.1增强：场景多样性+知识点标注。** 进阶题必须换行业场景。迁移题必须让用户自己判断用什么武器。每道题标注"覆盖教学规格知识点：[具体条目]"。

```
基础练习（2题）
  - 沙盘场景
  - 照猫画虎，刚看完讲解就应该能写出来
  - 目标：L2（能用）
  - 如果做不出→回对应概念的cell b-c重看

进阶练习（2题）
```

## 四、深度标准与检验

### 深度四级

| 级别 | 标准 | 检测方式 | Notebook位置 |
|------|------|---------|------------|
| **L1：知道** | 能认出概念，知道它是干什么的 | "sort_values是排序" | 各概念的讲解cell (cell b) |
| **L2：能用** | 在原场景独立写出正确代码 | 基础练习完成 | 各概念即时小练习 + 综合基础练习 |
| **L3：能讲** | 能白话解释+对比选择+知道为什么这样设计 | 中级自检写200字解释 | 概念讲解cell b第④段 + 自检清单中级 |
| **L4：能判断** | 新场景中自己选工具+论证+讲出局限 | 迁移练习完成 | 迁移练习 + 自检清单高级 |

**每个新概念日必须推到L3，目标L4。** 综合练习日和项目日检验L4是否达成。

### 禁止的假深度

| 假深度 | 为什么假 | v3.0替代做法 |
|--------|---------|------------|
| 罗列5个子知识点 | 广度≠深度 | 只讲2-4个，推到"为什么这样设计" |
| 所有练习在同一场景 | 不变场景=无法迁移 | 进阶必须换行业，迁移必须全新领域 |
| "做不出来正常" | 给放弃发许可证 | "至少试15分钟，写下你的思路" |
| 自检只是打勾 | 没实际产出=没检验 | 中级必写一段话，高级必写代码 |
| 讲源码实现 | 对初学者是噪音 | 讲"为什么这样设计"而不是"源码怎么写的" |
| **从高层计划脑补深度**（v3.1新增） | 高层计划只有概念名，没有底层机制 | **强制读取教学规格**——规格写了什么就教什么 |
