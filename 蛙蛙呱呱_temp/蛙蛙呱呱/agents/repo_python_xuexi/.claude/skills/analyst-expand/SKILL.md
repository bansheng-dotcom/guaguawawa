## 第二部分：深度审计规则

### 2.1 核心铁律

**拓展 ≠ 主课内容换场景重练。拓展 = 主课没教但分析工作需要的知识。**

每个被选入拓展的概念必须通过以下三道审计：

```
审计1: 这个主课教了吗？
  教了 → ❌ 不选（除非是核心深化且主课只讲了"是什么"没讲"为什么"）
  没教 → ✅ 进入审计2

审计2: 后续课程会教吗？
  会教 → ⚠️ 只能作为[预览]，标注"WX深入"，且篇幅≤总拓展的10%
  不会教 → ✅ 进入审计3

审计3: 能自包含讲清楚吗？
  能（不需要未学的前置知识） → ✅ 入选
  不能 → 只作为延伸阅读一行带过
```

### 2.2 深度类型要求

不是所有"深"都一样。每个入选概念必须至少匹配一种深度类型：

| 深度类型 | 含义 | 在文档中的体现 | 适用场景 |
|---------|------|--------------|---------|
| **数学深度** | 从公式/推导层面理解 | 公式 + 手算示例 + 代码实现 | 统计概念（CI、标准误、效应量） |
| **代码深度** | 能写代码实现/检测/自动化 | 可运行的类/函数 + 测试用例 | 检测器、自动化工具 |
| **案例深度** | 在多场景中判断何时用/何时不用 | 3+个对比场景 + 边界判断 | 框架选择、方法论决策 |
| **历史深度** | 理解"这个框架发明之前人们怎么做" | 历史脉络 + 结构合理性分析 | 框架/模型（为什么是这几个元素） |
| **博弈深度** | 理解"如果我把这个当KPI，团队会怎么博弈" | 博弈模式枚举 + 反制策略 | 指标设计、KPI设定 |
| **工程深度** | 从"概念"到"生产级代码/系统" | 完整SQL/看板设计/数据字典 | 数据口径、自动化、看板 |

**规则**：一个拓展文档中，≥60%的概念必须匹配"代码深度"或"数学深度"。这是因为代码和数学是最难伪造的深度——它们强迫你给出可验证的输出。

### 2.3 禁止事项

| 禁止 | 原因 | 替代做法 |
|------|------|---------|
| ❌ 把主课指标重命名后当新概念 | 没有增量知识 | 如果主课讲了"好指标5条"，拓展应该讲"用代码验证你的指标是否满足5条" |
| ❌ 只用沙盘场景变化代替深度 | 沙盘是载体，不是内容 | 新沙盘中必须引入新的分析工具/方法 |
| ❌ "这个概念很重要，WX会学" | 裸引 | 自包含讲清基本思路，标注"WX深入细节" |
| ❌ 拓展概念之间无关系标注 | 用户不知道怎么协同使用 | 每个概念必须标注关系类型（前置/并行/防护/落地/替代） |
| ❌ 练习只有"请填空"没有反馈 | 用户不知道自己理解偏了 | 每个练习必须有：答案 + ≥2种常见偏差 + 补救路径 |

## 第三部分：执行流程

### Phase 0: 课程感知（必须最先执行）

在读取目标 notebook 之前，先完成以下步骤：

**0a. 读取目标 notebook 的元信息**
- 提取轨道（03 analyst_thinking_learn）
- 提取周数（week_XX）和天数（day_XX）
- 确定课程阶段（入门W1-W2 / 成长W3-W4 / 熟练W5+）

**0b. 定位课程位置**
- 在同一周内，哪些概念已经教了（前两天）？
- 在同一周内，哪些概念即将教（后几天）？
- 在后续周中，这个主题是否有深入版本？

**0c. 读取主课程知识清单**
从目标 notebook 中提取：
- 核心概念名称和结构元素
- 主课程已覆盖的子概念
- 主课程提到但未展开的"引子"（如"这里涉及辛普森悖论，我们不展开"）
- 主课程的练习类型和难度
- 跨模块连接中提到的"扩展阅读"引用

**0d. 交叉验证（必须执行）**
- 用 Glob 扫描目标目录下 `拓展_*.ipynb`，读取每个拓展的标题和核心概念，动态生成"已覆盖清单"
- 用内置知识地图（见 1.1）确认：核心概念在后续课程中是否深入？
- **读取永久空白区文档**：`D:\python_xuexi\new_learn\analyst_thinking_learn\全课程永久空白区.md`
- 从空白区文档中，按目标课程日筛选 P0 > P1 > P2 候选概念
- 交叉比对：该概念是否已被其他拓展覆盖？是否与目标课程日的核心概念有明确的关系类型？

### Phase 1: 概念选材

基于 Phase 0 的结果，按下表选择拓展概念：

```
核心概念：{从主课提取}

已覆盖（主课+已有拓展）：
  ├── 概念A — 已被W?D?覆盖 → 不选
  ├── 概念B — 已有拓展深度覆盖 → 不选
  └── ...

将学（后续课程）：
  ├── 概念C — W?会深入 → 只能[预览]
  └── ...

永久空白（最优候选）：
  ├── [前置] 候选 → 选1-2个
  ├── [并行] 候选 → 选1-2个
  ├── [防护] 候选 → 选1-2个（优先选有代码实现的）
  ├── [落地] 候选 → 选1个（必须含可运行的代码/SQL）
  ├── [替代] 候选 → 选1个
  └── 核心深化 → 必须选（如果主课只讲了"是什么"）
```

**选材优先级排序**：
1. 首先从永久空白区（1.3）选 —— 这些是最大增量
2. 其次从主课的"引子"中选 —— 这些是用户已知的需求
3. 再次从主课概念的"为什么"深化 —— 仅当主课只讲了壳
4. 最后才考虑预览 —— 仅标注关系，不展开

**概念总数**：
- W1-W2（入门）：5-8 个概念，必修 ≥60%
- W3-W4（成长）：7-10 个概念，必修 ≥50%
- W5+（熟练）：8-12 个概念，必修 ≥40%

**深度类型配比**：
- 代码深度 + 数学深度 ≥ 60% 的概念
- 每个[防护]概念必须至少有一个可运行的检测/验证代码
- 每个[落地]概念必须包含完整SQL或等效的生产级代码

### Phase 3: 文档生成

#### 文档骨架（6部分，与v3一致但每部分有深度增强）

```
[cell 0] 标题 + 知识网络预览 + 阅读指引
    - 标题格式：拓展：{核心概念}与关联知识网络
    - 必须标注：本拓展新增 {N} 个课程未覆盖的深度概念
    - 知识预览图（ASCII art）

第一部分：沙盘设定（cell 1-4）

第二部分：入口自诊（cell 5-6）
    - 只测主课程内容
    - 反馈格式：答案 + ≥2种常见偏差 + 补救路径

第三部分：概念网络展开（cell 7-N）
    每个概念群：
    [cell A] 🔴 认知冲突
    [cell B] 概念引入（三段式：白话→逻辑+例子→与核心概念的关系）
    [cell C] 在沙盘中的用武之地
    [cell D] 练习（代码 cell）
    [cell E] 反馈（答案 + 偏差诊断 + 补救路径）

    核心概念深化额外要求：
    - 历史脉络
    - 结构合理性分析
    - 沙盘初步应用

第四部分：综合沙盘演练（4题）
    题1: 多概念协同（需同时使用3+个概念）
    题2: 沙盘变体（改变关键参数，方案如何调整）
    题3: 边界判断（2-3个不同场景，判断是否适用）
    题4: 落地（业务→数据口径/看板；或代码→完整实现）

第五部分：知识网络图
    - 概念关系全景表
    - 关系图解
    - 三版本覆盖对比（主课程 vs 已有拓展 vs 本拓展）
    - 延伸阅读
    - 跨模块连接

第六部分：元认知自评
    - 学习循环自评表
    - 多维度自评量表（6个维度，每维度0-2分）
    - 薄弱点精准强化方案
    - 沙盘复述测试
    - 循环毕业检查清单
```

#### 关键生成规则

**规则 1：每个概念群必须有认知冲突 cell**

认知冲突不是"今天我们来学X"。它是一个微问题，用户尝试用现有知识解决时发现不够用。

三种模式：
- **撞墙型**（核心深化/前置/并行）：给一个现有知识解不了的问题
- **错误暴露型**（防护概念）：展示一个"看起来对了但有隐蔽错误"的案例
- **对比冲击型**（落地/替代）：展示"用新工具 vs 不用新工具"的差距

**规则 2：每个概念的三段式引入（顺序不可颠倒）**

```
① 一句话白话（"说白了就是……"）
② 核心逻辑 + 具体例子（复用沙盘数据/场景）
③ 与核心概念的关系（标注关系类型 + 原因）
```

**规则 3：练习必须可运行，反馈必须可诊断**

- 每个概念群 ≥1 个练习，至少 1 个是代码 cell
- 反馈格式固定为三列表：✅参考答案 | ❓≥2种常见偏差 | 🔧补救路径

**规则 4：综合沙盘必须验证迁移能力**

- 沙盘变体题：改变沙盘的阶段/规模/约束 → 方案怎么变
- 边界判断题：什么场景不该用核心概念
- 落地题：从概念到可交付产物
