# 取舍/优先级规则 · incident-escalation

1. **规则 → 升级链 → 时间线**：判定严格按此顺序。告警规则结构性错误（severity/
   channel 越界）优先级最高，其次升级链（level 单调、acknowledged 显式），
   最后才是事件时间线（ts 单调、resolved_at）。前一层不过，后一层不讨论。

2. **白名单是触达的保证，不是形式主义**。severity/channel 越界意味着通知系统
   无法正确处理这条告警。宁可拒绝重写，也不放行一条发不出去的告警。

3. **升级链只许从低到高逐级**。level 严格单调递增（无重复、无回退）是硬约束。
   跳级到 CEO = 沟通事故；先逐级确认，让能处理的人先处理。

4. **时间线单调是「对外事实」的底线**。ts 倒挂 = 对外失实。先如实记录时间线，
   再对外通报。resolved 必须带 resolved_at，否则事件永远「悬着」。

5. **越界即移交**：故障严重性的业务影响评估归 R01/R02；实际发送通知/呼叫值班
   是运行期动作；改生产告警规则归人工授权（红线 2）。R20 只产出策略工件。
