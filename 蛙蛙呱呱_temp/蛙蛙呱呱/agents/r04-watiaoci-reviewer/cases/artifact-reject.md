# SOP：交付物证据链缺失的驳回裁定（R04 蛙挑刺）

## 1. 逻辑导图

```text
[异常/诉求输入] → [L1 数据与证据真实性] → [L2 维度下钻：L2 实质性证据完备度]
                → [L3 外部锚点对齐] → [决策指令] → [护栏熔断] → [阶梯灰度]
```

## 2. 核心指标口径

| 指标 | 公式 | 单位 | 目标 | 告警 |
| :--- | :--- | :---: | :---: | :--- |
| L2 实质性证据完备度 | `已提供实质证据条目 / 应提供条目` | % | 100% | < 100% 即刻驳回 |
| 占位实现命中数 | `stub/TODO/NotImplemented 出现次数` | 处 | 0 | ≥ 1 判不通过 |

## 3. 分步诊断动作

1. 先查 L1：产物是否真的存在（文件/接口/记录）。
2. 再查 L2：内容是否有实质实现，还是只有占位与声明。
3. 再查 L3：是否真的接到调用链，而不是孤立文件。
4. 抽查事实：抽样 3 条结论回溯到源头，无源即驳。
5. 出裁定：PASS / 有条件 PASS / REJECT，每条附证据位置。

## 4. 门禁（不满足即阻断）

| 编号 | 触发条件 | 判定 | 处置 |
| :---: | :--- | :---: | :--- |
| G1 | L1 存在性通过但 L2 实质性为空 | BLOCKER | 判 REJECT，退回补证 |
| G2 | 发现 stub/TODO 占位实现 | BLOCKER | 判不通过，不得进入下游 |
| G3 | 结论无来源引用 | BLOCKER | 驳回并要求标注来源 |

## 5. 归因路径

- **L1 数据层**：先排除脏数据、断流、重复计数，确认是真实异动。
- **L2 经营层**：按维度下钻，锁定贡献度 ≥70% 的因子（本角色主维度见 KPI 表）。
- **L3 商业层**：对齐外部锚点，区分内因外因；未接入外部数据时只声明口径，不虚构大盘数字。

## 6. 禁用词与反例

- ❌「大幅提升」「表现良好」「值得期待」等无数据锚定的形容词。
- ❌ 只给建议不给阈值；只给阈值不给回滚动作。
- ❌ 把历史个案当通用结论，不做样本量说明。
