1A/B 测试怎么做：六个步骤

抖音商品店铺的 A/B 测试，本质是把流量随机分成两组、只改一个变量、用同一指标比较，再用统计检验判断差异是否可信。按下面六步走，可以避免「看着数据不错就全量」的常见错误。

  1. 先定假设与单一变量。

    一次只改一件事。本次实验只改「商品详情页」：新版高清主图、卖点前置、缩短加载、更强的「立即购买」按钮；价格、库存、投流、客服保持不变。假设写清楚：新版详情页能使下单转化率相对提升 ≥ 3%。

  2. 定主指标与护栏指标。

    主指标用「下单转化率」（下单人数 / 进店人数，0/1 二值）；次指标用「每用户营收」和「客单价（买家）」做归因。护栏指标看客单价不能暴跌——如果转化率靠打折换来的，客单价会明显下滑。

  3. 先算样本量与周期，再开实验。

    用功效计算（power）反推「每组需要多少用户」：基线转化率 5%、要检出的绝对提升 1 个百分点（5%→6%）、α=0.05、功效 80% 时，每组至少 8158 人、共 16316 人。14 天周期要覆盖完整周（工作日/周末流量结构不同），避免只跑一个周末。

  4. 随机分流，保持 50/50。

    用户进店即按随机算法分到对照组或处理组，同一用户全程固定在同一组，避免「串组污染」。分流后要检查两组是否真的大致均衡——这就是 SRM（样本比例失配）检测。

  5. 收数后做三层检验：显著性 → 效应量 → SRM。

    先看差异是否显著（Welch t 检验，p<α=0.05）；再看提升幅度（相对提升 lift）是否达到业务阈值（impact_min=3%）；最后看 SRM 卡方是否 >3.841 判失配。三层都过才下结论。

  6. 按决策表放量或重跑。

    决策规则只有三条：显著正、lift≥3%、SRM 正常 → ship（放量）；任一不满足 → no_ship；SRM 异常 → 重跑。放量后仍要监控 1~2 周，确认效果不回吐。

lift = (处理组均值 − 对照组均值) / 对照组均值   |   SRM χ² > 3.841 判失配

4.3 归因：提升来自转化率，不是客单价

两组「客单价（买家）」几乎持平（¥98.03 vs ¥98.86，+0.85%），而转化率提升 18.49%，因此营收提升（GMV +20.07%）主要来自「更多人下单」，而非「每人买更贵」。这说明新版详情页没有靠变相降价换量，护栏指标安全。

结论：ship（放量）。三项决策条件全部满足，且客单价未下滑，说明提升来自转化率而非降价。建议将新版详情页灰度放量至全量，并持续监控 1~2 周，确认转化率不回吐、客单价与退款率无异常。

建议动作

  1. 放量节奏：50% → 100% 分两步灰度，每步观察 3 天，防止突发技术或体验问题。
  2. 护栏监控：同步盯客单价、退款率、差评率、加载时长；任一护栏指标恶化即回滚。
  3. 沉淀结论：把「新版详情页提升转化率 18.49%」写入经验库，作为下次迭代的基线。
  4. 下一轮假设：可在新版基础上继续测「主图首图」「评论区置顶」「价格锚点」等单一变量。
