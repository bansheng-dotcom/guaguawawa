01一句话结论

先给判断，再给证据。

真正的门槛不是读代码，是同时握住几套互相矛盾的叙事。
新人读代码的速度不会是瓶颈；他会在“五套唯一入口、四套 claim 模型、六种 card、三层知识注入”之间反复确认“哪个才是真的”，这才是成本。

这个仓库的工程质量并不差：673 条单测、20 角色端到端全绿、门禁真跑且抓到过真问题（结构同构、图表契约、隐私扫描）。问题集中在命名过载与历史层叠——它们是“演进的副产品”，不是“水平不够”。所以方案也不应该是重写，而是收口。

4.3 同一概念四套模型，且各自都“唯一”

  • claims.py —— class Claim，论证层；
  • claims_v4.py —— claim → slice → encoding → findings；
  • claim_card.py —— 自称“决策级断言的唯一 schema”；
  • cell_claim.py —— 判断格 schema；
  • 再叠加 cells_claims.py（格子→claims）与 cells_unified.py（承认“同一格可能得到三个数”）。

为什么贵：“三套读数”写进了注释，说明这是已知债务。新人会以为自己理解错了，反复重读。

05升级方案总览

三批，每批可独立上线、独立回滚。先导航，后外壳，最后动模型。

批次主题动什么不动什么风险
批次一 导航与索引 文档、术语表、门禁索引 任何 .py 行为 零
批次二 外壳收敛 目录结构、唯一门面、导出表 业务逻辑与产物格式 中：import 断裂，用 shim 兜
批次三 模型收敛 claim / cells / prose / card 门禁判据、schema 版本号 高：需要兼容期

06批次一 · 导航与索引 零行为变更

目标：让新人在 90 分钟内建立正确地图，而不是靠猜。

动作产出验收
写术语表 docs/GLOSSARY.md（≤120 行） 定义 task card / probe card / ClaimCard / cell / Observation / ExperienceCard / SkillCard；声明“裸 card 禁止用于新代码”
重画核心地图 docs/CORE-MAP.md 一张图：入口 → 产线 → 拆卡 → 收卡 → 证据；每个模块只出现一次
门禁索引 scripts/gates_index.py → docs/GATES.md 从 configs/gates.yaml + 所有 check_* 生成：ID / 触发 / 失败含义 / 修复入口；28 个脚本 100% 登记
文档归档 docs/_archive/ + 每份头部 status 标记 docs/ 当前有效 ≤10 份；根目录 5 份入口文档
为什么先做这批：它是后面两批的“施工图”。没有术语表和入口图，分包与合并会被反复质疑“这到底是哪个 card”。

08批次三 · 模型收敛 需要兼容期

目标：同一件事只有一套模型、一个 schema、一个 validate。

收敛做法判据
claim 四合一 ClaimCard 为唯一内存模型；cells_claims 只做“格子 → ClaimCard”编译器；claims.py / claims_v4.py 标 deprecated，一版后删除 全仓只剩一个 SCHEMA 字符串、一个 validate
cells 三读数 cells_unified.observations() 为唯一读数；v1/v2/v3 入口从 CLI 移除，保留只读适配器 同一格不可能出三个数
prose 五合一 prose_contract（spec + style）+ prose_render（candidates + gen）；prose_critic 归 r04 改正文只需读 2 个文件
card 六合一 cards/pipeline.py = plan + issue + probe + bundle；task_frame 并入 card_plan 新增卡类型只改 1 处
版本词汇 代码里不再写 v10–v14；只保留 schema 版本（dsh.*/vN） 全仓“唯一入口”≤1 处
兼容期规则：旧 JSON 读取器至少保留一版；所有新写盘只产出新 schema；check_convergence 的违规数只许下降。禁止“一次删干净”。

09不做清单（明确不简化）

不动的部分原因
43 个门禁脚本它们是真护城河：F12 结构同构、图表契约、隐私扫描都抓到过真问题。要简化的是索引，不是检查。
20 个角色的 references/那是产品知识，不是代码债。先统一骨架，再逐步上收通用方法。
brief 七层契约 / 项目边界 / gate lock防的是“听起来专业但没出处”的报告，属于产品底线。
schema 版本号跨项目资产要可追溯；删除版本号会让旧报告无法复算。
role_runtime 这个抽象20/20 角色都接入了，是“共享层 + 薄 agent”的成功样板，后续收敛应复制它。

11新人上手路线
