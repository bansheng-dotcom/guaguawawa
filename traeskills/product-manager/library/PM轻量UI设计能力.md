# PM 轻量 UI 设计能力

## 1. 定位

这是产品管理 person 自己拥有的轻量 UI 能力，不依赖外部 UI 角色或本机插件。

PM 可以完成：

- 页面目标和用户动作定义。
- 信息架构、模块优先级、状态清单。
- 低保真布局说明。
- UI brief 和设计验收标准。
- 现有页面的产品体验初审。

PM 不做高保真视觉、设计系统、组件实现、真实截图像素级校准。

## 2. 轻量 UI 工作流

| 步骤 | 要回答的问题 | 输出 |
| --- | --- | --- |
| 页面任务 | 这个页面帮用户完成什么任务 | 页面目标 |
| 主动作 | 用户最重要的 1-3 个动作是什么 | 主按钮/主路径 |
| 信息优先级 | 第一眼看什么、第二眼看什么、可折叠什么 | 信息层级 |
| 低保真结构 | 页面分几块，每块解决什么 | 线框说明 |
| 状态清单 | 空态、加载、成功、失败、权限、异常怎么呈现 | 状态表 |
| 文案规则 | 标题、按钮、错误提示是否能被用户理解 | UI copy |
| 验收标准 | 做到什么算页面可用 | UI 验收 |

## 3. 输出模板

```md
# UI Brief

## 页面目标

## 目标用户和使用场景

## 主路径和关键动作

## 信息架构

| 区块 | 目的 | 优先级 | 主要内容 |
| --- | --- | --- | --- |

## 状态清单

| 状态 | 触发条件 | 用户看到什么 | 可用动作 |
| --- | --- | --- | --- |

## 低保真布局说明

## 文案与提示

## 验收标准
```

## 4. 设计判断规则

- 页面先服务用户任务，再服务内部组织结构。
- 主动作要显眼，次动作要可找到，危险动作要可确认。
- 数据页面必须写清筛选、排序、空数据、错误和导出状态。
- AI/自动化页面必须写清生成中、失败、重试、人工接管和审计状态。
- 低保真可以粗，但状态不能漏。

## 5. 禁止

- 不把低保真 brief 伪装成高保真设计。
- 不承诺具体设计系统、组件库或视觉 token。
- 不做像素级验收结论。
- 不跳过用户动作直接描述页面好看不好看。
