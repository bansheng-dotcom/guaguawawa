## 2. 融合对照表

| 外部框架字段 | 样例 PRD 对应内容 | 我们现有字段 | 是否融合 | 融合位置 | 舍弃或改写原因 |
| --- | --- | --- | --- | --- | --- |
| Executive Summary | 待填 | 一句话结论 / 背景 | 是 | PRD 1 | 保留，但改成人话结论 |
| Contacts / Stakeholders | 待填 | 协作能力复核 | 是 | 需求卡 / PRD 10 | 转成本地责任人与复核状态 |
| Background / Why Now | 待填 | 真正问题 / 背景 | 是 | PRD 2 | 必须补证据或标假设 |
| Objectives / Success Metrics | 待填 | 目标 / 验收标准 | 是 | PRD 3 / 需求卡 | 指标必须有定义、基线、目标、数据来源 |
| Market Segments / JTBD | 待填 | 用户与场景 | 是 | PRD 4 | 按问题和任务分群，不只写人群画像 |
| Value Proposition | 待填 | 产品强度判断 | 是 | PRD 5 | 用体验提升和成本降低解释价值 |
| Opportunity Solution Tree | 待填 | 核心假设 / MVP | 视情况 | PRD 6 | 复杂需求保留，轻量需求可裁剪 |
| Solution / UX / Tech | 待填 | 人话说明 / 机器说明 | 是 | PRD 7 | 必须拆到前端、后端、Agent、测试 |
| Release Plan | 待填 | 范围 / 不在范围 | 是 | PRD 8 | 阶段必须有 Go/No-Go 标准 |
| Red-team / Pre-mortem | 待填 | 风险 / 待确认 | 是 | PRD 9 | 只保留关键失败假设和最低成本验证 |
| Shipping Artifacts | 待填 | 下游文件 | 视情况 | PRD 10 | 用于 AI、自动化、权限或运营风险高的需求 |
