# 验收与测试场景质量指南

## 1. 这类报告做什么

验收与测试场景位于 PRD 和开发/测试之间。它把“需求写完了”变成“怎么判断做完了”。

| 输入 | 输出 |
| --- | --- |
| PRD | 验收标准 |
| 需求卡 | 测试场景表 |
| 用户流程 | 主路径和边界路径 |
| 数据/权限需求 | 状态变化和权限验证 |

## 2. 好验收的标准

| 标准 | 说明 |
| --- | --- |
| 可观察 | 能看到页面、接口、状态或数据结果 |
| 可复现 | 有前置条件、动作和预期结果 |
| 覆盖主路径 | 用户核心任务能完整验证 |
| 覆盖失败态 | 错误、权限、空数据、超时、回退不漏 |
| 绑定范围 | 只验本次范围，不扩大需求 |

## 3. Given/When/Then

| 字段 | 写什么 |
| --- | --- |
| Given | 前置条件、用户状态、数据状态、权限 |
| When | 用户动作或系统事件 |
| Then | 系统结果、页面反馈、数据变化、日志或通知 |

## 4. 常见状态

| 类型 | 示例 |
| --- | --- |
| 空态 | 没有数据、没有权限、首次使用 |
| 加载 | 请求中、后台任务中、排队中 |
| 成功 | 保存成功、生成成功、状态变更 |
| 失败 | 网络失败、校验失败、任务失败 |
| 权限 | 未登录、无权限、权限过期 |
| 回退 | 重试、取消、恢复、人工处理 |

## 5. 常见反模式

- “功能正常使用”这种不可检查描述。
- 只验成功路径，不验失败和权限。
- 验收标准混入新需求。
- 没写前置数据，导致测试无法复现。
- AI/自动化需求没有人工兜底。
