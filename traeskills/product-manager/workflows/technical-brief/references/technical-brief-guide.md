# 技术翻译报告质量指南

## 1. 好技术翻译的定义

好技术翻译不是把术语换成白话，而是让用户知道怎么判断、技术角色知道怎么接手。

| 模块 | 必须回答 |
| --- | --- |
| 用户影响 | 用户看到什么、能做什么、受什么限制 |
| 前端影响 | 页面、状态、入口、交互 |
| 后端影响 | 数据、接口、权限、任务、日志 |
| Agent 影响 | 输入、输出、工具、记忆、停止条件 |
| 失败兜底 | 出错时谁能查、怎么恢复、怎么人工处理 |

## 2. 常见反模式

- 只讲技术，不讲用户影响。
- 只说“后端支持”，不说数据从哪来。
- 自动化任务没有失败、重试、人工处理。
- 把架构争议包装成产品已确认。
