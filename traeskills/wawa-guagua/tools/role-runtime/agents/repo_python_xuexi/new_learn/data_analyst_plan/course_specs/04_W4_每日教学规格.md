### 具体知识清单

**1. matplotlib基础——每张图从创建画布到保存**
- **推荐写法**（面向对象API）：`fig, ax = plt.subplots(figsize=(12, 6))` → 然后`ax.plot(...)`。这种写法能精确控制每个元素
- **不推荐的写法**（pyplot状态机）：`plt.plot(...); plt.title(...)` → 多子图时容易被全局状态搞乱
- 画布大小：`figsize=(宽, 高)`单位是英寸。`(12,6)`=横向长方形适合趋势图，`(6,6)`=正方形适合分布图
- `fig, axes = plt.subplots(nrows, ncols, figsize=(w, h))` → axes是二维数组→`axes[0,0].plot()`。单行/单列时axes是一维数组
- **折线图**`ax.plot(x, y, marker='o', linestyle='-', color='#2196F3', linewidth=2, label='销售额')`：
  - marker参数：'o'圆点/'s'方块/'^'三角/'D'菱形。用来标注数据点
  - linestyle：'-'实线/'--'虚线/'-.'点划线/':'点线
  - color：十六进制颜色码或颜色名。常用：'#2196F3'(蓝)/'#FF9800'(橙)/'#4CAF50'(绿)/'#F44336'(红)
- **柱状图**`ax.bar(x, height, color=..., width=0.6)`：
  - width：柱宽。0.6=柱之间有间隙，1=柱紧挨着
  - `ax.barh(y, width)` → 水平柱状图→标签长时用（城市名/品类名不会旋转）
- **散点图**`ax.scatter(x, y, s=size, c=color, alpha=0.6, cmap='viridis')`：
  - s=点大小(面积不是半径!)→可传入一列值让点大小反映第三个维度
  - c=颜色→可传入一列值让颜色反映第四个维度
  - alpha=透明度→重叠点多时降低alpha看出密度
  - cmap='viridis'/'RdBu'/'coolwarm'→配色方案
- **直方图**`ax.hist(data, bins=30, edgecolor='white', density=False)`：
  - bins：柱数。太少→分布特征被掩盖。太多→全是噪声。`bins='auto'`让matplotlib自己算
  - density=True→变成概率密度(面积和=1)。False→频次
  - edgecolor='white'→柱子之间白线分隔→更好看
- **箱线图**`ax.boxplot(data, vert=True, patch_artist=True)`：
  - 箱体=Q1到Q3，中间橙线=中位数，须子=1.5IQR范围内的最远值，须子外=异常值(小圆点)
  - `patch_artist=True`→可以给箱体填色
- **饼图**`ax.pie(values, labels=labels, autopct='%1.1f%%', startangle=90, explode=explode)`：
  - autopct：显示百分比格式。`'%1.1f%%'`=一位小数
  - startangle：起始角度。`startangle=90`从12点方向开始
  - explode：某块突出。`[0,0.1,0,0]`→第二块突出
- **陷阱1：饼图类别>5→可读性灾难**。5块以上→图例密密麻麻→看不清。改用柱状图
- **陷阱2：直方图bins太多太少**都影响解读。不确定时用`bins='auto'`→50-100之间通常合适
- **陷阱3：`plt.savefig()`必须在`plt.show()`之前**。show()会清空当前figure→之后savefig得到空白图

**2. 子图与多面板**
- `fig, axes = plt.subplots(2, 2, figsize=(14, 10))` → 2行2列共4张子图。axes.shape=(2,2)
- `fig, axes = plt.subplots(1, 3, figsize=(18, 5))` → 1行3列。axes.shape=(3,)
- 遍历子图：`for ax, col in zip(axes.flat, df.columns[1:5]): ax.hist(df[col])`
- `fig.tight_layout(pad=2)` → 自动调整子图间距。pad=子图间距
- `fig.suptitle('鲜果多2025年销售分析', fontsize=16, fontweight='bold', y=1.02)` → 整张图的总标题
- 双Y轴`ax2 = ax1.twinx()`：销售额(柱状图/左轴)+利润率(折线/右轴)。两个Y轴通常不同色→区分
  - `ax1.set_ylabel('销售额(万元)', color='#2196F3')` → 左轴标签用蓝色
  - `ax2.set_ylabel('利润率(%)', color='#FF9800')` → 右轴标签用橙色
- **陷阱1：双Y轴容易误导**——两个轴的刻度范围不同→"看起来相交"的曲线并没有实际关系。使用时必须明确标注两轴刻度
- **陷阱2：tight_layout和suptitle可能重叠**→加`y=1.02`把总标题抬高

**3. 图表美化——从"能看"到"能放PPT给CEO看"**
- 标题必须是结论不是描述：
  - ❌ "月度销售额趋势图"
  - ✅ "Q2销售额逐月上升，6月环比增长15%至1280万元"
- `ax.set_title('...', fontsize=14, fontweight='bold', pad=15)` → pad加大标题和图的间距
- `ax.set_xlabel('月份', fontsize=12)` / `ax.set_ylabel('销售额(万元)', fontsize=12)`
- 图例`ax.legend(loc='best', frameon=True, fontsize=10)` — loc可选：'upper right'/'upper left'/'lower left'/'lower right'/'best'
- 网格线`ax.grid(True, alpha=0.3, linestyle='--', axis='y')` — axis='y'只在Y轴方向画网格(辅助读数)。axis='both'X和Y都画
- 数值标注`ax.bar_label(ax.containers[0], fmt='%.0f', fontsize=9)` — 柱状图顶部标具体数值
- 刻度调整`ax.tick_params(axis='x', rotation=45, labelsize=10)` — 长标签旋转45度避免重叠
- 配色方案：`sns.set_palette('Set2')`或自定义`colors=['#2196F3','#FF9800','#4CAF50','#F44336','#9C27B0']`
- 中文字体配置（三选一）：
  - Windows: `plt.rcParams['font.sans-serif'] = ['SimHei']`
  - Mac: `plt.rcParams['font.sans-serif'] = ['PingFang SC']`
  - 通用方案：`plt.rcParams['font.sans-serif'] = ['Microsoft YaHei', 'SimHei', 'PingFang SC']` → 逐个尝试
  - `plt.rcParams['axes.unicode_minus'] = False` → 解决负号显示为方块的问题
- 保存高清图：`fig.savefig('output.png', dpi=150, bbox_inches='tight', facecolor='white')`
  - dpi=150适合PPT，dpi=300适合印刷
  - bbox_inches='tight'→自动裁掉多余白边
  - facecolor='white'→背景白色(否则可能透明→在PPT里看不清)
  - `fig.savefig('output.png', dpi=150, bbox_inches='tight', facecolor='white', edgecolor='none')`

**4. seaborn统计图——一行代码出带有统计信息的图**
- `sns.barplot(x='品类', y='金额', hue='城市', data=df, estimator=sum, ci=None)` → 分组柱状图。estimator默认mean→想显示总金额写estimator=sum。ci=None关闭置信区间(数据量大时计算很慢)
- `sns.boxplot(x='城市', y='金额', data=df, palette='Set2')` → 每个城市一箱→一眼看出"哪城市中位数高""哪城市异常值多""哪城市分布广"
- `sns.violinplot(x='城市', y='金额', data=df)` → 比boxplot多展示分布形状(宽度=数据频率)。看出"双峰分布"(两种用户群混合)
- `sns.heatmap(corr_matrix, annot=True, cmap='RdBu_r', center=0, vmin=-1, vmax=1, fmt='.2f', linewidths=0.5)` → 相关性热力图。center=0→白色=0，红色=正相关，蓝色=负相关
- `sns.pairplot(df[['金额','利润','数量','评分']], diag_kind='kde', plot_kws={'alpha':0.5})` → 多变量关系矩阵。对角线=该变量的分布图
- `sns.countplot(x='城市', data=df, order=df['城市'].value_counts().index, palette='Set3')` → 频次统计图。order按频次降序排列
- **陷阱：seaborn的estimator默认是mean→你想显示总和的话要写`estimator=sum`**

**4.1 🔥Matplotlib架构层——理解Figure/Axes/Artist三层模型（v6.1补全）**

前面的matplotlib教学用的是"推荐写法"`fig, ax = plt.subplots()`，但没解释**为什么这样写**。理解三层架构=从"能画图"到"能控制图的每个像素"。

- **Figure（画布）→ Axes（坐标系）→ Artist（元素）**：
  - **Figure**：最顶层容器。一张图=一个Figure。`fig = plt.figure(figsize=(10, 6))`
  - **Axes**：实际绘图区域。一个Figure可以有多个Axes（子图）。**注意：Axes不是Axis！Axis是坐标轴刻度，Axes是包含坐标轴+数据+标题的整个子图区域**
  - **Artist**：可见的一切——线条、点、文本、图例、坐标轴刻度——都是Artist对象。每个Artist都可以被单独访问和修改
- **为什么用`fig, ax =`而不是`plt.plot()`**：
  - 状态机`plt.plot()`：最后一次调用`plt.figure()`隐式创建figure→全局状态→多子图时操作混乱→你不知道在改哪个子图
  - 面向对象`ax.plot()`：显式指定"我在这个ax上画"→控制精确→多子图不混乱→代码可读
  - **一句话**：简单图用`plt.plot()`交作业，生产环境用`ax.plot()`——能控制每个细节
- **Axes不是Axis！** Axis=坐标轴（x轴/y轴的刻度/标签），Axes=包含坐标轴+数据+标题的整个绘图区域
- **Figure → Axes的两种方式**：
  - `fig, axes = plt.subplots(2, 2)` → 一次性创建fig和2×2的axes。适合"我先规划好subplot布局"
  - `ax = fig.add_subplot(2, 2, 1)` → 逐个子图添加。适合"动态决定子图数量"或"不规则布局"
- **GridSpec不规则布局**（当subplots的规整网格满足不了需求时）：
  ```python
  from matplotlib.gridspec import GridSpec
  
  fig = plt.figure(figsize=(14, 8))
  gs = GridSpec(3, 3, figure=fig)     # 3行×3列的虚拟网格
  
  ax_top = fig.add_subplot(gs[0, :])   # 第一行占满→放总标题/汇总图
  ax_left = fig.add_subplot(gs[1:, 0]) # 左边2行1列→放分类对比
  ax_main = fig.add_subplot(gs[1:, 1:])# 右边2行2列→放主图
  
  # 比subplots(2,2)灵活得多——可以做出"顶部是总览KPI+下面是三张并列分析图"的报告布局
  ```

**4.2 Seaborn catplot家族完整对比——一张决策表选对图（v6.1补全）**

W4D1前面覆盖了barplot/boxplot/violinplot，但catplot家族还有三个重要成员在特定场景下更优：

| 图表类型 | 展示内容 | 最佳场景 | 局限 |
|---------|---------|---------|------|
| **stripplot** | 每个数据点的位置+少量随机抖动 | 数据量<200→看到每一个点 | 数据>500→点重叠严重→看不清 |
| **swarmplot** | 每个数据点的位置+智能排布(绝不重叠) | 数据量<200→想看每个点+不重叠 | 数据>500→计算极慢（O(n²)排布算法）|
| **boxenplot** | 增强箱线图→展示更多分位数(非只有Q1/Q3) | 大数据集(>10000)→箱线图太粗糙，boxen展示8-16个分位级 | 数据量小(<50)→过度展示，不如箱线图 |
| **pointplot** | 均值+置信区间+连线 | 多组对比+需要连线强调趋势(如"连续6个月的A/B组转化率") | 不能展示数据分布 |

```python
# stripplot vs swarmplot 选择
sns.stripplot(data=df, x='城市', y='金额', jitter=0.2)   # 加点随机抖动→点不重叠但看不清密度
sns.swarmplot(data=df, x='城市', y='金额')               # 智能排布→点不重叠且保持密度信息

# boxenplot——大数据集(>10000行)的箱线图替代
sns.boxenplot(data=df, x='城市', y='金额', k_depth='tukey')  # 展示更多分位数→比boxplot更精细

# pointplot——展示趋势（均值连线）
sns.pointplot(data=df, x='月份', y='转化率', hue='实验组',
              dodge=True, markers=['o', 's'], capsize=0.1)
# 比barplot更适合展示"时间趋势+组间对比"——连线让你一眼看到趋势方向
```

**4.3 双Y轴陷阱与正确用法**
- `ax2 = ax1.twinx()` 创建共享X轴的第二个Y轴
- 使用场景：两个指标量纲不同但需要放在一张图里（销售额万元 vs 利润率%）
- **关键规则**：两个Y轴必须用不同颜色区分→左轴标签用蓝色、右轴标签用橙色→读者不会把数据点对错轴
- **陷阱1——"视觉相交"误导**：左轴范围0-1000、右轴范围0-10→两条线在图中"看起来交叉"→但实际数值毫无关系。这就是为什么双Y轴被某些数据可视化专家批评为"最容易被滥用的图表"
- **陷阱2——双Y轴不能超过2个**：有人加`ax3 = ax1.twinx()`再加第三个轴→读者完全混乱→信息图失败

**5. 图表叙事——选对图+讲对故事。这不是"美化"，是"不误导"**
- 每种图回答一种特定的业务问题。如果问题和图不匹配→误导读者
- 趋势→折线。"月度销售额如何变化？"（各月之间有前后关系→用线连接是对的）
- 对比→柱状图。"各城市销售额排名？"（各城市之间没有前后关系→用线连接是错的！）
- 关系→散点图。"单价和销量有关系吗？"（两个连续变量的关系）
- 分布→直方图/箱线图/小提琴图。"订单金额的分布特征？有没有异常大单？"
- 占比→饼图(≤5类别)/堆叠柱状图(>5类别)。"各品类占总销售额的比例？"
- 相关性→热力图。"多个指标之间哪些关联度高？"
- **选错图的真实后果**：用折线图展示"各城市销售额"→读者被连接线暗示"城市之间有顺序/递进关系"。用饼图展示10个品类→读者完全看不出各块的相对大小。用散点图展示趋势→趋势方向完全看不出来
- **结论式标题**：不是"销售额趋势图"，而是"Q2销售额逐月上升，6月环比增长15%"。图应该能配上标题独立存在(看标题+图就能理解，不需要看正文)
- **图中标注关键发现**：`ax.annotate('双11促销峰值', xy=('2025-11-11', 5230000), xytext=('2025-10-01', 6000000), arrowprops=dict(arrowstyle='->', color='red'), fontsize=11, color='red')` → 异常点/突变点/转折点→标出来→读者不需要自己找

### 必须覆盖的陷阱
1. **中文显示方框□→配置字体**：`plt.rcParams['font.sans-serif'] = ['SimHei']`
2. **`savefig`在`show`之后→保存空白图**：必须先save再show
3. **饼图类别>5→可读性灾难→改用柱状图**

## W4D2：数据清洗实战（上）——缺失值/异常值/重复值

### 能力簇
**脏数据的诊断与修复** —— 理解数据为什么脏，学会"诊断→策略→执行→验证"的完整清洗流程。今天是你看重的"数据清洗"能力最核心的一天

### 为什么今天重要
真实世界的数据永远是脏的。你入职后做的第一件事十有八九不是分析，是洗数据。洗不干净→分析结果全错→老板基于你的错误结论做决策→公司亏钱→你被diss。反过来，能快速诊断数据问题、设计合理的清洗策略、验证清洗质量——这就是你区别于"会用pandas"的人的核心竞争力。今天学的不只是`fillna`和`drop_duplicates`的语法——是"拿到一份脏数据后，从哪个角度切入、先诊断什么问题、选什么策略、怎么验证"的系统性思维。

### 具体知识清单

**1. 数据为什么会脏——理解根因才能对症下药**
- **系统bug产生的脏数据**：
  - 支付系统挂了→订单"金额=0"或"金额=NULL"
  - 时间戳bug→日期显示"1970-01-01"(Unix纪元0)或"2038-01-19"(32位溢出)
  - 编码问题→中文名变乱码→"北京"变成"åŒ—äº¬"
  - 数据类型错误→金额列被存成字符串(因为系统里有个"待定"的值)
- **人为错误产生的脏数据**：
  - 手动录入：门店名"朝阳店"/"朝阳分店"/"CY店"三种写法→其实是同一家店
  - 手抖：金额多打一个0→299变成2990→正常的299元订单变成异常大单
  - 单位混淆：金额列有人填"元"有人填"万元"→5和50000同时出现
- **数据管道产生的脏数据**：
  - 上游改表结构→下游ETL脚本没更新→多了/少了列
  - 定时任务某天失败→那天数据全空
  - 数据迁移→字段映射错误→"城市"列里存的是"品类"的数据
- **认知：数据分析80%的时间在洗数据。这不是浪费时间——洗得好的数据是分析的基石。洗不干净=垃圾进垃圾出**

**2. 拿到新数据后的清洗流程（诊断→策略→执行→验证，这个顺序不能乱）**
- **第一步：诊断**。找到所有问题，不打无准备之仗
- **第二步：策略**。针对每个问题制定处理方案。区分"数据错误"(修正)vs"真实极端值"(保留)
- **第三步：执行**。按策略实施清洗。每步记录"处理了什么+处理了多少"
- **第四步：验证**。清洗后检查：行数对不对、统计量是否合理、跨表校验是否一致

**3. 缺失值——先诊断,再处理,别上来就fillna**
- **诊断四步**：
  1. 每列缺失比例：`(df.isna().sum() / len(df) * 100).sort_values(ascending=False)` → 排序列→一眼看出最严重的列
  2. 缺失模式：`df.isna().sum(axis=1).value_counts().sort_index()` → 有多少行缺0列/1列/2列/...→如果大量行同时缺多列→可能需要直接删
  3. 缺失关联分析：`df[df['收入'].isna()].describe()` → 缺失收入的人和其他人有什么不同？年龄更高？→了解缺失不是随机的
  4. 可视化：`import missingno as msno; msno.matrix(df.sample(500))` → 黑白图一眼看出缺失集中在哪里
- **缺失的三种机制——决定处理策略的核心理论**：
  - **MCAR(完全随机缺失)**：缺失和其他任何变量都无关。如"传感器随机故障"→所有观测有相同的缺失概率→可以安全删除或均值填充
  - **MAR(随机缺失)**：缺失和观测到的变量有关。如"女性比男性更可能不填年龄"→在观测数据中是可解释的→可以用其他列预测填充(如用"购买品类"预测"性别")
  - **MNAR(非随机缺失)**：缺失和缺失值本身有关。如"高收入者更可能不填收入"→缺失本身包含信息→不能简单填充→需要专门建模或用业务知识估算
  - **判断方法**：对比"有缺失"和"无缺失"两组在其他列上的分布→如果有显著差异→MAR或MNAR→不是MCAR
- **处理策略选择矩阵**：
  | 缺失率 | MCAR | MAR | MNAR |
  |--------|------|-----|------|
  | <5% | 均可(删除最简单) | 删除行或KNNImputer | 需业务知识→特殊处理 |
  | 5-20% | 均值/中位数填充 | KNNImputer/回归填充 | 分组填充或多重插补 |
  | 20-50% | 多重插补或保留(标记) | 模型预测填充 | 单独建模估算 |
  | >50% | 删除整列(信息太少) | 删除整列 | 删除整列(填什么都是猜) |
- **具体填充方法**：
  - `df['金额'].fillna(df['金额'].median())` — 中位数填充。适合偏态分布的数值列(均值被极端值拉偏时中位数更稳健)
  - `df['金额'].fillna(df['金额'].mean())` — 均值填充。只适合大数定律成立的正态分布数值列
  - `df['城市'].fillna(df['城市'].mode()[0])` — 众数填充。`.mode()`返回Series→`[0]`取第一个众数
  - `df.fillna(method='ffill')` — 前向填充。用上一行的值填。适合时间序列(今天缺了用昨天)
  - `df.fillna(method='bfill')` — 后向填充。用下一行的值填。适合"下一个观测才是正确的"
  - `df.interpolate(method='linear')` — 线性插值。在两点之间画线取中间值。适合平滑的时间序列
  - `df.interpolate(method='polynomial', order=2)` — 多项式插值。适合非线性的时间序列
  - `df['金额'].fillna(df.groupby('城市')['金额'].transform('mean'))` — 分组均值填充。比全局均值更精确(考虑到不同城市的差异)
- **陷阱1：不诊断机制直接fillna(均值)→MNAR数据填均值=系统性偏差。如高收入者不填收入→填均值→整体收入被低估→分析结论错误**
- **陷阱2：`df.fillna(df['金额'].mean())` vs `df['金额'].fillna(df['金额'].mean())`——前者填充所有列(用金额均值填年龄→错误！)，后者只填金额列。永远用列名指定要填的列**
- **陷阱3：删除缺失行→样本可能从10000条变200条→剩下的200条不代表总体→分析结论偏差**
- **陷阱4：`fillna(method='ffill')`要求数据有序→无序数据前向填充=随机填入→必须`sort_values`后做**

**3.1 🔥进阶填充方法——KNN Imputer与MICE多重插补（v6.1补全）**

前面学的fillna(均值/中位数/前向/后向)是"简单填补"——不需要模型，一行代码搞定。但它们有一个共同的弱点：**只用单列信息填补，没有利用列之间的关系**。比如用户没填"收入"→用全体中位数→但该用户"职业=医生""年龄=45"→收入肯定远高于中位数→填中位数=错误填补。

- **KNN Imputer（K近邻填补）**：找和"缺失样本"最相似的K个完整样本→用他们的均值/中位数填补
  - 核心思想："你是什么样的人→参考和你最像的人"。缺失收入的医生用户→找"职业=医生+年龄40-50+城市=北京"的完整样本→用他们的收入均值
  - 比简单填补更准确（尤其是MNAR和MAR数据），但计算量大（需要算距离矩阵）
  ```python
  from sklearn.impute import KNNImputer
  
  # 选择用于"找邻居"的特征（要选和缺失列可能相关的列）
  features = ['年龄', '收入', '工作年限', '教育水平编码']
  imputer = KNNImputer(n_neighbors=5, weights='distance')  
  # n_neighbors=5: 参考最相似的5个邻居
  # weights='distance': 越近的邻居权重越大
  df_filled = pd.DataFrame(
      imputer.fit_transform(df[features]),
      columns=features
  )
  ```
  - **注意事项**：①KNN对量纲敏感→先做StandardScaler ②KNN能填补多列同时缺失 ③大数据集(>10万行)可能很慢

- **MICE（多重插补）**：用机器学习模型迭代填补
  - 核心思想："用所有其他列预测缺失列→反复迭代直到收敛"。缺失收入→用(年龄+职业+教育)建回归模型→预测缺失的收入。但其他列也可能缺失→MICE循环处理每列→每次迭代填补都更准确→反复多轮直到稳定
  - **和KNN的区别**：KNN找邻居→简单直观但没"学习"。MICE建模型→能捕捉复杂的列间非线性关系→更准确但更重
  ```python
  from sklearn.experimental import enable_iterative_imputer
  from sklearn.impute import IterativeImputer
  
  mice = IterativeImputer(max_iter=20, random_state=42, n_nearest_features=5)
  # max_iter=20: 最多迭代20轮（实际收敛会提前停止）
  # n_nearest_features=5: 每次建模最多用5个最相关的特征
  df_imputed = pd.DataFrame(
      mice.fit_transform(df[features]),
      columns=features
  )
  ```
  - **什么时候用MICE**：①MNAR数据（缺失和自身值相关，如高收入者不填收入→简单填补偏差大→MICE用其他特征间接推算）②多列同时缺失③后续分析对缺失值填补精度要求高
  - **陷阱：MICE假设"数据是随机缺失的"→如果"为什么缺失"本身蕴含信息→任何填补方法都无法完全消除偏差**

- **三种填充策略的决策流程**：
  ```
  缺失率<5%且MCAR → 简单fillna（均值/中位数/众数）→ 够用
  缺失率5-30%且MAR/MNAR → KNNImputer或MICE → 利用列间关系
  缺失率>30%且不是关键列 → 考虑删除该列→但留下"缺失指示变量"
  
  简单fillna vs KNN vs MICE的选择：
  - 数据<1万行且列间有强相关 → KNN（快且直观）
  - 数据>1万行且列间关系复杂→ MICE（建模捕捉非线性）
  - 缺失列和其他列没有相关 → 简单fillna（KNN/MICE也没用）
  ```

**4. 异常值——"异常"不等于"错误"，这是今天最重要的判断力**
- **检测三法**：
  1. IQR法(不假设分布)：Q1=25%分位、Q3=75%分位、IQR=Q3-Q1。下界=Q1-1.5×IQR、上界=Q3+1.5×IQR。之外=异常
     ```python
     Q1 = df['金额'].quantile(0.25); Q3 = df['金额'].quantile(0.75)
     IQR = Q3 - Q1
     异常 = df[(df['金额'] < Q1-1.5*IQR) | (df['金额'] > Q3+1.5*IQR)]
     ```
  2. Z-score法(假设大致正态)：z = (x-均值)/标准差、|z|>3为异常。偏态分布下Z-score会有很多假阳性
  3. 业务规则法(不依赖统计)：金额不能为负(除非退款)、年龄不能>120或<0、日期不能在未来、利润率不能>100%
- **Boxplot辅助判断**：`sns.boxplot(df['金额'])` → 一眼看到有多少离群点(须子外的小圆圈)、离群点集中在哪一侧
- **处理策略——分区"数据错误"和"真实极端值"（这是你分析能力的体现）**：
  - **数据错误**：金额=负数但没有退款标记→录入错误、年龄=0→未填→修正为NaN或删除
  - **真实极端值**：大客户一笔订单100000元→是真实大单→保留！删了会低估高消费群体的贡献
  - **业务特殊值**：金额=0且有备注"赠品"→是公司促销行为→保留但标记为"促销订单"
  - **Capping(缩尾)**：把<1%分位和>99%分位之外的值裁剪→`df['金额'].clip(lower=quantile(0.01), upper=quantile(0.99))` → 适合建模时处理(不改变整体分布形状，只去掉极端尾巴)
- **处理决策树**：
  ```
  这个"异常"值在业务上可能吗？→是→可能是真实极端值→保留
                         →否→可能是数据错误→调查来源→修正或删除
  ```
- **陷阱1：盲目用IQR删"异常"→把大客户订单全删了→高消费群体从分析中消失→结论严重偏差**
- **陷阱2：Z-score假设正态→销售额数据通常严重右偏→Z>3的可能有一大堆→大部分是正常的长尾而非错误**
- **陷阱3：不检查就直接删→删了才知道删掉的是"双11的促销大单"→核心业务数据被丢**

**4.1 🔥多维异常检测——IsolationForest（v6.1补全）**

前面IQR和Z-score都是单变量方法——一次只看一列。但真实数据中的异常往往是多维的：单看"金额"正常、单看"数量"正常，但"金额=10元，数量=10000"组合在一起就不正常了。IsolationForest专门解决这种多维异常。

- **核心思想**：异常点是"容易被孤立的点"——用随机树切割数据，异常点平均用很少的切割就能被隔离开
- **优势**：①不需要假设数据分布 ②能检测多维联合异常 ③对大数据集高效（O(n)）
- **Python实现**：
  ```python
  from sklearn.ensemble import IsolationForest
  
  # 选择用于异常检测的特征（多维）
  features = ['金额', '数量', '折扣率']
  X = df[features].dropna()
  
  # contamination=预期异常比例（如0.05=预期5%异常）
  iso = IsolationForest(contamination=0.05, random_state=42)
  df.loc[X.index, '异常标签'] = iso.fit_predict(X)
  # 标签含义：1=正常, -1=异常
  
  # 查看异常样本
  异常样本 = df[df['异常标签'] == -1]
  
  # 异常得分（越低越异常）
  df['异常得分'] = iso.decision_function(X)
  # 画异常得分分布→设置阈值
  ```

- **什么时候用IsolationForest vs IQR/Z-score**：
  - 只查一列的极端值 → IQR或Z-score（简单直观）
  - 查"单列正常但组合异常"的数据 → IsolationForest
  - 数据有多个相关特征（金额×数量×时间）→ IsolationForest
  - 需要给业务解释"为什么这个是异常" → IQR/Z-score（IsolationForest难以逐条解释）

- **contamination参数怎么定**：
  - 有历史标签数据 → 用历史异常率
  - 无标签 → 从0.01开始尝试→检查异常样本是否有业务意义→调整
  - 画`decision_function`得分的直方图→寻找自然断点

- **练习场景**：给一个电商订单数据集（金额、数量、折扣、用户等级）→用IQR查单列异常→再用IsolationForest查多维异常→对比两套结果→发现"IQR认为正常但IsolationForest标为异常"的订单（如：金额中等、数量极大、折扣极高）→判断这些是否真的是异常

- **陷阱1：contamination设太高→把正常数据标为异常→删掉好数据**
- **陷阱2：IsolationForest结果不能逐条解释"为什么异常"→需要回到原始特征手动检查→不适合需要给业务方解释每个异常原因的场景**
- **陷阱3：特征量纲差异大→先做StandardScaler→IsolationForest基于树分裂→实际不太受量纲影响→不做标准化也能用**

**5. 重复值——区分"真重复"和"合理重复"。这个判断错了数据就废了**
- 检测：`df.duplicated(subset=['订单号', '用户ID'], keep=False)` → `keep=False`标记所有重复行(含第一次出现)
- `df[df.duplicated(subset=['订单号'], keep=False)].sort_values('订单号')` → 把所有重复的放在一起→逐对比
- **全行完全相同**：所有列内容一模一样→系统重复推送→直接`drop_duplicates()`
- **订单号重复但内容不同**：订单号OR001出现了两条→一条金额299、一条金额0→可能是下单+退款→保留哪条取决于分析目标(分析销售额保留299，分析退款率保留0)
- **合理重复不是重复！**：同一用户多条订单→这是"多次购买"的正常行为→不是数据重复！如果drop_duplicates把同用户多条订单合并→每个用户只剩一条订单→你的复购率分析直接废了
- 去重策略：
  - `df.drop_duplicates(subset=['订单号'], keep='first')` → 保留第一条
  - `df.drop_duplicates(subset=['订单号'], keep='last')` → 保留最后一条(常用于保留最新状态)
- **陷阱1：`df.drop_duplicates()`不指定subset→只有全行完全相同才去重→可能漏掉"订单号相同其余列不同"的异常**
- **陷阱2：`drop_duplicates(subset=['用户ID'])`→每个用户只剩一条→分析复购率=0%→分析废了**
- **陷阱3：keep='first'和keep='last'可能留下不同的信息→需要根据业务判断谁是最新版**

**6. 清洗日志——洗了什么都得记录下来**
- 每条清洗操作记录：操作名称、处理的列、处理前行数/后行数、处理的记录数
  ```python
  def log_step(df_before, df_after, step_name):
      print(f"[{step_name}] 行数: {len(df_before)} → {len(df_after)} ({len(df_after)-len(df_before):+d}行) | 处理列: ...")
  ```
- 为什么：将来分析报告要写"数据质量说明"章节→告诉老板"原始数据有多少问题/我怎么处理的/处理对结果的可能影响"
- 数据质量报告模板：原始概况(行数/列数/缺失率/异常率)→处理决策(每类问题怎么处理+理由)→处理后概况(行数/列数/缺失率)→处理对分析的潜在影响(哪些结论可能受清洗策略影响)

### 能力簇

### 为什么今天重要
入职后发现分析跑得慢——不是你的分析逻辑有问题，是你的数据处理方式不支持大数据量。昨天的`df.fillna()`在1000行上秒级，在1000万行上可能直接OOM(内存溢出)。今天学的chunksize分块、astype内存优化、Parquet格式——是把昨天的清洗能力从"实验级"升到"生产级"的关键。

### 具体知识清单

**1. 格式标准化——让所有数据"说同一种语言"**
- **日期统一**：
  - `pd.to_datetime(df['日期'], errors='coerce', format='mixed')` → mixed让pandas自己推断混合格式
  - `errors='coerce'`：无效日期→NaT。`errors='raise'`(默认)：无效→报错。`errors='ignore'`：无效→保持原样(object类型不变)
  - format参数：指定格式`format='%Y-%m-%d'`明确告知→比自动推断快。format='mixed'自动处理混合格式
  - 常见日期格式码：`%Y`四位年/`%y`两位年/`%m`月/`%d`日/`%H`时/`%M`分/`%S`秒
- **数值统一**：
  - `pd.to_numeric(df['金额'], errors='coerce')` → 字符串→数字。无效变NaN
  - 去掉货币符号和逗号后再转换：`df['金额'].str.replace('¥','').str.replace(',','').str.strip()` → `pd.to_numeric()`
  - `astype('int64')` → 明确转int。`astype('float64')` → 明确转float
- **文本标准化**：
  - `df['门店'].str.strip()` — 去前后空格。" 朝阳店 "→"朝阳店"
  - `df['门店'].str.replace(' +', ' ', regex=True)` — 多个连续空格→压缩成一个
  - `df['门店'].str.lower()` — 统一小写(英文文本)
  - 门店名统一映射：`df['门店'].map({'朝阳店':'朝阳店','朝阳分店':'朝阳店','CY店':'朝阳店','朝阳店 ':'朝阳店'})` → 4种写法统一为1个标准名
- **陷阱1：`to_datetime(errors='coerce')`把无效变成NaT→但如果整列所有日期格式都不匹配→全会变NaT(数据全丢了)→先`.head()`看下日期长什么样再转换**
- **陷阱2：`str.replace`默认`regex=False`→如果要替换的是`¥`(特殊字符)确保不用正则→设置`regex=False`**

**2. 数据一致性验证——洗完后必须做的质量检查**
- 跨表外键校验：`orders[~orders['user_id'].isin(users['user_id'])]` → 找出订单表中在用户表中不存在的user_id→这些"孤儿订单"→要么users表数据不全/要么orders表user_id录入错误
- 范围校验：订单日期在2024-2025年之间(不能1900年也不能2100年)、金额≥0(除非有退款标记)、数量≥1
- 逻辑校验：下单日期≤发货日期、金额=单价×数量×(1-折扣率)(允许微小误差)
- 汇总校验：明细金额之和 ≈ 汇总表的总金额。`abs(df['明细金额'].sum() - 汇总表['总金额'].sum()) / 汇总表['总金额'].sum() < 0.01`
- **数据一致性验证=踩刹车不看后视镜→上了高速才发现问题就晚了。每次清洗完必做**

**3. 🔥 分块读取大文件——100万行以上数据不会OOM的处理方式（v5.0核心）**
- **问题**：一个500MB CSV→`pd.read_csv('500mb.csv')`→pandas里占1.5GB(CSV膨胀3倍是常态)→8GB内存可能直接OOM
- **解决方案**：`pd.read_csv('big.csv', chunksize=10**5)` → 返回`TextFileReader`迭代器→每次只读10万行到内存→处理完→释放→再读下一块
- **分块聚合模式（最常用，可加和的操作都能这样用）**：
  ```python
  # 分块计算每城市的sum和count→合并后算全局mean
  sums, counts = [], []
  for chunk in pd.read_csv('500mb.csv', chunksize=100000):
      sums.append(chunk.groupby('城市')['金额'].sum())
      counts.append(chunk.groupby('城市')['金额'].count())
  total_sum = pd.concat(sums).groupby('城市').sum()
  total_count = pd.concat(counts).groupby('城市').sum()
  avg = total_sum / total_count  # 全局mean = 所有块的sum之和 / 所有块的count之和
  ```
- **分块过滤模式（筛选后数据量小→合并后内存OK）**：
  ```python
  filtered = []
  for chunk in pd.read_csv('big.csv', chunksize=100000):
      filtered.append(chunk[chunk['金额'] > 100])
  result = pd.concat(filtered, ignore_index=True)
  ```
- **分块转换模式（不可合并的操作→每块独立处理→各自写出）**：
  ```python
  for i, chunk in enumerate(pd.read_csv('big.csv', chunksize=100000)):
      chunk = clean(chunk)  # 每块清洗
      chunk.to_csv(f'output_{i:04d}.csv', index=False)  # 各自写出
  ```
- **chunksize设多大**？取决于可用内存。通常`10**5`(10万行)到`10**6`(100万行)。太小→迭代次数多→慢。太大→单块内存大→OOM。一般30万行作为起点尝试
- **陷阱1：不是所有操作都可以分块**——需要全局排序的(`rank`)、全局分位数的(`quantile`)、全局分组的(不聚合的`groupby`)→不能分块各自处理→结果会是错的
- **陷阱2：分块后concat→index重复**。`pd.concat(chunks, ignore_index=True)`重置索引
- **陷阱3：分块写出时→第一块写header→后续块`header=False`→否则中间行会有重复的列名**

**4. 🔥 内存优化——同一份数据从1.5GB降到200MB的方法（v5.0核心）**
- **诊断**：`df.info(memory_usage='deep')` → 显示精确内存占用。看"memory usage: XX MB"
- `df.memory_usage(deep=True)` → 每列各自的内存占用。找"内存大户"(通常是object类型的长字符串列)
- **优化策略一：`astype('category')`——重复值多的字符串列→内存减少90%**
  - 原理：category不存每个字符串→而是存整数编码(1,2,3...)→整数编码→指向实际字符串。10万个"北京"→存1个"北京"+10万个1→内存从800KB→10KB
  - 适用列：城市/性别/品类/用户等级/是否会员→值种类少(几十到几百种)但行数多(百万行)
  - 不适用列：用户ID/手机号/身份证号→每行都不同→编码后反而更占内存(需要同时存编码和字符串映射)
  - 操作：`df['品类'] = df['品类'].astype('category')` → 然后`df.info(memory_usage='deep')`看变化
  - **判断标准**：去重值的数量÷总行数<1%→加category几乎肯定优化。>80%→不加
- **优化策略二：数值降级——int64→int32→int16→int8**
  - int64(8字节/值)→int32(4字节/值)→int16(2字节/值)→int8(1字节/值)
  - `pd.to_numeric(df['年龄'], downcast='integer')` → 自动选最小够用的int类型(0-120→int8够用)
  - `pd.to_numeric(df['单价'], downcast='float')` → float64→float32
  - **注意**：降级前检查列的范围→年龄0-120→int8(范围-128~127)刚好够。销售额0-10000000→int32(范围-21亿~21亿)够。int64→适合所有场景但占内存
- **内存优化前后对比示例**：
  ```
  优化前：300MB(品类/城市/会员等级/用户ID都是object×100万行)
  品类→category: 300→280MB(-20MB)
  城市→category: 280→260MB(-20MB)
  会员等级→category: 260→255MB(-5MB,值只有3种)
  年龄→int8: 255→253MB(-2MB)
  金额→float32: 253→250MB(-3MB)
  合计优化: 300→250MB(-17%)
  ```
- **陷阱1：category不是万能药→每行都不同的列加category反而更占内存(多存了一份编码表和一份字符串表)**
- **陷阱2：数值降级后范围可能不够→int16范围-32768~32767→如果金额超过这个范围就溢出。降级前先检查min/max**

**5. 🔥 Parquet——比CSV快5-10倍的列式存储格式（v5.0核心）**
- **Parquet是什么**：列式存储+压缩→专为大数据分析设计。不是CSV的替代，是CSV的"高性能版"
- **为什么比CSV快那么多**：
  1. 列式存储→只读需要的列→CSV读100列全读、Parquet只读2列→IO少50倍
  2. 压缩效率极高(同类型数据放一起→压缩算法大展拳脚)→同数据量→Parquet文件比CSV小3-5倍→磁盘IO减少
  3. 数据类型保留→读回来时类型已对(CSV全object→需要astype推断→慢)
  4. Parquet每列自带min/max统计→查询时直接跳过不相关的行块→谓词下推(predicate pushdown)
- **写入**：`df.to_parquet('data.parquet', index=False, compression='snappy')` — snappy=速度快，gzip=压缩率高
- **读取**：`pd.read_parquet('data.parquet', columns=['金额','城市'])` — 只读需要的列
- **实战对比（同一份100万行×10列DataFrame）**：
  | 操作 | CSV | Parquet | 倍数 |
  |------|-----|---------|------|
  | 写入耗时 | 3.0秒 | 0.5秒 | 快6倍 |
  | 文件大小 | 80MB | 15MB | 小5倍 |
  | 读全量耗时 | 2.0秒 | 0.3秒 | 快7倍 |
  | 读全量内存 | 150MB | 80MB | 省47% |
  | 只读3列耗时 | 1.2秒(仍全读) | 0.06秒(只读3列) | 快20倍 |
- **什么时候用Parquet**：①数据>100MB②需要反复读取③只需要部分列④需要传给同事/存到数仓→都应该用Parquet。小文件(<10MB)用CSV也行
- **陷阱1：Parquet不支持Python复杂对象(list/dict/set)→碰到`dtype=object`且实际内容是list的列→`to_parquet`报错→先`.astype(str)`或拆成多列**
- **陷阱2：pandas和PySpark的Parquet默认设置不同→pandas写的Parquet给PySpark读可能出现类型不兼容→用`engine='pyarrow'`统一引擎**

4. **数值降级后范围可能不够**→降级前检查min/max
5. **Parquet不支持Python复杂对象**→list/dict/set列→先astype(str)
6. `to_datetime(errors='coerce')`→**整列格式都不对**→全会变NaT→数据全丢

### 连接点
- **W2 pandas**：chunksize是`pd.read_csv()`的参数→W2基础用法→今天高级用法
- **W8（数据工程）**：Hive/Spark的存储格式=ORC/Parquet。今天理解Parquet→W8理解"大数据为什么用列式存储"

### 具体知识清单

**1. 清洗流水线设计——让清洗可重复、可审查、可维护**
- 每个清洗步骤一个函数→单一职责(只做一件事)→输入df→输出df
  ```python
  def clean_dates(df, date_cols=['日期','注册日期']):
      for col in date_cols:
          df[col] = pd.to_datetime(df[col], errors='coerce')
      return df
  
  def clean_amounts(df, amount_cols=['金额','成本']):
      for col in amount_cols:
          df[col] = pd.to_numeric(df[col].astype(str).str.replace('[¥元,]','',regex=True), errors='coerce')
      return df
  
  def remove_outliers(df, col, method='iqr'):
      if method == 'iqr':
          Q1, Q3 = df[col].quantile([0.25,0.75])
          IQR = Q3 - Q1
          return df[(df[col] >= Q1-1.5*IQR) & (df[col] <= Q3+1.5*IQR)]
      return df
  
  def validate_cleaned(df):
      # 验证清洗后的质量
      checks = {
          '无负金额': (df['金额'] >= 0).all(),
          '日期在2024-2025': df['日期'].between('2024-01-01','2025-12-31').all(),
          '缺失率<1%': df.isna().mean().max() < 0.01
      }
      return pd.Series(checks)
  ```
- **pipe链式调用**：
  ```python
  clean_df = (raw_df
      .pipe(clean_dates)
      .pipe(clean_amounts)
      .pipe(remove_outliers, col='金额', method='iqr')
      .pipe(remove_outliers, col='数量', method='iqr')
      .pipe(validate_cleaned)  # 最后验证
  )
  ```
  - pipe第一个参数自动传入df→后面的`col='金额'`传给函数的其他参数
- **清洗日志增强版**：每个pipe步骤写一条日志→记录函数名/处理前shape/处理后shape/处理了多少
- **为什么要流水线化**：①可重复(每次新数据→跑同一条pipe)。②可审查(每一步独立函数→单独测试)。③可维护(改一步不影响其他)
