## W14D1：数据理解+清洗+SQL取数

### 今日任务
**5份电商数据——完成理解、清洗、验证。** 和W13D1同样的流程但数据不同（电商订单vs内容阅读），踩的坑也不同。

### 具体操作步骤

**Step 1：数据盘点（30分钟）——"电商数据和内容数据有什么不同"**
- 5份数据的来源和内容：
  1. `user_info.csv`：用户基础信息（user_id/注册日期/城市/设备/渠道来源/年龄/性别）—50万行
  2. `orders.csv`：订单表（order_id/user_id/product_id/下单日期/金额/数量/支付状态/退款标记/使用优惠券）—200万行，过去12个月。**电商的核心表**
  3. `membership.csv`：会员数据（user_id/加入会员日期/会员等级/会员到期日/是否自动续费）—8万行。会员等级=普通/银牌/金牌/钻石。改版日期=2025-03-01（新版会员权益从这天生效）
  4. `marketing_spend.csv`：投放数据（日期/渠道/花费/曝光量/点击量/新用户量/新用户首单转化率）—8个渠道，过去12个月
  5. `product_info.csv`：商品信息（product_id/名称/品类/品牌/成本/售价/上架日期/库存状态）—10万商品
- **电商数据的特征**：订单表有"订单状态"(已支付/已取消/已退款/已完成)→分析前必须统一口径（"GMV=已支付+已完成-已退款",不能含"已取消"）。有优惠券信息→需要标记"自然订单"vs"券订单"。有退货→需要看"退货率"作为护栏指标。**用户可能同一天下多笔订单→分析"客单价"时要注意去重**

**Step 2：数据清洗（60分钟）——电商特有的脏数据问题**
- 缺失值：订单表中"支付状态"缺失率0.5%→排查→发现是"下单后30分钟内未支付"的订单→状态应为"待支付"→补全。用户表中"年龄"缺失率15%→偏高→分析缺失模式（老年用户更可能不填年龄?还是某个渠道的用户默认不采集年龄?）→决定是否填充
- 异常值：订单金额出现负数→核对→有退款标记的订单→正常(退款)。订单金额出现999999→0.01%→人工标记→疑似数据错误(可能是"大额批发"也可能是"录入错误")→需要业务确认→先标记不删
- 重复值：同一order_id出现两次→一次"已支付"+一次"已退款"→是同一订单的两次状态变更→保留两条(累积快照思路)
- 关键清洗：**把"订单状态"统一为"已完成(不退款的)"和"已退款"**——GMV计算只用前者。把"优惠券使用"标记出来→后续分析券效果。把"会员"和"非会员"标记出来→为Day2的会员改版评估做准备
- 外键校验：orders的user_id→99.8%在user_info里→0.2%缺失→是"游客下单"(未注册)→排除在"会员分析"之外,但保留在"全量GMV"中。orders的product_id→全部在product_info里→✓

**Step 3：SQL取数（40分钟）——会员改版前后+实验组/对照组的提取**
- 会员改版日期=2025-03-01。改版前=2024-09-01至2025-02-28(6个月)。改版后=2025-03-01至2025-08-31(6个月)
- 关键SQL：
  ```sql
  -- 提取"改版前6个月"和"改版后6个月"的会员消费数据
  SELECT m.membership_level, 
         CASE WHEN o.order_date < '2025-03-01' THEN 'pre' ELSE 'post' END as period,
         COUNT(DISTINCT o.order_id) as order_cnt,
         SUM(o.amount) as gmv,
         COUNT(DISTINCT o.user_id) as user_cnt
  FROM membership m
  JOIN orders o ON m.user_id = o.user_id AND o.payment_status IN ('已完成')
  WHERE o.order_date BETWEEN '2024-09-01' AND '2025-08-31'
  GROUP BY m.membership_level, period;
  
  -- 提取"会员vs非会员"的对比数据（用于PSM匹配→Day2用）
  -- 会员用户：在membership表中有记录+加入日期在改版前
  -- 非会员用户：在membership表中无记录或加入日期在改版后
  ```

**Step 4：数据质量验证（20分钟）**
- 完整性：改版前6个月和改版后6个月的数据都有→✓。每个月的订单量稳定(约30万单/月)→无断层→✓
- 一致性：会员表中的user_id都在orders中有订单→会员不是"僵尸会员"→✓
- 准确性：金额无负数(退款已排除)、日期无未来、品类分布符合常识(数码/服装/食品为Top3)→✓
- 及时性：数据到2025-08-31→改版后6个月完整→✓
- 唯一性：同一order_id不会同时"已完成"和"已取消"(互斥状态)→✓

## W14D2：会员改版效果评估

### 今日任务
**评估"会员体系改版"的效果——这是本周最核心的分析。** 改版是2025年3月全量上线的（没做AB）。你需要用因果推断方法（W11）来评估效果——不能直接看"改版前后对比"。

### 具体操作步骤

**Step 1：分析策略设计（30分钟）——为什么不能直接看前后对比？**
- 为什么不能直接对比"改版前vs改版后"：①季节性：3月是电商旺季（春节后恢复消费）→自然增长会混淆改版效果②产品迭代：同期改版的不只是会员（可能也有其他功能更新）→无法区隔各自的效果③用户自然成熟：老会员改版前就已经高消费→改版后继续高消费→这部分增长不是改版带来的
- 可以用的方法：
  - 方法1-DID（如果有可比的对照组）：找"和速卖通相似但没改版会员体系的竞品/行业数据"做对照组→可能没有
  - 方法2-PSM（会员自选→倾向得分匹配）：用户在改版前"自己选择是否加入会员"→自选偏差→用PSM匹配"特征相似但未加入会员"的对照组→对比"加入会员"的因果效应。**这个方法更适合这个场景**——因为会员是用户自己选的，没法做AB
  - 方法3-前后对比+DID思路：用"改版前就已是会员的用户"作为"实验组"（他们的会员权益变了）。用"从未加入会员的用户"作为"对照组"（他们不受影响）。实验组改版前后的变化-对照组改版前后的变化=改版对老会员的效果。但老会员和新会员不同→不能代表"新会员加入"的效果

**Step 2：PSM分析——会员vs非会员（60分钟）**
- 用W11D3的PSM完整流程：
  - 问题："加入会员是否提升了用户消费？"（改版后的新会员为处理组）
  - 倾向得分估计：用Logit→特征=改版前6个月的"月均消费/订单数/活跃月数/注册天数/城市等级/年龄/性别"→P-Score=加入会员的预测概率
  - 匹配：近邻匹配k=1+卡尺(caliper=0.2)→平衡性检验→所有特征SMD<0.1→匹配充分→✓
  - ATT估计：匹配后→会员月均消费=320元 vs 非会员=240元→ATT=+80元(+33%)→加入会员显著提升消费
  - 敏感性分析(Rosenbaum Bounds)：Γ=2.5时p>0.05→需要"不可观测因素让加入会员几率提高2.5倍"才能推翻→结论比较稳健
  - **但是**——这个PSM估计的是"加入会员(改版后)的效果"→不是"改版本身的效果"。改版前后的老会员的消费提升→才是"改版的效果"

**Step 3：老会员改版前后对比——用DID思路（40分钟）**
- 分析对象：在改版前(2025-03-01前)就已经是会员的用户→他们经历了改版
- 实验组=老会员（权益变了）。对照组=从未加入会员的用户（权益没变）+他们的消费趋势
- DID计算：老会员改版后6个月月均消费-改版前6个月月均消费=+50元。非会员同期变化=+15元（自然增长）→DID=+50-(+15)=+35元→改版让老会员月均消费额外提升了35元(+15%)
- 分等级分析：金牌会员→效果最强(+60元,+20%)——他们的权益提升最大(新增了专属客服+优先发货)。钻石会员→效果不显著(本来就最高,权益变化不大)。银牌会员→效果中等(+25元,+10%)
- **和PSM对比**：PSM估计"加入会员"的效果=+80元(+33%)→这是"会员vs非会员"的差异(含自选偏差→可能高估)。DID估计"改版对老会员的效果"=+35元(+15%)→这是"改版增量"→更可信（消去了时间趋势）

**Step 4：护栏指标检查（20分钟）**
- 会员改版后→退货率有没有升高？→改版前后=改版前5.2% vs 改版后5.0%→无显著变化→好。没有"会员改版后更容易退货"
- 会员的"优惠券使用率"有没有暴涨？→改版前35% vs 改版后55%→**涨了！** 会员在用更多优惠券→"会员折扣"让GMV涨了但利润可能在下降→需要分析"去掉券折扣后的净GMV"
- 非会员的体验有没有变差？→非会员的订单量/GMV在改版前后无明显变化→会员改版没有"挤出"非会员→好

**Step 5：结论与建议（30分钟）**
- 会员改版整体有效：老会员月均消费提升+35元(+15%)。新会员加入后消费显著更高(ATT=+80元,+33%)。但护栏指标"优惠券使用率"暴涨→需要关注"券成本是否侵蚀了利润"
- 建议：①继续推进会员改版（有效）②计算"券后净GMV"（扣除券成本后的真实收入）→如果净GMV仍然正→继续③如果净GMV为负→优惠券力度过大→需要调整(如设使用门槛/降低折扣力度)④金牌会员效果最强→后续改版可以重点参考金牌会员的权益设计

### 今日陷阱
1. **PSM和DID估计不同的东西**：PSM估计"成为会员的效果"(含自选偏差→可能高估)。DID估计"改版对老会员的增量"(消去时间趋势→更可信)。两者不矛盾→各自回答不同的问题→报告里说清楚
2. **券后净GMV**：券使用率从35%→55%→"GMV涨了"可能只是"用户用了更多券"（券成本增加）→如果去掉券成本→真实收入可能涨不了那么多。必须分析"券后净GMV"
3. **金牌会员效果最强但"金牌"本来就很少(占会员5%)**：不能把金牌会员的效果简单外推到其他等级→"改版效果因等级而异"

## W14D3：用户增长诊断 + 渠道精细化分析

### 今日任务
**电商场景的用户增长诊断——漏斗/RFM/LTV/渠道/PDS全部用上。** 和W13D3同样的武器库但场景切换到电商。

### 具体操作步骤

**Step 1：电商漏斗（30分钟）——电商的漏斗和内容不同**
- 电商漏斗：浏览商品→点击→加购→下单→支付→完成。每一步转化率→找出最大的泄漏点
- 最大泄漏：浏览→点击只有18%（行业通常25-30%）→首页推荐和搜索不够好→用户看了很多商品但没点。加购→下单=65%→还行。下单→支付=88%→正常
- 分群漏斗：新用户vs老用户→新用户在"加购→下单"转化率只有50%(老用户75%)→新用户对平台信任不足/价格敏感→建议给新用户"首单免运费"降低下单门槛。会员vs非会员→会员的"加购→下单"=78%(非会员=60%)→会员权益里的"会员价"有效减少了"加购→下单"的犹豫

**Step 2：RFM+LTV（40分钟）——电商的RFM比内容更容易定义**
- RFM：R=最近一次下单距今(天)。F=过去6个月下单次数。M=过去6个月总消费。三维qcut(5)→7类画像
- 电商的7类画像和内容的差异：电商的"高价值用户"(R=5,F=5,M=5)→占用户15%但贡献60%的GMV→核心资产。电商的"重要挽留"(R=1,F=5,M=5)→曾经买很多但最近3个月没买了→可能是"被竞品抢走了"→**给他们发"老客户回归专享券"(大额→挽回成本高但值得)→预期挽回率25%**
- LTV各渠道对比：渠道A(搜索广告)→用户LTV=350→CAC=120→LTV/CAC=2.9→优。渠道B(信息流)→LTV=180→CAC=100→LTV/CAC=1.8→良。渠道C(社交媒体)→LTV=120→CAC=90→LTV/CAC=1.3→勉强。渠道D(线下)→LTV=80→CAC=110→LTV/CAC=0.73→亏！

**Step 3：PDS+渠道四维（30分钟）**
- PDS拆解：GMV=2000万/月→老用户贡献1200万(60%)→新用户贡献600万(30%)→沉睡回流200万(10%)→增长健康（老用户主导）
- 渠道四维：渠道D(线下推广)→量大/质差(LTV最低)/价低(ARPU最低)/本高(CAC最高)="垃圾流量"→建议**停投**。渠道A(搜索)→量中/质高/价高/本中→加大投放(ROI最高)。渠道B(信息流)→量中/质中/价中/本中→优化素材→提升用户质量
- 预算重分配：当前8个渠道总预算500万→建议：停渠道D(省80万)+停渠道H(省30万)→110万重新分配→70万给渠道A+40万给渠道B→预期净增GMV约250万

**Step 4：Q4增长建议（20分钟）**
- P0：停投渠道D(线下,ROI=0.73,每月亏22万)+渠道H(展示广告,ROI=0.85)
- P0：加大渠道A(搜索)投放→ROI=2.9→有扩量空间→预期每月额外GMV 200万
- P1：优化新用户"加购→下单"转化→当前50%→引入新用户首单免运费→目标65%→预期新用户GMV+30%
- P1：针对"重要挽留用户"→发老客户回归专享券→预期挽回率25%→每月额外GMV 50万
- P2：会员券使用率控制→当前55%→设券后ROI底线(>2.0)→低于底线的券→调整面额或取消

### 用到武器
W10D1-3(AARRR/Cohort/漏斗/RFM/LTV/渠道/PDS/供需)/W10D4(活动评估)

### 今日陷阱
1. **电商的"加购→下单"转化率受价格/运费/支付方式影响**：如果转化率异常低→先查技术(支付系统/库存)再查业务(价格/运费)

## W14D4：活动ROI评估 + 数仓方案设计

### 今日任务
**两件事：①评估两次大促的ROI②为数仓团队设计"会员分析主题"的DWS层表结构。** 今天一半时间做分析、一半时间做数仓设计——入职后数据分析师确实需要同时做这两件事。

### Step 1：活动ROI评估（60分钟）
- 两次大促：618年中大促(6月1-18日)+双11(11月1-11日)。每次都有"活动组"(收到活动推送/优惠券)和"对照组"(未收到)
- 618评估：活动组GMV=580万/对照组GMV=420万→增量=160万(+38%)。自然增长(对比去年同期)=+12%→扣除自然增长→"真正的增量"=160-(420×12%)=110万(+26%)。活动成本=优惠券成本80万+推广成本40万=120万。ROI=110/120=0.92→**亏了！**
  - 为什么亏：优惠券力度太大(满200减80→折扣40%→太多用户为了用券凑单→券后复购率低→很多人用了一次券就不再买了)。建议：降券力度至满200减40+设"新用户专享"→预期ROI从0.92→2.0
- 双11评估：活动组760万/对照组480万→增量=280万(+58%)。扣除自然增长(+15%)→真增量=280-(480×15%)=208万(+43%)。活动成本=150万→ROI=208/150=1.39→**正但不惊艳**。和618对比→双11效果好得多→因为双11用户有"购物心理预期"→转化率本身就高。建议：双11继续(ROI>1),618优化后再看

### Step 2：数仓方案设计（60分钟）——会员分析主题
- 需求：为"会员分析"设计DWS层表——支持"每天会员消费统计+会员等级分布+会员留存+会员RFM"
- 粒度：一行=一个会员一天（user_id + dt）
- 字段设计（15+字段）：
  | 字段名 | 类型 | 含义 | 计算逻辑 | 来源 |
  |--------|------|------|---------|------|
  | dt | string | 日期分区 | — | — |
  | user_id | string | 用户ID | — | dim_user |
  | membership_level | string | 会员等级 | — | dim_membership |
  | is_new_member | int | 是否当天新加入 | — | dim_membership.join_date=dt |
  | order_cnt | bigint | 当天订单数 | COUNT(order_id) | dwd_orders |
  | gmv | decimal(18,2) | 当天GMV | SUM(pay_amount) | dwd_orders |
  | gmv_excl_refund | decimal(18,2) | 不含退款的GMV | SUM(CASE WHEN refund=0 THEN pay_amount) | dwd_orders |
  | coupon_used_cnt | int | 当天使用券数 | COUNT(CASE WHEN coupon_id IS NOT NULL) | dwd_orders |
  | coupon_discount | decimal(18,2) | 当天券折扣总额 | SUM(coupon_amount) | dwd_orders |
  | net_gmv | decimal(18,2) | 券后净GMV | gmv - coupon_discount | 计算 |
  | category_cnt | int | 当天购买品类数 | COUNT(DISTINCT category) | dim_product |
  | avg_order_value | decimal(18,2) | 当天客单价 | gmv/order_cnt | 计算 |
  | ... | | | | |
- 分区策略：按dt分区→保留最近180天。每天凌晨2点ETL更新→SLA=每天8:00前产出
- 验收标准：每天数据量稳定(会员数×天数)。GMV和DWD层对账偏差<0.5%。券后净GMV不能为负(如果有负→排查）
