## W6D1：AB实验第一性原理

### 能力簇
**理解实验的底层逻辑** —— 为什么观察性数据不能得因果结论？随机化为什么是黄金标准？今天把AB实验最基本的"信条"建立起来。入职后PM问你"为什么不能直接对比上线前后的数据"——你能用30秒讲清楚。

### 为什么今天重要
入职第一周，leader让你review一份PM发来的"分析报告"——PM对比了新功能上线前后的数据，说"转化率涨了15%"。你要能指出：前后对比≠因果结论。上线前后可能有假期/季节/竞品变化/自然增长。你的价值不是"会做AB实验"——是"能判断什么情况下需要AB实验、什么情况下前后对比就够了"。

### 具体知识清单

**1. AB实验解决了什么问题——不是"分两组比一下"，是"排除混淆"**
- PM的需求："新推荐算法能提升阅读时长吗？"
- 错误做法：上线新算法→对比上线前后→发现涨了10%→"新算法有效！"
- 为什么错：上线前后同时发生了——①元旦假期用户更闲②竞品出了负面③自然增长。10%的涨幅有多少是算法贡献的？不知道
- AB实验做法：随机把用户分成两组→同时上线→旧算法(对照组) vs 新算法(实验组)→其他因素同等地影响两组→两组唯一系统性差异=算法→差异只能归因于算法
- **你要记住的一句话**（给PM解释用）："前后对比看到的是'算法+假期+竞品+趋势'，AB实验看到的是'算法单独的效果'。"

**2. 随机化为什么有效——大数定律+独立分配=两组在一切特征上都趋近相同**
- 随机分流→每个用户有相同的概率进入实验组→大数定律→两组在所有方面(年龄/性别/历史消费/活跃度/甚至"今天心情好不好")的分布都趋近一致→n越大越一致
- **关键认知**：随机化消除的不只是你能测量的混杂(年龄/性别)——更重要的是**你不能测量的混杂**(用户心情/手机电量/竞品活动)。这就是为什么即使你有完美的用户画像，观察性数据的回归分析也不如RCT
- Python模拟——亲眼看到随机化平衡一切特征：
  ```python
  np.random.seed(42)
  users = pd.DataFrame({
      'age': np.random.normal(30, 8, 10000),
      'activity': np.random.exponential(5, 10000),
      'history_spend': np.random.lognormal(3, 1, 10000),
  })
  users['group'] = np.random.choice(['control','treatment'], size=10000, p=[0.5,0.5])
  print(users.groupby('group')[['age','activity','history_spend']].mean())
  # 两组均值差异<0.1→随机化有效
  ```

**3. SUTVA——AB实验有效的前提。违反=结论无效。入职后要能识别**
- SUTVA(Stable Unit Treatment Value Assumption)="一个用户的潜在结果不受其他用户是否在实验组的影响"
- 违反场景：社交产品(分享→对照组被间接触及)、出行平台(司机抢单→互相竞争)、外卖(商家补贴→竞食效应)
- 后果：低估或高估策略效果。实验组效应泄漏到对照组→两组差异缩小→可能错过好策略
- 入职后你要做的：接到实验需求→第一反应不是"样本量多少"→而是"用户之间互相影响吗？需要标准AB还是Switchback/Geo？"

**4. 从PM需求到统计假设——入职后最常做的事**
- PM说："新推荐算法应该让用户看更多书"
- 你翻译成：
  - H₀：新算法和旧算法的日均阅读时长无差异(μ_new = μ_old)
  - H₁：新算法和旧算法的日均阅读时长有差异（双尾）
  - 核心指标：7天日均阅读时长(分钟)。为什么不是1天？1天太短→受新颖性效应影响
- PM说："新注册流程提升完成率"
- 你翻译：H₀:p_new=p_old, H₁:p_new≠p_old（双尾，新流程可能反而更差）

**5. AB实验的统计框架——W5知识的直接应用**
- H₀=策略无效→收集数据→检验→拿到p值→如果p<α=0.05→不太可能是随机波动→策略有真实效果
- 但p值不告诉你"效果多大"——效应量告诉你。Cohen's d=0.2小/0.5中/0.8大
- 但点估计不确定——置信区间告诉你。95%CI不包含0→等价于p<0.05
- **入职后汇报实验的标准格式**："实验组比对照组日均阅读时长增加2.3分钟(p=0.003, Cohen's d=0.4, 95%CI[0.8, 3.8])"

## W6D2：样本量计算（上）——均值指标

### 能力簇
**实验设计的第一道数学关** —— 样本量不够=实验白做。今天彻底理解均值指标样本量公式，实现计算器。入职后PM问你"这个实验要跑多久"，你能10秒估算。

### 为什么今天重要
入职后最常见的场景：PM说"我想测试这个新功能,给我一个实验方案"。你算完样本量→告诉他需要2周→PM说"能不能快点,只要1周?"→你反算MDE→告诉他"1周只能检测到>8%的效果,历史同类功能效果约3%,大概率检不出→做也是白做"。这个对话决定了"实验能不能做"——你算不准=实验白跑=浪费团队2周。

### 具体知识清单

**1. 均值指标样本量公式——每个参数的含义和选择方法**
- 公式：**n = 2(Zα + Zβ)²σ² / Δ²**
- **n = 每组需要的样本量**(不是总量！总量=2n。入职后最常见低级错误=把n当成总量→少算一半→Power不够→实验做了白做)
- Zα：α=0.05(双尾)→1.96。α越小→Zα越大→n越大。**不是越小越好**：α=0.01→n翻约1.5倍→流量成本高
- Zβ：Power=0.8→Zβ=0.84。Power越大→Zβ越大→n越大。**不是越高越好**：Power=0.9→n翻约1.3倍→时间成本高
- σ²：指标的方差。从哪获取？→**拉过去30天数据，算对照组用户的指标标准差**。这是入职后你最常做的事
- Δ：你想检测到的最小效应。这是**业务决策，不是数学问题**。PM说"只有提升>5%才值得开发"→Δ=5%

**2. Δ怎么选——这是你和PM谈判的核心参数**
- 方法1(业务重要性)：PM说"效果<3%不值得做"→Δ=3%。检测不到3%以下无所谓，反正不值得做
- 方法2(历史参考)：同类策略历史上效果约5-10%→取Δ=5%
- 方法3(反向计算)：已知每天1万新用户→实验最长跑2周→n=14万→反算MDE→发现MDE=8%→历史效果>8%的策略极少→这个实验做不了(灵敏度不够)→跟PM说"要么延长时间，要么放宽预期"
- **入职必备技能：MDE反向计算** → 给n/α/Power/σ→反算Δ→判断"这个实验在当前流量下能检测到什么程度的效果"

**3. 🔥平方关系——Δ减半, n翻4倍**
- n ∝ 1/Δ²→Δ减半→n×4倍。Δ减到1/3→n×9倍
- 追求高灵敏度的代价非常大。从检测"提升10%"到检测"提升5%"→n×4→实验时长×4
- Python实现+可视化：
  ```python
  def sample_size_mean(alpha, power, sigma, delta):
      z_alpha = stats.norm.ppf(1 - alpha/2)
      z_beta = stats.norm.ppf(power)
      return int(np.ceil(2 * (z_alpha+z_beta)**2 * sigma**2 / delta**2))
  
  deltas = np.arange(0.5, 10, 0.5)
  ns = [sample_size_mean(0.05, 0.8, sigma=10, delta=d) for d in deltas]
  # 画Δ-n曲线→标注"Δ=2→n=393, Δ=1→n=1570(4倍!), Δ=0.5→n=6279(16倍!)"
  ```

**4. σ从哪来——入职后实际操作**
- 最常用：拉过去30天数据→筛选出对照组用户(或模拟)→算核心指标的σ
- 注意：剔除异常期。如果过去30天包含双11→σ偏大→算的n偏大→样本量被高估→浪费流量
- σ和Δ的单位要一致：Δ是绝对值(元/分钟)→σ也用绝对值。Δ是百分比(如提升5%)→σ用CV=σ/μ

**5. 入职后标准的样本量计算流程**
1. 找PM确认Δ(业务重要性阈值)
2. 拉历史数据算σ
3. 设定α=0.05(双尾), Power=0.8
4. 算每组需要的n
5. 看日活→算实验需要的天数
6. 如果天数太长→和PM谈判(增大Δ/降低Power/选更稳定的指标)

## W6D3：样本量计算（下）——比例指标 + MDE判断

### 能力簇
**留存率/转化率/点击率的样本量** —— 互联网最常用指标。MDE让你在实验结果不显著时，能判断"是真没效果还是灵敏度不够"

### 为什么今天重要
入职后leader找你review一个"不显著"的实验结果——PM失望地说"策略没效果"。你算MDE→发现MDE=10%→但同类策略历史效果约3%→实验灵敏度不够→不是策略没效果，是实验设计有问题。你把这个分析写进报告→leader对你刮目相看。区分高级和初级分析师的标志：初级说"不显著=没效果"，高级说"不显著→先看MDE→再判断"。

### 具体知识清单

**1. 比例指标样本量公式——和均值的唯一差异在方差**
- 公式：**n = 2(Zα + Zβ)² × p(1-p) / Δ²**
- 差异：σ²被替换为p(1-p)。比例指标的方差=p(1-p)
- **p(1-p)的性质**：p→0或1→p(1-p)→0。p=0.5→p(1-p)=0.25(最大!)→需要最大n
- 直觉：转化率=50%→买和不买各一半→最大的不确定性→需要最大n来确认效果。转化率=2%→几乎确定"大部分不转化"→不确定性小→需要更少n
- **入职后最常踩的坑**：Δ用相对提升而非绝对提升。留存率从40%→44%→Δ=4pp(绝对值)=10%(相对值)→公式用Δ=0.04(4pp),不是0.1！用错了→n被严重低估→实验Power不够→白做

**2. p(1-p)曲线——和PM讲"为什么这个实验贵"的工具**
- 画p从0.01到0.99→p(1-p)钟形曲线→在0.5达到峰值
- 业务翻译：转化率50%的指标=最难做实验。转化率98%或2%的指标=样本量需求小得多
- **入职场景**：PM问"为什么测'是否购买'比测'是否点击'需要更多用户"→你画p(1-p)曲线说"点击率50%附近(0.25)→波动最大。购买率2%附近(0.02)→波动小→需要更少样本就能确认效果"

**3. 🔥MDE——入职后最有用的"救场工具"**
- MDE(Minimum Detectable Effect)=在给定α/Power/n/σ下，实验能检测到的最小效应
- 反向公式：**Δ = (Zα+Zβ)×σ×√(1/n₁+1/n₂)**
- **不显著时的标准处理流程**：
  1. 算MDE→得到"在这个样本量和Power下,最小能检测到Δ=XX的效果"
  2. 对比PM预期效应→"我预期提升5%"
  3. MDE=3%<5%→灵敏度够→大概率真没效果→建议放弃
  4. MDE=8%>5%→**灵敏度不够！** ×→不能说没效果→建议延长实验或扩大流量
- Python实现：
  ```python
  def calc_mde_mean(n_per_group, alpha, power, sigma):
      z_alpha = stats.norm.ppf(1 - alpha/2)
      z_beta = stats.norm.ppf(power)
      return (z_alpha + z_beta) * sigma * np.sqrt(2/n_per_group)
  ```

**4. 降低方差=加速实验——不需要更多样本也能提高灵敏度的三招**
- 招1：剔除极端值(Capping)→σ变小→MDE变小。但要验证剔除的是"错误"不是"真实"
- 招2：聚焦核心人群→只实验高活跃用户→他们的行为更稳定→σ更小→MDE变小。代价：结论只适用该人群
- 招3：换指标→均值类指标波动大→换比率类。如"人均消费"→"付费率"→方差变小

### 能力簇
**从业务需求到完整实验方案** —— 今天产出你入职后最常写的文档：AB实验设计文档。leader给你一个PM需求，你能独立输出包含假设/样本量/指标/决策标准的完整方案。

### 为什么今天重要

### 具体知识清单

**1. 从PM需求到统计假设——翻译能力**
- PM："新推荐算法应该让用户看更多书"→核心指标=7天日均阅读时长(分钟)→均值类→H₀:μ_new=μ_old, H₁:μ_new≠μ_old
- PM："新注册流程提升完成率"→核心指标=注册完成率→比例类→H₀:p_new=p_old, H₁:p_new≠p_old(双尾,新流程可能更差)
- 为什么用双尾：互联网大部分用双尾(不知道策略是好是坏)。只有100%确定不会变差时才用单尾

**2. 分流单位——选错了实验白做**
- User(用户级)：最常用。策略影响"用户长期行为"→用User
- PV(页面级)：同一用户可能看新旧两个版本→用户困惑→只适合"纯外观测试"
- Device(设备级)：未登录用户的产品
- Session(会话级)：一次性策略(弹窗)
- **陷阱：PV分流但按User分析→标准误算错→p值偏小→假阳性飙升→需要聚类标准误**

**3. 指标体系三层——不设护栏=自欺欺人**
- 核心指标：和假设直接相关的1-2个。事前指定
- 护栏指标：绝对不能显著恶化的(投诉率/卸载率/退款率)。**必须事前指定！事后说"这个跌了不算"=选择性汇报**
- 观察指标：长期关注的(留存/付费)

**4. 实验时长——不只是n÷日活**
- 必须覆盖一个完整周期(≥1周,推荐2周)→周末和工作日行为不同
- 新颖性效应→前几天虚高→太短=高估效果
- 实验时长=样本量/(日活×可用流量比例) + 新用户缓冲时间

## W6D5：AA实验 + SRM + 策略生效验证

### 能力簇
**实验上线前后的健康检查** —— 三道防线确保实验不出低级错误。入职后最惨的事：实验跑了2周→发现策略没上线→白跑。今天学会防御。

### 为什么今天重要
真实工作中，实验失败80%的原因不是分析方法错了，是实验本身有问题：分流bug、策略没生效、两组用户不均衡。今天三道防线确保你不会犯这些低级错误——犯了=浪费时间+丢掉信任。

### 具体知识清单

**1. AA实验——"分流系统在正常工作吗？"**
- 什么是AA：两组都不给新策略→应无差异→出现显著差异→分流系统有bug
- 做了100次AA→约5次p<0.05→正常(α=0.05)。如果30次p<0.05→分流有隐藏偏差→排查分流系统
- Python模拟：
  ```python
  fp = sum(1 for _ in range(1000) 
           if stats.ttest_ind(np.random.normal(100,15,1000), 
                              np.random.normal(100,15,1000))[1] < 0.05)
  print(f"假阳性率={fp/1000:.3f} ≈ 0.05")
  ```
- **入职后操作**：新实验上线前→跑1-2天AA→看核心指标p值→如果有显著→暂停→排查分流系统

**2. SRM检验——"实际流量分配符合设计吗？"**
- 设计50/50→实际跑一周→实验组48%/对照组52%→不对！卡方检验→p<0.05→有SRM→暂停分析
- `chisquare([4800,5200], f_exp=[5000,5000])`→p很小→有问题
- 常见原因：实验组用户被意外排除(某个OS版本)/某组卸载率更高/分流系统bug
- **SRM没过=所有分析暂停。绝对不能"不管它,继续分析"**

**3. 🔥策略生效验证——最致命的错误**
- 实验p=0.9→查策略→根本没上线→2周白费
- 五法：①埋点检查(实验组触发新策略event了吗)②数据量对比③关键行为对比④日志审查⑤用户反馈
- **必须在实验上线后1-2天内完成！不能等到结束才发现**

**4. 三道防线时间线**
- 上线前：Pre-AA(历史数据验证)
- 上线后Day1-2：策略生效验证+SRM
- 持续：AA监控(如果SRM中途变化→排查)
- 结束：回顾三道防线→确认实验可信

## W6D6：实验分析全流程——从数据到可交付的报告

### 能力簇
**独立完成实验分析并输出结论** —— 今天产出入职后最重要的工作输出：一份完整的AB实验分析报告。leader拿着这份报告可以直接做决策。

### 为什么今天重要
入职后你的核心产出就是实验报告。一份好的报告=leader能在5分钟内看完+做决策。一份差的报告=leader看不懂+追着你问"所以呢"+"到底推不推全"。今天学的不只是怎么选检验方法——更重要的是"怎么把分析结论写成一份可用的报告"。

### 具体知识清单

**1. 检验方法选择——根据数据类型选，不确定就用Welch's**
- 连续+大样本→Welch's t(不确定等方差→Welch's更稳健)
- 比例→卡方检验或z检验→大样本等价
- 口诀：不确定等方差→Welch's。大样本(n>100)→CLT保证t检验可用
- **入职实际场景**：你不会手动比较Student's t和Welch's的区别——直接用Welch's。更安全+统计软件默认

**2. 完整分析报告的必备要素**
- p值+效应量+置信区间——三者缺一不可
- 护栏指标逐一检查——有显著恶化→报告里必须标注
- 分群分析——按渠道/新老用户/城市看效应是否一致。但做了分群必须多重检验校正(BH)
- 结论明确——推全/优化/下线，不模棱两可

**3. 决策标准——不只看p<0.05**
- **推全**：核心p<α + 效应量>业务重要性 + CI不过宽 + 护栏OK + 成本可接受
- **优化(不确定)**：正向趋势但不显著→算MDE→判断灵敏度是否够
- **下线**：核心显著为负或护栏显著恶化→立刻下线，不要犹豫

**4. 分析报告模板——入职后直接套**
```markdown
# AB实验分析报告
## 1. 实验概况
## 2. 数据质量(SRM/生效验证/清洗)
## 3. 核心指标(p+效应量+CI)
## 4. 护栏指标(逐一检查)
## 5. 分群分析(校正后)
## 6. 结论与建议(推全/优化/下线+理由+风险)
```
