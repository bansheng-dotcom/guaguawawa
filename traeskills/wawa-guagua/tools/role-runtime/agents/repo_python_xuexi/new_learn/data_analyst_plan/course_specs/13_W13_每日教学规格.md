## W13D1：数据理解+清洗+SQL取数

### 今日任务

### 具体操作步骤

**Step 1：数据盘点（30分钟）——搞清楚"我有什么数据"**
- 5份数据的来源和内容：
  1. `user_info.csv`：用户基础信息（user_id/注册日期/城市/设备/渠道来源/会员等级）—30万行
  2. `reading_log.csv`：阅读行为日志（user_id/book_id/阅读时长/阅读日期/读完/加书架/付费/推荐来源）—500万行，过去6个月
  3. `ab_experiment.csv`：AB实验分流数据（user_id/实验组别/分流日期/实验名称）—30万行。实验名称="recommend_v2_test"，2025-05-01至2025-07-15，50/50分流
  4. `marketing_spend.csv`：市场投放数据（日期/渠道/花费/曝光量/点击量/新用户量）—过去6个月，5个渠道
  5. `content_info.csv`：书籍信息（book_id/书名/作者/品类/字数/上架日期/评分/评论数）—5万本

- 用W2D1的六板斧初探每份数据：`info()/describe()/head()/shape/dtypes/value_counts()`
- 每份数据记录：行数/列数/各列的缺失率/数据类型是否正确/有没有明显的异常

**Step 2：数据清洗（60分钟）——把脏数据洗到可用**
- 用W4D2-D3学的完整清洗流程：
  - 缺失值处理：reading_log中"阅读时长"缺失率约5%→分析缺失模式（是随机缺失还是某类书籍/用户特别容易缺？）→中位数填充或标记
  - 异常值处理：阅读时长>24小时（不可能,数据错误）→标记为NaN或用0替换。阅读时长=0但"读完"=True→矛盾→标记为数据错误
  - 重复值：同一user_id+同一book_id+同一日期出现多次→可能是系统重复记录→`drop_duplicates`
  - 格式统一：日期列统一为datetime、分类列统一为category（W4D3优化）、金额列统一为float
  - 外键校验：reading_log的user_id是否都在user_info里？reading_log的book_id是否都在content_info里？（W4D3数据一致性验证）
- **清洗日志**（W4D2清洗日志模板）：每一步记录"做了什么/处理前行数/处理后行数/处理了多少条异常"

**Step 3：SQL取数（30分钟）——实验组/对照组用户行为提取**
- 用W3学的SQL（在Python中用SQLite模拟）：
  ```sql
  -- 提取实验组和对照组的用户行为
  SELECT a.group_name, r.user_id, r.reading_date, r.reading_duration, r.is_finished, r.is_paid
  FROM ab_experiment a
  JOIN reading_log r ON a.user_id = r.user_id
  WHERE a.experiment_name = 'recommend_v2_test'
    AND r.reading_date BETWEEN '2025-05-01' AND '2025-07-15';
  
  -- 验证分流均衡性（AA检验）
  SELECT group_name, COUNT(DISTINCT user_id) as user_cnt,
         AVG(pre_exp_reading) as pre_avg_reading
  FROM ab_experiment
  GROUP BY group_name;
  -- 两组人数≈接近(50/50)→分流OK。实验前阅读时长≈接近→AA通过
  ```

**Step 4：数据质量验证（20分钟）——确认数据可以进入分析**
- 用W8D4的数据质量五维度检查：
  - 完整性：实验组和对照组各有约15万用户→和设计50/50一致→✓
  - 一致性：reading_log的user_id都在ab_experiment中→无"孤儿用户"→✓
  - 准确性：阅读时长没有负数、日期没有未来、金额没有异常→✓
  - 及时性：数据覆盖2025-05-01至2025-07-15→实验期完整→✓

## W13D2：推荐算法AB实验评估

### 今日任务
**完成推荐模型更新的AB实验评估——从设计回顾到分析到决策建议。** 这是本周最核心的分析任务。入职后"评估算法更新效果"是你最常做的事。

### 具体操作步骤

**Step 1：实验设计回顾（20分钟）——确认实验本身没问题**
- 用W6D4-D5的完整实验设计框架回顾这个实验：
  - 假设：H₀=新旧推荐模型在"7日人均阅读时长"上无差异。H₁=有差异
  - 分流：50/50→是否均衡？用Day1的数据验证→两组实验前特征接近→✓
  - 指标：核心=7日人均阅读时长（均值类）。护栏=用户投诉率/卸载率。观察=30日留存/付费转化
  - 样本量：实验跑了75天→n够吗？用W6D2的样本量计算器验证→数据量充足→Power>0.8→✓
  - AA检验：用W6D5的AA模拟→实验前两组指标无显著差异→分流系统OK→✓
  - SRM检验：实际流量比=实验组49.8%/对照组50.2%→卡方检验p>0.05→符合设计→✓
  - 策略生效验证：实验组用户是否真的收到了新推荐模型？→查埋点`recommend_v2_test`事件→实验组用户触发率>99%→策略生效→✓

**Step 2：核心指标分析（60分钟）——p值+效应量+置信区间**
- 用W6D6的完整分析流程：
  - 选检验方法：7日人均阅读时长→连续指标→大样本→用Welch's t检验（W6D6）
  - p值：`stats.ttest_ind(treat['reading_duration'], control['reading_duration'], equal_var=False)`→p=0.003
  - 效应量：Cohen's d=(实验组均值-对照组均值)/pooled_std→d=0.4（中等）
  - 置信区间：95%CI [0.8, 3.8]分钟→不包含0→和p<0.05一致
  - 标准汇报格式："实验组比对照组7日人均阅读时长增加2.3分钟(p=0.003, Cohen's d=0.4, 95%CI[0.8,3.8])"

**Step 3：分群分析（40分钟）——不同用户群效果一致吗？**
- 用W6D6的分群分析+多重检验校正：
  - 分群维度1-新老用户：新用户(d=0.6 → 效果更强！新推荐模型对新用户帮助大)。老用户(d=0.2 → 效果弱,老用户习惯了旧推荐)
  - 分群维度2-活跃度：高活用户(d=0.1→几乎无效,他们本来就读很多)。低活用户(d=0.7→效果很强!新推荐模型"激活"了低活用户)
  - 分群维度3-渠道：各渠道效果基本一致→无渠道差异
  - **多重检验校正**：做了3个维度×内部各2-3个子群=约8个检验→用BH校正（W5D6）→校正后新用户和低活用户仍然显著→其他不再显著
  - 写结论："新推荐模型的效果主要来自'新用户'和'低活用户'——它帮助这两类用户找到了更感兴趣的内容。对老用户和高活用户→效果不明显——他们已经有稳定的阅读习惯"

**Step 4：护栏指标检查（20分钟）——有没有"副作用"？**
- 用W6D6护栏检查：用户投诉率→实验组2.1% vs 对照组2.0%→p=0.45→无显著差异→✓。卸载率→实验组1.8% vs 对照组1.9%→无显著差异→✓。推荐多样性下降？→实验组用户阅读品类数=2.8 vs 对照组=2.5→多样性反而提升了→好

**Step 5：决策建议（20分钟）——推全还是继续优化？**
- 用W6D6决策标准：核心指标p<0.05+效应量中等(d=0.4)+CI不包含0+护栏指标未恶化→建议**推全**。但附条件：①关注长期效应(继续监控30日留存→如果衰减需调整)②对新用户和低活用户的效果最大→推全后重点宣传这两个人群③老用户效果弱→后续研究"如何让老用户也受益于新推荐"
