## W2D1：DataFrame核心思维

### 能力簇
**进入DataFrame世界** —— 理解pandas的设计哲学，掌握数据初探全流程。今天每一个操作都要搞清楚"W1的Python手写版长什么样、pandas一行版长什么样"

### 为什么今天重要
W1你写了7天纯Python。今天pandas让你看到：之前30行代码做的事，现在1行搞定。但前提是你理解W1的容器(list/dict)、控制流(for/if)、函数(def)——pandas底层就是这些东西的工程化版本。不理解W1→pandas只是死记硬背。理解了W1→pandas是自然延伸。

### 具体知识清单

**1. pandas是什么——从W1自然延伸**
- W1你学了list和dict。list存"一排数据"，dict存"标签→值的映射"
- pandas的Series = 带标签的list = W1的dict + W1的list的合体。每个值有个标签(index)，可以按位置取(`[0]`)也可以按标签取(`['a']`)
- pandas的DataFrame = dict of Series。每一列是一个Series，列名是dict的key，列值是Series。整个DataFrame像一个超级增强版的"list套dict"
- 为什么不用纯Python：W1你做"统计每个城市的销售额"→需要手写for循环+if判断+dict累加→15行代码。pandas: `df.groupby('城市')['金额'].sum()` → 1行。而且pandas底层用C写的，比Python快100-500倍
- **核心认知**：pandas不是"新的要背的东西"，是"W1你手写的那堆代码的工业级实现"。你今天学的每个函数，底层都是W1的list/dict/for/if的组合

**2. 数据读入——从文件到DataFrame**
- `import pandas as pd` — 约定俗成的别名。不写全称，全世界都这么写
- `df = pd.read_csv('文件路径', encoding='utf-8')` — 最常用。CSV→DataFrame
- `type(df)` → `pandas.core.frame.DataFrame`。注意不是list也不是dict
- `pd.read_csv('data.csv', nrows=100)` — 大文件先读100行看看结构，再读全量
- `pd.read_csv('data.csv', usecols=['列1','列2'])` — 只读需要的列。节省内存+加快读取
- `pd.read_csv('data.csv', dtype={'user_id': str})` — 指定列类型。防止"00123"变成123
- `pd.read_csv('data.csv', parse_dates=['日期'])` — 读的时候就转成日期类型
- `pd.read_excel('data.xlsx', sheet_name='Sheet1')` — Excel文件
- `pd.read_json('data.json')` — JSON文件
- **W1连接**：W1你手写csv.DictReader分行读→pandas一行read_csv全搞定。W1的`open()+csv.DictReader()+for循环+=list.append()`=今天的`pd.read_csv()`
- **陷阱1：Windows路径`\`被当转义符**："C:\data\orders.csv"→`\d`被当`\d`转义→报错。用`/`：`C:/data/orders.csv` 或 `\\`：`C:\\data\\orders.csv` 或 在前面加r：`r"C:\data\orders.csv"`
- **陷阱2：CSV有BOM头(UTF-8 with BOM)→第一列名变成`ï»¿订单号`→用`encoding='utf-8-sig'`**
- **陷阱3：CSV文件太大一次性读→内存爆了→加`nrows`先探索 或 `chunksize`分块(周四学)**

**3. DataFrame初探六板斧——拿到任何新数据先跑这6行**
- `df.head(n)` — 看前n行(默认5行)。直观感受数据长什么样
- `df.tail(n)` — 看后n行。检查数据是否"突然断了"或最后几行格式异常
- `df.info()` — **最重要的一步！** 显示：①列名有哪些 ②每列多少非空值(一眼看出缺失) ③每列dtype(一眼看出类型对不对，金额是否object) ④内存占用。每列non-null数不等→有缺失。object类型→可能需要转成数字/日期
- `df.describe()` — 数值列的8个统计量：count(非空数量)/mean/std/min/25%/50%/75%/max。一眼看出：量纲(均值几百还是几百万)、离散度(std是均值的多少倍)、范围(min和max差距)、是否有极端值(max是75%的几十倍→肯定有异常)
- `df.shape` — (行数, 列数)。tuple格式。`df.shape[0]`行数，`df.shape[1]`列数
- `df.columns.tolist()` — 所有列名的list。方便复制粘贴列名到代码里
- `df.dtypes` — 每列的数据类型。object(字符串)/int64(整数)/float64(浮点)/datetime64(日期)/bool(布尔)。重点找：应该是数字的列→显示object(被当成文本了)。应该是日期的列→显示object(被当成文本了)
- `df['列名'].value_counts()` — 看一列里每个值出现了几次。类别列(城市/品类/性别)→看有哪些值、分布均不均匀。数值列→看是否有大量重复(可能应该是类别列)
- `df['列名'].value_counts(normalize=True)` — 变成比例。比看绝对数更直观
- **W1连接**：`df.info()` = W1的`type(var) + len(lst) + for k in dict.keys()`三合一。`df.describe()` = W1你手写`sum()/len()/max()/min()+排序取中位数`

**4. 行列操作——选你想要的数据**
- 选一列(返回Series)：`df['列名']`。等价于W1的`dict['key']`取dict里的一个value
- 选多列(返回DataFrame)：`df[['列1','列2']]`。**注意双括号！** 里面是一个list
- `df.loc[行标签, 列标签]` — 按标签名选。`df.loc[0:5, ['金额','城市']]` → 取标签0-5行(包含5!)的金额和城市列。**loc包含右边界**
- `df.iloc[行位置, 列位置]` — 按数字位置选。`df.iloc[0:5, 0:3]` → 取位置0-4行(不包含5!)的前3列。**iloc不包含右边界(和W1的list切片一样!)**
- `df.at[行标签, 列标签]` — 取单个值。`df.at[3, '金额']` → 比`.loc`快
- `df.iat[行位置, 列位置]` — 取单个值。`df.iat[3, 0]` → 比`.iloc`快
- **W1连接**：`df.iloc[0:5]`和W1的`lst[0:5]`切片行为一致(左含右不含)。`df.loc[0:5]`包含右边界→是pandas特别设计的(因为标签选择时包含右边界更直观)
- **陷阱1：`df.loc[]`和`df.iloc[]`搞混→取出来的数据不对。标签=名字(可能是数字也可能是字符串)，位置=数字序号(永远是0,1,2...)**
- **陷阱2：`df.loc[0:5]`包含标签5→但`df.iloc[0:5]`不包含位置5→同样的`0:5`，loc和iloc行为不同！**
- **陷阱3：选多列必须双括号`df[['A','B']]`→单括号`df['A','B']`→报错KeyError**

**5. 布尔索引——SQL WHERE的pandas版。W1 if判断的向量化版**
- 单一条件：`df[df['金额'] > 500]` — 金额大于500的所有行
- 多条件AND：`df[(df['金额'] > 500) & (df['城市'] == '北京')]` — **每个条件必须用括号包起来！必须用`&`不能用`and`！**
- 多条件OR：`df[(df['城市']=='北京') | (df['城市']=='上海')]` — **必须用`|`不能用`or`！**
- 多值筛选：`df[df['城市'].isin(['北京','上海','深圳'])]` — 城市在这个名单里→isin比多个OR简洁
- 取反：`df[~df['城市'].isin(['北京','上海'])]` — 城市不在这个名单里。`~`是pandas的NOT运算符
- 字符串筛选：`df[df['商品'].str.contains('耳机', case=False)]` — 商品名包含"耳机"。case=False忽略大小写
- 组合筛选：`df[(df['金额']>500) & (df['商品'].str.contains('耳机')) & (~df['城市'].isin(['北京']))]` — 多条件组合，每个条件一对括号
- **W1连接**：`df[df['金额']>500]` = W1的`result=[]; for item in lst: if item['金额']>500: result.append(item)`。刚才那4行Python→现在1行pandas
- **陷阱1：`and`/`or` vs `&`/`|`——pandas的布尔索引必须用按位运算符`&`/`|`！用`and`/`or`直接报错。根因：`and`/`or`是Python级别的逻辑运算(操作单个bool)，`&`/`|`是numpy/pandas级别的按位运算(操作bool数组)**
- **陷阱2：不加括号→运算符优先级错乱。`df[df['金额']>500 & df['城市']=='北京']`→先算`500 & df['城市']`→报错。因为`&`的优先级比`>`高！必须每个条件一对括号**

**6. 排序与基础统计**
- `df.sort_values('金额', ascending=False)` — 按金额降序。ascending=False=从大到小，True=从小到大(默认)
- `df.sort_values(['城市','金额'], ascending=[True, False])` — 先城市升序，城市相同再金额降序
- `df['列'].nlargest(10)` — 该列最大的10个值+对应行。比sort_values+head更快
- `df['列'].nsmallest(5)` — 该列最小的5个值
- `df['列'].unique()` — 有哪些不同值。返回numpy array
- `df['列'].nunique()` — 有多少不同值。`len(df['列'].unique())`的快捷版
- `df['列'].value_counts().head(10)` — 出现最多的Top10
- **W1连接**：`df.sort_values()` = W1的`sorted(lst, key=lambda x:x['金额'], reverse=True)`。`df['列'].unique()` = W1的`set(lst)`

**7. 列操作**
- 新增列：`df['新列'] = 值`。如`df['税后金额'] = df['金额'] * 0.87`
- `df.assign(新列1=表达式1, 新列2=表达式2)` — 一次新增多列，且不修改原df(返回新df)。推荐写法
- 删除列：`df.drop(['列1','列2'], axis=1)` — axis=1表示删列，axis=0表示删行。默认不修改原df→`inplace=True`或赋值回去
- 重命名列：`df.rename(columns={'旧名':'新名', '旧名2':'新名2'})`
- **W1连接**：`df['新列'] = ...` = W1的`for o in orders: o['新key'] = ...`。W1手写循环→pandas向量化一次搞定

## W2D2：分组聚合全量

### 能力簇
**数据的分组与汇总** —— 掌握groupby/agg/transform/filter四种分组模式。这是pandas最核心的能力，90%的数据分析都会用到

### 为什么今天重要
数据分析的本质就是"分类汇总"：每个城市的销售额、每个品类每月的利润、每个用户的累计消费...所有这些回答的都是"按XX分组后看YY"。groupby就是pandas实现这个的万能钥匙。今天学的agg(汇总)、transform(保持形状)、filter(筛选组)三种模式，学完就能应对90%的分组需求。

### 具体知识清单

**1. groupby基础——分组+聚合**
- `df.groupby('城市')` → 返回GroupBy对象。**打印出来看到的是一个内存地址，不是数据！** 必须接聚合函数才有结果
- `df.groupby('城市')['金额'].sum()` → 每个城市的总销售额。返回Series
- `df.groupby('城市')[['金额','利润']].sum()` → 多列聚合。返回DataFrame
- `df.groupby('城市').sum()` → 对所有数值列都聚合。慎用——可能产生你不需要的结果
- `df.groupby('城市', as_index=False).sum()` → 城市保持为普通列而不是index。不加的话城市变成index→后续操作可能不方便
- 多级分组：`df.groupby(['品类','城市']).sum()` → 层次化索引(品类→城市→指标)。返回MultiIndex DataFrame
- **W1连接**：groupby = W1你手写：
  ```python
  # W1手写版(伪代码)
  city_sales = {}
  for o in orders:
      city = o['城市']
      if city not in city_sales: city_sales[city] = 0
      city_sales[city] += o['金额']
  # pandas一行版
  df.groupby('城市')['金额'].sum()
  ```
  理解这个对照→你就理解了groupby在做什么
- **陷阱1：groupby返回GroupBy对象，不接聚合函数直接print→只看到一个内存地址(如`<pandas.core.groupby.DataFrameGroupBy object at 0x7f...>`)。必须`.sum()`/`.mean()`等才有结果**
- **陷阱2：groupby默认把分组列变成index→后续`.loc[]`、`.reset_index()`等行为都受影响→加`as_index=False`保持为列**

**2. agg——对不同的列做不同的聚合（最灵活的分组方式）**
- 单列单函数：`df.groupby('城市')['金额'].agg('sum')` → 和`.sum()`一样但更灵活
- 单列多函数：`df.groupby('城市')['金额'].agg(['sum','mean','count','std','min','max'])` → 一列出多个统计量→MultiIndex列
- 多列不同函数：`df.groupby('城市').agg({'金额':'sum', '订单号':'count', '利润':'mean'})` → 每个列指定不同聚合方式
- **命名聚合（推荐，pandas 0.25+）**：`df.groupby('城市').agg(总销售额=('金额','sum'), 平均单价=('金额','mean'), 订单数=('订单号','nunique'))` → 结果列名是中文，直接可用
- 自定义聚合：`df.groupby('城市').agg(极差=('金额', lambda x: x.max()-x.min()))` → lambda灵活定义
- 同时用内置和自定义：`.agg(总销售=('金额','sum'), 极差=('金额', lambda x:x.max()-x.min()))`
- **W1连接**：agg = W1的"遍历分组→对每组跑一个函数→汇总结果"。custom agg的lambda = W1的def函数→传入分组后的子集→返回一个值
- **陷阱1：`agg`和`aggregate`是同一个函数→用`agg`更短**
- **陷阱2：自定义聚合函数里用lambda→lambda里不能有复杂的if/else(多行逻辑)→复杂逻辑单独def函数再传进去**

**3. transform——分组后保持原形状。和agg最本质的区别**
- 关键区别一句话：**agg把n行压成k行(每组1行)，transform保持n行不变(n行→n行)**
- `df.groupby('城市')['金额'].transform('mean')` → 每行=该行所在城市的平均金额。365行→365行，每行都是所在城市的均值
- 用途1分组标准化(去量纲)：`df['金额_zscore'] = df.groupby('城市')['金额'].transform(lambda x: (x-x.mean())/x.std())` → 每行的金额减去该城市的均值再除以标准差→不同城市间可比较
- 用途2填充分组均值：`df['金额'].fillna(df.groupby('城市')['金额'].transform('mean'))` → 缺失值用"同城市其他人的均值"填充，比全局均值更合理
- 用途3计算"高于组均多少"：`df['高于组均价'] = df['金额'] - df.groupby('城市')['金额'].transform('mean')` → 正值=高于均值，负值=低于均值
- 用途4分组排名：`df.groupby('城市')['金额'].transform('rank', ascending=False)` → 在各自城市内的销售排名
- **W1连接**：transform = W1的for循环+if判断。W1里你遍历每个人→判断所在城市→用城市均值填充→transform一行搞定
- **agg vs transform vs apply 选择决策表**：
  | 你要什么 | 用哪个 | 输入shape | 输出shape | 示例 |
  |---------|--------|----------|----------|------|
  | 每组一个汇总值 | agg | (n,) | (k,) k=组数 | 每城市总销售额 |
  | 每行一个值，用的组统计量 | transform | (n,) | (n,) | 每行=所在城市均值 |
  | 复杂的逐行/逐组操作 | apply | 灵活 | 灵活 | 每组Top3+其他合并 |

**4. filter——筛选"符合条件的组"，不是筛选行！**
- `df.groupby('城市').filter(lambda g: g['金额'].sum() > 10000)` → 只保留总销售额>10000的城市的所有行。**筛选的是组，返回的是这些组的所有行**
- 用途：剔除数据量太少的组、找大客户组、排除低频用户
- **陷阱1：`filter`里lambda的参数g是一个DataFrame(这一组的所有行)→返回True(保留整组)或False(丢弃整组)**
- **陷阱2：`df.groupby('城市').filter(lambda g: g['金额']>500)`→报错！因为`g['金额']>500`返回的是bool Series(多行)，不是单个True/False→filter需要单个True/False**

**5. 累计与滚动窗口**
- `df.sort_values('日期').groupby('用户')['金额'].cumsum()` → 每用户累计消费曲线。必须先sort_values确保日期有序！
- `df.groupby('用户').cumcount()` → 每用户第几次消费(从0开始)。`+1`变成第1次/第2次
- `df.sort_values('日期').groupby('用户')['金额'].rolling(3).mean()` → 每用户最近3单的移动平均
- `df.sort_values('日期').groupby('用户')['金额'].expanding().mean()` → 每用户到当前为止的累计平均
- **W1连接**：cumsum = W1的`total=0; for x in lst: total+=x; result.append(total)`→pandas一行搞定
- **陷阱1：cumsum/cumcount依赖顺序→必须先`.sort_values()`确保数据有序**
- **陷阱2：rolling窗口需要足够的行→前N-1行的结果是NaN(不够窗口大小)→加`min_periods=1`允许不够时也算**

**6. 分箱——把连续值变成类别**
- `pd.cut(df['金额'], bins=[0, 200, 500, 2000, 99999], labels=['小单','中单','大单','超大单'])` → 按值域等宽切分
- `pd.qcut(df['金额'], q=4, labels=['Q1','Q2','Q3','Q4'])` → 按数量等频切分(每份一样多行)
- `pd.cut(df['金额'], bins=[0, 200, 500], include_lowest=True)` → 包含最小值(0被分到第一组)
- **cut vs qcut：cut="钱多钱少"(按值)，qcut="人头均分"(按排名)。RFM分箱通常用qcut(每个等级人数一样多才有比较意义)**
- **陷阱1：cut的bins默认左开右闭→最小值(0)可能不在任何区间→加`include_lowest=True`**
- **陷阱2：qcut要求每个箱至少有1条数据→如果数据有大量重复值可能导致报错→加`duplicates='drop'`**

**7. 其他聚合技巧**
- `df.groupby('城市').size()` — 每组行数(含NaN)。返回Series
- `df.groupby('城市').count()` — 每组非NaN行数(可能每列不同)。返回DataFrame
- `df['列'].nunique()` — 不重复值的个数。等价于`len(df['列'].unique())`
- `df.groupby('城市').agg(订单数=('订单号','nunique'))` — 注意不是`count`(数行数)而是`nunique`(数不重复订单数)
- **`size()`和`count()`区别**：size数行(含NaN)，count数非空值。多数场景同意，但有NaN时不同

## W2D3：合并与连接全量

### 能力簇
**多表关联** —— 掌握merge/concat/join，能检测和预防行数膨胀

### 具体知识清单

**1. merge —— 像SQL JOIN**
- `pd.merge(left_df, right_df, on='user_id')` — 默认内连接(两表都有的key才保留)
- `how='left'`：左表全部保留，右表匹配不上的填NaN
- `how='right'`：右表全部保留
- `how='inner'`：交集(默认)
- `how='outer'`：并集。所有key都保留，匹配不上的各自填NaN
- `on=['user_id','order_date']` — 多列关联(两表的这多列值都相同才算匹配)
- `left_on='uid', right_on='user_id'` — 两表key列名不同时用
- `suffixes=('_订单','_用户')` — 两表有同名非key列时加后缀区分，否则会覆盖
- `indicator=True` — 新增`_merge`列，标记每行来源：`left_only`(只在左表)/`right_only`(只在右表)/`both`(两表都有)。**排查数据不匹配的神器**
- `validate='many_to_one'/'one_to_one'/'one_to_many'/'many_to_many'` — 验证关联关系→不符合就报错。**防御膨胀的第一道防线**
- **W1连接**：merge = W1里你写"两个list套dict→遍历左list→在右list里找相同user_id→合并信息"。pandas一行merge替代W1的8行嵌套循环
- **陷阱1：一对多merge→行数膨胀！用户表1个用户→订单表5条=结果5条。这是正常行为但要检查膨胀倍数是否合理**
- **陷阱2：关联key有重复→笛卡尔积式膨胀！左表3条×右表2条(同key)=6条→爆炸。merge前后用`validate`或检查`df['key'].duplicated().any()`**
- **陷阱3：left join后过滤右表条件→等价inner join。和SQL的LEFT JOIN+WHERE右表条件=INNER JOIN的陷阱完全一样**

**2. join —— 按索引连接**
- `df1.join(df2, how='left')` — 两个df都按各自的index连接
- `df1.set_index('key').join(df2.set_index('key'))` — 把key设为index后用join
- merge vs join：merge可以指定任意列、更灵活。join按index、语法更简洁。多数场景merge更直观

**3. concat —— 纵向或横向拼接**
- `pd.concat([df1, df2], axis=0)` → 纵向堆叠(行变多)。多份相同结构CSV拼接(1月+2月+3月)
- `pd.concat([df1, df2], axis=1)` → 横向拼接(列变多)。**必须确保两个df行序完全一致！**
- `pd.concat([df1, df2], ignore_index=True)` — 重置索引(避免多个源df的index重复)
- `pd.concat([df_jan, df_feb, df_mar], keys=['Jan','Feb','Mar'])` — 多层索引标记每块的来源
- **W1连接**：concat(axis=0) = W1的`lst1 + lst2`列表拼接。纵向堆叠=把两个list接起来
- **陷阱：concat(axis=1)不检查行序→df1第5行是用户A、df2第5行可能是用户B→直接横向拼=张冠李戴→数据全错！拼接前必须确认两个df的行一一对应**

**4. 行数膨胀的检测与预防——今天最重要的防御技能**
- 检测流程：
  1. merge前打印：`print(f"左表{len(df1)}行, 右表{len(df2)}行, 预期结果≤{max(len(df1), len(df2))}行(left)或≥{len(df1)}行(inner)")`
  2. merge后打印：`print(f"结果{len(result)}行, 膨胀倍数={len(result)/len(df1):.1f}x")`
  3. 如果膨胀倍数不合理(如left join从5万行膨胀到50万行)→排查
- 排查方法：
  - 检查关联键重复：`right_df['user_id'].duplicated().sum()` → 如果>0说明右表有重复key→可能是一对多→看业务是否合理
  - 检查indicator：`result['_merge'].value_counts()` → `left_only`很多→右表数据缺失。`both`很少→两表交集很少
- 预防方法：
  1. merge前对右表去重：`right_unique = right_df.drop_duplicates(subset=['user_id'])`
  2. 先聚合再关联：`user_agg = orders.groupby('user_id').agg(总消费=('金额','sum'),订单数=('订单号','count'))` → 再和用户表关联
  3. 用`validate`参数→不符合预期关联关系立即报错

## W2D4：变换与性能 + 向量化专题（v5.0 🔥核心，Python弱项的重点攻克日）

### 能力簇
**列的变换与代码加速** —— 掌握apply家族、str/dt访问器，**重点攻克：理解为什么向量化比for循环快200倍**。今天每个性能对比都必须亲手跑，因为这是你"Python基础弱"最需要补的一课——理解了向量化，你才能真正理解pandas存在的意义

### 为什么今天是弱项攻克的关键
你W1写了大量for循环，觉得"这样就能处理数据了"。今天要给你一个认知冲击：**同样的逻辑，for循环15秒，向量化0.01秒。而且数据量越大，差距越大。** 这解释了为什么W1学的for循环只是过渡——生产环境的数据量根本不允许你用for循环。今天彻底理解"把Python代码向量化"的思维方式，今后写pandas就不会下意识用for循环了。

### 具体知识清单

**1. apply家族——三兄弟各自的使用场景和性能差异**
- `df['列'].apply(func)`：对Series每个元素执行func。如`.apply(lambda x: x*1.1)`每行金额加10%
- `df.apply(func, axis=0)`：axis=0(默认)→每列传给func。axis=1→每行传给func。**axis=1极慢！**
- `df['列'].map({'A':1, 'B':2})`：字典映射替换。A→1, B→2。比apply(lambda x: d[x])快3-5倍
- `df.applymap(func)`：对DataFrame每个单元格执行func。慎用——整个df逐格操作=极慢
- **W1连接**：apply = W1的`[func(item) for item in lst]`列表推导。apply(axis=1) = W1的for row in list_of_dict逐行处理
- **陷阱1：`apply(axis=1)`逐行操作→100万行跑几十秒。能用向量化(np.where/str.contains/isin)绝不用apply(axis=1)**
- **陷阱2：apply和map都不修改原df→需要赋值回去：`df['新列'] = df['列'].apply(func)`**
- **陷阱3：apply里写lambda→如果逻辑超过一行→单独def函数传进去(可读性+可复用)**

**2. str访问器——文本列专用。每个方法名和Python str方法一样**
- **前提**：列必须是object或string类型→int列先用`.astype(str)`才能用`.str`
- `.str.strip()` — 去前后空格
- `.str.lower()` / `.str.upper()` — 统一大小写
- `.str.replace('旧','新', regex=False)` — regex=True时"旧"是正则表达式。"北京.*"能匹配"北京市"/"北京朝阳"
- `.str.split(',', expand=True)` — 按分隔符拆成多列。expand=True返回DataFrame(多列)，expand=False返回Series(每个元素是list)
- `.str.extract(r'(\d+)元')` — 正则提取到新列。括号里的内容被提取出来
- `.str.extractall(r'(\d+)')` — 提取所有匹配(一行可能有多个匹配→产生多行)
- `.str.contains('关键词', case=False, na=False)` — 返回True/False Series→可直接用于布尔索引
- `.str.len()` — 字符串长度
- `.str.cat(sep='/')` — 把所有字符串用分隔符拼接成一个
- `.str.startswith('A')` / `.str.endswith('.com')` — 和Python str方法同名同功能
- **W1连接**：`.str.xxx` = W1D4学的Python字符串方法的pandas版。同一个名字、同一个功能，但`.str`版本可以一次处理整列

**3. dt访问器——日期列专用**
- **前提**：列必须是datetime64类型→不是的话先`pd.to_datetime(df['列'], errors='coerce')`
- `.dt.year` / `.dt.month` / `.dt.day` / `.dt.hour` / `.dt.minute` / `.dt.second` — 取出日期成分。返回int
- `.dt.dayofweek`(周一=0周日=6) / `.dt.day_name()`('Monday') / `.dt.quarter`(1-4)
- `.dt.is_month_start` / `.dt.is_month_end` — 是否月第一天/最后一天。返回bool
- `.dt.diff()` — 每条和上一条的时间差。`Timedelta`对象，`.dt.days`转成天数。常用于计算用户行为间隔
- `.dt.strftime('%Y年%m月')` — 格式化为自定义字符串
- `df.set_index('日期').resample('W').sum()` — 按周聚合。resample频率：'D'天/'W'周/'M'月/'Q'季/'Y'年/'H'小时
- `df.set_index('日期').resample('M').agg({'金额':'sum','订单号':'nunique'})` — 按月多重聚合
- **W1连接**：dt = W1没学过的东西。W1的Python标准库`datetime`也能做日期运算，但pandas的dt把整列当做操作对象→一行搞定
- **陷阱1：`to_datetime`遇到无效日期格式→默认报错。`errors='coerce'`把无效变NaT，`errors='ignore'`保持原样(但仍是object!)**
- **陷阱2：year/month返回的是int数字→不能再用`.dt.month`(因为已经不是datetime类型了)**
- **陷阱3：resample要求index是DatetimeIndex→不是的话先`set_index('日期列')`**

**4. assign / pipe —— 优雅的链式写法**
- `df.assign(利润=df['金额']-df['成本'], 利润率=lambda x: x['利润']/x['金额'])` — 一次新增多列，不修改原df
- assign支持lambda引用刚创建的列——`lambda x: x['新列']/x['旧列']`
- `df.pipe(func, arg1, arg2)` — 把df传给func再返回df。`df.pipe(clean).pipe(analyze).pipe(visualize)` → 每个函数职责单一，链式调用可读性极高
- pipe vs apply：pipe对整个DataFrame操作(输入df→输出df)，apply对每行/列操作
- **W1连接**：assign+pipe = W1的"def函数+链式调用"。每个pipe里的func就是你W1写的函数

**5. 🔥 向量化性能专题——今天最重要的一节。Python弱项的核心突破点**
- **问题**：同一件事，三种写法性能差距有多大？
  - **写法1 - Python for循环**(W1的方式)：
    ```python
    result = []
    for i in range(len(df)):
        if df.iloc[i]['金额'] > 500:
            result.append('大单')
        else:
            result.append('小单')
    # 100万行 ≈ 15秒
    ```
  - **写法2 - pandas apply**：
    ```python
    df['标签'] = df['金额'].apply(lambda x: '大单' if x > 500 else '小单')
    # 100万行 ≈ 3秒 (比for快5倍)
    ```
  - **写法3 - 向量化np.where**：
    ```python
    df['标签'] = np.where(df['金额'] > 500, '大单', '小单')
    # 100万行 ≈ 0.01秒 (比for快1500倍！)
    ```
- **为什么向量化这么快？三个原因**：
  1. **C底层实现**：`np.where`是NumPy的C函数→直接在编译后的机器码里执行→没有Python解释器开销(for循环每行都要回到Python解释器→"Python→C→Python→C"来回跳)
  2. **SIMD指令**：现代CPU一次可以处理多个数据(并行)。向量化让CPU用SIMD → 一次处理4-8个数据。for循环只能一次处理1个数据
  3. **无Python对象创建**：for循环每行创建一个Python int对象(占用28字节)→然后丢掉→GC回收。向量化在C层面的连续内存上操作→没有对象创建开销
- **其他向量化替代方案**：
  - 条件赋值：`np.where(条件, True值, False值)` 替代 `apply+if`
  - 条件多分支：`np.select([条件1,条件2], [值1,值2], default=默认值)` 替代 `apply+if/elif/else`
  - 条件选择：`df['列'].isin([...])` 替代 `apply(lambda x: x in [...])`
  - 字符串匹配：`df['列'].str.contains('关键词')` 替代 `apply(lambda x: '关键词' in x)`
  - 多列运算：`df['A'] + df['B'] * 2`（数组运算）替代 `df.apply(lambda row: row['A']+row['B']*2, axis=1)`
- **pd.eval()加速**：`pd.eval('df.金额 > 500 and df.城市 == "北京"')` → 利用numexpr库多核并行→复杂表达式更快
- **核心原则刻进脑子里**：能用向量化不用apply，能用apply不用iterrows，**永远不要**用for循环遍历DataFrame
- **陷阱：apply(axis=1)是慢的原因**——axis=1意味着每行创建一个Series对象→100万行创建100万个Series→内存爆炸+速度灾难**

**1. Broadcasting广播机制——不同形状数组如何自动对齐**
- **广播规则（两条，从尾端维度向前比较）**：①两维度相等 ②其中一个维度为1
- **为什么重要**：理解广播=理解为什么`df['A'] + 10`能工作、为什么`arr(3,1) + arr(1,4) = arr(3,4)`不报错——NumPy不是在"复制数据"，而是在"逻辑扩展"
- 广播的真正威力：**零内存复制**——广播不实际复制数据，只是改变了索引方式
```python
# 经典应用：每列减去各自的均值（中心化）
data = np.random.randn(100, 5)             # 100样本×5特征
centered = data - data.mean(axis=0)         # (100,5) - (5,) → 自动广播
standardized = centered / data.std(axis=0)  # Z-score标准化

# 外积——利用newaxis创建可广播的形状
a = np.array([1, 2, 3])[:, np.newaxis]     # shape (3, 1)
b = np.array([10, 20, 30, 40])             # shape (4,)
result = a * b                              # shape (3, 4)——自动广播！
# 广播过程: (3,1) * (4,) → (3,1) * (1,4) → (3,4) → (3,4)
```

**2. 线性代数——数据分析的隐藏武器**
- `np.linalg`模块是scikit-learn底层的基础
```python
# 逆矩阵/行列式/特征值（PCA的核心就是协方差矩阵的特征分解）
A = np.array([[1, 2], [3, 4]])
np.linalg.inv(A)              # 逆矩阵（解线性方程组 Ax=b → x=A⁻¹b）
np.linalg.det(A)              # 行列式（=0→奇异矩阵/不可逆/特征间线性相关）
eigenvalues, eigenvectors = np.linalg.eig(A)  # 特征分解
U, S, Vt = np.linalg.svd(A)   # 奇异值分解（SVD）——PCA/推荐系统/LSA的基础

# np.linalg.solve——解线性方程组（比求逆再乘快且数值稳定）
b = np.array([5, 11])
x = np.linalg.solve(A, b)     # 解 Ax=b

# np.linalg.lstsq——最小二乘（线性回归的底层）
X = np.random.randn(100, 3)
y = X @ np.array([1.5, -0.5, 2.0]) + np.random.randn(100) * 0.5
coeffs, residuals, rank, singular = np.linalg.lstsq(X, y)
# coeffs ≈ [1.5, -0.5, 2.0] ——线性回归系数！
```
- **面试考点**："PCA的原理是什么？"→"协方差矩阵的特征分解+取前K个最大特征值对应的特征向量→即最大方差方向"
- **NumPy的底层用了优化过的BLAS/LAPACK**→比手写Python循环快几百倍→向量化之所以快=NumPy把循环下推到了C/Fortran层的BLAS

**3. 随机数的正确姿势——Generator API (NumPy 1.17+)**
- 旧的`np.random.seed(42)`设全局种子——依赖全局状态，并行代码互相踩
- 新推荐——独立Generator实例，可复现且线程安全：
```python
rng = np.random.default_rng(42)         # 创建独立生成器
rng.normal(loc=0, scale=1, size=100)    # 不依赖全局种子
# 并行场景：每个线程/进程创建自己的rng(seed+n) → 互不干扰
```

## W2D5：透视表 + SettingWithCopyWarning专题（v5.0 🔥核心）

### 能力簇
**数据重塑与防坑** —— 掌握pivot/melt/stack，**彻底根治SettingWithCopyWarning——pandas新手最高频的警告，面试最爱考的陷阱**

### 为什么今天重要
SettingWithCopyWarning是你将来写pandas最常遇到的警告。90%的新手选择"关掉警告"（`pd.set_option('mode.chained_assignment', None)`）——这等于把烟雾报警器电池拆了。今天要让你理解这个警告的底层原因（pandas的view vs copy设计权衡），三招根治它。面试官问到这个警告时，你说得出根因、触发条件、三种解法→瞬间区分"会用API"和"理解pandas底层"。

### 具体知识清单

**1. pivot_table —— Excel透视表的pandas版**
- `pd.pivot_table(df, values='金额', index='品类', columns='城市', aggfunc='sum')` — 品类(行)×城市(列)的金额总和
- `margins=True` — 加"All"行和"All"列(汇总)。默认不显示
- `fill_value=0` — 缺失交叉点填0(而非NaN)→报告里更好看
- 多值透视：`values=['金额','利润']` — 同时透视多指标
- 多级行索引：`index=['年份','品类']` — 层次化行(年份→品类)
- 多级列索引：`columns=['城市','渠道']` — 层次化列(城市→渠道)
- 不同value不同aggfunc：`aggfunc={'金额':'sum', '利润率':'mean'}` — 金额求和、利润率求平均
- **W2D2连接**：pivot_table ≈ groupby().unstack()。groupby是底层实现，pivot_table是封装好的高级接口(margins/fill_value/多value)
- **陷阱1：pivot_table的aggfunc默认是mean不是sum！想要总金额必须写`aggfunc='sum'`。这是最高频的pivot_table错误**
- **陷阱2：pivot_table和pivot不是同一个函数。pivot没有聚合功能(只做重塑)→数据有重复index+columns组合时报错→用pivot_table替代**

**2. melt —— 宽表↔长表转换**
- `df.melt(id_vars=['ID','日期'], value_vars=['Q1','Q2','Q3','Q4'], var_name='季度', value_name='销售额')`
- 每行原来的Q1-Q4四列→变成4行(每个季度一行)→列"季度"存原来的列名→列"销售额"存原来的值
- id_vars=保持不变的列(就像groupby的key)。value_vars=要被"熔化"的列。var_name=原列名变成值的列名。value_name=原值变成值的列名
- 长表格式是seaborn/plotly最爱的格式——melt后可以直接`hue='季度'`分组画图
- **W1连接**：melt = 把"宽的dict"变成"长的list of dict"。如果W1你有一个dict`{'张三':{'Q1':85,'Q2':90}, '李四':{'Q1':78,'Q2':88}}`→你需要遍历拆成`[{'姓名':'张三','季度':'Q1','成绩':85},{'姓名':'张三','季度':'Q2','成绩':90},...]`→melt就是做这个的

**3. stack / unstack —— 把index和columns互相转换**
- `df.set_index(['A','B']).unstack(level='B')` — 把行索引B"旋转"成列索引
- `df.stack()` — 把某些列名变成行索引的值
- unstack = pivot_table的底层实现。stack = melt的底层实现
- **陷阱：unstack要求被旋转的index和未旋转的组合唯一→不唯一报错"duplicate entries"→先去重**

**4. crosstab —— 交叉频次表**
- `pd.crosstab(df['品类'], df['城市'], values=df['金额'], aggfunc='sum', normalize='columns', margins=True)`
- normalize='index'→行百分比(每行加总=1)。normalize='columns'→列百分比。normalize='all'→全局百分比
- crosstab vs pivot_table：crosstab更简洁(不需要写values=和aggfunc=)，pivot_table更强大(多values多aggfunc)

**5. 🔥 SettingWithCopyWarning专题——彻底根治这个警告**

**这是什么**：Pandas在执行"链式索引"时，无法确定你在修改原始DataFrame还是它的临时副本→只能给你一个Warning提醒你

**为什么会产生——根因是pandas的设计权衡**：
- 为了性能，pandas有时返回"view"(视图，指向原数据内存)有时返回"copy"(副本，独立的新内存)
- 但pandas无法100%确定某次操作返回的是view还是copy(取决于数据布局/dtype/操作类型)
- 链式索引赋值时：`df[df['A']>0]['B'] = 0` → 第一步`df[df['A']>0]`返回可能是view也可能是copy → 第二步`['B']=0`如果能改原数据就改了，如果改的是临时副本→改了也白改→pandas只能Warning
- **W1D1连接**：这个问题的根因 = W1D1学的`lst2 = lst1`(不拷贝→改一个两个都变)。SettingWithCopyWarning就是Python引用语义在pandas里的表现

**触发方式1——链式索引赋值（最常见）**：
```python
# ❌ 链式索引→两个方括号连着→pandas不确定你在改哪
df[df['金额'] > 500]['标签'] = '大单'
# SettingWithCopyWarning!

# ✅ .loc一步到位→同时定位行和列→pandas确定你在改原df
df.loc[df['金额'] > 500, '标签'] = '大单'
```

**触发方式2——先筛选产生了不确定的中间变量**：
```python
# ❌ df2可能是原df的view也可能是copy→不确定
df2 = df[df['金额'] > 500]
df2['标签'] = '大单'   # 可能触发Warning

# ✅ 明确告诉pandas"我要独立的副本"
df2 = df[df['金额'] > 500].copy()
df2['标签'] = '大单'   # 安全！明确是副本
```

**触发方式3——隐形链式（表面上看是两步但实际上有中间值）**：
```python
# ❌ df[df['A']>0]返回中间值→然后.loc[:, 'B']赋值→链式
df[df['A'] > 0].loc[:, 'B'] = 0

# ✅ 一个loc搞定
df.loc[df['A'] > 0, 'B'] = 0
```

**三种正确解法（面试标准答案）**：
1. `.loc[row_indexer, col_indexer]` 一次性选行选列然后赋值 → **首选！90%场景用这个**
2. 先`.copy()`明确创建独立副本再修改 → 确实需要副本时用
3. ~~`pd.set_option('mode.chained_assignment', None)`~~ → **永远不要用！** 关闭报警器不等于没有隐患。正确的做法是学.loc

**为什么面试爱问这个**：
- ①新手几乎100%踩过→考察你有没有真正理解pandas
- ②根因涉及pandas底层设计(view vs copy的性能权衡)→能区分"会用API"和"理解底层"
- ③三种触发方式+三种解法→标准答案有结构→面试官容易评分

**练习1：`describe_column(df, col)` ——封装一个统计描述函数**
```python
def describe_column(df, col):
    """返回一个列的完整统计描述（dict格式）
    
    W6+的场景中，你不会每次都手写df[col].mean()——会封装成函数复用
    """
    series = df[col].dropna()
    return {
        '列名': col,
        '样本量': len(series),
        '缺失率': f"{df[col].isna().mean():.1%}",
        '均值': round(series.mean(), 2),
        '中位数': round(series.median(), 2),
        '标准差': round(series.std(), 2),
        '最小值': series.min(),
        '最大值': series.max(),
        'IQR': series.quantile(0.75) - series.quantile(0.25)
    }

# 使用
for col in ['金额', '数量', '评分']:
    print(describe_column(df, col))
```

**练习2：`filter_and_aggregate(df, filters, group_col, metric_col, agg_func)` ——封装筛选+聚合**
```python
def filter_and_aggregate(df, filters, group_col, metric_col, agg_func='mean'):
    """筛选→分组→聚合，一步完成。W6-W12反复出现的模式
    
    filters: dict 如 {'城市': '北京', '会员等级': ['金卡', '钻石']}
    """
    df_filtered = df.copy()
    for col, value in filters.items():
        if isinstance(value, list):
            df_filtered = df_filtered[df_filtered[col].isin(value)]
        else:
            df_filtered = df_filtered[df_filtered[col] == value]
    
    return df_filtered.groupby(group_col)[metric_col].agg(agg_func)

# 使用
result = filter_and_aggregate(
    orders, 
    filters={'城市': '北京', '品类': ['数码', '服装']},
    group_col='月份', 
    metric_col='金额', 
    agg_func=['sum', 'mean', 'count']
)
```

**练习3：`compare_groups(df, group_col, metric_col)` ——封装两组对比（W5-W6核心操作）**
```python
def compare_groups(df, group_col, metric_col):
    """比较两组在某个指标上的差异——W5假设检验+W6 AB实验的前置技能
    
    返回：每组的样本量/均值/中位数/标准差 + 差值
    """
    groups = df.groupby(group_col)[metric_col]
    
    stats = groups.agg(['count', 'mean', 'median', 'std'])
    diff = stats.loc[stats.index[0], 'mean'] - stats.loc[stats.index[1], 'mean']
    
    result = stats.to_dict('index')
    result['difference'] = {'mean_diff': round(diff, 2)}
    return result

# 使用（为W5的ttest_ind做准备）
print(compare_groups(df, group_col='会员等级', metric_col='消费金额'))
```
