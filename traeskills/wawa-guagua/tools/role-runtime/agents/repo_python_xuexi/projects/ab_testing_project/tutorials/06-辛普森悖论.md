# 06 辛普森悖论

---

## 一、白话理解

### 整体赢了 = 所有人都赢了吗?

你做了个实验:

```
整体: 算法推荐 GMV +1.96%
结论: "不错,算法更好!"
```

然后你多看了一眼,分城市等级:

```
一线/新一线: 算法 +7.17%  → 哇!算法碾压运营
三五线城市:  算法 -2.03%  → ...等等,算法反而更差?
```

**整体+2%,但三五线城市是负的。** 因为一线城市用户占总量的40%却贡献了更大比例的GMV,"拉高"了所有人的平均值。三五线60%的用户被整体平均掩盖了。

这就是辛普森悖论——**整体趋势与子组趋势不一致甚至相反。**

### 社区团购的真实写照

**为什么在社区团购里这个悖论特别常见?**

一线城市:
- 用户数据丰富(手机号注册,行为追踪完整,高频下单) → 算法有充足信号做个性化
- 供应商集中在城郊,履约半径短,成本可控 → 算法推荐基本不会推"送不到"的品
- 用户习惯APP下单,行为可追踪

三五线城市:
- 团长代下单普遍 → 用户画像缺失,算法不知道到底是谁在买
- 供给不稳定 → 算法推了某个品,当地网格仓今天没配货 → 用户下单后被告知缺货 → 体验差
- 团长密度低 → 自提点距离远 → 履约成本远高于一线
- 用户更信任团长推荐(口头推荐),而不是冷冰冰的算法

**这就是为什么数据驱动的推荐在三五线失效——不是算法不聪明,而是输入数据就有问题。**

## 二、核心概念

### 2.1 辛普森悖论的数学结构

```
整体: (组A均值×组A比例 + 组B均值×组B比例)

如果组A占比大,且组A的效果方向与组B相反 → 整体被组A主导
```

在这个实验里:
```
整体 lift = 40% × (+7.17%) + 60% × (-2.03%) ≈ +1.96%
                         ↑                      ↑
                   一线拉高整体        三五线拖低整体,但被稀释了
```

### 2.2 交互效应检验

不只是"分别看每个子组",还要统计检验"子组之间的差异是不是真的":

```python
GMV ~ is_treatment + is_city_tier1 + is_treatment × is_city_tier1
```

交互项p<0.001 → 确认"城市等级调节了实验效果,不是随机波动"

### 2.3 除了城市等级,还要查什么

代码里还检查了:
- **购买频次**(高/中/低频):高频用户的个性化推荐效果更好(数据多),低频用户可能反而被算法带偏
- **团长密度**(高密/中密/低密):低密区域履约成本高,算法如果不考虑这个约束,会给用户推"性价比高但履约贵"的品

这些都对你的拼多多买菜经验有直接对应——你在简历里写的"供给重构"、"本地直采"、"成本拆解",本质上都是在解决低线城市的供给和数据稀疏问题。

## 四、输出解读

```
  一线/新一线(n=16,024, 40%):
    GMV: +7.17%  件数+5.21%  履约成本-2.26%  损耗率-5.49%
    → 算法全面优于运营——数据丰富+供给稳定

  三五线(n=23,976, 60%):
    GMV: -2.03%  件数-0.47%  履约成本+6.22%  损耗率+4.93%
    → 算法全面劣于运营——供给约束+数据稀疏

  [WARNING] 辛普森悖论: 三五线方向与整体相反!

  交互效应检验: 交互项p=0.0000 → 显著
```

**核心结论:**

一线城市:算法完胜。可以全量。

三五线城市:算法输了——但不是"算法不够聪明",而是**输入数据本身就有缺陷**(团长代下单导致用户画像缺失,网格仓库存数据未接入推荐模型)。

**改进方向(直接对应你简历的经验):**
1. 引入本地库存约束到推荐模型(供给感知推荐)
2. 降低冷启动用户的算法权权,保留部分运营选品
3. 针对低团长密度区域,优化履约成本模型

## 五、面试怎么讲

**面试官:"什么是辛普森悖论?遇到过吗?"**

> "辛普森悖论就是整体趋势和子组趋势不一致——甚至方向相反的现象。根源在于存在混淆变量同时影响分组比例和效果大小。
>
> 我在社区团购爆品推荐的A/B实验里就遇到了。整体看算法推荐GMV提升了约2%,但分城市看——一线城市提升了7%,三五线城市反而下降了2%。
>
> 因为一线用户只占40%但GMV贡献大,'拉高'了整体平均,掩盖了三五线的负效果。我通过交互效应检验确认了城市等级对实验效果的调节作用是统计显著的。
>
> 根因分析指向三个点:三五线团长代下单普遍导致用户画像不完整、网格仓库存数据与推荐模型未打通导致的供给匹配断裂、以及低团长密度区域的履约成本问题。
>
> 基于这个发现,我建议分城上线——一线先全量,三五线先做供给感知优化后再测。如果当时没做细分分析,直接全量上线,三五线60%的用户会看到更差的推荐体验——在社区团购这个业务里,三五线恰恰是核心用户群。"
