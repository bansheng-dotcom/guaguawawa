# 02 AA验证

---

## 一、白话理解

### 一个社区团购的事故

某城市的BD(商务拓展)在小区门口摆摊拉新用户,扫码注册送一盒鸡蛋。他恰好被分配到了"实验组"的分流桶里,因此他的所有新用户都进了实验组。

结果呢?实验组的首单转化率"显著高于"对照组——算法团队狂喜,以为自己的推荐策略特别厉害。但实际上是因为**实验组多了一批"拿着鸡蛋来下一单就跑"的薅羊毛用户**。

如果做了AA验证——在正式实验前让两组用户看完全相同的推荐内容——就会发现分流阶段两组就已经不一样了。

### AA验证的日常类比

你说"我想吃水果",让我去水果店帮你买。

- **正确做法**: 我从筐里闭着眼睛随机拿几个 → 有好的有坏的,概率一样
- **分流有问题**: 我从筐里拿,但下意识挑颜色好看的 → 你拿到的水果整体偏好看

AA验证就是在正式买之前,先测试**"我的挑选过程是不是真的随机"**——如果我不是随机的,那最后水果好不好吃,到底是水果本身的问题还是我挑的问题?你不知道。

### 在社区团购里的重要性

社区团购的流量分发有天然的不均匀因素:

- 团长推荐位:某些团长的群里被重点推广 → 他的团员被导流进实验组的概率更高
- 地推BD:不同BD负责不同区域 → 如果分桶逻辑和BD区域重叠,可能造成地域性偏差
- 新老客混杂:新用户和复购用户的GMV差异巨大(新客可能就走一个引流品,老客一次买一周的菜)

AA验证的目的就是在这些问题暴露之前抓到它们。

## 二、核心概念

### 2.1 为什么p>0.05在AA验证里是好事

```
A/B实验: p<0.05 → "两组确实不同" → 实验有效果 (好事)
AA验证:  p>0.05 → "两组没有显著不同" → 分流均匀 (好事)

方向完全相反!
```

### 2.2 不只检查均值,还要检查分布

代码里在t检验之外,还做了KS检验(分布一致性检验):

```python
ks_stat, ks_p = stats.ks_2samp(group_a['gmv'], group_b['gmv'])
```

为什么?因为**均值相同 ≠ 分布相同**。

举个极端例子:
- A组: 50%用户GMV=0元(只看不买),50%用户GMV=50元 → 均值25元
- B组: 全部用户GMV=25元 → 均值也是25元

均值一样,t检验p>0.05。但两组构成完全不同! KS检验能发现这个问题。

### 2.3 用户画像检查:被忽略的最重要环节

社区团购的用户画像维度:

| 维度 | 为什么重要 | 如果分布不均会怎样 |
|------|----------|------------------|
| 城市等级 | 一线用户和三五线用户GMV差30%+ | 实验组多了一线城市用户→假阳性 |
| 购买频次 | 高频用户(周≥2单)GMV是低频的3倍 | 实验组多了高频用户→严重偏差 |
| 团长密度 | 高密区域履约成本低,低密区域高 | 实验组多了低密区域用户→履约成本率虚高 |

**AA验证在3个维度中如果有1个FAIL,都要排查分流逻辑的bug。**

## 三、代码导读

打开 [02_aa_validation.py](../02_aa_validation.py):

### t检验部分 (第50-70行)

```python
t_stat, p_value = stats.ttest_ind(a_vals, b_vals)
```
对GMV、件数、履约成本率、损耗率、退货率、爆品占比分别做t检验。
AA验证中,我们期望p值**越大越好**。

### 卡方检验 (第75-85行)

首单转化率是二分类(买/没买),用卡方检验:
```python
table = pd.crosstab(df['group'], df['is_new_conversion'])
chi2, p_value, dof, expected = stats.chi2_contingency(table)
```

### 用户画像检查 (第90-110行)

```python
# 检查城市等级在两组中的分布是否一致
for dim_col, dim_name in [

    ('leader_density', '团长密度'),
]:
    table = pd.crosstab(df['group'], df[dim_col], normalize='index') * 100

```

如果某个维度的p<0.05,意味着该画像特征在两组间分布不均——分流可能有bug。

1. 分流系统的哈希函数有没有bug?

## 五、面试怎么讲

**面试官:"你们做A/B实验前做AA验证吗?"**

> "做的。AA验证是零成本的实验前提检查——两组用户看完全相同的推荐内容,理论上不应该有任何差异。
>
> 在社区团购场景下,AA验证我会重点查三个方面:
> 1. 业务指标(GMV、件数、履约成本等)的均值差异——用t检验
> 2. 分布的完整一致性——用KS检验做补充
> 3. 用户画像的分布——城市等级、购买频次、团长密度,这些在社区团购里差异很大
>
> 全部通过才进入正式实验。有一次我发现年龄分布p=0.03——排查后发现是某个BD在小区门口拉新时,他的流量被哈希到了实验组,而他负责的那片小区恰好以老年人为主。修复分桶逻辑后AA通过,才正式开始。"
