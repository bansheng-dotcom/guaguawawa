# 02 异动监控规则

---

## 一、白话理解

### 每天看数据，你不可能一个一个盯着

你有一个仪表盘，每天早上自动刷新。突然有天GMV暴跌30%——但你正在开会，没看到。等你发现已经是两天后了：配送车队罢工，影响了两天订单，损失了3万。

**异动监控就是要解决"能不能第一时间知道问题"这件事。**

### 异动监控三条线

每条监控 = **条件 + 等级 + 归因方向 + 建议动作**

```
[规则1] GMV单日骤降
    条件: 当日GMV < 7日均值 - 2×标准差 (连续2天)
    等级: 高风险
    归因方向: 全品类 or 特定品类? 天气? 竞对?
    建议动作: 查APP/支付/供给; 若特定品类→通知品类运营
```

**为什么是-2×标准差？** 统计学告诉你：正态分布下，-2σ之外的区域只占2.3%的概率。所以连续两天跌破-2σ，基本可以排除"随机波动"。

### z-score是什么

z-score = (今天值 - 7天均值) / 7天标准差

- z=0 → 今天的GMV正好是近7天平均水平
- z=-2 → 今天比7天均值低2个标准差 → 异常低
- z=+2 → 今天比7天均值高2个标准差 → 异常高（可能是促销）

## 二、社区团购的10条监控规则

### 核心监控（GMV+履约+损耗）

| 规则 | 监控什么 | 最重要的为什么 |
|------|---------|---------------|
| 1 | GMV骤降(>2σ, 2天) | 可能是竞对抢客/APP故障/供给断裂 |
| 2 | GMV骤升(>2σ) | 确认是不是刷单 |
| 3 | 履约成本率连涨5天 | **最容易被忽视的利润杀手** |
| 4 | 损耗率异常(>2σ) | 生鲜品可能滞销或冷链故障 |
| 5 | 退货率连涨3天>2.5% | 品控问题/推荐错配 |

### 扩展监控（团长+用户+品类）

| 规则 | 监控什么 |
|------|---------|
| 6 | 活跃团长连降7天且跌幅>10% — **团长流失预警** |
| 7 | 人均件数<3或>5 — 推荐策略可能出问题 |
| 8 | 周末GMV增幅<15% — 周末囤货效应消失=竞对抢客 |
| 9 | 月末冲量次月骤降 — 分辨自然冲量vs刷单 |
| 10 | 爆品贡献占比<30% — 爆品选品可能失准 |

### 告警等级判断逻辑

```
高风险(立即通知): GMV骤降/ 损耗率异常/ 团长流失
   → 需要当天响应,否则损失扩大

中等关注(日报标注): 履约成本上升/ 退货率/ 人均件数/ 爆品占比
   → 标记在日报里,趋势观察

正常波动: 周末波动/ 月末冲量
   → 正常业务节奏,记录但不告警
```

### 滚动窗口计算（第30-34行）

```python
daily['gmv_7d_avg'] = daily['gmv'].rolling(7).mean()
daily['gmv_7d_std'] = daily['gmv'].rolling(7).std()
```

## 四、输出解读

```
异动检测总结:
  GMV骤降: 0次 | 损耗异常: 4次 | 团长流失: 147天
```

团长流失预警触发了147天——这不是说团长流失了147天，而是说147天里有活跃团长下降超过10%的情况。需要进一步分析：
- 是不是周末效应？周末部分团长休息？
- 是不是季节性？春节前后团长回乡？
- 需要做真实流失确认——连续7天下降才算。

## 五、面试怎么讲

**面试官："你们怎么做数据监控？"**

> "我们有一套异动监控规则库。每条规则包含四个要素：触发条件(量化阈值)、告警等级(高/中/低)、归因方向(从哪些维度排查)、建议动作(做什么)。
>
> 比如GMV监控：当日GMV < 7日均值-2σ且连续2天，判定为高风险异动。然后归因决策树启动——先看是量还是价的问题，再看是哪个品类，最后定位到团长层级。
>
> 总共设了10条规则，覆盖GMV、履约成本、损耗、团长流失、品类结构。不是一次性设计的——前5条是上线第一天就有的，后5条是运营过程中发现新问题后追加的。"
