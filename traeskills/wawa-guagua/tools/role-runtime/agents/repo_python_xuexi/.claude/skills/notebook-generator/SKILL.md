## 零、内容深度保证机制 v3.1

> **v3.1核心变更：notebook的内容深度由每周详细教学规格驱动，而非从v5.0学习计划的高层摘要"脑补"。**

### 为什么需要这一节

v5.0学习计划提供的是**高层描述**（如"W1D1：变量/赋值、int/float/str/bool/None"）。但每周详细教学规格包含了真正决定深度的内容：

- **底层机制**：动态数组O(1)摊销、哈希表原理、IEEE 754双精度、`id()`对象身份……
- **陷阱细节**：`lst2=lst1`是引用不是拷贝、`(1)`不是tuple、`{}`是空dict不是空set、elif条件顺序……
- **跨天连接**：D1的容器→D2的遍历对象、D2的for+if→D3函数体的"肌肉"、D3的函数→D4的IO封装……
- **深度检测标准**：L2/L3/L4的具体检测问题

**教学规格是单一事实来源（Single Source of Truth）。** notebook不是从标题"脑补"深度的——它从教学规格中**提取**深度。

### 教学规格文件定位

```
notes/course_specs/{月份序号}_{周标识}_每日教学规格.md
```

| 周 | 文件路径 |
|----|---------|
| W1 | `notes/course_specs/01_W1_每日教学规格.md` |
| W2 | `notes/course_specs/02_W2_每日教学规格.md` |
| W3 | `notes/course_specs/03_W3_每日教学规格.md` |
| ... | ... |

每个文件中以`## W{X}D{Y}：{能力簇名称}`标记对应天的规格。

## 零-A、生成前强制流程（Phase 0——不可跳过）

**每个notebook生成前，必须先完成以下5步，缺一不可。** 跳过此流程直接生成 → 内容必然肤浅。

### 步骤1：读取教学规格

根据W{X}D{Y}定位教学规格文件 → 读取对应天的完整规格（从`## W{X}D{Y}`标题到下一个`## W{X}D{Y+1}`标题之间的全部内容）。

### 步骤2：提取深度知识清单

从教学规格的"具体知识清单"中提取**每一个条目和子条目**，形成`深度覆盖清单`。例如W1D1的清单：

```
□ 变量与赋值
  □ 变量名规则（字母/数字/下划线，不能数字开头）
  □ 动态类型（同一变量可先后指向不同类型）
  □ =是"贴标签"不是"装盒子"（引用语义）
  □ id()查看对象身份
  □ 多重赋值 a, b = 1, 2
□ 核心数据类型
  □ int任意精度（不溢出）
  □ float IEEE 754双精度（0.1+0.2!=0.3）
  □ str不可变
  □ bool真值测试（bool(0)=False, bool([])=False）
  □ None不是0/空字符串/False
  □ type()查看类型
...（list/dict/set/tuple的全部子条目）
```

**约束**：每个子条目都必须有对应cell覆盖。不能合并、不能简化、不能跳过。

### 步骤3：提取陷阱清单

从教学规格的"必须覆盖的陷阱"中提取**全部陷阱**。规格中列了几个就覆盖几个，不能只挑"最常见的"。

### 步骤4：提取连接点

从教学规格的"连接点"中提取所有跨天/跨周关系。这些内容分配到各概念讲解的③段（"跟你X天前学的XX的关系"）。

### 步骤5：输出覆盖矩阵（v3.2新增——不可跳过）

> **覆盖矩阵是"施工图纸"。必须输出后才能开始写notebook正文。不输出=没有验证基础=内容不可信。**

在完成步骤1-4后，**必须先输出以下三个矩阵**（markdown格式），确认知识清单/陷阱/连接点100%有对应cell覆盖：

#### 知识覆盖矩阵

```markdown
## W{X}D{Y} 教学规格知识覆盖矩阵

| 序号 | 教学规格知识点 | 规格来源 | 对应Cell | 讲解深度 |
|------|--------------|---------|---------|---------|
| 1 | {从教学规格提取的具体条目} | W{X}D{Y} §{章节} | Cell {X}b 第①段 | 白话+规则 |
| 2 | {从教学规格提取的具体条目} | W{X}D{Y} §{章节} | Cell {X}b 第④段 | 机制描述 |
| ... | ... | ... | ... | ... |

**统计**：教学规格条目总数 = {N}，覆盖矩阵条目数 = {M}，覆盖率 = M/N（必须=100%）
```

#### 陷阱覆盖矩阵

```markdown
## W{X}D{Y} 陷阱覆盖矩阵

| 序号 | 教学规格陷阱 | 规格来源 | 对应Cell | ❌✅代码对比 |
|------|------------|---------|---------|------------|
| 1 | {陷阱名} | W{X}D{Y} §陷阱 | Cell traps | ✅ |
| ... | ... | ... | ... | ... |

**统计**：教学规格陷阱总数 = {N}，覆盖矩阵陷阱数 = {M}（必须相等）
```

#### 连接点覆盖矩阵

```markdown
## W{X}D{Y} 连接点覆盖矩阵

| 序号 | 教学规格连接点 | 规格来源 | 对应Cell | 位置 |
|------|-------------|---------|---------|------|
| 1 | {连接关系描述} | W{X}D{Y} §连接点 | Cell {X}b ③段 | 白话说明 |
| ... | ... | ... | ... | ... |

**统计**：教学规格连接点总数 = {N}，覆盖矩阵条目数 = {M}（必须相等）
```

### 步骤6：深度覆盖检查（原步骤5增强）

逐项确认覆盖矩阵中的每个知识点都已分配到具体cell。**矩阵中的每个条目必须能在后续notebook中找到对应的讲解或练习。**

**校验规则**：
- 教学规格"具体知识清单"的条目总数 = 知识覆盖矩阵的条目总数（±0容差）
- 教学规格"必须覆盖的陷阱"条目数 = 陷阱覆盖矩阵条目数（±0容差）
- 每个"连接点"在矩阵中有对应行
- 通过后才能开始写notebook正文。未通过 → 补充分配 → 更新矩阵 → 再检查

**为什么覆盖矩阵能解决AI脑补**：
- AI不能说"我读了教学规格"就完事——它必须写出每一行来自教学规格的哪里
- 如果AI没读教学规格→它写不出"规格来源"列
- 如果AI脑补了额外内容→矩阵中会多出没有"规格来源"的条目→一眼可见
- 人（你）可以快速抽查：数一下矩阵行数 vs 教学规格条目数

**关键约束**：
- 规格中写了`id()` → notebook必须讲`id()`，不能省略
- 规格中写了"IEEE 754双精度" → notebook必须讲`0.1+0.2!=0.3`，不能省略
- 规格中写了"底层：动态数组，append均摊O(1)" → notebook的④段必须包含此描述
- 规格中写了"陷阱：`if a==3 or 4`→永远True" → 陷阱cell必须包含此陷阱
- 规格中的全部陷阱都要进入陷阱cell，**不能只挑"最常见的"几个**

## 零-B、内容边界约束 v3.2

> **核心原则：教学内容 = 教学规格的真子集。notebook中出现的每一个知识点，都必须能在教学规格中找到来源。**

### 为什么需要这一节

v3.1解决了"内容不够深"的问题（强制读取教学规格）。但引入了新问题：AI在读取教学规格后，可能凭训练数据中的知识**善意地添加**教学规格以外的内容——"补充知识点""高级用法""最佳实践""常见面试题"。这些添加物：

- 未经教学规格审查——可能是AI的幻觉
- 可能与教学规格矛盾——同一概念两种说法
- 可能难度不当——在W1教了W8才该学的东西
- 可能挤占练习时间——讲得越多练得越少

**notebook的内容边界由教学规格定义。超出边界=违规。**

### 禁止添加规则（黑名单——绝对不允许）

以下内容**绝对禁止**出现在notebook中，除非教学规格明确写了：

| 禁止项 | 示例 | 为什么 |
|--------|------|--------|
| 教学规格未提及的Python函数/方法/模块 | 规格只讲了`append()`→不要教`extend()`（除非规格写了） | 认知过载 |
| 教学规格未提及的"高级用法" | 规格只讲了`df.groupby().mean()`→不要教`groupby().transform()` | 超出当天深度 |
| 教学规格未提及的"最佳实践补充" | 规格没提到PEP 8→不要讲PEP 8 | 干扰主概念 |
| 教学规格未提及的"常见面试题" | 规格没列→AI自己编的面试题 | 可能是错的 |
| AI自行判断"这个也应该讲"的任何内容 | — | AI的判断不能替代教学规格 |
| 教学规格中未列出的"陷阱" | 即使AI觉得"这也是常见陷阱" | 陷阱应从规格来，不是从AI训练数据来 |
| 超出教学规格深度要求的底层实现细节 | 规格说"知道是哈希表"→不要讲哈希冲突解决 | L3≠源码分析 |

### 允许省略规则（灰名单——特定条件下可以不讲）

| 条件 | 处理 |
|------|------|
| 教学规格中标注"可选"或"进阶用"的内容 | 可在挑战/迁移练习中覆盖，不在主讲解中 |
| 教学规格中明确说"暂时不讲"或"后面会深入" | 严格遵守，不要提前展开 |
| 教学规格中标注"知道概念即可" | 只讲概念+一句话白话，不讲实现 |

### 边界验证规则

**生成notebook后，必须执行以下自查**：

```markdown
## 内容边界自查

对notebook中每个markdown cell里的每个技术术语（函数名/方法名/库名/概念名）：
1. 在教学规格中搜索该术语 → 
2. 找到了 → ✅ 合规
3. 找不到 → ❌ 违规 → 删除或替换

特别注意：
- "补充说明""拓展阅读""你可能还想知道"——这些段落全部删除（除非规格写了）
- "在面试中你可能会被问到"——如果规格没列，删掉
- "最佳实践是..."——如果规格没提，删掉
```

**核心记忆**：**"我想多教你一点"是AI的善意，但善意会产生错误的内容。教学规格是人类专家写的，AI的补充是模型猜的。信任规格，不信任猜测。**

## 零-C、拓展适宜性规则 v3.2

> **零-B定义了"什么不能加"。零-C定义"什么拓展是好的、怎么拓展"——解决"进阶必须换场景"和"不能加教学规格外内容"之间的结构性张力。**

### 核心原则：拓展是场景的迁移，不是概念的添加

```
✅ 合法拓展 = 在同一个概念集合上，换一个不同的行业/数据场景
❌ 非法拓展 = 在教学规格的概念集合之外，引入新概念
```

**一句话**：notebook里的**概念**数量由教学规格决定（一个不多），但每个概念的**应用场景**可以由场景池提供（可以不同）。

### 拓展的三种合法来源

| 来源 | 说明 | 用途 | 示例 |
|------|------|------|------|
| **教学规格的练习配置** | 规格中列出的练习题目（含场景指定） | 进阶练习、挑战练习 | 规格W1D1练习3："游戏背包→用list管理道具栏" |
| **场景池 + 数据Schema** | 第八节的场景Schema表定义了各行业的合法列名和数据 | 换行业场景的练习 | 沙盘是速卖通，进阶换成滴滴（使用Schema中的`trips`表） |
| **教学规格的场景池标注** | 规格中每个练习有场景标注如"(滴滴)""(游戏)""(社交)" | 迁移练习的合法场景选择 | 规格中标注了7个练习场景→从其中选1个未用过的 |

### 拓展的深度边界

| 练习层级 | 概念范围 | 场景范围 | 核心问题 |
|---------|---------|---------|---------|
| **基础练习** | 当天概念（1-2个） | 沙盘场景 | "刚看完讲解，能照猫画虎吗？" |
| **进阶练习** | 当天概念 + 1个旧概念 | **换行业**（场景池中与沙盘不同行业） | "换个场景还会用吗？" |
| **挑战练习** | 当天全部概念 + 2+个旧概念 | 沙盘或场景池 | "复杂业务问题能拆解吗？" |
| **迁移练习** | 当天全部概念（用户自己选） | **全新领域**（场景池中尚未用过的） | "没人提示时自己知道用什么吗？" |

**关键约束**：
- 进阶/挑战/迁移练习**只能复用已有概念**——禁止在练习中引入教学规格未列出的新函数/新方法/新库
- 如果"新场景"需要用到某个还没教的概念→**不要换到那个场景**，换一个不需要未教概念的场景
- 练习的复杂度增长来自**场景的陌生度+概念组合的数量**，不是来自"引入更高级的用法"

### 非法拓展识别（AI最容易犯的5种错误）

| 错误类型 | AI的典型行为 | 为什么错 | 正确做法 |
|---------|-------------|---------|---------|
| **引入未教函数** | 练习中要用户用`.apply()`但当天只教了`.map()` | 用户还没学→做不出 | 只用已教函数设计练习 |
| **场景越界** | 选了一个需要SQL的场景但当天是Python课 | 场景依赖未教工具 | 从场景池筛选"和当天工具有关"的场景 |
| **难度跳跃** | W1D1的迁移练习要求用户写"函数封装+异常处理+文件IO" | 这些概念还没教 | 迁移=场景迁移，不是概念迁移 |
| **隐性知识假设** | 练习中假设用户知道"数据库连接""REST API"等概念 | 这是W2.5才教的 | 只假设Cell 0列出的"需要的前置知识" |
| **知识补充段** | 在概念讲解后加"补充说明：你还可以用XXX方法" | 零-B禁止 | 如果XXX不在教学规格中→删除 |

### 拓展质量自检

生成notebook的练习部分后，逐题检查：

```markdown
## 拓展适宜性自检

### 进阶练习1
- [ ] 这道题用到的所有概念都在教学规格中出现过？（是/否）
- [ ] 这道题没用到任何未教的函数/方法/库？（是/否）
- [ ] 换的场景在场景池中且有合法数据Schema？（是/否）
- [ ] 换的场景不需要用到未教的知识？（是/否）

### 迁移练习
- [ ] 这道题没有引入新概念——只是在陌生场景中应用已知概念？（是/否）
- [ ] 用户"不会"的原因应该只是"场景陌生"，不是"概念没学过"？（是/否）
- [ ] 题干没有给提示用哪个概念——用户必须自己判断？（是/否）
```

**核心记忆**：**"让学生在不同场景里用同一个武器"=好的拓展。"让学生在同一个场景里用还没教的武器"=坏的拓展。场景可以无限换，概念不能偷偷加。**

## 一、底层原理：人类到底是怎么学会的（不变的基础）

### 原理1：好奇心先于内容（Zeigarnik效应）
→ 每个能力簇由认知冲突引出。禁止"今天我们来学X"。
**大脑不保留它没有主动想要的信息。** 未完成的认知任务会产生心理张力，驱动你去完成它。这就是为什么"猜谜语"比"看答案"记得更牢。

→ **设计决策**：每个概念必须由一个"你现有知识搞不定的微问题"引出。用户必须先感受到"我需要新武器"，再看到新武器。禁止上来就"今天我们来学X"。


### 原理2：具象先于抽象
→ 白话类比先于术语。先看到3个例子再归纳规律。
**人类大脑通过具体案例归纳出规律，不是通过抽象定义演绎出应用。** 先看到3个不同的"筛选订单"的例子，自然理解"筛选"这个概念；先看到定义再做题，大脑没有锚点。

→ **设计决策**：每个概念先说"说白了就是..."举一个生活中的例子，再说"在我们的数据里它长这样"。术语放在最后。


### 原理3：提取练习效应（Retrieval Practice）
→ **硬性：练习cell ≥ 讲解cell。每日练习cell ≥7个。目标占比 ≥55%。**

**主动回忆并应用信息的记忆效果，是被动重读的3-5倍。** 挣扎着解出一道题，比顺畅地看完一段讲解，记忆强度差一个量级。

→ **设计决策**：每个notebook至少50%的cell是练习（不是阅读）。用户必须在没有提示的情况下独立写出代码。练习之间不要插入讲解。


### 原理4：工作记忆上限（4±1 chunks）
→ 每天2-4个概念，但打包成1个"能力簇"（协同使用的概念群）。

### 原理5：错误驱动的学习（Error-Driven Learning）
→ 每个练习后必须有偏差诊断表：≥3种常见错误→误解→补救路径。
**犯错后纠正形成的记忆，比直接做对更强。** 但前提是反馈必须即时、具体、附带"为什么错了"的解释。

→ **设计决策**：每个练习后面不是"答案：XX"，而是"如果你的答案跟参考不同，你可能的误解是XX。如果是偏差A→回到cell Y重看，如果是偏差B→做额外练习Z"。


### 原理6：间隔重复（Spaced Repetition）
→ 概念在D+2/D+4/W+1/W+3强制复现。每周SQL持续练习。周日复习日刻意召回。
**一次学透>学完一周后全忘。** 新概念必须在第2天、第4天、第7天、第30天重新出现，每次出现间隔拉长，记忆才能固化。

→ **设计决策**：每周六的复习notebook会刻意召回前5天的概念；每周日的周项目要求同时使用本周所有概念；第4周会重新用到第1-2周的概念。


### 原理7：连接到已有知识
→ 每个能力簇必须说明"跟你X天前学的XX是什么关系，能组合做什么"。
**新信息只有挂在旧信息上才能被检索到。** "这个就像你之前学的XX，但用在YY场景"——这种类比构建记忆的提取路径。

→ **设计决策**：每个新概念的讲解中，必须有一句"这个跟你X天前学的XX是什么关系"。每天的第一个cell必须列出今天所需的前置知识。

### 原理8：情感投入决定记忆强度
→ 贯穿沙盘从生活经验出发。进阶题换行业场景。项目周给真实业务问题。
**大脑优先记住"对我重要"的信息。** 如果用户觉得"学这个干嘛，跟我有什么关系"，再好的讲解也白搭。

→ **设计决策**：贯穿案例必须从用户的生活经验出发，角色设定让用户有代入感（"你是数据分析实习生，mentor要你..."）。每天解决的业务问题必须让用户觉得"这个问题确实需要解决"。

## 二、Notebook类型与结构

v5.0计划中有4种Notebook类型：

| 类型 | 使用日 | 核心特征 |
|------|--------|---------|
| **新概念日** | 周一-周四、部分周六 | 认知冲突→讲解→7+练习→反馈→自检 |
| **综合练习日** | 部分周五 | 全周概念混合，8+道题 |
| **周项目日** | 周六 | 贯穿沙盘，完整业务问题 |
| **复习日** | 周日 | 闭卷自测+错题回溯+知识漏洞清单 |

---

### 类型1：新概念日（最重要，占60%天数）

#### 硬性约束

| 约束项 | 标准 | 不达标后果 |
|--------|------|-----------|
| 练习cell数 | **≥ max(7, ⌈总cells × 45%⌉)** | 练不够=学不会 |
| 总cells数 | **18-24**（新概念日不可超过24） | cells过多→练习占比被稀释 |
| 核心概念数 | 2-4个，打包为1个能力簇 | 多了消化不了 |
| 场景多样性 | **≥2个不同行业/产品场景** | 不换场景=无法迁移 |
| 陷阱/坑专题 | **教学规格中列出的全部陷阱**，每个含❌✅代码对比 | 少一个=用户就可能踩那个坑 |
| 偏差诊断 | **≥3种**常见误解 | 只有答案=不知道错在哪 |
| 知识点覆盖率 | **教学规格"具体知识清单"100%覆盖** | 漏一个=用户少学一个知识点 |

**练习密度计算公式（v3.2修复）**：
```
练习cell数 = max(7, ⌈总cells × 45%⌉)
总cells = 18-24
→ 练习cell数 = 8-11个

可行的cell分配示例（22 cells）：
  开头(全局冲突+沙盘+知识地图): 3 cells
  概念展开(2个概念 × 3 cells):       6 cells
  综合练习(递进4级 × 7题):           7 cells
  陷阱+反馈+回到冲突:                3 cells
  自检+预告+知识网络:                3 cells
─────────────────────────────────────────
  总计: 22 cells, 练习=7(32%)+即时小练习=9(41%)
  
注意：即时小练习(每个概念的cell d)也计入练习总量，所以实际练习占比=综合练习7+即时小练习≥2 = ≥9 cells
```

#### Cell 结构（约20-24 cells，v3.2精简）

**核心变化（v3.1）**：旧版的[cell 3]"核心能力簇讲解"把2-4个概念全塞进一个cell——变成文字墙，深度内容被压缩。新版**每个概念独立展开**，拥有自己的微认知冲突→四段式讲解→落地代码→即时小练习。

### 深度四级

| 级别 | 标准 | 检测方式 | Notebook位置 |
|------|------|---------|------------|
| **L1：知道** | 能认出概念，知道它是干什么的 | "sort_values是排序" | 各概念的讲解cell (cell b) |
| **L2：能用** | 在原场景独立写出正确代码 | 基础练习完成 | 各概念即时小练习 + 综合基础练习 |
| **L3：能讲** | 能白话解释+对比选择+知道为什么这样设计 | 中级自检写200字解释 | 概念讲解cell b第④段 + 自检清单中级 |
| **L4：能判断** | 新场景中自己选工具+论证+讲出局限 | 迁移练习完成 | 迁移练习 + 自检清单高级 |

**每个新概念日必须推到L3，目标L4。** 综合练习日和项目日检验L4是否达成。

### 禁止的假深度

| 假深度 | 为什么假 | v3.0替代做法 |
|--------|---------|------------|
| 罗列5个子知识点 | 广度≠深度 | 只讲2-4个，推到"为什么这样设计" |
| 所有练习在同一场景 | 不变场景=无法迁移 | 进阶必须换行业，迁移必须全新领域 |
| "做不出来正常" | 给放弃发许可证 | "至少试15分钟，写下你的思路" |
| 自检只是打勾 | 没实际产出=没检验 | 中级必写一段话，高级必写代码 |
| 讲源码实现 | 对初学者是噪音 | 讲"为什么这样设计"而不是"源码怎么写的" |
| **从高层计划脑补深度**（v3.1新增） | 高层计划只有概念名，没有底层机制 | **强制读取教学规格**——规格写了什么就教什么 |

## 六、生成后必执行的验证流程 v3.2

每生成一个notebook，必须跑以下验证。**验证不通过 → 修改notebook → 重新验证 → 直到全部通过。**

### 6.1 自动化校验（Phase 3——机器检查，替代人工逐项核对）

生成notebook后，必须运行此Python脚本。脚本输出PASS=继续。FAIL=修改后重跑。

```python
"""notebook质量自动校验脚本 v3.2"""
import json, re, sys, os
from pathlib import Path

def validate_notebook(nb_path, spec_path=None):
    """
    校验notebook的结构完整性、练习密度、禁止词、内容来源。
    
    参数:
        nb_path: notebook文件路径
        spec_path: 教学规格文件路径（可选，传入则做内容覆盖校验）
    
    返回: (errors, warnings)
    """
    nb = json.load(open(nb_path, encoding='utf-8'))
    cells = nb['cells']
    errors = []
    warnings = []
    
    # ====== 1. JSON合法性 ======
    # 能open+json.load即通过
    
    # ====== 2. Cell类型统计 ======
    code_cells = [c for c in cells if c['cell_type'] == 'code']
    md_cells = [c for c in cells if c['cell_type'] == 'markdown']
    total = len(cells)
    
    # 2.1 新概念日：练习cell≥7 且 总cells在18-24范围内
    if total < 18:
        warnings.append(f"总cells少于18（当前{total}）→ 内容可能不够详细")
    if total > 24:
        warnings.append(f"总cells超过24（当前{total}）→ 练习占比可能被稀释")
    
    min_practice = max(7, int(total * 0.45))
    if len(code_cells) < min_practice:
        errors.append(f"❌ 练习cell不足: {len(code_cells)} < {min_practice}（需求≥max(7, {total}×45%)={min_practice}）")
    
    practice_pct = len(code_cells) / total * 100
    if practice_pct < 40:
        warnings.append(f"⚠️ 练习占比偏低: {practice_pct:.0f}%（目标≥45%）")
    
    # ====== 3. 禁止词检查 ======
    full_text = ' '.join(
        ''.join(c['source']) if isinstance(c['source'], list) else c['source']
        for c in cells
    )
    
    banned_phrases = [
        '综上所述', '需要注意的是', '显然', '很容易', '只需', 
        '做不出来正常', '我们可以使用', 'foobar', 'foo_bar'
    ]
    for phrase in banned_phrases:
        if phrase in full_text:
            errors.append(f"❌ 禁止词出现: '{phrase}'")
    
    # ====== 4. 必须词检查 ======
    required_phrases = ['说白了就是', '为什么这样设计']
    for phrase in required_phrases:
        if phrase not in full_text:
            errors.append(f"❌ 必须词缺失: '{phrase}'（每个概念必须有白话解释+设计原理）")
    
    # ====== 5. 结构完整性 ======
    cell0_text = ''.join(cells[0]['source']) if isinstance(cells[0]['source'], list) else cells[0]['source']
    if '今天要解决的问题' not in cell0_text:
        errors.append("❌ Cell 0 缺少'今天要解决的问题'")
    if '你需要的前置知识' not in cell0_text and '需要的前置知识' not in cell0_text:
        errors.append("❌ Cell 0 缺少'需要的前置知识'")
    
    # 检查是否有陷阱cell
    trap_found = any('新手最容易踩的坑' in (''.join(c['source']) if isinstance(c['source'], list) else c['source']) for c in cells)
    if not trap_found:
        warnings.append("⚠️ 未找到陷阱专题cell（'新手最容易踩的坑'）")
    
    # 检查是否有偏差诊断
    deviation_found = any('偏差诊断' in (''.join(c['source']) if isinstance(c['source'], list) else c['source']) for c in cells)
    if not deviation_found:
        warnings.append("⚠️ 未找到偏差诊断cell")
    
    # 检查是否有自检清单
    selfcheck_found = any('今天你学会了吗' in (''.join(c['source']) if isinstance(c['source'], list) else c['source']) for c in cells)
    if not selfcheck_found:
        warnings.append("⚠️ 未找到自检清单cell（'今天你学会了吗'）")
    
    # ====== 6. 概念计数（通过④段计数） ======
    design_count = full_text.count('为什么这样设计')
    if design_count < 2:
        warnings.append(f"⚠️ '为什么这样设计'仅出现{design_count}次（新概念日建议2-4个概念）")
    
    # ====== 7. 内容来源校验（如果传入了教学规格路径） ======
    if spec_path and os.path.exists(spec_path):
        spec_content = Path(spec_path).read_text(encoding='utf-8')
        
        # 提取教学规格中"必须覆盖的陷阱"数量
        spec_traps = re.findall(r'陷阱\d+[：:]', spec_content)
        # 在notebook的陷阱cell中搜索
        trap_section_start = full_text.find('新手最容易踩的坑')
        trap_section = full_text[trap_section_start:] if trap_section_start > 0 else ''
        nb_traps = len(re.findall(r'坑\d+[：:]', trap_section))
        
        if nb_traps < len(spec_traps):
            errors.append(f"❌ 陷阱覆盖不全: notebook有{nb_traps}个, 教学规格有{len(spec_traps)}个")
    
    # ====== 8. 参考答案语法检查（快速版） ======
    # 提取所有code cell中的Python代码，尝试编译
    for i, cell in enumerate(code_cells):
        source = ''.join(cell['source']) if isinstance(cell['source'], list) else cell['source']
        # 跳过明显的SQL/非Python cell
        if source.strip().startswith('SELECT') or source.strip().startswith('--'):
            continue
        try:
            compile(source.strip(), f'<cell_{i}>', 'exec')
        except SyntaxError as e:
            warnings.append(f"⚠️ Cell {i} 可能有语法错误: {e}")
    
    return errors, warnings


# ====== 使用入口 ======
if __name__ == '__main__':
    import argparse
    parser = argparse.ArgumentParser()
    parser.add_argument('notebook', help='notebook文件路径')
    parser.add_argument('--spec', help='教学规格文件路径（可选）', default=None)
    args = parser.parse_args()
    
    errors, warnings = validate_notebook(args.notebook, args.spec)
    
    if warnings:
        print(f"⚠️ {len(warnings)} 个警告:")
        for w in warnings:
            print(f"  {w}")
    
    if errors:
        print(f"\n❌ {len(errors)} 个错误:")
        for e in errors:
            print(f"  {e}")
        print("\n🔴 校验失败——修改notebook后重新运行。")
        sys.exit(1)
    else:
        print(f"\n✅ 校验通过！({len(warnings)} 个警告)")
        sys.exit(0)
```

### 场景数据Schema（生成练习时强制使用）

> **为什么需要这个表**：场景池之前只有行业名称。AI每次生成练习时会即兴编造列名和数据量级——同一个沙盘，周一和周二生成的列名可能不同。Schema表锁定每个场景的数据结构，确保**同一沙盘内所有notebook使用相同的列名和数据类型**。

| **速卖通(电商)** | orders | order_id, user_id, product_id, amount, quantity, date, city, category | int, int, int, float, int, datetime, str, str | 5000行 |

**Schema使用约束**：
1. **同一沙盘内所有notebook必须使用相同列名**——不能周一用`amount`周二用`price`
2. **禁止在练习中编造不在schema中的列**——如果教学规格要求的数据列不在schema中，从教学规格中提取后补充到本表
3. **数据类型必须一致**——如果schema定义`amount`是float，所有notebook都按float处理
4. **数据量级是默认值**——基础练习用默认量级，进阶/挑战可以适当放大（×5-10倍）但列名不变

### 沙盘状态追踪协议 v3.2

> **为什么需要**：mentor小王周一说了什么、用户完成了什么——这些状态必须跨天传递。否则周二的Cell 2（沙盘衔接）只能靠AI"回忆"周一的内容→经常串戏。

**每周生成完毕后**，在周notebook目录下生成 `_sandbox_state.md`：

```markdown
# W{X} 沙盘状态

**公司**：{当前沙盘}
**角色**：{当前角色}
**mentor**：{mentor名字}

**本周每日关键事件**：
| 天 | mentor说了什么（原话） | 用户做了什么 | 关键产出 |
|----|----------------------|------------|---------|
| D1 | "{mentor口语}" | {完成了什么任务} | {产出文件/结论} |
| D2 | "{mentor口语}" | {完成了什么任务} | {产出文件/结论} |
| ... | ... | ... | ... |

**本周跨天故事线**：
{D1→D2→D3→D4→D5的事件因果关系——不是孤立的5天}

**下周沙盘切换**（仅沙盘变化时填写）：
- 从{当前沙盘}切换到{下周沙盘}
- 切换原因：{业务解释——如"实习轮岗""新项目接手""独立负责新业务线"}
- 过渡方案：{周一Cell 2应该怎么解释这个切换}
```

**生成规则**：
1. **生成每周D1的notebook前**：如果上周的 `_sandbox_state.md` 存在 → 读取 → 确认沙盘是否切换 → 如果是切换周，在Cell 2中解释切换原因
2. **生成每周最后一天的notebook后**：生成/更新本周末的 `_sandbox_state.md`
3. **沙盘不变时**：每日Cell 2引用 `_sandbox_state.md` 的前一天事件——mentor不会"忘记"昨天发生了什么
4. **沙盘切换时**：周一Cell 2必须包含过渡解释——不能突然换公司不做说明
