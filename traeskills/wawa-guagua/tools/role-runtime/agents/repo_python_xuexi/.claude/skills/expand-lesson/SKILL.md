# 通用拓展学习文档生成器（沙盘+概念网络版）

## 核心定位（v3 重构）

**v2 的问题**：场景是线性的——"阶段1遇到问题A引入概念1，阶段2遇到问题B引入概念2"。这仍然是单线推进，只是用场景包装了一下。真正的数据分析工作中，多个概念是**同时使用**的，不是先后使用的。而且为了让场景引出5个概念，需要硬编5个转折点，场景变得很假。

**v3 的解法**：**场景是沙盘，不是故事；概念是网络，不是链**。

```
v2（旧）：线性场景
  场景阶段1 → 概念1 → 场景阶段2 → 概念2 → 场景阶段3 → 概念3 → 场景阶段4
  ↓ 问题：单线推进，概念之间关系不明确，场景情节硬编

v3（新）：沙盘 + 概念网络
  第一部分：一次性交代完整的业务/技术沙盘（不推进，只设定）
  第三部分：概念网络展开
    ├── 核心概念深化（从"是什么"到"为什么这样设计"）
    ├── 并行概念群（与核心概念同时使用的，标注 [并行]）
    ├── 防护概念群（防止核心概念被误用的，标注 [防护]）
    ├── 落地概念群（把核心概念产出变成行动的，标注 [落地]）
    └── 替代概念群（核心概念不适用时的备选，标注 [替代]）
  第四部分：综合沙盘——所有概念在同一个沙盘中协同使用
```

**核心变化**：
- 场景不再是"推进的故事"，而是"固定的演练沙盘"
- 概念按关系类型分组展开，不再依赖场景情节串联
- 概念之间的关系通过**知识网络图**和**关系类型标注**显式展示
- 新概念可以大胆引入，只要自包含地讲清楚（不再被"不假设未来知识"束缚）

## 第一部分：通用设计原则

### 原则 1：沙盘驱动，而非情节驱动

**旧方式（v2）**：设计一个多阶段故事 → 每个转折点引入一个概念 → 概念之间靠情节串联
**新方式（v3）**：设计一个完整的演练沙盘 → 一次性交代清楚 → 概念按网络展开 → 最后在沙盘中协同使用

沙盘必须满足：
- **完整性**：有公司/产品/数据/约束/挑战，一次性交代，不搞"走着瞧"
- **复用性**：同一个沙盘承载所有概念的练习，不换场景
- **代入感**：用户扮演明确角色，有清晰的"我要解决什么问题"
- **多义性**：沙盘中有真正的权衡取舍（不是只有一个正确答案）

### 原则 2：广度优先——拓展 = 展开关联概念网络

每一课的核心概念不是孤立存在的。它天然关联着一群概念，它们在实际工作中是**同时使用**的。拓展的目的就是把这群关联概念一次性展开。

| 阶段 | 周数 | 沙盘复杂度 | 概念总数 | 必修占比 |
|------|------|----------|---------|---------|
| 入门 | W1-W2 | 单一业务线、消费者App / 单文件脚本 | 5-8 个 | ≥60% |
| 成长 | W3-W4 | 可加入 B2B/SaaS/平台型 / 多模块项目 | 7-12 个 | ≥50% |
| 熟练 | W5+ | 全行业、跨部门协作 / 系统工程 | 10-15 个 | ≥40% |

"概念"的定义：一个有独立名称、可独立使用、需要独立练习才能掌握的知识单元。

### 原则 3：概念引入三段式（不可颠倒）

```
① 一句话白话：用"说白了就是……"开头，假设读者完全不懂
② 核心逻辑 + 具体例子：（匹配用户阶段的案例领域）
③ 与核心概念的关系：这个概念跟今天主课程的核心概念是什么关系？
   ——标注关系类型（前置/并行/防护/落地/替代）
```

**禁止**：英文原文在前、学术定义先行、先抛术语再解释。
**不再要求**：必须由"场景卡点"触发。概念各自独立讲清楚，在沙盘中协同。

### 原则 4：每个概念标注 [必修] / [选修] / [预览]

| 标签 | 判断标准 | 在文档中的占比 |
|------|---------|-------------|
| [必修] | 不掌握则核心能力不完整 | ≥50% |
| [选修] | 能提升水平，不影响基本使用 | ≤50% |
| [预览] | 依赖未学前置知识，标注"WX 会深入" | ≤10%，且只出现在延伸部分 |

### 原则 5：反馈 = 答案 + 偏差诊断 + 补救路径

每个练习的反馈 section：
```
✅ 参考答案
❓ 如果你的答案跟参考不同，你可能的误解是____（至少 2 种常见偏差）
🔧 补救：如果是偏差 A → 回到第 X 节重看____；如果是偏差 B → 做额外练习____
```

### 原则 6：禁止裸引未学知识

- **旧版（v1/v2）"不假设未来知识"的问题**：被误解为"不能引入主课程没教的概念"——但这恰恰是拓展的目的
- **新版规则**：拓展中引入的任何新概念，必须自包含地讲清楚（三段式），让用户当下就能理解并使用
- **允许引入未学概念，禁止"裸引"**：
  - ❌ "这个概念涉及 AB 实验，W7 会学，现在跳过"——这是裸引
  - ✅ "这个概念涉及 AB 实验。说白了就是同时跑两个版本看哪个效果好，W7 会深入实验设计细节，但你现在就可以理解基本思路：……"——这是自包含引入
- 在 Phase 1 信息收集时，通过读前一天和后一天 notebook 来确定用户的知识背景

### 原则 7：自诊只测"已学内容"

- 入口自诊（放在第三部分之前）：只测主课程涉及的内容
- 结业自评：只测主课程 + [必修] 拓展内容
- 禁止在入口自诊中出现本拓展才引入的概念

### 原则 8：案例默认从用户生活经验出发

- W1-W2：外卖、短视频、电商、社交、在线教育——用户作为消费者每天接触的产品
- 使用陌生领域案例时，先在沙盘设定中交代清楚

### 原则 9：沙盘统一性

**整个拓展文档使用同一个沙盘贯穿始终**。概念各自独立讲解，但在沙盘演练环节全部回到同一个沙盘协同使用。

### 原则 10：概念关系标注

每个关联概念必须标注与核心概念的关系类型：

| 关系类型 | 含义 | 示例（核心概念=OSM） |
|---------|------|-------------------|
| **[前置]** | 核心概念需要它才能正确使用；应在核心概念之前或同时讲解 | SMART（目标不SMART则OSM无效） |
| **[并行]** | 与核心概念同时使用，解决同一问题的不同方面 | ICE（OSM定策略，ICE排优先级） |
| **[防护]** | 防止核心概念被误用/滥用 | 古德哈特定律（防止M层被刷）、护栏指标 |
| **[落地]** | 把核心概念的产出变成实际工作 | 数据口径定义（把M翻译成SQL）、看板设计 |
| **[替代]** | 当核心概念不适用时的备选方案 | OKR（探索期替代OSM）、Lean Canvas |

**概念群分组**：第三部分按关系类型分组展示概念，而不是按"场景阶段"分组。一组内的概念之间逻辑相关，用户一次性学完一组。

### 原则 11：完整学习循环——认知→输入→输出→反馈→迁移

一份有效的拓展文档必须覆盖完整的五环学习循环。每一环不可跳过，顺序不可颠倒。

```
认知（Awareness）  →  输入（Input）  →  输出（Output）  →  反馈（Feedback）  →  迁移（Transfer）
   "我需要这个"        "原来是这样"      "我能自己做吗"      "我哪里理解偏了"     "换个场景还行吗"
```

| 环节 | 解决什么问题 | 在文档中的位置 | 具体形式 | 不覆盖的后果 |
|------|------------|-------------|---------|------------|
| **认知** | 让用户意识到"现有知识不够用"，产生学习动机 | 每个概念群的第一个 cell | **认知冲突**：一个用现有知识解不了（或解得很难看）的微问题 | 用户被动接收，学完也不知道"为什么要学这个" |
| **输入** | 结构化传授新知识 | 每个概念的讲解 cell | 三段式引入（白话→逻辑+例子→与核心概念的关系） | 已覆盖 |
| **输出** | 让用户独立应用新知识 | 每个概念群的小练习 + 第四部分综合沙盘 | 基于沙盘的练习 | 已覆盖 |
| **反馈** | 纠正误解，指出偏差根因 | 每个练习后的反馈 cell | 答案 + 至少 2 种常见偏差诊断 + 补救路径 | 已覆盖 |
| **迁移** | 验证知识能在不同场景中灵活应用 | 第四部分的沙盘变体 + 边界判断 | 改变沙盘参数后方案怎么调？什么场景不该用？ | 已覆盖 |

**认知冲突的设计方法**（这是 v3 新增的核心能力）：

认知冲突 ≠ "今天我们来学 X"。认知冲突是一个**微问题**，用户尝试用现有知识解决，发现解决不了或解决得很烂，从而产生"我需要新工具"的意识。

三种认知冲突模式：

| 模式 | 做法 | 适用场景 | 示例 |
|------|------|---------|------|
| **撞墙型** | 给一个看似简单但现有知识解决不了的问题 | 核心概念深化、前置概念 | "你有5条策略但只能做2条。凭感觉选？还是扔骰子？"（引出ICE） |
| **错误暴露型** | 展示一个"看起来对了但其实有隐蔽错误"的案例，让用户找茬 | 防护概念 | "这个OSM看起来三个框都填了，但你能发现它其实是个假OSM吗？" |
| **对比冲击型** | 同时展示"用新工具"和"不用新工具"两种做法，让用户感受差距 | 落地概念、替代概念 | "同样的策略设计，分析师A画了张图，分析师B写了一页纸带口径——老板听谁的？" |

**认知冲突的约束**：
- 每个概念群的认知冲突 ≤ 1 个 cell（一个微问题，不是长篇大论）
- 认知冲突不要求用户答对（恰恰相反，答不对才是正常的——这正是引入新概念的理由）
- 认知冲突之后，立刻接"你刚才遇到的问题，XX概念就是专门解决它的"

## 第二部分：执行流程

### Phase 1: 信息收集（并行）

**1a. 提取元信息**
从 notebook 路径中提取：
- 所属轨道（01/02/03）
- 周数（week_XX）
- 天数（day_XX）
- 配对技术课（同一天的 01 轨道 notebook）
→ 确定阶段参数（概念总数、沙盘复杂度、案例来源）

**1b. 提取主课程知识清单**
读取主 notebook，列出：
- 核心概念名称（如 OSM、dict、漏斗分析……）
- 核心概念的结构元素
- 主课程已覆盖的子概念
- 主课程的练习类型和难度
- **主课程提到的但没有展开的"引子"**（如"这里涉及 XX，但我们不展开"）——这些是拓展的最佳切入点

**1c. 扫描知识网络**
- 读前一天 notebook → 确认用户已经知道什么（可复用的前置知识）
- 读后一天 notebook → 确认即将学什么（可做预览锚点）
- 读同轨道本周其他 notebook → 确认本周的主题弧线
- 搜索同主题在其他轨道的版本 → 标记"已被覆盖的概念"

**1d. 确定知识网络**
产出"已学 / 将学 / 未覆盖"三列，从未覆盖中按**与核心概念的关系紧密程度**选出拓展概念群：

```
核心概念：{X}

已学（可引用）：        [概念A, 概念B, ...]
将学（可预览）：        [概念C, 概念D, ...]
未覆盖（拓展候选）：
  ├── 前置关系候选：   [概念E, 概念F, ...]
  ├── 并行关系候选：   [概念G, 概念H, ...]
  ├── 防护关系候选：   [概念I, ...]
  ├── 落地关系候选：   [概念J, 概念K, ...]
  └── 替代关系候选：   [概念L, ...]
                          ↑
              按关系类型分组，每组选 1-3 个
```

**选材规则**：
- 每种关系类型至少选 1 个概念（除非该类型无合适候选）
- 总数不超过阶段上限
- 优先选关系最紧密的（同类型内按"距离核心概念的远近"排序）
- 剩余有价值但超限的 → 放到"延伸阅读"一节，一行带过

### Phase 2: 沙盘设计

沙盘不是"故事"，是"演练场"。它在第一部分一次性交代，然后在第四部分用于综合演练。

**2a. 识别轨道 → 选择沙盘类型**

| 轨道 | 沙盘类型 | 沙盘本质 |
|------|---------|---------|
| 01 Python 技术 | **技术任务沙盘** | 一个具体的开发任务，有明确的输入/输出/约束 |
| 02/03 分析师 | **业务决策沙盘** | 一个具体的业务场景，有明确的公司/产品/数据/挑战 |

**2b. 沙盘设计模板（通用）**

沙盘只需在文档开头一次性设定，不需要分阶段。沙盘包含：

```
【业务轨道】
  - 公司名称、行业、规模、阶段
  - 产品/核心功能/用户群体/商业模式（靠什么赚钱）
  - 当前挑战（为什么需要数据分析介入？）
  - 你的角色（职位、汇报对象、交付形式）
  - 数据资产（至少列 3-5 张具体表名 + 字段类型）

【技术轨道】
  - 任务描述（要构建什么工具/系统/脚本？解决谁的什么问题？）
  - 输入数据（格式、来源、规模）
  - 输出要求（格式、消费者、性能要求）
  - 当前基线（已有的初始代码/实现，及其局限性）
  - 技术约束（内存、时间、可用库、Python 版本）
```

**关键约束**：沙盘设定 ≤ 4 个 cell，一次性交代完毕。不搞"阶段1设定一部分，阶段2再补充"。用户在阅读后续任何概念章节时，脑中已经有了完整的沙盘图景。

**2c. 概念-沙盘映射**

不同于 v2 的"场景阶段 → 概念"映射，v3 是"概念 → 在沙盘中的用武之地"映射：

```
示例（03 轨道 OSM）：

沙盘：某 B 轮电商 App，你是一号位数据分析师，Q3 要定增长策略

核心概念 OSM → 在沙盘中：用 OSM 为这个电商 App 设计 Q3 增长框架
[并行] ICE  → 在沙盘中：5条策略但资源只够做2条，用ICE排序
[并行] 虚荣vs可行动指标 → 在沙盘中：审视你设计的M层，哪些是虚荣指标？
[防护] 古德哈特定律 → 在沙盘中：你选的M可能被怎么刷？怎么加护栏？
[防护] 因果链断裂诊断 → 在沙盘中：检查你的O→S→M因果链
[落地] 数据口径定义 → 在沙盘中：把M翻译成SQL，写清楚分母分子
[落地] 一页纸呈现 → 在沙盘中：把你的OSM压缩成一页纸讲给CEO
[替代] OKR → 在沙盘中：如果公司是A轮探索期而非B轮成熟期，该用什么？
```

**2d. 选材检查**
- 沙盘类型是否匹配轨道？
- 每种关系类型是否至少有 1 个候选被选中？
- 概念总数是否符合阶段上限？
- [必修]/[选修]/[预览] 比例是否正确？

### Phase 3: 文档生成

生成 `拓展_W{周}D{天}_{沙盘关键词}.ipynb`，放在主 notebook 同目录。

#### 文档骨架（6 部分）

```
┌──────────────────────────────────────────────────────────────┐
│ [cell 0] 标题 + 知识网络预览 + 阅读指引                        │
│   - 标题：拓展：{核心概念}与关联知识网络                         │
│   - 知识预览：本拓展覆盖 {N} 个概念，按 {M} 组关系类型展开       │
│   - 指引：必修优先 → 选修按需 → 沙盘演练必做                    │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│ 第一部分：沙盘设定（cell 1-4）                                  │
│   - 一次性交代完整沙盘（业务：公司/产品/数据/角色/挑战）         │
│   - 不搞"阶段推进"，沙盘是固定的演练场                          │
│                                                              │
│ 第二部分：入口自诊（cell 5-6）                                 │
│   - 只测主课程内容，3-4 题                                     │
│   - 放在任何新概念之前                                         │
│ 第三部分：概念网络展开（cell 7-32）                             │
│   - 核心概念深化（cell 7-13）：                                 │
│     · 🔴 认知冲突（1 cell）：用现有知识解决不了的微问题            │
│     · 从主课程的“是什么”推进到“为什么这样设计”                   │
│     · 历史脉络、结构合理性、常见误解                             │
│     · 沙盘中的初步应用                                         │
│     · 练习 + 反馈                                              │
│   - 概念群 A：{关系类型}（cell 14-19）                          │
│     · 🔴 认知冲突（1 cell）：针对该组概念的微问题                 │

#### 各部分的生成规则

**第一部分：沙盘设定（≤ 4 cells）**

一次性交代，不保留信息。读者看完这 4 个 cell 后就完全理解沙盘，后续任何概念章节都不需要补充新的沙盘信息。

【业务轨道】：
1. 公司画像 + 产品描述 + 商业模式（≤5 句）
2. 当前挑战 + 你的角色（≤4 句）
3. 数据资产（≥5 张具体表名 + 字段类型）
4. （可选）组织架构/利益相关方

【技术轨道】：
1. 任务描述 + 输入/输出（≤5 句）
2. 当前基线代码 + 局限性（必须给具体代码或伪代码）
3. 技术约束（内存/时间/库/Python版本）
4. （可选）更大的系统上下文

**第二部分：入口自诊（≤ 2 cells）**

- 3-4 题，只测主课程内容
- 格式：题干 + `print` 留空给用户填写
- 反馈：答案 + 偏差诊断 + 补救路径（参照主课程对应内容）
**第三部分：概念网络展开**

每个概念群（一组同关系类型的概念）的生成规则：

```
### 概念群标题：{关系类型}概念（如"并行概念：与OSM同时使用的工具"）

[cell A] 🔴 认知冲突（1 cell，不可跳过）
  - 一个微问题，用户尝试用现有知识解决，发现解决不了或解得很勉强
  - 三种模式选其一：
    · 撞墙型：给一个现有知识解决不了的问题（适用于核心深化、前置、并行概念）
    · 错误暴露型：展示一个"看起来对了但有隐蔽错误"的案例（适用于防护概念）
    · 对比冲击型：展示"用新工具 vs 不用新工具"的差距（适用于落地、替代概念）
  - 认知冲突不要求用户答对（答不对正是引入新概念的理由）
  - 认知冲突之后，紧接着一句过渡："你刚才遇到的问题，XX概念就是专门解决它的。"

对群内每个概念：

[cell B] 概念引入
  ① 一句话白话（"说白了就是……"）
  ② 核心逻辑 + 具体例子（例子尽量复用沙盘中的数据/场景）
  ③ 与核心概念的关系（"这个概念是OSM的[并行]概念，因为……"）

[cell C] 在沙盘中的用武之地
  - 一段话描述这个概念在沙盘中具体怎么用
  - 不是完整练习，是"预告"——让用户知道这个概念在第四部分的沙盘演练中会出场

[cell D] 小练习（1 题）
  - 针对这个概念本身的掌握度检查
  - 反馈：答案 + 偏差诊断 + 补救路径
```

核心概念深化（第一组）的额外要求：
- 认知冲突用"撞墙型"：给一个看似简单的业务问题，用户尝试用主课程的知识解决，发现主课程只讲了壳没讲核
- 历史脉络（1-2 段）：这个框架发明之前，人们怎么解决同类问题？
- 结构合理性分析：为什么是这几个元素？多一个少一个各有什么后果？
- 沙盘初步应用：用核心概念为沙盘建立初始框架

[预览] 概念群（最后一组）：
- 1-2 个未来概念，自包含简介 + "WX 会深入"标注
- 不需要认知冲突和小练习，只需要一句话预告

**第四部分：综合沙盘演练**

1. **多概念协同**（必做，≥2 题）：一个综合问题，需要同时使用来自不同概念群的 3+ 个概念
2. **沙盘变体**（必做，1 题）：改变沙盘中的某个关键参数（业务阶段 / 数据规模 / 约束条件），问用户方案如何调整
3. **边界判断**（必做，1 题）：给 2-3 个不同的业务场景，问用户在哪些场景中会选择不同的工具组合
4. **落地**（必做，1 题）：业务→数据口径/看板/沟通；技术→代码审查/重构/测试

**第五部分：知识网络图**

1. **概念关系全景表**：

| 概念 | 关系类型 | 必修/选修 | 一句话要点 |
|------|---------|----------|----------|
| SMART | [前置] | [必修] | 目标不SMART则OSM的O层无效 |
| ICE | [并行] | [必修] | OSM定策略，ICE排优先级 |
| 古德哈特定律 | [防护] | [必修] | 当M成了目标，它就不再是好M |
| ... | ... | ... | ... |

2. **关系图解**（文字描述，不画图）：用 3-5 句话描述各概念群在沙盘中如何协同
3. **三版本覆盖对比表**：主课程 vs 进阶版（如有）vs 本拓展
4. **延伸阅读**：超限未纳入的概念，一行一个 + 跳过原因 + 关系类型
5. **跨模块连接**：前一天→今天→后天；配对技术课

**第六部分：元认知自评**

1. **学习循环自评**——对照五环循环，判断自己在哪个环节卡住了：

| 循环环节 | 自检问题 | 通过标志 | 卡住时回到 |
|---------|---------|---------|----------|
| 认知 | 每个概念，我能说出"为什么要学它"吗？ | 能说出它解决的具体痛点 | 回对应概念群的认知冲突 cell |
| 输入 | 不看笔记，能独立复述概念的核心逻辑吗？ | 能用白话+例子讲清楚 | 回对应概念的三段式引入 cell |
| 输出 | 能独立完成沙盘中的练习吗？ | 不翻笔记完成练习 | 重做小练习+综合沙盘 |
| 反馈 | 做错了知道错在哪、为什么错吗？ | 能说出"我之前的误解是X，正确的是Y" | 回对应练习的反馈 cell |
| 迁移 | 换一个沙盘，还能正确选择和使用这些概念吗？ | 沙盘变体+边界判断题全对 | 重做第四部分沙盘变体 |

**如果你的薄弱环节在"认知"**——说明概念不是你不需要，而是你不知道你需要。回到第三部分对应概念群，重新做认知冲突题，感受"现有知识不够用"的那一刻。

2. **多维度自评量表**（每维度 0-2 分）：

| 维度 | 0 分 | 2 分 | 得分 | 对应循环环节 |
|------|------|------|------|-----------|
| 核心概念 | 离开沙盘就不会用 | 能在新沙盘中独立应用 | /2 | 输出→迁移 |
| 关联概念 | 只知道定义 | 知道何时用、跟核心概念怎么配合 | /2 | 输入→输出 |
| 概念关系理解 | 说不出概念之间的关系 | 能画出概念网络并解释协同方式 | /2 | 认知→输入 |
| 沙盘迁移 | 换一个沙盘就懵 | 能判断什么沙盘用什么工具组合 | /2 | 迁移 |
| 落地能力 | 只会讲理论 | 能把概念产出翻译成具体工作 | /2 | 输出→迁移 |
| 综合判断 | 只会用一个工具 | 知道工具的边界和替代方案 | /2 | 迁移 |

3. **薄弱点强化方案**：得分最低的维度 → 结合学习循环自评表定位卡住的环节 → 回到对应概念群重做
4. **沙盘复述测试**：能不能把沙盘中的每个决策点为什么用这个工具讲给同事听？（覆盖全部五环：你需要知道为什么需要、怎么用、做错了怎么办、换个场景怎么办）
5. **循环毕业检查清单**：5-8 条具体的能力检查项，覆盖认知→输入→输出→反馈→迁移全部环节

## 第三部分：交互规则

**调用方式**：
- `/expand-lesson path/to/notebook.ipynb` — 全用默认值（v3 沙盘+概念网络模式）
- `/expand-lesson path/to/notebook.ipynb, v2` — 使用 v2 线性场景模式
- `/expand-lesson path/to/notebook.ipynb, v1` — 使用 v1 6螺旋深度钻井模式
- `照上次拓展模式来一份，文件是 xxx.ipynb` — 复用上次配置

**生成后报告格式**：
```
✅ 拓展文档已生成：{路径}
🏢 沙盘：{一句话描述} | 你的角色：{角色}
📊 文档结构：6 部分（沙盘设定→入口自诊→概念网络→综合沙盘→知识网络图→元认知）

- 用户对拓展内容提出追问 → 先回答，再升级文档（插入新 cell 到对应概念群中）

- **v2**：线性场景。适合"想用一个故事串起来"的场景
- **v1**：6螺旋深度钻井。适合"今天就想吃透这一个框架"的场景
