## 模块 3：SQL 面试题（大厂真题）

### 高频考点

| 考点 | 代表题目 | 关键技巧 |
|------|----------|----------|
| **留存率** | 新老用户次留/7留/30留 | 自连接 + datediff |
| **连续登录** | 连续登录≥7天 | ROW_NUMBER + 日期相减（gap-and-island） |
| **Top N** | 每国家充值Top3 | ROW_NUMBER() PARTITION BY + ORDER BY |
| **时间窗口** | 1小时内同起终点算同一需求 | 自关联 + timestampdiff + row_number |
| **LEFT JOIN陷阱** | ON vs WHERE 的区别 | WHERE 在 JOIN 后过滤=变 INNER JOIN |
| **复购率** | 购买≥2次用户/总购买用户 | COUNT DISTINCT + CASE WHEN |
| **渗透率** | 小程序交易额/总交易额 | 多表 JOIN + 条件聚合 |

### 面试实战提醒
- 不会写完美SQL时，先清晰说思路（伪代码/逻辑描述）
- 对逻辑的清晰阐述比代码本身更重要

## 模块 4：Hive/数据仓库

### Hive vs MySQL

| 维度 | MySQL (OLTP) | Hive (OLAP) |
|------|-------------|-------------|
| 用途 | 在线交易 | 离线分析 |
| 数据量 | GB级 | TB-PB级 |
| 延迟 | 毫秒 | 分钟-小时 |
| 事务 | 完整ACID | 不支持 |

### 数仓四层

```
ADS (应用层)  → 面向业务的报表、看板
DWS (服务层)  → 轻度聚合、主题宽表
DWD (明细层)  → 清洗、维度退化、保持明细
ODS (操作层)  → 原始日志、基本清洗
```

**核心理解**：数仓从下到上是不断 GROUP BY 的过程。

### 数据倾斜（最高频性能问题）

- **现象**：任务卡在 99%，某 Reduce 进度不动
- **原因**：某 Key（如「北京」）数据量是其他 Key 的几十倍
- **解决**：加盐打散大Key / MAPJOIN 小表 / 开启 skewjoin 优化

## 模块 5：AB 实验全流程

### 六个阶段

| 阶段 | 核心任务 | 最容易忽略的 |
|------|----------|------------|
| 1. 准备设计 | 明确假设、计算样本量、确定指标体系 | 护栏指标的设定 |
| 2. 部署监控 | 上线、策略验证、搭建看板 | **策略生效验证** |
| 3. 分析 | 显著性检验、效应大小、子组分析 | 看 Effect Size 而非只看 P 值 |
| 4. 决策 | 推全/优化/下线 | 综合考量统计+业务+商业价值 |

### 关键公式
- 样本量：n ≈ 15.69 × σ² / Δ²（α=0.05, Power=80%）
- MDE（检验灵敏度）：已有样本量下能检测到的最小效应
- 多重检验假阳性率：1 - (1-0.05)^m，m=30时概率79%！

## 模块 6：样本量计算与 MDE

### 铁三角关系
**样本量 ↔ 功效 ↔ MDE ↔ 效应大小** — 确定任意三个，第四个就确定了。

### MDE 最重要的用途
**评估「不显著」的结果**：
- 如果 MDE > 你预期的提升 → 实验灵敏度不够，不能下「功能无效」结论
- 如果 MDE < 你预期的提升，且结果仍不显著 → 功能大概率确实无效

### 提升灵敏度两招
1. 降低指标方差（剔除极端值、聚焦核心人群、用比率类指标替代均值类）
2. 扩大样本量（延长时间或扩大流量）

## 模块 7：AB 实验避坑指南

### 四大类陷阱

| 阶段 | 典型陷阱 | 后果 |
|------|----------|------|
| **设计期** | 混淆「最小样本量」与 MDE 概念 | 流量设计错误 |
| **设计期** | 计算样本量当成总量而非单组 | 样本量只有需要的一半 |
| **实施期** | **策略未生效就分析数据**（致命错误） | 实验沦为笑柄 |
| **实施期** | 反复窥视然后据此决策 | 假阳性率飙升 |
| **分析期** | 多重检验不校正 | 必然找到「假显著」结果 |
| **分析期** | 只看 P 值不看效应大小 | 大样本下微小差异也显著 |
| **决策期** | 机械按 P 值决策 | 忽略业务逻辑和投入产出 |

## 模块 8：经营分析

### 经营分析 ≠ 数据分析
- 经营分析 = **定期体检**（全面扫描，确认有没有毛病）
- 数据分析 = **专项手术**（针对具体问题深入分析）

### 四大模块框架
1. **目标达成**：KPI 完成率、时间进度差（红绿灯标注）
2. **指标拆解**：MECE 原则下钻，定位到具体责任人
3. **资源配置**：投入产出 ROI 分析，引导预算调整
4. **专题分析**：近期重点业务动作的深度分析

### 核心原则
- 结论先行，语句精炼
- 不要只描述「环比下降5%」，要说「因XX原因导致XX下降5%」
- 每次回答三个问题：投给了谁？效果如何？下一步怎么调？
