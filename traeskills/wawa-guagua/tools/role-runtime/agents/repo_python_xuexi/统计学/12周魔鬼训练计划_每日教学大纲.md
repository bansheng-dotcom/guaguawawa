### 第1周 · 周一：SQL窗口函数——聚合不折叠的艺术

📘 核心概念与第一性原理
- 窗口函数设计哲学：SQL是集合操作语言，GROUP BY把多行压成一行，但业务需要"行级上下文"——比如每人看到自己比上个月涨了多少。窗口函数填补了集合语言和行级需求之间的鸿沟。
- 从第一性原理推导：为什么需要PARTITION BY + ORDER BY两个子句？PARTITION BY定义"和谁比"，ORDER BY定义"按什么顺序比"，两者缺一不可。
- 要讲的核心认知：窗口函数 = GROUP BY(不折叠) + 自连接(不膨胀) —— 它兼具两者的优点，避免了两者的缺点。

🧩 知识点拆解（8个子知识点）
1. ROW_NUMBER / RANK / DENSE_RANK —— 行号/跳跃排名/连续排名，三种排名函数的选择直接影响TopN业务逻辑
2. LAG / LEAD —— 向前/向后取行，是计算环比、时间间隔的基石
3. SUM/AVG/COUNT + OVER —— 累计值计算，滚动GMV、累计用户数的标准做法
4. FIRST_VALUE / LAST_VALUE —— 窗口首尾值，取每组最早/最晚状态
5. 窗口帧规范 ROWS vs RANGE —— 物理行窗口 vs 逻辑值窗口，影响移动平均和滚动指标
6. PARTITION BY 多列 —— 多维分组下的窗口计算
7. ORDER BY 在窗口内 vs 查询尾部 —— 两个ORDER BY的作用域完全不同
8. 窗口函数 vs GROUP BY vs 自连接 —— 三种方案的性能和使用场景对比

💻 动手练习
- 步骤0：生成用户订单表（1000行，含user_id, order_date, amount, city, category）
- 步骤1基础：每人累计消费、每人每天排名、每人环比变化

### 第1周 · 周二：连续登录与留存——Gap-and-Island经典问题

📘 核心概念与第一性原理
- Gap-and-Island本质：在有序序列中识别连续区间。为什么不能直接用GROUP BY？因为GROUP BY只认相同的值，不认"连续"的概念。gap-and-island通过数学变换（日期-序号）将"连续"转化为"相同"，让GROUP BY能够工作。
- 从第一性原理推导：日期减序号的核心洞察——如果登录日期是连续的，那么"日期 - 序号"会得到同一个参考日期。这个巧妙的代数变换是理解gap-and-island的关键。

🧩 知识点拆解（7个子知识点）
1. 连续登录的精确定义 —— "连续"在不同业务场景下的不同定义（自然日连续 vs 工作日连续）
2. Gap-and-Island三步法 —— 去重→编号→日期减编号，每一步的数学原理
3. 次日留存/7日留存/30日留存 —— 三种留存的定义、SQL模板和业务含义
4. 自连接 + DATEDIFF 法 —— 留存计算的另一种写法，与gap-and-island的对比
5. 新用户留存 vs 全量用户留存 —— 分母不同，含义完全不同
6. Sessionization（会话切分） —— 时间窗口内连续行为合并为一个session
7. 留存率的时间维度 —— 为什么看次日留存曲线比看单个数字更有价值

💻 动手练习
- 步骤0：生成2000用户×180天的登录数据（含随机间断）
- 步骤1基础：次日留存率、7日留存率
- 步骤2进阶：连续登录≥7天的用户及连续天数
- 步骤3挑战：30分钟内连续行为合并为一个session，统计平均session时长
- 每题标注【预期输出】

📊 业务场景
- 场景1：某日留存率突降5%——是整体恶化还是某批新用户拉低了均值？同期群分析比单日留存更能定位问题

### 第1周 · 周三：JOIN全家桶与陷阱——你以为的INNER可能不是INNER

📘 核心概念与第一性原理
- JOIN的本质：集合论中的笛卡尔积 + 过滤条件。LEFT JOIN = 左表完整保留 + 右表匹配不上的填NULL。INNER JOIN = 交集。RIGHT JOIN = LEFT JOIN调换顺序。FULL JOIN = 并集。
- 最致命的陷阱：LEFT JOIN + WHERE右表条件 = INNER JOIN。原因：WHERE在JOIN结果生成后才执行，NULL被WHERE过滤掉了。ON条件在JOIN过程中生效，WHERE条件在JOIN后生效。

🧩 知识点拆解（8个子知识点）
1. INNER/LEFT/RIGHT/FULL JOIN 的韦恩图 —— 必须能徒手画出来
2. ON vs WHERE 的执行时机差异 —— LEFT JOIN中ON条件影响匹配，WHERE条件过滤结果
3. 一对多JOIN的行数膨胀 —— 为什么LEFT JOIN后行数变多了？怎么验证膨胀是否合理？
4. 多表JOIN的过滤条件位置 —— 条件放ON还是WHERE，对中间结果和最终结果的影响
5. 自连接(Self Join) —— 同一张表自己连自己，留存和会话化的基础
6. CROSS JOIN —— 笛卡尔积，什么时候该用（生成日期序列）什么时候不该用
7. SEMI JOIN / ANTI JOIN —— 用EXISTS/NOT EXISTS替代IN/NOT IN（处理NULL安全）
8. JOIN的索引策略 —— EXPLAIN怎么看JOIN用了什么算法（Nested Loop / Hash Join）

💻 动手练习
- 步骤0：构造t1(左表5行)+t2(右表4行)，精心设计NULL和多对多关系
- 步骤1基础：4种JOIN的输出行数和内容对比（手动预测 vs 实际输出）
- 步骤2进阶：LEFT JOIN + WHERE的陷阱验证——和INNER JOIN结果一模一样
- 步骤3挑战：多表JOIN（订单+用户+商品+分类），统计每品类复购率，注意行数膨胀
- 每题标注【预期输出】

📊 业务场景

### 第1周 · 周四：CTE与子查询——让复杂SQL可读可维护

📘 核心概念与第一性原理
- CTE(Common Table Expression)的本质：给子查询起名字。它不改变执行效率（大部分数据库），但改变可读性和可维护性。
- 为什么需要CTE？人脑的工作记忆有限（约4-7个组块）。嵌套3层的子查询已经有9个组块（SELECT→FROM→WHERE各3层），超过认知负荷。CTE把每个逻辑块命名，降低了认知复杂度。
- 递归CTE的哲学：用声明式SQL做命令式编程（循环），用来处理层级数据（组织树/品类树）。

🧩 知识点拆解（7个子知识点）
1. CTE语法：WITH name AS (...) —— 基本结构和多个CTE链式定义
2. CTE vs 子查询决策框架 —— 需要多次引用/超过2层嵌套/需要递归→用CTE
3. 递归CTE —— UNION ALL + 终止条件，组织树/品类层级/日期序列
4. CTE的物化行为 —— MySQL中CTE可能被多次执行，PG中可以MATERIALIZED
5. 临时表(TEMP TABLE) vs CTE —— 大数据量下临时表优于CTE
6. 派生表(Derived Table) —— FROM子句中的子查询，必须给别名
7. 子查询的位置：SELECT/ FROM / WHERE/ HAVING —— 每个位置的使用场景和限制

💻 动手练习
- 步骤0：生成组织架构表（员工ID+上级ID+姓名+部门）
- 步骤1基础：用CTE重写周二的连续登录SQL，对比可读性

- 步骤3挑战：用递归CTE生成2025年全年日期序列做报表骨架，LEFT JOIN业务数据填坑
- 每题标注【预期输出】

### 第1周 · 周五：TopN + 复购率 + 漏斗——三大高频业务SQL

📘 核心概念与第一性原理
- TopN的本质：排序+截断。但"并列第N名"的处理是业务逻辑的分水岭——ROW_NUMBER（严格N个）、RANK（保留并列）、DENSE_RANK（连续但保留并列）。
- 复购率的本质：在购买用户中识别重复行为。CASE WHEN + COUNT DISTINCT是核心技法，度量的是"用户对产品的持续认可"。
- 漏斗的本质：用户行为序列中每步的衰减。每一步的流失都是产品体验的"裂缝"。

🧩 知识点拆解（8个子知识点）
1. TopN三种实现 —— ROW_NUMBER PARTITION BY vs RANK vs 子查询+LIMIT
2. 每组TopN的平局处理 —— 并列第3名都取 vs 只取一个
3. 复购率SQL模板 —— COUNT DISTINCT CASE WHEN cnt>=2 THEN uid END / COUNT DISTINCT uid
4. 复购率的时段选择 —— 月度复购 vs 季度复购 vs 滚动复购
5. 漏斗SQL两种实现 —— 多COUNT DISTINCT vs 自连接+窗口函数
6. 漏斗的分群对比 —— 渠道/设备/新老用户的分群漏斗
7. 渗透率/占比 —— 条件聚合，SUM(CASE WHEN) / SUM()
8. 环比/同比 —— LAG + 日期计算

💻 动手练习
- 步骤0：生成订单表（含user_id, amount, category, country, order_date）
- 步骤1基础：每国家消费Top3、每月复购率
- 步骤2进阶：5步电商漏斗（浏览→加购→下单→支付→完成），每步转化率
- 步骤3挑战：每国家×每品类×每月的复购率矩阵 + 找出复购率下降最快的3个细分
- 每题标注【预期输出】

📊 业务场景
- 场景1：老板问"上个月复购率怎么样了"——你只回答一个数字的话，漏掉了什么？（不同品类/渠道/用户群的复购率可能完全不同）
- 场景2：某APP漏斗中发现"加购→下单"转化率突然下降——可能的原因有哪些？（技术、运营、竞品三条线排查）

### 第1周 · 周日：SQL反模式与查询优化——写出不被人骂的SQL

📘 核心概念与第一性原理

- 反模式之所以"反"，是因为它们阻止了优化器使用索引，导致全表扫描。

🧩 知识点拆解（8个子知识点）
1. SELECT * —— 为什么不能用：索引覆盖失效、传输带宽浪费、列变化导致代码崩溃
2. 函数包裹列名 —— WHERE DATE(create_time) = '2025-01-01'用不了索引
3. 前缀模糊 LIKE '%xxx' —— B+树最左前缀失效
4. OR跨列 —— WHERE a=1 OR b=2 优化器可能无法使用索引
5. 隐式类型转换 —— VARCHAR列比较数字，索引失效
6. ORDER BY RAND() —— 全表扫描+排序，致命的性能杀手
7. 深分页 LIMIT 1000000, 20 —— 延迟关联或基于主键的游标分页
8. EXPLAIN解读 —— type/rows/key/Extra 的含义和优化方向

### 第2周 · 周一：Hive基础——OLTP到OLAP的思维范式转换

📘 核心概念与第一性原理
- OLTP vs OLAP的本质区别：事务型数据库追求低延迟+高并发+ACID，分析型数据库追求高吞吐+扫描效率。这是为什么MySQL处理TB数据时会崩溃，而Hive可以处理PB数据的根本原因。
- Hadoop/Hive的哲学：移动计算而非移动数据。数据存储在HDFS上，Hive把SQL编译成MapReduce/Tez/Spark任务去数据所在节点计算，避免了海量数据的网络传输。
- Hive不是数据库，是数据仓库工具。它的延迟是分钟-小时级，不适用于在线业务。

🧩 知识点拆解（7个子知识点）
1. Hive架构 —— Metastore(元数据)/Driver(编译优化)/Executor(执行)三层
2. HiveQL vs SQL差异 —— HQL支持的特有语法和限制（不支持行级UPDATE/DELETE）
3. MapReduce基本原理 —— Map(分) + Shuffle(合) + Reduce(算)，理解数据流动过程
4. Hive的执行计划 —— EXPLAIN能看到多少MapReduce阶段
5. Hive的数据类型 —— 复合类型ARRAY/MAP/STRUCT及其使用场景
6. Hive与MySQL的5个核心差异 —— 用途/数据量/延迟/事务/索引
7. Hive的适用场景 —— ETL/报表/机器学习特征工程

### 第2周 · 周二：Hive核心语法——表类型+分区+分桶+文件格式

📘 核心概念与第一性原理
- 分区(PARTITION)的本质：通过目录结构对数据进行物理分割，实现"只扫描需要的数据"。分区键的选择直接影响查询性能——选择过滤条件中出现频率最高的列。
- 分桶(CLUSTERED BY)的本质：将数据按哈希值均匀分配到多个文件中，用于JOIN优化（两个桶数相同或倍数关系的表可以做SMB JOIN）。
- 内部表vs外部表：DROP时内部表连数据一起删，外部表只删元数据保留HDFS文件——数据安全性是选择的核心依据。

🧩 知识点拆解（8个子知识点）

2. 分区表 —— PARTITIONED BY语法、静态分区vs动态分区、分区裁剪原理
3. 分桶表 —— CLUSTERED BY + SORTED BY、桶数选择原则、SMB JOIN
4. ORC vs Parquet —— 列式存储格式对比、压缩比、谓词下推支持
5. Hive SerDe —— 序列化/反序列化，处理JSON/CSV/自定义格式
6. LOAD DATA vs INSERT —— 数据加载方式的差异
7. 动态分区(DPP) —— 自动将数据写入对应分区、风险（小文件）和控制
8. 复杂数据类型 —— ARRAY/MAP/STRUCT的建表和使用

### 第2周 · 周四：数仓建模（一）——四层分层与维度建模

📘 核心概念与第一性原理
- 数仓分层的本质：解耦。原始数据(ODS)变动时不影响下游，明细数据(DWD)提供统一的事实基础，汇总数据(DWS/DM)面向特定分析场景。分层是"不变应万变"的策略。
- 从第一性原理推导：为什么要有DWD？因为ODS是业务系统的快照，可能有重复/脏数据/格式不一致。DWD做一次"清洗+标准化"，让所有下游应用都消费干净数据。
- 核心认知：数仓从下到上是不断GROUP BY的过程——ODS(明细)→DWD(清洗后的明细)→DWS(GROUP BY到轻度汇总)→ADS(GROUP BY到最终报表)。

🧩 知识点拆解（8个子知识点）
1. ODS层 —— 原始日志快照，不做加工或仅基本清洗
2. DWD层 —— 数据清洗、维度退化、事实粒度统一
3. DWS层 —— 轻度聚合、主题宽表、日/周/月粒度
4. ADS层 —— 面向业务的报表看板、直接可读
5. 星型模型 vs 雪花模型 —— 事实表+维度表的设计，冗余与规范化的权衡
6. 事实表类型 —— 事务事实/周期快照/累积快照，三种事实表的使用场景
7. 维度建模四步法 —— 选择业务过程→声明粒度→确定维度→确定事实
8. 数据域的划分 —— 用户域/流量域/交易域/内容域的切分逻辑

### 第2周 · 周五：数仓建模（二）——缓慢变化维度与宽表设计

### 第2周 · 周六：数据倾斜——Hive最高频性能问题及其解决方案

📘 核心概念与第一性原理
- 数据倾斜的本质：分布式计算中，某几个Key的数据量远大于其他Key，导致处理这些Key的Reduce节点成为瓶颈。MapReduce要求所有Reduce完成才算任务完成——一个Reduce卡住，整个任务卡住。
- 为什么倾斜如此常见？互联网数据天然服从幂律分布（二八定律）——Top城市(北京/上海)的数据量是普通城市的几十倍，这是数据倾斜的温床。

🧩 知识点拆解（8个子知识点）
1. 数据倾斜的三现象 —— 任务卡99%/某Reduce进度不动/GC超限
2. 倾斜的根因 —— 某Key数据量远大于其他Key + GROUP BY/JOIN操作
3. 加盐法(Salting) —— 给大Key加随机后缀打散，处理完再去后缀聚合
4. MAPJOIN —— 小表全量加载到内存做Map端JOIN，避免Shuffle
5. 两阶段聚合 —— 先局部聚合缩小数据量，再全局聚合
6. Skew Join优化 —— Hive自身的倾斜优化参数(hive.optimize.skewjoin)
7. 小文件问题 —— 小文件过多导致Map数爆炸，需要合并
8. 如何预防倾斜 —— 分区键/分桶键的选择、NULL值过滤

💻 动手练习（Python模拟）
- 步骤0：生成倾斜数据（1个Key占50%，999个Key分剩余的50%）
- 步骤1：实现标准GROUP BY，记录处理时间（模拟单节点瓶颈）
- 步骤2：实现加盐方案——大Key拆分为10份+两阶段聚合，对比时间
- 步骤3：实现MAPJOIN方案——适合大小表关联的场景
- 每步输出性能对比

📊 业务场景
- 场景1：按城市统计GMV——"北京"数据量是小城市的50倍，不加盐直接GROUP BY，任务跑了6小时
- 场景2：用户表(千万) JOIN 城市表(300行)——用MAPJOIN，300行的城市表全量进内存，0次Shuffle

### 第3周 · 周一：AB实验概念体系——统计基础与第一性原理

📘 核心概念与第一性原理
- AB实验的本质：用随机化创造"平行宇宙"。将用户随机分到实验组和对照组，由于随机化平衡了所有已知和未知的混杂因素，两组之间的唯一系统性差异就是"策略的差异"，因此结果的差异只能归因于策略。
- 第一性原理推导：为什么需要统计检验？因为即使策略完全无效，随机波动也会让两组看起来有差异。统计检验量化了"这个差异是随机波动的概率(p值)"——p值越小，越不像是随机波动。
- p值最核心的认知：p值不是"策略有效的概率"，而是"假设策略无效，观察到当前差异（或更大差异）的概率"。

🧩 知识点拆解（10个子知识点）
1. H₀(零假设) vs H₁(备择假设) —— 无罪推定原则，为什么零假设永远是"无效果"
2. α(显著性水平) —— 你愿意容忍的假阳性概率，0.05意味着每20次有一次谎报
3. β(第二类错误) —— 有真效果但没检测到的概率，1-β=Power(检验功效)
4. p值的正确解读 —— p值不是"有效概率"，三句话让不懂统计的人听懂
5. 置信区间的含义 —— 如果重复实验100次，有95次的置信区间会包含真实效应
6. 效应量(Effect Size) —— 组间差异的绝对值，大样本下微小差异也能p<0.05
7. p值和效应量的关系 —— 为什么只看p值是危险的（大样本下0.001%差异也显著）
8. 双尾检验 vs 单尾检验 —— 为什么互联网推荐用双尾
9. 中心极限定理 —— 为什么样本均值的分布趋近正态分布
10. t检验的基本原理 —— t值 = (均值差) / (标准误)，衡量差异相对于噪声的倍数

💻 动手练习

- 步骤1：修改实验组均值（真有差异），观察p值变化
- 步骤2：逐渐增大样本量（n=100/1000/10000），观察p值和效应量的关系
- 步骤3：200字给不懂统计的PM写一段话解释p值（严禁出现"概率"以外的统计术语）

### 第3周 · 周二：样本量计算——均值指标的铁三角

📘 核心概念与第一性原理
- 样本量公式的本质：n = 2×(Zα+Zβ)²×σ²/Δ²，从第一性原理理解为什么每个参数在公式中：
  - Zα：你想要多严格的假阳性控制，α越小→Zα越大→样本量越大（越严谨越贵）
  - Zβ：你想要多大概率抓到真效果，β越小→Zβ越大→样本量越大
  - σ²：数据本身的波动，波动越大越难区别信号和噪声→样本量越大
  - Δ：你关心的最小效应大小，效应越小越难检测→样本量呈平方级增长
- 最反直觉的认知：Δ减半，样本量翻4倍（平方关系）。这意味着追求高灵敏度很贵。

🧩 知识点拆解（7个子知识点）
1. 样本量公式推导 —— 从双样本t检验的检验统计量出发，理解每个参数的物理含义
2. Zα和Zβ的取值 —— α=0.05→Zα=1.96, β=0.2→Zβ=0.84，为什么选这些值
3. Δ的三种确定方法 —— 业务重要性、历史数据参考、行业基准
4. σ的估计方法 —— 历史数据的标准差、预实验估计
5. 铁三角关系 —— 样本量↔功效↔MDE↔效应大小，确定任意三个→第四个确定
6. 样本量指的是每组 —— 最常见的陷阱：算出来是单组的量，总数要×2
7. 非平衡设计的样本量 —— 如果实验组和对照组的流量比不是1:1

💻 动手练习
- 步骤0：实现样本量计算函数（输入α/β/σ/Δ→输出n）
- 步骤1：固定其他参数，画Δ从0.01到0.1变化时样本量的曲线（观察平方关系）
- 步骤2：固定其他参数，画σ从0.5到3变化时样本量的曲线
- 步骤3：已有10000样本量，σ=2，反算MDE——这个实验能检测到多大的效果？

📊 业务场景

### 第3周 · 周三：样本量计算——比例指标与MDE

📘 核心概念与第一性原理
- 比例指标的方差：σ²=p(1-p)，p=0.5时方差最大。这意味着转化率50%附近的实验需要最大的样本量——这和均值指标不同，比例指标的方差自带上限。
- MDE(Minimum Detectable Effect)：在给定的样本量和方差下，实验能检测到的最小真实效应。它是对实验灵敏度的度量。
- MDE最实用的场景：当实验结果不显著时，计算MDE帮你判断是"真没效果"还是"灵敏度不够"。

🧩 知识点拆解（6个子知识点）
1. 比例指标的样本量公式 —— n=2×(Zα+Zβ)²×p(1-p)/Δ²
2. p=0.5最大方差 —— 为什么转化率50%需要最大样本量
3. MDE的定义与计算公式 —— 在给定n/σ/α/β下反算最小可检测效应
4. 均值指标MDE vs 比例指标MDE —— 公式和计算方式的差异
5. 不显著结果的三步判断法 —— 计算MDE→比对预期效应→下结论
6. 灵敏度提升的两招 —— 降低方差(剔除极端值/聚焦核心人群/换比率类指标) + 扩大样本量

💻 动手练习
- 步骤0：实现比例指标样本量计算函数和MDE计算函数
- 步骤1：固定n,α,β，画p从0.01到0.99时所需样本量曲线（观察对称性）
- 步骤2：给定n=10000，p_control=0.1，计算MDE
- 步骤3：模拟3组"不显著"的实验结果，分别用MDE判断是没效果还是灵敏度不够

📊 业务场景
- 场景1：实验GMV+3%但p=0.12，MDE=5%——意思是如果真实效应<5%，你的实验检不出。3%的提升可能真实存在但灵敏度不够
- 场景2：实验GMV+0.5%但p=0.08，MDE=1%——意思是实验能检出1%的效应，但只看到了0.5%。大概率真没效果

✅ 分级检验
- 初级：能计算比例指标的样本量和MDE
- 中级：能解释为什么p=0.5时需要最大样本量
- 高级：能判断一个"不显著"的结果是没效果还是灵敏度不够

### 第3周 · 周五：AA实验与策略生效验证——实验的"健康检查"

📘 核心概念与第一性原理
- AA实验的本质：将用户随机均分到两组但都不给新策略，理论上两组应该完全一致。如果AA实验出现显著差异→分流系统有Bug→这个系统上跑的所有AB实验结论都不可信。
- 策略生效验证的本质：实验开始后，先确认策略真的对实验组用户"起作用"了。如果策略根本没生效（比如算法上线失败、UI没变），那分析出来的"无差异"是策略没生效而不是策略没效果——这是最致命的错误。

🧩 知识点拆解（6个子知识点）
1. AA实验的原理 —— 为什么要做AA、怎么做、假阳性率的期望
2. AA实验的假阳性率模拟 —— 重复1000次AA实验，~50次p<0.05是正常的
3. Pre-AA检验 —— 实验上线前用历史数据验证分流均匀性
4. 策略生效验证的五种方法 —— 埋点检查/数据量对比/关键行为对比/日志审查/用户反馈
5. 策略未生效的常见原因 —— 上线失败/配置错误/触发条件不满足/灰度不完全
6. SRM(样本比率不匹配)检验 —— 卡方检验验证实际流量分配是否符合设计比例

💻 动手练习
- 步骤0：实现AA实验模拟代码，重复1000次，统计p<0.05的占比（应≈5%）
- 步骤1：构造"策略未生效"的数据→策略生效验证代码检测
- 步骤2：实现SRM检验（卡方检验实际分组是否符合设计比例）
- 步骤3：写一份"如何说服PM不要偷看实验"的沟通稿

### 第3周 · 周六：统计检验与分析——从p值到完整结论

📘 核心概念与第一性原理
- 检验方法选择的本质：不同的假设和数据特征需要不同的检验方法。连续指标→t检验，比例指标→卡方检验/Delta Method，方差不等→Welch's t检验，非正态→Mann-Whitney U检验。
- 效应量的核心地位：p值告诉你"差异是否可能是随机"，效应量告诉你"差异有多大"。业务决策需要后者——一个p<0.0001但效应量0.001%的策略可能不值得做。

🧩 知识点拆解（7个子知识点）
1. t检验（Student's t-test） —— 等方差假设下的均值差异检验
2. Welch's t检验 —— 不等方差时使用，更通用更稳健
3. Mann-Whitney U检验 —— 非参数检验，不假设正态分布
4. 卡方检验(Chi-Squared) —— 比例差异检验
5. Delta Method —— 比率类指标（如RPM）的方差估计和检验
6. 效应量的汇报 —— Cohen's d(均值)/相对提升%(比例)/置信区间宽度
7. 分析报告的结构 —— 检验→效应量→置信区间→分群分析→结论建议

💻 动手练习
- 步骤0：生成一组实验数据（含连续指标+比例指标+分组）
- 步骤1：选正确的检验方法→跑检验→输出p值+效应量+置信区间
- 步骤2：对比Student's t和Welch's t在同一数据上的结果差异
- 步骤3：写出完整实验分析报告（不超过1页）

📊 业务场景
- 场景1：分析师只汇报了"p=0.03，显著"，PM问"效果到底多大"——你答不上来
- 场景2：实验组方差远大于对照组→用Student's t会低估p值→应该用Welch's t

✅ 分级检验

- 中级：分析报告至少包含p值+效应量+置信区间三个输出
- 高级：能根据数据特征判断该用参数检验还是非参数检验

### 第3周 · 周日：Peeking与多重检验——假阳性的两大元凶

📘 核心概念与第一性原理
- Peeking(反复窥视)的危害：每次看数据都是一次假设检验，每次都有5%的假阳性概率。如果每天偷看一次实验，7天后假阳性概率不是5%，而是1-(1-0.05)^7≈30%。
- 多重检验的本质：查的指标越多，总有一个会"偶然显著"。查20个指标，至少1个假显著的概率=1-(1-0.05)^20≈64%。如果30个→约79%。
- Bonferroni vs BH纠正确实：Bonferroni(严控FWER)适合"不允许一个假阳性"的高风险场景(医药)；BH(控制FDR)适合"允许少量假阳性"的互联网场景(探索性分析)。

🧩 知识点拆解（6个子知识点）
1. Peeking的数学原理 —— 每次窥视→独立的假阳性机会→累计假阳性率飙升
2. 序贯检验(Sequential Testing) —— 解决Peeking问题的正确方法
3. 多重检验假阳性率 —— 1-(1-α)^m，m个指标的累计效应
4. Bonferroni矫正 —— α/m，简单但过于保守
5. BH(Benjamini-Hochberg)矫正 —— 控制FDR，更适合互联网
6. 子组分析的陷阱 —— 子组越多越容易找到假显著

### 第4周 · 周一：MDE深度应用——不显著结果的科学判断

📘 核心概念与第一性原理
- MDE的深层理解：它不是"实验无效的标志"，而是"检验灵敏度的度量"。一个实验结果不显著，可能是真没效果，也可能是实验灵敏度不够（MDE太大）。
- 不显著≠无效：这是分析师区别于"看p<0.05就喊有效、p≥0.05就喊无效"的关键。高级分析师会计算MDE+业务判断。

🧩 知识点拆解（5个子知识点）
1. MDE反向计算 —— 在给定n/σ/α/β下计算MDE
2. MDE与预期效应的比较 —— MDE < 预期效应时的不显著→大概率真无效；MDE > 预期效应时的不显著→灵敏度不够
3. 降低方差的三招实操 —— 剔除极值(truncation/capping)/聚焦核心人群(特定用户群)/替换指标(比率类代均值类)
4. 扩大样本量的实操 —— 延长时间/扩大流量比例/跨地域
5. CUPED预览 —— 协变量调整（明天详细讲）

### 第4周 · 周二：CUPED方差缩减——让实验更灵敏

📘 核心概念与第一性原理
- CUPED的本质：用预实验数据作为协变量，消除已知的个体差异，从而降低指标方差。如果预实验指标和实验期指标高度相关，CUPED可以把方差缩小20-50%。
- 数学直觉：方差缩小的幅度 = 1 - ρ²，其中ρ是预实验指标和实验期指标的相关系数。ρ=0.5→方差缩小25%，ρ=0.8→方差缩小36%。
- 为什么这个技术重要？方差缩小一半 = 样本量需求减半 = 实验时间减半。

🧩 知识点拆解（5个子知识点）
1. CUPED的核心公式 —— 调整后指标 = Y - θ×(X - E[X])，θ=Cov(Y,X)/Var(X)
2. 协变量X的选择标准 —— ①与Y高度相关 ②不受处理影响 ③实验前数据
3. CUPED对样本量的影响 —— 方差缩小后，所需样本量等比例缩小
4. 多层CUPED —— 用多个预实验变量做多元回归调整
5. CUPED的局限 —— 协变量选择不当反而可能增加方差

💻 动手练习
- 步骤0：生成实验数据（含预实验指标X和实验期指标Y，ρ≈0.7）
- 步骤1：实现CUPED调整，对比调整前后的方差
- 步骤2：计算CUPED带来的样本量节省
- 步骤3：验证选错协变量的后果（选ρ≈0.1的变量，方差反而增大）

📊 业务场景

### 第4周 · 周三：网络效应与Switchback——当用户之间互相影响时

📘 核心概念与第一性原理
- 网络效应的含义：在社交/出行/外卖/支付等产品中，一个用户的行为会影响其他用户——违背了SUTVA假设(Stable Unit Treatment Value Assumption)。此时标准的用户级随机分流失效。
- Switchback的哲学：不做"用户间"的对比，做"时间段内"的对比。一段时间全量上线策略，一段时间全量下线策略，交替进行→每个时间段是一个实验单元。

🧩 知识点拆解（5个子知识点）
1. 网络效应的典型场景 —— 社交裂变/共享出行/外卖拼单/红包分享
2. SUTVA假设及其违反后果 —— 实验组用户分享给对照组→两组不再是干净的对比
3. Switchback实验设计 —— 时间窗口划分+交替策略+聚类稳健标准误
4. 地理分流(Geo Testing) —— 按城市/区域分流，减少区域间溢出
5. Switchback的局限 —— 时间窗口选择困难、新颖性效应的干扰

- 步骤2：设计一个外卖平台的Switchback实验方案（时间窗口+指标+分析）
- 步骤3：对比不同时间窗口长度对Switchback结论的影响

### 第4周 · 周四：长期效应与Holdout——短期显著≠长期有效

📘 核心概念与第一性原理

- Holdout设计的哲学：保留一小部分用户(如5%)长期不给他们新策略，作为"真实基准线"。当回退对照组被污染（策略连续迭代）时，Holdout是唯一可信的对照。

🧩 知识点拆解（5个子知识点）
1. 新颖性效应的表现 —— 初期显著→随时间效果衰减→甚至反转
2. Holdout设计 —— 保留5-10%用户长期不接受任何新策略
3. 短期vs长期矛盾案例 —— 短期GMV涨但长期用户留存跌的陷阱
4. 长期效应衰减的3个原因 —— 新颖性消退/用户适应/竞争反应
5. 如何评估长期效应 —— 时间序列分析+衰减曲线+Holdout对比

### 第4周 · 周日：AB实验避坑大全——14个经典陷阱

📘 核心概念与第一性原理
- 14个陷阱的本质：每一个陷阱都是对"AB实验=简单对比"这一认知偏差的修正。AB实验看似简单，实则细节决定成败——设计期的漏洞会传到分析期放大。

🧩 14个陷阱（分四类）
**【设计期陷阱】**
1. 混淆最小样本量与MDE——流量设计错误
2. 计算样本量时当成总量而非单组——样本量差一倍
3. 护栏指标事后定义——已经跌了的指标被排除→自欺欺人

**【实施期陷阱】**
5. 策略未生效就分析数据——致命错误第一名
6. 反复窥视然后据此决策——假阳性率飙升
7. SRM检验不通过仍继续分析——分流有bug
8. 实验组和对照组用户有重叠——网络效应

**【分析期陷阱】**
9. 多重检验不校正——必然找到假显著
10. 只看p值不看效应量——大样本下什么都显著
11. 子组分析不做校正——分群越多越容易找到假显著
12. 用错误的分流单位做分析——PV分流用UV分析

**【决策期陷阱】**
13. 机械按p值决策——忽略业务逻辑和ROI
14. 忽视新颖性效应和长期效应——短期推全长期后悔

### 第5周 · 周一：北极星指标——找到产品的「唯一重要数字」

📘 核心概念与第一性原理

- NSM的5个标准：①反映用户价值 ②可指引长期战略 ③可拆解为可行动的子指标 ④不过度依赖短期波动 ⑤跨部门共识。为什么这些标准缺一不可？因为一个不能被拆解的NSM只是一个数字，无法指导行动。

🧩 知识点拆解（6个子知识点）
1. NSM定义与5个标准——逐一解释每个标准的业务含义
2. 各行业NSM案例——短视频(人均时长)/电商(GMV)/出行(完单量)/SaaS(MAU)
3. 同一产品不同阶段的NSM——早期(留存)→增长期(DAU)→成熟期(收入)
4. 虚假NSM的识别——注册用户数/下载量/曝光量→为什么它们不是真正的NSM
5. NSM的拆解——如何从NSM拆到可执行的过程指标

### 第5周 · 周二：OSM模型——从目标到度量的结构化拆解

📘 核心概念与第一性原理

3. OSM vs KPI体系——OSM更强调"策略-度量的因果连接"
4. OSM的适用场景与局限——冷启动/新业务设计行之有效，但复杂度受限
5. OSM与CMOP的衔接——OSM设计完初始体系→CMOP补充组织和流程视角

### 第5周 · 周三：CMOP模型——复杂平台的指标体系设计

### 第5周 · 周四：指标拆解与异动归因——从"订单下降了"到"谁的责任"

📘 核心概念与第一性原理
- 异动归因的本质：一个总量指标的变化，由多个子因素共同驱动。归因分析就是量化每个因素的贡献度——"订单下降15%，其中新用户贡献-8%，老用户贡献-5%，技术故障贡献-2%"。
- MECE拆解的必要性：只有互斥且穷尽的拆解，才能保证贡献度之和=100%，才能让每个部门的责任边界清晰。

🧩 知识点拆解（6个子知识点）
1. MECE拆解原则——互斥(Mutually Exclusive)+穷尽(Collectively Exhaustive)
2. 驱动树(Driver Tree)——从顶层指标到末端指标的树状拆解
3. 对数分解法(Logarithmic Decomposition)——量化每个因素的贡献率
4. 乘法分解——总量=因素1×因素2×因素3，每个因素的变化如何贡献
5. 归因到责任人——每个分解因子对应到具体部门或团队
6. 异动归因的5步流程——确认异动→MECE拆解→计算贡献→定位根因→输出建议

💻 动手练习

- 步骤1：订单量下降15%，用驱动树拆解
- 步骤2：Python实现对数分解法，量化每个因素的贡献率
- 步骤3：写出归因结论——"订单下降15%主要因为XX渠道的XX用户群体，建议XX条"

📊 业务场景
- 场景1：VP说"上个月订单为什么跌了？"——你不能回答"因为新用户少了"，要精确到"新用户占比从30%降到25%，贡献了60%的降幅"
- 场景2：多个因素同时变化，有正有负——总量没变可能是"此消彼长"，总量变化可能是"共振"

### 第6周 · 周一：AARRR海盗模型深度——不背概念，懂每个A的分析重点

📘 核心概念与第一性原理
- AARRR的本质：用户和产品的交互有5个关键阶段——获取→激活→留存→变现→传播。每个阶段的流失都是产品价值的"漏洞"。
- 为什么不同阶段AARRR的侧重不同？早期产品需要先验证留存的A，因为留存是"用户觉得产品有用"的根本信号。没有留存的产品拉再多新用户也只是"蓄水池底部有个洞"。

🧩 知识点拆解（7个子知识点）
1. 获客(Acquisition)——CAC、渠道转化率、渠道质量评估（不仅看量还要看留存质量）
2. 激活(Activation)——Aha Moment的定义和测量、激活率、核心行为漏斗
3. 留存(Retention)——次留/7留/30留、魔法数字(Magic Number)
4. 变现(Revenue)——付费率/ARPU/LTV/ARPPU
5. 传播(Referral)——K因子、病毒系数、邀请转化率
6. 不同产品阶段的AARRR侧重——MVP期(留存活下来)→增长期(获客+激活)→成熟期(变现+传播)
7. AARRR的局限——线性思维、不适合复杂双边市场

### 第6周 · 周二：同期群分析——避免「平均化」的误导

📘 核心概念与第一性原理
- 同期群(Cohort)的本质：同一时间段内具备共同特征的一批用户。固定这批用户，追踪某个指标随时间的变化——这就是Cohort Analysis。
- 为什么Cohort比平均值更有价值？看看一个例子：总体留存率50%——可能是"老用户100%+"新用户0%"。平均值掩盖了天壤之别的真相。

🧩 知识点拆解（5个子知识点）
1. Cohort的定义和分类——时间Cohort(注册月/首购月) / 行为Cohort(高消/低消)
2. Cohort矩阵的构建——行=Cohort, 列=时间周期, 值=指标
3. Cohort矩阵的阅读方法——横向(同批用户的指标随时间变化)、纵向(不同批次同期的对比)
4. Cohort热力图的信号解读——哪些模式代表产品变好/变差
5. Cohort分析的业务价值——精准定位"哪批用户出了问题"

💻 动手练习
- 步骤0：用Python生成用户注册+活跃数据
- 步骤1：构建用户留存Cohort矩阵（12个月×12列）
- 步骤2：绘制热力图，标注3个关键信号
- 步骤3：基于Cohort写出"产品变好还是变差"的判断及证据

📊 业务场景

- 场景2：总体留存率没变→Cohort显示老用户越来越差但新用户越来越好在相互抵消

### 第6周 · 周三：漏斗分析——找到最大的转化机会

📘 核心概念与第一性原理
- 漏斗的本质：用户从A到B的路径中，每一步都在经历"筛选"。漏斗分析就是量化每一步筛选的"漏出率"，找到改善ROI最高的那一步。
- 最大绝对值损失 vs 最大相对下降：前者告诉你"补哪个洞最多水"，后者告诉你"哪个环节最弱"——两个角度都要看。

🧩 知识点拆解（5个子知识点）
1. 漏斗的构建——定义步骤、确保步骤覆盖所有路径
2. 诊断方法——最大绝对值损失(补最大的洞) + 最大相对下降(修最弱的环节)
3. 分群漏斗——按渠道/设备/新老用户分群对比
4. 时间窗口漏斗——漏斗步骤之间的合理时间窗口设定
5. 漏斗分析的陷阱——某渠道转化率低但体量大，优化它更值

💻 动手练习
- 步骤0：构建5步电商漏斗（浏览→加购→下单→支付→完成）
- 步骤1：计算每步转化率+整体转化率
- 步骤2：按渠道分群，找出各渠道最需要优化的环节
- 步骤3：给出优化建议——优先修哪个环节，为什么？

### 第6周 · 周四：留存分析与LTV——留存是结果不是原因

3. 留存下降的根因拆解——供应不足/价格不优/体验不好/竞品干扰
4. LTV简单估算——ARPU×平均生命周期
5. LTV的高级估算——Pareto/NBD模型的概念
6. LTV vs CAC——渠道预算分配决策的核心依据

### 第7周 · 周一：因果推断基础——相关≠因果，反事实框架

📘 核心概念与第一性原理
- 因果 vs 相关的根本区别：相关是"A和B一起变化"，因果是"如果改变A，B会怎样变化"。因果需要假设其他条件不变（ceteris paribus）——这正是反事实框架的核心。
- 反事实框架：你永远无法同时看到同一个人"吃了药"和"没吃药"两种状态。因果推断就是构建"如果没吃药会怎样"这个不可能被观察到的反事实。
- 随机实验为什么是黄金标准：随机化让两组在所有混杂因子上趋于平衡→唯一系统差异=处理本身→差异可归因于因果。

🧩 知识点拆解（6个子知识点）
1. 相关≠因果的三个典型例子——冰淇淋与溺水/鞋子尺码与阅读能力/雨伞与车祸
2. 反事实框架——Rubin Causal Model, 个体处理效应 vs 平均处理效应(ATE)
3. 混杂因子的三种结构——Confounding/Collider/Mediator
4. 选择偏差(Selection Bias)——处理组和对照组不是随机分配的
5. 方法选择决策树——AB实验 → PSM → DID → PSM-DID → 合成控制法
6. 因果推断的局限——永远只是推断，不是证明

### 第7周 · 周二：DID原理——减去时间趋势的智慧

📘 核心概念与第一性原理
- DID(Difference-in-Differences)的直觉：处理组有"处理效应+时间趋势"，对照组只有"时间趋势"。处理组变化-对照组变化=净处理效应。两次差分就消掉了时间趋势和组间固有差异。
- 平行趋势假设——DID的灵魂：假设如果没有处理，处理组和对照组的变化趋势是平行的。这个假设不可检验（因为反事实不可见），但可以用事件研究法检验"处理前的趋势是否平行"。

🧩 知识点拆解（6个子知识点）
1. DID的2×2表格——(T1-T0) - (C1-C0) = 处理效应
2. 回归方程形式——Y=β₀+β₁Treated+β₂Post+β₃Treated×Post，β₃=ATT
3. 平行趋势假设——最关键的前提假设及其含义
4. 事件研究法(Event Study)——处理前的趋势是否平行
5. DID的适用场景——新政策/新功能/新渠道的评估
6. DID的公式推导——理解两次差分消掉的是什么

💻 动手练习

- 步骤3：画出DID的三条线（处理组/对照组/反事实），可视化DID原理

📊 业务场景

### 第7周 · 周四：PSM原理——"找个长得像的人"

📘 核心概念与第一性原理
- PSM(Propensity Score Matching)的直觉：在非随机实验中，处理组和对照组在很多特征上不相等。PSM通过倾向得分（进入处理组的概率）匹配出特征相似的对照组。
- PSM的核心假设是CIA(Conditional Independence Assumption)：在控制了观测到的协变量后，处理组的分配与潜在结果独立。换句话说——你没有遗漏重要的混杂因素。

🧩 知识点拆解（5个子知识点）
1. 倾向得分的定义——给定协变量，个体进入处理组的概率P(T=1|X)
2. Logistic回归估计倾向得分
3. 匹配方法——最近邻匹配/卡尺匹配/核匹配各自的特点
4. CIA假设——给定X，处理和结果独立（关键但不可检验）
5. PSM的局限——不能解决不可观测的混杂

💻 动手练习
- 步骤0：生成有选择偏差的数据（处理组的协变量不同于对照组）
- 步骤1：Logistic回归估计倾向得分
- 步骤2：实现最近邻匹配（1:1无放回）
- 步骤3：可视化匹配前后的协变量分布对比

- 场景2：PSM的结果说VIP效果+15%→但如果有你没观测到的变量（比如收入）→结果不可靠→这就是CIA假设的局限

### 第7周 · 周五：PSM实现与检验——平衡性是最重要的检验

📘 核心概念与第一性原理
- 平衡性检验的直觉：匹配后（不是匹配前），处理组和对照组在所有协变量上应该"长得像"。SMD(Standardized Mean Difference)<0.1是经验标准。
- 如果某些变量SMD仍然>0.1→匹配不够好→尝试不同的匹配方法或增加协变量。

🧩 知识点拆解（4个子知识点）

### 第8周 · 周一：工具变量IV——解决内生性的经济学方法

📘 核心概念与第一性原理
- IV的三条件：①与内生变量相关(Relevance) ②只通过内生变量影响结果(Exclusion) ③与其他混杂因素无关(Exogeneity)。缺任何一个，IV就不成立。
- 2SLS(两阶段最小二乘)：第一阶段用IV预测内生变量→第二阶段用预测值估计因果效应。

🧩 知识点拆解（4个子知识点）
1. 内生性的来源——遗漏变量/测量误差/反向因果
2. IV的三个条件——相关性/外生性/排他性
3. 2SLS的原理和实现——第一阶段+F检验(F>10)→第二阶段
4. 弱工具变量问题——弱IV比OLS更危险

💻 动手练习
- 步骤0：生成有内生性的数据
- 步骤1：普通OLS→估计有偏
- 步骤2：找工具变量→2SLS→对比OLS偏差
- 步骤3：弱IV的演示——F=3时2SLS的偏差比OLS还大

📊 业务场景
- 案例：广告投放对GMV的影响——广告投放有内生性（高GMV的地区投放多），用"广告预算"做IV

✅ 分级检验

### 第9周 · 周一：5种归因模型——渠道效果的广告归因

### 第9周 · 周三：商业分析案例——定价与补贴的ROI分析

3. 补贴的长期效应——补贴用户后续的留存和消费
4. 预算分配决策——多场景下的ROI排序和资源优化

### 第9周 · 周六：从0到1数据驱动——新业务冷启动的数据支持

📘 核心概念与第一性原理
- 新业务冷启动的数据困境：没有历史数据、用户少、波动大。常规分析方法（统计检验/AB实验）在这不适用。
- 解决方案：定性+定量混合、快速迭代、用代理指标(North Star Proxy)、寻找早期信号而不是证明。

🧩 知识点拆解（4个子知识点）
1. 冷启动的数据困境——没有历史/样本少/波动大
2. 代理指标的使用——短期内用中间行为预测长期留存
3. 定性+定量混合——用户访谈+小样本数据的结合
4. 快速迭代的数据闭环——从分析到策略到验证的缩短周期

💻 动手练习

📊 业务场景

✅ 分级检验

- 中级：能为新业务选合适的代理指标
- 高级：能设计冷启动的完整数据支持方案

### 第9周 · 周日：数据治理与数据质量——"垃圾进垃圾出"

📘 核心概念与第一性原理
- 数据治理的本质：确保数据是可信的、一致的、可用的。如果分析师用了错误的数据得出了结论→比没有结论更糟糕。
- 数据质量的六个维度：完整性(Completeness)、准确性(Accuracy)、一致性(Consistency)、时效性(Timeliness)、唯一性(Uniqueness)、有效性(Validity)。

🧩 知识点拆解（4个子知识点）
1. 数据质量六维度——完整/准确/一致/时效/唯一/有效
2. 数据血缘(Data Lineage)——数据从哪来，经过了什么变换
3. 数据质量监控——自动化的质量检测报警
4. 数据治理的组织保障——谁来负责数据质量

💻 动手练习

### 第10周 · 周一：业务面试篇一 —— 异动归因类问题的回答框架

📘 核心概念与第一性原理
- 面试中的异动归因不是考你SQL写得有多快，而是考你能否在高压下展示结构化思维。标准框架：①确认异动范围(时间+地域+用户群) → ②MECE拆解 → ③逐个排除 → ④给出结论。

🧩 知识点拆解（3个子知识点）
1. 异动归因回答模板——范围→拆解→排除→结论
2. 常见异动归因题的变体——GMV下降/留存下降/DAU波动
3. 容易踩的坑——只描述数据不给原因、只给原因不了了责任

💻 练习
- 面试官问"Q3日活下降了20%，你觉得可能的原因是什么？"
- 录音自己回答→修改→再录音→直到结构清晰

✅ 检验标准："范围→拆解→排除→结论"四步框架烂熟于心

---

### 第10周 · 周二：业务面试篇二 —— 项目深挖与STAR法则

📘 核心概念与第一性原理
- STAR法则：Situation(背景) + Task(任务) + Action(行动) + Result(结果)。面试官想通过你的项目经历判断你在真实工作环境中的能力水平。
- Result必须有量化数字："降低了成本"→"月度成本降低了15%，约等于节省了200万/年"。

🧩 知识点拆解（3个子知识点）
1. STAR法则的四个要素和常见错误
2. 如何准备3个"招牌项目"——一个SQL深度的/一个业务价值的/一个技术创新的
3. 项目讲述的时间控制——3分钟内讲清楚一个项目

💻 练习
- 准备3个招牌项目，每个用STAR法则写出来（每个≤200字）
- 录音讲述，控制在3分钟内

✅ 检验标准：每个项目都有量化数字、有业务价值、有个人贡献

### 第10周 · 周三：技术面试篇 —— SQL + 统计 + AB实验考点

📘 核心概念与第一性原理

🧩 知识点拆解（3个子知识点）
1. SQL考点——留存/连续登录/TopN/漏斗/窗口函数（必须秒做）
2. 统计考点——p值解读/置信区间/假设检验选择/样本量计算
3. AB实验考点——实验设计/样本量/MDE/Peeking/多重检验/避坑

💻 限时训练

✅ 检验标准：SQL-秒做、统计-能解释给非技术人员听、AB-能从设计讲到最后决策

### 第10周 · 周四：简历打磨——从「做了什么」到「创造了什么价值」

📘 核心概念与第一性原理
- 简历的黄金法则：描述结果而非描述过程。"用Python做了用户画像分析"→"通过RFM用户分群，帮助运营部门提升沉睡用户召回率15%"。
- 每个bullet point都应包含：做了什么 + 用了什么方法/工具 + 带来了什么量化结果。

🧩 知识点拆解（3个子知识点）
1. 简历的结构——个人信息/自我总结/工作经历/项目经历/技能
2. 量化结果的写法——用数字说话（不是"提升了效率"而是"节省了5小时/周"）
3. 自检清单——每个bullet point都能量化吗？

💻 练习
- 重写你的简历，确保每个bullet point都有量化数字
- 从源笔记中找出3个最有价值的项目写到简历中

✅ 检验标准：每个项目描述都能量化、能回答"你在这个项目中的独立贡献是什么"
