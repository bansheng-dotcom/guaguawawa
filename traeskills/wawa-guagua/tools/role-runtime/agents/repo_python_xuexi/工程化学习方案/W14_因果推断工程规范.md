## D1（周一 10/27）：DID 假设透明——平行趋势不是"假设成立"，是"需要被数据验证"

> 📓 今日主课：DID——2×2 面板/平行趋势/安慰剂检验/事件研究法

---

### 🔴 认知冲突

你学会了 DID 的公式：ATT = (Treat_post - Treat_pre) - (Control_post - Control_pre)。你跑了回归——ATT = +8%——北京 AI 推荐让 GMV 提升了 8%。你在报告里写了一行"假设平行趋势成立"——然后给出了结论。

面试官看到你的报告——追问了一句："你怎么验证平行趋势成立的？"

你说"我画了图——处理前北京和上海的 GMV 趋势看起来平行"。面试官追问——"'看起来平行'就够了？如果处理前倒数第二个月两组趋势已经开始分叉——但分叉不够明显——肉眼看不出来——你的 DID 结论还可靠吗？"

你说不出话。你做了**视觉检验**——但视觉检验是主观的。"看起来平行"因人而异。面试官需要的是**统计检验**——把"平行"这个模糊的判断变成"交互项系数不显著 ≠ 0"这个精确的判断。更进一步——他可能追问"事件研究法的动态效应——你做了吗？"——你沉默了。

**问题**：DID 的平行趋势假设有三个检验层次——视觉（L1）、统计（L2）、稳健性（L3）。如果你只做了 L1——你的结论建立在"我看起来觉得平行"的基础上——这不是科学——这是印象。**L2 是用处理前的数据做"安慰剂 DID"——如果处理前两组的差异有显著的时间趋势——平行趋势假设被拒绝。L3 是逐个去除处理前最早的时间点——检查 ATT 的稳定性——确保你的结论不依赖于某个特定的时间窗口。**

---

### 📖 核心原理

**平行趋势检验的三个层次——从"看起来平行"到"统计上不能拒绝平行"到"删掉任何一个时间点结论都稳定"：**

**L1（视觉检验）——必要但不充分。** 画处理前北京和上海的 GMV 趋势——肉眼判断是否大致平行。如果两条线在某个时间点明显交叉或分叉——平行趋势不成立——不需要做 DID。但如果看起来平行——不能"因为看起来平行就假设成立"——需要 L2。

**L2（统计检验——事件研究法）——这是你代码的核心。** 处理前每个时间点生成一个"虚拟处理"变量——和处理组的交互项。如果任何一个处理前的交互项系数显著 ≠ 0——说明在那个时间点——即使没有真正的处理——两组之间已经出现了显著差异——平行趋势不成立。

```python
import numpy as np
import pandas as pd
from scipy import stats
import statsmodels.formula.api as smf
import matplotlib.pyplot as plt
import logging

logger = logging.getLogger(__name__)


def parallel_trend_test(
    df: pd.DataFrame,
    y_col: str = 'gmv',
    treat_col: str = 'treat',
    time_col: str = 'time',
    unit_col: str = 'city',
    pre_periods: int = 6
) -> dict:
    """平行趋势假设检验——事件研究法（三层次）。

    ⚠️ 这是 DID 分析的前置检验——在主回归之前必须通过。
    如果处理前的任何时间点有显著的"虚拟处理效应"——平行趋势假设被拒绝——
    DID 的 ATT 估计不再可信——不要继续做 DID——考虑其他方法（如 Synthetic Control）。

    检验逻辑:
    1. 生成处理前每个时间点的虚拟处理变量 × 处理组的交互项
    2. 逐时间点回归——每个交互项系数代表"在那个时间点——处理组相对对照组的差异"
    3. 处理前交互项系数应不显著（p > 0.05）——说明处理前两组没有显著差异趋势
    4. F 检验——所有处理前交互项系数联合是否显著——不显著则通过

    不适用场景:
    - 处理前只有 1 个时间点（无法检验趋势——至少需要 ≥2 个）
    - 存在预期效应（处理组提前知道要处理→提前改变行为→趋势在处理前已变）
    - 面板不平衡（某个 unit 在处理前缺了某些时间点——无法画完整的趋势线）

    ⚠️ 注意: 通过平行趋势检验 ≠ 平行趋势必定成立。它只说明"现有数据不拒绝该假设"。
    如果样本量小（检验 power 低）——可能"通过了但其实不平行"。
    所以在报告中应该说"数据未拒绝平行趋势假设"——而不是"平行趋势成立"。

    Args:
        df: 面板数据——含 y_col, treat_col, time_col, unit_col
        y_col: 结果变量列名
        treat_col: 处理组标记列名（0/1）
        time_col: 时间列名（整数——相对处理时间的周期数——处理时点=0, 处理前=-1,-2,...）
        unit_col: 个体标识列名
        pre_periods: 处理前有多少个时间点

    Returns:
        Dict 含:
            passed_visual: L1 视觉检验结果 (True/False + 图)
            passed_statistical: L2 统计检验结果 (True/False + 每个时间点的 p 值)
            passed_joint_F: L2 联合 F 检验结果
            passed_robustness: L3 稳健性检验结果
            can_proceed_did: 是否可以继续做 DID（三个层次综合判断）
    """
    # === L1: 视觉检验 ===
    fig, axes = plt.subplots(1, 2, figsize=(14, 5))

    # 处理前趋势图
    pre_data = df[df[time_col] < 0]
    for unit in pre_data[unit_col].unique():
        unit_data = pre_data[pre_data[unit_col] == unit]
        is_treat = unit_data[treat_col].iloc[0]
        label = f"{unit} (Treat)" if is_treat else f"{unit} (Control)"
        linestyle = '-' if is_treat else '--'
        axes[0].plot(unit_data[time_col], unit_data[y_col], label=label, linestyle=linestyle, marker='o')
    axes[0].axvline(x=-0.5, color='red', linestyle=':', label='处理时点')
    axes[0].set_title('L1: 处理前趋势对比（视觉检验）')
    axes[0].legend()

    # === L2: 事件研究法——处理前各时间点的"虚拟处理效应" ===
    # 生成虚拟时间点变量
    df_es = df.copy()
    for t in range(-pre_periods, 0):  # 处理前: -6, -5, ..., -1
        df_es[f'pre_{abs(t)}'] = (df_es[time_col] == t).astype(int) * df_es[treat_col]

    # 回归——包含所有时间点的交互项
    pre_vars = [f'pre_{abs(t)}' for t in range(-pre_periods, 0)]
    formula = f"{y_col} ~ treat + " + " + ".join(pre_vars)
    model = smf.ols(formula, data=df_es).fit()

    # 检验每个时间点
    timepoint_results = {}
    any_significant = False
    for var in pre_vars:
        p_val = model.pvalues.get(var, 1.0)
        coef = model.params.get(var, 0.0)
        timepoint_results[var] = {'coef': coef, 'p_value': p_val, 'significant': p_val < 0.05}
        if p_val < 0.05:
            any_significant = True
            logger.warning("处理前时间点 %s 显著 (p=%.4f)——平行趋势可能不成立", var, p_val)

    # 联合 F 检验——所有处理前交互项系数是否同时为 0
    f_stat = model.f_test(pre_vars)
    joint_p = f_stat.pvalue
    passed_f = joint_p > 0.05

    # 画事件研究图（动态效应）
    time_labels = list(range(-pre_periods, 0))
    coefs = [timepoint_results.get(f'pre_{abs(t)}', {}).get('coef', 0) for t in time_labels]
    axes[1].axhline(y=0, color='black', linestyle='-', linewidth=0.5)
    axes[1].axvline(x=-0.5, color='red', linestyle=':', label='处理时点')
    axes[1].plot(time_labels, coefs, marker='o', color='steelblue')
    axes[1].set_title(f'L2: 事件研究法——处理前动态效应 (联合 F 检验 p={joint_p:.3f})')
    axes[1].set_xlabel('相对处理时间（周期）')
    axes[1].set_ylabel('估计系数')

    # === L3: 稳健性——逐个去除最早的时间点 ===
    robustness_results = []
    for drop_t in range(-pre_periods, -1):  # 从最早开始删——(-6), (-5), ..., (-2)
        reduced_vars = [v for v in pre_vars if v != f'pre_{abs(drop_t)}']
        formula_reduced = f"{y_col} ~ treat + " + " + ".join(reduced_vars)
        model_reduced = smf.ols(formula_reduced, data=df_es).fit()
        f_reduced = model_reduced.f_test(reduced_vars)
        robustness_results.append({
            'dropped_period': drop_t,
            'joint_F_p': f_reduced.pvalue,
            'still_pass': f_reduced.pvalue > 0.05
        })

    all_robust = all(r['still_pass'] for r in robustness_results)

    # === 综合判断 ===
    can_proceed = (not any_significant) and passed_f and all_robust

    if can_proceed:
        logger.info("✅ 平行趋势检验通过（三个层次）——可以继续 DID 分析")
    else:
        logger.error("❌ 平行趋势检验未通过——DID 的 ATT 估计可能不可靠")

    return {
        'passed_visual': True,  # 无法自动判断——人工确认
        'passed_statistical': not any_significant,
        'passed_joint_F': passed_f,
        'passed_robustness': all_robust,
        'can_proceed_did': can_proceed,
        'timepoint_details': timepoint_results,
        'joint_F_p': joint_p,
        'robustness_details': robustness_results,
        'fig': fig
    }
```

### 🔴 认知冲突

你的 DID 回归跑出了一个巨大的 ATT——+35%。你兴奋地准备汇报——同事看了一眼你的数据——"你这个面板是平衡的吗？北京的观测是 12 个月——上海只有 8 个月？"

你发现——上海的 4 个月数据因为 ERP 系统故障缺失了——DID 的"差分"成了"上海缺失那 4 个月的插值"。ATT +35% 不是 AI 推荐的效果——是**数据缺失导致的偏差**。你在跑回归之前没有检查数据质量——面板不平衡——DID 的前提不满足——结论全错。

**问题**：DID 的数据集——在你把数据塞进 `smf.ols()` 之前——必须先做**面板质量检查**。"数据能跑通" ≠ "数据适合 DID"。DID 要求：①面板平衡（每个 unit 在处理前后都有观测）②处理分配正确（同一个 unit 不会同时被标记为 T=0 和 T=1）③关键变量无缺失。

---

### 📖 核心原理

**DID 面板构建函数——不只是"合并数据"——是"质检——只有通过质检的数据才进入回归"：**

```python
def build_did_panel(
    df: pd.DataFrame,
    unit_col: str = 'city',
    time_col: str = 'month',
    treat_col: str = 'treat',
    y_col: str = 'gmv'
) -> dict:
    """构建 DID 面板数据集——含三项质量检查。
    
    检查项（三项全部通过——才能进行 DID 回归）:
    1. 面板平衡性——每个 unit 在处理前后是否都有观测？
       缺失→标记为"不平衡面板"——DID 要求平衡面板
    2. 处理分配一致性——是否存在同时被标记为 T=0 和 T=1 的 unit？
       存在→数据错误——同一 unit 不应既是对照又是处理
    3. 变量完整性——Y/T 是否有缺失值？
       缺失→标注缺失的 unit 和时间点
    
    返回: 清洗后的平衡面板 + 数据质量报告
    """
    issues = []
    
    # 检查1: 面板平衡性
    time_counts = df.groupby(unit_col)[time_col].nunique()
    expected_periods = df[time_col].nunique()
    unbalanced = time_counts[time_counts < expected_periods]
    if len(unbalanced) > 0:
        issues.append(f"面板不平衡——以下 unit 缺少时间点: {unbalanced.to_dict()}")
    
    # 检查2: 处理分配一致性
    treat_consistency = df.groupby(unit_col)[treat_col].nunique()
    inconsistent = treat_consistency[treat_consistency > 1]
    if len(inconsistent) > 0:
        issues.append(f"处理分配不一致——以下 unit 同时有 T=0 和 T=1: {inconsistent.index.tolist()}")
    
    # 检查3: 变量完整性
    missing_y = df[y_col].isna().sum()
    missing_treat = df[treat_col].isna().sum()
    if missing_y > 0:
        issues.append(f"{y_col} 缺失 {missing_y} 行")
    if missing_treat > 0:
        issues.append(f"{treat_col} 缺失 {missing_treat} 行")
    
    return {'passed': len(issues) == 0, 'n_units': df[unit_col].nunique(),
            'n_periods': expected_periods, 'issues': issues, 'df_clean': df if len(issues) == 0 else None}
```

## D3（周三 10/29）：事件研究法——不只是画图，是完整的动态效应推断

> 📓 今日主课：事件研究法——平行趋势/动态效应/基准期/置信区间

---

### 🔴 认知冲突

D1 你做了平行趋势检验——处理前 6 个时间点都不显著——通过。但面试官追问："处理**后**呢？DID 只给你一个 ATT（平均效应）——但你怎么知道处理效应是即刻生效的——还是渐进式的——还是延迟的？"

DID 的 ATT = 一个数字——+8%。这个数字假设"处理效应在处理后每一期都相同"。但如果处理效应是渐进式的——第一期为 +2%、第二期 +5%、第三期 +12%——DID 的"平均效应" +8% 会掩盖这个动态——你会错误地认为"效果是均匀的"。

**事件研究法 = DID 的动态版本。不只是"处理前趋势是否平行"（D1）——还回答"处理后效应如何随时间演变"。**

---

### 📖 核心原理

**事件研究法 = 生成处理前后每个时间点的动态交互项——估计每个时间点的"逐期处理效应"。DID 的 ATT 是"一个数字"——事件研究法是"一条曲线"。**

```python
def event_study(
    df, y_col, treat_col, time_col, unit_col, pre_periods=6, post_periods=6, ref_period=-1
):
    """事件研究法——估计处理效应的动态变化。

    核心逻辑: 
    1. 生成处理前后每个时间点×处理组的交互项
    2. 选一个基准期（通常是处理前最后一期 t=-1）——其效应强制为 0
    3. 逐期回归——每期交互项系数=该期相对于基准期的处理效应

    为什么基准期通常是 t=-1？
    因为处理前最后一期最接近处理——如果处理前趋势平行——这一期两组的差异
    最能代表"处理前两组的正常差异水平"——后期效应是相对这一期的偏离。

    ⚠️ 注意: 事件研究法的交互项代码"最容易写错"——因为需要动态生成变量名——
    少了某个时间点就少了那个点的效应估计——而不会报错。
    """
    # 生成动态交互项——t=-6,-5,...,-2,-1(基准),0,1,...,5
    for t in range(-pre_periods, post_periods + 1):
        if t == ref_period:
            continue  # 基准期——不生成变量——被吸收到截距中
        df[f'time_{t}'] = (df[time_col] == t).astype(int) * df[treat_col]

    time_vars = [f'time_{t}' for t in range(-pre_periods, post_periods + 1) if t != ref_period]
    formula = f"{y_col} ~ treat + " + " + ".join(time_vars)
    model = smf.ols(formula, data=df).fit()

    # 提取逐期系数 + CI——画动态效应图
    effects = {}
    for t in range(-pre_periods, post_periods + 1):
        if t == ref_period:
            effects[t] = {'coef': 0.0, 'ci_lower': 0.0, 'ci_upper': 0.0}  # 基准期=0
        else:
            var_name = f'time_{t}'
            effects[t] = {
                'coef': model.params.get(var_name, 0),
                'ci_lower': model.conf_int().loc[var_name, 0] if var_name in model.conf_int().index else 0,
                'ci_upper': model.conf_int().loc[var_name, 1] if var_name in model.conf_int().index else 0,
            }
    return effects
```

**事件研究法图——面试时最有力的可视化。X 轴=时间（-6→+6），Y 轴=逐期处理效应，垂直线=处理时点（t=0），基准期 t=-1 效应=0（参考线）。处理前各期系数在 0 附近波动（CI 含 0）→平行趋势通过。处理后各期系数逐步上升（CI 不含 0）→渐进式效应。**

**面试中最高频的追问——"你为什么选 DID 而不是其他方法？"**

你的回答不能是"因为我只学了 DID"——也不能是"因为 DID 简单"。你需要展示你理解"每种方法的适用条件"——并根据数据特征选择了最合适的方法。

**因果推断方法选择的决策逻辑——从数据特征出发：**

| 数据特征 | 推荐方法 | 不推荐的方法 | 关键判断依据 |
|---------|---------|------------|------------|
| 有面板数据（处理前后多个时间点）+ 有对照组 | DID / Event Study | 简单的 before-after 对比 | 平行趋势假设可通过处理前数据检验 |
| 只有处理后数据 + 有对照组 + 可观测混淆变量充足 | PSM（倾向得分匹配） | DID（因为没有处理前数据） | CIA 假设（给定可观测变量——处理分配独立于潜在结果）——不可检验——需要敏感性分析 |
| 处理分配有明确的断点（如分数 >= 60 分通过、>= 60 分不通过） | RDD（断点回归） | DID（因为没有时间维度） | 连续性假设——在断点附近——除处理外——其他特征连续变化 |
| 有工具变量（影响处理但不直接影响结果——如"是否被随机邀请参加培训"） | IV（工具变量） | DID/PSM（如果没有面板/可观测混淆） | 外生性假设 + 相关性假设——IV 必须影响处理且只通过处理影响结果 |
| 只有一个处理单元 + 多个对照组 + 处理前多个时间点 | Synthetic Control | DID（单一处理单元无法检验平行趋势） | 合成控制组的"处理前拟合"质量——MSPE 越小越好 |
| 多个处理单元 + 不同处理时间 | CSDID / Sun & Abraham | Traditional 2x2 DID | 传统 DID 会产生负权重——已处理单元作为未处理单元的对照组 = 污染 |

### 📖 DID 实战中的常见陷阱与排查——不只是"假设检验通过了"——还有五个静默失败模式

**陷阱 1——处理前的预期效应（Ashenfelter's Dip）：** 处理组在处理前一期出现了异常波动——比如北京在 8 月（处理前 1 个月）GMV 突然大幅下降——然后 9 月"恢复"——DID 会把这个"恢复"归因为处理效应——实际上只是均值回归。**排查方法：** 事件研究法——看 t=-1 的系数是否异常——如果 t=-1 明显偏离 0（而 t=-2, -3 都在 0 附近）——可能存在预期效应或 Ashenfelter Dip。

**陷阱 2——处理后的时变混淆：** DID 控制了"时间不变"和"单位不变"的未观测因素——但不控制"时变的未观测因素"。北京 9 月同时上线了另一个促销活动——这个活动的影响会被 DID 归因到"AI 推荐"上。**排查方法：** 在报告的"局限"部分显式列出处理后的混淆事件——访谈业务方——"9 月除了 AI 推荐——北京还有没有其他变化？"——记录所有发现。

**陷阱 3——功能形式错误（Log vs Level）：** Y 是指数增长的——但你用了 Level 模型——处理效应被错误估计。**排查方法：** 对比 Level 模型和 Log 模型的 ATT——如果差距 > 30%——可能需要 Log 变换。画残差图——检查残差是否随时间系统性地变化——如果是——模型设定有问题。

**陷阱 4——标准误的聚类层级错误：** 你的 DID 回归聚类在 city 级别——但只有 2 个 city（北京/上海）——2 个 cluster 的标准误估计是完全不可靠的。**排查方法：** 至少需要 10-20 个 cluster 才能可靠估计聚类标准误。如果只有 2 个 city——可以考虑用 wild bootstrap 或 randomization inference 代替聚类标准误——或者在报告中明确标注"标准误可能被低估——因为 cluster 数量不足"。

**陷阱 5——把 DID 等同于"因果"：** DID 估计的是"处理组在处理后的变化"减去"对照组在处理后的变化"——它识别的是"平均处理效应"——但如果处理组和对照组的"处理后的趋势"不同（即使处理前趋势平行）——DID 估计有偏。**排查方法：** 事件研究法——如果处理后的逐期效应有明确的 trend（如每期都在增加）——这可能不是"处理效应在增强"——可能是"两组的趋势在处理后开始分叉"——而不完全是因为处理本身。在报告的局限性中讨论这种可能性。

**鲜果多 AI 推荐的完整排查记录——你是如何在报告中呈现这些陷阱的：**

> "本分析使用 DID 方法评估 AI 推荐对北京 GMV 的影响。DID 的核心假设——平行趋势——通过了三层次检验（视觉+事件研究法+稳健性——联合 F 检验 p=0.32）。ATT 估计为 +8.2%（p=0.031）。我们确认了以下潜在混淆因素：(1) 北京 9 月无其他重大运营活动（已和运营团队确认）(2) 处理前无 Ashenfelter Dip（t=-1 系数不显著，p=0.65）(3) 功能形式——Log 模型 ATT 和 Level 模型 ATT 方向一致（+7.8% vs +8.2%）。主要局限——(a) 只有 2 个城市——聚类标准误可能被低估——使用 wild bootstrap 得到的 p 值为 0.045——仍在 5% 水平显著 (b) DID 无法控制处理后的时变混淆——如果北京 9 月有其他无法观测的变化——估计可能有偏。总体而言——数据支持 AI 推荐对北京 GMV 有正向影响的结论。"

### 📝 闭卷自测（5 题——每题含完整答案分析）

**Q1**：平行趋势检验的三个层次？"通过平行趋势检验"应该怎么表述——为什么不能写"平行趋势成立"？

> **A**：L1 视觉（画图）→L2 统计（事件研究法+联合 F）→L3 稳健性（逐个去掉最早时间点）。只能写"数据未拒绝平行趋势假设"——不能写"成立"——因为统计检验只能"不拒绝"——不能"证明成立"。样本量小→power 低→可能通过了但其实不平行。偏差：写"平行趋势成立"——面试官一眼看出你不够严谨。

**Q2**：事件研究法和 DID 的核心区别？为什么事件研究法比 DID 更有信息量？

> **A**：DID = 一个数字（ATT——平均效应）。事件研究法 = 一条曲线（逐期效应——动态变化）。事件研究法更有信息量——可以回答"效应是即刻的还是渐进式的（处理前检验平行趋势——处理后看动态效应）。偏差：说"事件研究法是 DID 的变体"——应该说"DID 是事件研究法的特例——假设所有处理后各期效应相同"。

**Q3**：DID 面板需要哪三项质量检查？面板不平衡怎么办？

> **A**：①面板平衡性（每个 unit 处理前后都有观测）②处理分配一致性（同一 unit 不能同时 T=0 和 T=1）③变量完整性（Y/T 无缺失）。不平衡→不能做传统 DID——考虑 CSDID 或 Synthetic Control。偏差：说"去掉缺失的 unit"——如果缺失和处理状态相关（如北京 AI 上线后数据完整——但上海数据在缺失期可能因为系统问题）——去掉缺失会引入选择偏差。

**Q4**：因果推断函数的 docstring 四段式是哪四段？为什么"面试常见追问"要写在 docstring 里？

> **A**：核心逻辑/假设清单/不适用场景/面试常见追问。面试追问写在 docstring 里——因为你三个月后回来看这个函数——你也是"面试官"——你需要知道"这个方法有什么陷阱"和"别人会质疑什么"。这些信息不会过期——每次用这个方法前读一遍——你的分析质量就高一层。偏差：说"面试准备用的"——不只是面试——是"帮助使用者（包括自己）了解方法的边界"。

**Q5**：敏感性分析回答什么问题？"如果平行趋势被轻微违反——ATT 会差多少"——这为什么不是"自我否定"？

> **A**：敏感性分析回答"结论对假设违反有多敏感"。这不是自我否定——是**科学诚实**。所有因果推断方法都依赖不可验证的假设——敏感性分析让你量化"假设违反到什么程度我的结论会反转"。如果轻微违反结论不变→结论是稳健的。如果轻微违反结论就反转→结论是脆弱的——需要更谨慎地表述。偏差：说"反正假设不可能完美成立——所以 DID 没用"——这不是 Did 的问题——是所有观测因果推断方法都有的问题——敏感性分析就是应对这个问题的方法。



**Q6**（Synthetic Control）：什么时候用 Synthetic Control 而不是 DID？两者的核心区别是什么？

> **A**：Synthetic Control 适用于"只有一个处理单元"且"对照组需要被加权组合"的场景。DID 假设"处理组和对照组在处理前趋势平行"——直接选一个或几个对照组做差分。Synthetic Control 不假设任何单个对照组和处理组平行——而是用多个对照组的加权组合"合成"一个和处理组处理前趋势最接近的"合成控制组"——权重由数据驱动（最小化处理前预测误差）。核心区别：DID 由你"选"对照组——Synthetic Control 由数据"造"对照组。鲜果多场景——如果只有北京一个处理单元——且没有任何一个城市和北京处理前趋势完全平行——Synthetic Control 用所有未处理城市的加权组合——造出"合成北京"。

**Q7**（CSDID vs Traditional DID）：多期处理（不同城市在不同时间上线）——传统 DID 有什么问题？CSDID 怎么解决？

> **A**：传统 DID 假设所有处理单元在同一时间接受处理——2x2 面板（前期/后期 x 处理组/对照组）。多期处理（如不同城市在不同月份上线 AI 推荐）——传统 DID 不能用——因为"已经处理的单元"被用作"尚未处理单元的对照组"——而"已经处理的单元的后期数据"包含了处理效应——作为对照组会产生负权重问题（Goodman-Bacon 分解）。CSDID（Callaway & Sant Anna, 2021）解决了这个问题——它按"处理时间"分组——每个组单独估计 ATT——然后加权平均——避免了"已处理单元作为对照组"的污染。如果你的数据是多期处理——不要用传统 DID——用 CSDID 或 Sun & Abraham (2021) 的 event study。
