# MVP 与实验验证工作流拓扑

## 1. 目标

把想法或需求转成最低成本验证计划，回答：

- 最容易让方案失败的假设是什么？
- 这次 MVP 到底验证什么？
- 不开发完整功能，怎样最快学到结果？
- 成功、失败、停止、转向标准是什么？

## 2. 拓扑图

```mermaid
flowchart TD
  A["输入: 想法 / 需求 / PRD草稿"] --> B["N1 明确目标与假设"]
  B --> C{"G1 承重假设是否清楚?"}
  C -- 否 --> C1["回 requirement-report 或只问 1 个关键问题"]
  C -- 是 --> D["N2 选择最低成本实验"]
  D --> E["N3 定义成功与 Kill 标准"]
  E --> F{"G2 是否真是 MVP?"}
  F -- 否 --> F1["删功能，保留验证动作"]
  F1 --> F
  F -- 是 --> G["N4 输出验证计划"]
```

## 3. 节点备注

| 节点 | 责任 | 输出 |
| --- | --- | --- |
| N1 明确目标与假设 | 找价值、可用性、可行性、商业性假设 | 假设地图 |
| N2 选择最低成本实验 | 在访谈、假门、原型、手工服务、小流量实验中取舍 | 实验方案 |
| N3 定义标准 | 写成功、失败、停止、转向 | 判定标准 |
| N4 输出计划 | 让用户能决定是否先验证 | MVP 验证报告 |
