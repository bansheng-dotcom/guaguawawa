# 文风拆解分类体系

## 一级分类

```text
文风
├─ 结论生成机制
├─ 论述组织机制
├─ 语言表达机制
├─ 段落节奏机制
└─ 认知风格机制
```

## 1. 结论生成机制

### 1.1 问题入口

- 现象入口：从一个数据变化、业务异常、用户行为进入。
- 误区入口：从常见错误理解进入。
- 场景入口：从真实工作场景进入。
- 目标入口：从业务目标、管理目标、资源约束进入。

### 1.2 判断路径

- 是否异常。
- 是否重要。
- 是否可干预。
- 是否能被当前证据支持。
- 是否需要继续下钻。

### 1.3 证据结构

- 数据证据。
- 业务证据。
- 经验判断。
- 案例证据。
- 反例证据。
- 模型或公式证据。

### 1.4 结论类型

- 事实型结论：发生了什么。
- 解释型结论：为什么发生。
- 取舍型结论：什么重要，什么不重要。
- 行动型结论：接下来做什么。
- 边界型结论：哪里不能用。

## 2. 论述组织机制

### 2.1 开篇方式

- 定义开篇。
- 问题开篇。
- 场景开篇。
- 误区开篇。
- 结论开篇。
- 系列回顾开篇。

### 2.2 推进结构

- 递进：一层一层拆。
- 对照：先讲常规理解，再讲作者判断。
- 反问：用问题推动读者思考。
- 案例：用具体场景承载抽象方法。
- 复盘：从结果回推过程。
- 清单：并列列出动作或因素。

### 2.3 收束方式

- 阶段性总结。
- 行动建议。
- 边界提醒。
- 下一步问题。
- 读者互动。

## 3. 语言表达机制

### 3.1 判断句

功能：给出立场、取舍、优先级。

识别方式：含“关键是”“真正的问题”“不是……而是……”“本质上”。

### 3.2 转折句

功能：推翻表层理解，把论述带到更深层。

识别方式：含“但是”“问题在于”“如果只……”“并不是”。

### 3.3 解释句

功能：把抽象概念翻译成读者能理解的场景。

识别方式：含“换句话说”“你可以理解为”“背后的含义”。

### 3.4 推进句

功能：从一层问题进入下一层问题。

识别方式：含“接下来”“再往下”“到这里”“继续看”。

### 3.5 边界句

功能：限定结论适用范围。

识别方式：含“不意味着”“解决不了”“不能理解成”“只适用于”。

## 4. 段落节奏机制

### 4.1 段落长度

- 短段：强调判断、转场、结论。
- 中段：解释一个概念或一个小推理。
- 长段：承载完整业务推理链。

### 4.2 段内结构

- 现象 -> 判断 -> 解释。
- 误区 -> 反驳 -> 正解。
- 指标 -> 场景 -> 动作。
- 结论 -> 证据 -> 边界。

### 4.3 句子节奏

- 长句承载复杂逻辑。
- 短句承担判断和停顿。
- 反问用于换层。
- 口语句用于降低理解成本。

## 5. 认知风格机制

### 5.1 问题观

作者认为问题来自哪里：数据波动、业务机制、组织协作、资源配置、用户行为、技术限制。

### 5.2 方法观

作者偏好什么解决方式：公式、拆解、案例、模型、经验、流程、产品化、管理动作。

### 5.3 读者观

作者如何预设读者：初学者、从业者、业务同学、管理者、面试者。

### 5.4 边界观

作者如何承认不确定性和方法限制。
