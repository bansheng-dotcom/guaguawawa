# 文风解析核心协议

## 目标

把输入文章拆成可复用的写作机制，而不是内容摘要。最终要回答：这个作者如何得出结论、如何让读者相信、如何推进段落、如何形成个人判断感。

## 总流程

```text
输入样本
-> 语料边界
-> 段落功能标注
-> 五大类机制拆解
-> 抽象规则
-> 下游 agent 输出契约
```

## 语料边界

先判断输入样本的稳定性：

- `single_sample`: 单篇文章，只能形成临时判断。
- `small_corpus`: 2-5 篇，可形成初版 profile。
- `stable_corpus`: 6 篇以上，且主题或作者一致，可形成稳定 profile。
- `mixed_corpus`: 多作者或多类型混杂，必须先分组再分析。

输出时标注置信度：

- `high`: 多篇文章反复出现的机制。
- `medium`: 多处出现但样本类型集中。
- `low`: 只在个别样本中出现。

## 段落功能标注

每个段落至少标一个功能：

- `problem_entry`: 提出问题、现象、矛盾。
- `misconception`: 指出常见误解或错误拆法。
- `judgment`: 给出作者判断。
- `evidence`: 给出数据、案例、经验、反例。
- `mechanism`: 解释问题背后的运行机制。
- `transition`: 从上一层问题推进到下一层。
- `action`: 给出建议、动作、看板、复盘、策略。
- `boundary`: 说明限制、例外、不适用范围。
- `summary`: 收束本段或全文。

## 五大类机制

### 1. 结论生成机制

分析结论是怎么得出来的：

- 从什么问题进入。
- 先排除了哪些错误理解。
- 用什么证据支撑判断。
- 哪些判断来自数据，哪些来自经验。
- 如何区分事实、推断、建议和边界。
- 结论是阶段性、取舍型、行动型还是边界型。

### 2. 论述组织机制

分析作者如何把推理讲出来：

- 开头先定义、先场景、先问题、先反驳还是先结论。
- 中间是递进、对照、反问、案例、公式、故事还是复盘。
- 转折通常发生在什么位置。
- 结尾是总结、行动、边界、下一问还是开放讨论。

### 3. 语言表达机制

分析常用表达的功能：

- 判断句：建立作者立场。
- 转折句：推翻表层理解。
- 解释句：把抽象概念翻译给读者。
- 推进句：把读者带到下一层问题。
- 边界句：防止过度外推。
- 口语句：降低理解门槛，但不能替代判断。

### 4. 段落节奏机制

分析文章的呼吸感：

- 单段平均长度。
- 长段和短段如何交替。
- 一段通常承载一个观点、一个推理链还是多个并列点。
- 关键判断是否单独成段。
- 段内常见顺序是“现象-解释-判断”还是“判断-原因-例子”。

### 5. 认知风格机制

分析作者看问题的方式：

- 反对什么低质量理解。
- 默认优先级是什么。
- 如何处理不确定性。
- 如何把知识转化为行动。
- 是否偏好系统视角、业务视角、读者视角或方法论视角。

## 规则抽象格式

每条规则用同一结构输出：

```yaml
name:
category:
confidence:
evidence:
mechanism:
writing_instruction:
review_check:
anti_pattern:
```

要求：

- `evidence` 可以是原文短句、文件位置或段落功能描述。
- `mechanism` 解释这条规则为什么成立。
- `writing_instruction` 告诉下游写作 agent 怎么用。
- `review_check` 告诉审稿 agent 怎么判断通过。
- `anti_pattern` 告诉改写 agent 要避免什么。
