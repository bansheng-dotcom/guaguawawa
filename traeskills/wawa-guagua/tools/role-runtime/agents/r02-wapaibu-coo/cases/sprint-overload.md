# SOP：冲刺容量过载与交付节拍回溯（R02 蛙排布）

## 1. 逻辑导图

```text
[异常/诉求输入] → [L1 数据与证据真实性] → [L2 维度下钻：交付周期溢出率]
                → [L3 外部锚点对齐] → [决策指令] → [护栏熔断] → [阶梯灰度]
```

## 2. 核心指标口径

| 指标 | 公式 | 单位 | 目标 | 告警 |
| :--- | :--- | :---: | :---: | :--- |
| 交付周期溢出率 | `(实际交付天数 − 计划天数) / 计划天数` | % | ≤ 10% | > 20% 触发全链路回溯 |
| 单人并发任务数 | `同一 owner 处于 running 的任务数` | 个 | ≤ 3 | > 3 强制委派或拆分 |

## 3. 分步诊断动作

1. 先看 WBS：kind 是否越界、step 是否断档，结构错直接退回。
2. 再看容量：加权负载 > 100% 先减负，不允许靠加班消化。
3. 拆大任务：> 8h 一律拆成 ≤8h 子任务，保证 Σ 恒等。
4. 排关键路径：浮动为 0 的任务优先锁资源。
5. 出交接包：owner / 产物 / 复现步骤 / 验收判据齐全才放行。

## 4. 门禁（不满足即阻断）

| 编号 | 触发条件 | 判定 | 处置 |
| :---: | :--- | :---: | :--- |
| G1 | WBS kind 越界或 step 断档 | BLOCKER | 拒绝排期，先修拆解 |
| G2 | 加权负载 > 100% | CRITICAL | 先减负再派工，不允许带病排期 |
| G3 | 任务 > 8h 未拆分 | CRITICAL | 按 Σ 恒等拆成 ≤8h 子任务 |

## 5. 归因路径

- **L1 数据层**：先排除脏数据、断流、重复计数，确认是真实异动。
- **L2 经营层**：按维度下钻，锁定贡献度 ≥70% 的因子（本角色主维度见 KPI 表）。
- **L3 商业层**：对齐外部锚点，区分内因外因；未接入外部数据时只声明口径，不虚构大盘数字。

## 6. 禁用词与反例

- ❌「大幅提升」「表现良好」「值得期待」等无数据锚定的形容词。
- ❌ 只给建议不给阈值；只给阈值不给回滚动作。
- ❌ 把历史个案当通用结论，不做样本量说明。
