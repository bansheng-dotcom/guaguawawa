# 优先级规则 · 订阅用量账单争议

## 判定顺序（不可跳步）

1. **账单恒等式 > 一切争议**
   `invoice.total == Σ(line_items.amount)`。不成立 → **BLOCKER**，先重建账单。
   理由：恒等式不成立时，讨论用量多少没有意义——账单本身不可信。

2. **口径枚举合法性 > 数值复算**
   `aggregation_type ∈ AGGREGATION_TYPES`、`charge_model ∈ CHARGE_MODELS`、`interval ∈ INTERVALS`。
   任一非法 → **BLOCKER**。口径非法时复算结果不可引用。
   特例：`custom_agg` 必须带 `custom_expression`，否则不可复现（H4）。

3. **用量记录合法性 > 客户主张**
   `metric_code` 非空且 `quantity ≥ 0`（H2）。记录非法 → 拒绝；记录合法 → 客户主张仅登记差异。

4. **模型决定复算方式**
   | charge_model | 复算方式 |
   |---|---|
   | standard | amount ≈ quantity × unit_amount |
   | graduated / volume | 按阶梯区间分段累加 |
   | package | ⌈quantity / package_size⌉ × unit_amount |
   | percentage | 基数 × 百分比 |
   | graduated_percentage | 按阶梯比例分段 |
   复算不吻合 → 标记为口径待澄清，**不是**直接判客户有理。

5. **差异只登记不裁决**
   客户主张与系统记录不一致 → 输出「待核对条目」＋抽样建议，**禁止** R14 直接调账。

## 冲突取舍

- **客户关系 vs 恒等式**：恒等式优先。哪怕客户是大客户，金额对不上先补正账单。
- **"赶紧改一下" vs 授权链**：任何调账、减免、退款都必须走人工授权，不得因催促跳过。
- **用量记录 vs 客户日志**：两者都是证据，R14 只做「记录了什么」的确定性陈述，不替任一方定罪。
- **多诉求并发**：客户同时要"调账 + 红冲发票 + 解释合同条款"时，R14 只处理用量核验与调账请求工件；红冲与合同解释移交 R03。

## 授权层级建议

| 差异占账单比 | 建议处置 |
|---|---|
| ≤ 5% | 登记差异，人工抽样核对后可小额调整 |
| 5%–20% | 必须提供事件明细抽样，业务负责人复核 |
| > 20% | 升级为账单争议，需完整事件明细导出 + 双人复核 |
| 恒等式不成立（任意比例） | 一律先重建账单，不进入争议流程 |

## 常见误判清单

- 用 `draft` 状态的账单和客户对账 → 错，draft 未定稿，尚可变更，对外呈现应用 finalized。
- 把 `custom_agg` 当成"系统自己会算"而不追问表达式 → 错，无表达式即不可复现。
- 把部分退款导致的 `partially_refunded` 当成"账单已结清" → 错，仍属已支付族。
- 客户主张差异就立刻按主张改数 → 错，属越权调账（unauthorized_exec）。
- 只报"差异 400 次"不给金额折算 → 不完整，必须给金额影响以便人工决策。
