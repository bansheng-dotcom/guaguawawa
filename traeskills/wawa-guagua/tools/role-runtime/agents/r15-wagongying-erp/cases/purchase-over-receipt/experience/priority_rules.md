# 优先级规则 · 采购超收争议

## 决策优先级（先满足前者）
1. **结构合法性 > 业务合理性**：状态越界 / 主体不匹配 / 行项目缺字段 → 直接 BLOCKER，不进入算术。
2. **授权先于执行**：任何「改库存 / 调历史账目 / 让步接收」必须先有 handoff 声明。
3. **账实可复算 > 账面好看**：入库增量必须与收货单数量一致，宁可慢也不可假平。
4. **边界先于帮助**：商业决策（是否接受超收）留给采购负责人；财务口径移交 R03。

## 冲突时的取舍
- 供应商说「补发损耗」但无书面授权 → 按无授权处理（授权未落字 = 无授权）。
- 超收比例极小（0.1%）但容差=0 → 仍拦截，但给出「一键申请容差豁免」的轻量路径。
- 收货单与 PO 供应商名不一致 → 主体不匹配，先拦后查，不默认合并。

## 红线（不可越）
- 不擅自改库存、不调整历史账目、不冲销历史凭证。
- 不擅自采购、不代付款。
- 凭据（api_key/secret/token/password/私钥）绝不出现在任何输出。
