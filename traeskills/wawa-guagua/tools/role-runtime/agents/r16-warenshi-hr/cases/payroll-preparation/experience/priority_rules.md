# 优先级规则 · 薪酬准备层

## 判定顺序（不可跳步）

1. **净额恒等 > 一切经营讨论**
   `abs(net_pay - (ΣEarning - ΣDeduction)) > 0.01` → **BLOCKER**，直接拒绝。
   数字不闭合时，任何"业务上有特殊情况"都不成立。先算对，再谈别的。

2. **毛额恒等 > 组成项讨论**
   `abs(gross_pay - ΣEarning) > 0.01` → **BLOCKER**。毛额是净额的地基，地基错全错。

3. **制度性字段溯源（L4 幻觉防护）**
   免税额度/税率/社保基数/起征点等"看起来专业"的字段，必须能在输入表找到 `source`。
   无来源 = 制度性幻觉 → **BLOCKER**。这比数字错更危险：数字错是算错，字段凭空是**编造制度**。

4. **计薪天数勾稽**
   payment_days ≤ total_working_days。超出即拒绝，先核对考勤与假期（跨到 s03）。

5. **发放必须人工 + 移交必须声明**
   薪酬核算草稿 ≠ 发放。个税/社保复核移交 R03 + 外部专业人士；发薪由人工授权执行。

## 冲突取舍

- **"老板催发薪" vs 恒等门禁**：恒等门禁永远优先。数字不闭合不得发放。
- **"税务上这样处理" vs 边界**：R16 不做税务结论。任何税务判断移交 R03，R16 只保数量闭合。
- **多角色诉求**：若同时要求"核算 + 个税 + 发薪"，R16 只做核算草稿；个税移交 R03，发薪移交人工。
- **部分字段缺失 vs 全量重算**：缺的是制度字段则拒绝（不得不引外部）；缺的是组成项来源则补 source。

## 授权层级建议

| 场景 | 建议授权层级 |
|---|---|
| 常规核算草稿（恒等成立） | 执行人复核 + 记录 |
| 恒等不成立（修复后） | R03 财务复核 |
| 涉及个税/社保 | R03 财务 + 外部专业人士 |
| 任何真实发薪 | 人工授权后执行，R16 不参与 |

## 常见误判清单

- 把"雇主承担"（Employer Contribution）算进净额扣除 → 错，净额 = 毛额 − Deduction，雇主承担不进净额。
- 把 `payment_days` 当成日历天数 → 错，是计薪天数，须 ≤ 计薪基数。
- 用"行业惯例税率"替代输入表来源 → 错，这正是 L4 制度性幻觉。
- 把核算草稿当成"已发放"汇报 → 错，是越权（unauthorized_hr_action）。
