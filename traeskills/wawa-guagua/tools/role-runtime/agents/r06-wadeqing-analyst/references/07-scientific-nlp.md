## 1. 根因下钻方法论 (Root Cause Investigation)

当业务指标发生重大异动时，切忌凭空臆测，必须严格执行多维度下探框架：

### 1.1 基线偏移验证与异动确权
- **动作**：不要一看到指标下跌就启动大规模下钻。第一步是排查数据管道（ETL延迟、Schema变更）及确认异动幅度是否超出正常方差。
- **算法规则**：
  - 计算滚动均值与标准差。若异动幅度在 $\pm 1.5$ 个标准差内，判定为“常规波动”（Noise），记录并归档；若超出，确认为“信号”（Signal）。
  - **业务阈值参考**：
    - 营收类：> 3% 且不可解释的偏差。
    - 留存/活跃类：> 5% 的周环比异动。
- **产出**：异动确权说明（Signal Confirmation）。

### 1.2 结构拆解与贡献度量化
- **动作**：将单一指标拆解为构成要素。例如，营收 = 流量 $\times$ 转化率 $\times$ 客单价。
- **算法规则（绝对贡献度公式）**：
  在多维度（如：地区、渠道、客群）累加型指标中，使用贡献度分析锁定核心驱动维度。
  $$\text{维度 } i \text{ 贡献度} = \frac{\text{当前期值 } V_{i,1} - \text{基期值 } V_{i,0}}{\text{总指标当前期值 } V_{\text{total},1} - \text{总指标基期值 } V_{\text{total},0}}$$
- **核心判定**：寻找**绝对变化量大且贡献占比极高**（如 > 40%）的维度，锁定为第一层驱动因子。
- **帕累托下钻**：遵循 80/20 原则，层层剥离（例如：先看地区，发现某区贡献了 80% 的跌幅；再看该区的操作系统，发现安卓端贡献了其中 90% 的跌幅）。
- **效应分解**：进一步将变动拆解为：
  - **量效应 (Volume effect)**：该维度用户基数的变化。
  - **率效应 (Rate effect)**：该维度人均指标/转化率的变化。
  - **结构效应 (Mix effect)**：该维度在总体中占比的变化。

### 1.3 假设检验与结论收敛
- **动作**：基于时间线（突发性阶跃 vs. 渐进式漂移）与业务日志（发布、大促、宕机），穷举潜在假设。
- **验证**：通过维度下探数据，证伪或证实假设（例如：若是前端 Bug，应集中在特定平台或版本；若是流量质量变差，应体现在特定渠道转化率暴跌）。
- **生成交付物**：必须包含：(1) 确诊根因及量化影响；(2) 支持性证据与被证伪的假设；(3) 行动建议（短期止血/长期预防）。

## 2. 科学计算与文本探索 (Scientific NLP)

在处理大量评论、工单、反馈等文本数据时，NLP 的核心目的是**支持业务决策，而非单纯堆砌语言学特征**。

### 2.1 统计学底盘与偏态控制 (SciPy 能力面)
- **动作**：在报告任何“平均词频”或“平均情感得分”前，必须进行分布形态诊断。
- **算法规则**：
  - 计算 Pearson 第二偏度系数：$3 \times (\text{均值} - \text{中位数}) / \text{标准差}$。
  - **阈值设定**：当 $|\text{偏度}| > 1$ 时，提示分布存在严重偏斜（如长尾分布或极端异常值）。
- **诚实纪律**：在此情况下，**严禁单独汇报均值**，必须同时呈现中位数（Median）、P5 和 P95 分位数，防止高管被均值误导。

### 2.2 文本特征提取与主题偏移 (spaCy / 文本降级能力面)
- **动作**：通过词频统计、N-gram 及实体抽取，将非结构化文本转化为结构化指标。
- **算法规则与业务界定**：
  - **核心词频与 Bigram**：提取高频词表与二元词组（如 "login failed", "price too high"），快速定位用户痛点集中区。
  - **类 Zipf rank1 占比**：计算排名第一的高频词在总词频中的占比。
    - **业务阈值**：若 rank1 占比 $> 0.3$，强烈提示（1）文本主题极度单一（可能遭遇水军或系统性刷单）；或（2）停用词清洗不彻底。
- **模型降级契约**：
  - `scinlp backend` 会探测底层库（spacy, scipy, statsmodels 等）可用性。
  - 当缺乏中文模型时，仅能使用空白/标点切分的简易策略，**此时必须在输出中显式标注：“警告：由于缺失本地 NLP 依赖，当前中文分词仅依赖启发式切分，存在语义截断风险。”** 杜绝假能力承诺。

## 3. 高管摘要与交付物结构指南 (Deliverable Blueprint)

所有经过根因下钻或 NLP 探索的产出，必须封装为高度结构化的高管记分卡（HTML Scorecard 或 Markdown 报告），结构如下：

1. **核心发现 (Executive Summary)**
   - 一句话结论：例如 “指标 X 环比下跌 Y%，其中 85% 由安卓端 V3.2 版本的结账流中断（率效应）所致。”
2. **异动时间线与确权 (Timeline & Signal)**
   - 说明异动的起始点，附带基线验证结果（排除自然波动的概率）。
3. **驱动因子量化拆解 (Driver Breakdown)**
   - 核心维度贡献度表格。
   - 必须拆分量效应（Volume）、率效应（Rate）与结构效应（Mix）。
4. **文本/用户声音佐证 (Voice of Customer / Text Signals)** *(如有 NLP)*
   - 列出在此期间突增的高频 Bigram 或主题偏移量。
5. **已证伪假设排雷 (Ruled-out Hypotheses)**
   - 罗列排查过但不成立的假设，防止其他团队重复投入排查精力。
6. **落地方案 (Recommendations)**
   - 按紧急程度划分为 P0 止血动作与 P1 修复动作。
7. **数据质量及后端探针说明 (Note)**
   - 附带 `scinlp backend` 的探测结果及分布偏度警告（如有）。
